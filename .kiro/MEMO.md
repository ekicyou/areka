# 「αマスク連動クリックスルー」実証試験と導入

## 0. 背景と前提知識（必読）

このタスクは Windows 10/11 上で動作する **Rust 製デスクトップマスコット** に「キャラクター描画領域だけクリックを受け、それ以外の透明領域は背面アプリ（他プロセス）にクリックを透過させる」機能を実装するものです。

過去の検討で以下が確定しています。**この知見を前提として作業してください。再調査・再検討は不要です。**

### 0-1. 採用しない手法と理由

- **`WM_NCHITTEST` で `HTTRANSPARENT` を返す方式は採用しない**。
  - MSDN仕様上、HTTRANSPARENTのカスケードは「同一スレッド内」でしか機能せず、他プロセス（Explorer/ブラウザ等）には届かないため、デスクトップマスコット用途では役に立たない。
- **Layered Window (`UpdateLayeredWindow` + GDI) も採用しない**。
  - GPU→CPU転送が毎フレーム発生し、3D描画では重い。今回はモダンな構成にする。

### 0-2. 採用する手法

「**`WS_EX_TRANSPARENT` を αマスクに応じて動的に付け外しする**」方式。

- 既定状態：`WS_EX_TRANSPARENT` は立っていない（クリックを受ける）
- 別スレッドのワーカが定期的にカーソル位置を取得し、αマスク関数に問い合わせる
- 透明領域なら `WS_EX_TRANSPARENT` を立てる、不透明領域なら外す
- 状態変化したフレームでのみ `SetWindowLongPtr` + `SetWindowPos(SWP_FRAMECHANGED)` を呼ぶ
- Windows 10以降は **`WS_EX_LAYERED` は併用不要**（他プロセスへのクリック透過は WS_EX_TRANSPARENT 単独で成立）

### 0-3. 参考にする既存実装（Rustポートではない）

- **kirurobo/UniWindowController**（Unity, C# + C++, MIT）
  - 本リポジトリの `VisualStudio/LibUniWinC/libuniwinc.cpp` 内 `SetClickThrough()` がコア
  - C#側 `UniWindowController.cs` の HitTestType::Opacity 判定（毎フレーム `Texture2D.ReadPixels` で1px読み）を参考
- これらの設計を Rust + `windows` クレートに置き換えるのが今回の作業

### 0-4. 同等のRustクレートは現時点で存在しない

調査済み。`winit::Window::set_cursor_hittest(bool)` や `tauri::set_ignore_cursor_events(bool)` は **API としては存在する** が、「αマスクに応じた自動切替」を行うクレートは見つかっていない。自前実装する。

## 2. フェーズ1：実証試験（PoC）

### 2-1. 成果物

独立したexample 先進坑プロジェクトを作成。

### 2-2. PoCの仕様

最小構成で以下を実証する：

1. 透過したトップモストのウィンドウを作成
2. ウィンドウ全域は透明。中央に「不透明な四角領域」を定義
3. 別スレッドが16ms周期でカーソル位置を見て、αマスク関数（仮想）に問い合わせる
4. 円内ならクリックスルーOFF、円外ならクリックスルーONを動的に切り替える
5. 切替が起こるたびでログ出力
6. 四角領域のクリックでもログ出力＆四角領域の色をトグル変更

重要なのは「クリックスルーの状態切替が正しく動くこと」「実際に四角がクリックできること」。

αマスク関数は以下のような仮実装でよい。座標とかは適当だが、あえて丸判定する方がクリックスルーが分かりやすいかもしれない。

```rust
let mask: HitMaskFn = Arc::new(|x: i32, y: i32| -> bool {
    // 仮：画面中央(960, 540)を中心とした半径200pxの円の「外」を透明扱い
    let dx = x - 960;
    let dy = y - 540;
    let dist_sq = dx * dx + dy * dy;
    dist_sq > 200 * 200  // true = 透明 = クリックスルーON
});
```

### 2-4. 必須の実装上の注意

- **DPI対応**: `main` 冒頭で `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)` を必ず呼ぶ。これを忘れるとマルチモニタ環境で GetCursorPos の座標がズレる。
- **状態変化最適化**: 毎フレーム SetWindowLongPtr を呼ぶのは禁止。前回状態と比較し、変化したときだけ呼ぶ。
- **HWND の Send**: HWND は `!Send` だが、`unsafe impl Send for AppState` でラップしてよい。Win32の慣例。
- **HTTRANSPARENT は使わない**。WM_NCHITTEST を自前ハンドルしない。
- **WS_EX_LAYERED は付けない**。WS_EX_TRANSPARENT 単独で十分。

## 4. 禁止事項・注意事項

- **`tokio` の使用は禁止**。`event_listener` + `std::thread` で組むこと（依頼者の方針）。
- **`WS_EX_LAYERED` を勝手に追加しないこと**。必要だと判断したら必ず理由とともに依頼者に確認。
- **`WM_NCHITTEST` ハンドラを書かないこと**。HTTRANSPARENTは他プロセスに届かないため無意味。
- **既存の本体コードを推測で書き換えないこと**。フェーズ2で既存コードに触る前に、対象ファイルと変更内容を依頼者に提示して確認を取ること。
- **Cargo.toml の依存追加は最小限**。新しい大きなクレート（winit, tauriなど）は提案のみ行い、勝手に追加しないこと。
- **マルチモニタ・高DPI環境を仮定すること**。プライマリディスプレイのみを前提にした実装はしない。
- **クレートやWin32 APIの仕様で不確実な点があれば、推測で進めず質問すること**。
