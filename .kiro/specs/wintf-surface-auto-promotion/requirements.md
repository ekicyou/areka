# Requirements Document

## Project Description (Input)
wintf の描画の木で、更新が頻繁な Visual を wintf が自動で描画面の持ち主へ上げ、落ち着いたら節へ戻す（描画面の自動の昇格・降格）。`wintf-visual-tree`（11-06 着地）で描画面の有無を Visual ごとに選べるようになった（規則は `wants_own_surface` の 1 か所・新しい描き方の部品を持つ Visual は既定で描画面なしの節・目印 `OwnSurface` で手動で持ち主へ上げる）が、上げ下げは使い手の手作業で、更新の頻度を見て自動で決める仕組みは無い。さらに、節の下に描画面の持ち主を置けない（`fill_world_visuals` が `error!` を残してその部分木を切る）ので木の途中の Visual だけを上げることができず、持ち主へ上げた Visual の `VisualTransform` は WUC の側で無視される（`warn!` を残すだけ）。困るのは wintf を使う描き手で、頻繁に変わる部品が節のままだと、その部品が変わるたびに親の描画面を描き直すことになる。出どころは `wintf-visual-tree` の要件 Introduction の到達点（2026-11-06 開発者）＝「既定は描画面なし・更新が頻繁になった Visual から描画面を作る（更新の頻度で自動で昇格・降格する）」。詳細は `brief.md`（末尾の 2026-11-16 棚卸㊳の再測定と、`wintf-visual-damage-redraw` からの申し送りが正本）。

## Introduction

wintf の描画面（WUC の `CompositionDrawingSurface`）は、描画面の持ち主の下の節を描画の木として平らにし、描画面 1 枚ごとの入れ物へ合成してから描画面へ写す。`wintf-visual-damage-redraw`（11-14 着地）から、前の合成から変わった所だけを入れ物の中で描き直す。それでも、頻繁に変わる節（まばたきのコマ・動く部品）が節のままだと、その節が変わるたびに親の描画面の中で描き直しが起きる。その節が自分の描画面を持てば、位置だけの変化は親の描画面に触らず、中身の変化も自分の描画面の中で閉じる（`draw/README.md` の「写し」の後半）。今はこの切り替えを使い手が目印 `OwnSurface` の付け外しで手で行うしかない。

本 spec は次の 3 つを作る。

1. 節の更新の頻度（見た目の版 `VisualVersion` の上がりと、世界の変形の変化）を、フレームの時刻で経過した実時間として見て、頻繁に変わる節を自動で描画面の持ち主へ上げ、落ち着いたら節へ戻す。上げ下げの閾値と、行ったり来たりを防ぐ履歴は 1 か所の純粋な規則に置く。上げ下げで画面の画素の答えは変えない（変わる形の節は自動では上げない）。
2. 節の下に描画面の持ち主を置けるようにする（WUC の木の同期と配置の伝播が節をまたぐ）。自動の昇格の前提であり、手動の `OwnSurface` でも使える。
3. 描画面の持ち主の `VisualTransform` を画面の見た目に効かせる（無視して `warn!` を残すのをやめる）。

あわせて、既定を「描画面なし」へ寄せる道筋（今の描き方の Visual の既定を変えるかどうか）を決める。

今の areka の描き手（emo のシェル・wintf のウィジェット）は新しい描き方の部品を使わず `GraphicsCommandList` で描く（新しい描き方の部品を使うのは wintf の中のテストと example だけ）ので、本 spec の効きは CPU の数字でなく、上げ下げの記録（要件 7）と、上げた形・戻した形・全部を節にした形の画素の一致のテスト（要件 8）で確かめる。

この文書の語は `wintf-visual-tree`・`wintf-d2d-composite-rules`・`wintf-visual-damage-redraw` の要件と同じ。**Visual が最小の描画単位**で、「描画面の持ち主」は自分の描画面を持つ Visual、「節」は自分の描画面を持たず、いちばん近い描画面の持ち主の描画面へ描き込まれる Visual を指す。「新しい描き方の部品」は `VisualDrawContent`・`VisualTransform`、「今の描き方」は `GraphicsCommandList` で描くことを指す。「節の更新」は、節の見た目の版（`VisualVersion`）が上がること、またはその節自身の局所の変形（`VisualTransform`）か配置（`Arrangement`）が変わることを指す（どちらも親の描画面の描き直しを起こす変化。祖先が動いて世界の変形だけが変わった回は数えない・討議の確定 1）。「自動で上げた持ち主」は、目印 `OwnSurface` を持たず、本 spec の判断で描画面の持ち主になっている節を指す。「全部を節にした形」は、同じ木で自動の昇格をせず、節を全部祖先の描画面へ描き込んだときの画面の画素を指す。「画面の画素」は、描画面の持ち主ごとの入れ物を、画面での位置と重なりの順で重ねた画素を指す。

## Boundary Context

- **In scope**:
  - 自動の昇格・降格の判断（材料・閾値・履歴を 1 か所の純粋な規則に置く）と、その答えどおりに描画面の部品を出し入れする係。
  - 自動で上げてよい節の見分け（上げると画素の答えが変わる形の節は上げない・上げた後にそうなったら戻す）。
  - 節の下の描画面の持ち主（WUC の木のつながりと位置の同期が節をまたぐこと・祖先の節の可視と矩形の切り抜きと不透明度の扱い）。`wintf-visual-tree` の要件 1.11 の「切って `error!`」をやめる。
  - 描画面の持ち主の `VisualTransform` を画面の見た目に効かせること（窓や持ち主の直下の持ち主と、節の下の持ち主の両方）。
  - 既定を「描画面なし」へ寄せる道筋の決めと、その文書。
  - 上げ下げと見送りの記録。判断の規則の純粋な決定論のテスト・上げ下げの画素の一致の WARP の決定論のテスト・実 GPU で画面に出ることの確かめ。wintf の既存のテストの更新。`draw/README.md` と steering の描画の道の記述の更新。
- **Out of scope**:
  - 差分の描き直しそのもの（前の描く列の保持・最長増加部分列・描き直す範囲・写し・描き直しの量の記録の行）＝`wintf-visual-damage-redraw`（着地済み）。本 spec はその作りに乗り、変えない。
  - 層・不透明度・重ね方・ブレンドの規則（`wintf-d2d-composite-rules`）の変更。
  - areka の側の使い方・emo の部品を節として載せること（`draw-methods-canon`・`shell-multi-compose`・`balloon-text-visual-tree`）。
  - 今の描き方の Visual（`GraphicsCommandList`）を節にすること（命令の列を祖先の描画面へ描き込むこと）。本 spec は道筋を決めて書くだけ（要件 6・討議の確定 7）。
  - 当たり判定（`hit_test`）の答え。当たり判定は描画面の有無に依らない今の作りのままとする。
  - 描画面 1 枚ごとの読み戻し（`SurfaceReadback`）の答えの形の変更（討議の確定 7）。
- **Adjacent expectations**:
  - `wintf-visual-tree` の規則 `wants_own_surface`・目印 `OwnSurface`・描画の木（`DrawTree`・`WorldVisual`・`VisualVersion`）と、`wintf-visual-damage-redraw` の差分の描き直しと記録の行（target `wintf::damage`・`[render_surface] damage`）をそのまま使う。変形では見た目の版を上げない約束（`version.rs`）を保つ。記録の行の欄と文言を変えない。
  - `draw-methods-canon`・`shell-multi-compose` など、emo の部品を節として載せる後の spec は、本 spec の自動の上げ下げの恩恵を受ける（頻繁に変わる部品だけが描画面を持つ）。
  - 同じウェーブ（C21）の約束: 本 spec は `Cargo.toml` に触らない（依存を足さない）。触るのは wintf の `ecs/graphics/visual/` の下（`mod.rs`・`systems.rs`・`world_visual.rs`・`draw/emit_test_support.rs`・`draw/README.md` とその兄弟のテスト）と、おそらく `ecs/graphics/systems/{visual_sync,clip_sync,surface}.rs`（`render.rs` は触らない見込み・ギャップ分析 §7）と wintf の `tests/graphics/` の下だけで、`crates/areka*`・`crates/pilot`・`tools/` に触らない。

## Requirements

### Requirement 1: 自動の昇格・降格の判断

**Objective:** wintf を使う描き手として、頻繁に変わる節は wintf が自動で描画面の持ち主へ上げ、落ち着いたら節へ戻してほしい。目印を手で付け外しせずに、頻繁に変わる部品のために親の描画面を描き直し続ける負荷を避けるためである。

#### Acceptance Criteria

1. When 節の更新が、直近の決まった長さの実時間の中で決まった回数以上起きた, the wintf shall その節を自動で描画面の持ち主へ上げると判断する（窓の長さと回数は設計で決める wintf の中の定数・討議の確定 7）。
2. When 自動で上げた持ち主の更新が、決まった長さの実時間のあいだ起きなかった, the wintf shall その持ち主を節へ戻すと判断する。
3. The wintf shall 上げる条件を戻す条件より厳しくし、上げた・戻した後の決まった長さの実時間のあいだは逆向きの判断をしない（行ったり来たりを防ぐ履歴）。ただし要件 2.4 の戻しはこの履歴を待たない。要件 2.4 で戻した後も、上げる側の履歴（決まった長さの実時間は上げない）を掛ける（討議の確定 4）。
4. The wintf shall 判断の材料を、既に在る見た目の版の上がりと節自身の局所の変形・配置の変化と、フレームの時刻（`FrameTime`）だけから取り、新しい計測の仕組み（描き直しの量の記録の行・別の時計）に頼らない。
5. The wintf shall 時間を経過した実時間で数え、丸めず、フレームの数で数えない。同じフレームの中で起きた複数の更新は 1 回の更新として数える。
6. If フレームの時刻が前の回より戻った, then the wintf shall その回の経過を 0 として扱い、戻った時刻を理由に上げる・戻すと判断しない。
7. The wintf shall 閾値・時間の長さ・履歴の値と判断の規則を 1 か所の純粋な規則に置き、同じ入力（更新の時刻の並び・今の時刻・今の上げ下げの状態と、それに入った時刻）からいつも同じ答えを出す。
8. The wintf shall 判断の答えを、ログの水準の設定（記録を出すかどうか）で変えない。
9. While 窓の下の木に変化が無いフレームが続く, the wintf shall 判断のために全部の節を毎フレーム調べ直さず、自動で上げた持ち主と、そのフレームに更新が起きた節だけを判断する。
10. When 祖先の節と子孫の節が同じ回に上げる条件を満たした, the wintf shall 祖先だけを上げる（子孫は祖先の描画面に描かれる・討議の確定 1）。
11. While 節が自動で上げた持ち主の部分木の中に在る, the wintf shall その節の更新をその持ち主の更新として数える（戻す判断に使う・討議の確定 1）。

### Requirement 2: 自動で上げ下げする節と見送り

**Objective:** wintf を使う描き手として、自動の上げ下げで画面の見た目も、手で決めた描画面の有無も変わらないでほしい。自動の上げ下げを意識せずに描き手が木を組めるようにするためである。

#### Acceptance Criteria

1. The wintf shall 自動の上げ下げを、窓の下の節（新しい描き方の部品を持ち、`GraphicsCommandList` と `OwnSurface` を持たない Visual）だけに行い、`GraphicsCommandList` を持つ Visual・何も持たない Visual・`OwnSurface` を持つ Visual の描画面の有無を自動では変えない。
2. When 使い手が自動で上げた持ち主に `OwnSurface` を付けた・`OwnSurface` を外した, the wintf shall 付いている間は判断に依らず手動の持ち主とし、外れた後は規則 `wants_own_surface` の答えに戻し、節なら自動の判断の対象にする（外した後の更新が頻繁なら要件 1.1 で改めて上げる）。
3. If 節を上げると画面の画素が全部を節にした形と変わる形である（同じ描画面の中で後に描く中身と重なる・前順で前に在る手動の持ち主と重なる・その部分木の中に手動の持ち主が在る・祖先の節の不透明度の層か図形の切り抜きの中に在る・その部分木に `SOURCE_OVER` でない混ぜ方の件が在る・その部分木の描く範囲が自分の描画面と親の描画面と祖先の節の矩形の切り抜きに収まらない・持ち主から見た世界の変形が平行移動でない（回転・拡大を含む）・自分の切り抜きが物理ピクセルの整数の矩形でない（角丸か図形））, then the wintf shall その節を自動では上げず、節のまま描く（重なりの判定ににじみの余白を足すかは設計で確かめる・討議の確定 2）。
7. Where 自動で上げる節の世界の位置が物理ピクセルの整数でない, the wintf shall 端数を自分の描画面の中でずらして描き、WUC の位置を整数に置いて、画面の画素を全部を節にした形と一致させる。端数が変わった回は自分の描画面だけを描き直し、親の描画面に触らない。設計の段でこの形の画素が親の描画面の中で描いた形と（要件 3.2 の許しの範囲で）揃わないと分かったら、物理ピクセルの整数でない位置の節を自動では上げない形に落とす（討議の確定 2）。
4. If 自動で上げた持ち主が要件 2.3 の形になった, then the wintf shall 履歴を待たず、その形になったフレームのうちに節へ戻す。
5. If 自動で上げる節の描画面を作れない（装置が無い・作るのに失敗した）, then the wintf shall その節を節のまま描き続け、その旨を記録に残す（続く間は繰り返さない）。
6. The wintf shall 自動の上げ下げで、使い手が付けた部品（`OwnSurface`・`GraphicsCommandList`・新しい描き方の部品）を足したり外したりしない。

### Requirement 3: 上げ下げのフレームの描画

**Objective:** wintf を使う描き手として、上げ下げの瞬間にも画面がちらつかないでほしい。自動の上げ下げが見た目に現れないようにするためである。

#### Acceptance Criteria

1. When 節を自動で上げる・戻すと判断した, the wintf shall そのフレームのうちに描画面の有無を切り替え、そのフレームの画面に、その部分木が欠けたり 2 度描かれたりしない（1 フレーム遅らせて合わせない）。
2. The wintf shall 自動で上げた形・戻した形・上げ下げのフレームの画面の画素を、全部を節にした形と一致させる。
3. When 節を自動で上げる・戻す, the wintf shall 親の描画面の描く列からその部分木が外れる・戻る変化を、差分の描き直しの変化（範囲だけの描き直しか、決められなければ全部）として扱う。

### Requirement 4: 節の下の描画面の持ち主

**Objective:** wintf を使う描き手として、木の途中の Visual も描画面の持ち主にできてほしい。自動の昇格の前提であり、手動の `OwnSurface` でも、動く部品を木の深い所に置いたまま自分の描画面に載せるためである。

#### Acceptance Criteria

1. While 描画面の持ち主（今の描き方の Visual・`OwnSurface` を持つ Visual・自動で上げた持ち主）が節の子孫に在る, the wintf shall その持ち主とその下の木を切らずに画面に出し、`wintf-visual-tree` の要件 1.11 の `error!` を残さない。
2. The wintf shall 節の下の持ち主の子孫の節を、その持ち主の描画面に描き、祖先の持ち主の描画面には描かない。
3. The wintf shall 節の下の持ち主を、いちばん近い祖先の描画面の持ち主の描画面の上に重ねて画面に出す。
4. The wintf shall 節の下の持ち主の画面での位置を、祖先の節の局所の変形と配置（`Arrangement`）をいちばん近い祖先の持ち主まで重ねた世界の変形と、DPI の拡大で決め、全部を節にした形でその持ち主が描かれる位置と同じ物理ピクセルに置く。
5. When 祖先の節の変形・配置・親子のつながりが変わった, the wintf shall 同じフレームのうちに、その下の持ち主の位置と WUC の木のつながりを合わせ直す。
6. The wintf shall 同じ祖先の持ち主の下に在る持ち主（直下の持ち主と節の下の持ち主）の画面での重なりの順を、木の前順（`Children` の並び順）に合わせる。自動で上げた持ち主も前順に並べる（前の手動の持ち主と重なる節は要件 2.3 で上げない）。
11. When 節や持ち主の親は同じまま `Children` の並びだけが変わった, the wintf shall 同じフレームのうちに WUC の子の並びを前順に合わせ直す（今の手動の持ち主にも効く・討議の確定 5）。
7. While 祖先の節が見えない（`is_visible` が偽か不透明度が 0）, the wintf shall その下の持ち主も画面に出さない。
8. While 祖先の節が 1 未満の不透明度か矩形の切り抜きを持つ, the wintf shall その下の持ち主の見た目に、祖先の節の不透明度の積と矩形の切り抜きを効かせる（討議の確定 3）。
9. If 手動の持ち主（今の描き方の Visual・`OwnSurface` を持つ Visual）の祖先の節が図形の切り抜き（`ClipShape::Geometry`）か `SOURCE_OVER` でない混ぜ方を持つ、またはその持ち主が同じ描画面の中で後に描く中身と重なる, then the wintf shall 効かせられない・重なりの順が全部を節にした形と違う旨を実体名つきで `warn!` に残し、続く間は繰り返さない（討議の確定 3）。
10. When 持ち主が節の下から外れた・消えた・節へ戻った, the wintf shall その WUC の Visual を古い親の子から外し、古い親の下に残さない。

### Requirement 5: 描画面の持ち主の VisualTransform

**Objective:** wintf を使う描き手として、描画面の持ち主へ上げた Visual の `VisualTransform` が、節のときと同じく見た目に効いてほしい。上げ下げで部品の位置や形が変わらないようにするためである。

#### Acceptance Criteria

1. While 描画面の持ち主が `VisualTransform` を持つ, the wintf shall その変形を、節のときと同じ意味（局所の変形 × 配置の平行移動）で、その持ち主とその下の木の画面の見た目に効かせ、`warn!` を残して無視しない。
2. When 持ち主の `VisualTransform` が変わった, the wintf shall 同じフレームのうちに画面の見た目へ反映する。
3. The wintf shall 持ち主の `VisualTransform` の変化で、その持ち主の見た目の版を上げない（`version.rs` の約束を保つ）。
4. Where 手動の持ち主の `VisualTransform` が回転か拡大を含む, the wintf shall 画面での位置・向き・大きさを全部を節にした形と合わせ、画素の境界の再標本化による違いは許す（討議の確定 3）。

### Requirement 6: 既定の寄せ方

**Objective:** wintf を使う描き手と保守者として、既定を「描画面なし」へ寄せる道筋を知りたい。今の描き手の見た目を変えずに、後の spec が同じ方向へ進めるようにするためである。

#### Acceptance Criteria

1. The wintf shall 今の描き方の Visual（`GraphicsCommandList` を持つ）と何も持たない Visual の既定（描画面の持ち主）を本 spec では変えない（討議の確定 7）。
2. The wintf shall 新しい描き方の Visual の既定（節）を保ち、自動の昇格はその既定の上に足す。
3. The wintf shall 既定を「描画面なし」へ寄せる道筋（今の描き方の Visual と何も持たない Visual を節にするための条件と、それを受け持つ後の spec）を `draw/README.md` に書く。

### Requirement 7: 上げ下げの記録

**Objective:** wintf の保守者と描画の負荷を測る開発者として、どの Visual がいつ、なぜ自動で上げ下げされたか（されなかったか）を記録で知りたい。判断の閾値の効きを確かめ、見送りの理由を追えるようにするためである。

#### Acceptance Criteria

1. When 節を自動で上げた・戻した, the wintf shall 実体名・向き（上げた・戻した）・理由（更新が頻繁・落ち着いた・画素が変わる形になった）を `debug!` に 1 行残す。
2. When 判断が上げると答えたが要件 2.3 で見送った, the wintf shall 実体名と見送りの理由を `debug!` に残し、同じ理由の見送りが続く間は繰り返さない。
3. The wintf shall 上げ下げと見送りの記録を毎フレーム繰り返さない。
4. The wintf shall 既存の記録の行（`[render_surface] damage`・`[tick]` ほか）の文言と欄を変えない。

### Requirement 8: 決定論のテスト

**Objective:** wintf の保守者として、判断の規則と上げ下げの答えを決定論のテストで固定してほしい。上げ下げで見た目がずれる欠陥と、行ったり来たりする欠陥を、画面を見ずに見つけるためである。

#### Acceptance Criteria

1. The wintf shall 判断の規則を、GPU を使わない純粋なテストで、真理値表（上げる・戻す・据え置く・履歴で止める・要件 2.4 の即時の戻し）と時系列（一定の間隔の更新・途切れる更新・閾値のちょうど前後・時刻が進まない回・戻る回・同じフレームの複数の更新）で固定する。
2. The wintf shall 自動では上げない形（要件 2.3 の各場合）の見分けを、GPU を使わない純粋なテストで固定する。
3. The wintf shall 全部を節にした形・自動で上げた形・戻した形・上げ下げのフレームの画面の画素が一致することを、D2D を CPU の描き手（WARP）で動かす決定論のテスト（`draw/emit_test_support.rs` の足場）で確かめる。場合には、節の下の持ち主・`VisualTransform` を持つ持ち主・祖先の節の不透明度と矩形の切り抜きを含める。
4. The wintf shall 節の下の持ち主の WUC の木のつながりと位置（DPI の拡大を含む）・付け替え・外し・祖先の節が見えない回・重なりの順（`Children` の並びだけが変わった回を含む）を、テストで確かめる。
5. The wintf shall 節の下の持ち主と `VisualTransform` を持つ持ち主が画面に出ることを、実 GPU で確かめる。確かめは WUC の Visual の性質の読み戻し（親・位置・変形の行列・不透明度・子の並び）と描画面ごとの画素（`CopySurface`）で行い、表示した窓の画面の画素は読まない（`Cargo.toml` に触らず、画面の操作も要らない・討議の確定 6）。
6. The wintf shall 節の下の持ち主を切る `error!`（`wintf-visual-tree` の要件 1.11）と持ち主の `VisualTransform` の `warn!` を確かめていた既存のテストを、本 spec の支える形に合わせて更新する。
7. The wintf shall 本 spec で足す新しいテストを、本番ファイルの中に書かず、同じディレクトリの兄弟ファイルに置く（`structure.md` のテスト分離の規約）。

### Requirement 9: 文書と制約

**Objective:** wintf を使う描き手と保守者として、自動の上げ下げと節の下の持ち主の使い方と制限を文書で知りたい。後の spec と外の使い手が同じ形で乗れるようにするためである。

#### Acceptance Criteria

1. The wintf shall `draw/README.md` に、自動の上げ下げ（材料・履歴・見送りの形）・節の下の持ち主（重なりの順と祖先の節の性質の扱い）・持ち主の `VisualTransform` を書き、「写し」の節の前提（節の下の持ち主は切られる・持ち主の `VisualTransform` は効かない）を今の作りに合わせて書き直す。当たり判定は今の作り（`GlobalArrangement`）のままで、回転・拡大を含む `VisualTransform` を持つ持ち主は見た目と当たりがずれうることも書く（範囲外の明記・ギャップ分析 R6）。
2. The wintf shall steering（`structure.md`・`tech.md`）の描画の道の記述に、描画面の自動の上げ下げと節の下の持ち主を足す。
3. The wintf shall areka に依存せず、公開の名前に areka の語を使わない。
4. The wintf shall 依存を足さない（`Cargo.toml` に触らない）。
5. The wintf shall 1 ファイルを 1,000 行以内に保つ。

## 討議の確定（2026-11-16・開発者が全議題を推奨案で承認）

要件を書いた段の仮定（10 件）とギャップ分析の設計の判断の項目（D1〜D12）を 7 つの議題にまとめ、開発者が全部を推奨案で承認した。本文の「討議の確定 n」はこの番号を指す。

1. **判断の材料と数える先**（要件 1.1・1.4・1.10・1.11・Introduction・D5）: 材料は見た目の版の上がりと、その節自身の局所の変形か配置の変化。祖先が動いて子孫の世界の変形だけが変わった回は子孫に数えない（動くまとめ役の下の子孫が一斉に上がるのを防ぐ）。祖先と子孫が同じ回に条件を満たしたら祖先だけを上げる。自動で上げた持ち主の部分木の中の節の更新は、その持ち主の更新として数える。描き直しの量の記録の行（`[render_surface] damage`・debug でだけ出る）は使わない（判断がログの設定に依らない＝要件 1.8）。
2. **画素の一致の厳しさと自動で上げてよい形**（要件 2.3・2.7・3.2・4.6・D3・D4・D7）: 自動で上げるのは画面の画素が全部を節にした形と一致する形だけ。親の描画面を上下に分けて重なりの順を保つ形は取らない。上げない形に、ギャップ分析 §5 の 5 つ（前順で前の手動の持ち主との重なり・部分木の中の手動の持ち主・描画面と親と祖先の矩形の切り抜きに収まらない・平行移動でない・自分の切り抜きが整数の矩形でない）を足した。物理ピクセルの整数でない位置は、端数を自分の描画面の中でずらして描き WUC の位置を整数に置く形（D3 の案 b）を取り、設計の段でこの形の画素が揃うか（ギャップ分析 R-e）を確かめる。揃わなければ整数の位置だけを上げる形（案 a）に落とす。回転・拡大を含む節は自動では上げない。自動で上げた持ち主の重なりの順は前順のまま（前の手動の持ち主と重なる節は上げない＝要件 4.6 を変えない）。画素の一致の許しは `wintf-visual-tree` 議題 3 に揃える（境界から離れた画素・1 チャネルあたり ±1）。重なりの判定ににじみの余白を足すかは設計で確かめる。
3. **手動の持ち主を節の下に置いたときの性質と規模**（要件 4.7〜4.9・5.4・D10）: 本 spec で作る（見立て 14〜18 タスク・上限 20 の内）。可視・矩形の切り抜き・不透明度の積は効かせる。図形の切り抜き・`SOURCE_OVER` でない混ぜ方・後に描く中身との重なりの順は効かせられないので `warn!` を 1 度残す（`wintf-visual-tree` 議題 2 の「持ち主の図形の切り抜きは `warn!` 1 度で保留」に揃える）。不透明度の積は、重なる子孫どうしでは層の不透明度と答えが違う（手動の持ち主に限る）。回転・拡大を含む手動の持ち主の `VisualTransform` は、画面での位置・向き・大きさを合わせ、再標本化による境界の画素の違いは許す。WUC への写し方（祖先の持ち主に直に繋ぐ B-1 か、道の上の節ごとに入れ物を作る B-2 か）は設計で決める。
4. **形で即座に戻した後の履歴**（要件 1.3・2.4・D6）: 形が変わって履歴を待たずに戻した後も、上げる側の履歴を掛け、決まった時間は上げない（往復を防ぐ）。
5. **`Children` の並びだけの変化**（要件 4.11・D12）: 本 spec で直す。WUC の同期の係は並びだけの変化で並べ直さない（今の手動の持ち主にも在る欠け）ので、同じフレームのうちに前順へ合わせ直す。
6. **実 GPU の確かめ方**（要件 8.5・D11）: WUC の Visual の性質の読み戻し（親・位置・変形の行列・不透明度・子の並び）と描画面ごとの画素（`CopySurface`）で確かめる。表示した窓の画面の画素は読まない（`Windows.Graphics.Capture` は `Cargo.toml` に触る・画面の操作の机も要らない）。
7. **小さな仮定**（下書きどおり）:
   - 閾値・時間の長さ・履歴の値は設計で決める wintf の中の定数（1 か所）とし、使い手が変える設定の口は出さない。
   - 今の描き方の Visual と何も持たない Visual の既定（描画面の持ち主）は変えない。命令の列を祖先の描画面へ描き込む作りは無く、emo の部品を描画の木へ移すのは `draw-methods-canon` なので、道筋（条件と受け持つ spec）を `draw/README.md` に書くだけにする。
   - 自動の昇格を止める口は持たない（Visual ごとの目印も全体の切り替えも足さない）。上げ下げで画素が変わらないので止める理由が無い。テストは時刻を注入して判断を決定論にする。
   - 自動で上げる持ち主の数と大きさに上限を設けない。描画面 1 枚ごとに同じ大きさの入れ物が増えるが、今は新しい描き方の使い手が wintf の中にしか居ない。使い手が出たら測って足す（上げた数は要件 7.1 の記録で追える）。
   - 描画面 1 枚ごとの読み戻し（`SurfaceReadback`）は今どおり描画面ごとの入れ物を読み、自動で上げた部分木は親の描画面の読み戻しに載らなくなる。そのことを `draw/README.md` に書く。今の読み戻しの使い手（areka の実機の確かめ・emo-text のテスト）は新しい描き方の部品を使わないので答えは変わらない。
   - 記録は、上げ下げと見送りを `debug!`（状態の変化・`logging.md`）、描画面を作れずに節のまま描く回は既存の作成の失敗の記録（`error!`）に加えて見送りの `debug!` を 1 度残す。

**設計の段へ回したもの**（ギャップ分析 §8）: D1 同じフレームで切り替える係の順（用意してから切り替える 2 段か、係の順の組み替えか）・D2 自動の状態の置き場・D8 静かな間の戻し（心拍で拾うか `tick_wake::arm_deadline` か。遅れは画素に出ない）・WUC の写し方（B-1／B-2）・調べること R-a〜R-e。
