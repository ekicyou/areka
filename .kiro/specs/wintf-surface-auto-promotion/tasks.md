# Implementation Plan

> 設計（`design.md`）の部品名で書く。新しいテストは全部、本番ファイルの中に書かず同じディレクトリの兄弟ファイルに置き、接続宣言（`mod ...;`）だけを `visual/mod.rs`・`visual/draw/mod.rs`・`tests/graphics.rs` に足す（要件 8.7）。`Cargo.toml` には触らない。

- [ ] 1. 純粋な規則と置き場の補助（ECS に依らない土台）
- [x] 1.1 上げ下げの判断の規則と状態の部品を作る
  - 判断の定数 5 つ（1 秒に 8 回で上げる・3 秒更新が無ければ戻す・上げた後と戻した後の履歴 3 秒）を 1 か所に置き、設定の口は出さない
  - 相（節・用意中・上げた）と、用意中の描画面の様子・戻す理由・判断の答えの型を作り、1 回ぶん進める規則・祖先へ吸い込む戻し・手動の目印が入ったときの初期化を、設計の答えの表どおりに組む
  - 時刻は丸めずに比べ、前の回より戻った時刻は前の回の値として扱い、同じ時刻の複数の更新は 1 回に数える
  - 見送りの理由の型（8 種と記録の語）を、形の見分けのファイルに型だけ先に置く（見分けの中身は 2.2）
  - 状態の部品（規則の状態・最後の見送りの理由・部分の列を描いたかの印）を作る。欄は crate の外から触れない
  - 真理値表（上げる・見送る・用意中の待ち／切り替え／作れず戻す・落ち着きの戻しと履歴の内の据え置き・形の即時の戻し・即時の戻しの後の上げの履歴・吸い込み・初期化）と時系列（8 Hz で 1 秒ちょうどとその前後・途切れる更新・時刻が進まない回・戻る回・同じ時刻の複数の更新）の純粋なテストが緑になる
  - _Dispatch: standard — 新しい規則の分岐を設計の表から組む_
  - _Requirements: 1.1, 1.2, 1.3, 1.5, 1.6, 1.7, 2.4, 2.5, 8.1, 8.7_

- [x] 1.2 置き場の部品と WUC へ写す純粋な補助を作る
  - 置き場の部品（節の下の手動の持ち主＝親の節の世界の行列・不透明度の積・可視・切り抜き、自動で上げた持ち主＝整数の物理ピクセルの原点と大きさ）を作る
  - 持ち主の WUC の親からの変形（平行移動だけなら位置、それ以外は行列に全部・DPI の拡大込み）を出す補助を作る
  - 自分の切り抜きと置き場の切り抜きを 1 つの WUC の切り抜きへ合わせる補助（今のまま・軸に沿う矩形・逆行列で局所へ・合わせられない）を作る
  - 子の WUC の親になる持ち主（節と用意中の自動の持ち主を通り抜ける・窓の外は外す）と、親の持ち主の WUC の子の並び（手動の持ち主を前順で先に、自動で上げた持ち主を前順の逆で後に）を出す補助を作る
  - 親の決め（直下・節の下・深い節の下・用意中・窓の外）、子の並び（節の通り抜け・自動の持ち主の位置・`Children` の並べ替え）、変形（平行移動・回転・拡大と DPI）、切り抜きの合わせの各場合の純粋なテストが緑になる
  - _Dispatch: standard — 新しい純粋な補助の分岐を設計の契約から組む_
  - _Requirements: 4.3, 4.4, 4.6, 4.8, 5.1, 8.4, 8.7_

- [ ] 2. 走査の列・形の見分け・部分の列
- [x] 2.1 描画面の持ち主の木を埋める係を走査の列へ広げ、節の下の持ち主を切らなくする
  - 節（`WorldVisual`）が生まれたときから状態の部品を持つようにする
  - 埋める係が、手動の持ち主ごとに前順の走査の列（深さ・親の添字・部分木の終わり・種類・可視・世界の行列・この回の更新・自分の切り抜きの種類・混ぜ方・祖先の不透明度の積と層と矩形の切り抜きの交わりと混ぜ方）を 1 度の歩きで記す
  - 子が手動の持ち主なら、その部分木は歩かず、置き場の材料（親の節の世界の行列）を持つ項を 1 つ入れて止まり、`error!` を残さない。自動で上げた持ち主の部分木は通り抜ける
  - 「この回の更新」は見える節の版の上がりか、その節自身の `VisualTransform`・`Arrangement` の変化だけで立ち、祖先の動きでは立たない
  - 描画の木を組む係は走査の列から見える節の列を作って今の組み立てに渡し、今の描画の答えを変えない
  - 節の下の持ち主を切って `error!` を確かめていた既存のテスト 2 本を、置き場の材料を記して `error!` を出さない形へ書き換え、走査の列の材料と更新の印のテストを兄弟ファイルに足して、wintf の既存の描画の木のテストと合わせて緑になる
  - _Dispatch: standard — 既存の歩きに新しい記しを足し呼び出し元を合わせる_
  - _Requirements: 1.4, 4.1, 4.2, 4.4, 4.7, 4.8, 8.6, 8.7_

- [x] 2.2 自動で上げてよい形の見分けと自分の描画面の矩形の決めを作る
  - 走査の列と候補の添字と拡大と親の描画面の大きさだけを入力に、5 つの見送り（後に描く中身との重なり・部分木の中の手動の持ち主・祖先の不透明度の層か角丸・図形の切り抜き・`SOURCE_OVER` でない混ぜ方・親の描画面と祖先の矩形の切り抜きに収まらない）を見分ける
  - 重なりと収まりは物理ピクセルへ外向きに丸めた外接矩形ににじみの余白（差分の描き直しと同じ規則）を足して見る。ほかの自動の持ち主の部分の中の中身は数えず、手動の持ち主との重なり・回転や拡大・自分の角丸や図形の切り抜きは見送りの理由にしない
  - 自分の描画面の矩形と原点（範囲の左上の整数の物理ピクセル・DIP・物理の大きさ）を決め、整数の位置だけを上げる形へ落とすための 1 か所の条件（原点の端数）を用意する（使うかは 2.4 の結果で決める）
  - 上げた後に描く範囲が矩形からはみ出したかを見分け、新しい範囲で矩形を決め直す
  - 見分けの各場合の真偽・余白のちょうど前後・矩形と原点の決め（負の座標・親の描画面と祖先の切り抜きで切る回）・はみ出しの決め直しの純粋なテストが緑になる
  - _Dispatch: standard — 新しい幾何の判定を設計の列から組む_
  - _Requirements: 2.3, 2.7, 4.6, 8.2, 8.7_

- [x] 2.3 (P) 描画の木の組み立てに部分の列の形を足す
  - 組み立てに組む木の枠（今の持ち主の木・自動で上げた持ち主の部分の列）を足し、今の呼び出しは持ち主の木の枠で同じ答えを出す
  - 部分の列は根の中身を出さず、先頭の自動の持ち主自身から節と同じ不透明度の層・切り抜き・中身を出し、全部の世界の行列と外接矩形から原点を引く
  - 組み立ての今の呼び出し元 3 か所（描画の木を組む係・組み立てのテスト・WARP の足場）を持ち主の木の枠に合わせる
  - 部分の列が根の中身を出さないこと・原点を引いた行列と外接矩形・整数だけ動いた原点で件の鍵が変わらないことのテストが兄弟ファイルで緑になり、既存の組み立てのテストも緑のまま
  - _Boundary: SegmentBuild（組み立ての呼び出し元を含む）_
  - _Depends: 2.1_
  - _Dispatch: standard — 既存の組み立てに新しい枠の分岐を足す_
  - _Requirements: 2.7, 3.2, 8.7_

- [x] 2.4 WARP の足場に WUC の重ねの写しを足し、端数の位置の画素が揃うかを最初に確かめる
  - 描画面ごとの絵を整数の物理ピクセルの位置と不透明度で `SOURCE_OVER` で親の絵へ重ねる写しを足場に足す
  - 拡大 1.0・1.25・1.5 で、小数の位置の節の部分木（矩形・にじみのある楕円・ビットマップの補間）を、親の描画面の中で描いた絵と、部分の列で原点を引いて描き整数の位置へ重ねた絵とで比べる
  - 境界から離れた画素で 1 チャネルあたり ±1 に揃うテストが緑になる。揃わなければ 2.2 の 1 か所の条件で整数の位置だけを上げる形へ落とし、そのテストが緑になる
  - 後の群（3・4）より先に結果を出すため、ここに置く
  - _Dispatch: standard, effort high — 結果で形を落とすかを決める確かめ_

- [ ] 3. 1 回の判断と係の配線
- [x] 3.1 1 回の判断（帰属・祖先の優先・相の移り・置き場・描く列の分け方）を作る
  - 更新のあった見える節を、自分か祖先のいちばん近い自動の持ち主（用意中・上げた）へ帰属させ、帰属先ごとにこの回 1 回の更新とする
  - 判断はこの回に更新のあった帰属先とこの走査の列に居る自動の持ち主だけに行い、ほかの節の規則は呼ばない。時刻が無い回は判断しない
  - 同じ回に祖先も上げると答えた候補は上げず、上がった候補の部分木の中の自動の持ち主は同じ回に吸い込みで戻す
  - 用意中の描画面の様子を部品の様子から決め（待ち・できた・作れなかった）、装置か WUC の資源が無い回の上げは見送る。上げた持ち主の描く範囲がはみ出したら矩形を決め直す
  - 手動の持ち主の項と自動の持ち主に置き場を値が変わったときだけ書き、書いた実体を控えに記す（外すのは全部の根を回した後の 3.4）。描く列の分け方（親の列＝上げた持ち主の部分を除く・部分の列＝用意中と上げた持ち主）を返す。使い手の部品には触らない
  - 帰属・祖先の優先・吸い込み・用意中から上げたへの移り・置き場の書き込みと書いた控え・分け方の事後条件（上げた部分は親の列に無く、用意中の部分は両方に在る）の GPU を使わない ECS のテストが兄弟ファイルで緑になる
  - _Depends: 1.1, 1.2, 2.2_
  - _Dispatch: standard, effort high — 設計が形を与えるが帰属と祖先の優先の組み合わせが細かい_

- [x] 3.2 上げ下げと見送りの記録と、節の下の手動の持ち主の効かせられない形の warn! を足す

  - 見送りは理由が前の見送りと違うときだけ `debug!` を残し、描画面を作れなかった回は既存の作成の `error!` に加えて見送りの `debug!` を 1 度残す
  - 節の下の手動の持ち主の効かせられない形（祖先の図形・角丸の切り抜き・軸に沿わない矩形の切り抜き・混ぜ方・後に描く中身との重なり・切り抜きを 1 つに合わせられない形）を、実体名つきで続く間 1 度の `warn!` に残す
  - 判断の答えはログの水準で変わらず、既存の記録の行の文言と欄は変えない
  - 記録が移りの回だけ 1 行・見送りが続く間 1 度・`warn!` が続く間 1 度・ログの水準を変えても答えが同じことのテスト（記録の捕まえ）が緑になる

- [x] 3.3 描画面の 3 部品の係に自動の持ち主を入れ、手動の目印の優先を効かせる

  - 3 部品の係が相の変化を見て、自動の持ち主に 3 部品を入れ、戻した次の回に外す
  - 手動の目印か命令の列が入った節は状態を初期化し、用意中か上げた形で持っていた描画の木を外す。外れた後は規則の答えに戻り、節なら判断の対象になる
  - 相の変化で 3 部品が出入りすること・手動の目印で初期化されること・既定の答えが変わらないことのテストが兄弟ファイルで緑になる

- [x] 3.4 描画の木を組む係に 1 回の判断と部分の列を配線する

  - 組んだ部分の列は全部の根を回した後にまとめて自動の持ち主の描画の木へ書き、用意中の部分を書いた回に描いた印を立てる

  - フレームの時刻を注入した GPU を使わない ECS のテストで、頻繁に更新した節が用意中を経て上げたへ進み、親の描く列から外れ、落ち着くと戻ることと、根が 2 つの木で置き場が毎回外れたり付いたりしないことが確かめられ、既存の描画の木のテストも緑のまま

## Implementation Notes
- 1.1: `promotion.rs`・`promotion_shape.rs` は配線までの間 `#![cfg_attr(not(test), allow(dead_code))]`（`shortcut:` 注記つき）。3.x で配線したら外す。`promotion.rs` の時刻の繰り上げ `!(now >= prev)` は clippy `neg_cmp_op_on_partial_ord` が出て、最初の回の NaN で固まるので、3.x の配線のときに `self.last_now.map_or(now, |p| now.max(p))` へ替える（レビューの提案）
- 1.2: `merged_clip` の `Rect{local}` は交わりが空だと `Aabb::EMPTY`（無限の値）になる。4.3 の ClipSync は「何も出さない」として扱う。`Transformed.inverse` は DIP の値で、物理への換算は ClipSync の受け持ち
- 2.1: `update_draw_trees` は今も全部の `VisualGraphics` を根に取る（3.4 で手動の持ち主だけに絞る）。`FillData` の `Has<VisualGraphics>` は読まれなくなった（3.4 で消してよい）。`visited.extend(scan.visible_nodes())` は組み直しの無い回の早期 continue の後へ移せる
- 2.2: 描く中身の無い部分木は大きさ 0 の `Origin` を返す。3.x の配線で 0×0 の描画面を作らない。後ろの見える節が `SOURCE_OVER` でなければ位置によらず重なりとみなす（控えめな側）。走査の列は件の補間を持たないので、縮める `HIGH_QUALITY_CUBIC` のビットマップ（diff.rs の R1: 描く範囲で答えが変わる）は見分けられない。2.4 の WARP の比べにこの回を入れ、揃わなければ見送りの理由を足すかを決める
- 2.3: `TreeFrame::Segment` の `origin` は `Origin.dip`、`viewport` は原点から測った持ち主の描画面の矩形を渡す（3.4 の配線）。2 の冪でない端数の位置では原点を引いた f32 の下位の桁が揃わず、整数の移動でも件の鍵が変わりうる（自分の描画面の描き直しが増えるだけ）
- 2.4: R-e は案 b（端数の位置のまま上げる）で揃った（拡大 1.0・1.25・1.5、矩形・にじむ楕円・線形と縮める HQC のビットマップ、画像全体で ±1）。ただし原点を DIP（px÷拡大）で引くと f32 の丸めで崩れる（楕円・拡大 1.25 で 16）ので、`TreeFrame::Segment` は `origin_px` と `scale` を取り、列を自分の描画面の物理ピクセルで出す。**3.4 の配線では、自動の持ち主の描画面の再生の根の変換を恒等に、`diff::entries` の拡大を (1,1) にする（さもないと DPI の拡大が二重に掛かる）**。`INTEGER_POSITION_ONLY = false`。`Origin.dip` は部分の列では使わない
- 3.1: `RoundPlan.segments` は Active と 3 部品（`SurfaceGraphics`）つきの Preparing だけ。3.4 は (a) `segments` に入った Preparing の部分を書いた回にだけ、全部の根を回した後で `built = true` を `bypass_change_detection` で立てる (b) `segments` に無い持ち主には立てない (c) 係の順 `sync_surface_owner_parts` → `update_draw_trees` → `deferred_surface_creation_system` を保つ (d) どの根の回でも `written` に入らなかった実体の置き場を外し、どの走査の列にも現れなかった控えの自動の持ち主を見えないとして戻す (e) `promotion_round.rs` の dead_code の許しを外す。装置が無ければ用意中は Failed で戻す
- 3.2: `run_round` は `reported: &mut ReportedIssues` を取る。3.4 は `update_draw_trees` の `Local<ReportedIssues>` を `fill_world_visuals` と `run_round` で共有し、`end_round` は全部の根を回した後に 1 度だけ呼び、`run_round` は `needs_rebuild` に関係なく毎フレーム回す（さもないと warn! の「続く間 1 度」が崩れる）。どの走査の列にも現れなかった自動の持ち主の `hidden` の戻しは `promotion_round::record` を `pub(crate)` にして記録を残す。`clip_combo` は `merged_clip` の `Unsupported` の条件の写しなので、4.3 で `merged_clip` を本番で呼ぶときに両者の答えが合うテストを 1 本足す
- 3.4: 境界を広げた（進行役の裁定・並走なし）: `render.rs` の `replay_transform` は `DrawTree::device_px` の木だけ恒等。visual/mod.rs の `Visual`・`OwnSurface` の文書は「持ち主の `VisualTransform` を WUC の Visual の変形として写す」と書いたが、本当になるのは 4.2。4.2 で確かめる。拡大 1.25 の画素は根の変換の選びまでしか確かめていないので、5.1 の WARP で通しで確かめる
- 3.5: 戻した回は置き場が先に外れ 3 部品は次の回に外れるので、その回に配置などが変わると、捨てる描画面を外接矩形の大きさで 1 度作り直しうる（画素には出ない・GPU の手間だけ）。直すなら作る係で「置き場が無く、もう描画面を欲しがらない（目印も命令の列も無く相が Node）」実体を飛ばす。4.1 で入れる
- 4.1: 3.5 の申し送り（戻した回の無駄な作り直しを飛ばす）は `deferred_surface_creation_system` に入れた。並べ直しの条件のうち「下の節の相の変化」（visual_sync.rs の `rephased`）は今のテストでは固まっていない（親の食い違いが先に拾うため）。5.2 の実 GPU の確かめで、相だけが変わる回の並びを見る
- 4.2: WUC の Offset は前から物理ピクセル（DIP×拡大）なので、自動の持ち主の `origin_px` は拡大を掛けずに写す。持ち主の `VisualTransform` が版を上げないことは構造（version.rs に触らない）だけで、テストは無い。5.x で 1 行足すとよい
- 4.3: 切り抜きの鍵は当てた置き場の切り抜き（`PlacedClip`）を持つ（設計を追随）。`Transformed` の切り抜きが画面に正しく出るかは 5.1／5.2 で確かめる。係のテストは「置き場が Embedded のまま相だけ変わる回」と「`VisualTransform` の外れでの当て直し」を通していない（鍵の純粋なテストが同じ分岐を覆う）
- 5.1: WARP の写しは WUC の振る舞いを仮定する（切り抜きは Visual の局所の空間・`CompositionClip.TransformMatrix` は図形に掛かる・回した Visual は線形で標本化）。本物の `render_surface` の係は回していない（`replay_transform` と `compose_planned` の道だけ）。5.2 の実 GPU で WUC の値を読み戻して仮定を確かめる。端数の位置の手動の持ち主は縁がにじむ（前からの振る舞い・この spec の外）
- 5.2: 実 GPU のテスト（`tests/graphics/surface_embedding_test.rs`）は HWND も画面も使わない普通のテストで、机は要らない。描画面の画素は `CopySurface` でなく既存の `SurfaceReadback::read_all`（WUC の描画面へ写す元の描画面ごとの絵）で読む。WUC が `CompositionClip.TransformMatrix` を図形に掛けることは値の読み戻しと逆行列の往復までで、画面の画素では確かめていない（討議の確定 6 で画面を読まないため）
