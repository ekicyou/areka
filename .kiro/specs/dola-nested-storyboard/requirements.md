# Requirements Document

## Introduction

dolaクレートのストーリーボードに、他のストーリーボードを起動（トリガー）する機能を追加する。
現在のストーリーボードはアニメーション変数へのトランジション適用のみを行うが、
本機能により「あるストーリーボードの特定キーフレーム到達時に別のストーリーボードを開始する」
といったオーケストレーションが宣言的に記述可能になる。

これにより、複雑なアニメーションシーケンス（例: 表情切り替え → 吹き出し表示 → テキスト流し込み）を
個別のストーリーボードとして分離・再利用しつつ、1つのストーリーボードから連鎖的に起動できる。

## Project Description (Input)
ストーリーボードの項目に、他のストーリーボードを起動する機能が欲しい。具体的には値としてdolaランタイム自身を指定でき、そこにスタートコマンドを与えるなど。これは1案なので、最適な要件・設計を詰めたうえで実装してください。

## Requirements

### Requirement 1: ストーリーボードトリガーエントリ
**Objective:** アニメーション作成者として、ストーリーボードのエントリから別のストーリーボードを起動したい。これにより、複雑なアニメーションシーケンスを分割・再利用可能な単位で構成できる。

#### Acceptance Criteria
1. When ストーリーボードエントリに `trigger_storyboard` フィールドが指定されている場合, the dola runtime shall エントリの配置時刻（`at`/`between` / 前エントリ連結）に従い、指定されたストーリーボードを起動する
2. The `StoryboardEntry` shall 既存の4配置パターン（前エントリ連結、KF起点、KF間、純粋KF）と同じタイミング解決メカニズムをトリガーエントリにも適用する
3. When トリガーエントリに `variable` と `transition` が同時に指定されている場合, the dola compiler shall バリデーションエラーを返す（トリガーエントリは変数操作と排他）
4. The `StoryboardEntry` shall トリガーエントリに `keyframe` フィールドの指定を許容し、他のエントリからの依存解決に利用可能とする(keyframeはトリガー発火時刻として登録され、再生時間は0秒として扱われる)
5. When トリガー対象のストーリーボード名がドキュメント内に存在しない場合, the dola compiler shall バリデーションエラーを返す

### Requirement 2: トリガー実行とランタイム統合
**Objective:** ランタイム利用者として、トリガーされたストーリーボードが親ストーリーボードの再生フロー内で自動的に開始されてほしい。手動で start() を呼ぶ必要がなくなり、宣言的なオーケストレーションが実現される。

#### Acceptance Criteria
1. When ランタイムの `update()` がトリガーエントリの配置時刻に到達した場合, the dola runtime shall 指定されたストーリーボードの `start()` を自動的に実行する
2. When トリガーされたストーリーボードの `start()` が競合（`RuntimeError::Conflict`）を返した場合, the dola runtime shall エラーを無視せず、呼び出し元の `update()` 結果にエラー情報を含める
3. The dola runtime shall トリガーされたストーリーボードを独立したインスタンス（独自の `group_id`）として管理し、親ストーリーボードのライフサイクルから独立させる（並行起動：Fire-and-forget semantics）
4. When 親ストーリーボードがキャンセルまたは中断された場合, the dola runtime shall トリガー済みの子ストーリーボードのライフサイクルに影響を与えない（独立動作の保証）
5. The dola runtime shall トリガーの実行結果（`group_id` や `end_time`）を `update()` の返却値に含め、呼び出し元がトリガーされたインスタンスを追跡可能とする

### Requirement 3: コンパイル時バリデーション
**Objective:** アニメーション作成者として、トリガー定義の誤りをコンパイル時に検出したい。ランタイムエラーではなく早期の静的検証により、デバッグ効率が向上する。

#### Acceptance Criteria
1. When トリガーエントリが自身のストーリーボードを直接参照している場合, the dola compiler shall 自己参照エラー（直接再帰）を報告する
2. When トリガーエントリのチェーンが循環を形成する場合（A→B→C→A）, the dola compiler shall 循環参照エラーを報告する
3. The dola compiler shall トリガーエントリを「再生時間0秒」として扱い、`total_base_duration` 計算に影響を与えない(トリガーは開始指示のみで待機しない)
4. When トリガーエントリに `from` / `to` / `easing` / `duration` 等のトランジション固有フィールドが指定されている場合, the dola compiler shall バリデーションエラーを返す
5. The dola compiler shall 既存の `DolaError` 列挙体にトリガー関連のエラーバリアントを追加し、エラーメッセージにトリガー元・トリガー先のストーリーボード名を含める

### Requirement 4: 宣言的フォーマット対応
**Objective:** アニメーション作成者として、JSON/TOML/YAML でトリガーエントリを直感的に記述したい。既存のストーリーボードフォーマットと一貫性のある構文であることが重要。

#### Acceptance Criteria
1. The dola crate shall JSON/TOML/YAML のすべてのサポートフォーマットでトリガーエントリのシリアライズ・デシリアライズを提供する
2. The トリガーエントリ shall 最小構成として `trigger_storyboard` フィールド（文字列: ストーリーボード名）のみで記述可能とする
3. Where オプションの `trigger_start_offset` フィールドが指定されている場合, the dola runtime shall トリガー時刻に対する相対オフセット（f64秒）を開始時刻として適用する
4. The トリガーエントリ shall 既存エントリの `at` / `between` / `keyframe` フィールドと組み合わせ可能とし、タイミング制御の柔軟性を維持する(注記:`keyframe`はトリガー発火時刻を表し、再生時間0秒として扱われる)
5. The dola crate shall `Storyboard::entry` の配列内で、トリガーエントリと既存のトランジションエントリを任意の順序で混在可能とする

### Requirement 5: ループとの相互作用
**Objective:** アニメーション作成者として、ループするストーリーボード内のトリガーがどう振る舞うか明確に理解したい。予測可能な動作が必要。

#### Acceptance Criteria
1. When `loop_count` >= 2 のストーリーボード内にトリガーエントリが存在する場合, the dola runtime shall 各ループ反復ごとにトリガーを再実行する
2. When `loop_count` = -1（無限ループ）のストーリーボード内にトリガーエントリが存在する場合, the dola runtime shall 各ループ反復ごとにトリガーを実行する
3. The dola runtime shall トリガーによって起動された子ストーリーボードのループ回数を、親のループ設定から独立して扱う
4. When 前回のループで起動した子ストーリーボードがまだ再生中の場合, the dola runtime shall 新たなトリガー実行時に通常の競合解決（`InterruptionPolicy`）に従って処理する

## 制約事項と設計選択

### トリガーの「0秒完了」原則
トリガーエントリは**他のストーリーボードの開始指示を発火する行為**のみを表現する。
この行為は瞬間的(再生時間0秒)であり、以下の特性を持つ:

- **keyframeの意味**: トリガー発火時刻として登録される(子の再生時間は考慮されない)
- **決定論的動作**: コンパイル時に全keyframe時刻が確定可能
- **既存メカニズムとの整合**: 純粋keyframeエントリと同じく、再生時間を持たないタイミングマーカーとして機能

#### 制約と責任分離
- ✅ 対応範囲内: 
  - 並行起動(Fire-and-forget)による複数ストーリーボードのオーケストレーション
  - 決定的タイミング制御(at/between/keyframe)
  - ループ内でのトリガー再実行
- ❌ 対応範囲外: 
  - 子ストーリーボードの終了待機(Await/シーケンシャル起動)
  - 子の再生時間を考慮したkeyframe登録
  - トリガー先の動的条件分岐
- 📋 代替手段: 
  - 複雑な同期制御や条件付き起動はdolaランタイムの外側(呼び出し側アプリケーション)で管理
  - 子の終了を待つ場合は、呼び出し側で `end_time` を監視し次の `start()` を呼ぶ

#### Fire-and-forget semantics
トリガーされた子ストーリーボードは独立したインスタンス(`group_id`)として並行起動され、親のタイムライン進行をブロックしない。親ストーリーボードの `total_base_duration` 計算に子の再生時間は**一切含まれない**。
