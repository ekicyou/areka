- [ ] 2. areka: キャラクター窓での開始・終了の捕まえ方

- [ ] 2.1 開始の受け手・終了の包み・共通の送出と、キャラクター窓への付け替え
  - `input_events` の子に新しいファイルを 1 本作り、design.md の 3 つの部品を置く: Bubble の相でだけ送る開始の受け手／どの相でも先に位置の保存の受け手を同じ引数で呼び、その戻り値を返し、Bubble の相でだけ送る終了の包み／送出の共通部
  - 共通部は、対象が別の窓・`MouseWiring` なし・スコープなし・窓の位置なしの 4 つを、その順に `mouse_drag_dropped`（理由と種類つき。`no_wiring` だけ debug、ほかは warn）で記録して戻る。それ以外は「画面の位置 − 窓の位置」で当たり判定を引き、移動の間引きを通らずに `KanadeMsg::Mouse` を送る。送出に失敗したら既存の `mouse_send_failed` を `kind = drag_start`／`drag_end` で出す
  - 終了の包みは取り消しかどうかを見ない。座標は位置の保存を呼んだ後の窓の位置から引く（決定 D1）
  - キャラクター窓にポインタの受け手を付ける所で、開始の受け手と終了の包みを同じ `insert` で入れる。`placement::spawn` が先に付けた終了の受け手を置き換えること、順を入れ替えないことを doc に書く。バルーン窓には何も付けない
  - areka のビルドが通り、既存の areka のテスト（位置の保存のテストを含む）が緑のまま
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.5, 3.3, 4.2, 4.4, 4.5, 6.1, 6.2, 8.2_

- [ ] 2.2 テストの土台と、届く・届かないの基本のテスト

- [ ] 2.3 終了の座標と位置の保存のテスト

  - A4: 開始 → 窓を別の位置へ動かし、窓の位置が開始と違うことを確かめる → 取り消しの終了。窓が開始の位置へ戻り、終了が 1 件届き、座標と当たり判定が開始と同じ値

  - 3 本が緑で、保存の前に座標を引く形にすると A4・A6 が赤、保存を呼ばない形にすると A7 が赤になる
