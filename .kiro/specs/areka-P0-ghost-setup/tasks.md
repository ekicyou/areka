- [ ] 2. Core: ghost 結線コンポーネントの実装

  - _Depends: 1.5_

- [x] 2.2 (P) 差し替え可能な時刻供給コンポーネントを実装する

  - 大幅な遅延で複数の境界を跨いだ場合は各系統1回のみ配り、次の境界へスナップする
  - 時計そのものを差し替え可能にし、決定論テストでは起動せず外部からの直接投函に道を譲れるようにする
  - 発火判定（どの境界を打つか・次はいつか）を独立した検証可能な処理として切り出す
  - 観測可能な完了条件: 境界整列・複数境界スキップ・時計注入の各挙動が単体テストで緑

  - _Boundary: ghost::ticker_
  - _Depends: 1.5_

- [x] 2.3 (P) 運行設定の値源解決コンポーネントを実装する

- [ ] 3. Integration: 起動・終了統括とアプリ結線
- [x] 3.1 起動手順を組み上げる
  - マウント解決から各コンポーネントの起動までを正しい順序で結線し、開始状態にする
  - 運行設定の値源解決を経て、各コンポーネントへ供給する
  - マウント解決に失敗した場合は起動を打ち切り、失敗内容を呼び出し側へ返す
  - 観測可能な完了条件: 正常な起動の一連の流れが結合テストで確認でき、マウント失敗時は起動が安全に打ち切られる

  - _Boundary: ghost::runtime_
  - _Depends: 1.5, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6_

- [x] 3.2 終了統括を実装する
  - 終了要求を受けたら、常駐コンポーネントを段階的に停止させたのち残りを一括で後始末する（一部を先に明示停止させ、残りは接続の手放しに任せることで、循環した接続関係でも確実に停止できるようにする）
  - 各段の停止失敗は記録した上で処理を続け、最終的にまとめて呼び出し側へ伝える
  - 全ての後始末が終わったら正常終了とみなす
  - テストや上級用途向けに、統括対象を分解して個別操作できる手段も用意する
  - 観測可能な完了条件: 正常な起動〜終了の一連の流れが結合テストで確認できる
  - _Requirements: 6.1, 6.4, 6.5_
  - _Boundary: ghost::runtime_
  - _Depends: 3.1_

- [x] 3.3 アプリ本体へ起動と終了を結線する

  - アプリ終了時に ghost 結線層の終了統括を実行する
  - 既存のダミー窓生成・スモークゲートの挙動は変更しない
  - 観測可能な完了条件: 既存のアプリスモークテストが結線追加後も変わらず成功する
