> 本 spec の成果物は文書である（台帳 1 本・ブリーフィング 1 本・報告 1 本の再生成・ソースの正典 URL 1 行コメント）。areka の実行時の振る舞いは変えない。`crates/` にテストを足さない。生成と検査に使うスクリプトと作業記録は `crates/` の外の作業用ディレクトリに置き、成果物としてコミットしない。
> **上流の道具は 2026-09-05 に main へ着地した**（`crates/ukadoc-survey`・`doc/ukadoc-coverage/` 一式）。台帳 `assets.toml` は 542 項目の骨組みが既に並んでいるので**その場で値を書き換えるだけ**であり、形式・id・並び順・語彙の検査は `cargo test -p ukadoc-survey` と `cargo run -p ukadoc-survey -- check` に任せる。自前で書くのは上流が見ていない分だけ（設計 §11 の W1〜W8）。
> 台帳 `doc/ukadoc-coverage/ledger/assets.toml` は**全群が書き込む唯一の集約ファイル**なので、台帳へ書くタスクには `(P)` を付けない（同時編集で取り合いになる）。並行できるのは台帳に触れない作業だけである。
> **台帳が確定してから URL とブリーフィングへ進む**（依存は一方向）。群 5 以降で台帳の状態を書き換えることはしない。
> タスクをまたいで渡す作業記録は、作業用ディレクトリの下に名前を決めて置く——縮退の転記元は `degraded-sources.md`、検査の較正結果は `check-calibration.md`、URL を置く前のテスト結果は `pretest-baseline.txt`。
