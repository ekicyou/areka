# Implementation Plan

> 順序は design.md「実装の順序（赤を先に見せるため）」に従う。1 は修正前の HEAD で書いて赤（または緑のまま）を確かめる。2 で修正と、形に依存するテストの更新を入れて全部を緑にする。3 は実機と全体テスト。

- [x] 1. 修正の前に赤になる決定論テストを立てる（`FlushResult` の形に依存させない）
  - 1.x の完了時点で、ここで足したテストのうち「修正前は赤」と書いたものは意図して赤のまま残す。製品コード（`accumulator.rs`・`dispatch.rs`）は変えない。レビューは「赤であること・赤の理由が設計どおりであること」を合格の条件とする
- [x] 1.1 (P) 左解放を wndproc の経路で配るテストを wintf に足す
  - 左ボタンを押して準備に入った窓で、閾値に届かずに離して 1 回配ると、終了の知らせが 0 件で、ドラッグの状態は離しの印つきの休む状態になることを確かめる
  - 閾値を越えた（開始の種を手で積んだ）窓で離して 1 回配ると、開始の知らせと終了の知らせが 1 件ずつ届き、状態は休む状態になることを確かめる
  - 知らせの件数は配る処理を 1 回呼んだ後の知らせの箱を読み出して数え、累積器の返す形には触らない。テストの窓には窓の印を持たせ、予備の枝の窓の一致を通す
  - 新しいテストは本番ファイルの兄弟ファイルに置き、本番ファイルの末尾にテストの登録だけを足す。製品コードは変えない
  - 修正前の HEAD で 1 本目は終了 1 件で赤・2 本目は開始 0 件で赤（終了 1 件は修正前から満たす）になることを実行して確かめ、新しいテストファイルが 1,000 行以下の状態
  - _Requirements: 3.1, 3.3, 3.4, 3.5, 5.2, 5.5, 5.6_
  - _Boundary: C3（mouse_click のテスト）_
- [x] 1.2 (P) 準備中の取り消しで終了を配らないテストを wintf のキーボードのテストに足す
  - 準備に入った窓へ ESC・メニューやダイアログの割り込み・捕捉の喪失をそれぞれ配り、1 回配ると終了の知らせが 0 件で、状態は取り消しの印つきの休む状態になることを確かめる 3 本
  - 準備中の非活性化で終了の知らせが 0 件であることを確かめる 1 本
  - 既存のテストはこのタスクでは触らない（形に合わせる直しは 2.1）。製品コードは変えない
  - 修正前の HEAD で取り消しの 3 本が赤・非活性化の 1 本が緑であることを実行して確かめ、テストファイルが 1,000 行以下の状態
  - _Requirements: 3.2, 3.5, 5.2, 5.6_
  - _Boundary: C3（keyboard のテスト）_
- [x] 1.3 (P) 速いドラッグで開始 → 終了の順に両方が届くテストを wintf の配る所のテストに足す
  - 開始と終了の種を続けて積み、配る処理を 1 回呼ぶと、開始の知らせ 1 件・終了の知らせ 1 件が届き、受け手が記録した並びが「開始 → 終了」で、配り終えた時点でドラッグ中の記録と印が外れていることを確かめる
  - 製品コードは変えない
  - 修正前の HEAD で赤（開始 0 件）になることを実行して確かめ、テストファイルが 1,000 行以下の状態
  - _Requirements: 3.4, 5.4, 5.6_
  - _Boundary: C3（wintf/tests の配る所のテスト）_
- [x] 1.4 (P) 知らせの経路から保存までを通すテストを areka に足す
  - キャラクターの窓とバルーンの窓（素材の確認用にキャラクター側へキーワードで決めたバルーンの位置の素材を付ける）、偽の記憶の書き手、知らせの箱を入れた World を組み、累積器へ種を積んで配る処理を呼ぶ形で駆動する
  - 動かさないクリック（キャラクター・バルーン）と準備中の取り消しで、保存 0 件・窓の位置が変わらない・素材が残ることを確かめる 3 本（修正前は赤）
  - 速いドラッグで、キャラクターの窓が行き先へ置かれ、その位置が 1 件保存されることを確かめる 1 本（修正前は赤）。期待値が偽の窓の座標変換の失敗に寄りかかることをコメントに書く
  - 本物のドラッグ（キャラクター・バルーンで 1 件ずつ保存・素材が外れる）と閾値を越えた後の取り消し（今どおり 1 件）の 2 本（前後とも緑）
  - 新しいテストは兄弟ファイルに置き、配置の親モジュールのテスト登録の並びに足す。900 行を超えそうなら速いドラッグと本物のドラッグの 3 本を 2 つ目の兄弟ファイルへ分ける。分けるかどうかの判断と、2 つのファイル・2 行の登録はどちらもこのタスクが受け持つ。製品コードは変えない
  - 修正前の HEAD で赤 4 本・緑 2 本になることを実行して確かめ、各テストファイルが 1,000 行以下の状態
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.1, 2.2, 2.3, 2.5, 5.1, 5.3, 5.4, 5.6_
  - _Boundary: C4_

  - 知らせの種の置き場を 1 枠から積んだ順の待ち行列にし、取り出すと空になるようにする。取り出しの結果も全件を積んだ順で返す
  - 開始を積んでいないドラッグの終了の種は置かず、対象と離しか取り消しかを添えた debug の記録を 1 行残す。開始を積んだ後の終了は今どおり置く
  - ドラッグ中の対象の欄の説明を「開始を積んでから終了を積むまで値がある」に直す
  - 配る所は取り出した種を積んだ順にすべて処理する。各腕の中身とその後の移動の知らせは変えない
  - 累積器の中にある既存テスト 7 本を兄弟ファイルへ移して新しい形に合わせ、開始の無い終了を捨てること・1 回の取り出しで開始 → 終了・終了 → 開始の順が保たれることのテスト 3 本を足す。キーボードのテストの既存 1 本も新しい形に合わせる
  - wndproc のハンドラ・状態機械・areka の受け手は変えない
  - `cargo test -p wintf --lib` が緑で、1.1・1.2 で赤だったテストが名前ごと緑になり、累積器の本番ファイルと新しいテストファイル・キーボードのテストファイルがどれも 1,000 行以下の状態
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.1, 2.2, 2.3, 2.5, 3.1, 3.2, 3.3, 3.4, 3.6, 4.4, 5.6_

## Implementation Notes

- 1.1: 素の `EcsWorld` に `Window::default()` を付けると `on_window_add` が `WindowPos::default()`（CW_USEDEFAULT）を入れるので、知らせの位置は i32::MIN 付近になる（設計 C3 の「画面座標＝クライアント座標」は成り立たない）。位置を確かめるテストは自分で `WindowPos` を入れること。`mouse_click.rs` は CRLF。
- 1.4: areka のテストの窓には `Window::default()` も付けた（設計 C4 の部品の列挙の外）。開始の腕が窓を見つけて偽の HWND の座標変換に実際に失敗し、inset (0,0) が C4 の根拠どおりの経路で出るため。`WindowPos` は明示。`smoke_boot_loop_exit` は i686 の補助の成果物が無いと落ちる（環境由来・`tools/test-all.ps1` が先に建てる）。
