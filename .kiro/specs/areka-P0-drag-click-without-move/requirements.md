# Requirements Document

## Project Description (Input)
キャラクターの絵の上を、動かさずに左クリックしただけで、その窓の位置が記憶に書かれる。次の起動からは「既定の配置」でなく「保存した位置」として読み戻される。初回の起動で台詞が相方をずらした（初回だけの位置合わせ）後に利用者が相方を 1 回クリックすると、ずらした位置が保存され、「初回だけの位置合わせは保存しない」（`alpha-release-signoff` の項目 12・2026-10-01 に開発者が確定）がクリック 1 回で崩れる。原因は、wintf が左ボタンを離したとき、ドラッグの閾値（既定 5 px）に届かず動かし始める前のままでも、ドラッグの終了の知らせを配ること（開始の知らせの無い終了）と、areka のキャラクターの終了の受け手が、ドラッグの開始時の記録が無いと今の窓の位置へ縮退して必ず保存すること。バルーンの終了の受け手も同じ知らせだけを見て相対位置を保存する。窓の位置（キャラクター・バルーン）を記憶へ書くのは掴んで動かして離したときだけにし、動かさないクリック・ダブルクリック・右クリックの前の左クリックでは書かない。多窓のときに開始時の記録が先に落ちても、本当にドラッグした窓の位置は今どおり保存する。根本を 1 か所で直し、1 フレーム遅らせる解は取らず、直す前に赤になる決定論のテストを立てる。種別はバグ。

## Introduction

窓の位置の記憶は「利用者が掴んで動かし終えたとき」にだけ書かれる決まりである（完了 spec `areka-P0-position-persist` 要件 1.9「利用者の明示的なドラッグの確定によってのみ更新する」）。ところが今は、動かさないクリックでも位置が書かれる。`alpha-release-signoff` の実機の一周では、窓を動かしていない保存の記録が 3 件あり（A1r・A2r）、3 件とも走行の中でドラッグの開始の知らせが 0 件だった。本当に掴んで動かした 1 件（A3r）だけが開始の知らせを伴っていた。

利用者から見える症状は次のとおり。

- キャラクター（本体・相方）の絵を動かさずにクリックすると、そのときの位置が記憶に書かれ、次の起動からは既定の配置でなくその位置に立つ。
- 初回の起動で台詞が相方をずらした後に相方をクリックすると、ずらした位置が保存され、2 回目の起動でも相方がずれたままになる。
- バルーンでも同じことが起こりうる（未観測・静的には同じ形）。動かさないクリックで相対位置が書かれ、キーワードで決めたバルーンの位置の素材が退役する。

根は、ドラッグの終了の知らせが「動かし始める前に離した」場合にも配られることにある。完了 spec `event-drag-system` 要件 4.1 は終了の知らせを「ドラッグ中にボタンが離されたとき」に配ると定めており、動かし始める前の離しは対象ではない。同じ wintf の中でも、窓の非活性化による取り消しは既に動かし始める前の状態を除いている。本 spec は、終了の知らせの出し方を「開始の知らせを配ったドラッグにだけ終了の知らせを配る」へ揃えて根本を 1 か所で直す。これにより areka の 2 つの終了の受け手（キャラクター・バルーン）は動かさないクリックで呼ばれなくなり、キャラクター側の縮退（開始時の記録が先に落ちても現在の位置を保存する）は変えずに残せる。

## Boundary Context

- **In scope**:
  - 動かさないクリック（単独のクリック・ダブルクリック・右クリックの前の左クリック）で、キャラクターの窓の位置とバルーンの相対位置を記憶へ書かないようにする修正。
  - 動かし始める前のドラッグの準備が、ESC キー・メニューやダイアログの割り込み・マウスの捕捉の喪失で取り消された場合も、同じく書かないようにする修正（窓の非活性化による取り消しは既にそうなっている）。
  - ドラッグの終了の知らせを、開始の知らせを配ったドラッグにだけ配るという、wintf の知らせの約束の整理。
  - 決定論の自動テストと、実機での確かめ（初回の位置合わせの後に相方をクリック → 次の起動で既定の配置）。
  - 完了 spec の要件を上書きする場合の `doc/COMPAT_ARCHITECTURE.md` §8 への記録。
- **Out of scope**:
  - ドラッグの閾値の値（既定 5 px）の変更。
  - ドラッグ中の窓とバルーンの追従の作り。
  - 初回だけの位置合わせそのもの（台詞が相方をずらす規則）。
  - 位置の記憶の形式・保存先。
  - 閾値を越えた後に取り消されたドラッグの扱い（今は取り消しでもその時点の位置を保存する。これは変えない）。
  - 右クリックメニューの出し方、ドラッグの状態が離した後に休む決まり（完了 spec `areka-P0-wintf-drag-state-rest-contract` の決め）。
  - 拡大率の切替での位置の扱い（`areka-P0-dpi-transition-two-tick-bounce` の範囲）。
  - 同じウェーブの他の spec との約束により、`crates/areka/src/emo2_boot/`・`crates/areka/src/input_events/`・`crates/areka/src/install/` には触らない。
- **Adjacent expectations**:
  - 右クリックメニューの引き金（`areka-P0-popup-menu-minimal`・`areka-P0-wintf-drag-state-rest-contract`）は、知らせでなくドラッグの状態を読む。本 spec はドラッグの状態の移り変わり（押して準備 → 離して休む）を変えないので、右クリックメニューの出方は変わらない前提で進める。
  - ゴーストへ伝わるマウスのイベント（クリック・ダブルクリックなど）は、ドラッグの終了の知らせとは別の経路で伝わる。本 spec はそれらを変えない。
  - 位置の記憶へ書く唯一の観測点がドラッグの終了であること（完了 spec `areka-P0-position-persist` 要件 1.9）は保ち、その観測点が動かさないクリックで発火しないようにする。

## Requirements

### Requirement 1: 動かさないクリックでは窓の位置を記憶へ書かない

**Objective:** As a areka の利用者, I want キャラクターやバルーンをクリックしただけでは位置が記憶されないこと, so that 次の起動で、意図して動かしていない窓が思わぬ位置に立たない

#### Acceptance Criteria

1. When 利用者がキャラクターの窓を左ボタンで押し、ドラッグの閾値に届く距離を動かさないまま離したとき, the areka shall その窓の位置を記憶へ書かない（位置の保存の記録 `areka::persist::save` は 0 件）。
2. When 利用者がバルーンの窓を左ボタンで押し、ドラッグの閾値に届く距離を動かさないまま離したとき, the areka shall そのバルーンの相対位置を記憶へ書かず、キーワードで決めたバルーンの位置の素材も退役させない。
3. The areka shall 前 2 項を、1 回のクリック、ダブルクリックの各回、右クリックの手順に先立つ左クリックのいずれにも同じく適用する。
4. When 前各項のクリックが終わったとき, the areka shall キャラクターとバルーンの窓をクリックの前の位置から動かさない。
5. If 動かし始める前（閾値に届く前）のドラッグの準備が、ESC キー・窓の非活性化（Alt+Tab など）・メニューやダイアログの割り込み・マウスの捕捉の喪失のいずれかで取り消されたとき, then the areka shall 窓の位置とバルーンの相対位置を記憶へ書かない。

### Requirement 2: 掴んで動かして離したときは今どおり保存する

**Objective:** As a areka の利用者, I want 本当に窓を動かしたときは、今までどおりその位置が覚えられること, so that 修正によって、動かした位置が次の起動で失われない

#### Acceptance Criteria

1. When 利用者がキャラクターの窓を掴み、閾値を越えて動かして離したとき, the areka shall その窓の最終位置を記憶へ 1 件書く（1 回のドラッグにつき書き込み 1 件）。
2. When 利用者がバルーンの窓を掴み、閾値を越えて動かして離したとき, the areka shall そのバルーンの相対位置を記憶へ 1 件書き、キーワードで決めたバルーンの位置の素材を今どおり退役させる。
3. When 押してから閾値を越えて動かし、離すまでが 1 回の画面更新の間に収まったとき（速いドラッグ）, the areka shall それを動かさないクリックと取り違えず、前 2 項と同じく位置を記憶へ 1 件書く。
4. While 複数の窓があり、ドラッグの終了を受け取る時点で、そのドラッグの開始時に記録した情報が先に失われているとき, the areka shall 閾値を越えて動かされたその窓の現在の位置を記憶へ 1 件書く（今の縮退を保ち、ドラッグした窓の位置を落とさない）。
5. When 閾値を越えて動かした後のドラッグが、ESC キーなどで取り消されたとき, the areka shall 今の振る舞い（取り消しでも、その時点の位置を記憶へ書く）を変えない。

### Requirement 3: ドラッグの終了の知らせは、開始の知らせを配ったドラッグにだけ配る

**Objective:** As a wintf を使う開発者, I want ドラッグの終了の知らせが、必ずそれに先立つ開始の知らせと対になって届くこと, so that 終了の受け手が「本当にドラッグしたか」を自分で見分けなくてよい

#### Acceptance Criteria

1. When 左ボタンが押されてから閾値に届かないまま離されたとき, the wintf ドラッグ機能 shall ドラッグの終了の知らせを配らない。
2. If 閾値に届く前のドラッグの準備が、ESC キー・メニューやダイアログの割り込み・マウスの捕捉の喪失・窓の非活性化のいずれかで取り消されたとき, then the wintf ドラッグ機能 shall ドラッグの終了の知らせ（取り消しの印つきのものを含む）を配らない。
3. When 閾値を越えたドラッグが、離す・取り消しのいずれかで終わったとき, the wintf ドラッグ機能 shall 今どおり終了の知らせを 1 回配る。開始と終了が 1 回の画面更新の中に重なった場合も、終了の知らせを落とさない。
4. The wintf ドラッグ機能 shall ドラッグの状態の移り変わり（押して準備に入り、離すと休む状態へ移る）と、離したときのマウスの捕捉の解放を、閾値に届いたかどうかに関わらず今どおり行う。
5. When 閾値に届かないまま離された、または取り消されたために終了の知らせを配らないと判定したとき, the wintf ドラッグ機能 shall その判定（対象の窓・離しか取り消しか）を debug の記録に 1 行残す。

### Requirement 4: 初回だけの位置合わせが守られ、ほかの振る舞いは変えない

**Objective:** As a areka の利用者, I want 初回の起動で台詞がずらした相方をクリックしても、次の起動では既定の配置に戻ること, so that 初回だけの演出が、何気ないクリックで以後ずっと残らない

#### Acceptance Criteria

1. When 初回の起動で台詞が相方をずらした後、利用者が相方を動かさずにクリックし、そのまま終了して再び起動したとき, the areka shall 2 回目の起動で相方を既定の配置に立たせる。
2. The areka shall 右クリックメニューの出方（左クリックの後の右クリックを含む）を、本 spec の修正によって変えない。
3. The areka shall クリック・ダブルクリック・右クリックをゴーストへ伝える今の振る舞いを、本 spec の修正によって変えない。
4. The areka shall ドラッグの閾値の値、ドラッグ中の窓とバルーンの追従、初回だけの位置合わせの規則、位置の記憶の形式を、本 spec の修正によって変えない。

### Requirement 5: 検証と記述の追随

**Objective:** As a 開発チーム, I want 穴が塞がったことと、本物のドラッグの保存が崩れていないことを決定論のテストと実機で示すこと, so that 同じ穴が再び入り込めば赤で気付ける

#### Acceptance Criteria

1. The 開発チーム shall 動かさないクリックでキャラクターの位置の保存が 0 件であることと、バルーンの相対位置の保存が 0 件かつキーワードで決めたバルーンの位置の素材が残ることを確かめる決定論の自動テストを用意し、それらが修正の前に失敗し、修正の後に通ることを確かめる。
2. The 開発チーム shall 閾値に届かないまま離したとき、および閾値に届く前に ESC キー・メニューやダイアログの割り込み・マウスの捕捉の喪失で取り消したときに、ドラッグの終了の知らせが 0 件であることを確かめる決定論の自動テストを用意し、修正の前に失敗し、修正の後に通ることを確かめる（窓の非活性化は今も 0 件なので、修正の前後とも通ることを確かめる）。
3. The 開発チーム shall 閾値を越えたドラッグで保存 1 件（キャラクター・バルーン）、速いドラッグ（要件 2.3）で保存 1 件、開始時の記録が先に失われた多窓の場面（要件 2.4）で保存 1 件、閾値を越えた後の取り消し（要件 2.5）で今どおりの保存になることを確かめる決定論の自動テストを用意し、修正の前後とも通ることを確かめる。
4. The 開発チーム shall 要件 3.4（ドラッグの状態の移り変わりと捕捉の解放）と要件 4.2（右クリックメニューの出方）が崩れていないことを、既存または新しい決定論の自動テストで確かめる。
5. The 開発チーム shall 前各項のテストを注入した入力と画面更新の並びで駆動し、実時間の待機に依存させない。新しいテストは本番ファイルの兄弟ファイルへ置き、本番ファイル・テストファイルのどれも 1,000 行以下に保つ。
6. The 開発チーム shall 実機で、初回の起動で相方がずれた後に相方を動かさずにクリックし、終了して再び起動したとき、相方が既定の配置に立つこと（要件 4.1）と、その走行で位置の保存の記録が 0 件であることを確かめる。このとき記録の level を、位置の保存（`areka::persist::save`）・ドラッグの終了の受け手・要件 3.5 の判定の記録の debug まで開け、実機の根と一時フォルダはワークツリーの `target\` の下だけに置く。
7. Where 本 spec の修正が完了 spec の要件と食い違うとき, the 開発チーム shall その上書きを `doc/COMPAT_ARCHITECTURE.md` §8 へ記録し、完了 spec のアーカイブ本体は書き換えない。
8. When 本 spec の完了を判定するとき, the 開発チーム shall ワークスペース全体のテストが緑であることを確かめる。
