# Requirements Document

## Project Description (Input)

- **だれが困っているか**: areka の利用者。本体だけをドラッグして終了し、起動し直すと、本体は動かした位置に立つが、相方まで動く。前回閉じたときに見えていた並びで立ち上がらない（開発者 2026-10-05「初回起動時に位置保存されていないということ？それはちょっと不自然」）。
- **今の状況**: キャラクター窓の位置を記憶（ゴーストごとの保存先）に書くのは、ドラッグの終了だけ。終了するとき・起動の最後に並べ終えたとき・SHIORI の移動の指示（`\![move]` など）で動いたときは書かない。そのため一度もドラッグしていないキャラクターの位置は記憶に無く、相方は起動のたびに既定の位置から始まり、起動の最後に本体の左隣へ並べ直される（完了 spec `areka-P0-mouse-drag-events` の実機 R7 で観測）。
- **何を変えるか**: 正常に終了したとき、表示している全部のキャラクター窓の位置を記憶に書き、次の起動で同じ並びに立つようにする。書く時機を、完了 spec `areka-P0-position-persist` の規律（要件 1.9＝利用者のドラッグの確定でだけ書く）と突き合わせて改め、改めた内容を記録に残す。きれいに終わらなかった回の扱いも決める。決定論のテストで「本体だけ動かして終了 → 再起動で相方も前回の位置」を固定し、実機で確かめる。

出どころは `brief.md`（2026-10-05・`/kiro-discovery`）。段は**バグ**。

## Introduction

areka は、利用者がドラッグで動かしたキャラクター窓の位置をゴーストごとに覚え、次の起動でその位置に立たせる。ところが覚えるのはドラッグを終えた瞬間だけなので、一度もドラッグしていないキャラクターの位置は覚えていない。本体だけを動かして終了すると、次の起動で相方は既定の位置から本体の隣へ並べ直され、前回閉じたときの並びと違う並びで立ち上がる。

この spec は、正常に閉じるときに、表示している全部のキャラクター窓の位置を覚える口を 1 つ足す。これで「閉じたときに見えていた並びで次も立ち上がる」が、ドラッグしたかどうかに関わらず成り立つ。あわせて、位置を覚える時機の規律（完了 spec `areka-P0-position-persist` の要件 1.9）を「ドラッグの確定だけ」から「ドラッグの確定と正常に閉じるとき」へ改める。

書く時機の候補は 3 つあった（正常に閉じるとき・起動の最後に並べ終えたとき・SHIORI の移動の指示の後）。この要件は**正常に閉じるとき**だけを採る。閉じるときに書けば、起動の最後の並べ直しや SHIORI の指示で動いた結果も、閉じた時点の位置としてまとめて覚えられる。残りの 2 つは、きれいに終わらなかった回にしか差が出ないうえ、自動で決まった途中の位置を利用者の意図として覚えてしまうので採らない。

## Boundary Context

- **In scope**: 正常に閉じるときに全部のキャラクター窓の位置を記憶に書くこと／次の起動でその位置に立つこと／位置を書く時機の規律の改訂とその記録／きれいに終わらなかった回と書き込みの失敗の扱い／決定論のテストと実機の確認。
- **Out of scope**: 位置を戻すときの規則（画面の外に出る位置を画面の中へ寄せる補正・吸着の規則など。完了 spec `areka-P0-position-persist` の要件 1.4〜1.8・5 のまま）／バルーンの相対位置の保存（今のまま＝バルーンのドラッグの確定で書く）／記憶に位置が無いキャラクターの、起動の最後の並べ方そのもの／記憶の保存先・形式・書き込みの安全さ（統一プロパティシステムの持ち分）／3 体目以降のキャラクター窓を出すこと（`extra-character-windows`）。
- **Adjacent expectations**:
  - ドラッグの確定で位置を書く今の動きは変えない（完了 spec `areka-P0-position-persist` の要件 1.1）。
  - 「正常に閉じる」の範囲と順序は、完了 spec `areka-P0-app-lifetime-separation`（正規の終了）と `areka-P0-session-running-mark`（起動中の印・Windows の終了時の後始末）が決めたものを使う。この spec は終了の順序を変えず、そこに位置を書く口を足すだけにする。
  - きれいに終わらなかった次の起動が既定のゴーストで始まること（`areka-P0-session-running-mark`）は変えない。
  - `extra-character-windows` が 3 体目以降の窓を出すようになったら、その窓も同じ口で書かれる（キャラクターの数を 2 体に決め打ちしない）。

## Requirements

### Requirement 1: 正常に閉じるときに全部のキャラクター窓の位置を覚える

**Objective:** As an areka の利用者, I want 閉じたときに表示されていた全部のキャラクターの位置が覚えられること, so that 一度もドラッグしていないキャラクターも、次の起動で前回と同じ場所に立つ

#### Acceptance Criteria

1. When areka が正常に終了するとき, the areka shall その時点で表示している全部のキャラクター窓の位置を、キャラクター（本体・相方など）ごとに区別して、そのゴーストの記憶に書く。
2. The areka shall 要件 1.1 で書く対象を、その回に利用者がドラッグしたかどうかで分けない（一度もドラッグしていないキャラクターの位置も書く）。
3. When 起動の最後の自動の並べ直しや SHIORI の移動の指示（`\![move]` など）でキャラクター窓が動いたあとに areka が正常に終了するとき, the areka shall 動いたあとの、閉じる時点の位置を書く。
4. When Windows の終了（ログオフ・シャットダウン）に伴って areka が終了するとき, the areka shall 要件 1.1 と同じく全部のキャラクター窓の位置を書く。
5. When ゴーストの切り替えで今のゴーストを降ろすとき, the areka shall 降ろすゴーストについて、要件 1.1 と同じく全部のキャラクター窓の位置をそのゴーストの記憶に書く。
6. The areka shall 要件 1.1 の書き込みで、位置のほかの記憶（バルーンの相対位置・起動の記録など）を変えない。

### Requirement 2: 次の起動で前回の並びに立つ

**Objective:** As an areka の利用者, I want 起動したとき、前回閉じたときに見えていた並びでキャラクターが立つこと, so that 動かしていないキャラクターまで勝手に動いたように見えない

#### Acceptance Criteria

1. When 正常に終了した次に同じゴーストを起動したとき, the areka shall 全部のキャラクター窓を、前回閉じた時点の位置に立たせる（画面の構成が前回と同じ場合）。
2. When 本体だけをドラッグして正常に終了し、同じゴーストを起動し直したとき, the areka shall 本体をドラッグで動かした位置に、相方を前回閉じた時点の位置に立たせ、相方を本体の隣へ並べ直さない。
3. When 一度もドラッグせずに正常に終了し、同じゴーストを起動し直したとき, the areka shall 全部のキャラクター窓を前回閉じた時点の位置に立たせる。
4. When 記憶に位置が無いキャラクターを起動するとき（初めての起動・記憶を消したあとなど）, the areka shall 今までどおりの既定の並べ方でそのキャラクターを立たせる。
5. The areka shall 記憶にある位置を戻すときの規則（画面の外に出る位置の補正・吸着の規則）を、今のまま変えない。
6. If 記憶にある位置が、そのキャラクターの既定の位置とたまたま同じ値のとき, the areka shall それを記憶にある位置として扱い、そのキャラクターを起動の最後に並べ直さない（「記憶から戻したか」は値の違いでなく、記憶に位置があるかで見分ける。これは位置を戻すときの規則の変更には当たらず、この spec の範囲に入る）。

### Requirement 3: 位置を覚える時機の規律

**Objective:** As a 開発者, I want キャラクター窓の位置を覚える時機が 2 つに限られ、その理由が記録に残っていること, so that 自動で動いた途中の位置が、利用者の決めた位置を知らないうちに上書きしない

#### Acceptance Criteria

1. The areka shall キャラクター窓の位置を記憶に書く時機を、利用者のドラッグの確定と、正常に閉じるとき（要件 1）の 2 つだけにする。
2. While ゴーストが動いている間, the areka shall 起動の最後に並べ終えた時点・SHIORI の移動の指示で窓が動いた時点・画面の構成や作業領域が変わって窓を寄せ直した時点・絵の大きさが変わって窓を置き直した時点では、キャラクター窓の位置を記憶に書かない。
3. If 正常に閉じる時点で、あるキャラクター窓が「記憶にある位置が今の画面に収まらないため、画面の中へ寄せ直して表示されているだけ」（その回に利用者のドラッグでも SHIORI の移動の指示でも動いていない）のとき, the areka shall そのキャラクターの記憶にある位置を書き換えず、前の値を保つ（画面の構成が元に戻った次の起動で、元の位置に立てるようにする。完了 spec `areka-P0-position-persist` の要件 5.4 を保つ）。
4. The areka shall バルーンの相対位置を記憶に書く時機を変えない（バルーンのドラッグの確定だけ）。
5. The areka shall 完了 spec `areka-P0-position-persist` の要件 1.9（利用者のドラッグの確定でだけ書く）をこの要件 3.1〜3.3 で改めたことと、その理由を、位置を書く処理の説明と開発の記録（`doc/COMPAT_ARCHITECTURE.md` の、完了 spec の要件を改めた記録の表。先例は `areka-P0-kero-balloon` の行）に残す。

### Requirement 4: きれいに終わらなかった回と書き込みの失敗

**Objective:** As an areka の利用者, I want 強制終了や書き込みの失敗があっても、それまでに覚えた位置が壊れず、終了も起動も止まらないこと, so that 位置の保存の都合でゴーストが使えなくならない

#### Acceptance Criteria

1. If areka が正常に終わらなかったとき（強制終了・異常終了など）, the areka shall キャラクター窓の位置の記憶を、最後に書かれた値（その回のドラッグの確定で書いたもの、または前の回の正常な終了で書いたもの）のまま残す。
2. When きれいに終わらなかった回のあとにそのゴーストを起動するとき, the areka shall 記憶に位置があるキャラクターをその位置に、無いキャラクターを既定の並べ方で立たせる。
3. If 正常に閉じるときの位置の書き込みが失敗したとき, the areka shall 失敗を記録（ログ）に残し、終了の手順を最後まで進める（終了を止めない・終了の結果を失敗に変えない）。
4. If 正常に閉じる時点で、一部のキャラクター窓の位置を取り出せないとき, the areka shall そのキャラクターを飛ばしたことを記録（ログ）に残し、残りのキャラクターの位置を書く。
5. The areka shall 正常に閉じるときに位置を書いたこと（どのキャラクターをどの位置で書いたか）を、あとから記録（ログ）で確かめられるようにする。

### Requirement 5: 受け入れの確認（決定論のテストと実機）

**Objective:** As a 受け入れを判定する人, I want この直しが決定論のテストで固定され、実機でも確かめられること, so that 同じ崩れが後から戻ってきたら気付ける

#### Acceptance Criteria

1. The areka shall 「本体だけをドラッグして正常に終了 → 起動し直すと、本体は動かした位置・相方は前回閉じた時点の位置に立つ」を、決定論のテストで確かめられるようにする。
2. The areka shall 「一度もドラッグせずに正常に終了 → 起動し直すと、全部のキャラクター窓が前回閉じた時点の位置に立つ」を、決定論のテストで確かめられるようにする。
3. The areka shall 要件 3.2 の各時点（起動の最後に並べ終えた時点・SHIORI の移動の指示・画面の構成の変化・絵の大きさの変化）で記憶が書き換わらないことと、要件 3.3（寄せ直して表示しているだけの位置を書き換えない）を、決定論のテストで確かめられるようにする。
4. The areka shall きれいに終わらなかった回では位置の記憶が変わらないこと（要件 4.1）と、書き込みが失敗しても終了が最後まで進むこと（要件 4.3）を、決定論のテストで確かめられるようにする。
5. The 受け入れの判定 shall 実機（適合ゴースト emo2）で「本体だけをドラッグ → 終了 → 起動し直す → 相方も前回の位置に立つ」を開発者が確かめることを必達とする。
