# Implementation Plan

- [ ] 1. 系列解決の単一権威を確立する

- [x] 1.1 scope 番号から接頭辞優先連鎖を導出する
  - 系列族を表データとして定義し、族の基底名・scope 0 の旧名候補列・scope 1 の旧名候補列を可変長で保持する（装飾族の一段深い旧名も同じ表構造で表せる形にする）
  - 連鎖を「当該 scope 自身の候補」「相方系列（scope 2 以上のみ）」「デフォルト定義（scope 1 以上のみ）」の 3 段連結として組み立て、各候補に連鎖内の役割タグを付す
  - 各段で正規名を先頭に置き、旧名を後続に置く
  - 相方系列の段は正典が名指しした系列であり、scope 1 の解決へ再帰的に縮退するものではないため、scope 2 以上の連鎖に scope 1 の正規名を含めない
  - scope を数値のみで扱い、本体／相方の 2 値列挙もスクリプト側の別語彙も内部の正準表現にしない
  - 決定論檻: scope 0 / 1 / 5 の連鎖が期待どおりの順序と役割タグで得られ、scope 2 以上の連鎖に scope 1 の正規名が入らないこと
  - _Requirements: 1.1, 1.6, 1.8, 1.9, 1.10, 7.1_

- [x] 1.2 面 ID 単位で連鎖を探索して採用面を決める
  - ファイル名リストに対する純関数として選択核を分離し、ファイルシステムに依存させずに檻へ入れられる形にする
  - 連鎖内の全接頭辞にまたがる面 ID 集合の和を取り、各 ID について連鎖を先頭から辿って最初に画像が存在した接頭辞の面を採用する
  - ある ID の欠落を理由に当該 scope の系列全体を後段の接頭辞へ切り替えない
  - 面判定は接頭辞の厳密一致・拡張子の除去・残余の全数字化という 3 段とし、入力ウィンドウ用や装飾用のファイルを面として採用しない
  - 決定論檻: 正規名と旧名が併存する場合に正規名が採られる／相方側の面 0 のみ存在する場合に面 0 は相方側・面 1 はデフォルト定義側になる／旧名のみの場合に全 scope が同一面集合へ収束する／入力ウィンドウ系のファイルがどの連鎖でも採られない
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 7.1_

- [x] 1.3 ディレクトリ列挙と面解決を公開 API として束ね、観測ログと失敗経路を組む
  - 列挙 1 回と選択核を組み合わせ、面 ID 昇順の決定論的な解決結果を返す
  - 面 0 がどの接頭辞でも解決できない場合は理由をエラーレベルで記録したうえでエラーを返し、全消費者に共通の単一施行点とする（プロセス終了ポリシーは変更せず既存の縮退経路へ伝播させる）
  - 解決完了時に scope・連鎖・採用面一覧を情報レベルで記録する
  - scope 1 以上でデフォルト定義側へ縮退した面について、scope・面 ID・採用ファイルを警告レベルで記録する
  - 採用面から面別上書きファイル名を導出する手段を提供する
  - 決定論檻: 面別上書きファイル名が採用接頭辞に対応して導出され、縮退した面ではデフォルト定義側の名前になること
  - _Requirements: 1.7, 2.2, 2.3, 6.1, 6.2, 6.4, 7.1_

- [x] 1.4 scope 別バルーン定義の 2 層マージを権威側で提供する
  - 現在は起動時資産側にある文字コード解決つきの寛容な読み取りと 2 層マージ構築を、権威クレートへ移設する（旧呼び出し元の置換と旧コードの退役は 3.1 が行う）
  - 既定設定と採用面の面別上書きを既存パーサへ渡し、scope 専用のマージ済み定義を返す（パーサ本体は改造しない）
  - 面別上書きファイルの不在は正常な縮退としてデバッグレベルで記録し、失敗として扱わない
  - 面別上書きの読み取りがその他の入出力エラーで失敗した場合は警告レベルで記録し、既定設定のみで継続する
  - 既定設定側の読み取り失敗は現行どおり警告レベルを維持する
  - 確定した表示位置指定と文字範囲の実値を scope 付きで情報レベルに記録する
  - 決定論檻: 実 fixture で本体側 scope と相方側 scope が異なる実値へマージされ、上書きで指定されなかった項目が既定設定から継承されること
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 6.3, 6.4, 7.1_

- [x] 1.5 表示 World 構築を scope 対応にし、単一接頭辞固定の実装を退役させる
  - World とアトラスの構築入口に scope を受ける形を用意し、解決済み面列から構築する形も併せて提供する
  - 単一接頭辞固定の定数・旧列挙・旧面判定を連鎖版へ置換する
  - 相方側ファイルを常に非採用としていた既存テストを、系列を明示した判定へ意味を変えて更新する
  - 観測可能な完了状態: 相方側 scope の構築 World が相方側系列の面から成る

  - 配置層に供給層のモジュールを新設し、その宣言を配置層の入口へ加える（このタスクが宣言行の唯一の所有者）
  - 表示位置指定の生値から画面座標の調整量を求める純関数を置く
  - x はシェル側を正とする規約を、バルーンがキャラのどちら側に置かれるかに応じて画面座標の符号へ変換する。y は下が正で画面座標と同符号ゆえ変換しない
  - 表示スケールは大きさのみ既存の丸め権威へ委譲し、符号を保存する
  - 両軸とも未指定なら調整量なしを返し、片軸のみ指定なら他軸を正典既定値 0 として扱う
  - 既存の調整量欄へ合流させる手段を用意し、別供給元の既存値があれば加算する。この欄が物理 px の加算欄であり別供給元は非スケールの生値である旨を実装コメントに明記する
  - 決定論檻: 左右 × 正負 × 片軸欠落 × 表示スケール非 1 の全分岐、および両軸未指定時に調整量なしを返すこと

## Implementation Notes

- worktree では `vendors/pasta` サブモジュールが未 populate ＝ cargo が manifest ロードで落ちる。着手前に `git submodule update --init --recursive vendors/pasta`（本ランで実施済み）。
- `cargo clippy` は `wintf` に依存する crate（`areka-emo-present` 等）では使えない（`wintf` に既存のコンパイルエラー約 20 件があり clippy が対象 crate へ到達しない）。`areka-seriko` 等の非依存 crate では動くが、既存 lint（`collapsible_if` 等）がワークスペース各所で鳴るためゲートにはしない。ゲートは `cargo build` / `cargo test`。
- **バルーン World にアニメ定義は構造的に存在しない**: `synthetic_surfaces_txt`（balloon.rs）は `surface{id}` ブロックのみを出力し `animation*` 行を一切出さない ⇒ `AnimationTable::from_world` は常に空表。バルーン表まわりの「観測等価」判断はこの構造事実に依拠してよい（fixture 依存ではない）。
- 本 crate は rustfmt-clean ではない（既存の未整形箇所が多数）。追加分のみ整形し、既存部の一括整形はしない（無関係な巨大差分を作らない）。
- **`load_scope_balloon_model` の署名は `(balloon_dir, scope: u32, face0)`**（design.md の 2 引数版から実装時訂正・design.md 側も追記済み）。R6.3／観測点 3 が info! に scope を要求する一方、`ResolvedFace` から scope は逆算できない（縮退した相方の面は採用接頭辞が `balloons` ＝ scope 0 と区別不能）。3.1／placement の呼出点は scope を渡すこと。
- テスト内のログ捕捉は `tracing` のプロセス大域 callsite interest が並列実行で `never` に焼かれて取りこぼす。同 crate `scale.rs` 由来の常駐 `InterestProbe` ＋窓内 `rebuild_interest_cache()` パターンを使う（1.4 で balloon.rs のテストハーネスへ導入済み）。
