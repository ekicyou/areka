  - 判定の腕の定義行に正典 URL のコメントを 1 行置く（網羅台帳の実装済みの根拠）
  - ファイル先頭・結論・判定関数の説明から「未対応」「裁定 7」の句を外し、今の動きに合わせる
  - 調停側の分岐の参照は新しい名前へ付け替えるだけにとどめる（この段では今の解決の動きを変えない・ビルドを通すための機械的な改名）
  - 判定の境目のテストを新しい名前に直す: `script:\e`・`script:`・`script:OnFoo` は「台本を実行する」、`script`・`Script:x`・`xscript:y` は通常の選択肢。取り出す関数は `script:` に `Some("")`、当たらない ID に `None` を返すことも確かめる
  - 完了の状態: `cargo build -p areka-kanade` が警告なしで通り、`cargo test -p areka-kanade` が緑、ソース全体に旧い結論名が残っていない

- [ ] 2. `script:` の選択肢の結末を実装する
- [ ] 2.1 結末を決めて台本を新しいトークとして始める子のモジュールを作り、選択肢の受け付けへつなぐ
  - 調停のファイルの子として新しいファイルを置き（共通のモジュール宣言のファイルには宣言を足さない）、「台本 1 つを新しいトークとして始める」関数（採番・枠の差し替え・再生開始の行動を返す・記録なし）と、結末を決める関数を実装する
  - 結末: 余分な引数があれば数を警告に残す → 台本が空なら空の警告を出して状態を変えずに何も始めない → 台本があれば新しいトークを始め、元のトークを 1 世代だけ控え、実行の記録（選択肢の ID・新旧のトーク番号）を 1 件出す
  - 選択肢の受け付けの `script:` の腕を「結末を先に決め、解決を先頭・再生開始をその後ろに並べて返す」数行に付け替える。結果の語は台本ありで `script`・空で `script_empty`。未対応の警告と結果の語 `unsupported` を消す
  - 解決を発行するのは調停側の既存の 1 関数のまま。新しいファイルは解決も帳簿も触らず、SHIORI への往復・翻訳の依頼を作らない
  - 調停の説明（選択肢の受け付け・解決の関数）と受理の記録の添え文言を今の動きに合わせる（event 名と欄は変えない）。共通のモジュール宣言のファイルの、解決の行動の説明コメントの 1 句を「`script:` の選択肢の解決」に直す（コードは変えない）
  - 古い前提のテスト 2 本（調停の選択肢のテストの「未対応の選択肢はイベントを起こさず解決する」・記録の発火のテストの「未対応の警告が出る」）を消す（消すだけ・新しい警告の確認はこれらのファイルに足さない）
  - 完了の状態: `cargo build -p areka-kanade` が警告なしで通り、`cargo test -p areka-kanade` が緑、調停のファイルが 1,000 行未満、`crates/areka-kanade` に `choice_unsupported_category`・`"unsupported"`・「未対応カテゴリ」が残っていない
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.7, 2.1, 2.3, 2.4, 2.5, 3.1, 3.2, 3.3, 4.1, 4.2, 5.1, 5.2, 5.3, 7.4_

  - すべて最上位の進行の入口から選択肢の入力を通す。既存の調停のテストの補助（帳簿つきの状態・選択肢の入力の組み立て）を使い、見える範囲は広げない
  - `\q[バルーンを閉じる,script:\e]`: 返る一括がちょうど「解決 → 再生開始（台本 `\e`）」で SHIORI の依頼・翻訳の依頼が無い・帳簿が消える・枠が新しいトーク（出どころの語 `choice_script`）・元のトークの控え・採番が 1 進む・実行の記録と解決の記録（`script`）があり、未対応の警告と余分な引数の警告が無い

  - 境目の ID `Script:x`: 返る一括が通常の選択肢のイベントの依頼 1 つだけで、`script:` の結末の記録が 1 つも無い
