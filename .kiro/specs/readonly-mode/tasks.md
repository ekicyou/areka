# 実装計画

> 設計の正本は `design.md`。触るファイルと関数の名前はそこに書いてある。ウェーブ C11 との重なり（`runtime.rs` は ④、`persist/mod.rs` は ⑥ と文字だけ）も `design.md` の表に従う。

- [x] 1. 土台: 保存の口で書かずに控える
- [x] 1.1 控える範囲と、重ね書きの控えを作る
  - プロセスに 1 つの状態として、「全部を控える」の旗・試験が登録した根の列・パスから中身への控えを持つ。全部を控える旗は一度立てると下ろす口が無い
  - パスの鍵は、小文字にして区切りを逆斜線にそろえた文字列にする。根の下かの判定はパスの部品の単位で行う（根の鍵に区切りを 1 つ足してから頭を比べる）
  - 試験用の取っ手は根を 1 つ登録する。落とすと、その登録とその根の下の控えを消す
  - このモジュールはファイルシステムに触れない
  - 保存の口のモジュールに `pub mod withhold;` を足す。範囲を見る関数と試験用の取っ手は、試験の外でも公開にする（`crates/areka` の本番の道と試験が `areka_sylphya::persist::withhold` から使う）
  - 終わった形: 兄弟の試験が緑になる。確かめる点は、範囲の中のパスで控えたものが読み返せる・取っ手を落とすと控えが消える・登録していない隣の根は範囲の外・`…-1` を登録しても `…-10` は範囲の外・鍵の大小を問わない、の 5 つ
  - _Requirements: 2.1, 2.3, 2.4, 10.5_
- [x] 1.2 保存の口が控えを使い、`Withheld` を返すようにする
  - 保存の入出力の型に「この道を控えるか」を足す。既定は控えない（試験の偽の入出力は今のまま）
  - ファイルの入出力の型は、控える範囲の中なら書かずに控えへ入れ、読むときは控えを先に見る。範囲の外の道と記録は 1 つも変えない
  - 保存の結果に `Withheld` を足す。保存の段は、重ねた中身を作った後で控える道なら控えへ入れ、`persist_withheld` の debug を 1 件残して `Withheld` を返す（「書けた」「書けなかった」の判定には入らない）
  - ゴーストの記憶のフォルダを先に作る口を、ファイルの入出力の型の関連関数として足す。範囲の中なら作らずに debug を 1 件残して成功を返し、外なら今どおり作る
  - 終わった形: 兄弟の試験で次の 4 つが確かめられ、`areka-sylphya` のテストが緑になる
    - 範囲の中では親のフォルダも一時ファイルも宛先も作られない
    - 保存は `Withheld` と `persist_withheld` を返し、保存の失敗の記録は出ない
    - フォルダを作る口は、範囲の中では作らず、外では作る
    - `io.rs` の今の試験は変えずに緑のまま
  - 結果の型に値が増えると、`crates/areka` の `boot_resolve` にある網羅の分岐 3 か所（印を書く・降ろした直後を書く・印を消す）が通らなくなる。そこで、この 3 か所に `Withheld` の腕も足す。腕は `session_mark_withheld`・`switch_drop_withheld`・`session_mark_clear_withheld` の info を残して成功を返す。これでワークスペースが途中で赤にならない
  - 終わった形（追加）: `crates/areka` がビルドでき、`boot_resolve` の今の試験が緑のまま
  - _Requirements: 2.1, 2.2, 2.3, 2.5, 2.6, 3.1, 5.2, 5.3, 6.1, 6.2, 6.3, 6.4, 8.2, 8.5, 11.4_
- [x] 1.3 起動中の印の後始末の文を合わせ、印の 3 つの書き手の控えを試験で固める
  - きれいに終わらなかった後始末では、記憶の置き場が控える範囲の中なら印を読み直さず、`readonly = true` の `session_mark_kept` の info だけを残す
  - 印を読む道・印の 3 関数を呼ぶ側・`argv_session` には触らない
  - 終わった形: 新しい兄弟の試験で次の 3 つが確かめられ、今の `boot_resolve` の試験が緑のまま
    - 根の取っ手の下で、3 関数が成功を返し、書いたときの記録を出さず、控えたときの記録を出す
    - 前のふつうの走りの印を植えると、読み手がその印を読み、後始末の後もファイルの印が同じ
    - 後始末が読み取りだけの文を出す
  - _Requirements: 2.6, 3.1, 3.2, 6.1, 6.3, 11.1, 11.4_
- [x] 1.4 ゴーストを起こす段の記憶のフォルダ作りを、保存の口へ寄せる
  - ゴーストを起こす段の、ゴーストの記憶のフォルダを作る 1 行を、1.2 の関連関数の呼び出しに替える。失敗したら warn を残して続ける今の扱いはそのまま
  - 差分は `runtime.rs` の 1 行だけにする。同じファイルを触る ④ `mcp-scope-rect-property` には、設計の段で伝え済み。どちらが先に着地しても、取り込みは文字の重なりだけで済む
  - 終わった形: `areka-ghost` のテストが緑で、`runtime.rs` の差分が 1 行
  - _Requirements: 2.5, 11.5_

- [x] 2. 起動オプションの語と、走りの状態を立てる口
- [x] 2.1 `--option readonly` を扱う語にする
  - 起動オプションの値に読み取りだけの欄を足す（既定は偽）。語の読み手は `readonly` を扱う語の腕に入れ、扱った語の一覧に 1 度だけ載せ、「まだ扱わない」の記録を出さない
  - 今の試験で `readonly` を「まだ扱わない語」の例にしている 3 か所は `kiosk` に替える
  - 終わった形: 新しい兄弟の試験で次の 5 つが確かめられ、`cli` の今の試験が緑のまま
    - 大小、カンマの並び、`--option` を 2 回渡す、のどれでも読み取りだけが真になり、扱った語は 1 つ
    - `kiosk,readonly` では `kiosk` だけがまだ扱わない語になる
    - `--offline-dump` と一緒のときは、効かなかった記録が出て `readonly` は無視の側へ回る
    - `readonly` を渡しても `bootunlock` を渡しても、起動の求めの値が同じ
    - `nobootcheck`・`dontloadmodule` と組んでも、それぞれの語の効き目が変わらない
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 10.3_
- [x] 2.2 走りの状態を 1 度だけ立てて配る口を作る
  - 起動の前に 1 度だけ呼ぶ入れの口を作る。真なら、プロセスの旗を立て、1.1 の全部を控える旗を立て、`readonly_engaged` の info を 1 件残す。偽なら何もしない
  - 旗を読む口・World に印の資源を足す口・World の印を読む口を作る。旗を下ろす口と資源を外す口は作らない
  - この口は入口のモジュールを使わない（入口の側がこの口を見る）
  - `crates/areka` はバイナリだけのクレートなので、`main.rs` に `mod readonly;` をこのタスクで足す（足さないと、この口も後の呼び手もビルドされない）。入れの口と資源を足す口は 5.1 で呼ばれるまで呼び手が無いので、その 2 つにだけ一時の `#[allow(dead_code)]` を付け、5.1 で外す
  - 試験は兄弟の `readonly_tests.rs` に置き、`readonly.rs` から宣言する
  - 終わった形: 兄弟の試験で次の 3 つが確かめられる
    - 試験のプロセスでは旗が偽で、資源を足す口が何も足さない
    - World の印を読む口が、資源の有無どおりに真偽を返す
    - 構造の試験で、入れの口を `main.rs` の外から呼ぶ所が無く、全部を控える口をこの口の外から呼ぶ所も無い（`main.rs` が実際に呼ぶことは 5.1 で確かめる）
  - _Requirements: 1.1, 1.2, 1.6, 8.1, 8.3_

- [x] 3. 起動の段の読み取りだけの道
- [x] 3.1 (P) 書けるかの確かめを、読み取りだけで通す
  - 起動の前の確かめの入口を足す。読み取りだけなら何も開かず作らず、`readonly_boot_check_skipped` の info を残して通す。そうでなければ今の確かめをそのまま呼ぶ
  - 今の確かめと止め方は変えない
  - 新しい入口は 5.1 で呼ばれるまで呼び手が無いので、一時の `#[allow(dead_code)]` を付け、5.1 で外す
  - 終わった形: `crates/areka/src/readonly_tests.rs` に次の 2 つが足されて緑になる
    - 書けない置き場で、読み取りだけなら通り、記録が出て、木が変わらない

  - _Depends: 2.2_

- [x] 3.2 (P) 利用者ごとの置き場を、作らず写さずに決める関数を足す
  - 読み取りだけの置き場の決め方を、判断と記録はふつうの道と分け合う形で足す。根のフォルダが在ればそれを使い、無ければ作らずに exe の隣の形にして `user_root_withheld` の info を残す。写しは呼ばない
  - 「写すはずか」の条件は 1 か所の関数にまとめ、写しの道と、読み取りだけの記憶の置き場を選ぶ関数が分け合う
  - 読み取りだけの記憶の置き場を選ぶ関数を足す。環境変数の指定があればそれを使う。写すはずの場面なら写す元を返し、`app_memory_read_beside` の info を残す。ほかの場面はふつうと同じ値を返す
  - 試験は `Signals` を注入して、本物の `%LOCALAPPDATA%\areka` と exe の隣に触れない
  - 終わった形: 兄弟の試験で次の 4 つの腕が確かめられ、`areka-user-data` のテストが緑になる。どの腕でも木の前後は同じ
    - 根が無いとき、作らない
    - 根が在るとき、そこを使う
    - 根は在るが記憶が無く、隣に記憶があるとき、隣を読む
    - 環境変数の指定が勝つ
  - _Boundary: UserRootReadonly（areka-user-data）_
  - _Requirements: 4.1, 4.2, 4.3, 4.5, 10.5, 11.2_
- [x] 3.3 (P) フォルダ選びを「最近使った所に足さない」の指定で開く

  - 終わった形: 兄弟の試験で次の 2 つが確かめられる

    - 偽なら、今の指定のまま
  - _Boundary: FolderPickerReadonly_

- [x] 3.4 areka の側で、置き場の形と記憶の置き場を読み取りだけの関数から選ぶ

  - 終わった形: 次の 2 つの試験が緑になり、ふつうの起動の値が変わらないことを今の試験が緑のまま示す
    - 選び分けの純粋な関数の試験
    - 覚えた値を 2 度読んでも同じで、`app_memory_read_beside` が 1 件だけ

- [x] 3.5 書けない所のゴーストとバルーンを、写さずに元から起こす
  - 書ける写しを作る道が、旗を見て「読み取りだけなら写さずに元を返す」関数を呼ぶ。写すはずだったときだけ `user_data_copy_withheld` の info を残す
  - 写しの計画と写しの本体は変えない
  - 終わった形: `crates/areka/src/readonly_tests.rs` の 3.1 の試験の後に「写すはずの並びで元が返り、記録が出て、写し先が作られない」が足されて緑になる

- [ ] 4. 入口の断り
- [x] 4.1 (P) どの入口のインストールも、窓口に積む前に断る
  - インストールの判定に「読み取りだけ」の値を足す。受け付けの頭で World の印を見て、真なら `readonly_refused`（`what = install`）の info を 1 件残して断る。積まず、ゴーストへは何も送らず、断りの warn も出さない
  - インストールの判定を網羅で読む所があれば、新しい値の腕を足す
  - 終わった形: 兄弟の試験で次の 4 つが確かめられる
    - 窓への投げ込み・台本の `path`・メニューの出どころの、どの依頼も断られる
    - 待ち行列が空で、窓口は忙しくない
    - 3 回頼むと記録が 3 件になり、断りの warn は出ない
    - ゴーストへの送り物が 0 件

  - 受け口を作る関数の引数は変えない（受け口の並びを字で固めた試験に触らない）
  - 終わった形: 兄弟の試験で、読み取りだけの取得の口を渡した `url` の腕が要求を送らずに記録を出すことが確かめられ、今の試験が緑のまま

- [ ] 4.3 (P) 更新の断りで送る総括の字を作る

  - 送らない 7 語の檻に、この関数の出力を足す
  - 終わった形: 試験で次の 3 つが確かめられる

- [ ] 4.4 どの入口の更新も、段を移す前に断り、総括の 2 件だけを送る
  - 更新の判定に「読み取りだけ」の値を足す。判定は「窓口が無い」「終わりが始まった」の次に World の印を見る。真なら断りの関数を呼んで「読み取りだけ」を返す。段・預かり・背景のスレッドには触れない
  - 断りの関数は新しいファイルに置く。対象を解き、`OnUpdateResultEx`、続けて `OnUpdateResult` を、返事なしで置き場のゴーストへ 1 件ずつ送る
  - 対象が 0 なら何も送らない。`readonly_refused`（`what = update`）の info を、送れたかの値を添えて 1 件残す。受け付けの記録の腕では、断りの warn を出さない
  - 終わった形: 兄弟の試験で次の 2 つの依頼を確かめる
    - 依頼は、バルーンの「にゃんばるーん」と、自分のゴーストの 2 つ
    - どちらも、断られる・段が待ち・預かりが空・窓口が忙しくない
    - 送り物は Ex → Result の 2 件だけで、字は設計のとおり
    - 記録は 1 件で、2 回目も同じ
  - _Depends: 4.3_
  - _Requirements: 7.3, 7.4, 7.5, 7.6, 7.7, 10.4, 11.3_

  - 入れの口は、`--help` と `--offline-dump` の戻りの後、起動の値を解く段の前に、起動オプションの値で 1 度呼ぶ

  - 構造の試験に「`main.rs` が入れの口を 1 度呼ぶ」を足す

    - 保存の口から期待の値が読み返せる

  - 終わった形: 新しい試験が緑で、今の「どの種類も机に届く」試験も緑のまま。1 種でも抜けると落ちる

- [ ] 5.3 起動から終わりまでを読み取りだけで通し、木の前後を比べる
  - 新しい試験 `readonly_run_tests.rs` は `readonly.rs` から宣言する
  - `target\` の下の 1 つの根に、exe の隣の形と、まだ無い利用者ごとの置き場を置き、前の木（ファイルとフォルダの一覧と中身）を取る
  - 読み取りだけの道を順に通す: 置き場を決める → 記憶の置き場を選ぶ → 書けるかを確かめる → ゴーストの写しを決める

  - 終わった形: 試験が緑で、次の 3 つが確かめられる
    - 後の木が前の木と同じ
