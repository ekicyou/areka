# 実装計画

> 本 spec の成果物は文書 3 本（台帳・ブリーフィング・機械で作り直すドメイン別の報告）と、実装済みと判定した項目の定義箇所へ置く正典 URL の 1 行コメント 23 行だけである。実行時の振る舞いは 1 ビットも変えない。
> 段の番号は設計の「作業手順」の段に対応する。台帳 `doc/ukadoc-coverage/ledger/sakura-script.toml` は本 spec が単独で持つ 1 ファイルであり、そこへ書き込む作業は互いに並行できない（同じファイルを奪い合うため）。並行できるのは中間ファイルだけを作る作業である。
> **前提の更新（2026-09-05・`origin/main` を取り込み済み）**: 上流の道具 `crates/ukadoc-survey` が着地し、`doc/ukadoc-coverage/` 一式（カタログ 1,749 件・4 ドメインの台帳・報告 4 本・テーマ定義・手順書）が repo に既にある。担当の台帳は 342 項目すべてが `unclassified` で並んでおり、前置き・欄の順・id のバイト順は設計の規則 0 と一致している。したがって本計画は**骨組みを作る側ではなく、既にある骨組みの値を書き換える側**である（要件 1.10 の「道具が未着地の場合」の枝は使わない）。報告の再生成も本 spec の担当に入った（要件 11.1 が生き、11.2 の枝は死んだ）。常設の検査 15 種が既に動くので、使い捨ての台本で作るのはそこに無い検査だけでよい。
