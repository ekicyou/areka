# Implementation Plan

> 相の境界（R12.4・design「Components and Interfaces」前書き）: **相 1** ＝ タスク 1〜3 と 4.1（決定論層と、間欠的な赤の系統 ⑴ の更新）。**相 2** ＝ タスク 4.2〜4.4（系統 ⑵⑶ の隔離）とタスク 5〜7（実機層・判定・正本の更新）。適合検証項目表と記録の様式は両相が参照するため、相 1 の入口（タスク 1）で確定させる。

- [ ] 1. 相 1 の入口: 期待値の源・記録の様式・着手前の非干渉確認

  - 表の「期待値の出典」欄が挙げる参照先を 1 行ずつ当たり、実在し記述が現在の内容と合っていることを確かめる
  - 観測の層が「実機」の行（選択肢の見た目の反転・位置の永続化・掴んで動かしたときの追従・再表示直後の重なり順・子プロセスへの受け渡し）について、決定論層で観測できない理由が欄に書かれていることを確かめ、欠けていれば補う
  - 上流の裁定で変わった期待値（二体の隣接・台本の移動量の拡大率倍・バルーン追従の相対位置）と、退役ユニットの吸収・省略機能の縮退・総数の登記（14 を基礎＋追補 6 ＝ 20）が表と前書きに揃っていることを確かめる
  - 完了状態: 20 行すべての出典が実在確認済みで、ずれていた行は表の当該行だけを更新し、写しはどこにも作られていない
  - _Requirements: 1.4, 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8, 4.9_
- [ ] 1.2 受入記録の様式を空欄のまま起こす
  - 同定・実機構成・資産・環境変数・走行・宣言・点灯確認・判定・機械判定・目視所見・合否（決定論層）・合否（実機層）・登記の各欄を持つ空の記録を置く
  - 決定論層と実機層の合否を別の欄に置き、片方を他方で置き換えられない形にする（決定論層の欄は相 1 の走行の証跡がそのまま入る）
  - 子プロセスへの受け渡しの欄を 3 経路の同時成立として作り、3 つの証跡（接続失敗 0 行・実 SHIORI 由来の起動挨拶・正規の解放完了 1 行）を書く場所を用意する
  - 中断時の欄（中断点・観測できたところまで）と、判定に載せない症状の登記節・仕分け節の骨格を置く
  - 完了状態: 走行前に空欄のまま置ける記録が完成し、根拠の種別を区別して書け、相 1 の証跡の置き場が先に決まっている
  - _Requirements: 1.3, 5.2, 5.4, 5.8, 5.11, 7.5, 8.4, 8.5, 8.7, 12.5_
- [ ] 1.3 着手前の非干渉確認を行い隔離裁定の記録を起票する

  - 同時期に走る 3 系統の仕様の編集集合を実測で確かめ、本仕様が例外として触れる `wintf` の 2 ファイルに 1 つも触れないことを根拠つきで記録する
  - 本仕様の編集集合（新規の兄弟テスト 3 ファイル・既存の組立ファイルへの接続宣言と記録の追補・実物定義の文書・本仕様の記録）と、事前登記済みの例外 2 件を明記する
  - 完了状態: 着手前の確認節が埋まり、非干渉の根拠が後から再検証できる形で残っている

- [ ] 2. 決定論一周テストの土台
- [ ] 2.1 既存の基準を採ってから進行状態の記録の第 2 系統を追補する

  - 台本受け口へ「呼出 id と組み立て済み進行状態の対」の記録を足し、観測ハンドルへ取り出し口を 1 本足す
  - 記録の型と取り出し口の本体はテスト支援ファイル側に置き、既存の組立ファイルにはフィールドと書き込み 2 か所だけを残す（追補は接続宣言込みで 40 行以内）
  - 既存の呼出記録の型と既存の取り出し口は一字も変えない
  - 完了状態: 編集前の基準値が記録に残り、新しい取り出し口から選択待ちを含む進行状態が読める

- [ ] 2.2 (P) 台本と期待列の逐語を 1 ファイルに集める
  - 起動 5 呼出・自発会話（会話可／会話中）・撫で・二重クリック・選択確定・終了握手の応答表を、id ごとの待ち行列として組む
  - 毎秒の通知の応答は、段の上限から導ける本数に余裕を足す規則として書く（本数を駆動器の実装値から借りない）。行列が尽きると受け口が落ちるため、余裕は必ず正とする
  - 送出の期待列を、呼出の別・id・参照列の 3 要素で逐語に書く（撫では話者と当たり領域、二重クリックはボタン、終了は Ref0 のみ）
  - 完了状態: 台本と期待列がこのファイルだけに存在し、駆動も判定も 1 行も含まない
  - _Requirements: 3.1, 3.3, 3.4, 3.5, 3.9, 3.10_
  - _Boundary: D2 台本と期待列_
- [ ] 2.3 段の駆動器を作る
  - 段名・注入の種類・完了条件・注入時刻の上限を受け取り、完了条件が成立するまで注入と観測を交互に回す駆動器を書く
  - 注入時刻が段の上限に達したら以後は注入せず観測だけを待つ（注入時刻が観測を追い越すと待っている条件そのものが壊れるため）
  - 毎秒の通知は kanade 側の送信端へ直接投函する（既存の駆動は再生側にしか届かず毎秒の通知を起こさない）
  - 完了条件が成立しないまま有界時間が尽きたことを必ず呼び手へ返し、素通りさせない
  - 完了状態: 駆動器 1 つで全段を回せ、段名を名指しした失敗が出せる
  - _Requirements: 2.10, 3.2_
  - _Depends: 2.1_

- [ ] 3. 一周の走行と判定
- [ ] 3.1 一周の全段を 1 本の走行で辿る
  - 起動 → 装着 → 自発会話 → 会話中の抑止 → 撫で → メニュー → 選択確定 → サブメニューと戻り → 位置調整 → 終了、の順に段を駆動する
  - 各段に設計の段表どおりの完了条件を持たせ、終了段は解放がちょうど 1 件であることに加えて kanade の送信端への送信が Err になる（自己終了の観測）ところまで待つ
  - 後片付けは既存の有界な畳み方を使い、注入口は既存の公開送信端だけを使って新設しない
  - 明示実行の門（`#[ignore]`・環境変数）を付けない
  - 完了状態: テスト 1 本が通常のテスト実行で走り、一周を最後まで辿って全実行主体が有界時間で畳まれる
  - _Requirements: 1.1, 1.5, 1.6, 2.1, 2.2, 2.6, 2.7, 2.8, 2.9_
- [ ] 3.2 3 つの列を採取して期待と完全一致で判定する
  - 交信の列・〈段名と表示指令〉の列・進行状態の列を同一の走行から採り、段の駆動をすべて終えた後にまとめて等値照合する（部分一致・包含判定を使わない）
  - 表示指令の判定の本体は段名を含む列の等値とし、採取時の注入時刻が段の宣言区間に入ることは駆動器の自己検査として別に扱う
  - 会話の発火・時報・更新系 4 種・バルーン変更が 1 件も現れないことを、等値照合が拾う形で成立させる
  - 失敗の形を設計の表どおりに作り分ける（段名を名指しした待ち切れ・列の差分・解放の件数・自己検査の失敗）
  - 完了状態: 期待に無い照会・通知・表示指令が 1 つでも現れると走行が赤になる
  - _Requirements: 2.3, 2.4, 2.5, 3.6, 3.7_
- [ ] 3.3 判定が生きていることを対照で示す
  - 段の上限を意図的に 1 段ずらして駆動する変異を一時的に入れ、〈段名と表示指令〉の照合が赤になることを確かめる
  - 赤の出力を記録の決定論層の欄へ引用し、変異を戻して緑に復すること
  - 完了状態: 記録に「変異で赤・復帰で緑」の 2 つの出力が残り、判定が空振りでないことが示されている
  - _Requirements: 2.4, 2.5_
  - _Depends: 1.2_
- [ ] 3.4 既存テストへの非回帰と分量・時間の規律を確かめる
  - 2.1 で採った基準値と突き合わせ、既存の spine 兄弟テスト 19 本の結果が追補の前後で変わらないことを判定する（非回帰の判定はこのタスクだけが行う）
  - 新規 3 ファイルと追補後の組立ファイルがいずれも 1 ファイルの分量上限を下回ること（上限の見張りが常設で走る）と、例外表に触れていないことを確かめる
  - 走行時間の増分が基準値に対し 1 秒前後に収まることを実測する
  - 完了状態: 既存の期待値を 1 つも緩めずに全数が緑で、分量と時間の実測値が記録に残っている

- [ ] 3.5 実物定義の文書の選択確定の記述を実装に合わせて訂正する
  - 適合対象の選択肢 ID がすべて `On` 始まりであり、確定時に発火するのは同名イベント 1 段のみであることを、走行で得た交信の列を根拠に書き直す
  - 正典が同名イベントの直接発火を明記していること、正典の選択確定イベントは `On` で始まらない ID の形で発火し適合対象では使われないこと、先行段の有無について正典が沈黙していることを併記する
  - 完了状態: 実物定義の文書の当該行が実装と一致し、根拠が正典と実装の両方から辿れる
