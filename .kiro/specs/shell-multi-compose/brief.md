# Brief: shell-multi-compose

## Problem

- **ノベルの作者**（pasta で書く演劇）: pasta の 0.5.0 は「背景・登場人物・トークの出る場所が、それぞれシェルである」と決めた（pasta の 2026-10-10 の決定）。ところが areka は、キャラクター 1 人に透明の窓を 1 枚ずつ立てるだけで、2 人までしか出せない。1 つの窓の中に背景と何人もの役者とトークの場所を重ねる画面が作れない。普通の窓や全画面で遊ぶこともできない。
- **開発者**（2026-10-28 `/kiro-discovery`・N1「ノベルゲーム向けの画面構成」）: 「複数のシェルを 1 つの窓に並べる仕組み（層の順序、配置、サイズ、透過）」「普通の窓と全画面の両方」「場面転換の演出」。議題 4 の追記「play についてはさくらスクリプトやキャラクター管理の拡張が必要だと考える。原則として任意のゴーストの任意のシェルを呼び出せるのが play の立場」。原文と決めたことは `doc/ideas/novel-platform.md`。

## Current State

起票のときの実測（main `d6054e4d`）:

- **窓は 1 人 1 枚・2 人まで**: `crates/areka/src/emo2_boot/mod.rs` の `derive_scopes()` は `vec![0, 1]`。3 人目からの窓はいつかの段の `extra-character-windows` が持つ（`input_events/mod.rs`・`menu/captions.rs` に `debug_assert!(scope <= 1, …)`）。
- **全画面・枠つきの普通の窓は無い**。全画面に触れるのは「全画面のアプリが居るときの最小化」（`tasktray-minimize`）だけ。
- **一番近い土台はシェルの中のバルーン**（完了済み・areka 独自）: `surfaces.txt` の `balloon.名前` ブレスと `elementN,balloon,名前,X,Y` で、文字を描く場所をシェルの中にいくつでも置ける（`roadmap.md` のシェルの中のバルーンの節）。トークの場所（role=stage）のシェルは、これで組める見込み。
- **描画は v0.2.0 で作り直す**: `wintf-visual-tree`（`ecs\visual` の層を新しいビジュアル層・描画層として取り込む）・`wintf-d2d-composite-rules`・`wintf-visual-damage-redraw`。1 つの窓に何枚ものシェルを重ねる形は、その新しい層の上に乗る。
- **pasta の取り決め**（`novel-areka-contract`・未着手）が頼む見込みの画面の項目: 名前の付いた席と数値の位置・重ね順・出す・消す・3 体以上・普通の窓と全画面とその切り替えと拡縮・サーフェスの替わり方（瞬間・クロスフェード・ルール画像のワイプ）・揺れ・フラッシュ・色調。命令の名前は決まっていない。

## Desired Outcome

- 1 つの舞台の窓の中に、背景（role=background）・役者（role=character）・トークの場所（role=stage）のシェルを、決めた順に重ねて描ける。役者は 3 体以上立てられる。
- 役者ごとに、任意のゴーストの任意のシェルを割り当てられる（借り物の宛名は `ghost-material-metadata` の素材 ID・借りてよいかは同 spec の「借りないで」の印）。
- 舞台の窓は、普通の窓（枠つき）と全画面のどちらでも開け、切り替えられる。縦横の比が違うときは、レターボックスかクロップで収める。
- 状態はサーフェスの切り替えで表せる（例: 背景のシェル「教室と窓」に稲光の面を出すと雷の絵に替わる）。
- 場面転換（暗転・フェード・スライドなど）と、サーフェスの替わり方（クロスフェード・ルール画像のワイプ）を演じられる。
- デスクトップに常駐する今の透明の窓は、そのまま変わらない。
- 性能の目標（メモリ・起動の時間・GPU の負荷）を要件の最初に決め、それを測って守る。

## Approach

- 舞台の窓は、v0.2.0 の新しいビジュアル層の上に、シェルの絵を何枚も重ねる 1 枚の窓として作る。今のキャラクターの窓（1 人 1 枚・透明）とは別の種類の窓にする。
- 役者の席と割り当ては、今のスコープ（`\p[n]`）の考え方を広げる形を第一の候補にする（台本はさくらスクリプトのまま・pasta の「舞台をさくらスクリプトで制御する」枠組み）。`extra-character-windows` の「窓の数の導き方を 1 か所にする」と同じ根なので、どちらが土台を持つかを要件の段で決める。
- 席・割り当て・転換の命令は `\![名前,引数…]` に載せ、areka は `Custom{command, params}` の 1 本で運ぶ。**命令の名前は pasta の依頼書が決める**。この spec は名前の要らない仕組み（席・重ね順・窓の形・転換の描き方）を先に作り、名前は依頼書が届いたら付ける（届く前に着手するなら、仮の名前を areka の独自の語として置く案を要件の段で決める）。
- 重い見込み（L 超）。要件の段で、⑴ 舞台の窓と席・割り当て ⑵ 普通の窓と全画面・レターボックス ⑶ 場面転換とサーフェスの替わり方・揺れ・フラッシュ・色調、のように切る（2026-10-28 議題 3）。

## Scope

- **In**: 舞台の窓（1 つの窓に何枚ものシェル）・席と重ね順と位置と大きさと透過・3 体以上の役者・役者ごとのシェルの割り当て（任意のゴーストの任意のシェル）・role の扱い（background・character・stage）・普通の窓と全画面とその切り替え・レターボックスとクロップ・場面転換・サーフェスの替わり方・揺れ・フラッシュ・色調・性能の目標と測り方・決定論のテスト。
- **Out**: 命令とイベントの名前（pasta の依頼書）・進行と入力（オート・既読スキップ・キーボード送り＝受け口の節）・バックログとセーブ（受け口の節）・音（`sound-canon-tags`）・素材 ID と descript のキー（`ghost-material-metadata`）・演劇のパッケージの形（受け口の節）・デスクトップの透明の窓で 3 人目を出すこと（`extra-character-windows`）。

## Boundary Candidates

- 舞台の窓の種類と、その開き方・閉じ方（areka 本体・wintf の窓）。
- 席と重ね順と割り当ての状態（emo の World・placement）。
- シェルの絵を何枚も重ねる描画（v0.2.0 のビジュアル層・emo の合成）。
- 場面転換とサーフェスの替わり方（SERIKO とアニメーションの土台・dola の時計）。

## Out of Boundary

- pasta の側の台本の書き方と、台本の進行・巻き戻し（pasta が持つ）。
- シェルの読み込みと解析そのもの（今の `areka-parsers` のまま）。

## Upstream / Downstream

- **Upstream**: v0.2.0 の `wintf-visual-tree` → `wintf-d2d-composite-rules` → `wintf-visual-damage-redraw`（新しい描画の層）・v0.4.0 の `element-animation-easing`（転換のイージング）・`ghost-material-metadata`（役者のシェルの宛名・role の宣言）・`extra-character-windows`（3 人目からの土台・どちらが持つかは要件の段）・`multi-ghost-runtime`（v0.1.0 の余力の枠・ゴーストの部品をゴーストごとに作る土台）。
- **Downstream**: ノベルの進行と入力・バックログ・セーブ・システム画面の部品（受け口の節）・`areka-usage-stats`（演劇の信号）。

## Existing Spec Touchpoints

- **Extends**: なし。
- **Adjacent**: `extra-character-windows`（3 人目からの窓・窓の数の導き方）・`multi-ghost-runtime`・`window-snap`（夢の段・複数のマスコットの積み重なり）・完了済みのシェルの中のバルーン（`ghost-inner-balloon`・`shell-balloon` 系）・`shell-companion-balloon`。

## Constraints

- 区分 A（開発者が起票）・版は新しい段「ノベルゲーム基盤」（2026-10-28 議題 1・3）。
- 規模の見立て: L 超（要件の段で切る）。Opus。
- 語彙の名前は pasta の `novel-areka-contract` に従う。pasta のリポジトリは書き換えない。
- 窓の当たり判定は α ≥ 0.5 の画素（今の決まり）・時刻は正確に扱う・1 フレーム遅らせる解は取らない。
- 失敗の経路は記録を残す（借りたシェルが無い・読めないときは既定のシェルへ戻し、`warn!` を 1 行）。メッセージボックスは出さない。
