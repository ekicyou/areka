## 2. 暫定の要件

出どころの略: 【取】＝pasta の `novel-areka-contract/brief.md` の「決定（最終形）」の節の小見出し。【骨】＝骨子の節番号。【b】＝areka の `shell-multi-compose/brief.md`。

1. 台本が舞台を開く命令を打ったとき、areka は舞台の窓を 1 枚開く。形はウィンドウ・全画面・ボーダーレスの 3 つで、命令に形が無ければウィンドウにする。同じ形をもう一度受けたら何もしない。別の形を受けたら、開いたまま形を替える。【取「舞台の窓と箱」・骨 2.7】
2. 舞台は 1920×1080（96DPI の論理の大きさ）を基準にする。areka は、窓の中の大きさに合わせて、比を保って拡大縮小し、中央に置き、余りを黒にする。【取「舞台の窓と箱」】
3. ウィンドウの形では、遊ぶ人が窓の大きさを変えられる。最大化のボタンは押せない。areka は、窓の形も大きさも保存しない。【取「舞台の窓と箱」】
4. 舞台が開いている間、areka はデスクトップの窓とバルーンを隠す。舞台を閉じたら、隠す前の位置と絵のまま戻す。【取「舞台の窓と箱」・骨 2.7】
5. 舞台を閉じるとき、areka は、舞台の残る命令（並び・位置・重ね順・大きさ・透明度）を全部「無い」に戻す。走っている転換・揺れ・フラッシュは捨てる。並走を止めること・バックログの目印を外すこと・単発の音を止めることは、持ち主の単位へ「舞台が閉じた」と知らせる。【取「舞台の窓と箱」「並走」】
6. 舞台の窓の × と Alt+F4 は、`OnClose` へ流す。SHIORI が答えないときも、遊ぶ人は舞台から必ず出られる。【取「舞台の窓と箱」「要件定義へ送ること」】
7. 並びの命令（仮 `\![play,cast,名前,…]`）を受けたとき、areka は舞台のアクターを、その並びに置き換える。並びに無いアクターは消える。同じ並びなら何もしない。見つからない名前・読めないシェルは飛ばして、`warn!` を 1 行残す。【取「舞台の窓と箱」・b の Constraints】
8. 舞台が開いている間、`\p[n]`（`\0`・`\1`）の n は、並びの n 番目のアクターを指す。同じ 1 本の中でも、並びの命令より後ろは、新しい並びで読む。【取「舞台の窓と箱」】
9. 位置を明示しないアクターは、並びと、シェルの役（背景 → 役者 → トークの場所）から、重ね順と位置を自動で決める。位置を明示したアクターは、自動の並べ方に数えない。位置は、数値か、舞台の定義に書いた席の名前で指す。【取「舞台の窓と箱」・骨 2.9 のフェーズ 3 の前半】
10. 位置・重ね順・大きさ・透明度は、舞台に残る。同じ値をもう一度受けたら何もしない。引数なしは「無い」（既定へ戻す）。【取「命令の表」】
11. 待ちを挟まずに続けて書いた命令は、同じフレームで見える。areka は、同じ時刻の命令を全部当ててから、絵を出す（作りかけの舞台を見せない）。【取「命令の表」】
12. 出し直しの印（`\![play,again]`）の 1 本では、areka は、舞台の残る命令の値を全部既定へ戻してから、続く命令を当てる。走っている転換は、終わりの絵へ飛ばす。前と同じ値になったアクターは、ちらつかない。【取「命令の表」・骨 4 章の「承認が要らない整理」】
13. 転換の命令（仮 `\![play,trans,ミリ秒]`）の後ろから「次の字・次の待ち・次の転換・1 本の終わり」までの変更は、その時間をかけて、アクターごとに替わる。サーフェスは前の絵から次の絵へ溶け、透明度・位置・大きさは動き、並びに入る・出るアクターは溶けて現れる・消える。重ね順は、その瞬間に替わる。転換は台本を待たせない。時間 0 は、前の転換の組を終わらせる。【取「転換」】
14. 転換の途中に次の変更が来たら、そのとき画面に出ている絵と値を出発点にする。字を早送りしたら、走っている転換は終わりの絵へ飛ぶ。【取「転換」】
15. 台詞の字は、話者のスコープに打たれた物を、並びで最初の、出ている「トークの場所」の役のアクターの箱へ出す。トークの場所のアクター自身のスコープで打った字は、その箱に出す。トークの場所が並びに居なければ、話者自身のシェルの箱へ出す。【取「舞台の窓と箱」・骨 2.7】
16. 話者の名前は、台詞の箱のシェルの中の、決まった名前の小さい箱に出す。箱が無ければ出さない。既定は並びの名前で、`\![play,speaker,名前]` が在れば、その 1 本ではそれを出す。【取「舞台の窓と箱」「命令の表」】
17. 舞台の中に、ふつうのバルーンは出さない。行き先の箱が無い字は、出さずに記録を残す。【取「舞台の窓と箱」】
18. 舞台の上のマウスのイベントの座標は、基準の大きさの値で届ける。黒い余白の上のクリックは送らない。当たりは α ≥ 0.5 の画素で決め、Reference3 でどのアクターか、Reference4 で当たり判定の名前を届ける。【取「舞台の窓と箱」「画面の部品はアクター」・b の Constraints】
19. 揺れとフラッシュは、その行が再生されるときだけ起きる（残らない）。【取「命令の表」・骨 2.9 のフェーズ 3 の前半】色調とカメラは、この暫定の設計では作らない（4.9 に境だけ書く）。
20. 舞台が閉じている間の動き（デスクトップの透明の窓）は、1 つも変えない。失敗は記録に残し、メッセージボックスは出さない。性能の目標（メモリ・開くまでの時間・GPU の負荷）は、要件の最初に決める。【b の Desired Outcome・Constraints】

読み替えた所: areka の brief の Desired Outcome と Scope に在る「クロップ」「暗転」「スライド」「ルール画像のワイプ」は、pasta の決定（取「転換」: 「黒を挟む形と、ルール画像は入れない」／取「舞台の窓と箱」: 「比を保って中央に置き、余りは黒にする」）で要らなくなった、と読んだ。

### 4.2 スコープの番号の読み替え（CueSheet への直しと両立するか）

**見立て: 両立する。ただし、読み替えは「配る直前の 1 か所」で行う。**

- 今の作りは、台本を直す時点でスコープの番号を合図へ写す。番号の意味（どのアクターか）は、直す時点では決まらなくてよい。合図は書いた順に配られ、並びの命令も、そのときの位置で、同じ列の中を流れるからである（3 章）。
- 読み替えを、受け手のそれぞれに任せてはいけない。受け手は別々の線とスレッドで動くので（seriko は自分のスレッド）、「今の並び」を共有の状態として後から読むと、並びの命令の前の合図を、新しい並びで読み違える。
- そこで、受け手の束の外側に `CastScopeSink` を 1 つかぶせる。
  - 登録のときの先渡し（これから届く合図の全部）を、頭から 1 度たどる。出発点は「最後に配り終えた並び」。並びの命令に出会ったら、そこから後ろは新しい並びで読む。こうして、合図の 1 つ 1 つに、アクターの鍵を先に決めておく（純粋な畳み込みで、時計を見ない）。
  - 配るときは、決めておいた鍵に書き換えて、内側の受け手へ渡す。並びの命令を実際に配ったら、「最後に配り終えた並び」を進める（途中で置き換えられて配られなかった並びの命令は、効かない）。
  - 並びの命令そのものは、名前を鍵へ直した内部の合図（台本からは書けない運搬名）にして、内側へ流す。文字の層と seriko と `StageCueSink` が、同じ 1 つの答えを受け取る。
- アクターの鍵は、数の帯で分ける。舞台のアクターは、名前ごとに 1 つ、舞台が開いている間ずっと変わらない番号 `STAGE_SCOPE_BASE + 連番` をもらう。下流（`target_map`・seriko・文字の層）は、今の「`ActorKey` は数」のまま動く。舞台のアクターかどうかは、番号が帯の中かどうかで分かる。採番の正本は、今と同じ `target_map` に置く。
  - 台本が帯の中の番号を直接書いたら、捨てて記録する。
  - 舞台が開いている間に、並びの長さ以上の番号で打たれた合図は、捨てて記録する（デスクトップのスコープへは流さない）。
- 並走の区間（`parallel-visual-script`）は、区間の流れを始めるときの並びで、区間の全部を先に読み替える。後から主の流れが並びを替えても、走っている区間の番号の意味は変わらない（取「並走」の「後から始まった流れが、あるアクターの表情を置いたら、前から走っている並走は、そのアクターへはもう書かない」は、アクターの鍵で判定できる）。
- SHIORI へ送るイベントの Reference3 は、送る時点の並びで、鍵から番号へ戻す。

### 4.3 舞台の状態と、同じ時刻の組の適用

- **状態の持ち方**: 舞台の状態は、純粋な値 `StageState` 1 つである（開いているか・形・並び・アクターごとの位置〔数値／席の名前／無い〕・重ね順・大きさ・透明度）。命令は、この値を書き換えるだけで、絵には直接触らない。絵へ当てるのは、古い値と新しい値の**差**である。「同じ値は何もしない」「出し直しは全部を既定へ戻してから当てる」は、この形から、そのまま出る（既定へ戻して当て直した結果が前と同じなら、差は空で、ちらつかない）。
- 表情（サーフェスと着せ替え）は、今と同じく seriko が持つ。`StageState` には入れない。出し直しでも、表情は「無い」へ戻さない（戻すと、同じ表情の置き直しでも SERIKO のアニメーションが頭から始まる）。pasta が全アクターの表情を書く前提（5 章）で、結果は同じになる。
- **同じ時刻の組**: `CastScopeSink` は、先渡しの列から「時刻（`at`）が同じ合図のまとまり」を知っている。まとまりの最後の合図を配った直後に、内側の受け手の全部へ「組の終わり」を通し番号つきで流す。
  - `StageCueSink` は、組の中の舞台の命令を 1 通にまとめて UI スレッドへ送る。
  - seriko は、自分の受け箱の順で「組の終わり」に着いたら、提示の段へ `PresentCommand` の新しい 1 種（組の終わり・通し番号）を送る。今の `StageAck`（`crates/areka-emo-present/src/command.rs:95-105`）と同じ形の、合成に触らない合図である。
  - UI スレッドの舞台の適用は、舞台のアクター宛ての指令を、組ごとにためる。「舞台の命令の 1 通」と「seriko からの組の終わり」と「その組が要るシェルの読み込み」の 3 つがそろった組を、古い順に、1 回のフレームの処理の中で全部当てる。
- これで、同じ時刻の命令は同じフレームに出て、作りかけは見えない。そろうまでの間、画面には前の絵が残る。フレームを数えて遅らせる作りではない（そろった時に当てる）。台本の時計は止めない。当てるのが遅れた転換は、過ぎたぶんだけ進んだ所から始まる（4.7）。
- 舞台が閉じている間は、`CastScopeSink` は何も書き換えず、組の終わりも流さない（デスクトップの動きは今のまま）。

### 4.4 舞台の窓と、描く木

- 舞台の窓は、今のキャラクターの窓とは別の種類の窓 1 枚である。

| 形 | 窓 | 絵の無い所 | 大きさ |
| -- | -- | ---------- | ------ |
| ウィンドウ | OS の枠つき・タスクバーに出る・最大化のボタンなし | 黒 | 開くときは、モニターに収まる大きさ。遊ぶ人が変えられる |
| 全画面 | 枠なしで、今いるモニターいっぱい | 黒 | モニターの大きさ |
| ボーダーレス | 枠なし | （仮定）透明 | （仮定）基準 × そのモニターの DPI の倍率を、モニターに収まるまで縮めた大きさ |

- 拡大率 s は「舞台が占める物理の大きさ ÷ 基準の大きさ」で、`stage_fit(窓の中の大きさ) → (s, 余白)` の純粋な関数で出す。窓の大きさが変わった知らせ（プッシュ）のたびに引き直す。
- 描く木（暫定の案 A: アクターごとに描画面を持つ）:

```
舞台の窓（黒い地）
└ 舞台の中身（offset＝余白＋揺れ・scale＝1）
   ├ アクターの席 … 重ね順の順に並ぶ（offset＝位置 × s を丸めた値・scale＝1・不透明度＝透明度）
   │  ├ 文字の層の置き場（今と同じ）
   │  ├ 絵（offset＝0・scale＝k）        ← 今の表示対象の作りのまま
   │  └ 消えていく前の絵（転換の間だけ・4.7）
   └ フラッシュ（舞台いっぱいの色・ふだんは見えない）
```

- 絵の拡大率は、今の「アプリの倍率」の席（3 章）に `s × アクターの大きさ` を入れて導く。絵の Entity は offset 0 のまま、席の Entity は scale 1 のままなので、3 章の「offset は 0」の決まりを破らない。文字は、今と同じく、拡大した後の大きさで描き直される。当たり判定も、今の「k で割る」道がそのまま使える。
- 表示対象の親（`PresentTarget.window`）が窓でない Entity（席）になるので、k を「その親の DPI」から導く所（3 章）に、舞台のアクター用の出どころを足す。
- 重ね順は、席の Entity の並び順で表す。自動の決まりは `auto_layout`（純粋な関数）に置く。役の順（背景 → 役者 → トークの場所）、同じ役の中は並びの順。位置の自動は、背景は舞台の原点、役者は並びの順に横へ等分。位置の基準点と間隔は決まっていない（8 章）。
- 案 B（舞台を 1 枚の描画面にして、アクターを wintf の新しい節として描く）は採らなかった。areka の側に使い手がまだ 0 件で（3 章）、当たり判定が今の配置の道（`GlobalArrangement`）に乗っているためである。色調とカメラ（フェーズ 3 の後半）は、舞台の全体に効かせる物なので、そのときに案 B へ替える見込みが在る（4.9）。

### 4.5 アクターのシェルの読み込みと seriko

- 並びに初めて入ったアクターは、名前 → シェルの宛名 → フォルダ、と解いて（`ghost-material-metadata` の関数）、今の `load_shell_target` で読む。読み込みは UI スレッドの外で行う。読み終わるまで、そのアクターを含む組は当てない（4.3）。読んだシェルは、舞台が開いている間は持ち続ける（仮定）。
- seriko は、アクターごとに、SERIKO の表・サーフェスの名前を解く表・着せ替えの名前を解く表を持つ（今のバルーンの側の「スコープごとの表」と同じ持ち方）。アクターの足し引きは、並びの内部の合図で行う。
- 借りたシェルが無い・読めない・「借りないで」の印が在るときは、そのアクターを飛ばして `warn!` を 1 行残す（b の Constraints は「既定のシェルへ戻し」と書くが、舞台のアクターには「既定のシェル」が決まらないので、飛ばす、を仮定にした）。

### 4.6 台詞の字の行き先と、話者の名前

- 合図の `actor` は、話者のままにする（字に合わせて動く SERIKO のアニメーションは、話者の側で動かしたいので、合図を書き換えない）。回すのは、文字の層である。
- 文字の層に足す物:
  - 箱の表を、アクターごとに持つ（今は 1 つ。デスクトップでは、全スコープに同じ表を入れるだけで、動きは変わらない）。
  - 行き先を「スコープの中の場所」から「（持ち主のアクター, 場所）」へ広げる。舞台が開いていて、並びに、出ているトークの場所が居るとき、トークの場所でないアクターの字の既定の行き先は、並びで最初の、出ているトークの場所の、既定の箱になる。トークの場所のアクター自身の字は、今の決まりのまま（自分の箱）。
  - 並び・役・「出ているか」は、文字の層がもう持っている材料（スコープごとの今のサーフェス番号）と、並びの内部の合図から決まる。
  - 行き先が決まらない字（舞台の中で、箱が 1 つも無い）は、出さずに `warn!` を残す。舞台のアクターには、ふつうのバルーンの表示対象を作らない。
- 話者の名前: トークの場所のシェルの、決まった名前の箱（名前は取り決めで決める）へ、その 1 本で最初に字を回したときに、話者の並びの名前を置く。`\![play,speaker,名前]` が先に在れば、それを置く。トークの場所のアクター自身の字のときは、名前の箱を空にする（仮定。取「要件定義へ送ること」の問いのまま）。
- 選択肢・クリック待ちの印・`\c` も、字と同じ行き先へ行く。

### 4.7 転換・揺れ・フラッシュ（時刻の扱い）

- **時計**: 転換は、トークより長く生きる（待たせないので、次の 1 本が来ても走っている）。だから、値は「絶対の始まりの時刻と長さ」の関数で決める。始まりは「そのトークの起点 ＋ 転換の合図の `at`」。毎フレーム、今の時刻から途中の値を計算する。フレームを数えない。当てるのが遅れたら、過ぎたぶんだけ進んだ値から出る。
- **組**: `CastScopeSink` は、転換の命令から「次の字・次の待ち・次の転換・列の終わり」までを、先渡しの列から先に知っている。字と待ちだけが時刻を進めるので、転換の組は、いつも同じ時刻の組の中に収まる。`StageCueSink` の 1 通に「この組の、ここから後ろの変更は、何ミリ秒かける」と書く。
- **値の転換**（透明度・位置・大きさ・並びの出入り）: 差を当てるとき、今の途中の値を出発点に、新しい値へ動かす。並びを出るアクターは、透明度 0 へ動かし終えてから外す。重ね順は、その瞬間に替える。
- **サーフェスの転換**: 組の中で seriko から届いた「絵の替え」だけを、溶かす対象にする（SERIKO のコマ送りは、組の外で届くので溶かさない）。前の絵の表示の記録を「消えていく前の絵」として新しい絵の上に残し、不透明度を 1 から 0 へ動かして、終わったら外す。転換の途中に次の転換が来たら、消えかけの絵は消え続けさせ、今の絵を新しい「前の絵」にする（前の絵を何枚か持つ）。
- **飛ばす**: 早送り（`talk-fast-forward`）と、出し直しの印と、転換なしの変更は、走っている転換を終わりの値へ飛ばす。舞台の時計はトークの時計と別なので、早送りは「知らせ」として受ける（6 章）。
- **揺れ**: 舞台の中身の offset を、時刻の関数で揺らす（当たりの境も一緒に動く）。**フラッシュ**: 舞台いっぱいの色の Visual の不透明度を、時刻の関数で 1 から 0 へ動かす。どちらも残らない。強さと長さの値は決まっていない。
- 速さの形は等速で始める。形を選ぶ書き方は `element-animation-easing` が後から添える。

### 4.8 入力と、舞台から出る道

- 舞台の上のクリックは、舞台の窓の入口 1 つで受ける。点から、いちばん手前の、α ≥ 0.5 のアクターを決め（wintf の今の当たりの道）、そのアクターの表示対象で、今の `hit_region_client` を引く。届ける座標は、そのアクターの絵の中の座標（k で割った値）にする（仮定。8 章）。
- 黒い余白と、どのアクターにも当たらない点は、送らない（後ろは仮定。8 章）。
- 舞台の窓の閉じる要求は、今のゴーストの窓と同じ受け手へつなぎ、`OnClose` の流れへ入れる（3 章の口がそのまま使える）。全画面とボーダーレスでも Alt+F4 は効く。SHIORI が答えないときは、今の終了の流れの待ちの上限で抜ける（上限が在ることは読んでいない。11 章）。

### 4.9 色調とカメラとの境（設計しない）

- 色調とカメラは、舞台の全体に効く残る命令である。`StageState` に欄を足せば、状態の持ち方（差を当てる・出し直しで既定へ戻す）は同じ形で受けられる。
- 描く側は、案 A のままでは受けにくい。カメラ（舞台の中身の変形）は、当たりの境の計算（`GlobalArrangement`）が変形を知らないので、ずれる。色調は、アクターごとの描画面のままでは、舞台の全体に 1 度で掛けられない。後半で、案 B（1 枚の描画面）へ替えるかを決める。

### 4.10 失敗の扱い

| 失敗 | 扱い |
| ---- | ---- |
| 並びの名前が解けない・シェルが読めない・「借りないで」 | そのアクターを飛ばす。`warn!` を 1 行（名前・理由）。番号は詰めない（後ろのアクターの番号をずらさない） |
| 並びに無い番号・帯の中の番号で打たれた合図 | 捨てて `warn!` |
| 舞台が閉じているのに届いた舞台の命令（並び・位置・転換ほか） | 何もせず `warn!` |
| 読めない引数（位置・時間・形） | その命令だけ捨てて `warn!`。状態は変えない |
| 知らない席の名前 | 位置を変えずに `warn!` |
| 行き先の箱が無い字 | 出さずに `warn!` |
| 組がそろわない（seriko が止まった・読み込みが終わらない） | 上限の時間で、そろった分だけ当てて `error!`（上限の値は決まっていない） |
| 舞台の窓が作れない | `error!` を残し、デスクトップの窓は隠さない。舞台は閉じたまま |

テストの境: `StageState`・`auto_layout`・`stage_fit`・`CastScopeSink` の畳み込みは、どれも時計も窓も見ない純粋な関数にして、決定論のテストで押さえる。

| wintf（持ち主の spec が無い） | 枠つきの窓の大きさの換算の確かめと直し・窓を隠す／出す口・全画面への切り替え。この単位が持つか、先に小さい単位を立てるかは決めていない（10 章では「窓の形」の切りに数えた） |
| メニュー（持ち主は未定） | シェルの切り替えのメニューから、役が背景・トークの場所のシェルを隠す（取「舞台の窓と箱」） |

## 7. 置いた仮定

1. 舞台を開く・閉じる・形を替えるは、1 つの命令（仮 `\![play,stage,…]`）で受ける。
2. 舞台のアクターの鍵は、数の帯（`STAGE_SCOPE_BASE` から上）で分ける。
3. 並びを出たアクターの残る値（位置・重ね順・大きさ・透明度・表情）は消える。入り直したら既定から始まる。
4. 出し直しでは、表情を「無い」へ戻さない（pasta が全部書く前提）。
5. 読んだシェルは、舞台が開いている間は持ち続ける。読み込みは、並びに初めて入ったとき。
6. 借りたシェルが無い・読めないアクターは、既定のシェルへ戻さず、飛ばす。番号は詰めない。
7. ボーダーレスは、枠なし・絵の無い所は透明・余白は無い（areka の見立て `window-modes` のまま）。
8. マウスの座標は、そのアクターの絵の中の座標（k で割った値）で届ける。どのアクターにも当たらない点は送らない。
9. 重ね順の数は、大きいほど手前。明示しないアクターは、役ごとの既定の数を持つ。
10. 舞台が開いている間、ほかの出どころ（SSTP・MCP）の台本の番号も、並びで読む。
11. 描く木は案 A（アクターごとに描画面）。フェーズ 3 の前半は、これで足りる。
12. トークの場所のアクター自身の字では、話者の名前を出さない。
13. 揺れとフラッシュの強さ・長さは、引数で受ける（値は未定）。
14. 舞台の窓は、ゴーストに 1 枚まで。

## 8. 決まっていない所（開発者に諮る問い）

1. **舞台の中の透明度・大きさ（と位置・重ね順）を、どのタグで受けるか。** `play` の命令だけにするか、正典の `\![set,alpha]`・`\![set,scaling]` も「そのスコープの絵がどこに在っても効く」として舞台のアクターへ届けるか。→ 後者なら、受け手の表（`consumer_ledger`）の担当が `window-timed-directives` と重なり、舞台のアクターへ回す分岐が向こうの受け手に入る。
2. **マウスの座標の原点と、絵の無い所のクリック。** 原点は、アクターの絵の左上か、舞台の左上か。背景が無い舞台で、どのアクターにも当たらない点のクリックを送るか（送るなら Reference3 は何か）。→ 送らないなら、「どのシーンも拾わない所を押して進める」（骨 2.6）が、背景の無い舞台では効かない所ができる。
3. **アクターの名前 → シェルの対応の置き場。** 舞台の定義（descript の独自キー）に並べるか、ゴーストの `shell/` の下のフォルダ名と同じ名前で引くか。→ `ghost-material-metadata` のキーの一覧と、4.5 の解き方が変わる。
4. **読み込みの時期と、性能の目標。** 舞台を開くときに定義の全アクターを読むか、並びに入ったときに読むか。メモリと、開くまでの時間の上限。→ 4.3 の「組がそろうまで待つ」時間と、4.5 の持ち方が変わる。
5. **止まった舞台から出る道。** 終了（× と Alt+F4）だけにするか、舞台だけ閉じてデスクトップへ戻る道（ベースウェアのキーかメニュー）も持つか。→ 後者なら、pasta の知らない所で舞台が閉じるので、pasta へ知らせるイベントが要る（5 章の 11 が変わる）。
6. **ボーダーレスの中身。** 絵の無い所は透明か黒か。大きさは何で決まるか。→ 4.4 の表と、クリック透過の扱いが変わる。
7. **並びを出たアクターの状態。** 消すか（仮定 3）、舞台が開いている間は名前に付けて残すか。→ 残すなら、5 章の 4 が要らなくなり、出し直しの「既定へ戻す」の範囲が広がる。
8. **自動の配置の決まり。** 役者の位置の基準点（足もとの中央か）・間隔・背景とトークの場所の置き方。数値の位置は、アクターのどこを合わせるか。→ `auto_layout` の中身。
9. **描く木を案 A で始めてよいか。** 後半（色調・カメラ）で案 B へ替える見込みを、今のうちに織り込むか。→ 織り込むなら、wintf の新しい節の当たり判定を先に作る仕事が増える。
10. **組がそろわないときの上限の時間**と、舞台の窓が作れないときに pasta へどう伝わるか（既定のゴーストの台詞で伝える決まりとの関係）。

## 9. 差し戻しが要りそうな所

上位の決定の中身を変える必要が在る物は、見つからなかった。文面の食い違いと、決定のすき間が、次のとおり在る。どれも、取り決めの要件定義で閉じられる見込みである。

1. **「役」の文面が、同じ brief の中で割れている。** `novel-areka-contract/brief.md`「画面の部品はアクター」: 「『背景』『ボタン』『システム』という役や種別を、pasta にも取り決めにも作らない」。同「舞台の窓と箱」: 「位置を明示しないアクターは、並びと役（背景 → 役者 → トークの場所）から自動で置く」「ベースウェアが『トークの場所』の役のアクターの箱へ出す」。骨子 2.7 も「役や種別を、pasta に作らない」と「『トークの場所』の役のアクター」を並べて書く。この設計は「役は、シェルの descript の属性（areka の側）で、命令の種別ではない」と読んだ。取り決めの文書は、役を説明しないと、自動の配置と字の行き先を書けない。文面を 1 つにしてほしい。
2. **Reference3 の番号を、pasta が読み違えるすき間。** 「舞台の窓と箱」: 「スコープの番号は並びの順で、同じ 1 本の中でも、並びの命令の位置で意味が切り替わる」と、「画面の部品はアクター」: 「押すと `OnMouseClick`（Reference3＝どのアクターか…）で届く」を合わせると、並びが替わる 1 本の再生中に押されたクリックの番号が、替わる前の並びの物か後の物かを、pasta は知る手段が無い。直す向き: areka が、舞台のイベントに、アクターの名前も載せる（Reference の後ろに足す）。正典の並び（ukadoc `OnMouseClick`: 「Reference3: 本体の場合は0、相方の場合は1。SSP/CROWでは2以降もある。」 `https://ukatech.shillest.net/ukadoc-spec/list_shiori_event.html#OnMouseClick`）は変えない。
3. **フェーズの表の文面。** `play-script-guide.md` 6 章のフェーズ 3 の後半に「舞台の全体を溶かす転換とルール画像」が在る。brief「転換」は「黒を挟む形と、ルール画像は入れない」、骨子 3 章は「転換の種類（暗転・明転）・ルール画像」を取り下げた物に挙げる。後半で作るのか、作らないのかが割れている。同じ 6 章のフェーズ 3 の前半は「舞台の窓（ウィンドウと全画面）」で、brief の 3 つの形のうち、ボーダーレスのフェーズが書いていない。
4. **areka の brief が古い。** `shell-multi-compose/brief.md` の Desired Outcome・Scope の「クロップ」「暗転」「スライド」「ルール画像のワイプ」「色調」は、上の決定の前の文である。正式な要件定義の前に、brief を読み替える追記が要る（上位の決定への差し戻しではない）。

## 10. 規模の見立て

- 全体で **46〜66 タスク**の見込み。brief の見立て（L 超・要件の段で切る）と合う。切り方は、brief の 3 つに、土台を 1 つ足した 4 つが自然である。

| 切り | 中身 | タスクの幅 |
| ---- | ---- | ---------- |
| 土台 | `CastScopeSink`（読み替えと組の終わり）・seriko と文字の層の「アクターごとの表」・組の適用 | 12〜16 |

## 11. 確かめた物と机の上だけの物
