## Implementation Notes

- 2.1: Windows の Copy-Item/copy は LastWriteTime を保存するため、ソースをバックアップから復元すると cargo が再コンパイルせず「stub 版のキャッシュバイナリ」でテストが走り偽の失敗を出す。復元後は必ず mtime を更新（touch）してから cargo test すること。ミューテーション検証（実装 stub 化→テスト赤確認→復元）はレビュアーと親で同時にやらない（作業ツリー競合）。

- 2.4: design 正準の数式（round/ceil 等）は割り切れる値だけでなく端数ケースで檻化する（floor/ceil 変異を殺す値を選ぶ）。レビュアーの変異検証で檻穴が実際に検出された（round→floor で全緑だった）。10.3 の複数スケール検証でも同様に。
