## そのほかの指摘

タスクの前に直す物（どれも 1 行から数行）:

1. **文字の線には、フレームを起こす旗を立てる者が居ない**（「areka-runtime」の「次のフレームを起こす」・「areka-emo-text」の「次のフレームを起こす」）。設計が足した予約は、`advance` が「待っている時刻」を返した時だけに働く。文字の線の物は、フレームの外で届く（UI のスレッドのメッセージ。`crates/areka-actor/src/ui.rs:90`）ので、届いた物の時刻は、次のフレームでは必ず来ている。本番で要るのは「物を列に足した後に、フレームが回る事」のほうである。文字の受け口も、受け取る所も、旗を立てない（旗を立てる所は `crates/areka-runtime/src/talk_lifecycle.rs:212`・`adapter.rs:166`・`move_cue.rs:354` ほかで、`areka-emo-text` には無い）。今は、同じ合図から出た寿命の知らせの旗でフレームが回る。
   - 列: トークのスレッドが、文字の受け口へ合図を送り、続けて寿命の受け口が旗を立てる（受け口の並びは `crates/areka-session/src/runtime_boot.rs:80-84`）。UI のスレッドが、文字のメッセージを読む前に、その旗でフレームを回す（`advance` は空の列を見て、何も予約しない）。その後で合図が列に入る。次の旗か、心拍（30 回の画面の更新。`crates/wintf/src/ecs/world/tick_gate.rs:53`）まで、合図は当たらず、後ろの印も当たらない。
   - 今のコードでも、同じ巡りで描くのが遅れる。新しい作りでは、状態を当てる事も遅れる（今は、届いた時に当たる）。「areka-runtime」の「本番では、列に物が残るのは、…そのフレームの間に届いた時だけ」は、寿命の線については正しいが、文字の線には当たらない。
   - 直し方の案: UI のスレッドで列に物を足した時に、旗を立てる（`tick_wake` の旗の持ち主の一覧と、それを照らすテスト＝`tick_wake.rs:19-23` が言う 2 本も一緒に直す）。借りられずに進められなかったフレームも、同じ旗を立てる。テスト（「受け手の追従」）に「空の列で `advance` を呼んだ後に物が届いた時、次のフレームが予約される」を足す。
2. **要件 12.4 の「もう現れた字」が、D22 の限界と読み分けられない**。12.4 は「効く時刻より後の物を動かす」と「もう起きた事（もう現れた字）を書き換えない」を並べる。後ろへ動かす知らせが遅れて着いた時、効く時刻より後で、もう見せた字は、両方に当たる。設計は、その字を動かす（見えなくなる）と決めた。12.4 の括弧を「効く時刻以前に現れた字」と言い切るか、限界（知らせが着くまでのフレームは、着く前の時刻のまま見せる）を 12.4 か 18.1 に 1 句足す。18.1 の「字が、どこまで現れるか…届いた時刻に左右させない」も、同じ限界に当たる。
3. **文字の相は、借りられないフレームを見送らない**（「areka-runtime」の「`advance` を呼ぶ所」と Error Strategy の「文字の層が借りられないフレーム」）。設計は「可視性の相と文字の相は、今の決まり（借りられなければ、見送る）のまま」と書く。可視性の相は、そのとおりである（`crates/areka-runtime/src/balloon_visibility_phase.rs:343`・`:607`）。文字の拡大率の相と文字の相は `borrow_mut()` で、借りられなければ、そこで落ちる（`crates/areka-runtime/src/frame/scale_text.rs:101`・`:107`・`:233`）。進める相だけが `error!` で見送っても、同じフレームの後ろの相が落ちる。進める相を、文字の相と同じ扱いにするか、3 つの相をそろえて見送るかを、1 行で決める。

実装の時に決めればよいが、設計に 1 行ずつ要る物:

4. **seriko の `TalkFeed` は、字の列と別に「前の字の時刻」を持つ**（`crates/areka-seriko/src/talk.rs:76-98` の `last`。列は、数えた分を刈り込む）。知らせの決まりを、列だけでなく、この欄にも当てると書く。当てないと、次の塊の「前の字」が、文字の層（列の最後の字を読む。`crates/areka-emo-text/src/state.rs:293`）と食い違う。
5. **並走の流れの知らせ**（「使い手の居ない口の確かめ」の「並走の流れの待ち」の行）。受け手は、持っている時刻を再生ごとに分けない。流れの置き直しの知らせを、流れの複製の受け口が seriko へ送ると、主の流れの字の時刻が動く（文字の層は、流れの複製を持たないので動かない）。「後の spec が足す物」に、「流れの複製の受け口は、置き直しの知らせを受け手へ送らない」を足す。知らせの形は変えずに済む。
6. **起点が先の時刻の台本の先渡し**。先渡しは時刻を持たないので、受け口の登録の時に届き、列が空なら、その場で当たる（起点の時刻より前）。選択待ちの口を閉じ、空回しを入れ替える。前の再生の字は、状態の写しに在るので、配置は変わらないはずだが、要件 18.4（起点が来るまで、その台本の何も現さない）との関係を 1 行書く。本番の起点は最初の刻みなので、間は無い。
7. **字が先の時刻まで現れない間の予約**（「次のフレームを起こす」の 3 つ目）。今の予約は、現れていない字が在る間、毎回の画面の更新を予約する（`scale_text.rs:242-250`）。後ろへ長く動かす置き直しの後は、その長さの間、毎回回る。次に現れる字の時刻へ予約する形にできる。この spec に置き直しの使い手は居ないので、限界として書くだけでもよい。
8. **要件の字面の整え**。12.10 は、主語（文字の層と seriko とバルーンの寿命の時計）と、する事（字を現す・字のほかの指令と寿命の知らせを効かせる）が、掛け合わせで読める（寿命の時計は字を現さない）。12.8 は、3 つの事（絶対の時刻で持つ・知らせで動かす・同じフレームの時刻で判断する）を 1 文に持つ。受け手ごとに分けると、タスクと突き合わせやすい。「要件の討議で決まった事」の「台本の時刻 0 に丸めない」（`requirements.md:351`）は、12.10 の新しい言い方（時刻を 0 に丸めない）へ合わせる。「While 起点が 1 度も置き直されていない」は、今も意味が在る（置き直しの知らせを 1 つも当てていない間、字の時刻は発火時刻＋隔たりのまま）。

## 確かめて成り立った事

- **列の頭で待つ物**: 列に入る時刻は、合図の発火時刻・置き直しの効く時刻・現実の出来事の時計の読みで、どれも、送った時より後にならない。呼び手の現在の時刻が戻らない限り、置き直しの前に取り出した合図の発火時刻は、効く時刻以前である。だから、知らせが、時刻の来ていない合図の後ろで待つ列は、作れなかった。前へ動かした後の合図（発火時刻が効く時刻より前）は、知らせの後ろに並ぶので、効く時刻より前のフレームでは当たらない。前提が破れた呼び方（効く時刻より後の発火時刻の合図が、知らせより前に在る）でも、文字の層と seriko は、届いた順に同じ決まりを当てるので、持つ時刻は同じである。
- **字の時刻を積む時と、知らせを当てる時**: 文字の層は、合図を当てる時に字の時刻を積む。知らせを同じ列に並べるので、どのフレームで当てても、「届いた順に全部当てた」結果になる。seriko が届いた時に当てた結果と同じである。試した列: 合図 → 知らせ（前へ・後ろへ）→ 合図・取り出しごとの前への置き直し（字は、どれも効く時刻以前にそろう）・後ろへ動かして前へ戻す・その都度受ける受け手と、遅れてまとめて受ける受け手。
- **2 本の線**: 寿命の線と文字の線に、同じ合図の物が別のフレームで届いても、食い違う起点が無い。寿命の時計は、表示の終わりを、受け口と同じ決まりで動かす（受け口は、最大が上がるたびに送るので、受け手の最大は、知らせの時の受け口の最大と同じである）。
- **寿命の受け口が、最初の合図より前の知らせを送らない事**: その時、寿命の時計が持つのは、前のトークの期限だけで、期限は決まりで動かさない。受け口の複製は、トークごとに最大を空から始める（`crates/areka-runtime/src/talk_lifecycle.rs:216-229`）。動かし残す物は無い。
- **自然に終わったトークの期限**: 実効の表示の終わりは、表示の終わりと止まった時刻の早い方で（`crates/areka-runtime/src/balloon_visibility_wait.rs:93-111`）、自然に終わったトークの止まった時刻は、表示の終わり以後である。期限は、台本と起点で決まり、受け手の時計の読みに依らない。中断と選択肢つきは、現実の出来事の時刻を使う（要件 18.2 の「届いた時刻から導かない」には当たらない）。
- **利用者の中断**: 押下の後に同じスレッドで読むフレームの時刻は、押下の時刻以後である。押下より前に線に入った知らせの時刻も、そのフレームの時刻以前である。列の頭で押下を待たせる物は無い。
- **消去**: 文字の層は、当てる時に、その場所の字を全部捨てる。seriko は、発火時刻より後の字を捨て、次の塊を頭から始める（`crates/areka-seriko/src/talk.rs:94-98`）。どちらも届いた順に当てるので、消去 → 前への知らせ → 消去より前の発火時刻を持つ合図、の列でも、後の合図の字は、どちらにも残る。
- **選択待ちの印と押下**: 選択肢の合図と印は、同じ刻みで続けて届く。間にフレームが回らなければ、同じ `advance` の中で順に当たり、回っていれば、印は、空の列に届いて、その場で当たる。どちらでも、選択肢が画面に出た時には、印は当たっている。
- **中断・読み直し・切り替え**: 実行系だけを起こし直す読み直しは、文字の層と線を残す（`crates/areka-runtime/src/lib.rs:478-480`・`crates/areka-session/src/ghost_session_runtime.rs:62-68`）。残った物は、次のフレームで時刻が来て当たる。トークの終わりの通し番号を、線から取り出した時に数える決め（`crates/areka-runtime/src/frame/drain_resnap.rs:207-208`）は、届いた順の突き合わせに合う。
- **文字の層が持つ時刻**: 字の現れる時刻（場所ごとの `RevealSchedule`）だけである（`crates/areka-emo-text/src/state.rs:262`・`:504`・`:559`・`:589`）。知らせで動かす物は、ほかに無い。
- **段取り**: 後半の 3（列の型）は、時刻の型だけを使うので、1・2 と並べられる。足した持ち主（`balloon_visibility_held.rs`・`frame.rs`・`frame/wiring.rs`・`areka-input` の `user_break.rs`・`[dev-dependencies]` の行）は、家族の間で重ならない。
- **前の決めの残り**: `design.md` に、受け手が持つ起点・台本の時刻を受ける口・`HeldAt`・`Released`・最初の起点の知らせを待つ事・「確かめてある字の数」は、後半の姿としては残っていない（前半の間の形としてだけ書いて在る）。dola の側の節は、D12・D19・`TimeSpan::try_from_ticks`・最初の起点の知らせの説明のほかは変わらず、食い違いは無い。
