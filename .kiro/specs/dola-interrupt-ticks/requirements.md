# Requirements Document

## Project Description (Input)

困っているのは、dola の使い手（areka の各エンジンと wintf）と、dola の上にノベルの高速再生基盤と並走を建てる開発者である。

dola は「同じ台本を、別々の表示役（別のプロセスでもよい）へ配り、同じ絶対時刻に鳴らす」ための層なのに、時刻が素の `f64` の秒で、時計も「このプロセスで QPC を QPF で割った秒」（`dola::runtime::clock::now`）でしかない。`f64` の秒は足し引きのたびに丸めが積もり、同じ時刻を別の経路で計算すると一致しないことがある。時刻の物差しも、プロセスの外で通じる形になっていない。あわせて、ノベルの作り直しの検証（`doc/ideas/novel-redesign-2026-11-20/00-architecture.md` の 4.3・`92-validation-code.md` の 3〜5）で、高速再生基盤と並走が時刻の土台に 5 つを求めると分かった（起点が、もう配った合図にも効く・起点が、台本の始まりより前へ動ける・合図が、絶対の発火時刻を持つ・トークのスレッドへ送る刻みが、絶対の時刻である・storyboard の層を後ろへ切らない）。今の dola は、どれも約束していない。

直した後の姿: dola の時刻は「`QueryUnbiasedInterruptTimePrecise` が返す 100ns 単位の整数」を物差しにした型で表され、`f64` の秒は dola の公開の口から消えている。「今」を読む関数は 1 つで、同じ機械の上ならどのプロセスで読んでも同じ物差しの値になる。直列化した台本も同じ物差しで、別のプロセスへ渡しても読み替えが要らない。dola の使い手の 9 つの crate は全部新しい型で dola を呼び、wintf の `FrameTime` と areka の `TalkClock` はその関数から「今」を読む。ghost の刻み・kanade・seriko の時計も同じ 1 本の時計を読み、`GetTickCount64` を読む所は本番に無い。ノベルの作り直しが求める 5 つも入っている。これを 1 本の spec で最後まで終える。

（`brief.md` が正本。「時刻の土台」の 3 本の 1 本目。）

## Introduction

この spec は、dola の時刻の土台を作り直す。時刻（ある瞬間）と長さ（2 つの瞬間の差）を 100ns の整数の型にし、「今」を読む時計を `QueryUnbiasedInterruptTimePrecise` の 1 本にし、直列化した台本を同じ物差しにし、dola の使い手の全部の crate を追従させる。そのうえで、ノベルの作り直しが時刻の土台に求める 5 つを入れる。

範囲は分けない。型・時計・直列化の形・使い手の全部の追従・ノベルの 5 つは、この 1 本の spec の中で最後まで終える（要件 15）。

要件は、確かめ方の違う 3 つの組に分かれる。組ごとに、それぞれの物差しで確かめる。

| 組 | 要件 | 中身 | 確かめ方 |
|---|---|---|---|
| 型の付け替え（振る舞いを変えない） | 1〜9 | 型・時計・単位の変え方・dola の公開の口（cue の層と storyboard の層）・直列化の形・使い手の追従・「今」を読む所 | 同じ入力から、付け替えの前と同じ結果が出ることをテストで示す（要件 9） |
| 振る舞いを変える | 10〜14・17 | 止めて戻すときの時間の数え方・起点の置き直し・置き直しが、もう配った合図にも効くこと・合図の絶対の発火時刻・トークのスレッドへ送る刻み・時計の統一 | 新しい振る舞いを、要件ごとのテストで示す。変える前の期待と変えた後の期待を名指しで分ける（要件 9 の 6） |
| 全体の成り立ち | 15〜16 | 1 本の spec で終えるための縛り・文書 | spec の終わりの状態で確かめる |

ノベルの作り直しの 5 つと要件の対応: 1（起点が、もう配った合図にも効く）＝要件 12、2（起点が、台本の始まりより前へ動ける）＝要件 11、3（合図が、絶対の発火時刻を持つ）＝要件 13、4（トークのスレッドへ送る刻みが、絶対の時刻である）＝要件 14、5（storyboard の層を後ろへ切らない）＝要件 5。

この文書の語:

- **時刻**＝ある瞬間。**長さ**＝2 つの瞬間の差。
- **起点**＝台本の時刻 0 が当たる絶対の時刻（`CueSheet` の `absolute_start_time`・時刻の表の開始の時刻）。**台本の時刻**＝今 − 起点。
- **合図**＝受け口へ配る 1 件（`TalkCue`）。**受け口**＝`CueSink`。**時刻の表**＝`TimedSchedule`。**再生機**＝`CuePlayer`。**刻み**＝時刻を進める 1 回の呼び出し（`tick`）と、その時刻を運ぶ知らせ。**区切り**＝`BarrierKind`。**占有の終わり**＝台本の全部の合図の「開始＋長さ」の最大（`occupancy_horizon`）。
- 起点を**前へ**動かす＝より早い時刻（過去の側）へ置き直す。台本の時刻は進む。起点を**後ろへ**動かす＝より遅い時刻へ置き直す。台本の時刻は戻る。

要件の文の中の「（仮定 n）」は、brief だけでは決め切れずに仮に置いた前提を指す。一覧は末尾の「仮定と、要件の討議で決めること」に在る。

## Boundary Context

- **In scope**:
  - 時刻の型と長さの型・「今」を読む関数（`QueryUnbiasedInterruptTimePrecise`）・これまでの時計 `dola::runtime::clock::now` の置き換え。
  - dola の公開の口の全部（cue の層と storyboard の層の両方）を、`f64` の秒から新しい型へ替えること。
  - 直列化の形の変更と、往復のテスト。
  - dola の使い手の追従＝`areka-sakura`・`areka-seriko`・`areka-emo-text`・`wintf`・`areka-ghost`・`areka-runtime`・`areka-session`・`areka-input`・本体（`areka`）の、本番のコードとテストのコード（一覧は着手のときに数え直す）。同じ時刻をやり取りする `areka-talk`・`areka-kanade` と、先進坑の呼び手も含む。
  - 時計の統一: ghost の刻み・kanade・seriko の時計と、台詞の刻みの中継を、dola の時刻の型と時計へ替えること。台本の起点を、配る時に本物の絶対時刻（dola の時計の値）で押すこと。文字の層と seriko が起点を見積もるのをやめ、押された起点を読むこと（`talk-anchor-interrupt-ticks` の範囲を、この spec に入れる）。
  - wintf の `FrameTime` と areka の `TalkClock` の時計の差し替え。
  - storyboard の層の、止めた再生を戻すときの時間の数え方の直し（`transition` で再生中へ戻すと、止めた時点の記録が残る穴）。
  - ノベルの作り直しの 5 つ: 起点の置き直し（前へも後ろへも）・置き直しを受け口へ知らせ、文字の層の時計・口パク・バルーンの寿命の時計が付いて来ること・合図の絶対の発火時刻・トークのスレッドへ送る刻みの絶対の時刻・storyboard の層を同じ spec で替えること。
  - 文書: dola の README（今の姿だけ）・`tech.md` の dola の依存の行・替えた所の説明。
- **Out of scope**:
  - `std::time::Instant` で測る締め切りと入力の時刻、別の時計を止める番人（`instant-to-interrupt-ticks`）。
  - 暦の時刻（ログの日時・`GetLocalTime`・日付のイベント）。
  - 別のプロセスで実際に同期して再生すること。
  - 高速再生基盤そのもの（字を一度に出す・待ちを飛ばす・クリック待ちを通る）、`\x` の待ち、吹き出しのクリックの早送り、並走の流れ、値を時間で変える口（始める／終わりの値にする／止める／値を読む）。この spec が作るのは、それらが乗る時刻の土台（起点の置き直し・知らせ・絶対の発火時刻の口と決まり）まで。本番で起点を置き直す使い手は、この spec の中には居ない。
  - 台本の再生の振る舞い（いつ何が鳴るか）のうち、要件 10〜14・17 が変えると決めた所のほか。
  - 表示の周期（`DwmFlush` の待ち）と刻みの出どころ・刻みの周期（50・1000・16 ms）。
  - 区切りの種類を増やすこと（`BarrierKind` の新しい種類）。
- **Adjacent expectations**:
  - `instant-to-interrupt-ticks` は、この spec の型と時計を使う。`talk-anchor-interrupt-ticks` の範囲は、この spec に入れた（その spec は、この spec の着地で役目を終える）。kanade は今 dola に依存していないので、型と時計の置き場は、kanade が使える形を設計で決める。
  - 高速再生基盤・並走・値を時間で変える口の spec は、この spec の起点の置き直し・合図の絶対の発火時刻・刻みの絶対の時刻の上に建つ。この spec の後に、dola の時刻の土台をもう一度作り直さないことを前提にする。
  - 同じ時に走らせない相手: `element-animation-easing`（dola の `easing.rs` と storyboard の層）・`seriko-talk-clock-fidelity`・`talk-fast-forward`・`sakura-embed-directive`（`talk_clock.rs`）・`tick-gate-adoption`（wintf の `world/mod.rs`）。この spec は、ほかの spec が走っていない時に 1 本だけで通す。先に着地した spec が dola に足した口が在れば、その口の時刻も型を替える。
  - `dola-cue-test-builder` が作った正準のキャリアの合図の組み立て（dola の機能 `test-support`）は、使い手のテストが呼び方を変えずに済む形で保つ（要件 7 の 6）。
  - kanade の選択待ちの時間切れの権限の持ち主と、指令の読み分けは変えない（要件 4 の 6・14 の 6・17 の 5）。

## Requirements

### Requirement 1: 時刻と長さの型

**Objective:** As a dola の使い手, I want 時刻（ある瞬間）と長さ（2 つの瞬間の差）を 100ns の整数の別々の型で扱いたい, so that 足し引きで丸めが積もらず、時刻と長さを取り違えない

#### Acceptance Criteria

1. The dola shall 時刻を表す型と、長さを表す型を、別々の型として公開する
2. The dola shall どちらの型も 100ns を 1 とする整数で値を持ち、時刻の型の値を `QueryUnbiasedInterruptTimePrecise` が返す値と同じ物差しとする
3. The dola shall 時刻に長さを足し引きした結果を時刻として、時刻から時刻を引いた結果を長さとして返し、意味の通らない足し引き（時刻と時刻の足し算など）をコンパイルの時点で通さない
4. The dola shall 時刻と長さの足し引きを整数のまま行い、同じ値を別の順で足し引きしても同じ結果を返す
5. If 時刻の引き算の結果が負になる, then the dola shall その結果を、黙って 0 や別の正の値に変えずに、負であることを呼び手が区別できる形で返す
6. If 足し引きの結果が型の表せる範囲を越える, then the dola shall 値を回り込ませない
7. The dola shall 「終わりが無い」こと（周回の後の待ちで最後の値を保つ間の区間の終わり・終わりの期限が無いこと）を、時刻の型の普通の値と取り違えない形で表す
8. The dola shall 時刻の型と長さの型を、Windows でない所でもコンパイルできるようにする
9. The dola shall 負になりうる差を運ぶための符号つきの差の形を公開し、負の値が意味を持つ所（選択待ちの時間切れの指令・storyboard の層の負のオフセット・起点より前に置かれた区間の時刻）で、0 以上の長さの型と取り違えない

### Requirement 2: 「今」を読む時計

**Objective:** As a 時刻を読む使い手（wintf と areka）, I want 「今」を読む関数を 1 つだけにしたい, so that どのプロセスで読んでも同じ物差しの値になり、時計が増えない

#### Acceptance Criteria

1. The dola shall 「今」を時刻の型で返す関数を、1 つだけ公開する
2. When 「今」を読む関数が呼ばれた, the dola の時計 shall `QueryUnbiasedInterruptTimePrecise` が返した値を、丸めも換算もせずに時刻の型で返す
3. The dola の時計 shall プロセスごとの起点や倍率を持たず、同じ機械の上の別のプロセスで読んだ値と同じ物差しの値を返す
4. When 「今」を続けて 2 度読んだ, the dola の時計 shall 後の値を前の値より小さくしない
5. The dola の時計 shall 眠り（スリープ・休止）の間を数えない時計とし、その決まり（復帰した瞬間に、眠っていた分だけ時刻が飛ばない）を時計の説明に書く
6. The dola shall これまでの時計（`dola::runtime::clock::now`＝QPC の秒）を公開の口から無くし、時計を 1 本だけにする
7. Where Windows でない所でコンパイルする, the dola shall 「今」を読む関数だけを除き、ほかの公開の口をそのまま使えるようにする
8. The dola shall 再生と評価の口で時刻を外から受け取り、自分の中から「今」を読まない

### Requirement 3: 作者が書く単位からの変え方と丸め

**Objective:** As a 台本・シェル・storyboard の文書を書く作者, I want 今までどおりミリ秒や秒で書きたい, so that 書き方を変えずに、中では正確な整数の時刻で扱われる

#### Acceptance Criteria

1. The dola shall 作者が書く単位（ミリ秒・秒）の値から長さを作る口を持ち、丸めの決まりをその 1 か所に書く
2. When 整数のミリ秒の値を長さへ変える, the dola shall 誤差の無いちょうどの値（1 ミリ秒＝10,000）にする
3. When 実数の秒の値を長さへ変える, the dola shall 最も近い 100ns へ丸める
4. If 変える元の値が有限でない（NaN・無限大）か、長さとして表せない（負・範囲の外）, then the dola shall 長さを作らず、作れなかったことを呼び手へ返す
5. The dola shall 倍率（`time_scale`）とイージングの進み具合を、実数のまま扱う
6. The dola shall 実数の倍率を時刻や長さに掛けて整数へ戻す計算を 1 か所にまとめ、その丸めを 3 と同じ決まりにする
7. The dola shall 作者が書く単位の値を、読み込む縁で 1 回だけ長さへ変え、変えた後の計算を整数のまま行う
8. The dola shall 符号つきの差も、作者が書く単位（符号つきのミリ秒）から作る口を持ち、表せる範囲の端を越える値を、今までどおり端の値へ張り付ける

### Requirement 4: cue の層の公開の口

**Objective:** As a dola の cue の層の使い手, I want 台本の再生に関わる時刻と長さを全部新しい型で受け渡ししたい, so that `f64` の秒を介さずに、同じ時刻を同じ値で扱える

#### Acceptance Criteria

1. The dola shall cue の層で時刻や長さを運ぶ公開の口（`Cue` の開始の時刻と長さ・`TalkCue` の時刻と長さ・`CueSheet` の起点と絶対の発火時刻と絶対の終わりの時刻・時刻の表の項目の時刻と刻みと占有の終わり・再生機の刻みと占有の終わり）を、ある瞬間は時刻の型で、起点からの隔たりと続く長さは長さの型で受け渡しする（区切りの時間切れの指令は 6 のとおり）
2. The dola shall cue の層の公開の口に、`f64` の秒で時刻や長さを運ぶ欄・引数・戻り値を残さない
3. The dola shall 絶対の時刻を「起点＋相対」の整数の足し算で作り、`f64` の秒のあいだの継ぎ（ミリ秒の格子で足す関数）を無くす
4. When 刻みの時刻が、ある項目の「起点＋相対」の時刻とちょうど等しい, the 時刻の表 shall その刻みで、その項目を届ける
5. The dola shall `TalkCue` の `at`（起点からの隔たり＝台本の時刻）を長さの型で運び、ある瞬間を表す欄（要件 13 の絶対の発火時刻）と型で区別する
6. The dola shall 選択待ちの区切りの時間切れの指令を、符号つきの差で、今までと同じ値と意味（指令が無い・0 と負・正の 3 通りを kanade が読み分ける）のまま運ぶ（0 と負を、失敗にも別の値にもしない）

### Requirement 5: storyboard の層の公開の口

**Objective:** As a 値を時間で変える仕組みを dola の上に建てる開発者, I want storyboard の層も cue の層と同じ型と物差しで動かしたい, so that 合図の時刻を、そのまま連続のアニメの時刻として渡せる

#### Acceptance Criteria

1. The dola shall storyboard の層を、cue の層と同じこの spec の中で替え、2 つの層に同じ時刻の型・同じ長さの型・同じ物差しを使わせる
2. The dola shall storyboard の層で時刻や長さを運ぶ公開の口（変化の定義の遅れと長さ・コンパイル後の開始と終わりと発火の時刻・実行時の開始／刻み／止める／戻すの時刻・終わりの期限）を、時刻の型か長さの型で受け渡しする
3. The dola shall storyboard の層の公開の口に、`f64` の秒で時刻や長さを運ぶ欄・引数・戻り値を残さない（倍率・イージングの進み具合・時間で変わる値そのものは実数のまま）
4. The dola shall cue の層の絶対の時刻（合図の絶対の発火時刻を含む）を、読み替え無しで storyboard の層の開始の時刻として受け取る
5. While 終わらないループを再生している, the dola shall 今までどおり、終わりの時刻を 1 周分の有限の時刻として持ち、周回ごとに延ばす（終わりの時刻そのものを「終わりが無い」にしない）
6. If 終わらないループの 1 周の長さが下限（0.1 秒）より短い, then the dola shall 今までどおり開始を拒む
7. When 進み具合を求める, the dola shall 経った長さと全体の長さ（どちらも整数）の比として実数の進み具合を求め、実数の秒の引き算を介さない
8. If 終わらないループの終わりの時刻を、これ以上延ばせない（延ばすと型の表せる範囲を越える）, then the dola shall 値を回り込ませずに、今までの「延ばせなくなったら周回を止める」決まりのとおりに扱う

### Requirement 6: 直列化の形

**Objective:** As a 台本を別の表示役（別のプロセスでもよい）へ渡す使い手, I want 直列化した台本が同じ物差しの時刻を運んでほしい, so that 受け取った側が、読み替え無しで同じ時刻に鳴らせる

#### Acceptance Criteria

1. The dola shall 直列化した `CueSheet` の時刻と長さ（起点・各合図の開始の時刻と長さ・区切りの時間切れ）を、100ns の整数の値として書き出す
2. When 直列化した `CueSheet` を読み戻した, the dola shall 書き出す前と等しい値を返す
3. The dola shall 直列化した `CueSheet` の起点を、時計の関数が返す値と同じ物差しの値として運び、受け取った側に単位や起点の読み替えをさせない
4. The dola shall 起点の押されていない `CueSheet` を、今までどおり直列化して読み戻せるようにする
5. If 読み込む値が、時刻や長さとして表せない（負・範囲の外・整数でない）, then the dola shall 読み込みを失敗として返す（区切りの時間切れの指令の 0 と負の値は、要件 4 の 6 のとおり読み込む）
6. The dola shall storyboard の文書に作者が書く時刻の値（遅れ・長さ）を、今までどおり秒で読み書きする（仮定 2）
7. When 秒で書かれた storyboard の文書を読み、書き出し、もう一度読んだ, the dola shall 1 度目と 2 度目で等しい値を返す
8. The dola shall dola が対応する書式のそれぞれ（機能 `toml` の下の書式を含む）について、往復のテストを持つ
9. The dola shall 付け替えの前の形（実数の秒）で直列化した `CueSheet` を読む互換の口を持たない

### Requirement 7: 使い手の追従

### Requirement 11: 起点の置き直し（前へも後ろへも）

**Objective:** As a 高速再生基盤と並走を dola の上に建てる開発者, I want 再生の途中で、時刻の表の起点を前へも後ろへも置き直したい, so that 早送り（起点を前へ）と、待ちの後の続き（起点を後ろへ）を、項目を 1 つも落とさずに表せる

### Requirement 12: 起点の置き直しが、もう配った合図にも効く

### 要件の討議で決まった事

- 時計は 1 本に統一し、`GetTickCount64` は使わない（要件 17）。`talk-anchor-interrupt-ticks` の範囲は、この spec に入れた。
- `areka-talk`・`areka-kanade`・先進坑も、追従の相手である（要件 7 の 1・7 の 11）。
- 使い手は、使う所まで新しい型のまま持つ。wintf のタイプライターと自動の上げ下げの判断を含む（要件 7 の 5・7 の 12）。
- ノベルの 5 つは、口と決まりまでを作る。本番で起点を置き直す使い手は、この spec の中には居ない（Out of scope）。
- 古い形の `CueSheet` を読む互換の口は持たない（要件 6 の 9）。古い形の説明も書かない（要件 16 の 2）。この spec は版の行を動かさない。
- Windows でない target でのコンパイルを、全体のテストの 1 段で確かめる（要件 15 の 8）。

## 設計への申し送り

要件では決めず、設計で決める事。開発者への問いではない。

1. **移行の段取り**: 影響はリポジトリの全体（dola の全部と、使い手の 9 つの crate）に及ぶ。この 1 本の spec の中で、並行のサブエージェントで進められる段取り（波の切り方・crate ごとの並行・途中の段でコンパイルを保つための継ぎを置くか。置くなら、要件 15 の 5 のとおり最後に消す）を、設計とタスクで決める。型の付け替えの段（要件 1〜9）と、振る舞いを変える段（要件 10〜14・17）を、別々に確かめられる順に並べる。
2. **型と時計の置き場**: dola の中の 1 か所か、その下の小さい crate か。後で kanade が使えること。
3. **型の細部**: 符号つきの差を持つか（要件 1 の 5）・「終わりが無い」の表し方（要件 1 の 7）・範囲を越えた時に張り付けるか失敗にするか（要件 1 の 6）・丸めのちょうど中間の扱い（要件 3 の 3）・倍率を掛けて整数へ戻す 1 か所（要件 3 の 6）。
4. **起点の置き直しの口の形**: 1 回の刻みの中で、取り出しごとに起点を動かす手段（要件 11 の 6）・受け口への知らせの口（要件 12 の 1）・同じ時刻の刻み直しの守りとの兼ね合い（要件 11 の 9・10）・占有の終わりの説明「刻みでは変わらない」の改め・完了した後の置き直しの扱い・先渡し（`preview`）で見せる合図の絶対の発火時刻の扱い（まだ取り出していない）。
5. **使い手の中の端数**: 1 字ごとの間隔の端数（文字の層の式と、seriko のその写し）を、整数の長さでどう持つか（積もらない形で）。
6. **口パク**: 起点が飛んで、複数の字がまとめて現れた時に、`talk` の引き金が何回鳴るかを、今の決まりで読んで確かめる（要件 12 の 7）。
7. **OS の関数の呼び方**: `QueryUnbiasedInterruptTimePrecise` を、着手の時点のワークスペースの呼び方（`windows` の機能を足すか、束縛か）に合わせる。
8. **外すテストの一覧と記録の置き場**（要件 9 の 4・5）と、変える前後の期待の記録の置き場（要件 9 の 6）。
9. **時計の統一の細部**（要件 17）: kanade が dola に依存せずに型と時計を使える置き場（2 と同じ決め）・ghost と kanade のミリ秒の型と seriko の時計の型の置き換え方・`OnSecondChange` の参照の単位への直し方・眠りをまたぐ締め切りの確かめ方・文字の層と seriko が、押された起点を読む形。
10. **設計の前の確かめ**: 同じ時に走らせない相手が走っていないこと・先に着地した spec が dola に足した口が無いかを、設計の前に main に合わせ直して数える。
