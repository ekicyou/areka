## Boundary Context

- **In scope**: ① 署名の根拠にする配布 zip を `tools/package-alpha.ps1` で組み直して使う／② 第三者の手順の検証項目表の確定／③ 開発者の機械での実機一周と受入記録／④ `dist/README.txt` の仕上げ（「■ .nar の入れ方」「■ 更新のしかた」・メニューの欄・既知の制限・日付・既定バルーンの出典文）／⑤ 開発者が `halt` の台詞を足した `emo2` を配布したときの `vendors/sample_ghost/emo2.nar` の差し替え／⑥ 完成判定の文書と開発者の署名・持ち越しと引受先の表。
- **Out of scope**: インストーラ（msi・自己解凍）・アプリ本体の自動更新（`\![update,platform]`）・コード署名・配布サイトの用意・arm64 版の必須化・α での性能目標の引き直し／`emo2` の辞書の編集（リポジトリの外・開発者の手）／新しい機能の追加（例: 「ゴーストが無い」告知にフォルダを開くボタンやファイル選択を足すこと）／ゴーストの台本から起きる経路（`\![change,…]`・名前の特別な解決 `random`／`sequential`／`lastinstalled`・`\+`／`\_+`）を第三者の手順の検証項目にすること（第三者が直接行う操作ではなく、各完了 spec の決定論テストと実機確認が受け持つ）。
- **変更 0 と明記するもの**: `crates/` のソースの変更は 0（一周で見つかった欠陥を本仕様の中で直すと開発者が決めたときだけ例外＝要件 3.8）。配布スクリプトの変更は 0（zip の中身の許可表を含む・議題 3＝入れない／要件 1.2）。`THIRD-PARTY-NOTICES.md` を手で直す箇所は 0。
- **Adjacent expectations**: 前提の spec はすべて着地済み（`baseware-root-layout`・`alpha-package`・`ghost-shell-balloon-switch`・`session-mark-residue`・`ghost-change-name-resolution`・`frame-phases-after-exit`・`ghost-install`・`file-drop`・`network-update`・`shell-balloon-switch` ほか）。バグ `balloon-reappear-short-talk`（隠れたバルーンが 1 文字の台詞で現れない）は本仕様の前提ではないが、「バグ → α」の順で先に着地する見込みで、署名の時点で未着地なら既知の制限に載せる（要件 5.4）。`emo2` の辞書に `halt` の台詞を足すのは開発者の手（リポジトリの外）で、本仕様は届いた版を受け取るだけ。下流は α 後の組み直し（M3「伺かの冠」の起点＝本仕様の宣言）。

## Requirements

### Requirement 1: 署名の根拠にする配布 zip

**Objective:** As a α の完成を宣言する開発者, I want 一周に使う zip が、署名の根拠のコミットから組まれたものだと後から辿れること, so that 「どの実行体で確かめたか」が曖昧なまま宣言しない（M1 の教訓）

#### Acceptance Criteria

1. When 実機一周を始める, the 開発者 shall `tools/package-alpha.ps1` を、本仕様で変えたファイル（説明書・検体など）をすべてコミットした状態のコミットで全段が成功するまで走らせ、`-Check` の判定も合格させた zip を使う。その zip は、並走するバグ `balloon-reappear-short-talk` の PR が main に入り、本ブランチへ main を取り込んだ後のコミットで組む（開発者の段取り＝本仕様はタスク分解まで進めたところでその取り込みを待つ）。
2. The 受入記録 shall 一周に使った zip の名前と、zip の中の `BUILD-INFO.txt` の `commit=`（スクリプトが書く 7 桁の短い識別子）を写し、その横に `git rev-parse` で引き直した完全なコミットの識別子を添え、`dirty=` の値が 0 であることを示す（`tools/package-alpha.ps1` は変えない）。
3. If 一周の後に、zip の中身になるファイル（説明書・検体・本体のソース）を変えるコミットを入れた, then the 開発者 shall zip を組み直し、変えた中身に関わる検証項目を組み直した zip で採り直し、受入記録に採り直した項目と新しい `commit=` を書く（変えていない項目の結果は持ち越してよいが、その理由を書く）。
4. The 配布 zip shall `ghost/` に既定ゴースト `emo2` だけを入れ、2 体目のゴーストを最初から入れない（議題 3＝入れない・開発者が 2026-10-01 に確定）。
5. The 配布 zip shall x64 版の 1 種とし、arm64 版を作ることを署名の条件にしない。

### Requirement 2: 第三者の手順の検証項目表

**Objective:** As a α の完成を宣言する開発者, I want 第三者が zip を受け取ってから終えるまでの体験を、1 項目ずつ合否が決まる表にしたいこと, so that 各 spec の受入の寄せ集めではなく、体験の一周で α を確かめられる

#### Acceptance Criteria

1. The 検証項目表 shall 次の 12 項目を持ち、各項目に「操作」「期待」「証跡の取り方（記録の行の検索か、開発者の目視か、両方か）」を書く。
   1. **空の根の告知**: zip を展開して `ghost\` の中を空にした根で `areka.exe` を起動する → 「ゴーストが見つかりません。」と、置く場所の絶対パスと置くものの形を示す告知が出て、OK で終わる。
   2. **告知のとおりに置く**: 項目 1 の告知が示す場所に、展開したゴーストのフォルダ（`konnoyayame`＝手で置き、zip には入れない）を置いて起動し直す → そのゴーストが立って挨拶する。あわせて、目の周りに四角い地色が出ないこと・挨拶の字形が化けないこと・絵の中で左上の画素と同じ色の画素の場所のクリックが背後の窓へ抜けることを目視で見る。
   3. **初回の起動**: zip をそのまま展開した根で起動する → えも？？（`emo2`）が同梱のバルーン `emo2-kakukaku` で立って挨拶する。あわせて、絵の透明な場所のクリックが背後の窓へ抜けることを目視で見る。
   4. **2 体目・3 体目を入れる**: ⒜ メニューの「インストール…」で里々の標準テンプレート `R_POST_and_KOMAINU.nar` を選ぶ ⒝ ゴーストの窓へ `claudia.nar` をエクスプローラから落とす → どちらもインストールの台詞が流れ、表示中のゴーストのまま切り替わらない。利用条件の画面が出たときは「はい」で進める。
   5. **メニューでゴーストを替えて戻る**: メニューの「ゴースト」の一覧に 3 体が並ぶ → `R_POST_and_KOMAINU` を選ぶ → 送り出しの台詞の後に切り替わり、挨拶し、絵が出る（ファイル名の慣習で建つ面）。挨拶の字形が化けないことと、絵の中で左上の画素と同じ色の画素の場所のクリックが背後の窓へ抜けることを目視で見る → `claudia` を経て えも？？ へ戻る。
   6. **シェルの切り替え**: 2 つ目のシェルを持つゴースト（一周の根の中で手で作る・zip とリポジトリの検体には入れない）で、メニューの「シェル」から 2 つ目を選び、元へ戻す → どちらも絵が替わり、ゴーストは降りない。
   7. **バルーンの切り替え**: えも？？ でメニューの「バルーン」から `StayseeBalloon` を選び、`emo2-kakukaku` へ戻す → どちらも次の台詞から新しいバルーンで出る。
   8. **ネットワーク更新**: えも？？ でメニューの「ネットワーク更新」を選ぶ（更新先は `emo2` の配布サイト。zip の `emo2` と配布サイトの間に差分が無いときは、一周の根の中の `emo2` のファイルを 1 つ手で変えて差分を 1 件以上作ってよい）→ 進捗の台詞の後にいったん引っ込んで同じゴーストが戻り、最初に `OnUpdateComplete`（更新成功）、続けて `OnUpdateResult` が届く（`OnGhostChanged`・`OnBoot` は送らない）。続けてもう 1 度選ぶ → 差分が無く引っ込まずに `OnUpdateComplete`（更新無し）→ `OnUpdateResult` で終わる。
   9. **終了**: メニューの「終了」を選ぶ → 別れの台詞の後にプロセスが終わり、終了コードが 0 で、記録に ERROR が 0 件（要件 3.6 の除外を除く）で、起動中の印が消える。
