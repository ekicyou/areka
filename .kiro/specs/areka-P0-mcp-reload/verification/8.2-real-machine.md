## 手順（共通）

- ビルド: `cargo build -p areka --bin areka -j 4`・`cargo build -p shiori-host32-helper --target i686-pc-windows-msvc -j 4`（どちらも最新・HEAD `75d2101e`）。
- 検体: `cargo run -q -p sample-ghost-kit --bin nar-sample-path -- emo2` が開いた `target\nar-samples\manual\emo2` を `target\mcp-reload-signoff\root` へ写した（`ghost\emo2`・`balloon\emo2-kakukaku`）。`areka.exe` と i686 の `shiori-host32-helper.exe` も同じ根へ写した。時報（`dic\hour.pasta`）は外した。
- 根・記録・写しはすべてワークツリーの `target\mcp-reload-signoff\` の下。ゴーストは argv で絶対パスを渡した。
- 起こし方: PowerShell から `Start-Process`（標準出力を `target\mcp-reload-signoff\logs\<名>.log` へ）。環境変数は `AREKA_*`・`WINTF_*` を消してから `RUST_LOG=info,kanade=trace,areka::emo2_boot=trace,areka::ghost_session=debug,areka::ghost_session_runtime=debug,areka::roots=debug,shiori_host32_host=debug,areka_ghost=debug`・`AREKA_APP_SMOKE_EXIT_MS`（有界の自動終了）・`AREKA_NO_ALERT=1`・`AREKA_MCP_PORT`・`LOCALAPPDATA`／`TMP` を `target\mcp-reload-signoff\` の下へ。
- MCP: `POST http://127.0.0.1:<port>/api/mcp/v1`（`Accept: application/json, text/event-stream`）へ JSON-RPC の `tools/call`。
- `hwnd`: PowerShell から `EnumWindows`＋`GetWindowThreadProcessId` で、起こした areka の番号の窓を列挙した（画面の操作・SSP の MCP は使っていない）。
- 辞書が効いたかの判定: kanade の trace の `shiori_request method=GET id=OnTranslate references=[…]` に、再生する台本がそのまま載る。書き換えた `＊OnTalk`（ランダムトーク・15〜30 秒ごと）の台詞が出るかで見た。

- 1 回目の読み直しで、ゴーストは書ける根の写しへ移った（`info!` の `ghost_switch_copy_wait`・`user_data_copied` で分かる）。写しは読み直しの時点で取られるので、1 回目は同梱の根の書き換え（ＲＥＬＯＡＤ３）が効いた。

- 写しの行き先は `user_data_copied` に出るが、2 回目の読み直しの記録には「写しを読んでいる」ことを直に言う行は無い（シェルの `shell_dir=…\userroot\…` で間接に分かるだけ）。

## 気付いたこと（製品のコードは直していない）

1. **`ghost` の読み直しの後、キャラクターの姿が出ない。** 読み直しは窓を作り直し、起動の挨拶を送らないので、キャラクターの窓（`TargetId(0)`・`TargetId(2)`）に面を出す台本が来ない。run1 では 23:01:10 から 23:03:14（⑸ の台詞の `\s[0]`）まで `TargetId(0)` の `ShowSurface` が 0 件、trace は `chain_finalize: …（窓が無い・まだ一度も表示されていない） scope=Some(0)` を出し続け、`dump_surface {"scope":0}` は `NG:No surface has been shown in this scope yet`。areka はふつうの起動でも最初の面を挨拶の台本の `\s` から出している（run1 の起動でも最初の `TargetId(0)` の面は挨拶の `\s[1000]`）。要件 3.5 は窓の位置だけを言い、面には触れていない。読み直しの後に既定の面を出すかどうかは判断が要る。
2. **同梱の根から起こしたゴーストは、読み直しのたびに書ける根の写しを読む**（Risk 2）。同梱の根で辞書を直して読み直す使い方では、2 回目から書き換えが効かない。
3. **`get_status` は読み直しの途中でも答える。** MCP の答えの「Wait until get_status answers again」は SSP の文の写しで、areka では読み直しの終わりの合図にならない（run2 では答えた 6 秒後にまとめの `reload_failed` が出た）。終わりは `get_log` の `reload_done`／`reload_failed` で見る必要がある（要件 8 の「その場で答える」とは矛盾しない）。
4. 測り方の注意: pasta はデバッグ用の待受 127.0.0.1:9276 を取るので、pasta のゴーストを入れた areka は同時に 2 つ動かせない（run3 が LOAD で失敗した理由・`pasta.log` の `debug transport bind failed … os error 10048`）。
