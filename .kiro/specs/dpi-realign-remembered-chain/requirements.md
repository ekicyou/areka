# Requirements Document

## Project Description (Input)

- **だれが困っているか**: areka の利用者。Windows の拡大率を変える（例: 200% → 100%・拡大率の違うモニターへ移る）と、キャラクターの絵の幅が変わり、隣り合っていた本体と相方のあいだに隙間が開く（実測 359px）。隙間は開いたまま戻らない。ぱすた（「窓際のぱすたさん」）のように、拡大率の違う画面をまたいでドラッグすると、落とした点より左上にキャラクターが置かれる（`pasta-in-windows-verification` の件 9）。
- **今の状況**: 拡大率が変わったあとの詰め直しは、記憶から位置を戻したキャラクターを必ず外す。完了 spec `areka-P0-char-position-save-on-exit` が入ってから、2 回目の起動では全員が「位置を覚えているキャラクター」になり、誰も詰め直されない（直っていた動きが後退した）。両方をドラッグ済みの利用者は、前から詰め直されない。ドラッグの窓の位置は「始めの窓の左上＋カーソルの移動量」で決まり、拡大率が変わって窓が縮んでも、掴んだ点の窓の中の位置を縮めない。
- **何を変えるか**: 拡大率が変わる直前に隣り合っていたキャラクターは、位置を覚えていても、変わったあとも隣り合ったままにする。利用者が離して置いたキャラクター・重ねて置いたキャラクターは寄せない。拡大率の違う画面をまたぐドラッグでは、落とした点に掴んだ点が来るようにする。決定論のテストと実機（拡大率の違う 2 つの画面）で確かめる。

出どころは `brief.md`（2026-10-05 起票・`/kiro-discovery`。棚卸㉓〜㉙の再測定と、2026-10-23 の `pasta-in-windows-verification` からの申し送りを含む）。段は**バグ**（直っていた動きの後退。開発者の裁定「受け入れず、別の spec として起票」）。重ねた組と件 9 の分は開発者の指示（v0.1.0 のゴール）。

## Introduction

areka は、拡大率が変わるとキャラクターの窓を新しい拡大率の大きさで描き直し、各窓の足元の中央（下端の中央）を保ったまま置き直す。絵の幅が変わるので、隣り合っていた 2 体のあいだには幅の変わった分の半分の和だけ隙間が開く（または重なる）。これを閉じる「詰め直し」は完了 spec `areka-P0-dpi-transition-atomicity` で入ったが、対象を「既定の位置から誰も動かしていないキャラクター」に限ったので、記憶から位置を戻したキャラクターは対象から外れる。完了 spec `areka-P0-char-position-save-on-exit` で全員の位置が記憶に入るようになり、2 回目の起動から誰も詰め直されなくなった。

この spec は、詰め直しの対象を「位置がどこから来たか」でなく「拡大率が変わる直前に隣り合っていたか」で決め直す。あわせて、拡大率の違う画面をまたぐドラッグで、掴んだ点が落とした点に来るようにする。詰め直した位置を記憶に書くかと、起動し直したときに隙間が戻る件の扱いは、要件 6 に案 A を仮に置いた（**要件の話し合いで確定する**）。

### 決め方の選び（brief の候補から）

brief は決め方を要件の段で決めるとし、候補を 3 つ挙げた。

- **採る: 隣り合いを見て詰め直す**。拡大率が変わる直前に隣と接していた組を、記憶の有無にかかわらず詰め直す。理由:
  - brief の「利用者が離して置いたキャラクターどうしは、勝手に寄せない」と両立する（離れていた組は対象に入らない）。
  - 拡大率が変わるときに各窓の足元の中央を保つ今の決め（完了 spec `areka-P0-dpi-transition-atomicity`）を変えずに済み、DPI 追従の基本設計（大きさは拡大率に従う・2026-07-18 開発者）とも当たらない。
- **採らない: 覚えている位置そのものを拡大率の比で運ぶ**。何を中心に運ぶかによらず、離して置いたキャラクターどうしの間も縮む（または広がる）ので「勝手に寄せない」に反する。別の画面に置いたキャラクターまで動き、拡大率が変わるときに足元の中央を保つ今の決めも改めることになる。
- **再検討しない: 受け入れて記録だけ残す**（開発者が 2026-10-05 に採らなかった案）。

### 重ねた組・台本で置いた窓・ドラッグの最中の窓（brief 棚卸㉗・申し送りの節から）

- ぱすたは窓の枠（相方）とぱすた（本体）を同じ左上に重ね、一緒に動く組（`seriko.sticky-window`）にしている。「隣と接していた」を重なりまで広げて読むと、窓の枠をぱすたの横へ並べてしまう。重なっていた組は詰め直しで動かさず、一緒に動く組に入っている窓も詰め直しで動かさない（brief「組の窓は詰め直しから外す、で済む見込み」）。組の見分けに何を使うか（台本で置いた窓の印か、組の帳簿か）は設計で決める。
- 台本（`\![move]` など）で置かれた窓は、起動の最後の並べ直しでは引き戻さない（完了 spec `areka-P0-window-link-directives`）。拡大率が変わったあとの詰め直しでは、どうやってそこへ来たかを問わず「変わる直前に隣り合っていたか」で決める（重なり・組・ドラッグの最中は除く）。これで、並べ終える前に台本が縦にだけ動かした相方（`char-position-save-on-exit` の要件 1.7 の是正で詰め直しから外れていた窓）も、隣り合っていれば詰め直される（brief「対象の決め方を見直すときに合わせて扱う」）。
- 拡大率が変わったあと、詰め直しが済む前に、ゴーストが台本で窓を置き直したときは、ゴーストの置いた位置を詰め直しで上書きしない（ぱすたはドラッグを落とした後と倍率の変わりの合図で位置を出し直す）。

### 画面をまたぐドラッグの掴んだ点（申し送りの件 9）

ドラッグで拡大率の違う画面へ移り窓が縮んでも（例: 幅 1108 → 831）、窓の中の掴んだ点（225,806）を縮めないので、ぱすたが落とした点より左上に置かれた。窓の大きさが拡大率に合わせて変わること（件 8）は崩れではない（2026-07-18 開発者の DPI 追従の決め）ので変えず、掴んだ点の窓の中の位置だけを、窓の大きさの変わりと同じ比で合わせる。参照の SSP は画面を移っても窓の大きさを変えない（`ssp-measurement.md` 2 節の段 5）ので、areka のこの動きは DPI 追従の基本設計からの帰結である。

### 作業領域への寄せ（`window-work-area-clamp` との分け方）

詰め直した位置が作業領域の外（隣の画面）へ出うることは、`window-work-area-clamp` の brief が「先に着地する側の要件で決める」としていた。この spec が先に着地する（ウェーブ C11）ので、ここで決める: **この spec は詰め直した位置を作業領域の中へ寄せない**。寄せ方は SSP で測って決める段を向こうが持つので、寄せる働きは `window-work-area-clamp` が作り、詰め直しの位置にも同じ寄せを当てることを向こうの範囲とする（この spec の着地のときに向こうの brief へ申し送る）。

## Boundary Context

- **In scope**:
  - 拡大率が変わったあとの詰め直しの対象の決め方（隣り合っていた組を、記憶の有無にかかわらず詰め直す・離れていた組／重なっていた組／一緒に動く組の窓／台本で置き直した窓／ドラッグの最中の窓は動かさない）。
  - 拡大率の違う画面をまたぐドラッグで、掴んだ点を窓の大きさの変わりに合わせること（件 9）。
  - ゴーストの読み直し・切り替えで窓を作り直したあとも同じ決め方で詰め直すこと。
  - 詰め直した位置を記憶に書かないことと、起動・読み直し・切り替えで記憶から戻すときに、覚えたときに隣り合っていた組を今の絵の幅で隣り合わせること（要件 6・案 A を仮置き・要件の話し合いで確定する）。
  - 詰め直しの判断の記録（ログ）・決め方を改めた記録（`doc/COMPAT_ARCHITECTURE.md` §8）・決定論のテスト・実機の確認。
- **Out of scope**:
  - 起動の最後の並べ直しのうち、記憶に位置が無いキャラクターを本体の隣へ並べる働き（完了 spec `areka-P0-scope-chain-gap`）。記憶から戻したキャラクターの隣り合わせ（要件 6.3）は、案 A を採るかぎり In。
  - 位置を記憶に書く時機そのもの（完了 spec `areka-P0-char-position-save-on-exit` の持ち分）。案 A は時機を足さず、今ある時機に書く中身（覚えたときの幅または隣り合っていた印）を足す。
  - 記憶から戻した位置を作業領域の中へ寄せる規則（完了 spec `areka-P0-position-persist` の要件 5・`window-work-area-clamp`）。変えない。
  - 拡大率の切り替えの途中の見え方（`dpi-transition-two-tick-bounce`）。
  - 倍率が変わったことをゴーストへ知らせる合図（`OnShellScaling`）を送るかどうか（`shell-scale-linkage` に決まった・2026-10-23）。この spec は、ぱすたの出し直しと詰め直しの順を確かめるだけ。
  - 詰め直した位置を作業領域の中へ寄せること（`window-work-area-clamp`）。
  - 表情の差し替えで絵の大きさが変わったときにキャラクターを横へ動かさない約束（`areka-P0-scope-chain-gap` 7.4・`areka-P0-dpi-transition-atomicity` 要件 6.6）。変えない。
  - 3 体目以降のキャラクター窓を出すこと（`extra-character-windows`）。この spec の決め方はキャラクターの数を 2 体に決め打ちしない。
- **Adjacent expectations**:
  - 拡大率が変わるとき、各キャラクター窓は足元の中央を保ったまま新しい大きさで置き直される（完了 spec `areka-P0-dpi-transition-atomicity`）。この spec はその後に横の位置だけを詰める。
  - バルーンは今までどおりキャラクター窓に付いて動く（詰め直しで窓が動けばバルーンも同じだけ動く）。
  - 一緒に動く組（`seriko.sticky-window`）の窓は、ドラッグのとき今までどおり同じだけ動く（完了 spec `areka-P0-window-link-directives`）。
  - `multi-ghost-runtime`（後の版）は、隣り合いの判定をゴーストごとへ運ぶ。
- **同じウェーブ（C11）で並んで進む仕事との約束**（`roadmap.md`「ウェーブ編成」C11 の ⑥ の行）:
  - この spec が触る所: `crates/areka/src/placement/{chain_realign,chain_finalize,spawn,persist}.rs`・`emo2_boot/frame.rs`・`emo2_boot/frame/{dpi,drain_resnap}.rs`・wintf の `ecs/window_proc/mouse_move.rs`・`ecs/drag/dispatch.rs`（件 9）と、それぞれの兄弟のテスト（上限の近い `placement/persist_restore_tests.rs`・`emo2_boot/frame_test_support.rs` へは足さず、新しいファイルへ）・`doc/COMPAT_ARCHITECTURE.md` §8（表の末尾への追記）。
  - 件 9 は、組に入った窓（ぱすた）のドラッグにも効かせる。ぱすたのドラッグ中と落とした時の位置は wintf の `mouse_move.rs` でなく `placement/follow/drag_follow.rs` の式で決まる（`research.md` 1.4 節）が、`drag_follow.rs` には触らない約束のまま直す（直し方は設計で決める・`research.md` 3.4 節の D1＝ドラッグの始めの値を置き直す道なら `emo2_boot/frame/dpi.rs` か `drag/dispatch.rs` と `mouse_move.rs` の内に収まる見込み）。

## Requirements

### Requirement 1: 拡大率が変わる直前に隣り合っていたキャラクターを、隣り合わせたままにする

**Objective:** As an areka の利用者, I want 拡大率を変えても、隣り合っていた本体と相方が隣り合ったまま見えること, so that 拡大率を変えるたびにキャラクターを並べ直さずに済む

#### Acceptance Criteria

1. When 拡大率が変わり、全部のキャラクター窓が新しい拡大率の大きさで表示し終えたとき, the areka shall 変わる直前に隣り合っていたキャラクターの組を、位置を記憶から戻したかどうか・利用者がドラッグしたかどうかにかかわらず、新しい大きさで隙間なく隣り合わせる。
2. The areka shall 要件 1.1 の「隣り合っていた」を、2 つのキャラクター窓が横に並び（縦の範囲が重なり）、向かい合う左右の端の隙間または重なりが許す幅（数ピクセル。値は設計で決めて、処理の説明に残す）以内であることとする（拡大率の置き直しの丸めで出る 1 ピクセルほどの重なりは隣り合いに含める）。
3. When 隣り合っていた組を詰め直すとき, the areka shall 本体に近い側（スコープの番号が小さい側）の窓を動かさず、もう一方の窓を横にだけ動かし、隣り合っていた左右の側を保つ。
4. The areka shall 詰め直しでキャラクター窓の縦の位置を変えない（縦は拡大率が変わったときの置き直しが保っている足元の位置のまま）。
5. Where キャラクターが 3 体以上いるとき, the areka shall 本体から順に、隣り合っていた組ごとに要件 1.1〜1.4 を当て、前の窓を詰め直した後の位置を次の組の基準にする（キャラクターの数を 2 体に決め打ちしない）。
6. The areka shall 詰め直しを、拡大率の 1 回の変化につき 1 回だけ、全部のキャラクター窓が新しい大きさに揃った後で行い、切り替えの途中の大きさでは行わない（完了 spec `areka-P0-dpi-transition-atomicity` の要件 6.2・6.6 の「一度だけ」を保つ）。
7. When 拡大率が続けて変わったとき（例: 200% → 100% → 200%）, the areka shall 変化のたびに要件 1.1 を当て、どの拡大率でも隣り合っていた組を隣り合わせたままにする（大きくなる向きの変化で一度重なって見えても、詰め直しで隣り合わせに戻す）。
8. When 位置を記憶から戻したキャラクターだけのゴースト（2 回目以降の起動）で拡大率が変わったとき, the areka shall 要件 1.1 のとおり隣り合っていた組を詰め直す（`areka-P0-char-position-save-on-exit` の着地で後退した動きを戻す）。

### Requirement 2: 離して置いた・重ねて置いたキャラクターを寄せない

**Objective:** As an areka の利用者, I want 自分が離して置いたキャラクターや、ゴーストが重ねて置いた窓が、拡大率の変化で勝手に動かないこと, so that 自分やゴーストが決めた置き方が崩れない

#### Acceptance Criteria

1. If 拡大率が変わる直前に 2 つのキャラクター窓が離れていたとき（要件 1.2 の許す幅より広い隙間）, the areka shall どちらの窓も詰め直しで動かさない（拡大率が変わったときの足元の中央を保つ置き直しのまま）。
2. If 拡大率が変わる直前に 2 つのキャラクター窓が要件 1.2 の許す幅を超えて重なっていたとき, the areka shall どちらの窓も詰め直しで動かさず、横に並べない。
3. Where キャラクター窓が一緒に動く組（`seriko.sticky-window` などで結んだ窓）に入っているとき, the areka shall その窓を詰め直しで動かさない。
4. While 利用者がキャラクター窓をドラッグしている間, the areka shall その窓を詰め直しで動かさず、その窓へほかのキャラクター窓を寄せることもしない。
5. When 表情の差し替えなど、拡大率が変わらずに絵の大きさだけが変わったとき, the areka shall 詰め直しを行わない（キャラクターを横へ動かさない約束＝`areka-P0-scope-chain-gap` 7.4・`areka-P0-dpi-transition-atomicity` 要件 6.6 を保つ）。

### Requirement 3: ゴーストが台本で置いた位置を上書きしない

**Objective:** As a ゴーストの作者, I want 拡大率が変わったあとにゴーストが台本で置き直した窓の位置が、詰め直しで上書きされないこと, so that ゴーストが倍率の変化やドラッグの終わりに合わせて出し直す並びが崩れない

#### Acceptance Criteria

1. When 拡大率が変わったあと、詰め直しが済む前に、ゴーストが台本の移動の指示（`\![move]` など）でキャラクター窓を動かしたとき, the areka shall その窓を、その変化の詰め直しで動かさない。
2. When 詰め直しが済んだあとに、ゴーストが台本の移動の指示でキャラクター窓を動かしたとき, the areka shall ゴーストの指示した位置に窓を置き、同じ変化の詰め直しをもう一度行わない。
3. Where 拡大率が変わる前に台本の移動の指示で置かれたキャラクター窓が、変わる直前に隣の窓と隣り合っていて、重なりでも一緒に動く組でもないとき, the areka shall その窓を要件 1.1 の対象にする（どうやってそこへ来たかでなく、変わる直前に隣り合っていたかで決める）。
4. When ぱすた（「窓際のぱすたさん」）を拡大率の違う画面へドラッグして落としたとき, the areka shall ぱすたと窓の枠とバルーンの並びを、ぱすたがドラッグの終わりに出し直した並びのまま保つ（詰め直しで窓の枠をぱすたの横へ並べない）。

### Requirement 4: 拡大率の違う画面をまたぐドラッグで、掴んだ点を落とした点に置く

**Objective:** As an areka の利用者, I want 拡大率の違う画面へキャラクターをドラッグして落としたとき、掴んだ所がカーソルの下に残ること, so that 落とした所にキャラクターが来る

#### Acceptance Criteria

1. When 利用者が窓をドラッグして拡大率の違う画面へ移り、窓の大きさが拡大率に合わせて変わったとき, the areka shall 窓の中の掴んだ点の位置を、窓の大きさの変わりと同じ比で縮め（広げ）、掴んだ点がカーソルの下に来るように窓を置く（丸めによる差は縦横それぞれ 1 ピクセル以内）。
2. When 拡大率の違う画面へ移った窓を落としたとき, the areka shall 落とした点に掴んだ点が来る位置へ窓を置く（丸めによる差は縦横それぞれ 1 ピクセル以内）。
3. While ドラッグの間に窓の大きさが変わらないとき（拡大率が同じ画面のあいだのドラッグ）, the areka shall 窓の位置の決め方を今のまま変えない。
4. The areka shall 拡大率の違う画面へ移ったときに窓の大きさが拡大率に合わせて変わることを変えない（DPI 追従の基本設計・2026-07-18 開発者）。
5. When 一緒に動く組の窓をドラッグして拡大率の違う画面へ移ったとき, the areka shall 組の相手の窓を、今までどおりドラッグしている窓と同じだけ動かす（完了 spec `areka-P0-window-link-directives`）。
6. When 要件 4.2 で置いたキャラクター窓のドラッグが確定したとき, the areka shall その置いた位置を、今までどおりドラッグの確定の位置として記憶に書く（書く時機は変えない）。

### Requirement 5: ゴーストの読み直し・切り替えのあとも同じに詰め直す

**Objective:** As an areka の利用者, I want ゴーストを読み直したり切り替えたりしたあとでも、拡大率を変えたときの詰め直しが同じに働くこと, so that 読み直しや切り替えをしたかどうかで並びが変わらない

#### Acceptance Criteria

1. When ゴーストの読み直し（MCP の `reload` など）や切り替えで窓を作り直し、位置を記憶から戻したあとに拡大率が変わったとき, the areka shall 要件 1〜3 と同じ決め方で詰め直す。
2. The areka shall 要件 1〜3 の決め方を、起動・読み直し・切り替えのどれで窓を作ったかで変えない。

### Requirement 6: 詰め直した位置を記憶に書かず、起動し直しても隣り合わせたままにする（要件の話し合いで確定する（案 A を仮置き））

> **この要件は要件の話し合いで確定する。いまは案 A を仮に置いている。**
>
> **前提（コードの読み・main `aa8da8a7`）**: 記憶に残るのはキャラクター窓ごとの「足元の中央の x と上端の y」（物理ピクセル）だけで、覚えたときの絵の幅も拡大率も残らない（`placement/persist.rs` の `char_pos_to_origin_x`・`crates/areka-sylphya/src/persist/mod.rs` の `PersistKey::WindowPos`）。位置の記憶の決まり 3 つはどれも「画面の変化では書かない」を指す＝`areka-P0-position-persist` 要件 1.9（保存値＝利用者の意図・表示位置＝意図を今の画面へ写したもの）・同 5.4（寄せ直した位置を書き戻さない）・`areka-P0-char-position-save-on-exit` 要件 3.2（絵の大きさが変わって置き直した時点では書かない）。ほかに 2026-08-14 の開発者の裁定「拡大率の変更をまたぐ保存位置の追従はしない」（2026-08-27 に改めて継承・`doc/COMPAT_ARCHITECTURE.md` §8「バルーンオフセットの保存往復で拡大率をどう扱うか」の行）がある。
>
> **起きること（例）**: 200% で本体（幅 764）と相方（幅 672）が隣り合って記憶にある。実行中に 100% へ変えると、要件 1 で隣り合わせに詰め直される。ここで「書かない」だけにすると、同じ 100% のまま起動し直したとき、記憶の足元の中央は 200% のときのままで絵の幅だけが 382 と 336 になり、359px の隙間がまた開く（起動の最後の並べ直しは記憶から戻したキャラクターを外す）。起動と起動のあいだに拡大率を変えたときも同じ（brief 棚卸㉓の「見つけた穴」）。`char-position-save-on-exit` の前は、一度もドラッグしていないキャラクターは起動のたびに既定の位置から本体の隣へ並べ直されたので、この隙間は出なかった＝開発者が「受け入れず」と裁定した後退と同じ種類に当たる。一方で 2026-08-14 の裁定とは逆向きになる。
>
> **案 A（仮置き・ずっと隣り合ったまま）**: 詰め直した位置は記憶に書かない（3 つの決まりどおり）。記憶に覚えたときの絵の幅（または隣り合っていた印。どちらにするかは設計で決める）を足し、起動・読み直し・切り替えで記憶から戻すとき、覚えたときに隣り合っていた組を今の絵の幅で隣り合わせて立たせる。2026-08-14 の裁定のうち「保存の形に拡大率の情報を持たせない」の部分を、キャラクター窓の位置について改める。C11 の約束をまたぐ（Boundary Context）。規模は 3〜5 タスク増の見込み。
>
> **案 B（同じ拡大率での起動し直しだけ直す）**: 詰め直した窓の位置を記憶に書く（`char-position-save-on-exit` 要件 3.2 をこの 1 時点だけ改め、§8 に記録）。同じ拡大率で起動し直せば隣り合う。起動と起動のあいだに拡大率を変えた場合は直らない（隙間か重なりが出る）。C11 の約束の内。この案なら要件 6.1 を「書く」に替え、6.2〜6.5 を外す。
>
> **案 C（実行中だけ直す）**: 詰め直した位置は記憶に書かず、起動のときの隙間はこの spec の範囲外とする（2026-08-14 の裁定のまま）。拡大率を変えたあとに起動し直すと隙間が戻ることを既知の残りとして記録し、追う spec を `/kiro-discovery` で起票するかを決める。この案なら要件 6.1 だけを残し、6.2〜6.5 を外して残りの記録の要件に替える。

**Objective:** As an areka の利用者, I want 拡大率を変えたあとに起動し直しても、隣り合っていた本体と相方が隣り合ったまま立つこと, so that 起動し直すたびに並べ直さずに済み、それでも自分が決めた位置の記憶は画面の変化で書き換わらない

#### Acceptance Criteria

1. When 拡大率が変わって詰め直したとき, the areka shall 詰め直した位置を記憶に書かず、記憶の位置を利用者が最後に決めた（または並べ終えた時点で覚えた）位置のまま保つ（`areka-P0-position-persist` 要件 1.9・5.4、`areka-P0-char-position-save-on-exit` 要件 3.2 を保つ）。
2. When キャラクター窓の位置を記憶に書くとき（今ある時機＝ドラッグの確定・起動の最後に並べ終えた時点・既定の位置への並べ直しの時点）, the areka shall 隣の窓と隣り合っていたかを次の起動で見分けられる情報（そのときの絵の幅、または隣り合っていた印）を、位置と一緒に記憶に書く（書く時機は足さない）。
3. When ゴーストの起動・読み直し・切り替えで位置を記憶から戻し、覚えたときに隣り合っていた組が今の絵の幅では隣り合わない（隙間か重なりがある）とき, the areka shall その組を、要件 1.2〜1.5 と同じ決め方（本体に近い側を動かさず、もう一方を横にだけ動かし、左右の側を保つ）で今の幅で隣り合わせて立たせる。
4. If 記憶から戻した組が、覚えたときに離れていた・重なっていた・一緒に動く組だったとき, the areka shall 起動のときにその組を詰めず、記憶の位置のまま立たせる（覚えたときと今の幅が同じなら、どの組も動かさない＝`areka-P0-char-position-save-on-exit` 要件 2.1・2.3 を保つ）。
5. If 記憶に位置はあるが要件 6.2 の情報が無いキャラクター（この spec より前に覚えた位置）がいるとき, the areka shall 起動のときにそのキャラクターを詰めず記憶の位置のまま立たせ、起動の最後に並べ終えた時点で、位置を書き換えずに要件 6.2 の情報だけを書き足し、書き足したことを記録（ログ）に残す。
6. The areka shall 要件 6.3 で隣り合わせた位置を記憶に書かず、記憶から戻した位置を作業領域の中へ寄せる今の規則（`areka-P0-position-persist` 要件 5）を変えない。

### Requirement 7: 判断の記録と、決め方を改めた記録

**Objective:** As a 開発者, I want 詰め直しで何をどう判断したかがログに残り、完了 spec の決め方を改めたことが開発の記録に残っていること, so that 隙間や重なりの報告を受けたときに、詰め直しが走らなかったのか、走って動かさないと判断したのかをログから見分けられる

#### Acceptance Criteria

1. When 詰め直しを行ったとき（拡大率が変わったとき・要件 6.3 の起動のとき）, the areka shall 組ごとに、判断（隣り合っていた・離れていた・重なっていた・一緒に動く組・台本で置き直した・ドラッグの最中）と、動かした窓・動かした量・変わる直前の隙間を、あとから記録（ログ）で確かめられるように残す。
2. If 詰め直しに要る情報（変わる直前の窓の位置や大きさ）を取り出せないキャラクター窓があるとき, the areka shall その窓を動かさず、取り出せなかったことと理由を記録（ログ）に残し、ほかの組の詰め直しを続ける。
3. The areka shall 完了 spec `areka-P0-dpi-transition-atomicity` の要件 6.2（詰め直しの対象から、保存位置を戻したスコープと、台本やドラッグで動かしたスコープを外す）を、この spec の要件 1〜3 で改めたことと、その理由を、開発の記録（`doc/COMPAT_ARCHITECTURE.md` §8 の、完了 spec の要件を改めた記録の表）に残す。要件の話し合いで確定した要件 6 の案が、2026-08-14 の裁定（拡大率の変更をまたぐ保存位置の追従はしない）や `areka-P0-char-position-save-on-exit` 要件 3.2 を改めるときは、それも同じ表に残す。
4. The areka shall 詰め直しの処理の説明を、改めた決め方に合わせる（今の説明の「誰も触っていないスコープは対象に残る」は 2 回目の起動から成り立たない）。

### Requirement 8: 受け入れの確認（決定論のテストと実機）

**Objective:** As a 受け入れを判定する人, I want この直しが決定論のテストで固定され、実機でも確かめられること, so that 同じ隙間が後から戻ってきたら気付ける

#### Acceptance Criteria

1. The areka shall 「全員の位置が記憶から戻った状態で拡大率を 200% → 100% に変える → 隣り合っていた本体と相方の隙間が許す幅以内に閉じる」と、逆向き（100% → 200%）・往復（200% → 100% → 200%）を、決定論のテストで確かめられるようにする（実測の 359px の隙間の形＝幅 764 → 382 と 672 → 336 を含む）。
2. The areka shall 要件 2.1〜2.4（離れていた組・重なっていた組・一緒に動く組の窓・ドラッグの最中の窓は動かさない）と要件 3.1〜3.3（台本で置き直した窓を上書きしない・変わる前に台本で置かれて隣り合っていた窓は詰め直す）を、決定論のテストで確かめられるようにする。
3. The areka shall 「拡大率の 1 回の変化につき詰め直しは 1 回だけ」「表情の差し替えでは詰め直さない」（要件 1.6・2.5）を、決定論のテストで確かめ続けられるようにする（今あるテストを保つ）。
4. The areka shall キャラクターが 3 体のときの詰め直し（要件 1.5）を、決定論のテストで確かめられるようにする。
5. The areka shall 件 9 の実測の形＝「幅 1108・高さ 1368 の窓を、窓の中の (225,806) で掴み、拡大率 200% の画面から 150% の画面へ移して窓が 0.75 倍に縮み、(−1500,1000) で落とす → 窓の左上は掴んだ点を縮めた位置から決まり（およそ (−1669,395)）、落とした点と掴んだ点の差が縦横それぞれ 1 ピクセル以内」を、決定論のテストで確かめられるようにする（要件 4.1・4.2）。拡大率が同じ画面のあいだのドラッグが変わらないこと（要件 4.3）も確かめる。

7. The 受け入れの判定 shall 実機で次を開発者の机（拡大率の違う 2 つの画面・主の画面は 200%）で確かめることを必達とする: ⑴ 2 回目以降の起動の emo2 で、拡大率を切り替えても（200% → 100% → 200%）本体と相方のあいだに隙間が開かない ⑵ ぱすたを 200% の画面から 150% の画面へドラッグして落とすと、落とした点に掴んだ点が来て、ぱすたと窓の枠とバルーンの並びが保たれる ⑶ ぱすたの出し直し（ドラッグの終わり）の後に、詰め直しが並びを崩さない ⑷ emo2 で拡大率を 200% から 100% へ変えて閉じ、100% のまま起動し直しても、本体と相方のあいだに隙間が開かない（要件 6 の確定した案に合わせて形を替える）。実機の確かめは排他テストの机を持って回す。
