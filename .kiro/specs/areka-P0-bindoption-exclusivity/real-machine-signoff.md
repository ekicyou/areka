## 4. J3 不合格の根因（2026-08-11 デバッグ調査・静的構造証跡＋ログ実測）

**bind 集合から外れた bind 種アニメの「最終コマ残留」を掃除する経路が存在しない。**

| # | 機構 | 所在 |
|---|---|---|
| 1 | `FinishedResidual`（`-1` 終端なしの末尾到達）は **playback だけを除去しコマを残す** | `crates/areka-seriko/src/looper.rs:304-315` |
| 2 | playback を持たない slot は**丸ごと無評価でスキップ**。毎 tick `current_pattern` の clone から再開するため残留コマは誰も触らない | `looper.rs:244-247`・`:257` |
| 3 | bind ゲートは**発火を止めるだけ**。既に置かれたコマも再生中アニメの進行も止めない | `looper.rs:215`・`:264-346`（進行相に bind 判定なし） |
| 4 | `commit_bind` は bind 変化時に `current_pattern` を**そのまま複製して Show を再発行**。外れた ID を掃除する経路がない | `crates/areka-seriko/src/state.rs:377-405`・`:394` |
| 5 | 描画対象 ID 集合が `{有効 bind の pattern0 を持つ ID} ∪ {PatternState にコマを持つ ID}` で、**後者に bind 所属の条件が付いていない** | `crates/areka-emo-compose/src/plan.rs:302-309`・`:331-350` |

### emo2 データ側の裏取り

- `fixtures/emo2/shell/master/surfaces.txt:84-86` — animation1402（まばたき・ジトー）は
  `pattern1=1412, pattern2=1413` で終端し **`-1` を持たない＝必ず残留する**。
  **pattern0 も持たない**ため、1402 の視覚寄与は**すべて `PatternState` 経由**＝bind ゲートの外。
- `surfaces.txt:226-229` — surface1413 = `eyebase.png` ＋ `jito.png` で**不透明**。下層の目を完全に覆う。
- `descript.txt` に `animation-sort` 宣言なし → 既定 Descend → ID 昇順描画（`plan.rs:316`）
  → **14xx が 13xx の上**。

### ログ実測による裏取り

| 事象 | 実測 |
|---|---|
| 発火 / 末尾残留 / 停止 | 1400: 47 / 47 / **0**、1402: 19 / 19 / **0**（scope=0） |
| `-1` を持つアニメ | scope=1 の anim 0 のみが 33 回「停止」 |
| 最後の 1402 残留 | 09:10:15 |
| 以後の bind 遷移 | 09:10:16 まばたき→通常(1400)、09:10:44 まばたき→----(1403) |
| その後の 1402 掃除 | **無し**（実走末尾 09:11:26 まで） |

### 正典との関係

ukadoc は `bindgroup*.default` を「**1 で表示、0 で非表示**」、`bind` を「そのアニメーションを
サーフェスの着せ替えとして定義する」と規定する。**bindgroup が off のパーツのコマが描画され
続けるのは正典違反**である。

### 要件の因果モデルの誤り（本 spec 自身の瑕疵）

`requirements.md:21` は「積み上がったジトーまばたきの不透明最終コマが以後のすべての目・
まばたき表示を覆い、表情が固着する」と機構を**正しく**記述しながら、「排他置換すれば
積み上がりが消える」という**因果の一段を誤った**。1400/1401/1402 は `pattern0` を持たない
ため、bind 集合を正しても**既に置かれた残留コマには何の影響も及ばない**。

## 5. 併発した観測（切り分け済み・本件の根因ではない）

### 5.1 まばたきアニメーションのスロー再生・CPU 20% 超 → **別 spec の領分**

- seriko 側の進行は**壁時計どおり**（発火 09:05:04.596 → 末尾残留 09:05:04.779 ＝ **183ms**・
  定義値 172ms に一致）
- 遅いのは presenter 側で **1 コマあたり約 500ms**（09:05:05.032 / 05.559 / 06.074 ほか
  3 群で同型が再現: 493/484ms・527/515ms・543/417ms）
- `apply(ShowSurface)` **404 件すべて `cache_hit=false`**。`areka-emo-present` に
  throttle/debounce の実装は存在しない（grep 0 件）＝スロットリングではなく**実コスト**
- **所有者**: `recompose-budget`（W6.75）——`.kiro/steering/roadmap.md:71`・`:136` 追記(53) に
  2026-07-31 起票済み（「常駐アイドルの CPU 消費＝毎フレーム全再合成のアロケーション予算
  是正」・アイドル 1 コア 13〜22%）。開発者観測の 20% 超はこの帯の内側
- ただし**症状は悪化させている**——閉じ目コマが約 500ms 表示され続けるため、体感上は固着と混ざる

### 5.2 除外できた仮説

| 仮説 | 判定 |

## 6. 不一致の扱い（要件 5.6）

**本 spec は完了としない。** 根因の所在は**現行の Boundary Context の外**にあり、
スコープ拡大の可否は**開発者裁定を要する**:

- design.md **:42 / :74 / :206** は `looper.rs` を明示的に「**無改変**」と宣言している
- requirements.md の In scope は「非宣言カテゴリの排他置換」まで
- 他 spec に既存の所有者は**不在**（`recompose-budget`＝CPU／`test-cage-determinism`＝テスト
  分離／`emo2-conformance-e2e`＝W7 で検出するのみ／`seriko-loop` は completed で消化不能）
- なお `completed/areka-P0-seriko-loop` requirements.md:120 は最終コマ残留を
  「**デファクト推定・実機で齟齬が観測されたら SSP 実観察で裏取り**」と留保付きで確定させて
  おり、**今回がその齟齬の初観測**にあたる。ただし emo2 のデータ（1403「----」が `null.png` で
  「まばたき層なし」を表現している）は「bind 中の残留は意図どおり」という読みと整合するため、
  **残留保持そのものは疑う必要がなく、欠けているのは「外れたときの掃除」だけ**である

### 裁定後の修正方針（案）

1. `state.rs` `commit_bind`: `removed = 旧集合 \ 新集合` を求め、`pattern_states[(scope, Slot::Shell)]`
   から `removed` の ID を除去してから Show を組む（`:394` の複製前）
2. `looper.rs` phase (3): 再生中かつ bind 種かつ `current_binds` 非所属の ID を停止相当
   （コマ除去＋playback 除去）に落とす——これが無いと「再生中に外れた」場合に次 tick で復活する
3. 除去は info ログを出す（無言の状態変更を作らない・ログ規律）
4. 補強（任意）: `plan.rs:302-309` の合流に「bind 種 interval なら `binds.contains(id)` を要求」を追加
5. **片肺にしないこと**——design.md :42/:74/:206 の「`looper.rs` 無改変」宣言、Boundary Context、
   requirements.md:21 の因果記述を**同時に改訂**する

### 検証方法（実機を待たず決定論テストで可能）

- `state.rs`: 1402 のコマを commit → 1400 へ排他置換 → 発行 Show の pattern に 1402 が無いこと
- `looper.rs`: bind 種の発火中に bind を外す → 次 tick でコマと playback が消えること
- `emo-compose` golden: 非 bind の ID のコマを渡した合成にその層が現れないこと
- 実機: J3（目視）に加え、機械判定 **J4**「bind 除去痕跡の直後に同 ID の掃除ログが存在する」を
  `signoff-scan.py` へ追加可能

## 7. 本実走で確定した成果（是正の効いた範囲）

不合格ではあるが、本 spec が担った bind 層の是正は**実機で証明された**:

- **要件 2.1**（非宣言カテゴリ on の排他置換）— 同一カテゴリ 2 パーツの共存痕跡が**ゼロ**
- **要件 2.3**（飽和の構造的不成立）— まばたき Changed が 3 回 → **20 回**・末尾まで継続
- **要件 3.2**（mustselect 解除不可）— 回帰なし（warn 0 件・非宣言カテゴリの off は正しく除去）
- **要件 5.2 / 5.4** — J1・J2 とも FAIL から **PASS へ反転**

残るのは **表示層の後始末**という、本 spec が触っていない独立した欠陥である。
