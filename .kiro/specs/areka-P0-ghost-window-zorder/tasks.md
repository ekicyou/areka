# Implementation Plan

- [ ] 1. 基盤: 重なり関係の宣言と判断の中核
- [ ] 1.1 窓の重なりを OS へ問い合わせ、owner 関係を張り外す手段を用意する
  - ある窓の 1 つ手前／1 つ背後にある窓を OS へ問い合わせる手段を追加する
  - ある窓の owner を設定する手段と、owner を外す手段を追加する
  - いずれも失敗を握り潰さず呼び出し側へ返し、記録できる形にする
  - 観測: 既知の 2 窓を生成して重なり順を実測し、期待どおりの前後関係が返ることを確かめる単体テストが緑になる
  - _Requirements: 5.9, 7.2_

- [ ] 1.2 (P) ペア関係の宣言・再断行要求・確立記録・実行時ストラテジの状態を定義する
  - 「この窓は相手の窓のすぐ手前に居るべき」という永続宣言の状態を定義する
  - 重なりを断行し直す一回限りの要求（適用済み・検証待ちの段階を持つ）を定義する
  - owner を張った事実の記録と、案 A／案 B を実行時に切り替える設定を定義する
  - 宣言と再断行要求を**他のクレートから付けられる公開到達性**を持たせる（表示制御を所有する仕様が再表示時に再断行要求を入れる契約点になるため）
  - 観測: 別クレート側のテストから宣言と再断行要求を実体へ付けられ、各状態が読み書きできることを確かめるテストが緑になる
  - _Requirements: 1.1, 2.6, 3.4, 5.6_
  - _Boundary: zorder_pair 状態定義_

- [ ] 1.3 是正判断を実機不要の純粋な判断として実装し、全分岐をテストで固定する
  - 「トリガ種別・両窓の生存・実測した前後関係」から「何もしない（理由つき）／バルーンを相手のすぐ手前へ／キャラを相手のすぐ背後へ」を決める判断を実装する
  - トリガ種別は「バルーン側の重なりが動いた」「キャラ側の重なりが動いた」「確立」「再断行」を区別できる形にする
  - 既に隣接しているときは必ず何もしないと決める同値の歯止めを入れる
  - 片方の窓が存在しないときは理由つきで見送り、残る窓に一切書き込まない
  - 判断の結果が座標や寸法を持ち得ない形にし、常時最前面の指定を決して返さないことをテストで固定する
  - 動かす対象が宣言されたペアの 2 窓に限られることをテストで固定する
  - 観測: 全分岐（見送り 5 種・手前へ・背後へ・最上位の縁）を網羅した単体テストが緑になり、常時最前面を返す経路が存在しないことを対照ケース込みで確かめられる
  - _Requirements: 1.2, 1.3, 1.5, 1.6, 3.1, 3.2, 3.3, 3.4, 4.3, 7.1, 8.1_
  - _Depends: 1.2_

- [ ] 1.4 診断記録の語彙を実装する
  - 宣言・owner 確立・是正・見送り・検証不一致・確立失敗・沈降観測の各記録を出せるようにする
  - 是正の記録には出した指令と、その後に実測した前後関係を同じ 1 行へ載せる
  - 見送りは必ず理由を伴わせ、記録の無い見送りが起きない形にする
  - 失敗と検証不一致は error 水準で記録する
  - 観測: 記録捕捉のテスト支援で各記録が期待する語で拾えることを確かめ、対照ケース（記録されないはずの状況）も併置した単体テストが緑になる
  - _Requirements: 6.1, 6.2, 6.3_
  - _Depends: 1.2_

- [ ] 2. 案 A（本線）: owner による重なり保証の確立と維持
- [ ] 2.1 両窓のハンドルが揃った時点で owner を一度だけ張る確立処理を実装する
  - 両方の窓に OS のハンドルが付いた巡で、バルーン窓の owner をキャラ窓に設定する
  - 成功したら確立の記録を残し、初期の隣接を確定させるため再断行の要求を一度入れる
  - 失敗したら error 水準で記録し、同じハンドルでの再試行は繰り返さない（窓は現行どおり表示され続ける）
  - 観測: ヘッドレスで両窓のハンドル付与を再現し、確立が 1 回だけ走ること・片方欠けでは走らず見送りが記録されることを確かめるテストが緑になる
  - _Requirements: 1.1, 6.1, 6.2_
  - _Depends: 1.1, 1.2_

- [ ] 2.2 維持処理を実装する（トリガ受理 → 観測組立 → 判断 → 適用 → 次巡での実測検証）
  - 再断行の要求を受け、両窓の実測前後関係を採って判断へ渡す
  - 是正は位置・寸法・活性化を伴わない形で発行し、重なりだけを動かす
  - 適用の次の巡で実測と期待を突き合わせ、一致なら是正の記録、不一致なら error 記録を残す（再試行の輪は作らない）
  - 適用が失敗しても利用者の操作を継続可能に保ち、異常終了しない
  - 観測: 要求の挿入から適用・検証・要求の消滅までの状態遷移をヘッドレスで辿るテストが緑になり、既に隣接している場合に一切の指令が出ないことも確かめられる
  - _Requirements: 1.2, 1.4, 1.5, 2.6, 6.1, 6.2, 6.3, 6.4, 7.6_
  - _Depends: 1.3, 1.4_

- [ ] 2.3 破棄時に owner を切り離し、重複破棄でも異常終了しない状態を作る
  - ペアの相手が消えたことを維持処理が検知した時点で owner 関係を外し、OS の連鎖破棄を起こさせない
  - 他スコープの窓へは owner 関係を一切張らないことを構造として保つ
  - 同一スコープの 2 窓が対で消えること自体は許容する
  - 観測: キャラ先行・バルーン先行の双方の破棄順をヘッドレスで再現し、切離しが走ること・残る窓や他スコープの窓が消えないこと・処理が継続することを確かめるテストが緑になる
  - _Requirements: 5.7, 5.8, 5.9_
  - _Depends: 2.1, 2.2_

- [ ] 2.4 他アプリ活性化時の沈降を、遅延させた実測で記録する
  - 自窓が非活性化された時点では観測の目印を付けるだけに留める
  - 実際の前後関係の実測と記録は次の巡で行い、活性化の途中で測って偽の失敗を記録しないようにする
  - 記録には、ゴーストの窓が前面の窓より背面にあるかと、ペアの隣接が保たれているかを載せる
  - 窓の挙動は一切変えない（読み取りのみ）
  - 観測: 非活性化の受理で目印が付き、次巡で実測記録が 1 件出ることをヘッドレスのテストで確かめられる
  - _Requirements: 4.1, 4.2, 4.4, 7.5_
  - _Depends: 2.2_

- [ ] 3. ゴースト側の宣言付与と結線
- [ ] 3.1 (P) ゴースト窓の生成時にペア宣言を付け、スコープを突き合わせられる記録を残す
  - キャラ窓の生成後に、同一スコープのバルーン窓へ「キャラ窓のすぐ手前に居るべき」宣言を付ける
  - スコープと両窓の実体を対応付ける宣言の記録を出し、後段の記録と突き合わせられるようにする
  - この付与は案 A・案 B のどちらでも同一で、生成順は変更しない
  - 観測: 生成の組み立てテストで、バルーン窓が宣言を持ちスコープつきの記録が出ることを確かめられる
  - _Requirements: 1.1, 6.1_
  - _Depends: 1.2_
  - _Boundary: spawn ペア宣言_

- [ ] 3.2 実行時ストラテジを与え、確立・維持・観測の各処理を毎フレームの確定段へ結線する（統合タスク）
  - 既定を案 A（補助浮上なし）とする設定を与える
  - 確立・維持の処理を、既存のクリック透過登録と同じ確定段へ登録する
  - 観測: 実ゴーストを起動すると、宣言 → owner 確立 → 是正（指令と実測を併記）の記録が起動直後に順に現れ、バルーンがキャラの直前に居る実測値がログに残る
  - _Requirements: 1.1, 5.6, 6.1_
  - _Depends: 2.1, 2.2, 2.4, 3.1_

- [ ] 4. 拡大率の異なる 2 画面の実機で案 A の可否を判定し、判定表を残す
  - 有界時間で自動終了する実行とログ照合により、描画の生存・クリック透過・透過トグル・タスクバーと一覧への非露出・ドラッグと追従・キャラ活性化でのペア浮上と隣接を順に判定する
  - 上記 6 項目のいずれかが損なわれた場合は案 A を採らない（案 B へ切替）と決め、その判定を記録する
  - バルーン活性化でキャラも浮上するかを判定する（不成立でも案 A は継続し、補助浮上を足す分岐となる）
  - 破棄順の双方で異常終了しないかを判定する（不成立なら切離しの適用時点を早める分岐となり、それでも塞げない場合のみ案 B へ切替）
  - 観測: 8 項目の合否と根拠ログを判定表として仕様配下へ書き出し、以降の分岐（案 A 継続／補助浮上の追加／切離しの強化／案 B へ切替）が一意に決まる状態になる
  - _Requirements: 1.3, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.9, 7.2_
  - _Depends: 3.2_

- [ ] 5. ゲート結果に応じた分岐実装（判定表が指した分岐のみ実施する）
- [ ] 5.1 ゲートの判定を実行時ストラテジへ反映する
  - 全項目合格なら既定のまま（案 A・補助浮上なし）とする
  - バルーン活性化でキャラが浮上しなかった場合は、補助浮上を有効にした案 A へ切り替える
  - 案 A 不可と判定された場合は明示維持（案 B）へ切り替える（案 B の値の有効化は 5.7 の完了時点とする）
  - 観測: 起動時のログに選択された方式が現れ、ゲート判定表の結論と一致する
  - _Requirements: 5.6_
  - _Depends: 4_

- [ ] 5.2 破棄の連鎖を塞ぎ切れなかった場合に限り、切離しの適用時点を早める
  - 実体の消滅を検知してからではなく、窓の登録が実際に取り崩される直前に owner を外す
  - それでも重複破棄が塞げない場合は案 A 不可と判定し、判定表へ追記する
  - 観測: 双方向の破棄順に加えアプリ終了経路でも異常終了しないことを実機実行で確かめ、判定表に結果が残る
  - _Requirements: 5.9_
  - _Depends: 5.1_

- [ ] 5.3 重なりが動いたことを OS の通知から検知する仕組みを足す（補助浮上または案 B が必要になった場合）
  - 窓の重なりが動いた通知を受け、自分が出した指令の反響でなければ再断行の要求を入れる
  - 動いたのがバルーン側かキャラ側かでトリガ種別を区別して渡す
  - 活性化の既定処理が終わった後に届く通知で動くため、前面化との競合を構造的に避ける
  - 判断と適用はここでは行わない（維持処理へ一元化したまま保つ）
  - 観測: 重なりが動いた通知の有無と反響判定の 4 通りで、要求が入る場合と入らない場合が分かれることを配送テストで固定できる
  - _Requirements: 1.4, 2.7_
  - _Depends: 5.1_
  - _Boundary: 窓メッセージ処理_

- [ ] 5.4 補助浮上の受け口を維持処理へ実装する（バルーン活性化でキャラが浮上しなかった場合のみ）
  - バルーン側の重なりが上がったトリガを受けて、キャラをバルーンの直後へ引き上げる分岐を有効にする
  - 補助浮上が無効な構成では同じトリガで何もしないことを保つ
  - この分岐では位置書込への重なり同乗は実装しない
  - 観測: 実機でバルーン窓を掴んだ後に、キャラ窓が他アプリの背後に残らないことを実測記録で確かめられる
  - _Requirements: 1.3, 2.3_
  - _Depends: 5.3_
  - _Boundary: zorder_pair 維持処理_

- [ ] 5.5 重なりの意図を求める問い合わせ口を用意する（案 A 不可の場合のみ）
  - 観測の組立と判断を包んだ問い合わせを設け、位置を書き込む側が重なりの意図だけを受け取れるようにする
  - 判断の実装は 1.3 の一箇所のままとし、別クレートへ複製しない
  - 既に隣接している場合や対象がペアの当事者でない場合は「変更なし」を返す
  - 観測: 隣接済み・非当事者・要是正の 3 通りで期待どおりの意図が返ることを単体テストで確かめられる
  - _Requirements: 2.1, 2.2, 2.4, 2.5_
  - _Depends: 5.1_

- [ ] 5.6 位置書込の単一経路へ重なり指定を足し、全呼出元を追随させる（統合タスク・案 A 不可の場合のみ）
  - ゴースト窓の位置を書き込む唯一の経路に重なりの指定を受け取る口を足し、既定は現行と完全に等価とする
  - ドラッグ確定・別画面への移動・拡大率変化後の再配置・保存位置からの復元・寸法変更・スクリプト由来の移動の各呼出元を追随させ、ペアの当事者には 5.5 の問い合わせで得た意図を渡す
  - 本経路を迂回する第二の書込経路は作らない
  - 観測: 既定値では現行と同一の指令が出ることを回帰テストで固定でき、指定ありでは重なりの指定が指令へ載ることを確かめられる
  - _Requirements: 2.1, 2.2, 2.4, 2.5_
  - _Depends: 5.5_

- [ ] 5.7 owner 確立と切離しの仕組みを撤去する（案 A 不可の場合のみ）
  - owner を張る処理・確立の記録・破棄時の切離しをコードごと取り除き、効かない保険を残さない
  - 破棄の意味論を現行（対で生成し対で破棄される独立した窓）へ戻す
  - 明示維持（案 B）を既定の実行時ストラテジとして有効化する
  - 観測: owner 関係を張る呼び出しが本番経路から消え、破棄まわりの既存テストが緑のまま通る
  - _Requirements: 5.6, 5.9_
  - _Depends: 5.6_

- [ ] 6. 検証
- [ ] 6.1 決定論的テストの網羅を仕上げる
  - 判断の全分岐・再断行要求の状態遷移・生成の組み立て・片割れ消滅後の見送りを揃える
  - 重なりが動いた通知の配送は、実施した分岐に応じて反響有無との組み合わせで固定する
  - 記録の捕捉は対照ケースを併置し、「記録されないこと」の主張が恒真にならないようにする
  - 再表示の経路は決定論的テストのみで受け入れ、実機での確認は表示制御を所有する仕様の着地後に行うと明記する
  - 前提はゲート判定表が指した分岐のタスクのみとし、実施されなかった分岐は前提に含めない
  - 観測: 追加した全テストが緑で、既存のテスト総数が、撤去を伴う分岐で正当に取り除いた分を除いて減っていない
  - _Requirements: 1.5, 6.3, 7.1, 7.6_
  - _Depends: 5.1_

- [ ] 6.2 実機サインオフを行い、重なりの実測を証跡として残す
  - 拡大率の異なる 2 画面の間でキャラ窓を往復させ、各移動後にバルーンがキャラの直前に居ることを実測で確かめる
  - バルーン窓を操作した場合にキャラ窓が他アプリの背後に埋もれず、かつキャラ窓の位置が動いていないことを確かめる
  - 他アプリを活性化し、非活性化ごとの最後の観測記録でゴースト一式が背面かつ隣接を保っていることを確かめる
  - 観測: 3 つのシナリオそれぞれについて、指令と実測を併記した記録が揃い、判定が合格で確定する
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.6, 2.1, 2.2, 2.3, 2.4, 2.5, 2.7, 4.1, 4.2, 4.4, 7.2, 7.3, 7.4, 7.5_
  - _Depends: 6.1_

- [ ] 6.3 (P) 既定の重なり状態と、先送りした語彙に手を出していないことを回帰で固定する
  - ゴースト窓が常時最前面の指定を持たない現行の状態が変わっていないことをテストで固定する
  - ペアの前後関係を保つ仕組みと、一式を最前面へ上げる政策とが互いに独立していること（後者を足しても前者の不変条件が壊れないこと）をテストで固定する。この確認はテスト内に閉じ、本番経路へ最前面指定を持ち込まない
  - 最前面指定・窓状態の指定・関連する通知・最小化やタスクバー表示の扱いに新たな解釈を足していないことを確かめる
  - 観測: 上記を固定したテストが緑で、先送り語彙を扱う経路が本番に一つも存在しないことを確かめられる
  - _Requirements: 8.1, 8.2, 8.3, 8.4, 8.5_
  - _Depends: 6.1_
  - _Boundary: 回帰テスト_
