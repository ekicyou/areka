## 2. コア: 解決層・状態層・発行層・構築層の実装

各タスクは自分のモジュールファイルの中身のみを書き、lib.rs には触れない（re-export は 3.2 が担当）。

- [x] 2.1 (P) surface 引数の解釈（解決層）を実装する
  - 数値指定・非表示指定・alias/name 文字列指定を判別し、表示すべき surface / 非表示 / 解決不能のいずれかへ分類する
  - 解決不能となる入力（未知の alias・範囲外の数値表現など）を型で明確に区別する
  - 1 つの alias が複数の候補を持つ場合に、常に同じ候補（先頭）を選ぶ決定的な規則を適用する（ランダム選択は行わない）
  - 実データ（サンプルゴーストの alias 表）を使い、単一・複数候補・非表示・未知キーの全パターンが期待どおりに分類されることを単体テストで確認する（observable: 全パターンのテストが green）
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 3.3, 7.3, 7.4_
  - _Boundary: SurfaceResolver（解決層）_

- [x] 2.2 (P) スコープごとの surface 状態（状態層）を実装する
  - 話者スコープ単位で独立した現在の表示状態（表示中の surface / 非表示）を保持する
  - 特定スコープへの更新が他スコープへ影響しないことを保証する
  - 状態が実際に変化した場合のみ「変化あり」を返し、変化がない場合は再発行が不要であることを呼び出し側へ伝える（冪等ガード）
  - 静的な着せ替え集合（1.2/2.4 の成果を受け取る形）をスコープ状態と同じ置き場に保持し、以後の切替ユニットが置き場だけを差し替えられる形にする
  - 単体テストで、スコープ分離・非表示への遷移・非表示からの復帰・状態不変時の非発行を確認する（observable: 全ケースのテストが green）

  - _Boundary: ScopeStates（状態層）_

- [x] 2.3 (P) emo への表示指令と観測用出力先（発行層）を実装する
  - 「表示」「非表示」を表す指令データを定義し、スレッド間で安全に受け渡せる所有データとする
  - 表示指令の送り先を抽象化し、本番の表示系（emo-present）が未完成でも単体観測を完結できる観測用の実装（送られた指令列を記録し照合できるもの）を用意する

- [x] 2.4 (P) 静的な着せ替え集合の構築（構築層）を実装する

  - 番号の対応関係が恒等（変換なし）であることを実データ（既定オン集合）で確認する単体テストを用意する（observable: 期待される bind 集合と一致するテストが green）

## Implementation Notes

- 1.2: bindgroup default KV（`sakura.bindgroupNNNN.default,1`）は **shell の descript.txt**（`shell/<dir>/descript.txt`・category `descript_shell`）に存在し、ghost/master/descript.txt には無い。`MountModel` の parse 経路（`package/resolve.rs`）は shell descript を best-effort（不在は非致命→空）で追加読みして `bindgroups` へ転記する。emo2 実測 `sakura_default_on == {1100,1207,1302,1500,1800}`・`kero_default_on` は空。2.4（build_static_bindset）・ghost-setup 結線がこの入力源を消費する。
- 3.1: seriko の tracing ログ検証は `actor.rs` 内 in-module `capture_logs` ハーネス（`tracing-subscriber` を `[dev-dependencies]`・workspace 版・`with_default`+Layer で level/target 捕捉、emo-compose `log_capture` 流儀）で決定論化する。4.1/4.2 のログ発火テストはこの流儀を再利用可。SerikoSink::emit の送信失敗ログ経路の `unreachable!` は emit が Cue のみ送るため真に到達不能（6.4 非違反・軽微 nit）。
