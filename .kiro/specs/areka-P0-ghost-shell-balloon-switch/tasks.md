# Implementation Plan

> 前提: x64 の決定論テスト（1〜9）は i686 の成果物なしで回る。i686 の 2 成果物（`shiori-host32-helper`・`shiori-host32-testdll-loadu`）は 9.3 の全体テスト（常設 smoke）と 10.3 の実機でだけ要る。各タスクの完了時に `cargo build --workspace --tests`（x64）が通る状態を保つ（途中でワークスペースを壊したまま次へ渡さない）。
>
> 依存の向きは design のとおり kanade → areka-ghost → areka。停止通知の型を変える 1.2 は 3 クレートにまたがる機械的な追随なので、明示の統合タスクとして置く。
>
> 要件 11.12（裁定を覆す必要が出たら開発者へ議題として上げ、確定を待つ）は全タスクの実装中に守る進め方の決まりで、成果物は 10.2 の §8 の記録に現れる。

  - どの型も丸ごと突き合わせられる形（等価比較・複製・Debug）にし、出どころの Reference の綴り（`manual`／`automatic`）を型の側で返す

  - 停止通知に「切替の中身（無ければ無し）」の欄を足し、kanade の通知の送出端の型を運行の通知へ広げる。運行表の動作に「通知を送る」を 1 つ足し、アクターはそれを送出端へ流す（送出の失敗は `warn!(notice_send_failed)`・送出端が無ければ `debug!`）。停止は運行の通知の「停止」で送る

  - 運行表の動作の変種を網羅する既存テスト（`action_variants_are_existing_five_plus_choice_two`）を `schedule_tests.rs` から兄弟の新しいテストファイルへ移し（削除しない）、そこで新しい動作の腕を足す。`schedule_tests.rs` は行が減るだけで、`cargo fmt` 後も行を足さない
  - areka の終了の相は「停止」だけを今日どおり捌き、「定常到達」「切替の中止」は `debug!` で読み捨てる（振り分けは 8.4）。終了の判断・終了コード・記録の語彙は変えない
  - `cargo build --workspace --tests` が通り、kanade・areka-ghost・areka の既存テストが 1 本も落ちずに緑

- [x] 3.2 raise-event 無しの切替と、再生中に届いた切替の保留を足す

  - 定常でトークの再生中に届いた要求は保留し（`info!(change_pending)`・保留の間は受理した切替の欄を空のままにし、保留の欄だけを持つ＝受理した切替の欄が埋まるのは切替の相の間だけ）、そのトークが最後まで流れても利用者に中断されても保留を消化して切替を始める（定常のファイルには行を足さず、横断の腕から切替の相のファイルへ委譲）

- [x] 3.3 切替の中止と、終了要求への譲りを足す

  - 切替の相に終了要求が届いたら切替を取りやめ（切替の中止を通知・`info!(change_yield_to_close)`）、相ごとに今日の終了の握手へ合流する: 応答待ちは応答を見てから、`OnGhostChanging` の台詞の途中はその台詞を最後まで流してから `OnClose`、切替の `OnClose` を送った後はそれを二度送らずその別れの台詞の終わりで終了

  - テストで固定し緑: 2 つの台詞の待ちで中断（`\-` の予約あり）→ 定常・中止の通知 1 件・降ろす相へ進まない／中止のあとの終了要求で今日どおり `OnClose` が出る／各相の終了要求で `OnClose` の追加送出 0・切替の中止の通知 1 件
