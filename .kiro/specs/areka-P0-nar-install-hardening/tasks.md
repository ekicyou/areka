- [x] 2. 名前・パスの長さの上限
- [x] 2.1 (P) 名前の検査の並びに長さの項を足し、`install.txt` のフォルダ名にも同じ上限を効かせる
  - 上限は UTF-16 の単位で数える 1 つの定数 200 とし、定義点は名前の検査のモジュールの 1 か所だけ（要素ごとの別の上限は持たない）
  - 長さの検査は復号の直後・NUL の検査の前に置き、フォルダのエントリは末尾の `/` を除いた形を測る。超えたら「長すぎる」の理由で書庫全体を拒否し、後段の検査には進まない
  - 先頭の有界の一部（最大 32 単位・BMP 外の文字を途中で切らない）と、理由に載せる有界の値（上限の内側なら全体、超えていれば先頭＋測った長さ＋上限）を作る助手を同じモジュールに置く

  - モジュール注釈の検査順の列挙を「復号 → 長さ → NUL → …」に改め、本体にファイルシステム・プロセスの綴りを 1 つも足さない（字面の見張りが緑のまま）
  - 名前の検査のテストに、NUL・`\`・`..`・予約名を同時に持つ 200 単位超の名前が「長すぎる」で拒否され先頭と長さが正しいこと、1 階層の名前の判定が 200 で真・201 で偽になることの 2 本を足す
  - 完了の状態: 名前の検査のテストが緑で、長さの検査を外すか NUL の後ろへ動かすと順序のテストが赤になる（全数対応のテスト `every_refusal_kind_has_a_fixture_and_is_recorded_once` だけは 2.2 で固定入力を足すまで赤のまま＝期待どおり）

- [x] 3. 巻き戻せなかった元の木の在りかと保持
- [x] 3.1 (P) 巻き戻しの躓きから生き残りを全て集め、確定の失敗まで運ぶ
  - 巻き戻しは躓いた「元へ戻す」手ごとに、退避先がフォルダとして実在すれば「宛先と退避先」の組を集める。「新規の宛先を消す」手の躓きと、退避先が実在しない躓きは集めない。最初の躓きを返す既存の動きと、解く順・解く内容は変えない
  - 巻き戻しの結果を確定の失敗の値に写し、巻き戻せたときは生き残りが必ず空になる
  - 確定の部品のテストに、退避先に元の木・宛先に新しい木を置いて宛先側のファイルをテスト自身が掴み、巻き戻しを直接呼ぶ 1 本を足す: 巻き戻せず、生き残りがちょうど 1 件で退避先を指し、退避先の中身が置いた元の木とバイト列で一致する
  - 既存の「巻き戻しが終わらない」合成テストに、退避先が実在しない躓きと新規の宛先を消す手の躓きが生き残りに載らないことの判定を足す
  - 完了の状態: 確定の部品のテストが緑で、生き残りの欄を外すか集める条件を外すと新しい 1 本が赤になる（全数対応のテスト `every_refusal_kind_has_a_fixture_and_is_recorded_once` だけは 2.2 で固定入力を足すまで赤のまま＝期待どおり）

  - _Boundary: install.rs（unwind・roll_back・CommitError）, install_commit_tests.rs_
  - _Depends: 1.1_

- [x] 3.2 生き残りを含む作業フォルダを 7 日のあいだ棚の片付けから守る
  - 保持の期限は 7 日の 1 定数。棚の項目が退避先（`old-` で始まるフォルダ）を直下に持ち、その作業フォルダの更新時刻から期限未満なら、消さずに残り物として報告する（既存の残り物の出口だけを使い、新しい記録の出口は足さない）。読めない項目・時刻の取れない項目は今までどおり消しにいく。更新時刻が今より未来なら経過 0 として保持側へ倒す
  - 期限を過ぎた項目と、退避先を持たない項目は今までどおり消す
  - 作業フォルダを掘る入口に時刻を受け取る形を足し、既存の入口は現在時刻を渡す薄い皮にする。判定の契機は展開の開始時の片付けだけ
  - 自分の番地は保持中の項目を避けて取る（連番の供給源を差し替えられる形にし、テストがプロセス全体の連番に依らず判定できるようにする）
  - 片付けを直接呼ぶ既存の 2 本（自分の番地が消せない失敗・残り物の報告）は、足した時刻の引数に現在時刻を渡す追随だけを行い、判定は変えない
  - 片付けのテストに 3 本を足す: 期限の内側の生き残りが残って残り物に載る／期限を 1 秒過ぎた時刻を渡すと消える／自分の番地の候補が保持中なら次の番地を取る。退避先を持たない残骸が消える既存のテストは判定の変更 0 で緑
  - 完了の状態: 片付けのテストが実際の日数を待たずに緑で、保持の判定を外すと 1 本目が、期限の比較を外すと 2 本目が赤になる
  - _Requirements: 2.7, 2.8, 2.9, 2.10, 2.11_
  - _Boundary: install.rs（WorkArea・prepare_shelf・next_address・is_retained）, install_tests.rs_

## Implementation Notes

- 1.1: `NarError::Io.survivors` は `Vec` でなく `Box<[SurvivingTree]>`。`Vec` だと `sample-ghost-kit` の `SampleError`（`NarError` を包む）が clippy `result_large_err` の閾値に達し警告 18 件。内部の `CommitError.survivors` は `Vec` のまま、`place` で `into_boxed_slice` して写す（design.md 追随済み）。
- 2.2: 変異実験で退避コピーを `cp -p` で戻すと mtime が古いまま cargo が再ビルドせず、変異後のコードで走る（偽の赤）。戻したら `touch` する。
- 3.1: `CommitError.survivors` に一時の `#[cfg_attr(not(test), expect(dead_code, …))]` を置いた。4.1 で `place` が読んだら外す（外さないと期待外れの警告になる）。
- 4.1: 公開の入口から巻き戻しを決定論的に失敗させる手段は無く、`place` の生き残りの写し（1 行の配線）は公開面のテストで見張られない。空でない生き残りは `install_commit_tests.rs` の単体（3.1）が固定する（要件 2.6 の許す形）。
- 5.2: main（#170 shiori-loadu・#171 既定バルーンの .nar 化）を取り込んで検証。§8 の表の末尾は loadu の 3 行の後ろに本仕様の 1 行（後着が取り込む）。登記済みの検体は 6 本になり、`sample-ghost-kit` のテストで全て受理。
