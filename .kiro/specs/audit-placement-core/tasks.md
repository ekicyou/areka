# 実装計画: audit-placement-core

確定した 80 件（`requirements.md` の「確定した指摘の一覧」）を、`design.md` の単位 U1〜U28 の順に直す。直し方の詳細（行・名前・形）は `design.md` の各単位が正本で、ここでは仕事の区切りと、終わったと言える状態だけを書く。

共通の決まり（どのタスクにも当てはまる）:
- この spec の `/kiro-impl` は、C20 の先の段の 4 本（`wintf-visual-damage-redraw`・`wintf-winmsg-executor-import`・`audit-wintf-window`・`audit-placement-follow`）が `main` へ着地してから始める（要件 8.9）。
- 消す・まとめる・形を変える前に、ツリー全体（テスト・fixture・examples・文字列の参照を含む）で使い手を grep し、見つかった使い手を同じタスクで直し切る（要件 4.3・7.1・7.3）。
- 1,000 行に近いファイル（`persist.rs`・`lib.rs`・`persist_restore_tests.rs`・`measure_tests.rs`・`shell_target.rs`・sylphya の `actor.rs`）に触ったタスクは、終わりに行数を測り、越えるなら兄弟のファイルへ分ける（番人の例外表へは足さない・要件 9.1）。
- 各タスクの `_Dispatch:_` は、`/kiro-impl` が下請けのモデルと手間をそこから選ぶ段（`judgment` は 0 本・`standard` 15 本・`mechanical` 13 本）。
- 各タスクの終わりに `cargo test -p areka-placement --features test-support` が緑。本体に響くタスクは `cargo test -p areka` も緑。依存を足さず、`Cargo.lock`・`vendors/`・追随の持ち物（`src/follow*`・`src/transition_*`・`placement_tests/transition_*`）に触らない（例外は 2.4 の 1 行だけ）。
