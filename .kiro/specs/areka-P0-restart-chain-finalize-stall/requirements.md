# Requirements Document

## Project Description (Input)
ゴーストを同じプロセスの中で起こし直すと（起動中のゴーストへ上書きインストールした後・ネットワーク更新の読み直しの後）、起こし直した約 5 秒後に「初期配置の確定が続けて見送られている」WARN（`deferrals=600`・理由は相方 scope 1 の初回表示が未成立）が 1 件出ることがある。画面は正常で利用者から見える害は無いが、この WARN は本来「窓が在るのに初期配置がいつまでも決まらない」という本物の異常を知らせるためのもので、正常な起こし直しのたびに鳴ると本物と見分けられなくなる。困っているのは、ログで本物の異常を拾いたい開発者である。

観測は 2 件（完了 `ghost-install` の実機で emo2 へ `emo2.nar` を入れ直したとき・完了 `network-update` の実機であやめを更新して読み直したとき）。里々の上書きと、メニューからの普通の切替では 0 件。

静的に追った原因の見立て: 起こし直しは窓と初期配置の資源（見送りの数を含む）を外すが、毎フレームの処理は古い結線のまま回り続ける。窓の無い区間でも初期配置の確定へ入り、「窓が無い」を理由に見送りを数え直す（外したばかりの数の記録を作り直す）。新しい窓が開いてもこの数を戻す者が居ないため、新しい一式で相方の初回表示を待つ間に 600 へ届いて WARN が出る。窓の無い区間が数に入る点は静的な読みで、実機では確かめていない。

変えたいこと: 窓が無い巡は見送りに数えない。起こし直しの後、新しい窓の見送りは 0 から数え始める。本物の異常（窓が在るのに確定がいつまでも決まらない）では今日と同じ WARN を出す。これを決定論テスト（直す前は赤・窓が在る対照つき）と実機 1 回（emo2 の入れ直しで WARN 0 件）で確かめる。

## Introduction
初期配置の確定の見送りを数える判定を、「窓が無い巡は数えない」形に直す。起こし直しの窓の無い区間が数に入らなくなるので、新しい窓の一式は見送りを 0 から数え始め、正常な起こし直しで `deferrals=600` の WARN が鳴らなくなる。窓が在るのに確定が決まらない本物の停滞は、今日と同じ回数・同じ本文で知らせ続ける。

## Boundary Context
- **In scope**: 初期配置の確定を見送ったとき、その巡を数えるかどうかの判定（窓が無い巡を数えない）／それを確かめる決定論テスト（窓を全部閉じた後の次の窓の一式を確かめる既存の兄弟テストの並びへ足す）／emo2 の入れ直しによる実機の確かめ 1 回。
- **Out of scope**: 窓の無い区間で毎フレームの処理そのものを止めること（毎フレームの結線の持ち方）／起こし直しの手順（窓と資源の外し方・ゴーストのセッションの扱い）／初期配置の確定の規則と配置の計算／WARN のしきい値（600）と本文／拡大率の遷移の後の解き直しの見送りの数え方／インストールの手続き。
- **Adjacent expectations**: 起こし直しは今日どおり窓と初期配置の資源（見送りの数を含む）を外すことを前提にする（完了 `areka-P0-ghost-shell-balloon-switch` のタスク 11.9）。同じウェーブで並走する spec と触るファイルを重ねないため、触るソースは見送りを数える判定の 1 ファイル（`crates/areka/src/emo2_boot/frame/drain_resnap.rs`）と、その兄弟テスト（`crates/areka/src/emo2_boot/frame_chain_finalize_restart_tests.rs`）だけに限る。隣の `areka-P0-install-live-target-hazards` は同じ「起動中のゴーストへ入れる」場面を扱うが、触るファイルの共有は 0。

## Requirements

### Requirement 1: 窓が無い巡を見送りに数えない
**Objective:** As a ログで本物の異常を拾いたい開発者, I want 窓が 1 つも無い巡を初期配置の確定の見送りに数えないこと, so that 正常な起こし直しで停滞の WARN が鳴らない

#### Acceptance Criteria
1. While ゴーストの窓の一式が無い（起動で窓が生える前・起こし直しで窓を外した後）, the areka shall 初期配置の確定を見送った巡を見送りの数に加えない（外された見送りの数の記録を作り直さない）。
2. While ゴーストの窓の一式が無い（起動で窓が生える前・起こし直しで窓を外した後）, the areka shall 何巡続いても「初期配置の確定が続けて見送られている」WARN を出さない。
3. When 起こし直しで窓を外した後に新しい窓の一式が開いた, the areka shall 新しい一式の見送りを 0 から数え始め、窓の無い区間の巡を引き継がない。
4. When 窓の無い区間を挟んで起こし直した新しい窓の一式で確定の条件が揃った, the areka shall 初回の起動と同じく初期配置の確定を 1 回だけ行う。
5. The areka shall 窓が無いために数えなかったことを、既定の記録の level では記録を増やさず、実機の確かめで開けた level では読み取れる形で残す。

### Requirement 2: 本物の停滞は今日と同じく知らせる
**Objective:** As a ログで本物の異常を拾いたい開発者, I want 窓が在るのに初期配置がいつまでも決まらない停滞では今日と同じ WARN が出ること, so that 直した後も本物の異常を見逃さない

#### Acceptance Criteria
1. While 窓の一式が在り初期配置の確定が見送られ続けている, the areka shall 今日と同じしきい値（600 巡目）に届いたその 1 回だけ WARN を出し、599 巡目までは出さない。
2. When 停滞の WARN を出す, the areka shall 今日と同じ本文と項目（見送りの数・スコープ・見送りの理由）で出す。
3. When 一度 WARN を出した, the areka shall 同じ停滞が続いても WARN を繰り返さない（今日と同じ一度きり）。
4. The areka shall 初期配置の確定の規則・WARN のしきい値・拡大率の遷移の後の解き直しの見送りの数え方を変えない。

### Requirement 3: 決定論テストで確かめる
**Objective:** As a 開発者, I want 窓の無い巡を数えないことと、本物の停滞は今日どおり知らせることを決定論テストで確かめること, so that 実機を待たずに直りと後退の無さを判定できる

#### Acceptance Criteria
1. When 窓を全部閉じた後に窓なしで初期配置の確定の処理を 600 回回した, the 決定論テスト shall WARN が 0 件で、見送りの数が 0（数の記録が無い）であることを判定する。
2. If 直す前のコード（窓が無い巡も数える）で 1 のテストを回した, the 決定論テスト shall 赤になる（WARN が出る、または数が 0 でない）。
3. While 窓の一式が在り見送りが続く（対照）, the 決定論テスト shall 599 回目までは WARN が 0 件で、600 回目でちょうど 1 件出ることを判定する。
4. When 窓を閉じて窓なしの巡を回した後に新しい窓の一式を開き、そこで見送りが続いた, the 決定論テスト shall 新しい一式の 600 回目でちょうど 1 件の WARN が出て、それより前には出ないことを判定する。
5. The 決定論テスト shall OS の窓・GPU・時刻に頼らず、何度回しても同じ結果を返す。

### Requirement 4: 実機で 1 回確かめる
**Objective:** As a 開発者, I want 観測された場面（emo2 の入れ直し）を実機で 1 回再現して WARN が 0 件であることを確かめること, so that 静的な見立てが実機でも当たっていると判定できる

#### Acceptance Criteria
1. When emo2 の起動中に `emo2.nar` を入れ直してゴーストを起こし直した, the areka shall 起こし直しの後に `deferrals=600` の WARN を 0 件にする。
2. The 実機の確かめ shall 判定の分岐の記録が見える level まで `RUST_LOG` を開けて行い、新しい窓の一式で初期配置が確定した記録と、窓が無いために数えなかった記録を読み取る。
3. The 実機の確かめ shall 実機の根・検体・一時フォルダをワークツリーの `target\` の下だけに置く。
4. If 直した後の実機の確かめで `deferrals=600` の WARN が出た, the 開発の進め方 shall そこで止めて原因を取り直し、直しを重ねない。
