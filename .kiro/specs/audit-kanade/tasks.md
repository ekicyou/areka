# 実装計画

> 束 T1〜T19（design.md「タスクの束と順」）を、そのままの番号と順で大タスク 1〜19 にした。指摘の番号 #n は `research.md` §3 の通し番号、直し方の正本は design.md「指摘ごとの直し方」の各行。
>
> **始める時期**: 実装は `placement-crate-split` の着地の後に、その新しい形（`areka_placement::…`・`log-capture-kit` へ移った `ExpectField`・`expect_one`）の上で始める（design.md「申し合わせ」）。着地を受けたら、まず `main` を取り込んでから 1 に入る。
>
> **どのタスクにも効く決まり**: 消す前にツリー全体（テスト・fixture・設定・文字列）を grep して使われていないことを確かめる。足して 1,000 行を越えそうなら新しい兄弟のファイルへ。新しい依存を足さず `Cargo.lock` を変えない。範囲の外は design.md「範囲の外で触るファイル」の表の中身だけ。完了の印は、そのタスクで触ったクレートのテストが緑で、直す前に通っていたテストが同じ結果で通ること。
