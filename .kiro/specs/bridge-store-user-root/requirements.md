# Requirements Document

## Project Description (Input)

**だれが困っているか**: Microsoft Store 版の Claude Desktop から areka をつなぐ利用者と、areka の開発者。

**今どうなっているか**: Claude Desktop が起こす中継（`areka-mcp-bridge.exe`）は、隣に `areka.exe` が在ると、areka 本体と同じ規則で areka の記憶の置き場を決め、その下（`…\profile\areka\mcp-bridge\`）に控えを置く（完了 `user-data-root` の要件 6.1）。ところが中継は置き場を「決める」だけでなく、areka 本体と同じ準備をそのまま行い、利用者ごとの置き場（`%LOCALAPPDATA%\areka`）のフォルダを作り、exe の隣の記憶をそこへ写しうる。Store 版の Claude Desktop が起こした中継の `%LOCALAPPDATA%` の下への書き込みは、Claude アプリのパッケージのフォルダ（`%LOCALAPPDATA%\Packages\Claude_…\LocalCache\Local\` の下）へ回される（完了 `mcp-stdio-bridge` の実測）。このため Store 版の利用者では、areka 本体が使う置き場とは別の、利用者から見えない置き場の写しが箱の中にできうる。説明書（`dist/README.txt`）は今の振る舞い（控えが箱の中へ回る）を書いているが、確定の文ではない。利用者ごとの置き場の形での中継は、実機でまだ測っていない。

**何を変えるか**: 中継は置き場を決めるだけにし、利用者ごとの置き場を作らず、exe の隣の記憶を写さない。控えの置き場は「箱の外の本当の置き場に届く」か「箱の中に置くことを決まりとして受け入れる」のどちらかに決めて固定し、説明書と記録でそう伝える。どちらでも、中継の起動の記録に、決めた置き場と「箱へ回されている」ことが分かる行を残す。最初に実機で測り、決めた形を決定論テストに固定し、直した後にもう一度実機で測る。

## Introduction

この仕様は、Claude Desktop が起こす中継が、控えの置き場を決めるときに areka の記憶の置き場を作ったり写したりしないようにし、Microsoft Store 版の Claude Desktop から起こされたときの控えの置き場を決めて、説明書と記録で利用者に伝えるものです。

この文書で使う言葉:

- **中継**: Claude Desktop が起こす `areka-mcp-bridge.exe`。
- **控え**: 中継が areka から受け取った答えを残しておくファイル（areka が居ないときにツールの一覧を並べるために使う）。
- **利用者ごとの置き場**: `%LOCALAPPDATA%\areka\`（`AREKA_USER_ROOT` で変えたときはそのフォルダ）。winget で入れたときなどに areka が使う。
- **exe の隣の記憶**: `areka.exe` の隣の `profile\areka\`。areka は利用者ごとの置き場を初めて使うときに、これを利用者ごとの置き場の `profile\areka\` へ写す。
- **箱**: Microsoft Store 版のアプリから起こされたプログラムが `%LOCALAPPDATA%` の下へ書く物を、OS が回すアプリごとのフォルダ（実測では `%LOCALAPPDATA%\Packages\` の中の `Claude_` で始まるフォルダの `LocalCache\Local\`。このフォルダの形は OS の文書では約束されておらず、文書は「アプリごとの専用の場所」とだけ言う）。

## Boundary Context

- **In scope**:
  - Store 版の Claude Desktop から起こした中継の実機の測り（直す前と直した後）。
  - 中継の控えの置き場の決め方の直し（置き場を作る・記憶を写す働きを中継から外す）。
  - `areka-user-data` に、置き場を作らず写さずに「決めるだけ」の口を 1 つ足すこと（中継が呼ぶ。今の口の答えと areka 本体の振る舞いは変えない。写しの条件と判断の記録の持ち主は `areka-user-data` の 1 つのまま）。
  - 箱の外の本当の置き場へ届く手があるかの調べと、どちらの形にするかの決まり。
  - 中継の起動の記録に残す、控えの置き場と箱の行。
  - `dist/README.txt` の中継の控えの段落の確定。
  - 決定論テスト。
- **Out of scope**:
  - areka 本体の置き場の決め方・作り方・写し方（完了 `user-data-root` の持ち物）。
  - 中継の MCP の中継の働きそのもの（候補の番号・待つ時間・控えの中身・組み込みの答え。完了 `mcp-stdio-bridge` の持ち物）。
  - 書けない場所の伝え方（完了 `write-failure-notice` の持ち物）。
  - Store 版でない Claude Desktop の振る舞い（今の形で正しい）。
  - arm64 の機械で同じことが起きるか（次のリリースへの申し送り）。
  - Claude Desktop の側の設定や配り方。
- **Adjacent expectations**:
  - 利用者ごとの置き場を使う形かどうか、置き場がどこかの答えは、areka 本体と中継で同じ規則のまま変えない（完了 `user-data-root`）。この仕様は「その答えを使って中継が何をするか」だけを変える。
  - 中継の隣に `areka.exe` が無い形（`%LOCALAPPDATA%\areka\mcp-bridge\` に控えを置く形）は、今の決め方のまま変えない（完了 `user-data-root` の要件 6.2）。Store 版ではこの形の控えも箱の中へ回るが、それは今の説明書のとおりの振る舞いとして残す。
  - `winget-release-automation` は `dist/README.txt` の別の段落を触る。この仕様は中継の控えの段落だけを変える。

## Requirements

### Requirement 1: 直す前と直した後の実機の測り

**Objective:** As a 開発者, I want Store 版の Claude Desktop が起こした中継が箱の中で何を作り・何を写し・控えをどこへ置くかを数で知ること, so that 推測でなく実測に基づいて控えの置き場を決められる

#### Acceptance Criteria

1. The 本仕様 shall 中継の直しより前に、winget で入れた形（利用者ごとの置き場を使う形）の `areka.exe` の隣の中継を Store 版の Claude Desktop から起こし、次の 4 点を測って spec の記録に残す: (a) 箱の中に areka の利用者ごとの置き場のフォルダや `profile` のフォルダが作られるか、(b) exe の隣の記憶が箱の中へ写されるか、(c) 控えが実際にどのフォルダに置かれるか、(d) 箱の中から、箱の外の本当の利用者ごとの置き場が在ると見えるか。
2. The 本仕様 shall 比べとして、同じ中継を PowerShell から起こした形を、1 と同じ 4 点で測って記録に残す。
3. When 中継の直しを終えた, the 本仕様 shall 1 と 2 と同じ測りをもう一度行い、要件 2 と要件 3 のとおりに動くことを記録に残す。
4. While 測っている, the 本仕様 shall 測りに使う検体（`areka.exe`・中継・winget の控えのファイル）と一時フォルダを、ワークツリーの `target\` の下だけに置く。箱の働き（1 の a〜d）は振り替えが `%LOCALAPPDATA%` の下でしか起きないため、利用者ごとの置き場を既定の `%LOCALAPPDATA%\areka` のままにして測る。PowerShell から起こす比べ（2）は、`AREKA_USER_ROOT` を `target\` の下へ向けて測り、箱の外の本当の `%LOCALAPPDATA%\areka` を作らない。
5. If 測りが開発者の本物の `%LOCALAPPDATA%\areka` か箱の中の物（前の中継や測りが残した `LocalCache\Local\areka\` など）に触れうる, then the 本仕様 shall 測る前にそれらを `target\` の下へ控え、測った後に元の形へ戻す（測りで新しくできた物は消し、控えた物を戻す）。
7. The 本仕様 shall Claude Desktop の設定の向け直しと起動し直しを開発者に頼む前に、このセッションの Bash の道具（その子のプロセスも同じ箱へ回される）から検体の中継を起こして下見をしてよい。下見の結果は本番の測り（1）の代わりにしない。
6. The 本仕様 shall Claude Desktop の設定を測りの中継へ向け直すこと・Claude Desktop を落とすこと・起動し直すことを開発者に頼み、自分では行わない。止めるプロセスは、自分で起こしたと確かめたものだけとする。

### Requirement 2: 中継は控えの置き場を決めるだけにする

**Objective:** As a Store 版の Claude Desktop から areka をつなぐ利用者, I want 中継が areka の記憶の置き場を作らず写さないこと, so that 利用者から見えない置き場の写しが箱の中にできない

#### Acceptance Criteria

1. The 中継 shall areka の記憶の置き場がどこに当たるかの答え（`AREKA_PROFILE_DIR`・利用者ごとの置き場を使う形かどうか・その場所・`AREKA_USER_ROOT`）を、今と同じ規則で決め、その答えを今から変えない。
2. The 中継 shall 利用者ごとの置き場のフォルダを作らない（Store 版の Claude Desktop から起こされたときも、そうでないときも、作る数は 0）。
3. The 中継 shall exe の隣の記憶をどこへも写さず、そこに areka が覚えたファイルを書き換えず、消さない（写す数・書き換える数・消す数は 0）。
4. While 中継の隣に `areka.exe` が在り、利用者ごとの置き場を使う形で、利用者ごとの置き場のフォルダが中継から見えない, the 中継 shall 控えを持たずに動き、areka がその置き場を作るのを待たない。
5. While 中継の隣に `areka.exe` が在り、利用者ごとの置き場を使う形で、利用者ごとの置き場は在るが exe の隣の記憶がまだそこへ写されていない（利用者ごとの置き場の `profile\areka\` が無く、exe の隣の `profile\areka\` が在る）, the 中継 shall 控えを持たずに動き、利用者ごとの置き場の `profile\areka\` を作らない（areka が次に起動したときの写しを妨げない）。
6. While 中継の隣に `areka.exe` が在り、利用者ごとの置き場を使う形で、4 と 5 のどちらにも当たらない, the 中継 shall 控えを利用者ごとの置き場の `profile\areka\mcp-bridge\` に置く。
7. While 中継の隣に `areka.exe` が在り、利用者ごとの置き場を使う形である（利用者ごとの置き場の場所を決められないときも含む）, the 中継 shall exe の隣の `profile\areka\` の下に控えを書かない。場所を決められないときは、控えを持たずに動く（要件 3.3）。
8. While 中継の隣に `areka.exe` が在り、利用者ごとの置き場を使う形でない（zip を展開して使う形）, the 中継 shall 今どおり exe の隣の `profile\areka\mcp-bridge\` に控えを置く。
9. Where `AREKA_PROFILE_DIR` が設定されている, the 中継 shall 4〜8 に関わらず、今どおりその下の `mcp-bridge\` に控えを置く。
10. While 中継の隣に `areka.exe` が無い, the 中継 shall 今どおりの決め方（`%LOCALAPPDATA%\areka\mcp-bridge\` など）で控えを置く。
11. The 中継 shall 控えの置き場を起動のときに 1 回だけ決め、起動している間には決め直さない。4 か 5 で控えを持たずに動いた後に areka が置き場を作るか記憶を写したときは、次に起こされたときから 6 の置き場に控えを置く。
12. While 控えを持たずに動いている, the 中継 shall areka につなげるときは今どおり中継し、areka が見つからないときは今どおり組み込みの答えで最初の問い合わせとツールの一覧に答える（控えの有無の外では、中継の答え方を変えない）。

### Requirement 3: 起動の記録に置き場と箱の行を残す

**Objective:** As a 開発者, I want 中継の起動の記録を読めば、控えをどこに置いたか（または置かなかったか）と、書き込みが箱へ回されているかが分かること, so that 記録の無いまま控えが外れる道が無い

#### Acceptance Criteria

1. When 中継が起動して控えの置き場を決めた, the 中継 shall 決めた控えの置き場を、起動の記録に残す（info）。
2. When 中継が要件 2.4 か 2.5 に当たって控えを持たずに動くと決めた, the 中継 shall 控えを持たずに動くことと、その理由（利用者ごとの置き場がまだ無い・exe の隣の記憶がまだ写されていない）と、決めた利用者ごとの置き場の場所を、起動の記録に残す（info）。
3. If 控えの置き場を決められない（利用者ごとの置き場を使う形だが、その場所を決められないときを含む）, then the 中継 shall 控えを持たずに動き、そのことを記録に残す（warn）。
4. If 控えを書けない, then the 中継 shall 今どおり控えを持たずに続け、書けなかった場所と理由を記録に残す（warn）。
5. While 中継が箱の中で動いている（Store 版の Claude Desktop から起こされた）, the 中継 shall `%LOCALAPPDATA%` の下への書き込みが箱へ回されることが分かる行を、起動の記録に 1 件残す。
6. Where 中継が箱の実際のフォルダの場所を知ることができる, the 中継 shall 5 の行にその場所も残す。
7. While 中継が箱の中で動いていないと分かった, the 中継 shall 5 の行を残さない（0 件）。
8. The 中継 shall この要件で足す記録の文を、今の中継の記録と同じく ASCII で書く。
9. If 中継が箱の中で動いているかを見分けられない（初めての起動で、尋ねる物がまだ無いときなど）, then the 中継 shall 見分けられないことを起動の記録に 1 件残す（info）。このとき 5 の行は残さない。

### Requirement 4: 箱の外へ届く手の調べと、控えの置き場の決まり

**Objective:** As a 開発者, I want Store 版から起こされた中継の控えを、箱の外の本当の置き場に置けるかを調べて決めること, so that 控えの置き場が測りと調べに基づいて 1 つに固定される

#### Acceptance Criteria

1. The 本仕様 shall Store 版の Claude Desktop から起こされた中継が、箱の外の本当の利用者ごとの置き場へ控えを書ける手があるかを調べ、調べた手とそれぞれの結論を spec の記録に残す。
2. The 本仕様 shall 箱の外へ届く手を採るのは、新しい外部依存を足さず、Claude Desktop の側の設定や配り方を変えず、OS が文書で約束していない振る舞いに頼らない手が見つかったときだけとする。
3. If 2 を満たす手が無い, then the 本仕様 shall Store 版の Claude Desktop から起こされた中継の控えが箱の中に置かれることを決まりとして受け入れ、要件 5 の説明書と要件 3 の記録でそう伝える。
4. The 本仕様 shall 箱の中・箱の外のどちらの形に決めても、要件 2.2 と要件 2.3 を守る（箱の中にも外にも、中継が利用者ごとの置き場を作る数・記憶を写す数は 0）。
5. The 本仕様 shall 子のプロセスを箱の外で起こす属性（`PROC_THREAD_ATTRIBUTE_DESKTOP_APP_POLICY`）で手伝いのプロセスを起こす手は、作りが重く文書から確かさが読み切れないため、測らず採らない。調べの結論は 1 の記録に残す。
6. The 本仕様 shall 利用者ごとの置き場を `AppData` の外へ向ける手（`AREKA_USER_ROOT`）を、控えを箱に入れないための手として説明書に足さない。

### Requirement 5: 説明書の中継の控えの段落を確定する

**Objective:** As a Store 版の Claude Desktop から areka をつなぐ利用者, I want 説明書を読めば中継の控えがどこに在るかが分かること, so that 控えを探す・消すときに迷わない

#### Acceptance Criteria

1. The 本仕様 shall `dist/README.txt` の中継の控えの段落を、要件 4 で決めた形と要件 1 の測りの結果に合う確定の文に改める。
2. The 説明書 shall 利用者ごとの置き場を使う形で、Store 版の Claude Desktop から起こした中継の控えが置かれる場所（箱の中か外か、例のパスを含む）を伝える。
3. The 説明書 shall 中継が控えを持たずに動く場面（areka をまだ一度も起動していない・exe の隣の記憶がまだ写されていない）と、控えができるようになる時（areka を起動した後、次に Claude Desktop が中継を起こしてつないだとき）を伝える。
4. The 説明書 shall 中継が利用者ごとの置き場を作らず、exe の隣の記憶を写さないことを伝える。
5. The 本仕様 shall `dist/README.txt` のうち、利用者ごとの置き場の形の一覧の「中継の控え」の行と、その下の中継の控えの段落（Store 版の箱へ回る話の段落）の 2 か所だけを変え、その外の行（zip の形の一覧の「中継の控え」の行を含む）を変えない。
6. The 説明書 shall 前の版（0.0.3）の中継が、Store 版の Claude Desktop から起こされたときに箱の中に作ったかもしれない利用者ごとの置き場の写し（`LocalCache\Local\areka\` の下）の場所と、それを消してよいことを、中継の控えの段落の中で伝える。

### Requirement 6: 今の形を守り、決めた形をテストに固定する

**Objective:** As a 開発者, I want この直しが areka 本体と中継の他の働きを変えず、決めた形が決定論テストで固定されること, so that 後の変更で控えの置き場が黙って崩れない

#### Acceptance Criteria

1. The 本仕様 shall areka 本体の置き場の決め方・作り方・exe の隣の記憶の写し方を変えない（areka 本体の振る舞いの差は 0）。
2. The 本仕様 shall 中継の MCP の中継の働き（候補の番号・待つ時間・控えの中身・組み込みの答え）を変えない。
3. The 本仕様 shall 新しい外部依存を足さない（0）。
4. The 本仕様 shall 要件 2 の各場面（利用者ごとの置き場がまだ無い・exe の隣の記憶がまだ写されていない・控えを利用者ごとの置き場に置ける・利用者ごとの置き場の場所を決められない・zip を展開して使う形・`AREKA_PROFILE_DIR` が在る・隣に `areka.exe` が無い）で決まる控えの置き場を、決定論テストで固定する。
5. The 本仕様 shall 要件 2.4 と 2.5 の場面で中継が準備を終えた後に、利用者ごとの置き場のフォルダ（2.5 では利用者ごとの置き場の `profile\areka\`）が作られていないことと、exe の隣の記憶が写されておらず中身が変わっていないことを、決定論テストで確かめる。
6. The 本仕様 shall 要件 3 の記録の行（置き場の行・控えを持たない理由の行・箱の中で動くときの行・見分けられないときの行と、箱の中で動いていないと分かったときに箱の行が 0 件であること）を、決定論テストで固定する。
7. The 本仕様 shall テストでは環境の値と OS の場所を注入して組み、プロセスの環境変数を書き換えず、組む根・記憶の置き場・控えの置き場をワークツリーの `target\` の下に置く。

## 討議で決めたこと（2026-10-29・全議題を推奨案で確定）

1. **控えの置き場は箱の中を受け入れる**（要件 4.3・4.5・4.6）: 文書で約束された止め方は Claude アプリのパッケージの宣言でしか選べない。子のプロセスを箱の外で起こす手は測らず採らない。`AREKA_USER_ROOT` を `AppData` の外へ向ける手は説明書に足さない。
2. **置き場がまだ無いとき・写しがまだのときは控え無し・info**（要件 2.4・2.5・2.11・3.2）: areka を待たない。置き場は起動のときに 1 回だけ決め、次に起こされたときから控えを置く。
3. **置き場の場所を決められないときは控え無し・warn**（要件 2.1・2.7・3.3）: 利用者ごとの置き場を使う形なら、exe の隣には一切書かない（例外を作らない）。
4. **箱の中か見分けられないときも記録に 1 件残す**（要件 3.7・3.9）: info。見分け方は設計で決める。箱の実際のフォルダの場所は、知ることができるなら記録に出す（要件 3.6）。
5. **`areka-user-data` に「決めるだけ」の口を 1 つ足す**（Boundary Context）: 写しの条件と判断の記録の持ち主を 1 つに保つ。同じウェーブ（C12）のほかの 7 本は `areka-user-data` に触れない（重なり 0）＝roadmap のウェーブ表の「`establish.rs` は読むだけ」の約束はこの spec の中で外す。
