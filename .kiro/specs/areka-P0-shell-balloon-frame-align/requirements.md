# Requirements Document

## Project Description (Input)

- **困っている人**:
  - **ゴーストの作者**: 箱のあるサーフェスへ切り替えたフレームに `Status` を受け取ると、`balloon(ID群)` から見えているはずのバルーンが 1 フレームだけ欠ける。そのフレームに届いた要求では、見えている箱を前提にした分岐が外れうる。
  - **利用者**: 箱の置き場所が違うサーフェスへ替えた瞬間に、新しい絵の上に前の置き場所の文字が 1 フレーム（約 8 ms）残ることがある。目には付かない（2026-10-04 の実機の確かめで 16 回中 2 回）。
  - **開発者**: 普通のバルーンを一度出して隠した後に箱だけに文字が出ると、警告の段の行が 1 度出る。設計どおり番号 0 で届いているが、箱を使う普通の使い方で警告の段の行が出るので、本物の警告に紛れる。
- **今の状況**: 文字の層が台本の `\s` を受け取るのは画面を描くフレームの外で、箱の置き場所に効くのは次のフレームである。絵の差し替えが先に届いたフレームでは、新しい絵の上に前の置き場所の文字が残る。同じあいだ、箱に文字が出ているかどうかの写しが外れているので、`Status` の `balloon(ID群)` が空を報告する。箱だけが見えているとき、番号は普通のバルーンの今の面の番号から取るが、普通のバルーンを隠した後は取れないので 0 で届け、警告を 1 度出す。
- **変えたいこと**: 箱の置き場所の付け替えが絵の差し替えと同じフレームに効き（1 フレームのずれを 0 にする。1 フレーム遅らせて揃える手当ては取らない）、箱が見え続けているあいだ `balloon(ID群)` から箱のスコープが 1 フレームも欠けず、箱だけが見えている普通の使い方で警告の段の行が出ないようにする。どれも、直す前に失敗する決定論的なテストで固定する。詳細は同じフォルダの `brief.md`（2026-10-04 起票・同日再測定）にある。

## Introduction

本 spec は、完了した `areka-P0-shell-balloon`（シェルの絵の中に台詞を書く「箱」）の実機の確かめで残った 3 つの気付きを直す、バグの spec である。3 つは同じ根から出ている。台本の `\s` を文字の層が受け取る時機と、箱の置き場所・箱の表示の写しが付け替わる時機が 1 フレームずれることである。

1. 箱の置き場所が違うサーフェスへ替えた瞬間に、新しい絵の上に前の置き場所の文字が 1 フレーム残ることがある。
2. そのあいだ、ゴーストへ届ける `Status` の `balloon(ID群)` から箱のスコープが 1 フレーム欠ける。
3. 普通のバルーンを一度出して隠した後に箱だけに文字が出ると、警告の段の行が 1 度出る。

本書で使う言葉は次のとおり。

- **箱**: surfaces.txt の element定義の描画メソッド `balloon`（`elementN,balloon,名前,X,Y`）でサーフェスの中に置かれた、`balloon.*`ブレスの定義による文字の場所 1 つ（完了 spec の定義のまま）。
- **普通のバルーン**: バルーン専用の窓に出る、今までのバルーン。
- **置き場所**: 箱がそのサーフェスの中で文字を出す位置（element定義の X,Y）。
- **フレーム**: 画面を 1 回描き直す単位。
- **絵**: サーフェスの画像として画面に表示されているもの。

正典との関係: ukadoc の `Status` [SSP拡張] は `balloon(ID群)` を「バルーンが表示状態。キャラクターID=バルーンID の形式で列挙される」と定める（`ukadoc:spec_shiori3` の `Status` の項）。箱のスコープをこの形で載せる規則は完了 spec の要件 5.5・5.6 で定まっており、本 spec はそれが画面の表示と食い違わずに届く時機だけを直す。

## Boundary Context

- **In scope**:
  - サーフェスを切り替えたとき、絵と箱の文字の置き場所（表示する位置・表示をやめること・保持していた文字を再び表示すること）が同じフレームで替わること。絵の差し替えが先に届く場合と、台本の `\s` の受け取りが先に届く場合の両方。
  - ゴーストへ届ける `Status` の `balloon(ID群)` に載るスコープを、そのフレームの箱と普通のバルーンの窓の表示に一致させること（普通のバルーンの窓と箱のあいだで表示が移る場合を含む）。
  - 箱だけが見えているときの `balloon(ID群)` の番号と、警告の段の行。
  - 直す前に失敗する決定論的なテスト。
- **Out of scope**:
  - 普通のバルーンの窓の置き場所、表示・非表示の時機、普通のバルーンだけが見えているときの `Status` の振る舞い（今のまま）。
  - サーフェスの絵を描き替える仕組みのスレッドの構成（今のまま）。
  - 箱の当たり判定（表示されている字の矩形でポインタを受けること）。当たり判定も画素と同じ時機の姿を使うので、画素の付け替えが同じフレームになれば一緒に揃うが、本 spec は当たり判定そのものの要件を足さない。
  - 箱を element定義の並び順どおりに画像のあいだへ挟んで描く重ね順（`balloon-element-order`）。
  - バルーンの面の番号の決め方そのもの（面の偶数・奇数で左右のバルーンを選ぶこと＝`balloon-canon-residue`）。
  - サーフェスの切替を伴わない、拡大率の変化や窓の移動への箱の追従（完了 spec の範囲で成立済み）。
- **Adjacent expectations**:
  - 箱のスコープを `balloon(ID群)` に載せるときの番号は、完了 spec `areka-P0-shell-balloon` の要件 5.5 の規則のまま（「キャラクターID=そのスコープの普通のバルーンの今の面の番号（切り替えていなければ 0）」）。普通のバルーンを隠した後に「今の面の番号」として何を持つかは設計で決め、`balloon-canon-residue` の面の番号の規則と揃える。`balloon-canon-residue` が普通のバルーンの面の番号の決め方を変えた場合、箱だけのときの番号もそれに従う。
  - 完了 spec の要件 6（サーフェスを切り替えたときの文字の行き先と保持の規則）は変えない。本 spec が変えるのは、その結果が画面と `Status` に出る時機だけである。

## Requirements

### Requirement 1: サーフェスの切替で、絵と箱の置き場所を同じフレームで替える

**Objective:** As a 利用者, I want サーフェスを替えたとき、新しい絵と箱の文字の置き場所が同じフレームで替わること, so that 新しい絵の上に前の置き場所の文字が残る瞬間も、前の絵の上に新しい置き場所の文字が出る瞬間も無い

#### Acceptance Criteria

1. When 台本の `\s` で箱の置き場所が違うサーフェスへ切り替える場合, the areka shall 新しいサーフェスの絵が初めて表示されるフレームで箱の文字を新しい置き場所に表示し、それより前のフレームでは前の置き場所に表示する（絵の差し替えが先に届いた場合も、台本の `\s` の受け取りが先に届いた場合も同じ）
2. When 箱を持つサーフェスから、今表示している箱と同じ名前の箱を持たないサーフェスへ切り替える場合, the areka shall 新しいサーフェスの絵が初めて表示されるフレームで、その箱の文字の表示をやめる（文字は完了 spec の要件 6.2・6.4 のとおり保持する）
3. When `\s[-1]` でサーフェスを非表示にする場合, the areka shall サーフェスの絵が消えるフレームで、箱の文字の表示をやめる
4. When 保持している箱の文字があり、その箱と同じ名前の箱を持つサーフェスへ切り替える場合, the areka shall 新しいサーフェスの絵が初めて表示されるフレームで、その文字を新しい置き場所に表示する
5. When 今表示している箱と同じ名前の箱が同じ置き場所にあるサーフェスへ切り替える場合, the areka shall 箱の文字を 1 フレームも途切れさせずに表示し続ける
6. If シェルに無い番号の `\s` が来て絵が替わらない場合, the areka shall 箱の文字を今の置き場所のまま表示し続ける（本 spec の前と同じ）
7. The areka shall 新しいサーフェスの絵が表示されるフレームを本 spec の前より後へ遅らせず、絵と箱の置き場所の一方を 1 フレーム遅らせて揃える形を取らない

### Requirement 2: 箱の表示と `Status` の `balloon(ID群)` を一致させる

**Objective:** As a ゴーストの作者, I want 箱が見えているあいだ、ゴーストへ届く `Status` の `balloon(ID群)` に必ずそのスコープが載っていること, so that 見えている箱を前提にした分岐が、切替の瞬間にも外れない

#### Acceptance Criteria

1. While あるスコープの箱に文字が表示され続けている場合（サーフェスの切替で箱の置き場所が替わるあいだを含む）, the areka shall そのあいだにゴーストへ送る要求の `Status` の `balloon(ID群)` から、そのスコープを 1 フレームも欠かさない
2. When 同じスコープの文字の表示が、普通のバルーンの窓から箱へ、または箱から普通のバルーンの窓へ移る場合, the areka shall どちらかが表示されているフレームでは、そのスコープを `balloon(ID群)` に載せ続ける
3. The areka shall 各フレームで `balloon(ID群)` に載せるスコープを、そのフレームで表示されている箱と普通のバルーンの窓に合わせ、表示から遅れて外すことも遅れて載せることもしない（箱の表示をやめ、普通のバルーンの窓も表示していないスコープは、そのフレームで外す＝完了 spec の要件 5.6 のまま）

### Requirement 3: 箱だけが見えているときの番号と警告

**Objective:** As a 開発者, I want 箱だけに文字が出る普通の使い方で警告の段の行が出ないこと, so that 本物の警告がそれに紛れない

#### Acceptance Criteria

1. While あるスコープで箱にだけ文字が表示されている場合（普通のバルーンを一度も表示していない場合も、表示して隠した後の場合も）, the areka shall そのスコープを完了 spec の要件 5.5 の規則による番号で `balloon(ID群)` に載せる
2. While あるスコープで箱にだけ文字が表示されている場合（普通のバルーンを一度も表示していない場合も、表示して隠した後の場合も）, the areka shall そのことを理由とする警告の段（WARN 以上）の行をログに残さない

### Requirement 4: 決定論的なテストで固定する

**Objective:** As a 開発者, I want 直した振る舞いを、直す前には失敗する決定論的なテストで固定すること, so that 同じずれが戻ったときにすぐ気付ける

#### Acceptance Criteria

1. The areka shall 要件 1.1 の振る舞いを、絵の差し替えが台本の `\s` の受け取りより先に届く並びと、後に届く並びの両方で確かめる決定論的なテストを持つ
2. The areka shall 要件 2.1・2.2 の振る舞いを、箱の置き場所が替わる切替と、普通のバルーンの窓と箱のあいだで表示が移る切替の両方で確かめる決定論的なテストを持つ
3. The areka shall 要件 3.1・3.2 の振る舞いを、普通のバルーンを一度表示して隠した後に箱にだけ文字が出る並びで確かめる決定論的なテストを持つ
4. When 本 spec の修正を入れる前のコードで要件 4.1〜4.3 のテストを走らせた場合, the 決定論的なテスト shall 要件 4.1〜4.3 のそれぞれについて、直す前のずれ（前の置き場所の文字が残る・前の絵の上に新しい置き場所の文字が出る・`balloon(ID群)` が 1 フレーム空になる・警告の段の行が出る）を再現する場面で失敗する
5. The areka shall 普通のバルーンだけを使う既存のテストを、期待値を変えずに通す
