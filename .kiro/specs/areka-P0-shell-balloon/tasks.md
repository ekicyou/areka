# Implementation Plan

> 用語: 「箱」＝ element定義の描画メソッド `balloon` で置かれたシェル内バルーンの文字の場所 1 つ。「普通のバルーン」＝バルーン専用の窓に出る今までのバルーン。「行き先」＝スコープの文字が今入る場所（普通のバルーンか、箱の 1 つ）。
>
> 共通の決まり: テストは実装と同じフォルダの兄弟ファイル（`<stem>_*_tests.rs`）に置き、本番ファイルには接続の宣言だけを残す。1 ファイル 1,000 行以下。ログの無い失敗の経路を作らない。常時のテストは x64 と偽の境界で回す。実機の確かめの根・検体・一時フォルダはワークツリーの `target\` の下だけに置く。
>
> `crates/areka-emo-text/src` にファイル（`*_tests.rs` を含む）を足すタスクは、同じタスクの中で `lib.rs` の `PURE_SOURCES` か `SOURCES_OUTSIDE_THE_PURE_SCAN` のどちらかへ登記する（見張りのテスト `every_source_file_is_either_scanned_or_explicitly_excluded` が赤になるため）。純粋な側へ足したときは `PURE_SOURCES.len()` の母数の定数も同じタスクで合わせる。
>
> 呼び出しの形の変更に合わせた書き換えと、新しい欄に偽（`false`）を入れるだけの書き換えは、「既存のテストの期待値を変えた」には数えない。

- [ ] 3.2 `balloon.*`ブレスを定義として読む

  - `font.follow` は書かなければスコープに従う種類、`scope`・`balloon` はその種類、それ以外の値は報告へ載せてスコープに従う種類として採る

- [ ] 3.3 箱の element定義をサーフェス番号ごとに配る

  - 番号ごとに、element番号の読み取り → 名前の解決（ブレスが無い・採られなかった）→ X・Y の整数の読み取り → 同じ名前の重複の整理（element番号が一番小さいものを採る）→ element番号の昇順の並べ替えを行い、捨てた element定義だけを報告へ載せて残りは採る
  - 画像の element の最大の element番号より小さい番号の箱は採ったうえで報告へ載せる（描画は常に画像より手前）
  - 兄弟の `boxes_tests.rs` で、element定義に関わる報告の種類を 1 つずつ起こし、`surface.append*`の存在の条件（先に書かれた追記・面の画像だけの番号・範囲と除外）を `fold.rs` のテストと同じ文面で突き合わせ、テストの中に持つ箱を含む文面を畳んで期待どおりの表になることを確かめる（検体は読まない）
  - 完了の姿: 箱を含む文面を畳むと、各サーフェス番号の置き場所の列が element番号の昇順で名前の重複なく返り、列の名前はすべて定義の表で引ける。画像の合成の道（`fold.rs` の画像の畳み込み）の既存のテストは期待値を変えずに通る
