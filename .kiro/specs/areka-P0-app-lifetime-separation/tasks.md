# Implementation Plan

> 段取りは design.md「呼び手 4 か所 > Implementation Notes」の ⑴ wintf → ⑵ areka → ⑶ `main` の `Explicit` 切替（最後の 1 行）→ ⑷ 確認 に従う。⑶ までは既定ポリシーのまま動くので、各タスクの終わりで `cargo test -p wintf`／`cargo test -p areka`（smoke テスト込み）が緑であることを確かめられる。
> 裁定 1〜3 を覆す必要が実装中に見つかったら、その場で止めて開発者へ議題を上げる（要件 6.4）。

- [x] 1. wintf: 終了の指示の受け口と構築時の選択口

- [x] 1.1 終了の指示を覚える受け口を作り、ループの待ちをそれに乗せ替える
  - 「指示済み」の 1 ビットと終了シグナルを 1 つにまとめた受け口を、ループの終了規律の隣に置く。1 回目の指示は info で記録して通知し、2 回目以降は debug で流すだけにする
  - ループの待ちを「待ち受けを立てる → 指示済みなら即完了 → 通知を待つ」の順に改め、実行関数の中の待ち（手順 4）と防御の通知（手順 5）も同じタスクで受け口へ向ける（このタスクの終わりで wintf がビルドできる状態を保つ）
  - アプリが持つ終了シグナルをこの受け口に置き換え、World へ NonSend として据える。既定の「最後の窓が閉じたら」の仕掛けも同じ指示の口を通す（終了の完了機構を 1 本にする）
  - 受け口の doc に「窓は閉じてから指示すること」の契約を書く
  - 既存の 3 本のテストを受け口の終了シグナルへ追随させ、構築直後のテストに「指示されていない」の状態の確認を 1 行足す
  - 決定論テスト 3 本を足す: UI タスクからの指示でループの待ちが終わる／ループ開始前の指示でも即座に終わる／2 回目の指示でも失敗せず終わる
  - 完了時: `cargo test -p wintf` が緑で、新しい 3 本はそれぞれ「確認の順を外す」「指示で待ちを完了させない」を入れると赤になる
  - _Requirements: 1.4, 1.5, 2.5, 2.6, 2.7, 4.4, 5.2, 5.3_

- [x] 1.2 構築時に「窓 0 で終了するか」を選べる口を足す
  - 2 値の選択（窓 0 で終了＝既定／明示の指示でだけ終了）と、それを受け取る構築関数を足す。引数なしの既存の構築関数はこの既定で委譲し、署名を変えない
  - 選択は構築時に消費し、フィールドに持たない（実行中に変える口を作らない）
  - 「明示の指示でだけ終了」のときは空遷移の仕掛けを差さず、受け口は両方の選択で World に据える
  - 決定論テスト 1 本を足す: 明示の選択で実窓を 1 枚開いて閉じ、実際の照合を回しても通知が来ず指示済みにもならず、続けて新しい窓を開ける
  - 完了時: 新しいテストが緑で、既定の選択で同じ構築をする既存テストも緑のまま（両方が緑で分岐が効いていると言える）。example は 1 本も書き換えていない
  - _Requirements: 1.1, 2.1, 2.2, 2.3, 2.4, 2.8, 4.1, 5.1, 6.1_

- [x] 1.3 指示で戻るとき、残っている窓を壊してから戻る
  - ループの待ちが終わった直後に窓の登録表を World から取り出して破棄し、残っていた窓を壊す。残っていたときだけ info を 1 行残す
  - 実行関数の doc に「指示で戻るときは残った窓を壊してから戻る・戻った後は再入できない」を書く
  - テストは足さない（契約の明文化であり判断分岐ではない）
  - 完了時: `cargo test -p wintf` と `cargo test -p areka`（smoke テスト込み）が緑
  - _Requirements: 1.2, 1.3_

- [x] 2. (P) wintf: OS の閉鎖要求を窓ごとの関数へ渡す部品
  - 窓に差せる「閉鎖要求が来たら呼ぶ関数」の部品を足す（ドラッグ終了の部品と同型・バブリングしない最小の署名）
  - `WM_CLOSE` の生存窓の扱いを「部品があれば info を 1 行残して関数を呼び、窓は消さない／無ければ従来どおり消す」に分ける。破棄済み窓の打ち切りと戻り値は変えない
  - `WM_CLOSE` の処理を持つファイルに `#[path]` で兄弟テストファイルを結線する（同じディレクトリの窓位置の処理と同じ形）
  - 兄弟ファイルに決定論テスト 1 本を足す: 部品付きと部品なしの 2 窓へ閉鎖要求を送り、付けた方は生きたまま関数が 1 回呼ばれ、付けない方は消え、戻り値は両方同じ
  - 完了時: `cargo test -p wintf` が緑で、分岐を外すと新しいテストが赤になる
  - _Requirements: 2.9, 2.10, 2.11, 3.12, 5.3_
  - _Boundary: wintf ecs（window components・window_proc lifecycle）_

- [x] 3. areka: 全窓破棄と終了の指示を 1 操作にする

- [x] 3.1 終了の統合操作と出所の語彙を新モジュールに作る
  - 出所の語彙（終了系列の完了・強制退避・ダミー窓・smoke・OS の閉鎖要求）と、「全窓（ダミー窓＋ゴースト窓）を閉じてから指示する」統合操作を 1 モジュールに置く。全窓破棄の部品は私有にする
  - 統合操作は閉じた数が 0 でも指示し、出所と閉じた数を info で記録する。受け口が World に無いときは error を残して戻る
  - 全窓破棄の部品の判断は smoke 用の既存関数と同じ（連鎖破棄済みの標的は debug で打ち切り残りを処理し切る）。打ち切り行の相名は `[quit_app]` にする
  - `main.rs` に新モジュールを宣言し、新モジュールから `#[path]` で兄弟テストファイルを結線する
  - この時点では統合操作の呼び手が 0 で、OS の閉鎖要求の出所も未使用（呼び手は 3.2〜3.4 で付く）。一時的な未使用の警告は想定内
  - smoke 用の既存関数のテスト 3 本を新モジュールの兄弟テストファイルへ移し、対象を私有部品へ、打ち切り行の主張を `[quit_app]` へ追随させる（判断は変えない）
  - 完了時: `cargo test -p areka` が緑で、移した 3 本が新しい置き場で通り、元の置き場からは消えている
  - _Requirements: 3.6, 3.7, 4.4, 6.2_
  - _Depends: 1.1_

- [x] 3.2 終了系列の完了と強制退避を統合操作へ乗せ替える
  - 終了系列の完了通知の受け手と強制退避の腕を、それぞれ統合操作の 1 行呼びにする。既存の `ghost_quit`／`ghost_quit_no_windows`／`mouse_escape_close` の記録は据え置く
  - ゴースト窓だけを閉じる既存関数を削除し、呼び手が 0 であることを確かめる
  - 既存テストの World に受け口を挿し、終了系列の完了（通知 1 件・窓 0）と強制退避のテストに「指示済みになっている」の確認を 1 行ずつ足す
  - 受け手・強制退避の腕・配置モジュールの doc にある「窓 0 → `run()` 復帰」の記述を「統合操作 → `run()` 復帰」へ追随させる
  - 完了時: `cargo test -p areka` が緑で、ゴースト窓だけを閉じる関数がクレート内に存在しない
  - _Requirements: 3.1, 3.2, 3.3, 4.4_

- [x] 3.3 ダミー窓と smoke の自動終了を統合操作へ乗せ替える
  - ダミー窓のダブルクリックの受け手と smoke の自動終了のクロージャを、それぞれ統合操作の 1 行呼びにする。既存の info は据え置く
  - smoke 用の全窓破棄関数を削除する
  - ダミー窓ダブルクリックのテストに受け口を挿し、「指示済みになっている」の確認を 1 行足す
  - ダミー窓の受け手の doc と、`spawn_cleanup_tests.rs` の doc 1 行を追随させる
  - 完了時: `cargo test -p areka`（smoke テスト込み）が緑で、smoke 用の全窓破棄関数がクレート内に存在せず、`main.rs` の行数が変更前（958 行）より少ない
  - _Requirements: 3.4, 3.5, 4.4, 4.5_

- [x] 3.4 OS の閉鎖要求を areka の終了系列へ結線する
  - ゴースト窓の受け手: 窓のキャラ／バルーンの印からスコープを読み、メニューの「終了」と同じ終了要求を kanade へ 1 件送る。窓は消さない。送り口が無ければ warn を残して戻り、印が無ければ warn で戻る。受けたことは info で記録する
  - ダミー窓の受け手: info を残して統合操作（出所＝OS の閉鎖要求）を呼ぶ
  - HWND が付いた瞬間のゴースト窓へゴースト窓の受け手を差す system を作り、`main.rs` の起動窓の結線（準備成功の腕）でクリック透過の登録と同じ確定段に登録する。ダミー窓は生成時の bundle に受け手を直接差す
  - 決定論テスト 1 本を新モジュールの兄弟テストファイルに足す（送り口は `pub(crate)` の構築関数でテスト内に直接組む。入力イベントのテストの私有ヘルパは流用できない）: 送り口付きの World でスコープ 1 のキャラ窓へ受け手を呼ぶと、スコープ 1 の終了要求が 1 件届き窓は生きている。対照として送り口の無い World では送信 0 件で panic しない
  - 完了時: `cargo test -p areka` が緑で、新しいテストはスコープを落とすか窓を消すと赤になる。`main.rs` の行数が 3.3 の後も変更前（958 行）より少ないまま
  - _Requirements: 3.9, 3.10, 3.11, 3.12, 5.3, 6.3_
  - _Depends: 2, 3.1_

- [ ] 4. areka を「明示の指示でだけ終了」へ切り替え、変えない範囲を確かめる
  - `main` のアプリ構築を「明示の指示でだけ終了」の選択に切り替える（段取りの最後の 1 行）。実行呼び出し直前のコメントを「終了の指示で戻る」へ、smoke テストのモジュール doc 1 行を追随させる
  - 後始末①〜④の順序と終了コードは変えない
  - `cargo test -p wintf` と `cargo test -p areka`（smoke テスト 2 本を含む）を通す
  - 変えない範囲を差分で確かめる: example 14 本・kanade の終了の握手（`schedule/close.rs`・`user_break.rs`）とそのテスト・ゴースト実行環境の終了統括・登録表の空遷移の検知に差分が 0
  - 完了時: 両 crate のテストが緑、`main.rs` が 1,000 行未満、上記の変えない範囲の `git diff` が空（pathspec が実在することを確かめたうえで）
  - _Requirements: 1.1, 1.2, 3.8, 4.1, 4.2, 4.3, 4.4, 4.5, 5.4, 6.4_
  - _Depends: 1.3, 3.3, 3.4_

- [ ] 5. 実機で終了操作の見え方を確かめる
  - `RUST_LOG=info,wintf::runtime=debug`・引数は絶対パス・`Start-Process -PassThru` で起動し、その PID だけを見る（他のプロセスは止めない）
  - 走行 1（smoke の自動終了）: `origin=Smoke` の記録 → 指示の記録 → 後始末の記録の順に出て、プロセスが終了コード 0 で終わり、`app_exit_unwired` が 0 行
  - 走行 2（メニューの「終了」）: 別れの台詞の後に `origin=KanadeStopped(Quit)` → 指示の記録が出て、プロセスが終わる
  - 走行 3（キャラ窓への Alt＋F4）: 閉鎖要求の記録（wintf と areka）→ 別れの台詞（その間は窓が消えない）→ `origin=KanadeStopped(Quit)` → プロセスが終わる。可能なら PID を確かめた上で `taskkill`（`/F` なし）も同じ流れで終わる
  - 走行 4（任意・強制退避）: `origin=Escape` → 指示の記録 → プロセスが終わる
  - 完了時: 各走行でプロセスが残っていないことを `HasExited` で確かめ、期待した記録の行をログから引用できる
  - _Requirements: 5.5, 5.6_

## Implementation Notes

- 1.1: 実行器は投入済みタスクを `block_on` の future より先に回す。「待ちの後に指示が届く」経路を踏ませるテストは、待ちが立った印を見るまで譲ってから指示する形にする。新しいループのテストには 5 秒の見張り（`WM_QUIT` で `block_on` を panic させる）を付け、壊れたとき止まらず赤にする
- 2: `OnCloseRequest` の公開パスは `wintf::ecs::window::OnCloseRequest`（`lib.rs` は `ecs` を再公開しない）。design の記述を訂正済み
- 3.2: `quit_app` を通る経路を回すテスト World には `wintf::AppExit::new()` を `insert_non_send` で据える（無いと `app_exit_unwired` の error が出るが、ログを見ないテストは緑のまま通ってしまう）。`spine.rs` の `make_world_with_gpu` にも据えた
