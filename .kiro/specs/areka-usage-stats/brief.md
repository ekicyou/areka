# Brief: areka-usage-stats

## Problem

- **素材の作者**: 自分のゴースト・シェル・バルーンが使われているかを知る手立てが無い。
- **開発者**（2026-10-28 `/kiro-discovery`・U4「areka の利用統計連携」）: 「areka に、利用統計の発信連携を追加したい。発信そのものは別リポジトリのコンソールアプリ（U2）に任せ、areka は CLI で呼ぶだけにする。nostr の依存は areka 本体に入れない」。要件は「ユーザーを秘匿しつつ、ユーザーごとに識別して、1 日単位で利用状況を集計し、結果を GitHub Pages で集計サイトとして公開したい」。段は「利用集計は play とは独立して進められるので、dola が終わったタイミングでノベルゲームと並走するかもしれません」。
- 原文（U1〜U4）と決めたこと、実装のときの候補（A〜G）は `doc/ideas/usage-stats.md`。

## Current State

起票のときの実測（main `d6054e4d`）:

- 利用統計を外へ送る仕組みは、brief・steering・コードのどこにも無い（統計・telemetry・nostr・opt-in で引いて 0 件・性能の測定や開発用の opt-in は別物）。
- 近いもの: 正典のプロパティ `rateofuselist.*`（手元に残る使用率）を `property-catalog-lists` に登記だけしてある。網羅台帳の `OnNostr` は `not-applicable`。
- 発信器（U2）・仕様（U1）・集計サイト（U3）は、まだどこにも無い（外の新しいリポジトリで起こす）。
- 設定画面は windows-reactor 待ち（`roadmap.md` の版の段）。初回の起動で尋ねる画面を持つ spec は無い。メッセージボックスは使わない決まり（失敗は既定のゴーストの台詞で伝える）。
- 素材 ID は `ghost-material-metadata`（ノベルゲーム基盤の段）が作る。

## Desired Outcome

- 利用者が明示的に同意したときだけ、areka が「使った」素材の ID を 1 日 1 回まとめて発信器（U2 の CLI）へ渡す。既定は無効。
- 同意の正は発信器の側の設定で、areka の表示と食い違わない。
- 発信器が入っていない・失敗したときも、areka の動きは何も変わらず、黙って飛ばす（記録は残す）。
- ローカルパス・個人の名前・PC 固有の識別子は、渡す中身にも記録にも出ない。
- 説明の文は正確に書く。「匿名」の一語では済ませない（誰が送ったかは分からないが、接続元の IP は中継の運営者に見える、など。正確な文は U1 の方式で決まる）。
- 最初はゴースト・シェル・バルーンだけを送り、演劇の信号（再生の開始・場面への到達・再生の完了）は演劇のパッケージの spec が着地してから足す（U1 の「部分対応を許す」と同じ考え）。

## Approach

- areka は CLI を呼ぶだけ。nostr・暗号・鍵の依存は areka 本体に入れない。呼び方（引数か標準入力の JSON か・終了コードと標準出力の決まり）は U2 を作るときに決め、この spec はそれに従う。
- 「使った」の判定は、一定時間以上の利用を条件にする（演劇は再生の完了や場面への到達など・後の段）。
- 同意を尋ねる形は、設定画面（windows-reactor 待ち）を待たずに、既定のゴーストの台詞と選択肢で尋ねる形を第一の候補にする（メッセージボックスを使わない決まり）。設定画面ができたら、同じ同意を画面からも変えられるようにする。
- 鍵のリセット・運用モードの切り替え・送る中身の下見・送るのを止めることは、発信器の CLI の命令として呼ぶ。

## Scope

- **In**: 同意の取り方（既定は無効）と、発信器の設定との食い違いの防ぎ方・「使った」の判定・素材 ID で集めて 1 日 1 回まとめる・上限の件数・発信器を呼ぶ・失敗を黙って飛ばす（記録は残す）・渡す中身と記録の禁止事項・説明の文・下見と停止とリセットの入口・決定論のテスト（発信器が無い・失敗・同意なしで何も渡らない）。
- **Out**: 発信器そのもの（U2）・イベントの仕様と登記簿（U1）・集計とサイト（U3）・設定画面の作り（windows-reactor）・演劇の信号（演劇のパッケージの後）・任意の検討の「使ってます」の共有ボタン（要件の段で入れるか決める）。

## Boundary Candidates

- 利用の記録（どの素材をどれだけ使ったか・areka の中の控え）。
- 同意の状態の読み取りと表示（発信器の CLI に問う）。
- 発信器を呼ぶ所（UI スレッドの外・失敗を飲み込んで記録する）。

## Out of Boundary

- 鍵・暗号・中継との通信（U2）。
- 集計の規則と不正対策（U3）。

## Upstream / Downstream

- **Upstream**: `ghost-material-metadata`（素材 ID）・外の U1（仕様）と U2（CLI）・演劇の信号を足す段では演劇のパッケージ（受け口の節）。
- **Downstream**: 外の U3（集計サイト）。

## Existing Spec Touchpoints

- **Extends**: なし。
- **Adjacent**: `property-catalog-lists`（`rateofuselist.*`＝手元の使用率）・windows-reactor 待ちの「設定画面と設定ファイル」（予約）。

## Constraints

- 区分 A（開発者が起票）・版は「利用統計（ノベルゲーム基盤と並走してよい・dola の整備の後）」の段（2026-10-28 議題 1・9）。待つ spec は `ghost-material-metadata` と外の U2。
- 規模の見立て: M（10〜14 タスク）。Opus。
- 外のリポジトリ（U1〜U3）が無いあいだは着手できない。リポジトリを作ったら、`doc/ideas/usage-stats.md` を持ってそちらで `/kiro-discovery` を回す。
- 失敗の経路は記録を残す（ただし記録にも鍵・素材の一覧・ローカルパスを出さない）。
