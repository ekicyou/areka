# Requirements Document

## Project Description (Input)

演出指令（キュー）の逐次配送・消費メカニズムを ECS 上に確立する汎用基盤仕様。

### 背景

バルーンへのテキストコマンド、キャラクターへの演技指令、SE再生指示など、複数の消費者が「任意のタイミングで、特定のエンティティに、演出指令を逐次投入する」という共通パターンを必要とする。この横断的関心事を個別仕様（balloon03-content, animation-system 等）で再発明するのではなく、汎用的なキュー配送メカニズムとして確立する。

### 先行議論コンテキスト（balloon01-core v2.0 レビューより引継ぎ）

#### 問題の発端

balloon01-core の要件レビュー中、バルーンウィジェットが受け取るべき情報として以下が未整理であると判明：

| 情報カテゴリ         | 具体的な内容                             | 状態                                              |
| -------------------- | ---------------------------------------- | ------------------------------------------------- |
| フレーム外観         | 背景・枠線・角丸・しっぽ角度・パディング | ✅ BalloonSkinDef で定義済み                       |
| コンテンツ静的設定   | テキスト方向、感情値→スタイルマップ      | 🔄 balloon01-core v3.0 で対応予定                  |
| コンテンツ動的データ | テキストコマンド、再生速度、再生開始時刻 | ❌ 配送メカニズム未定義                            |
| アニメーション定義   | dola Document、ストーリーボード参照      | 🔄 dola はバルーン内部サブシステムとしても利用可能 |

#### 検討済みの配送方式

| 方式                       | 仕組み                                              | 評価                                   |
| -------------------------- | --------------------------------------------------- | -------------------------------------- |
| A: コンポーネント差し替え  | `BalloonTalk::new(commands)` で丸ごと insert        | Typewriter踏襲。「追加」が不自然       |
| B: 子エンティティ追加      | `ContentCommand` entity を `ChildOf` で spawn       | ECS的に自然。順序保証の設計が必要      |
| C: Messages\<T\>           | bevy_ecs メッセージキュー経由                       | 既存パターン(Drag系)。送り先特定が課題 |
| D: VecDeque コンポーネント | ルートに `CommandQueue(VecDeque)` を付与、直接 push | 明白。Changed 検出が Mut\<T\> 必須     |

#### 設計上の決定事項

- **バルーンはファサードパターン**: 外部入力はすべてルートエンティティのコンポーネントで受け取る
- **dola はバルーン内部サブシステムとしても利用可能**: タイミング計算、グリフ表示制御に dola を直接使える
- **テキスト方向はバルーンの静的属性**: 1バルーン内で混在しない。変更時はコンテンツ全削除
- **フォント・文字サイズは感情値ベース**: キーバリュー形式で感情値（文字列）→スタイル設定のマップ + デフォルト値

#### 横断的関心事の認識

コンテンツコマンド配送はバルーン固有ではなく、キャラクター演技指令にも同一インターフェースが必要。個別実装ではなく汎用基盤として確立すべき。

### スコープ

**含まれるもの:**
- ECS 上での演出指令（キュー）の逐次配送メカニズム
- 汎用的なコマンドキューコンポーネント設計（バルーン・キャラクター・演出要素で共用）
- コマンドの順序保証・バッチ消費パターン
- 型安全なコマンド定義の拡張ポイント（消費者ごとのコマンド型）
- dola との統合インターフェース（タイミング制御、再生開始時刻決定）

**含まれないもの:**
- バルーンのテキスト描画実装（balloon03-content の責務）
- キャラクターアニメーション実装（animation-system の責務）
- dola ランタイム自体の実装（dola クレートの責務）
- フレーム外観定義（balloon01-core の BalloonSkinDef の責務）

### 消費者（本仕様の利用者となる仕様群）

| 消費者            | コマンド例                                   |
| ----------------- | -------------------------------------------- |
| balloon03-content | テキスト表示、Wait、スタイル変更、感情値切替 |
| animation-system  | サーフェス切替、トランジション、ポーズ変更   |
| 将来の演出要素    | SE再生、画面効果、ウィンドウ演出             |

### 設計判断ノート（伺か非準拠）

本仕様は伺かの「さくらスクリプト」に相当する演出再生系を扱うが、さくらスクリプトの設計には意図的に寄せない。特に：
- さくらスクリプトのタグベース逐次解釈モデルは採用しない
- コマンドは構造化された型として定義し、文字列パースに依存しない
- ECS のデータ駆動パターンに沿った設計とする
