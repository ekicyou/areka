- [x] 5.1 作業領域源を実行時に同期する

  - 差し替えは拡大率の相より前（同一フレーム内で相が新しい源を読む）に置く
  - モニタ 0 台・帰属不能は警告の上で現状維持とする
  - 起動時も同じ構築関数で 2 つの源を挿入し、「セッション内固定」の注記を撤回する
  - 保存位置の復元経路には効かせない
  - モニタ別拡大率表の注入口をテスト土台へ足す（表を新設する本タスクが持つ）
  - 接地点差を測る対テストを先に書き、是正前の赤（差 −48px）を実行で記録してから是正を入れる
  - 観察可能な完了条件: 拡大率を下げた遷移でキャラ窓が 1 回の書込のまま新しい作業領域下端へ接地し（差 0）、モニタ表に変化のないフレームでは源を作り直さない

  - _Depends: 2.4_

- [x] 5.2 作業領域の変化を契機に現寸で再スナップする
  - 拡大率が変わらず作業領域だけ変わった窓を、現在の寸のまま新しい下端へ再射影する経路を設ける
  - 置き場は拡大率の相の後とし、相が既に書き終えた窓は同値のため書込を出さない
  - 変化が無ければ再射影そのものを行わない
  - 再射影した窓の随伴バルーンを同一フレームで窓相対の位置へ移す（追従オフセットは補正しない）
  - 観察可能な完了条件: 作業領域だけが変わったときに下端吸着のキャラ窓が 1 回だけ書き直され、その随伴バルーンが同一フレームで追随し、変化の無いフレームでは窓書込が 1 件も出ない
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 4.7_
  - _Depends: 5.1_

- [x] 5.3 (P) 同一窓のジオメトリ指令を合流させる
  - 同一 tick・同一窓の位置指令と寸指令を先着の枠へ畳み、各項目は後勝ち、移動なし／寸なしの札は双方が持つときだけ残す
  - Z のみの指令と表示状態を変える指令は合流の対象にも先にもしない
  - 合流結果を積み上げの記録に残す
  - 窓ごとの書込回数を測る対テストを先に書き、是正前の赤（バルーン窓 2 回）を実行で記録してから是正を入れる
  - 観察可能な完了条件: バルーン窓の書込が 2 回から 1 回になり、Z 指令の相対順と最終ジオメトリは合流前と一致する

  - _Boundary: 窓書込コマンド_
  - _Depends: 2.1_

- [x] 5.4 拡大率と表の整合待ちを設ける
  - 窓の拡大率と帰属モニタの表の値が揃うまで、その窓への窓書込を見送る（拡大率の相・報告寸の突合・再スナップの 3 点すべて）
  - 描画そのものは止めない
  - 帰属の判定は表示基盤側の再導出が使う純関数と同一の規則を共有する。当該関数は現在クレート内限定の可視性なので、共有するにはクレート外へ開く変更を伴う（開かない裁定を採る場合は同規則の述語を配置側に置き、両者が同一判定を返す対比テストを付ける。この裁定を採ったときは設計の触ったファイル一覧の該当行も書き換える——ファイル集合の差分では検出できないため）
  - 拡大率通知が先に届く順序の対テストを先に書き、是正前の赤（旧下端での書込を含む 2 段書込）を実行で記録してから是正を入れる
  - 上限フレームを超えたら警告の上で現在の源で進める
  - 待ち札のある窓へ窓書込が到達しないことを単一の窓書込口で監視する
  - 観察可能な完了条件: 拡大率通知が表更新より先に届く順序でも、旧下端の中間矩形を出さずに 1 回の書込で新寸・新下端へ移る

  - _Boundary: 整合ゲート, モニタ帰属判定（表示基盤側）_

- [x] 5.5 システム由来の再アンカーで既定位置を追随させる

  - 明示操作では追随させず、既定位置なし（保存位置の復元）はそのままにする
  - 既定位置の意味が「起動時の既定」から「システム由来の再アンカーで追随する既定」へ変わることを、既定位置を読む側の記述へ反映する（起動時確定の除外規則の意味は変えない）
  - 観察可能な完了条件: 拡大率の再射影のあとでも連鎖の対象判定が「明示的に動かされた」へ倒れず、ドラッグ後の窓は対象から外れたまま

  - 武装時に停滞の計数と一度きりの報告札を初期化する
  - 明示的に再配置されたスコープは対象から外す
  - 見送り理由を記録し、有界を超えたら一度だけ警告する
  - 隣接を測る対テストを先に書き、是正前の赤（幅が半分になった側の左端差が残る）を実行で記録してから是正を入れる
  - 観察可能な完了条件: 決定論テストで幅が変わる遷移のあとも隣接ペアの隙間が 0 になり（実機の 359px に対応する決定論版）、会話中の表情差替では 1 度も解き直しが起きない

  - _Depends: 5.4, 5.5_

## Implementation Notes

- **窓種別のフィールド名は `win_kind=`（`kind=` ではない）** — task 1.1 のレビューで確定。`tools/perf/judge-perf.py:562,588-596` の `parse_fields` は同名キーを後勝ちで上書きするため、接頭語の `kind=<レコード種別>` と衝突してレコード種別が消え、判定器の起点判定（`kind=monitor`）が壊れる。設計の Data Models 表（`write`／`enqueue`／`hold` の行）と C7 の `writes_per_window` は追随済み。**1 行に同じフィールド名を 2 度出さない**が語彙の不変条件であり、`transition_diag_tests.rs::no_line_repeats_a_field_name` が固定している。task 2.1・2.4・3.1 はこの語彙に従うこと。
- **`FlushRecord.total_us` は `Option<u64>`** — task 1.1 のレビューで確定。`stage=begin` では総所要が未確定であり、`0` を出すと「0µs で完了」と「未計測」が同一文字列になって番兵規則（欠損は `-`）と矛盾する。設計の C1 Service Interface は追随済み。
- **観測レコードの定数はすべて `crates/wintf/src/ecs/window/transition_diag.rs` が単一の定義元** — `kind`／`stage`／`msg` 語と全フィールド名の `pub const`、および `KIND_ALL`／`STAGE_ALL`／`MSG_ALL`／per-kind の必須フィールド列（`MONITOR_FIELDS` 等）。判定器（task 3.1/3.2）はこれらを参照し、文字列リテラルを二重定義しない。
- **ログ濾過テストはスレッド局所の subscriber で書く** — `crate::ecs::test_support::capture_under_filter`（`crates/wintf/src/ecs/test_support.rs:96`・既存）が `tracing::subscriber::with_default` を使う。大域 subscriber を使うとテスト間で状態が汚染される（要件 7.7）。また「既定で無音」を主張するテストには同じ捕捉窓の内側に必ず出るはずの対照行を置き、捕捉が死んでいるだけで緑になる形にしない。
- **`cargo fmt -p wintf -- <パス>` はパス列を無視してクレート全体を整形する** — task 1.2 で 75 本の無関係ファイルが書き換わった。個別ファイルの整形は `rustfmt --edition 2024 --style-edition 2024 <パス>` を使うこと。整形の巻き添えが差分に混ざっていないか、報告前に必ず `git status` で確認する。なお本ブランチでは `crates/wintf/examples/*.rs` と `world/mod.rs` の `tick_order_tests` 内 2 行が既に rustfmt 未整形であり、これらは触らない。
