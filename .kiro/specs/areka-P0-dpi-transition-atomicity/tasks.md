# 実装計画

> **要件 1（1.1–1.7）は要件フェーズで実施済み**（正本 `reobservation-2026-08-15.md`・判定＝残存）。ただし第 1 段は既存の観測点だけで採った**時刻近似**であり、フレーム番号による確定は観測基盤の着地後の再採取（task 4.2）で置き換える。
> **要件 6.4・9.2 は分岐非該当**: 6.4 は「連鎖を解き直さない」を採ったときの義務だが設計は解き直す（D8）を採用、9.2 は縮退分岐の義務だが判定は残存。いずれも意図的に対応タスクを作らない。
> **要件 9.1** の判定（残存）は要件フェーズで確定済みで、task 4.2 がフレーム番号つきで再確認する。

- [ ] 1. 観測の土台（刻印とレコード語彙）
- [ ] 1.1 遷移観測チャネルの語彙とレコード純関数を新設する
  - 専用の観測 target 定数、全レコード共通の刻印（フレーム番号・tick 開始からの経過）、レコード種別語（モニタ表更新／窓書込／一括書込の開始終了／メッセージ受理／指令の積み上げ）を 1 箇所に定義する
  - 各レコード行を組む純関数を置く（刻印は値で受け取り、関数自身は時刻を読まない）
  - 欠損フィールドは番兵で埋め、フィールドを落とさない
  - 語彙の正例（逐語一致）と負例（種別語・フィールド名を壊した入力）の決定論テストを付ける
  - 既定のログ設定では 1 行も出ず、専用 target を指定したときだけ出ることを実際の濾過で確かめる
  - 観察可能な完了条件: 5 種のレコード行が固定文字列として再現でき、既定設定で無音・専用指定で発行されることがテストで示される
  - _Requirements: 2.5, 2.6, 2.7_

- [ ] 1.2 フレーム刻印の権威を配管する
  - フレーム計数の増分点で tick 開始時刻も資源として更新し、同じ値をスレッド局所の写しへ配る
  - World を持つ観測点は資源から刻印を組み、World を持たない点（一括書込・ウィンドウメッセージ処理）だけが写しを読む取り決めを実装する
  - テスト冒頭で写しと時刻基準を初期化できる口を用意する
  - World 資源から刻印を組むテスト専用の相を既定の多スレッド実行のまま回し、そこで組まれた刻印がフレーム計数と一致することを検証する（実際のモニタ表更新点での確認は task 2.2 が行う）
  - 観察可能な完了条件: 同一 tick 内で資源から組んだ刻印と写しから組んだ刻印が同じフレーム番号になり、多スレッド実行でも資源側がずれない
  - _Requirements: 2.4, 7.6, 7.7_

- [ ] 2. 観測点の設置（3 クレート）
- [ ] 2.1 (P) 窓書込の実施を記録する
  - 窓書込指令に要求元の語彙（経路語・スコープ・窓種別）を運ぶ札を持たせる。既存の生成引数は変えない
  - 一括書込の開始・各書込・終了を記録し、各書込の所要と成否を載せる。観測が有効なときだけ書込後の実矩形を読み戻す
  - 表示基盤側の 2 つの積み上げ元（Z 維持系・汎用の位置反映）に札を付ける
  - 実行せずにキューの中身を取り出す検査用の口を設ける（別クレートのテストから使うため公開・本番からは呼ばない旨を明記）
  - 観察可能な完了条件: 偽の窓ハンドルでも開始・各書込・終了の 3 種が発行され、検査用の口から積まれた指令をそのまま取り出せる
  - _Requirements: 2.1, 7.7_
  - _Boundary: 窓書込コマンド, 積み上げ元 2 点（Z 維持系・汎用の位置反映）_
  - _Depends: 1.2_

- [ ] 2.2 (P) メッセージ受理とモニタ表更新を記録する
  - 拡大率変更・窓位置変更・表示構成変更の各メッセージ受理を、窓ハンドルと「窓書込の内側で受理されたか」つきで記録する
  - OS 提案位置を採用したときの同期書込を、一括書込と区別できる段として記録する（採否の判定自体は変えない）
  - モニタ表の値変化更新に刻印つきの記録を足す（既存の記録行と窓の拡大率再導出は変えない）
  - 観察可能な完了条件: 遷移 1 回でモニタ表更新と各窓のメッセージ受理が時系列に並び、採否判定の既存ログと矛盾しない。モニタ表更新の記録の刻印が、既定の多スレッド実行のままフレーム計数と一致する
  - _Requirements: 2.1, 2.3_
  - _Boundary: ウィンドウメッセージ処理, モニタ表_
  - _Depends: 1.2_

- [ ] 2.3 (P) サーフェス更新と段階別計時を記録する
  - 表示の適用直前に現在の供給面寸を控え、適用後の寸と比べて「バッファ寸が変わったか」を導く（表示チェインの戻り値型は変えず、アップロード失敗分岐の字面も動かさない）
  - アップロード成立後と可視化後の 2 点で、対象・寸・段階を記録する。寸が変わったときだけ、かつ観測が有効なときだけ組む
  - 再表示の見送り（拡大率不変・不可視）を理由つきで記録する
  - 段階別計時の行の末尾にフレーム番号を足し、既存の判定スクリプトの自己較正で互換を確かめる
  - 観察可能な完了条件: 寸が変わらない定常フレームでは 1 行も増えず確保も増えないまま、遷移時だけ 3 段階が記録され、計時行と同じフレーム番号で突合できる
  - _Requirements: 2.2, 2.8, 4.6, 10.4_
  - _Boundary: 表示適用_
  - _Depends: 1.2_

- [ ] 2.4 配置判断の記録と経路語彙を拡張する
  - 作業領域源の同期・整合待ち・接地点・連鎖再解決の 4 種の記録を組む純関数を新設する
  - 経路語彙に「作業領域変化による再スナップ」と「連鎖再解決」を加え、語の一意性と総数を検証する
  - 単一の窓書込口で札を付け、下端吸着のキャラ窓については接地点と作業領域下端の差を記録する
  - 観察可能な完了条件: 接地点の記録に現行の差（拡大率を下げた側で 48px 浮く）がそのまま現れ、経路語が 12 語で一意に固定される
  - 窓書込指令の札は task 2.1 が新設する仕組みを使うため、2.1 の着地後に行う（並列にしない）
  - _Requirements: 2.1, 2.7, 5.3, 9.4_
  - _Depends: 1.2, 2.1_

- [ ] 3. 判定器とテストの土台
- [ ] 3.1 観測行の解析と遷移の切り出し・判定量の集計を実装する
  - 観測行を種別つきのレコードへ解析し、モニタ表更新のうち拡大率が変わったものを起点に遷移を切り出す
  - 遷移ごとの判定量（起点から最終書込までのフレーム差・窓ごとの書込回数・同期書込の件数・随伴の同一フレーム性・可視化と書込の食い違い・整合待ちの件数・連鎖再解決の回数・接地点差の最大・見送り窓の除外・参考の実時間）を集計する
  - フレーム番号の周回は差分のみで扱う
  - 判定語は各レコード純関数の定数を参照し、二重定義しない
  - 観察可能な完了条件: 再観測ログを新語彙へ整形した埋め込み入力から、書込 6 回・同期書込 0・接地点差 −48px が逐語で再現される
  - _Requirements: 2.4, 2.7, 7.1_
  - _Depends: 2.1, 2.2, 2.3, 2.4_

- [ ] 3.2 判定の上限を 2 系統に分けて合否を出す
  - 決定論の上限（フレーム差・窓ごとの回数・同期書込・接地点差・連鎖再解決の回数）と、実機専用の上限（可視化から書込までの経過・一括書込の総所要）を別々に持つ。実機専用の上限は暫定値で置き、task 4.3 が実測から確定値へ差し替える
  - 違反は列で返し、沈黙を合格にしない
  - 判定語を壊した入力・フィールド欠落・フレーム番号の周回境界の負例を加える
  - 実機ログを環境変数で受け取り同じ純関数で判定する、既定では走らない検証入口を用意する
  - 観察可能な完了条件: 決定論の上限では現行ログが窓ごとの書込回数で違反し、実機専用の上限は別の呼び出しとして独立に評価できる
  - _Requirements: 7.1, 7.4, 8.3_

- [ ] 3.3 多フレーム駆動のテスト土台を整える
  - フレームを進めながらモニタ表・作業領域源・窓の拡大率を差し替えられる駆動口を用意する（モニタ別拡大率表の注入口は表そのものを新設する task 5.1 側で足す）
  - 二体ぶんのスコープを同時に駆動できる形にする（連鎖の検証が隣接ペアを要するため）
  - 窓書込キューの取り出しと観測の写しの初期化をテスト冒頭で行えるようにする
  - 表示基盤側でログ捕捉に依る検証は単一スレッド実行を明示する
  - 常時テストは 64bit のみで走る形に保つ
  - 観察可能な完了条件: 同一プロセス内で複数のテストを続けて走らせても、フレーム番号・キュー・標識の残りが他のテストの判定を変えない
  - _Requirements: 7.2, 7.5, 7.6, 7.7_

- [ ] 4. 新語彙での再採取と確定台帳
- [ ] 4.1 実機サインオフ手順書を作成する
  - 採取前に用意すべきもの（ビルドプロファイルとビルド手順・32bit ホスト成果物・ゴースト一式）を絶対パスで記す
  - 絶対パスの起動コマンド・有効化する観測 target と水準・有界自動終了・判定に使う語を、第三者が再実行できる粒度で書く
  - 充足条件を経過時間ではなく遷移回数（各スコープ・低→高／高→低 各 3 回以上）で規定する
  - 観測点と target と水準の点灯表を持ち、消灯している観測点を「発生 0 回」の根拠に使わない旨を明記する
  - 観察可能な完了条件: 手順書だけを見て採取・判定・記録が一巡でき、判定に使う語が判定器の実装と一致する
  - _Requirements: 8.1, 8.2, 8.5_

- [ ] 4.2 新語彙で再採取し是正前の基準値を保存する
  - 手順書に従って拡大率 100%↔200% を各方向 3 回以上採取し、フレーム番号つきの時系列を組む
  - 判定器を通した集計と生ログを、是正前の基準値としてリポジトリ外の採取先へ保存し、採取条件（コミット・ビルドプロファイル・実機構成）を添える
  - 要件 1.1〜1.7 の義務は要件フェーズの再観測レポート（settled main 上で採取済み）が果たしており、本タスクの採取はフレーム番号つきで 1.3・1.4・1.6 と判定（残存）を確認する位置づけであることを記録に明記する
  - 観察可能な完了条件: 6 遷移ぶんの時系列がフレーム番号で 1 本に並び、是正後に同じ手順で比較できる基準値が残る
  - _Requirements: 1.3, 1.4, 1.6, 9.1_
  - _Depends: 3.2, 4.1_

- [ ] 4.3 確定台帳を起こし実機専用の上限を確定する
  - 確定台帳を実機証跡と静的構造証跡の 2 クラスで起こし、既知の 8 項目を登記する。要件 1.1〜1.7 の採取条件・帰着・未特定は再観測レポートから転記する
  - 未特定だった 2 項目（窓書込 1 回の内訳・積み上げから一括書込までの間）をフレーム番号と所要で名指しし、名指しできなければ「未特定」と記す
  - 実機専用の上限値を 4.2 の実測から決め、根拠つきで台帳へ載せ、判定器の実機専用側の定数へ反映して同じログで再判定する
  - 所要の帰着が合成コストだった場合は最適化せず、brief を持つ実在の仕様へ申し送る
  - 観察可能な完了条件: 台帳の各項目に証跡クラスと根拠が付き、確定値を入れた判定器が 4.2 のログに対して同じ結論を返す
  - _Requirements: 1.1, 1.2, 1.5, 1.7, 3.1, 3.2, 3.3, 3.5_
  - _Depends: 4.2_

- [ ] 5. 確定済みの是正
- [ ] 5.1 作業領域源を実行時に同期する
  - モニタ表から作業領域源とモニタ別拡大率表を作り直し、順序に依存しない比較で変化時だけ差し替える
  - 差し替えは拡大率の相より前（同一フレーム内で相が新しい源を読む）に置く
  - モニタ 0 台・帰属不能は警告の上で現状維持とする
  - 起動時も同じ構築関数で 2 つの源を挿入し、「セッション内固定」の注記を撤回する
  - 保存位置の復元経路には効かせない
  - モニタ別拡大率表の注入口をテスト土台へ足す（表を新設する本タスクが持つ）
  - 接地点差を測る対テストを先に書き、是正前の赤（差 −48px）を実行で記録してから是正を入れる
  - 観察可能な完了条件: 拡大率を下げた遷移でキャラ窓が 1 回の書込のまま新しい作業領域下端へ接地し（差 0）、モニタ表に変化のないフレームでは源を作り直さない
  - _Requirements: 5.1, 5.5, 5.6, 5.7_
  - _Depends: 2.4_

- [ ] 5.2 作業領域の変化を契機に現寸で再スナップする
  - 拡大率が変わらず作業領域だけ変わった窓を、現在の寸のまま新しい下端へ再射影する経路を設ける
  - 置き場は拡大率の相の後とし、相が既に書き終えた窓は同値のため書込を出さない
  - 変化が無ければ再射影そのものを行わない
  - 再射影した窓の随伴バルーンを同一フレームで窓相対の位置へ移す（追従オフセットは補正しない）
  - 観察可能な完了条件: 作業領域だけが変わったときに下端吸着のキャラ窓が 1 回だけ書き直され、その随伴バルーンが同一フレームで追随し、変化の無いフレームでは窓書込が 1 件も出ない
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 4.7_
  - _Depends: 5.1_

- [ ] 5.3 (P) 同一窓のジオメトリ指令を合流させる
  - 同一 tick・同一窓の位置指令と寸指令を先着の枠へ畳み、各項目は後勝ち、移動なし／寸なしの札は双方が持つときだけ残す
  - Z のみの指令と表示状態を変える指令は合流の対象にも先にもしない
  - 合流結果を積み上げの記録に残す
  - 窓ごとの書込回数を測る対テストを先に書き、是正前の赤（バルーン窓 2 回）を実行で記録してから是正を入れる
  - 観察可能な完了条件: バルーン窓の書込が 2 回から 1 回になり、Z 指令の相対順と最終ジオメトリは合流前と一致する
  - _Requirements: 4.5, 4.3, 10.3_
  - _Boundary: 窓書込コマンド_
  - _Depends: 2.1_

- [ ] 5.4 拡大率と表の整合待ちを設ける
  - 窓の拡大率と帰属モニタの表の値が揃うまで、その窓への窓書込を見送る（拡大率の相・報告寸の突合・再スナップの 3 点すべて）
  - 描画そのものは止めない
  - 帰属の判定は表示基盤側の再導出が使う純関数と同一の規則を共有する。当該関数は現在クレート内限定の可視性なので、共有するにはクレート外へ開く変更を伴う（開かない裁定を採る場合は同規則の述語を配置側に置き、両者が同一判定を返す対比テストを付ける。この裁定を採ったときは設計の触ったファイル一覧の該当行も書き換える——ファイル集合の差分では検出できないため）
  - 拡大率通知が先に届く順序の対テストを先に書き、是正前の赤（旧下端での書込を含む 2 段書込）を実行で記録してから是正を入れる
  - 上限フレームを超えたら警告の上で現在の源で進める
  - 待ち札のある窓へ窓書込が到達しないことを単一の窓書込口で監視する
  - 観察可能な完了条件: 拡大率通知が表更新より先に届く順序でも、旧下端の中間矩形を出さずに 1 回の書込で新寸・新下端へ移る
  - _Requirements: 5.8, 4.1, 4.6, 10.7_
  - _Boundary: 整合ゲート, モニタ帰属判定（表示基盤側）_
  - _Depends: 5.1_

- [ ] 5.5 システム由来の再アンカーで既定位置を追随させる
  - 単一の窓書込口で、キャラ窓かつ経路がシステム由来かつ書込前の位置が既定位置と一致していたときだけ既定位置を書込先へ追随させる
  - 明示操作では追随させず、既定位置なし（保存位置の復元）はそのままにする
  - 既定位置の意味が「起動時の既定」から「システム由来の再アンカーで追随する既定」へ変わることを、既定位置を読む側の記述へ反映する（起動時確定の除外規則の意味は変えない）
  - 観察可能な完了条件: 拡大率の再射影のあとでも連鎖の対象判定が「明示的に動かされた」へ倒れず、ドラッグ後の窓は対象から外れたまま
  - _Requirements: 6.2_
  - _Depends: 2.4_

- [ ] 5.6 遷移後に連鎖を一度だけ解き直す
  - 拡大率変化を伴う再射影が起きたときに武装し、全スコープが遷移後寸へ揃い整合待ちの窓が無くなった最初のフレームで一度だけ解き直す
  - 起動時の確定標識は解除しない
  - 武装時に停滞の計数と一度きりの報告札を初期化する
  - 明示的に再配置されたスコープは対象から外す
  - 見送り理由を記録し、有界を超えたら一度だけ警告する
  - 隣接を測る対テストを先に書き、是正前の赤（幅が半分になった側の左端差が残る）を実行で記録してから是正を入れる
  - 観察可能な完了条件: 決定論テストで幅が変わる遷移のあとも隣接ペアの隙間が 0 になり（実機の 359px に対応する決定論版）、会話中の表情差替では 1 度も解き直しが起きない
  - _Requirements: 6.1, 6.2, 6.3, 6.6_
  - _Depends: 5.4, 5.5_

- [ ] 5.7 (P) キーワード由来のバルーン基本位置の裁定を追跡仕様へ申し送る
  - 再導出しない／追従オフセットを拡大率倍で追随させる裁定と根拠を、担当仕様の brief へ追記する
  - 担当仕様が実在すること（brief を持つこと）を確認してから書く
