- [x] 4. 長い待ち
- [x] 4.1 待ちの終わりの判定を作る
  - 見張り・マージの待ち・負荷テストの待ち・再開の待ちの 4 種について、「状態を見て、終わるか・まだ待つか」を決める純粋な判定を作る
  - 見張り: 参加者の記録が無い → 「消えた」。「作業中」でない → 「停止要請が出た」と誰のものか（すでに止まっていればその旨）
  - マージ・負荷テスト: 待ち行列にも持ち主にも居ない → 「消えた」。持ち主 → 「番が来た」。マージは直前のマージ（無ければ `none`）、負荷テストは止まった識別の列（無ければ `none`）を 1 行に載せる
  - 再開: 記録が無い → 「消えた」。「作業中」 → 「再開した」
  - 済んだ姿: 4 種それぞれの「終わる／消えた／まだ待つ」と出力の 1 行（ASCII だけ）を決定論テストが判定する

- [x] 4.2 待ちのループを作る
  - 時計・読み・状態を変える 1 回・眠り、を差し替えられる口にまとめる
  - 手順: 登録（見張りは見張りの開始、他は待ちの記録）→ 読んで判定 → 終わらなければ 1 秒眠る → 更新時刻と大きさが変わっていたか 10 回目なら読んで判定 → 30 回目ごとに周期の一回りを呼んで読んで判定 → 終わるときに自分の記録を消す
  - 時間の上限は置かない。途中経過は何も出さない。周期の一回りの失敗（ロックの混雑など）では待ちを終えず次の周期へ進む。読みの失敗（壊れた・版違い）は失敗で終える
  - 済んだ姿: 偽の口で、すでに条件が満ちていれば眠らずに終わる／番が来て終わる／記録が消えて「消えた」で終わる／変わっていなければ中身を読まず 10 回目は読む／30 回目に周期の一回りが届く／終わるときに待ちの記録が消える／周期の一回りが失敗しても待ちが続く、を実時間を使わずに判定する
  - _Requirements: 6.1, 6.2, 6.6, 6.7, 12.1, 13.1, 13.5, 13.6_

## Implementation Notes

- 1.1: `escape_path`（道筋の ASCII の外の字を `\u{XXXX}` に逃がす）は `error.rs` に在る（`HomeNotCreatable` を作る `home.rs` が `cli` を読めないため）。5.2 の `cli.rs` は `error::escape_path` を使い、2 つ目を作らない。
- 1.1: `error.rs` の先頭の `#![cfg_attr(not(test), expect(dead_code, …))]` は使い手が載るまでの手当て。後のタスクのモジュールも `main` につながるまで同じ警告を出すので同じ形で止め、使い手が載ったタスクで外す（「満たされない expect」の警告が出たら外す合図）。
- 1.1: `main.rs` は `cli` が空の間 ASCII 1 行＋終了コード 2 の仮の姿。5.x が `cli::run` へ置き換える。`main_layering_tests.rs` の接続は 5.4 が足す。
- 1.1: `AlreadyRunning.id` は出すときに逃がさない。5.1 の形の検査（英数字と `._-`）を待ちより前に通すことが、この文の ASCII を支える。
- 1.2: 空の状態は必ず `State::empty()`（版 1）で作る。`State::default()` は版 0（版の無いファイルを黙って版 1 に読まないため）なので、テストの組み立てで `..State::default()` と書かない。
- 1.2: `WaitRecord.kind` と `Recent.kind` だけは必須（欠けたら読みが `Err` → 3.4 の「形が合わない → 退避」に乗る）。`recent` へ足すのは `State::push_recent` だけ（新しい順・50 件で切る）。列挙に綴りを足すのは `VERSION` を上げる変更として扱う。
- 2.1: `Command::Watch.name` は `Option<String>`（省くと初回は識別が名前・2 度目からは元の名前のまま）。5.x の `cli` は `--name` の省略を `None` で渡す（識別を詰めて渡さない）。`Merge`／`LoadTest`／`LoadRunning` の名前も同じ `join` を通す。
- 2.1: `apply` の `changed` は「呼ぶ前の `state.clone()` と違うか」で決めている。回収・番の決め直しの段を前後に足してもそのまま正しい。
- 2.1: 既存の参加者の見張りの立て直しは状態を変えるが出来事は 0 件。2.5 で `Command::Watch` にも `WaitRegistered` を出させるなら、`plan_desk_tests.rs` の `watch_start_*` 3 本が出来事の列を丸ごと固定しているので期待値を更新する。
- 2.1: 2.5 の `RegisterWait` のテストに「同じ識別・別の種類の待ちの記録は並ぶ（上書きしない）」を 1 本入れる（`put_wait` の一致条件から種類を落とす変異が 2.1 のテストをすり抜けたため）。

- 2.2: 元のスクリプトと違えた点が 2 つ。(a) マージの二重の申し込みの判定はリポジトリごと（要件 3.2・`state.rs` の不変。スクリプトは全リポジトリの待ち行列を見る）。(b) 待ち行列は到着順のまま持ち、番のたびに（バグ優先, 申し込み時刻）の最小を 1 件だけ抜く（同点は行列の前）。5.x の `queued merge … pos=<n>` は同じ鍵で数える。
- 2.2: `replan` は今マージの段だけの 1 関数で、全コマンドの後に呼ぶ。2.3 は負荷の段をその前に足し、負荷テストが持たれ・待たれていれば早く戻ってマージの段へ来ない形にする。`Leave` と `Merged` の後始末は `depart(state, id, why, events)` に 1 本化済み（`Merged` の出来事の順: `Merged` → `Left{why:"merged"}` → 次の `MergeGranted`）。
- 2.2: 1 つの識別が 2 つの机を同時に持ったまま `merged` を呼ぶと、両方の机の「直前のマージ」に同じ PR・sha が書かれる（`merged` に `--repo` が無い設計・スクリプトと同じ）。1 セッション 1 spec の運用では起きない。
- 2.2: レビューの教訓: 「テストで固定した」と書く前に、その分岐を元へ戻す変異を当てて赤を見る。意図して元のスクリプトから変えた分岐は、両者が分かれる入力（待っている側か持っている側か）を踏むケースでないと檻にならない。
- 2.3: 「停止要請中・止まった」から「作業中」へ戻すのは `resume(participant, why, …)` の 1 か所（理由を消し・`awaiting_watch_since` を付け・`Resumed{why}` を出す）。2.4 の `Unstop` もこれを使う。`why` は `no-load`／`load-granted`／`load-request`。
- 2.3: `replan` は `plan_load` が真（負荷テストが持たれ・待たれている）なら戻り、再開とマージの段へ進まない。停止要請の段の「走っている印なら出さない」（`&& !running`）は元の `Invoke-Plan` の条件を先に写したもの（2.1 の `cancel_…` のテストを保つため）。2.4 は `LoadRunning`・`Unstop` とその専用テストを足す。
- 2.3: 負荷テストの順は申し込み時刻の最小・同点は行列の前（スクリプトは行列の先頭）。5.x の `queued load pos=<n>` は同じ鍵で数える。停止要請の理由（`by`・内容）は出したときのまま残り、候補が替わっても書き替えない（`status.md` と `watch` の終わりの `stop requested by <id>` に前の識別が出ることがある）。
- 2.3【開発者の裁定待ち 1・設計の穴】設計の「`LoadTest` は自分の状態を `Working` に戻す」は字のとおり実装済みだが、止まっている参加者が（候補でないまま）`loadtest` を出す／`loadtest --wait` を始め直すと「止まった → 作業中 → 停止要請中」に戻り、見張りはすでに終わっていて誰も知らせないので、候補の番がその参加者の 2 度目の `stopped` まで来ない（レビューが一時テストの実走で確認。要件 5.9 の趣旨にも反する。元のスクリプトは調停役が停止の文を送り直していた）。推奨: 自戻りを外す（`plan.rs` の `resume(…, "load-request", …)` の 2 行・テスト `asking_for_a_load_test_while_stopped_puts_the_requester_back_to_work_first` の期待値・design.md の 1 文）。番を受けたときの戻し（`load-granted`）は残す。手順書には「停止要請を受けたら、次が負荷テストでも先に `stopped --wait`」と書く。
