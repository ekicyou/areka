- [ ] 4. 長い待ち
- [ ] 4.1 待ちの終わりの判定を作る
  - 見張り・マージの待ち・負荷テストの待ち・再開の待ちの 4 種について、「状態を見て、終わるか・まだ待つか」を決める純粋な判定を作る
  - 見張り: 参加者の記録が無い → 「消えた」。「作業中」でない → 「停止要請が出た」と誰のものか（すでに止まっていればその旨）
  - マージ・負荷テスト: 待ち行列にも持ち主にも居ない → 「消えた」。持ち主 → 「番が来た」。マージは直前のマージ（無ければ `none`）、負荷テストは止まった識別の列（無ければ `none`）を 1 行に載せる
  - 再開: 記録が無い → 「消えた」。「作業中」 → 「再開した」
  - 済んだ姿: 4 種それぞれの「終わる／消えた／まだ待つ」と出力の 1 行（ASCII だけ）を決定論テストが判定する

- [ ] 4.2 待ちのループを作る
  - 時計・読み・状態を変える 1 回・眠り、を差し替えられる口にまとめる
  - 手順: 登録（見張りは見張りの開始、他は待ちの記録）→ 読んで判定 → 終わらなければ 1 秒眠る → 更新時刻と大きさが変わっていたか 10 回目なら読んで判定 → 30 回目ごとに周期の一回りを呼んで読んで判定 → 終わるときに自分の記録を消す
  - 時間の上限は置かない。途中経過は何も出さない。周期の一回りの失敗（ロックの混雑など）では待ちを終えず次の周期へ進む。読みの失敗（壊れた・版違い）は失敗で終える
  - 済んだ姿: 偽の口で、すでに条件が満ちていれば眠らずに終わる／番が来て終わる／記録が消えて「消えた」で終わる／変わっていなければ中身を読まず 10 回目は読む／30 回目に周期の一回りが届く／終わるときに待ちの記録が消える／周期の一回りが失敗しても待ちが続く、を実時間を使わずに判定する
  - _Requirements: 6.1, 6.2, 6.6, 6.7, 12.1, 13.1, 13.5, 13.6_

  - `merged`・`loaddone`・`loadrunning`・`stopped`（`--wait` 無し）・`unstop`・`cancel`・`leave`・`tick`・`--wait` 無しの `merge`／`loadtest` を、「置き場所の解決 → 開く → 状態を変える 1 回 → 出力 → 終了コード」の同じ手順でつなぐ

  - `clear`: 問い合わせをせず直ちに行い、退避の道筋を 1 行で出す
  - 出力は設計のコマンドの表のとおり ASCII の 1〜数行。「当てはまらなかった」は標準エラーへ 1 行出して 3。失敗はログに残して 1。置き場所の道筋だけは ASCII の外の字を逃がして出す
  - テストで 2 つ以上の識別を使うときは、呼ぶ前にほかの識別の居る印をテストのプロセス内で握っておく（握らないと、呼んだ識別以外の「作業中」の参加者が回収される）
  - 済んだ姿: 一時の置き場所に対して、申し込み → 番 → 済んだ、の列を続けて呼ぶと設計どおりの出力と終了コードになる／持ち主でない `merged` が 3 で状態ファイルが変わらない／`status` が状態ファイルを変えず、日本語の名前を入れても端末出力が ASCII だけ／`clear` の出力に退避の道筋が載る、をテストが判定する
  - _Depends: 3.5_
  - _Requirements: 3.10, 4.9, 4.11, 5.7, 7.6, 9.2, 9.3, 9.4, 10.2, 13.3, 14.4_

- [ ] 5.3 待つコマンドをつなぐ
  - `watch`・`merge --wait`・`loadtest --wait`・`stopped --wait`・`resume` を、「居る印を握る → 待ちのループ → 終わりの 1 行と終了コード」でつなぐ。待ちの口の本物（本物の時計・1 秒の眠り）をここで組む
  - 同じ識別・同じ種類の待ちがすでに走っていれば 1。「消えた」は 3、番・停止要請・再開は 0
  - `merge --wait`／`loadtest --wait` は申し込みを先に行い、すでに番が来ていれば直ちに終わる。`stopped --wait` は「止まった」を記録してから再開を待つ（すでに作業中なら直ちに 0）
  - アプリは合図を出すだけで、他のプロセスには触らない
  - テストの「あらかじめ条件が満ちた状態」のうち、コマンドの列だけでは作れないもの（すでに停止要請中の参加者など）は状態ファイルを直に書いて作る。2 つ以上の識別を使うときは 5.2 と同じく居る印を握っておく
  - 済んだ姿: 一時の置き場所で、あらかじめ条件が満ちた状態に対して各コマンドが直ちに正しい終了コードと 1 行で終わる（番が来ている `merge --wait` が 0 と直前のマージ／記録の無い `resume` が 3／居る印が握られている `watch` が 1）、をテストが判定する
  - _Depends: 4.2, 5.2_
