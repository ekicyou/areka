# 親仕様からの引継ぎコンテキスト

> **親仕様**: `wintf-P0-balloon-system`
> **対象要件**: R1（ウィジェット生成）、R2（フレーム描画）、R4（表示制御）
> **アーキテクチャ要件**: AR-1（複合ウィジェット構造）、AR-2（描画責務分離）、AR-3（描画責務間独立性）
>
> **スコープ外**: R3（配置制御）—— 配置・追従はバルーンウィジェットの描画責務ではなく、外部の協調制御システムの責務。親仕様 R3 は別途見直しが必要。

---

## 参照すべき設計情報

### design.md

- **Balloon コンポーネント定義**: 純粋な描画ウィジェット。on_add フックによる子エンティティ spawn。キャラクターへの参照や配置ロジックは持たない
- **BalloonSkinDef コンポーネント定義**: スキン定義インターフェース契約（背景・角丸・枠線・しっぽ角度）
- **エンティティ階層モデル**: Balloon → BalloonFrame → BalloonContentArea（Mermaid 図参照）
- **コンポーネント構成パターン**: 各エンティティに付与するコンポーネントの組み合わせ
- **モジュール配置**: `ecs/widget/balloon/mod.rs`（Balloon）、`frame.rs`（BalloonFrame, BalloonSkinDef）
- **システムフロー「バルーン生成シーケンス」**: on_add → Commands → 子エンティティ spawn
- **制約事項**: ULW / DComp 両モード対応
- **エラーハンドリング戦略**: スキン定義エラー → デフォルトスキンにフォールバック
- **設計原則**: Balloon は純粋な描画ウィジェット。ウィンドウ管理・配置制御・キャラクターとの紐づけは外部システムの責務

### research.md

- **Errata E1**: on_add フック内で `DeferredWorld::commands()` は使用可能。`on_window_add` が実証済みパターン。thread_local コマンドキューは不要
- **Errata E2**: BalloonContentArea は BalloonFrame の子（`ChildOf(balloon_frame)`）。Balloon の直接の子ではない

## 子仕様スコープ

- バルーン描画ウィジェットの生成・表示制御
- フレーム描画基盤（スキンインターフェース）
- 複合ウィジェットとしてのエンティティ階層構築
- 他の全バルーン子仕様が依存する基盤レイヤー

### スコープ外（外部システムの責務）

- 配置制御（キャラクター追従・デスクトップ境界反転）
- ウィンドウ管理（HWND 生成・窓スタイル設定）
- キャラクターとの紐づけ（アンカー参照）

## v2.0 レビュー議事の設計判断（2026-02-26）

### ブロッカー

- **`wintf-P0-cue-system`**: 演出キュー配送基盤仕様。コンテンツコマンド配送メカニズムの設計が balloon01-core のコンポーネント構成原則に影響するため、要件確定を待って v3.0 を最終化

### 確定した設計判断

- **D1: ファサードパターン原則**: 外部入力はすべて Balloon ルートエンティティのコンポーネントで受け取る。Typewriter パターンの正統な拡張
- **D2: TextDirection はバルーンの静的属性**: 1バルーン内で混在しない。変更時はコンテンツ全削除
- **D3: 感情値ベースの BalloonStyleMap**: HashMap<String, TextStyle> + デフォルト値。アニメーション指示での切替は可能だが非推奨
- **D4: dola はバルーン内部サブシステムとしても利用可能**: タイミング計算、グリフ表示制御等に直接使える
- **D5: コンテンツコマンド配送は cue-system に外部化**: バルーン固有ではなく、キャラクター演技指令にも同一インターフェースが必要なため横断的関心事として分離
