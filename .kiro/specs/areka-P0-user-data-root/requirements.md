## Project Description (Input)
winget で areka を入れた利用者（と、`areka.exe` の在るフォルダに書き込めない利用者）は、後から入れたゴースト・バルーン、areka の記憶、ゴーストの記憶、シェルの記憶を、winget の上げ直しや外し方のたびに黙って失う。機械の全員向けに入れると、普段の権限では areka の記憶を書けず、ゴーストを後から入れることもできない。areka は利用者の物をすべて exe の隣（入れ先のフォルダの中）に置くためである。利用者の物を入れ先の外の「書ける根」（OS の利用者ごとのフォルダ）に置き、同梱の物は exe の隣から探し続け、zip を展開して exe の隣で使う今の形は今と同じに動かす。詳細は brief.md。

## Introduction

### 誰が困っているか

- winget で areka を入れた利用者（利用者向け `--scope user`・機械の全員向け `--scope machine` のどちらも）。
- `areka.exe` の在るフォルダに普段の権限で書き込めない利用者（`C:\Program Files` の下へ zip を展開した人など）。

### いま何が起きているか

- areka は利用者の物をすべて実行ファイルの隣に置く。この文書では、ゴーストとバルーンを置くフォルダ（直下に `ghost\` と `balloon\` を持つ）を「根」と呼ぶ（説明書の語では「置き場」）。
  - 根の並びの既定は「実行ファイルの隣」1 つだけ（`crates/areka/src/roots/resolve.rs` の `resolve_roots_from`）。新しく入れる物は、見つかるいちばん上の根へ入る（`crates/areka-ghost/src/catalog_roots.rs` の `install_root`）。すでに在る物の入れ直しは、見えている根でその場で上書きする。
  - `.nar` を入れるときの作業フォルダは、宛先の根の `.nar-work\` の下（`crates/areka-nar/src/install.rs` の `WORK`）。
  - areka の記憶（前回使ったゴースト・根の並びなど）は、`AREKA_PROFILE_DIR` が無ければ実行ファイルの隣の `profile\areka\`（`crates/areka/src/boot_config.rs` の `default_app_profile_dir`）。
  - ゴーストの記憶とシェルの記憶は、ゴーストのフォルダの中の `profile\areka\`（`crates/areka-ghost/src/sylphya_wiring.rs` の `profile_areka_root`）。ゴースト自身の書き残し（SHIORI の保存データ）は、SHIORI が自分のフォルダへ書く。
  - ネットワーク更新は、対象のフォルダの中の `.update-work\` を作業に使い、対象のフォルダへその場で書く（`crates/areka-update/src/paths.rs` の `WORK_DIR`）。
  - 中継（`areka-mcp-bridge.exe`）の控えは、隣に `areka.exe` が在れば実行ファイルの隣の `profile\areka\mcp-bridge\`（`crates/areka-mcp-bridge/src/config.rs` の `from_values`）。
- winget は、配布 zip の最上位に在った物（`ghost\`・`balloon\` と 6 つのファイル）を、上げ直すときにも外すときにも、中に後から置かれた物ごと消す。出どころの spec `areka-P0-winget-manifest-submission` の実測（0.0.2・開発機 1 台）では、上げ直しでも外し方でも利用者の物が **6**（後から入れたゴースト 1・バルーン 3・ゴーストの記憶 2）消えた。
- 機械の全員向けでは、普段の権限で、areka の記憶を書けず（1 回の起動で 3 回「アクセスが拒否されました」）、メニューの「インストール…」が作業フォルダを作れずに止まった。
- この状態が直るまで、説明書に winget の入れ方を載せず、winget-pkgs へ次の版を出さないと決めてある（後続 `areka-P0-winget-release-automation` が待つ）。

### 何を変えるか

**利用者の物を、入れ先のフォルダの外の「書ける根」に置く。** winget の入れ先で動くとき、または実行ファイルのフォルダに書けないとき（以下「書ける根を使う形」）は、OS の利用者ごとのフォルダ（既定の案は `%LOCALAPPDATA%\areka\`）を根の並びの先頭に置き、実行ファイルの隣（同梱の物）をその下の段に残す。新しく入れる物と作業フォルダは、`baseware-root-list` の「新しく入れる物は先頭の根へ」でそのまま書ける根へ行く。areka の記憶と中継の控えも書ける根の下へ移す。同梱のゴーストは、書く必要が出る前（起こす前など）に書ける根へ写し、写しの方を使う（同じフォルダ名なので、上の根の写しが下の同梱の物を隠す）。＝書ける根を使う形では、areka は実行ファイルのフォルダの下に何も書かない。zip を展開して実行ファイルの隣に書ける今の使い方は、今と同じに動く。

## Boundary Context

- **In scope**:
  - 書ける根を使う形かどうかの決め方と、書ける根の場所の決め方（環境変数での上書きを含む）。
  - 書ける根を使う形での、既定の根の並び（書ける根を先頭・実行ファイルの隣をその下）と、記憶の並びや `AREKA_ROOT` との関係。
  - 書ける根を使う形での、実行ファイルの隣の根の物（同梱のゴーストとバルーン）へ書く必要が出たときの扱い（書ける根へ写してから写しへ書く）。
  - areka の記憶の置き場と、実行ファイルの隣に在る今の記憶の引き継ぎ。
  - 中継の控えの置き場を、areka の記憶の置き場にそろえること。
  - 説明書 `dist/README.txt` の「■ 置き場」「■ 記憶の置き場」の直し。
  - 後続 `areka-P0-winget-release-automation` への申し送り（雛形の注意書きを外してよい条件）。
  - 決定論テストと、winget で入れた形での実測（上げ直し・外す・機械の全員向け）。
- **Out of scope**:
  - 根の並びそのもの（値の形・上から探す規則・メニューの「置き場を追加…」「置き場を外す ▸」）＝完了 `areka-P0-baseware-root-list`。
  - winget が外した後に残す PATH の項目（winget の側の動き）。
  - インストーラー版（名乗り `Areka.Areka`）。
  - winget のマニフェストの雛形（`dist/winget/**`）の書き替えと、注意書きを外す作業。
  - 書けないときに利用者へ伝えること（`areka-P0-write-failure-notice`）。この spec は記録に残すまで。
  - `.nar` の展開の中身・ネットワーク更新の手続きの中身（宛先は今の「見えている根」の規則のまま）。
  - SHIORI が自分のフォルダの中のどこへ書くか（areka は場所を決めない。写しから起こすことで写しの中へ書かれる）。
  - 設定画面・本体の設定ファイル・メッセージボックス・SSP のフォルダ設定の写し。
- **Adjacent expectations**:
  - 完了 `areka-P0-baseware-root-list`: 根の並び・上から探す規則・「新しく入れる物は見つかるいちばん上の根へ」・「すでに在る物はその場で上書き」・作業フォルダは宛先の根ごと、をそのまま使う。この spec はその上に既定の並びと書ける根を足す。
  - `areka-P0-write-failure-notice`（同じウェーブ）: 書ける根を作れない・写せない・記憶を書けないときの利用者への知らせは向こうの持ち物。同じウェーブの約束で、この spec は `crates/areka/src/main.rs`・`crates/areka/src/boot_resolve.rs`・`crates/areka/src/roots/edit.rs` に触らない（`boot_resolve.rs` に手を入れないと済まないと設計で分かったら、そのタスクを最後に置き、向こうの着地を待って main を取り込んでから直す）。
  - `areka-P0-winget-release-automation`（後続）: この spec の着地で、説明書の winget の行と winget-pkgs への次の版の提出を始められる。雛形の注意書き（`InstallationNotes`）を外すかどうかと、その作業は向こうが持つ（要件 9）。
  - `areka-P0-dev-folder-alias`・`areka-P0-ghost-inner-balloon`・`areka-P0-shell-companion-balloon`: 同じ `roots/` と `boot_config.rs` の別の関数を触る。この spec は根の並びの値の形を変えない。

## Requirements

### Requirement 1: 書ける根を使う形かどうか

**Objective:** As a winget で入れた利用者, I want areka が自分の物を入れ先の外へ置くこと, so that 上げ直しや外し方で物が消えず、機械の全員向けでも書ける

#### Acceptance Criteria

1. When 実行ファイルのフォルダが winget の入れ先（利用者向け・機械の全員向けのどちらでも）である, the areka shall 書ける根を使う形で動く。
2. When 実行ファイルのフォルダに普段の権限で書けない, the areka shall 書ける根を使う形で動く。
3. When 書ける根の場所を指す環境変数（要件 2.3）が在る, the areka shall 1・2 に関わらず、書ける根を使う形で動く。
4. While 1〜3 のどれにも当たらない（zip を展開して実行ファイルの隣に書ける今の使い方）, the areka shall 書ける根を使わず、根の並び・記憶の置き場・インストール先・作業フォルダ・中継の控えの置き場を今と同じにする（変わる物は 0）。
5. When 起動する, the areka shall 書ける根を使う形かどうかと、その理由（winget の入れ先・書けない・環境変数・どれでもない）を記録に残す（info）。
6. The areka shall 書ける根を使う形かどうかを利用者に尋ねない（尋ねる画面・ダイアログ・メッセージボックスは 0）。

### Requirement 2: 書ける根の場所

**Objective:** As a 利用者, I want 書ける根が OS の決まった利用者ごとの場所に在ること, so that 自分で置き場を決めて作らずに済み、機械の全員向けでも書ける

#### Acceptance Criteria

1. The areka shall 書ける根を、OS の利用者ごとの場所（既定の案は `%LOCALAPPDATA%\areka\`）に置く。
2. When 書ける根のフォルダが無い, the areka shall それを作り、作ったことを記録に残す（info）。中の `ghost\`・`balloon\` は、入れる物ができたときに作る（今の根と同じ）。
3. Where 書ける根の場所を指す環境変数（`AREKA_` で始まる名前・名前は設計で決める）が在る, the areka shall その値を書ける根に使う（テストと実機の確かめで、ワークツリーの `target\` の下へ向けるため）。
4. If 書ける根の場所を決められない（利用者ごとの場所が取れない・相対パス・空）、または作れない, then the areka shall 書ける根を使う形でないものとして今と同じ並び・置き場（実行ファイルの隣）で続け、失敗の内容と試した場所を記録に残す（error）。利用者への知らせは `areka-P0-write-failure-notice` の持ち物とする。
5. The areka shall 書ける根の中を、ほかの根と同じ形（直下の `ghost\`・`balloon\`・`.nar-work\`）で扱う。

### Requirement 3: 書ける根を使う形での根の並び

**Objective:** As a winget で入れた利用者, I want 新しく入れた物が書ける根へ入り、同梱の物も今どおり選べること, so that 何も設定せずに物が消えない形で使える

#### Acceptance Criteria

1. While 書ける根を使う形である and 環境変数 `AREKA_ROOT` が無く、記憶に並びが無い, the areka shall 「書ける根 → 実行ファイルの隣」の 2 つの並びを使う。
2. While 書ける根を使う形である and 記憶に並びが在る, the areka shall 記憶の並びの先頭に書ける根を置いて使う（記憶の並びに書ける根が在れば、それを先頭へ動かし、2 回は並べない）。
3. While 書ける根を使う形である, when 利用者がメニューの「置き場を外す ▸」で書ける根を外す, the areka shall 遅くとも次の起動から、書ける根を並びの先頭に戻して使い、戻したことを記録に残す（warn）。
4. When 環境変数 `AREKA_ROOT` が在る, the areka shall 今どおりその値の並びだけを使い、書ける根を足さない（`AREKA_ROOT` の今の役目を残す）。
5. While 書ける根を使う形である and 記憶に並びが無い, the areka shall 並びを記憶に書かない（利用者がメニューで並びを変えるまで。完了 `baseware-root-list` と同じ）。
6. The areka shall 並びの記録（出どころ・見つかったかどうか）に、書ける根の出どころ（既定の書ける根・環境変数）を足して残す（info）。

### Requirement 4: 実行ファイルの隣の物へ書かない

**Objective:** As a winget で入れた利用者, I want areka が入れ先のフォルダの中へ何も書かないこと, so that 上げ直しで消える物が無く、外したときに入れ先のフォルダを winget が消せる

#### Acceptance Criteria

1. While 書ける根を使う形である, the areka and 中継 shall 実行ファイルのフォルダの下に、ファイルもフォルダも作らず、書き換えない（作る・書き換える物は 0）。
2. When 新しいゴーストまたはバルーンを入れる, the areka shall それを書ける根へ入れ、作業フォルダも書ける根の下に作る（完了 `baseware-root-list` の「見つかるいちばん上の根へ」で付いてくる）。
3. While 書ける根を使う形である, when 実行ファイルの隣の根にしか無いゴーストを起こす（起動・切替・`\![change,ghost,…]`・前回がきれいに終わらなかったときの既定ゴーストを含む）, the areka shall 起こす前にそのゴーストのフォルダを丸ごと書ける根の `ghost\` へ同じフォルダ名で写し、写しの方を起こす。
4. While 書ける根を使う形である, when 実行ファイルの隣の根にしか無いゴーストまたはバルーンへ書く（入れ直しの上書き・シェルや supplement を足す・ネットワーク更新）, the areka shall 先にそれを書ける根へ同じフォルダ名で写し、写しの方へ今と同じ手続きで書く。
5. While 書ける根を使う形である, when 実行ファイルの隣の根にしか無いバルーンを使う（表示するだけ）, the areka shall 写さずに実行ファイルの隣のものを読む。
6. When 写す, the areka shall 写した元と先を記録に残す（info）。
7. If 写す途中で失敗する, then the areka shall 書ける根に半端な写しを残さず（同じフォルダ名のものが書ける根に現れない）、写す前と同じく実行ファイルの隣のものを使って続け、失敗の内容を記録に残す（error）。
8. When 書ける根にすでに同じフォルダ名のゴーストまたはバルーンが在る, the areka shall 写さず、書ける根のもの（上の根）を使う（完了 `baseware-root-list` の隠れの規則のまま）。
9. The areka shall 写したゴーストを、areka の版が上がって同梱のゴーストが新しくなっても上書きしない（写しには利用者の記憶が在るため）。

### Requirement 5: areka の記憶の置き場と引き継ぎ

**Objective:** As a winget で入れた利用者, I want 前回使ったゴーストや根の並びの記憶が書けて、上げ直しの後も残ること, so that 毎回選び直さずに済む

#### Acceptance Criteria

1. Where 環境変数 `AREKA_PROFILE_DIR` が在る, the areka shall 今どおりその値を areka の記憶の置き場に使う（書ける根を使う形でも変えない）。
2. While 書ける根を使う形である and `AREKA_PROFILE_DIR` が無い, the areka shall areka の記憶を書ける根の `profile\areka\` に置く。
3. While 書ける根を使う形でない and `AREKA_PROFILE_DIR` が無い, the areka shall 今どおり実行ファイルの隣の `profile\areka\` に置く。
4. When 書ける根の `profile\areka\` に記憶が無く、実行ファイルの隣の `profile\areka\` に記憶が在る, the areka shall 実行ファイルの隣の記憶を書ける根の `profile\areka\` へ写して使い、写したことを記録に残す（info）。実行ファイルの隣の記憶は消さない・書き換えない。
5. If 4 で写せない, then the areka shall 実行ファイルの隣の記憶を読むだけにして続け、失敗の内容を記録に残す（error）。
6. The areka shall areka の記憶の置き場を、起動・ゴーストの起動・SHIORI の受け口・根の並びの読み書きのすべてで同じ 1 つに決める。

### Requirement 6: 中継の控えの置き場

**Objective:** As a 中継を使う利用者, I want 中継の控えが areka の記憶と同じ場所に在ること, so that winget の上げ直しで控えだけが消えない

#### Acceptance Criteria

1. The 中継 shall 控えを、areka の記憶の置き場（要件 5）の下の `mcp-bridge\` に置き、areka と同じ規則で置き場を決める（`AREKA_PROFILE_DIR`・書ける根を使う形かどうか・書ける根の場所の環境変数を含む）。
2. While 中継の隣に `areka.exe` が無い, the 中継 shall 今どおりの決め方（`%LOCALAPPDATA%\areka\mcp-bridge\` など）を使う。
3. If 控えの置き場を決められない, then the 中継 shall 今どおり控えなしで動き、そのことを記録に残す（warn）。

### Requirement 7: 今の使い方と、今在る物を守る

**Objective:** As a zip を展開して使っている利用者, I want 今の使い方と今の物がそのまま効くこと, so that この変更で何も選び直さず、何も見失わない

#### Acceptance Criteria

1. While 書ける根を使う形でない, the areka shall 起動・切替・メニュー・インストール・ネットワーク更新・記憶の読み書きを今と同じに動かす（変わるのは要件 1.5・3.6 の記録の行だけ）。
2. While 書ける根を使う形である, the areka shall 実行ファイルの隣の根を並びに残し、そこに在る物（同梱の物と、今までに入れた物）を今どおり一覧・切替・メニューに出す（自動で移すことも消すことも 0）。
3. The areka shall ゴーストの記憶とシェルの記憶の置き場（そのゴーストのフォルダの中）を変えない（書ける根を使う形では、写しのフォルダの中になる）。
4. The areka shall 起動の引数でフォルダを直接渡す起動（実機サインオフの絶対パス起動）を今どおり「目録の外」として扱い、写さない。
5. The areka shall 一度出した winget の名乗り `Areka.Areka.Portable` に関わる物を変えない。
6. The 本仕様 shall 新しい外部依存を足さない（0）。設定画面・本体の設定ファイル・メッセージボックスを足さない（それぞれ 0）。

### Requirement 8: 説明書

**Objective:** As a 利用者, I want 説明書の置き場の説明が実際と合うこと, so that 自分の物がどこに在るか、上げ直しで何が残るかが分かる

#### Acceptance Criteria

1. The 本仕様 shall `dist/README.txt` の「■ 置き場」に、winget で入れたとき・実行ファイルのフォルダに書けないときは、利用者ごとの書ける置き場（`%LOCALAPPDATA%\areka\` など、要件 2 で決めた場所）が並びの先頭に入り、新しく入れる物はそこへ入ること、同梱の物は実行ファイルの隣から使い続けること、を平易な語で書く。

## 要件の討議へ持ち込む議題

brief の議題 1〜10 を、本文での扱いと並べる。どれも開発者の裁定を受けていない。

1. **向き**（brief の議題 1）: 本文は brief の推す向き（利用者の物を入れ先の外の書ける根へ・同梱の物は実行ファイルの隣に下の段として残す）で書いた。代わりの案は brief のとおり（インストーラー版・zip の並びだけを変える）。
2. **いつ書ける根を使うか**（議題 2）: 本文の案は「winget の入れ先のとき、または実行ファイルのフォルダに書けないとき」（要件 1）。zip を展開して書ける所で使う今の形を今と同じに保つため。代わりの案は「いつも」（判断が要らず単純。ただし zip を USB メモリなどで持ち歩く使い方でも、新しく入れる物が PC の側へ行く）と「winget の入れ先のときだけ」（書けない所へ手で展開した人が救われない）。winget の入れ先をどう見分けるか（利用者が winget の設定で portable の入れ先を変えた機械を含む）は設計で決める。
3. **どこに置くか**（議題 3）: 本文の案は `%LOCALAPPDATA%\areka\`（要件 2.1）。利用者ごと・機械の全員向けでも普段の権限で書ける・前例が中継の控え（`%LOCALAPPDATA%\areka\mcp-bridge\`）に在る。ゴーストは大きくなりうるので、ローミングする `%APPDATA%` やドキュメントの下は採らない案。
4. **実行ファイルの隣に今在る利用者の物**（議題 4）: 本文の案は「探し続け、自動では移さない」（要件 7.2）。書く必要が出たときだけ写す（要件 4.3・4.4）。areka の記憶だけは、初回に書ける根へ写す（要件 5.4）。
5. **0.0.2 を winget で入れた人の最初の上げ直し**（議題 5）: winget は新しい版の areka が動く前に、入っている版の控えに従って消す見込み＝どの向きでも areka の側からは守れない見込み（測っていない）。本文は、実測で数える（要件 9.1）・説明書に書く（要件 8.4）・申し送る（要件 9.2）とした。
6. **areka の記憶の置き場**（議題 6）: 本文の案は書ける根の `profile\areka\`（要件 5.2）。実行ファイルの隣と同じ形にそろえる。
7. **同梱のゴーストの記憶**（議題 7・いちばん難しい）: 本文の案は「書く必要が出る前に、同梱のゴーストを書ける根へ写し、写しの方を使う」（要件 4.3〜4.9）。areka の記憶の分だけでなく、SHIORI が自分のフォルダへ書く分（同梱の えも？？ の `ghost\master\profile\pasta\` など）も写しの中へ書かれるので、Desired Outcome 1 の「消えた物 0」と、機械の全員向けで書けることの両方が満たせる。入れ直し・ネットワーク更新の作業フォルダ（brief の「残る穴」）も同じ規則で書ける根へ行く。代償は、areka の版が上がって同梱のゴーストが新しくなっても、写しが下の同梱の物を隠し続けること（要件 4.9。新しくするのはゴースト自身のネットワーク更新か、利用者の入れ直し）。代わりの案は「同梱のゴーストは実行ファイルの隣のまま起こし、areka が決める記憶（`profile\areka\`）だけを書ける根の下へ移す」（`sylphya_wiring.rs`・`runtime.rs`・`placement/persist.rs` を触る）。こちらは同梱のゴーストの更新がそのまま届くが、SHIORI の書き残しは上げ直しで消え、機械の全員向けでは書けない（説明書の既知の制限になる）。
8. **説明書の書き直し**（議題 8）: 本文は 2 つの形（zip・書ける置き場）で書く案（要件 8）。シェルの記憶の行は、作る操作の有無を確かめて書く（要件 8.3）。
9. **雛形の注意書きを外す時機と持ち主**（議題 9）: 本文の案は、持ち主を `areka-P0-winget-release-automation` とし、この spec は外してよい条件を申し送るまで（要件 9.2・9.3）。
10. **自分たち以外が次の版を winget-pkgs へ出しうること**（議題 10）: 本文は範囲に入れていない（areka の側からは止められない）。この spec が着地した後に第三者が出す版は、この spec の版以降なら要件 10.8 の上げ直しの結果どおり消える物 0 の見込み。着地の前に 0.0.2 の次の版が第三者から出た場合の知らせ方（注意書き・Release の説明）は、9 と一緒に `winget-release-automation` で決める案。
11. **書ける根を「置き場を外す ▸」で外したときの、その回の効き方**（brief 10-16 の「残る穴」）: 同じウェーブの約束で `roots/edit.rs` に触らないため、本文は「遅くとも次の起動から先頭に戻す」とした（要件 3.3）。外したその回のうちに新しく入れた物は、実行ファイルの隣へ入りうる。メニューで書ける根を選べない形にするなら、`write-failure-notice` の着地の後に `roots/edit.rs` を触ることになる。
