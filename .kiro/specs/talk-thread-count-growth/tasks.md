- [ ] 3. 名簿が終わったスレッドを畳んで手放す
- [ ] 3.1 名簿を「生きた項目と系統ごとの畳んだ合計」の芯に載せ替え、登録と読み出しのたびに掃除する
  - 名簿の状態を、生きた項目の並びと系統名ごとの合計（カーネル・ユーザーの 100ns の累積と畳んだ本数）を 1 つの錠で持つ形に替え、生死と CPU の読みを差し替えられる芯にする。本番の読み手は Win32 の口を呼ぶだけ。錠の毒化は今と同じく中身を受け取って続ける
  - 掃除: 終わったと見分けた項目は最後の CPU を読んで系統の合計へ足し、読めなければ合計へは足さずに記録へ残す。どちらでも本数を 1 足して項目とハンドルを外す。生きている項目は残す。見分けに失敗した項目は残し、掃除のたびに記録へ残す。記録に出す中身（tid・役割名・系統名・失敗の理由、読めなかったときは「その分は unregistered_rest へ回る」）は錠の中で集めるだけにし、錠を放してから `warn!`（target は今と同じ）で出す
  - 登録: 掃除の後に同じ TID の項目が残っていれば合計へ足さずに外し、末尾へ足す。登録が済んだら `debug!`（target `wintf::thread_registry`・役割名・tid）を 1 行出す
  - 系統の名: 役割名の末尾の `-<ASCII の数字>` を `-*` に畳み、番号の無い役割名はそのまま。系統の名は役割の語彙の検査に掛けない
  - 公開の口: 登録の口と生きた項目の複写を返す口は今の形のまま掃除の後の生きた項目を返し、報告器向けに、掃除の後の生きた項目の CPU と畳んだ合計（系統名の昇順）を錠の中の 1 つの時点の組で返す口を足す。呼び手は走り始めの登録と報告器の周期だけで、描画の刻みの経路には入れない
  - モジュールの説明（「終了した後も CPU 時間を読み出せる」「登録は複製 1 回と push 1 回」）・預かるハンドルの説明（「名簿が手放すまで」）・役割の語彙の一覧の説明（報告行に出る役割名は語彙のものとその系統の名）を直した後の振る舞いに合わせて書き直す
  - join の後も項目が残ることを前提にした今のテストを「join の後は生きた項目に無く、その系統の畳んだ合計に入る」へ書き直し、系統の名の表（`actor:sakura-talk-17` → `actor:sakura-talk-*`・`actor:kanade`・`vblank`・`-5`・`actor:x-1a` はそのまま）のテストを足す
  - 終わった姿: ワークスペースがビルドでき、書き直したテストと系統の名の表のテスト、名簿を読む今のテスト（カーソル監視・vblank・UI スレッド・アクターの役割宣言）が緑
  - _Dispatch: standard — 掃除・畳み・置き換えの分岐と静的な名簿への載せ替えを組む_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 5.5_

- [ ] 4. 報告器の 1 枚に畳んだ合計の行を足し、数の意味を合わせる
- [ ] 4.1 畳んだ合計の行と名簿外の残りの算出を、純関数として用意する
  - 畳んだ合計の 1 件（系統名・カーネルとユーザーの µs・本数）を表す型を足し、`perf(thread)` の今の欄のまま `tid=0 name=-`、役割名に系統名、末尾に `exited=<本数>` を 1 つ足した行を組む関数を足す。系統名は今の空白の置き換えを通す。100ns の和は最後に 1 度だけ µs へ切り捨てる
  - 名簿外の残りを、プロセスから生きた行の合計と畳んだ合計の両方を引いた差（カーネル・ユーザーそれぞれ 0 で止める）にする
  - 報告器のテストのファイルで、畳んだ行の欄名が重複しないこと・綴りと並び（`snap t_s tid name role cpu_us kernel_us user_us exited`）・`tid=0`・`name=-`・系統名の空白が `_` になること、名簿外の残りが両方を引いて 0 で止まることを固定する。今の `perf(thread)`／`perf(process)` の行の綴りと並びのテストは変えずに緑
  - 名簿外の残りの関数の引数が増えるので、今の唯一の呼び手（1 枚を出す関数）は 4.2 で配線し直すまで畳んだ合計に空の並びを渡す
  - 終わった姿: ワークスペースがビルドでき、足したテストと今の報告器のテストが緑
  - _Dispatch: mechanical — 欄の綴りと並び、引き算の形を設計が与える_
  - _Requirements: 4.2, 4.3, 4.5, 4.6, 7.4_

- [ ] 4.2 1 枚の組み立てを名簿の読み出しの組に替え、使われない差の規則を消す
  - 1 枚の行を組む純関数（Win32 を呼ばない）を足す: 順は `perf(process)` 1 行 → 生きた行（TID 昇順・CPU を読めた項目だけ）→ 畳んだ行（系統名の昇順）→ `unregistered_rest` 1 行。`threads=` は生きた項目の数（CPU を読めなかったものも数え、畳んだ行と残りの行は数えない）。読めなかった生きた項目の TID は別に返す。名簿の畳んだ合計（100ns）から報告器の畳んだ合計の 1 件（µs）への写しはこの関数の中で行い、µs へは 1 度だけ切り捨てる
  - 報告の 1 枚は、名簿の読み出しの組を先に、プロセスの CPU を後に読んでその関数に渡し、返った行を順に出し、読めなかった TID を今と同じく 1 枚に 1 度の `warn!` に並べる。点灯の判定と報告スレッドを起こす前のガードは変えない
  - 本番から呼ばれない差の関数とその `#[allow(dead_code)]`、そのテスト 3 本を消す。プロセスの数の欄の説明を「そのスナップショットの時点で生きている名簿のスレッドの本数（CPU を読めなかったものも数える）」に、モジュールの説明の「行は累積値である」「差の取り方はこの関数が権威」を「区間の差は読み手（`perf-rank.py` の段②・自己テストが規則を固定する）が最後のスナップショットと 60 秒前のものを比べて取る。名簿外の残りはプロセスの差から出す」に書き直す
  - 手で組んだ読み出しの組（読めない生きた項目 1 つ・番号の無い系統の畳んだ合計を含む）を渡し、`threads=` の数・行の順・読めない TID が別に返ることを固定するテストを足す。消灯時に何も起こさない今のテストは緑のまま
  - 終わった姿: ワークスペースがビルドでき、報告器のテストが全部緑で、差の関数への参照がソースに残っていない
  - _Dispatch: standard — 1 枚の組み立ての純関数と読む順の配線を組む_
  - _Requirements: 4.1, 4.2, 4.6, 4.7, 5.5, 7.4_
