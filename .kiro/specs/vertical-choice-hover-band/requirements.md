# Requirements Document

## Project Description (Input)

- **困っている人**:
  - ゴーストの利用者。縦書きのバルーンで選択肢の列にマウスを乗せると、反転の帯（背景の塗り）が列とずれ、選んでいる選択肢の字が読めなくなる。
  - バルーンの作者（ぱすた）。縦書きのバルーン `pasta_tategaki`（`vertical,1`・`cursor.style,square`）で、SSP と同じ反転にならない。
- **今の状況**:
  - 縦書きで選択肢の列に乗せると、帯が列からずれ、列の字のおよそ半分しか塗らない。横書きのバルーンでは帯は行に合っている。
  - 証拠は完了 spec `areka-P0-pasta-in-windows-verification` の `verification.md` の崩れた所の表の **23**（開発者の目視の判定・2026-10-23「選択肢をマウスホバーした時の背景の塗りが崩れている。横書きの時と縦書きの時で、枠の補正方法がことなるのでは？」）。撮った物は `target\pasta-verify-alt\shots\alt2\2b-choice-hover.png`（「雨だよ」の列の反転）。
  - 帯の厚みとずれは、横書きの行の箱の寸法（ascent＋descent と行送り）から決めている。縦書きでも同じ値を横の向きにそのまま当てている見込み。クリックの当たりも同じ値から作るので、塗りと当たりが一緒にずれている見込み。
- **変えたいこと**:
  - 縦書き（右から左の列送り・左から右の列送り）の選択肢の反転の帯が、列と合い、列の字を横の向きの全幅で覆う。当たりの範囲も同じ所になる。
  - 横書きの帯は変えない。
  - ぱすたの縦書きのバルーンで、SSP と同じ形の反転になる。
- 詳細は同じフォルダの `brief.md`。

## Introduction

本 spec は、縦書きのバルーンで選択肢にマウスを乗せたときの反転の帯の **形（厚みと置く所）** を、列に合わせて直す。版は **v0.1.0**（ゴールの 2 つ目「ぱすたが SSP と同じに動く」）。

**用語**:

- **列**: 縦書きの 1 行。字は縦に並び、列は横へ並ぶ。
- **ブロックの軸**: 列が並ぶ向き（縦書きでは横の向き）。**列の幅**はこの向きの厚み。
- **行内の軸**: 字が並ぶ向き（縦書きでは縦の向き）。
- **帯**: マウスを乗せた選択肢を塗る四角（`cursor.style,square` の塗り）。
- **当たり**: マウスを乗せた・クリックしたと判じる範囲。

**今の形の確かめ（2026-10-23・main `15d8b0f3`）**:

- 帯の厚みと寄せは、行ごとに 1 度だけ決めて、塗りと当たりの両方へ同じ値を配っている（塗りと当たりが同じ源から出る形は、完了 spec の決め「ハイライト矩形＝ヒット矩形と同一」）。
- 厚みは「行の箱の寸法（ascent＋descent）を、em の丈と行送りのあいだに収める」、寄せは「行の箱の中央へ寄せる」。どちらも横書きの行の字の置き方に合わせて決めたもので、縦書きでも同じ式の値を横の向きに当てている。
- 塗る側の四角も、右から左の列送りと左から右の列送りで同じ足し算で横の位置を出している。原因が「値の決め方」か「値の当て方」か「両方」かは設計の段で決める（本書は形の決まりだけを書く）。
- 選択肢と同じ帯を、アンカー（`\_a`）の範囲も使っている。
- 今ある縦書きの帯の検査は左から右の列送り（`VerticalLr`）だけを見ている。ぱすたは右から左の列送り（`VerticalRl`）。

**SSP の基準**: ukadoc は `cursor.style`・`cursor.blendmethod`・`cursor.brush.color.*`・`cursor.pen.color.*` を書くが、縦書きの帯の寸法そのものは書いていない。ぱすたの測り（`ssp-measurement.md` 2 節の段 2）は、縦書きの選択肢に乗せたときの反転を撮っていない。よって SSP の MCP で測る（要件 4）。

## Boundary Context

- **In scope**:
  - 縦書き（右から左・左から右）の選択肢の帯の厚みと置く所。塗りと当たりの両方。
  - 同じ帯を使うアンカーの範囲の、縦書きでの帯の厚みと置く所。
  - スクロール・倍率・マウスが離れたときの消し残しの、縦書きでの扱い。
  - 右から左・左から右の両方の決定論のテスト。
  - SSP の MCP での測り（縦書きの選択肢に乗せたときの帯）。
  - ぱすたの縦書きのバルーンでの実機の確かめ。
- **Out of scope**:
  - 横書きの帯（変更 0）。
  - 縦書きの列の並べ方そのもの（列の位置・列送り・字の置き方。完了 `balloon-vertical-canon` の持ち分）。
  - 選択肢の前の `\![*]` の印（`script-small-tags`・崩れた所の表の 3）。
  - `cursor.*` の鍵の色・混ぜ方・描き方の範囲を広げること、選択肢のマーカーの見た目（`choice-marker-styling`）。帯の形が直った後の `cursor.*` の色と描き方の見比べ（`verification.md` 6 節の案 B）は本 spec の外。
  - 選択肢の範囲の関数をまとめること（`choice-ranges-one-function`）。
- **Adjacent expectations**:
  - `pasta-in-windows-verification` の回し直し（v0.1.0 の版の門）は、本 spec の着地の後に崩れ 23 を見直す。本 spec は、その見直しに使える実機の記録を残す（要件 6）。
  - `balloon-link-hover` はアンカーのリンクの見た目を扱う。本 spec はアンカーの帯の**形**だけを選択肢と揃え、リンクの見た目は変えない。
  - ぱすたの縦書きのバルーンは、ぱすたの書庫の直し（ghost_dev の `c32229e`・未リリース）で入る。それまでは手順書 `doc/pasta-real-run.md` の入れ方で入れる（働きの前提ではない）。
- **同じウェーブ（2026-10-23 C11）との約束**:
  - 触るのは emo-text の選択肢の帯の作り（`choice.rs`）と、今ある検査のファイル。原因しだいで、帯の四角を描く所・行の箱の寸法の所まで。
  - emo-text に新しいソースファイルを足さない（1 ウェーブに 1 本だけの席を使わない）。`choice_tests.rs`（上限の近く）に検査を足さない。1 ファイル 1,000 行を超えない。依存を足さない。

## Requirements

### Requirement 1: 縦書きの帯を列に合わせて塗る

**Objective:** As a ゴーストの利用者, I want 縦書きの選択肢に乗せたとき帯が列と合って字を全部覆う, so that どの選択肢を選ぼうとしているかが読める

#### Acceptance Criteria

1. While バルーンが縦書き（右から左の列送り）, when 利用者が選択肢の範囲にマウスを乗せた, the areka shall 帯をその選択肢の列に重ね、列の字のインクをブロックの軸の全幅で覆って塗る。
2. While バルーンが縦書き（左から右の列送り）, when 利用者が選択肢の範囲にマウスを乗せた, the areka shall 要件 1.1 と同じく、帯で列の字のインクをブロックの軸の全幅で覆って塗る。
3. While バルーンが縦書き, when 帯を塗る, the areka shall 帯の行内の軸の範囲を今と同じく選択肢の字の範囲とする（列の全長に広げない）。
4. While バルーンが縦書き, the areka shall 帯を隣の列の字のインクへかからせず、隣の列の帯とも重ねない。
5. Where 選択肢が折り返して複数の列にまたがる, the areka shall またいだ列ごとに、その列に合った帯を塗る。
6. Where 列の中に既定より大きい字（`\f[height,…]` など）が在る, the areka shall その列の厚みから帯の厚みを決め、大きい字のインクも帯で覆う。
7. Where アンカー（`\_a`）の範囲が選択肢と同じ帯で塗られる, the areka shall 縦書きのアンカーの帯にも要件 1.1〜1.6 と同じ形を使う（選択肢とアンカーで帯の形を分けない）。

### Requirement 2: 当たりを塗りと同じ所にする

**Objective:** As a ゴーストの利用者, I want 見えている帯の所をクリックすればその選択肢が選ばれる, so that 見た目と操作が食い違わない

#### Acceptance Criteria

1. While バルーンが縦書き, the areka shall 選択肢の当たりの範囲を、その選択肢の帯を塗る範囲と数値まで同じにする。
2. While バルーンが縦書き, when 利用者が帯の中の点（列の字のインクの上を含む）をクリックした, the areka shall その選択肢を選ぶ。
3. If 1 つの点が隣り合う 2 つの列の帯の境に在る, the areka shall その点をたかだか 1 つの選択肢にだけ当てる。

### Requirement 3: スクロール・倍率・消し残し

**Objective:** As a ゴーストの利用者, I want 縦書きで列を動かしても大きさを変えても帯が列についてくる, so that どの表示の状態でも帯が崩れない

#### Acceptance Criteria

1. While 縦書きのバルーンがブロックの軸の向きにスクロールしている, the areka shall 帯と当たりを、スクロールした後の列の位置に合わせる。
2. While バルーンが等倍でない合成の倍率（画面の DPI など）で出ている, the areka shall 縦書きの帯と当たりを、その倍率で出た列に合わせる。
3. When 縦書きで、マウスが選択肢から離れた、または別の選択肢へ移った, the areka shall 前の帯の塗りを 1 画素も残さず消す。

### Requirement 4: SSP の形に合わせる

**Objective:** As a バルーンの作者（ぱすた）, I want 縦書きの選択肢の反転が SSP と同じ形になる, so that 同じバルーンが areka と SSP で同じに見える

#### Acceptance Criteria

1. When 設計の段で縦書きの帯の形を決める, the 本 spec shall その前に、開発者の許しを得て SSP の MCP で、ぱすたの縦書きのバルーンの選択肢にマウスを乗せたときの帯を撮り、帯の両辺が列の字のインクと隣の列に対してどこに在るか（帯の幅・ずれ・列との合い方）を、撮った物の置き場と SSP の版と一緒に spec のフォルダの記録へ残す。
2. When ぱすたの縦書きのバルーンで選択肢にマウスを乗せた, the areka shall 要件 4.1 で測った SSP の帯と同じ形（列のどの辺からどの辺までを塗るか）で帯を塗る。
3. If 要件 4.1 で測った SSP の帯の形が要件 1 の決まり（列の字を全幅で覆う・隣の列にかからない）と食い違う, the 本 spec shall どちらに合わせるかを自分で選ばず、測った値を添えて開発者の決めを仰ぐ。
4. The 本 spec shall 帯の色・混ぜ方（`cursor.brush.color.*`・`cursor.blendmethod` など）を SSP と見比べる対象にしない（形だけを合わせる）。

### Requirement 5: 横書きを変えない

**Objective:** As a 横書きのバルーンの利用者, I want 横書きの帯が今のまま, so that 直っている所が崩れない

#### Acceptance Criteria

1. While バルーンが横書き, the areka shall 選択肢とアンカーの帯と当たりを、今と数値も画素も同じにする。
2. The 本 spec shall 横書きの帯と当たりの今ある検査を、1 本も消さず、ゆるめず、すべて通す。
3. The 本 spec shall 既定のフォント（行の箱が em の丈に等しいもの）の横書きの画素の一致の検査を 1 バイトも動かさない。

### Requirement 6: 検査と実機の確かめ

**Objective:** As a 開発者, I want 縦書きの帯の形が決定論のテストと実機の両方で確かめられている, so that 再び崩れたら気づけて、崩れ 23 を閉じられる

#### Acceptance Criteria

1. The 本 spec shall 右から左の列送りと左から右の列送りのそれぞれで、帯の塗り（実際の描画の読み戻し）が列の字のインクをブロックの軸の全幅で覆うことを、決定論のテストで確かめる。
2. The 本 spec shall 右から左の列送りと左から右の列送りのそれぞれで、当たりの範囲が帯の塗りと数値まで同じであることを、決定論のテストで確かめる。
3. The 本 spec shall 要件 6.1・6.2 のテストを、行の箱が em の丈より大きいフォント（和文フォントの比）で回し、比がちょうど 1 のフォントだけでは確かめたことにしない。
4. If 縦書きの帯を横書きと同じ決め方に戻した, the 要件 6.1・6.2 のテスト shall 赤になる（本 spec は、直しを外すと赤になることを 1 度確かめて記録に残す）。
5. When 実装の後に実機で確かめる, the 本 spec shall 開発者の許しを得て、ぱすたの縦書きのバルーン（ぱすたの新しい書庫か、`doc/pasta-real-run.md` の入れ方）で選択肢に乗せた帯を撮り、要件 4.1 の SSP の撮った物と並べて開発者の目視の判定（同じ／違う）を受け、撮った物の置き場と判定を spec のフォルダの記録へ残す。
6. If 実機の確かめで帯が SSP と違うと判じられた, the 本 spec shall 完了とせず、違いを直すか、開発者の決めを仰ぐ。
