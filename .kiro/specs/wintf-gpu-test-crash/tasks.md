## Implementation Notes

- **G1 裁定（2026-07-24・調査完了）**: 宣言 (b) テストハーネス固有 → **Path B（SharedGpuFixture・専用オーナースレッド）**採用。証拠は research.md「根本原因記録」節が正本。要点:
  - 根因＝H-env（bisect: `68bd2e3e~1` でも AV）。クラッシュ点＝**2 個目の `Compositor::new()`**（生成時・別スレッド）。トリガ＝「同一プロセスで**別スレッド上に 2 個目の MTA 束縛 Compositor** を生成」。**同一スレッド逐次再生成は安全**（統制実験・`wuc_graphics_resource_lifecycle` 緑）。teardown/明示ドレインは無関係（実験 b/c）。
  - **Path A（Task 4）は SKIP**（実験 c で明示ドレイン無効を実証）。
  - **安全再生成プロトコル**（Task 3/5/6 の正準手順）: WUC の生成・操作・破棄を**単一オーナースレッド上**に集約する。
- **Task 5（Path B）実装方針**: design.md C4（B1 形）どおり。専用オーナースレッドで WUC スタックを 1 個だけ生成し、テストはクロージャを marshal してオーナースレッド上で実行。graphics 8 ファイルの `setup_world()` を fixture 委譲へ置換（アサーション不変）。
- **Task 6（回帰檻 R5）の形態調整（重要・design.md C7 との差分）**: C7 形態(i)「独立 2 `#[test]`（別スレッド）」は素で実行すると**必ず AV**（＝根因そのもの）ゆえ緑にできない。**回帰檻は「同一オーナースレッド上での逐次再生成」（形態(ii)相当）を正準形とする**。別スレッド生成の再発は「共有 fixture をバイパスした WUC 生成 → プロセス AV → バイナリ失敗」で検出保証（R5.3 充足）。
- **Task 7（検証マトリクス）修正前ベースライン**: wintf visual=✅52 / wintf lib=✅517 / areka-emo-text lib=✅368 / areka-emo-text draw_readback=✅2 / areka-emo-present=未実測。落ちるのは graphics と areka bin のみ。緑バイナリは原則無改修（波及/委譲の要否は実測で判断）。areka bin（7.2）が赤なら同型のオーナースレッド委譲で是正。
- **波及（brief 追記㊹）**: Path B 採用 → 本 spec が graphics ハーネス構造を単独所有。W4 emo-dpi-scaling・W5 kero-balloon は本 spec 完了後に rebase 必須。
- **環境 quirk**: 本 worktree は submodule `vendors/pasta` 未 populate で起動。`git submodule update --init --recursive`（permission denied は retry で解決）が先行必須。workspace test は i686 host-32 成果物ビルドも先行必須（Task 7.8）。
