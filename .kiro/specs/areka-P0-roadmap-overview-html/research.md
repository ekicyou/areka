### 3.1 括弧の深さを数える読み手（1.1〜1.5・4.3〜4.5 の芯）

確かめた区切り方: 「＝**N 本**」（括弧の外で最後に現れるもの）で列を切り、その前だけを読む → 括弧の外の `／` で組に分ける → 組の中の括弧の外の最初の `＝` の前を見出しとする（見出しの無い組も在る）→ 括弧の外の `→` と `・` で並びを作る → 各要素の先頭のバッククォートを名前、続く括弧書きを注とする。この形で今の 8 段がすべて書かれた数と一致した。括弧として扱う字は `（）`・`〔〕`・`「」` の 3 組（`「」` の中にも `・` が在る）。

### 3.2 台帳の行の割り方（1.6・1.7・2.4）

バッククォートの中の `|` を区切りとして扱わない割り方にすれば、今の 114 行がすべて 7 列になる。GFM の表は本来バッククォートの中でも `|` で割る（`\|` で逃がす決まり）ので、GitHub の表示ではこの 1 行は崩れている。要件 4.1 は roadmap.md を直さないので、道具の側で吸収する（警告を出すかは議題 8）。

### 3.3 文字コードの検査と道具の書き方（6.3・6.7）

`encoding-check.ps1` の規則 A は、日本語の目印をスクリプトの字句に書くことを許さない。取れる形は 3 つ:

- 目印も文言と一緒に外のファイル（`strings.json`）へ置く。
- 目印だけ `"`u{7248}`u{306E}..."` の書き方でスクリプトに置く（`encoding-check.ps1` 自身が使う形）。読みにくい。
- 目印を ASCII の形（正規表現の `版` など）で書く。

どれでも規則 A は通る。文言（要件 6.7）は前例どおり json に置く。HTML の骨組み（CSS・JS）は ASCII で書けばスクリプトの中に置いてよいし、別のテンプレートのファイル（`.html`・規則 A の対象外）にしてもよい。

### 3.4 決定論（5.4）

- 書き出しは BOM なしの UTF-8・LF（release-notes の `WriteAllText` の形）。
- 表の順は roadmap.md に出る順と順序つきの表（`[ordered]`）で保つ。並べ替えが要るなら序数の比べ方（文化に依らない）を使う。
- データを JSON として `<script>` に入れるなら、`ConvertTo-Json -EscapeHandling EscapeHtml`（PowerShell 7 の標準）で `<`・`>`・`&`・`'` を逃がせば、台帳の文の中の `</script>` のような字で壊れない。HTML の地の文へ出すなら `[System.Net.WebUtility]::HtmlEncode`。どちらも標準で、依存は増えない。
- コミットの名前（要件 1.8）は入力の一部なので、同じコミットなら同じバイトになる。
