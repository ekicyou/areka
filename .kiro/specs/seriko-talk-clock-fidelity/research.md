## 3. 2 つの件の中身

### 3.1 件 8（0 で止まる天井）は今も届く

- 届く道: `settle_talk` は刻みの最後に `seen = max(seen, revealed_until(now))` とする。その後に置き直しの知らせ（後ろへ動く・`delta > 0`）が効く時刻より遅れて届くと、`shift_after` が効く時刻より後の字を後ろへ動かし、**数え済みの字の一部が今より後ろ**になる（`revealed_until(now) < seen`）。この間に消去が届くと、`restart_chain(at)` が後ろへ動いた数え済みの字を捨て、`dropped = seen − total > 0`。
- 天井に触れる条件: `base < dropped`。台詞の頭の全消去の直後に構えた面は `base = 0` なので、**数えた字が 1 つでも後ろへ動いて捨てられれば必ず触れる**（例: `base = 0`・`seen = 5`・`total = 3` → 数えた数が 5 から 3 へ減る。`talk,3` なら次の区切りが 1 文字目から 3 文字分遅れる）。
- 「刻みの間に構えた直後（数えた数 0）」の側は `base = seen` かつ `dropped = seen − total ≤ seen = base` なので触れない（コメントの見立てどおり）。
- 問い合わせる序数は負にならない: 区切り k が尋ねられるのは前の数え済み以後なので、序数 `seen − 数えた数 + k × every − 1 ≥ seen` が成り立つ。符号が要るのは途中の引き算だけ。

### 3.2 件 5（列の単位の違い）は「仮の話」ではない

`chunk_reveal_offsets` は、前の字 p（塊の頭からの隔たり）が `p + D/n ≥ 0`（前の字に 1 字分の間隔を足すと塊の頭に届く＝塊が重なる）のときだけ「前の字の続き」になり、そうでなければ塊の頭から並べる。両者の時刻の差は `p + D/n` で、続きでなければ 0。だから **seriko と文字の層の時刻がずれるのは「前の字」が両者で違い、かつ片方が重なりの側に入るときだけ**である。

今のコンパイラの出す合図（字は 1 字 50 ms・`Text` の後は書き出しの時刻が D だけ進む・`Choice`・印・`\s`・`\b` は長さ 0 で書き出しの時刻を進めない）を当てると:

1. **字だけを場所をまたいで出す台詞は、今は差が出ない**。前の塊の最後の字は次の塊の頭のちょうど 50 ms 前（`p = −50`・`p + D/n = 0`）で、続きでも頭からでも同じ時刻になる。brief の見立てどおり。
2. **長さ 0 の字（選択肢・印）の直後に、同じ時刻で別の場所へ字が出ると、今でも 50 ms ずれる**。例: 面 10 に箱が在るシェルで `\s[10]\q[はい,yes]\s[0]つづき`。選択肢の字は箱に時刻 T で出る。`\s[0]`（箱の無い面）で行き先が普通のバルーンへ戻り、「つづき」が同じ T に出る。seriko の前の字は選択肢の T（`p = 0`）なので続きになり、字は T+50・T+100・T+150。文字の層の普通のバルーンの前の字はそれより前（`p ≤ −50`）なので頭から並べ、T・T+50・T+100。**口が画面より 50 ms 遅れる**。
3. 後続の `sakura-time-directives`・`talk-fast-forward` が塊ごとに速さを変えると、遅い塊が速い塊の直後に別の場所で始まるだけで差が出る（`p + D/n > 0` の側に入りやすくなる）。

**決定論のテストで今でも再現できる**: 1.3 の足場に箱の表を入れ、2 の台本（または手で組んだ合図の列）を通せば、文字の層の字の時刻と seriko の口の始まりの食い違いが赤で出る。合図を手で組めば、3 の「塊ごとの速さ」も今の台本の機能を待たずに通せる。

### 3.3 範囲の外で見つけたこと: 印（`\![*]`・`%*`）の字の食い違い（1 つの場所で今起きる）

文字の層は印の合図を目印の字 1 つとして列に積み、時刻の鎖に入れる（`state.rs` 579〜587 行）。seriko の `observe_cue` は `Custom` を読まないので、印は列に入らない。その結果:

- 台本 `あ\![*]いう`（印は長さ 0・書き出しの時刻 50）: 文字の層は「あ」0・印 50・「い」100・「う」150（印の時刻 50 が「い」の塊の頭と等しく `p = 0` なので続きになる）。seriko は「あ」0・「い」50・「う」100。**印より後の字が、文字の層では seriko より 50 ms 遅く出る**。50 ms 以上の待ちが挟まるまで、この差は後ろの塊へ持ち越される。
- 数えの単位も違う: 文字の層の列では印が 1 字、seriko は数えない。台帳の note は数える物（書記素クラスタ・選択肢の字）と数えない物（改行・消去・待ち）を挙げ、印には触れていない（正典も沈黙）。
- `\![*]` は行の頭の目印として書かれるので、`talk` を持つシェルで普通に踏む。要件 2 は「場所をまたぐ」場面だけを書いているので、この件は今の要件の外にある。seriko の側だけで直せる（`observe_cue` で印を長さ 0 の字として列に積む・`looper.rs` と `talk.rs`）。数えに入れるかは別の決め（数えに入れないなら、時刻の鎖にだけ入り数えに入らない字という区別が列に要る）。
- 付け足し: 印が後ろの字を 50 ms 押すこと自体（台本の時刻の線より文字の層の字が遅れていく）は文字の層の式の話で、本 spec の範囲（文字の層の結果を変えない）の外。直すべきかは文字の層の側の判断になる。

## 6. 設計の段へ渡すこと

### 推す形（作業の量を根拠にしない）
- 件 8 は **1-A（数えた数を持つ）**。要件 1.1 をそのまま型が保ち、天井という形自体が無くなる。1-B も同じ結果になる。1-C は採れない。
- 件 5 は **2-A（行き先の決め方を 1 本の純粋な型にして両方が使う）**。字の時刻の式を 1 本にした先例と同じ向きで、要件 2 を全部解き、文字の層の結果を変えない。ただしウェーブ C28 の約束の外に出る（下の 3）。

### 調べが要ること（Research Needed）
1. 3.2 の 2（選択肢の後で場所を替えた字）と 3.3（印の後の字）の食い違いを、1.3 の足場で赤のテストとして立てて確かめる（本書の数値は手で求めたもの）。

## 7. 決めの議題（要件の討議へ）

1. **件 5 を直すか、記録して閉じるか（OPEN QUESTION 1・仮定 A）**: 今のコンパイラでも、長さ 0 の字（選択肢・印）の直後に同じ時刻で別の場所へ字が出ると、口が画面より 50 ms 遅れる（3.2 の 2）。閉じるなら「差が出ない理由」ではなく「差が出る条件と大きさ」を記録し、その差を受け入れる決めになる。推す＝直す（2-A）。
2. **直すときの形（2-A／2-B／2-C／2-D）**: 推す＝2-A（行き先の決め方を下のクレートの純粋な型にして文字の層と seriko が使い、箱の表をシェルの差し替えの依頼で seriko へ渡す）。2-D は要件の境界を改めることになり、場所だけの消去が解けずに残る。
3. **ウェーブ C28 の約束の外に出ること（OPEN QUESTION 2）**: 2-A も 2-B も、箱の表を seriko へ運ぶ配線（seriko の `actor.rs`・`areka-runtime` の `frame/switch.rs` と起動の所・そのテスト）を要し、2-A はさらに emo-text の `state_route.rs` と共有の型の置き場に及ぶ。約束は「seriko の `trigger.rs`（送りの持ち方を直すなら `looper.rs`）」。兄弟のセッションと触るファイルを突き合わせて進めるか、件 5 の直しをこのウェーブの後へ送るか。
4. **印（`\![*]`・`%*`）の字の食い違い（範囲の外で見つけた）**: 1 つの場所で今起きる（印の後の字が文字の層で 50 ms 遅い・数えの単位も違う）。本 spec の要件に足すか（3-A）、別に起票するか（3-B）。足すなら、印を `talk` の数えに入れるか（正典は沈黙・SSP の MCP で測ってから決める）。
5. **件 8 の型（1-A 数えた数を持つ／1-B 数え始めを符号つきに）**: どちらも要件 1 を満たす。推す＝1-A。設計の段で決めてよい細部。
6. **箱の字を数えに入れるか（OPEN QUESTION 3・仮定 B）**: 今の振る舞いは入れる。箱が出ていない間の字も含めて入れ続けるか。
7. **実機の確かめを要件にしないこと（OPEN QUESTION 4・仮定 C）**: 置き直しの知らせが遅れて届く道は実機で狙えない。決定論のテストと静的な証跡で足りる。議題 4 で SSP を測るなら、それは決めのための測りで、本 spec の判定の証跡ではない。
8. **台帳の note の古い文の直し（OPEN QUESTION 5・仮定 D）**: 今のコード（`trigger.rs` の冒頭の doc と `next_starts`）が「越えた区切りを古い順に全部」であることを確かめた。直すことに障りは無い。

## 8. 要件の討議の決め（2026-11-27・推奨どおり一括承認）

1. 件 5 は直す（記録して閉じない）。
2. 直し方は 2-A（行き先の決め方を 1 つの型にして文字の層と seriko が使う）を前提に設計する。ウェーブ C28 の約束の外に出ることを認め、設計の段で触るファイルを全部挙げて `draw-methods-canon`・`talk-script-metadata` と突き合わせる。

## 9. 設計の段の調べと決め（2026-11-27）

> 進め方: 軽い調べ（既存の仕組みの拡張）。`kiro-spec-design` の規則（設計の原則・軽い調べ・まとめ・設計の関門）だけを使った。外部の依存は足さないので外の調べはしていない。

### 9.1 調べたこと

- **50 ms の食い違いの確かめ（§3.2 の 2・§3.3）**: `areka_sakura::reveal::chunk_reveal_offsets` の本文と、コンパイラが選択肢・`\!` の汎用の合図（印 `\![*]`・`%*` を含む）を長さ 0・書き出しの時刻を進めずに出すこと（`compile.rs` の `Instruction::Choice`・`Instruction::GenericCommand`）を読み、手で求め直した。`\s[10]\q[はい,yes]\s[0]つづき` は seriko が T+50・T+100・T+150、文字の層が T・T+50・T+100（口が 50 ms 遅い）。`あ\![*]いう` は文字の層が「い」100・「う」150、seriko が 50・100（口が 50 ms 早い）。どちらも §3 の見立てどおり。テストは回していない（設計の対のテストが赤で確かめる）。
- **`\s` の答えの同じさ（§6 の 3）**: 文字の層の閉包は `ShellBoxAssets` の別名の写しから seriko と同じ `SurfaceResolver` を組み、面の表に無い番号を「解決できない」にする（`shell_box_assets.rs` の `resolve_for_text`）。seriko の表示は面の表で絞らず `Show(id)` を当てる。行き先を求めるときは前者の規則が要るので、規則を seriko の `SurfaceTarget::for_text` へ移し、文字の層の閉包もそれを呼ぶ形にした。seriko は面の番号の集合も要る（シェルの差し替えでは `ShellSurfaceFallback.surface_ids` に在るが、起動の構成には無い）。
- **箱の表を渡す所（§6 の 4）**: `SerikoLoopConfig { … }` を直に組む所は本番 2（`areka-runtime/src/lib.rs`・seriko の `settle.rs`）とテスト 20 ファイル（seriko 17・runtime 2・本体 1）。`SerikoReplace::Shell { … }` を直に組む所は本番 1（`frame/switch.rs`）とテスト 3。`observe_cue` を直に呼ぶテストは `looper_talk_tests.rs` だけ。`TalkWindow` を直に組むテストは `trigger_tests.rs`・`parts_trigger_tests.rs`。
- **兄弟のセッションの触るファイル**: `draw-methods-canon`（`claude/kiro-start-draw-methods-canon-bee12e` の requirements・research）は emo-compose の多くのファイル・emo-present・emo-atlas・seriko の `table.rs` のテストの期待・runtime の `frame/wiring.rs`・`balloon_background.rs`・本体の書き出し・wintf。`talk-script-metadata`（`claude/kiro-start-talk-script-metadata-54c924`）は `areka-sakura` の `drive.rs`・`contract.rs`・`areka-ghost` の `config.rs`・`areka-session` の readme と起動・`StartTalk { … }` を組むテスト（seriko の `tests/common/mod.rs` を含む）。重なりうるのは emo-compose の `lib.rs` の宣言の行だけ。
- **文字の層の行き先が始まる時**: 文字の層の行き先の番号は `\s` が届くまで「無し」（普通のバルーン）。`set_box_layout` は装着の相とシェルの切替で必ず呼ばれる（`frame/attach.rs`・`frame/switch.rs` の `hand_to`）。seriko も起動の時は番号を持たないので同じになる。
- **SSP での印の数え（§6 の 2・要件 2.8）**: 測っていない。`talk` を持つシェルで口のコマの時刻を字ごとに見る必要があり、画面の操作の順取りと兄弟への知らせが要るため、設計の討議の議題に回した。

### 9.2 まとめ（一般化・作るか使うか・削る）

- **一般化**: 件 5 と印の件は「seriko の前の字が文字の層の前の字と違う」という同じ問題の 2 つの形。前の字を場所ごとに持ち、印を「前の字だけを進め、序数を作らない字」として扱えば、どちらも同じ式の同じ入力で解ける。件 8 と場所だけの消去も「捨てた字の序数の列で数えを揃える」1 つの形にまとまる（総数で揃える形は、捨てる字が列の末尾に並ぶときだけ成り立つ特別な場合）。
- **作るか使うか**: 外の物で置き換えられる所は無い。行き先の規則は今の `state_route.rs` を下のクレートへ移すだけで、新しい規則を作らない。
- **削る**: 新しい合図・新しい受け口は作らない（箱の表は今の差し替えの依頼と起動の構成に欄を 1 つ足すだけ）。行き先の状態は seriko の字の列が持ち、別の表を作らない。emo-text に新しいファイルを足さない。`TalkFeed` の `push_chunk`・`push_text`・`restart_chain` の名と引数を保ち、場所が 1 つの既存のテストを変えずに通す。

### 9.3 決め

| 決め | 選んだ形 | 選ばなかった形と理由 |
|---|---|---|
| 件 8 の型 | 1-A: `TalkCursor { seen, counted }`。揃えは `seen` を捨てた分だけ下げ、`counted` に触れない | 1-B（数え始めを符号つき）は同じ答えだが、符号つきと符号なしの混ざる式が残る。1-C は §4.1 のとおり採れない |
| 共有の型の置き場 | `areka-emo-compose` の新しいファイル `text_route.rs`（`BoxName`・`BoxLayout` の持ち主・両方が依存済み） | `areka-sakura` は台本の層で箱を知らず、置くと台本の層が描画の層へ依存する |
| 型の形 | スコープ 1 つの `TextRoute`（鍵の表は呼び手）。`TextPlace`・`SurfaceKeyOutcome` も同じ所へ移し、emo-text は名を再び出す | 鍵の表まで持つ型は `ActorKey`（`areka-sakura`）が要り、emo-compose に依存が増える |
| 場所をまたぐ序数 | スコープで 1 本・時刻の順 | 届いた順は、時刻が前後する字で区切りの時刻が逆転する |
| 印 | 行き先の場所の前の字だけを進め、序数を作らない（要件の討議の決め） | 序数を作って数えない印を付けると、数えと序数の決まりが 2 本になる |
| `\s` の答え | `SurfaceTarget::for_text` を seriko に置き、文字の層の閉包も呼ぶ | runtime に残すと seriko から呼べず、2 つ目の写しになる |
| 名前の形の `\b` の見分け | `TextRoute::is_box_key` を両方が呼ぶ（emo-text の `state.rs` の腕の条件 1 行） | seriko で同じ条件を書き写すと写しが増える |
| 印の見分け | seriko は `areka_parsers::sakura::MARKER_COMMAND` と名前で比べる（seriko が `bind` を見分けるのと同じ形） | emo-text の `is_marker_carrier` は seriko から呼べない。`areka-sakura` へ出すと兄弟の `lib.rs` と重なりうる |
| 門が閉じている間 | `\s` も追わない。門が開いた差し替えの直後に seriko の表示中の面から種を蒔く（仮定・設計の議題 1） | 門に関わらず追う形は要件 4.1 の字面から外れる |
| シェルの切替 | 最後の刻みの時刻より後に現れる箱の字を捨て、箱の場所の前の字を無しにし、行き先を既定と戻り先へ（仮定・設計の議題 2） | 捨てない形は、画面に出ない箱の字で口が動く |
| 振り分けの置き場 | `looper_trigger.rs`（`looper.rs` は 855 行で 1,000 行の手前） | `looper.rs` に置くと上限に近づく |
