# Implementation Plan

> 進め方の決まり（全タスク共通）:
> - GPU の檻は実 GPU で回す。游ゴシック・Yu Gothic UI が無い机では今の型（`assert_real_font_present`）どおり赤で止める。
> - 失敗の経路は `error!`＋`Err`（記録の無い失敗の経路を作らない）。新しいソースファイル・新しい依存は 0。
> - 同じウェーブ（C12）の約束で触らないと決めた所（`viewbox_draw_render.rs`・`layout.rs`）に触るタスクは、触る前に同じウェーブのほかのセッションへ知らせる（要件 5.3）。

- [ ] 1. 名前から顔を解く（家族名 → GDI の名前）
- [x] 1.1 顔の値と、太字・斜体の重ね方の規則を作る
  - 家族名・太さ・幅・斜体を DirectWrite の型のまま持つ顔の値と、家族名で当たった候補用の Regular の顔を作る
  - 太字の指定は「名前の太さと BOLD の大きい方」、指定が無ければ名前の太さ。斜体の指定は ITALIC、無ければ名前の斜体
  - 檻 U7: Regular・Medium・Light・Black × 太字の有無、Regular・斜体の顔 × 斜体の有無の表がすべて期待どおりで緑（中太＋太字は 700・Black＋太字は 900）
  - _Requirements: 4.2, 4.3, 4.4, 4.5_
- [x] 1.2 フォント台帳に GDI の名前での引き直しを足す
  - 候補ごとに「ファイル名なら読み飛ばし → 家族名で在れば Regular の顔 → 無ければ GDI の名前として引き、在ればその家族・太さ・幅・斜体」の順で、最初に当たった候補を採る
  - 台帳の生成時に GDI 互換の口を 1 度だけ取る（失敗は `error!`＋`Err`）。見つからない名前は次の候補へ（記録しない）、想定外の失敗は `error!` を残して次の候補へ、31 単位を超える候補は GDI では引かない（`debug!`）
  - 記憶を「候補列 → 顔（または無し）」にし、顔を返す口・家族名だけ返す口・全滅なら既定（ＭＳ ゴシック Regular）・全滅なら渡した顔、の 4 つの口を揃える。全滅の `warn!` は今のまま 1 度
  - 偽の台帳に「GDI の名前（小文字）→ 顔」の表を足し、今の家族名だけの偽の台帳はそれへの委譲として残す（今のテストは書き替えない）
  - 檻 U1〜U6（家族名で当たる・GDI で当たる・書いた順・大小を問わない・全滅とファイル名・2 度目は問い合わせない）と、実際の書体の集まりの檻 R1（「Yu Gothic Medium」「游ゴシック Medium」「yu gothic medium」が 500・ぱすたの候補列が 500・無い名前だけの列は無し）が緑
  - 切り替えの設定も新しい名前の書き方も設けない。number・sstpmessage・communicatebox の表示が後で同じ台帳を通せば同じ引き直しが効く形（共有の唯一の入口）を保つ
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8, 3.9, 3.11, 4.7, 6.2, 6.3_
- [ ] 1.3 解決した顔を束縛のフォントに載せる
  - 解決済みフォントに顔の欄を足し、組み立ての 1 か所では未解決の Regular の顔を入れ、台帳の `pick` が解決した顔と家族名へ差し替える
  - crate 内のテスト補助で解決済みフォントを組む所を追随させる（構築口は 1 か所のまま）
  - 檻 U8: ぱすたの候補列（偽の GDI の表に「游ゴシック medium」）で `pick` の家族名が「Yu Gothic」相当・顔の太さが 500 になり緑
  - _Requirements: 3.2, 3.10_

- [ ] 2. 書式に顔と太字・斜体を通す
- [ ] 2.1 書式を作る唯一の関数を「顔＋太字・斜体の指定」で作る形にし、既定の見た目の太字・斜体を束縛書式へ焼く
  - 書式の生成は顔の家族名・規則どおりの太さと斜体・顔の幅・locale ja-JP で行う。束縛書式は既定の見た目の太字・斜体を渡し、失敗時の既定フォントでの再試行も同じ太字・斜体を渡す
  - 書字方向は今のまま方向レシピの 1 行だけで効く（書字方向の字面の檻を保つ）
  - 家族名が DirectWrite へ渡る入口の字面の檻（922 行の書式と計測の試験のファイル）は照らす字面を新しい呼び方へ直すだけで、行を足さない
  - 檻 F1: ぱすたの候補列に束縛した計測器の束縛書式が太さ 500、バルーン定義に `font.bold,1` を足すと 700、`font.italic,1` を足すと ITALIC で緑
  - _Requirements: 3.2, 3.10, 4.8, 4.9_
- [ ] 2.2 装飾の区間の範囲指定を顔で考える形にする
  - 束縛の顔は `pick` と同じ規則で引く。区間の名前が既定と違えば「区間の候補列の顔、全滅なら束縛の顔」を使い、家族名と（束縛と違えば）幅を焼く
  - 太さ・斜体は「区間の顔＋区間の太字・斜体」と「束縛の顔＋既定の太字・斜体」を同じ規則で比べ、違えば焼く。大きさ・打ち消し線・範囲指定の数え方・失敗の扱い・署名は今のまま
  - 檻 D1（GDI の名前の区間が家族「Yu Gothic」・500、区間の外は束縛のまま）、D2（束縛が中太・既定が太字の行の `\f[bold,0]` が 500、Regular の家族名の区間は 400）、D3（幅の違う GDI の顔は幅を焼く・全滅の区間名は束縛の顔のまま範囲指定 0 回）が緑
  - 2.3 の檻 F4 の後半（全滅の区間を含む行の cluster の幅）はこの範囲指定に頼るので、2.3 より先に行う

  - 計測器の生成時に束縛の顔を覚え、計測鍵の書式は「鍵の候補列の顔、全滅なら束縛の顔」と鍵の太字・斜体で共用の関数から作る（設定の字面の写しを消す）。鍵と書式の記憶の形は変えない
  - 完了 spec が決めていた「全滅は ＭＳ ゴシックで測る」を「束縛の顔で測る」へ上書きする
  - 檻 F2（「Yu Gothic Medium」の鍵が 500・太字の鍵が 700・斜体の鍵が ITALIC）、F3（GDI の名前の鍵で測った英字の送り幅が同じ書式の行の cluster の幅と一致）、F4（束縛が中太で全滅の鍵が束縛の家族名・500、太字の鍵は 700、その区間を含む行の cluster の幅と 1 字の計測が一致）が緑

## Implementation Notes

- テストの絞り込み語は `draw_catalog` では 0 件（モジュールの道は `draw::catalog::tests`）。`cargo test -p areka-emo-text --lib catalog` を使う。
- `cargo clippy -p areka-emo-text --all-targets -- -D warnings` は触っていない `dola` と crate 内の既存の指摘（rustc 1.99.1 の新しい lint・約 45 件）で落ちる。判定は `--no-deps` で「触ったファイルに新しい指摘が無いこと」。既存の指摘は本 spec の外（完了の棚卸で扱う）。
- 1.1 の `FontFace` に付けた `#[allow(dead_code, reason = …)]` 2 か所は、1.2 で使い始めたら外す。
- 1.2 の後、ぱすたの候補列の `pick` の家族名は「Yu Gothic」（GDI の名前で当たった顔の GetFamilyNames の 0 番目）。`viewbox_draw_vertical_band_readback_tests.rs` の `R_FONTS` の期待値をそれに合わせた。
