# Requirements Document

## Project Description (Input)
同じマシンで実装の Claude セッションを何本も並べて進める開発者が困っている。並んだセッションが全体テスト（`tools/test-all.ps1`）や実機の UI テスト（`areka.exe` やゴーストを実際のデスクトップに立てる・`SendInput` や computer-use で操作する）を同時に回すと、areka が 2 つ立って窓・入力・前面を取り合い、全体テストどうしはメモリとビルドを取り合って偽の赤が出る。今の机の貸し出しのアプリ `areka-impl-watch.exe` で防ごうとすると、負荷テストの机を取るしかなく、ほかの参加者全員に停止要請が出て実装まで止まる（2026-10-17 に一度そう直して、開発者が差し戻した）。開発者の模型（2026-10-17）どおりに、机を「実装の机」「排他テストの机」「マージの机」の 3 種類に組み直し、1 回の申し込みで欲しい机を並べて全部そろったときに一度に渡す形にする。机を使うスキル（`kiro-impl`・`kiro-complete`・`release`）は、全体テストと UI テストの間だけ排他テストの机を取り、ほかのセッションの実装は止めない。

## Introduction

`areka-impl-watch` は、同じマシンで並んで走る実装セッションに机を貸し出すコンソールアプリである（完了した `impl-watch`・`impl-watch-skills`・`impl-watch-residue` が作った）。今の机は「マージの机」（リポジトリごとに 1 つ）と「負荷テストの机」（マシンに 1 つ・取るとほかの全員に停止要請を出す）の 2 種類で、全体テストと実機の UI テストを 1 本ずつにする机が無い。この spec は、開発者が決めた次の模型をアプリの状態・番の決め方・呼び方・表示と、机を使うスキルの段へ落とす。

机の模型（2026-10-17 開発者の指示・この spec の正本）:

| 机 | 数 | 乗り方 |
|---|---|---|
| 実装の机 | マシンに 1 つ | 実装が走る机。実装はいくつ乗ってもよい。負荷テストがひとり占めできる |
| 排他テストの机 | マシンに 1 つ | 同時に 1 人だけ。全体テスト・UI テストを回す者が取る |
| マージの机 | リポジトリに 1 つ | マージの作業が取る |

| する事 | 取る机 |
|---|---|
| 実装 | 実装の机に乗れたら実装する |
| 全体テスト・UI テスト | 排他テストの机 |
| 負荷テスト | 排他テストの机と、実装の机のひとり占め（ほかの全員を止める） |
| areka のマージ | マージの机と、全体テストをするので排他テストの机 |
| pasta のマージ | マージの机だけ |

この文書で使う言葉（今の手順書 `doc/impl-watch.md` の言葉を引き継ぐ）:
- **参加者**・**識別**・**持ち主**・**待ち行列**・**停止要請**・**見張り**・**再開**: 今の手順書と同じ意味。
- **実装の机に乗る**: 参加者が「作業中」でいること。今の「参加」と「停止要請」は、この机への乗り降りとして読み替える（見張りを立てて参加した参加者は、実装の机に乗っている）。
- **実装の机のひとり占め**: 実装の机の上の、ほかの参加者全員に停止要請を出し、全員が「止まった」ところで受け取る持ち方。今の負荷テストの机の停止要請・止まった・再開の仕組みをそのまま使う。
- **申し込み**: 欲しい机を 1 つ以上並べて番を待つこと。**返す**: 持っている机を空けること。
- **全体テスト**: ワークスペース全体のテスト（`tools/test-all.ps1` を、どの引数でも回すこと。`/kiro-validate-impl` が回すものを含む）。
- **UI テスト**: areka・ゴースト・窓を実際のデスクトップに立てる、または `SendInput`・computer-use で入力や画面を操作するテストや確かめ（Requirement 9 で基準を決める）。
- **負荷テスト**: 静かな CPU での計測・わざと負荷をかける再現・時間の比べ（今の `kiro-impl` の定義のまま）。

原則（今の机の道具の決まりを引き継ぐ）: **トークンの負荷を最優先に抑える。** 待ちは「番が来たら終わるコマンド」1 本で、見回りや時間で回すループを足さない。端末へ出す文は ASCII の数行と終了コードだけ。

### 要件の段で選んだこと（brief の「要件の段で決めること」への答え・要件の討議で確かめる）

1. **複数の机の申し込みの細部**: 1 回の申し込みに机を 1 つ以上並べ、全部そろって渡せるときに一度に渡す（Requirement 2）。並べられるのは排他テストの机と実装の机のひとり占めだけで、マージの机は今の `merge` でだけ申し込み、ほかの机と並べない（要件の討議 議題 1 で確定。使うスキルが無い形のために、マージの順と追い越しを列をまたいで重ねる決まりを作らない）。同じ机を 2 度並べたら使い方の誤り。番は申し込みの早い順に見て、渡せる最初の申し込みに渡し、渡せない申し込みは後の申し込みを止めない（追い越しを許す。Requirement 3）。追い越しを許さないと、負荷テストが「ほかの全員が止まる」のを待つ間、停止要請を受けたセッションが今のタスクの UI テストを回せず、切れ目まで進めないので、互いに待って止まる。机を持ったまま別の机を申し込めるのは「マージの机を持つ者が排他テストの机を申し込む」ときだけにする（Requirement 4）。今の `merge`・`merged` の呼び方はそのまま残す（pasta のマージの手順を直さずに済む。Requirement 7）。ほかのコマンドを残すか 1 つの申し込みのコマンドへまとめるかは設計で決める。
2. **pasta のマージと負荷テスト**: 今の決まりを残す（マージの机の持ち主・待つ者には停止要請を出さない・負荷テストが持たれている・待たれている間はどのリポジトリでも新しいマージを始めない・マージの持ち主が居る間は負荷テストを渡さない。Requirement 5）。負荷テストが守るのは静かな CPU で、pasta のマージの作業もその妨げになるため。
3. **areka のマージで排他テストの机を持つ長さ**: 完了の手順の全体テスト（とその回し直し）の間だけ（brief の推し。Requirement 11）。マージの机は今どおり手順の全部で持つ。
4. **「全体テスト・UI テスト」の判定の基準**: Requirement 9 のとおり。クレートのテスト（`--ignored` を付けない `cargo test -p`）・clippy・整形・ビルドは数えない（実装の机の上で回る）。
5. **`/release` の机**: 全体テストと起動の確かめ（窓を出す）の間だけ排他テストの机を取る。マージの机は取らない（`release` は roadmap も台帳も触らず、main が動いたときの取り込みと確かめ直しを手順の中にすでに持つ。Requirement 12）。

規模の見立て: アプリ 8〜11・スキルと手順書 4・実機の確かめ 1 で 13〜16 タスク（ギャップ分析の見立てに合わせた。20 を超えないので 1 本のまま）。

## Boundary Context

- **In scope**:
  - `areka-impl-watch` の机を 3 種類に組み直すこと（状態・番の決め方・複数の机の一度の申し込み・持ちながらの申し込みと一部の返し方・落ちた参加者の後始末・呼び方・終了コード・`status` と `status.md` の表示・状態ファイルの版と古い実行ファイルとの混在の扱い）。
  - 常時テスト（決定論）と、明示したときだけ走る実機テスト。
  - 手順書 `doc/impl-watch.md` の机の表・決まり・呼び方・終わり方・スキルからの呼び方・判定の基準・更新の注意。
  - スキル `kiro-impl`・`kiro-complete`・`release` の机の段と、`kiro-watch-clear` の説明文の机の語（呼び方は変えない）。
  - 「全体テスト・UI テスト」と「負荷テスト」の判定の基準。
- **Out of scope**:
  - 全体テストのスクリプト `tools/test-all.ps1` の中身。
  - 実機の UI テストそのものの直し（テストの中で areka を 1 つに限る仕組み など）。
  - pasta のリポジトリのスキルの中身（マージの机だけを取る今の形のまま。今の呼び方が残るので知らせも要らない）。
  - 実行ファイルの置き方の道具 `tools/impl-watch-install.ps1`（版が上がったら入れ直すだけ）。
  - `areka-impl-watch` を使わない手作業のテストや、ほかのリポジトリの道具。
  - 古い形の状態ファイルを新しい形へ移す仕組み（今どおり `clear` でやり直す。Requirement 7）。
  - 机の種類をこの 3 種類より増やすこと。
  - スキル `kiro-validate-impl`・`kiro-review` の文（`kiro-impl` の側で覆う。Requirement 10.7・10.8）。
  - マージの机をほかの机と 1 回で並べる申し込み（Requirement 2.1）。
- **Adjacent expectations**:
  - 棚卸のスキル `kiro-next`（`clear --repo`）と `kiro-watch-clear`（`clear` と `status`）は今の呼び方のまま動く。`kiro-next` は直さない。`kiro-watch-clear` は説明文の「負荷テストの机」の語だけを 3 つの机に合わせる。
  - 机は助けである。使えないとき（環境変数が無い・実行ファイルが無い・直らない失敗）は、どのスキルも今と同じく机の段を飛ばして作業を続け、訳を最後の報告に残す。
  - 負荷テストや実機の走行を使うこれからの spec（`areka-test-binary-stability`・`present-emit-tail-latency`・`install-live-target-hazards`・`real-run-input-guard-observations` など）は、この机が着地した後なら番を取って回せる。それらの brief に机の古い呼び方が書かれていれば合わせる（2026-10-18 の時点で 0 件）。
  - steering の `structure.md` の `areka-impl-watch` の節（「机は 2 種類」の記述）は、完了の手順の文書の同期で合わせる。
  - 実機テストの子プロセスの置き場所は、ワークツリーの `target\` の下の Windows 形の絶対パスで上書きする（開発者の機械には本物の置き場所が環境変数で設定されている）。

## Requirements

### Requirement 1: 3 つの机
**Objective:** As a 開発者, I want 机が実装の机・排他テストの机・マージの机の 3 種類になる, so that 全体テストや UI テストを 1 本ずつにしても、ほかのセッションの実装が止まらない

#### Acceptance Criteria
1. The areka-impl-watch shall マシンに 1 つの実装の机、マシンに 1 つの排他テストの机、リポジトリごとに 1 つのマージの机を持つ。
2. The areka-impl-watch shall 「作業中」の参加者全員を実装の机に乗っている者として扱い、乗る人数に上限を設けない。
3. While 排他テストの机に持ち主が居る, the areka-impl-watch shall 別の参加者を排他テストの机の持ち主にしない。
4. The areka-impl-watch shall 排他テストの机を渡すこと・待つこと・持つことのどれによっても、停止要請を出さない（全体テストや UI テストの番を待つ間も持つ間も、ほかの参加者は作業中のまま）。
5. The areka-impl-watch shall 机の決まりをリポジトリの名前によって変えない（areka と pasta の違いは、呼ぶ側が申し込みに並べる机の違いだけで出る）。
6. The areka-impl-watch shall 今の負荷テストの机を「排他テストの机」と「実装の机のひとり占め」の組として表し、負荷テストの机という別の机を持たない。

### Requirement 2: 複数の机の申し込み
**Objective:** As a 机を使うセッション, I want 1 回の申し込みに欲しい机を並べ、全部そろったときに一度に受け取れる, so that 一部だけ持って待つことが無く、2 つの机を取る者どうしが互いに待って止まらない

#### Acceptance Criteria
1. When 参加者が机を 1 つ以上（排他テストの机・実装の机のひとり占めの中から）並べて申し込んだ, the areka-impl-watch shall 1 つの申し込みとして、申し込みの時刻とともに待ち行列に加える（参加していない識別の申し込みは、今どおり参加の申し出を兼ねる。マージの机は今のマージの申し込みでだけ申し込み、この申し込みには並べない）。
2. While 申し込みに並べた机のどれかが渡せない, the areka-impl-watch shall その申し込みにどの机も渡さない（一部だけを先に渡さない）。
3. When 申し込みに並べた机が全部渡せるようになった, the areka-impl-watch shall 並べた机を同じ呼び出しの中で一度に渡す。
4. When 番が来て待ちのコマンドが終わる, the areka-impl-watch shall 渡した机を出力で伝え、実装の机のひとり占めを含むなら今どおり止まった参加者の一覧を添える。
5. If 1 つの申し込みに同じ机を 2 度並べた・知らない机の名前を並べた・机を 1 つも並べなかった・マージの机を並べた, then the areka-impl-watch shall 何も読み書きせず、使い方の誤りとして終わる。
6. When 排他テストの机を含む申し込みを受けた, the areka-impl-watch shall 申し込みに添えた内容（何のテストか）を記録し、`status.md` で読めるようにする（端末へは出さない）。
7. When 同じ参加者が、待っている・持っている机の組と同じ組で再び申し込んだ, the areka-impl-watch shall 二重に加えず元の申し込みのままとし、すでに持っていれば直ちに番が来たとして終える。
8. If 待っている申し込みを持つ参加者が、別の机の組で申し込んだ, then the areka-impl-watch shall 状態を変えず、当てはまらなかった旨を伝える（1 人の参加者が待つ申し込みは 1 つ。替えるときは取り下げてから申し込み直す。待っている申し込みを持つ参加者がマージの机を申し込んだときも、Requirement 4.7 と同じく状態を変えず、当てはまらなかった旨を伝える。2026-10-18 開発者の裁定。待っている申し込みを持つ状態は今は無いので、今ある状態でのマージの机の呼び方は Requirement 7.1 のまま）。

### Requirement 3: 番の決め方と追い越し
**Objective:** As a 開発者, I want 番が申し込みの早い順に、渡せる申し込みへ順に渡る, so that 渡せない申し込みが後ろの全員を止めず、どの申し込みもいずれ番が来る

#### Acceptance Criteria
1. When 机が空いた・申し込みが加わった・停止の状態が変わった・回収があった, the areka-impl-watch shall 同じ呼び出しの中で、待ち行列を申し込みの早い順に見て、並べた机が全部渡せる申し込みへ順に机を渡す。
2. The areka-impl-watch shall マージの机の申し込みどうしの順を、同じリポジトリの中では今どおり「バグの修正を先、同じならば申し込みの早い順」とする（マージの机の申し込みは今の待ち行列のまま並び、排他テストの机・ひとり占めの申し込みと同じ申し込みに混ざらない）。
3. While 先の申し込みが渡せずに待っている, when 後の申し込みの並べた机が全部渡せる, the areka-impl-watch shall 後の申し込みに先に机を渡す（渡せない申し込みは後ろを止めない。先の申し込みのために机を取っておくことはしない。取っておくと、マージの机を持って排他テストの机を待つ者と、その者のマージの机を待つ者とが互いに待って止まるため）。
4. While 実装の机のひとり占めを含む申し込みが待たれている, the areka-impl-watch shall 排他テストの机を、停止要請中の参加者とマージの机を持つ参加者のほかには渡さない（停止要請を受けたセッションは今のタスクの UI テストを済ませて切れ目まで進め、新しいマージは始まらないので、負荷テストの番はいずれ来る）。
5. While 参加者が「止まった」である, the areka-impl-watch shall その参加者の、実装の机のひとり占めを含まない申し込みに机を渡さない（止まっている者が排他テストの机を持って、負荷テストを止め続けない）。
6. The areka-impl-watch shall 2 つ以上の机を持つ・待つ参加者どうしが、互いに相手の机を待って番が永く来ない状態を作らない（常時テストで、マージの机を持つ者の排他テストの申し込み・負荷テストの待ち・停止要請中の参加者の UI テストの申し込みが重なる組み合わせを含めて確かめる）。

### Requirement 4: 持ちながらの申し込みと返し方
**Objective:** As a 完了の手順を回すセッション, I want マージの机を持ったまま全体テストの間だけ排他テストの机を取り、テストが済んだら排他テストの机だけを返せる, so that 全体テストの外では、ほかのセッションの全体テストや UI テストを待たせない

#### Acceptance Criteria
1. When マージの机を持つ参加者が排他テストの机だけを申し込んだ, the areka-impl-watch shall マージの机を持たせたまま、その申し込みを待ち行列に加える。
2. If 机を持っている参加者が、前の項のほかの組で新たに机を申し込んだ, then the areka-impl-watch shall 状態を変えず、当てはまらなかった旨を伝える（排他テストの机や実装の机のひとり占めを持ったまま別の机を待つことを作らない）。
3. When 持ち主が机を名指しして返した, the areka-impl-watch shall 名指しした机だけを空け、ほかに持っている机はそのまま持たせる（ただし「すでに走っている負荷テスト」の記録の持ち主は 2 つの机を 1 組で返す。排他テストの机だけを名指しして返そうとしたら、状態を変えず、その旨の専用の文で当てはまらなかった旨を伝える。2026-10-18 開発者の裁定）。
4. When 持ち主が机を名指しせずに返した, the areka-impl-watch shall 持っているマージの机のほかの机を全部空ける（マージの机は今どおり「マージが済んだ」の報告か取り下げで空ける）。
5. If 持っていない机を返そうとした, then the areka-impl-watch shall 状態を変えず、当てはまらなかった旨を伝える。
6. When 実装の机のひとり占めを返した, the areka-impl-watch shall 今の負荷テストの机を返したときと同じく、ほかに待たれていなければ止まった参加者を再開させる。
7. If 排他テストの机か実装の机のひとり占めを持つ参加者が、マージの机を申し込んだ, then the areka-impl-watch shall 状態を変えず、当てはまらなかった旨を伝える（`--wait` 付きでも待たずに終える。設計の討議で確定。排他テストの机を持つ状態は今は無いので、今ある状態でのマージの机の呼び方は Requirement 7.1 のまま）。
8. If どこかのリポジトリでマージの机を待っている（まだ持っていない）参加者が、排他テストの机か実装の机のひとり占めを申し込んだ, then the areka-impl-watch shall 状態を変えず、当てはまらなかった旨を伝える（マージの机を受けてから申し込む。7 と 8 で、待ちの向きは「マージの机の持ち主 → 排他テストの机」だけになり、排他テストの机とひとり占めの持ち主は何も待たないので、待ちの輪はアプリの形で生まれない）。

### Requirement 5: 負荷テストと停止要請・マージの決まりの引き継ぎ
**Objective:** As a 計測するセッション, I want 負荷テストが「排他テストの机＋実装の机のひとり占め」として今の決まりのまま回る, so that 計測の最中に全体テストや UI テストが始まらず、全体テストや UI テストの最中に計測が始まらない

#### Acceptance Criteria
1. While 実装の机のひとり占めを含む申し込みが待たれている、または持たれている, the areka-impl-watch shall 今の負荷テストの机と同じ相手（申し込んだ本人、どこかのリポジトリでマージの机を持つ・待つ参加者を除く「作業中」の参加者全員。後から参加した者を含む）に停止要請を出す。
2. The areka-impl-watch shall 実装の机のひとり占めを、ほかの参加者のうち止まる必要のある者が全員「止まった」と報告し、どのリポジトリにもマージの持ち主が居ないときにだけ渡す。
3. While 実装の机のひとり占めを含む申し込みが待たれている、または持たれている, the areka-impl-watch shall どのリポジトリでも新しいマージの机の持ち主を作らない（今の決まり 4。pasta のマージも同じ）。
4. The areka-impl-watch shall 今の停止要請・止まった報告・再開の待ち・停止要請の取り消しと出し直しの振る舞いを、実装の机のひとり占めについて変えずに引き継ぐ。
5. When 参加者が「すでに走っている負荷テスト」を記録した, and 排他テストの机と実装の机のひとり占めのどちらにも持ち主が居ない, the areka-impl-watch shall 停止要請を出さずに、その参加者を両方の持ち主として記録する（今の決まり 7）。
6. If 「すでに走っている負荷テスト」の記録のときに、排他テストの机か実装の机のひとり占めに持ち主が居る, then the areka-impl-watch shall 状態を変えず、当てはまらなかった旨を伝える。
7. If どこかのリポジトリでマージの机を待っている（まだ持っていない）参加者が「すでに走っている負荷テスト」を記録しようとした, then the areka-impl-watch shall 状態を変えず、当てはまらなかった旨を伝える（Requirement 4.8 と同じく、排他テストの机とひとり占めの持ち主がマージの机を待つ形を作らない。マージの机の持ち主は、5 の条件のとおり記録できる。2026-10-18 開発者の裁定）。

### Requirement 6: 回収・取り下げ・止まった参加者
**Objective:** As a 開発者, I want 落ちたセッションや止まったセッションが排他テストの机を塞ぎ続けない, so that 全体テスト・UI テスト・負荷テストの番が永く止まらない

#### Acceptance Criteria
1. When 今の決まりで参加者を回収した（見張りの無い「作業中」の参加者）, the areka-impl-watch shall その参加者の排他テストの机と、その申し込みも外し、同じ呼び出しの中で次の番を決め直す。
2. When 排他テストの机を持つ参加者が「止まった」と報告した, the areka-impl-watch shall その排他テストの机を空け、空けたことをログと `status.md` の最近の出来事に残す。
3. When 参加者が申し込みを取り下げた, the areka-impl-watch shall 今どおり、その参加者の申し込みと持っている机（排他テストの机を含む）を全部外し、参加者の記録は残す。
4. When 参加者が離脱した、マージが済んだと報告した、またはそのリポジトリの記録が消された, the areka-impl-watch shall その参加者の排他テストの机と申し込みも外す。

### Requirement 7: 今の呼び方との互換と状態ファイルの版
**Objective:** As a 開発者, I want 今の呼び方の大半がそのまま動き、古い実行ファイルと新しい実行ファイルが混ざっても状態を壊さない, so that pasta のスキルを直さずに済み、更新の手順が今と同じ 1 通りで済む

#### Acceptance Criteria
1. The areka-impl-watch shall 今のマージの机の呼び方（申し込み・番の待ち・「マージが済んだ」の報告）を、引数・出力・終了コードとも今のまま受け付ける。
2. The areka-impl-watch shall 今の参加・見張り・止まった報告・再開の待ち・停止要請の取り消し・取り下げ・離脱・回収だけの呼び出し・状態の確認・全部消す・リポジトリの記録を消す、の呼び方を今のまま受け付ける。
3. Where 今の負荷テストの呼び方（申し込み・返す・走っている負荷テストの記録）を残す, the areka-impl-watch shall それを「排他テストの机＋実装の机のひとり占め」の申し込み・返却・記録として扱う（残すかどうかは設計で決め、残さないなら手順書に読み替えを書く）。
4. The areka-impl-watch shall 状態ファイルの形式の版を上げ、知らない版の状態ファイルを今どおり読まず書き替えず、版の不一致を ASCII の 1 行で伝えて終了コード 1 で終わる（新しい実行ファイルが古い形のファイルを見ても、古い実行ファイルが新しい形のファイルを見ても同じ）。
5. The areka-impl-watch shall 古い形の状態ファイルを新しい形へ移さず、全部消す（`clear`）は今どおり版が合わなくても通す。

### Requirement 8: 状態の確認と出力
**Objective:** As a 開発者または呼び出すセッション, I want だれがどの机に乗り・持ち・待っているかを `status` と `status.md` で読める, so that 全体テストや UI テストの番待ちの訳が分かる

#### Acceptance Criteria
1. When 状態の確認が求められた, the areka-impl-watch shall 机ごとに、実装の机（乗っている人数・ひとり占めの持ち主と待つ者）、排他テストの机（持ち主・待ち行列の順）、リポジトリごとのマージの机（持ち主・待ち行列・直前のマージ）を、ASCII の数行の要約で示す。
2. When 状態の確認が求められた, the areka-impl-watch shall `status.md` に、申し込みごとの並べた机・申し込みの時刻・内容と、排他テストの机を空けた訳（返した・止まった・回収・取り下げ）を示す。
3. The areka-impl-watch shall 端末へ出す文を ASCII だけにし、名前と内容は端末へ出さない（今どおり）。
4. The areka-impl-watch shall 終了コードの意味を今と同じ 4 通り（0 できた・1 失敗・2 使い方の誤り・3 当てはまらなかった）に保ち、新しい申し込み・返し方の 0 と 3 の出力を `--help` と手順書に書く。
5. The areka-impl-watch shall 待ちを今どおり「番が来たら終わるコマンド」1 本で表し、見回りや時間で回すループを呼ぶ側に求めない。

### Requirement 9: 「全体テスト・UI テスト」と「負荷テスト」の判定の基準
**Objective:** As a 机を使うスキル, I want どの段で排他テストの机を取り、どの段で負荷テストを申し込むかを、タスクの文から一通りに決められる, so that 取るべき机を取り漏らさず、要らない机で他を待たせない

#### Acceptance Criteria
1. The 手順書とスキルの机の段 shall 次を「全体テスト・UI テスト」として排他テストの机を取る段に数える: 全体テストのスクリプトを回すこと（どの引数でも）、ワークスペース全体の `cargo test` を回すこと、`/kiro-validate-impl` が回す全体テスト、`#[ignore]` の実機テストを `--ignored` で回すこと（例外なし。窓も入力も使わないものも数える。要件の討議 議題 3 で確定）、spec ごとの実機の走行の道具、areka・ゴースト・窓を実際のデスクトップに立てる確かめ（配布物の起動の確かめを含む）、`SendInput` や computer-use でデスクトップを操作する確かめ。
2. The 手順書とスキルの机の段 shall クレートのテスト（`--ignored` を付けない `cargo test -p <クレート>`）・clippy・整形・ビルドを数えず、これらは机を取らずに実装の机の上で回す。
3. The 手順書とスキルの机の段 shall 負荷テストを今どおり「静かな CPU での計測・わざと負荷をかける再現・時間の比べ」に限り、排他テストの机と実装の机のひとり占めを並べて申し込む段とする。
4. The kiro-impl skill shall タスクの文・`_Boundary:_`・設計の確かめの記述から、そのタスクが上の段を含むかを決める。

### Requirement 10: `kiro-impl` の机の段
**Objective:** As a 実装を回す主の会話, I want 全体テスト・UI テストの間だけ排他テストの机を持ち、負荷テストは今どおり全部を止めて回す, so that ほかのセッションの実装を止めずに、テストどうしが重ならない

#### Acceptance Criteria
1. When タスクの中や最後の検証で全体テスト・UI テストを回す段に入る, the kiro-impl skill shall その前に排他テストの机を申し込み、番が来るまでその段に入らない（その間も、机の要らないほかのタスクは進めてよい）。
2. When 全体テスト・UI テストの走行が終わった（成否によらず）, the kiro-impl skill shall 直ちに排他テストの机を返し、直しの間は持たず、回し直す前に申し込み直す。
3. When 負荷テストを含むタスクに入る, the kiro-impl skill shall 排他テストの机と実装の机のひとり占めを並べて 1 回で申し込み、計測が済んだら直ちに両方を返す。
4. The kiro-impl skill shall 実装係・直し係・検証係などのサブエージェントに、主の会話が排他テストの机（または負荷テストの組）を持っていると知らせたときだけ全体テスト・UI テスト（または負荷テスト）を回させ、知らせていなければその手前で止まって机が要ることを返させる。
5. When 停止要請を受けた, the kiro-impl skill shall 今どおり今のタスクをコミットの切れ目まで進め（その途中の全体テスト・UI テストは排他テストの机を取って回してよい）、排他テストの机を返してから「止まった」を報告する。
6. The kiro-impl skill shall 机のコマンドを主の会話だけが呼ぶ・1 つの作業木で机を使うセッションは 1 つ・机が使えなければ机の段を飛ばして続ける、の今の約束を保つ。
7. When 最後の検証で `/kiro-validate-impl` を呼ぶ, the kiro-impl skill shall 呼ぶ前に排他テストの机を申し込み、番が来てから呼び、`/kiro-validate-impl` が終わるまで持ち続けて、終わったら直ちに返す（`kiro-validate-impl` の文は直さない。要件の討議 議題 2 で確定）。
8. The kiro-impl skill shall 審査係（`kiro-review`）に渡すテストのコマンドに、全体テスト・UI テストの段を、主の会話がその時に排他テストの机を持っているときだけ入れる（`kiro-review` の文は直さない）。

### Requirement 11: `kiro-complete` の机の段（areka）
**Objective:** As a 完了の手順を回すセッション, I want マージの机を手順の全部で持ち、全体テストの間だけ排他テストの机を足して持つ, so that 完了の全体テストがほかの全体テスト・UI テスト・負荷テストと重ならない

#### Acceptance Criteria
1. The kiro-complete skill shall マージの机を今どおり前置きステップで申し込み、手順の全部で持つ。
2. When 完了の手順の中で全体テスト（アーカイブの後の全体テストとその回し直し）・UI テストを回す, the kiro-complete skill shall その前にマージの机を持ったまま排他テストの机を申し込み、番が来てから回す。
3. When その全体テスト・UI テストの走行が終わった（成否によらず）, the kiro-complete skill shall 直ちに排他テストの机だけを返し、マージの机は持ち続ける。
4. When 手順をやめる（取りやめ・中断）, or マージが済んだ, the kiro-complete skill shall 今どおり取り下げ・「マージが済んだ」の報告・離脱で机を空ける（排他テストの机を持っていればそれも空く）。
5. The kiro-complete skill shall 排他テストの机の番待ちを、開発者への 1 行の知らせとして伝え、承認の止まりにしない。

### Requirement 12: `release` の机の段
**Objective:** As a リリースを回す主の会話, I want 全体テストと起動の確かめの間だけ排他テストの机を持つ, so that リリースの確かめがほかの全体テスト・UI テストと重ならず、リリースの「承認なしで最後まで」も崩れない

#### Acceptance Criteria
1. When `release` が全体テスト（手元の確かめの全体テストと、main が動いたときの回し直し）または配布物の起動の確かめ（窓を出す）を回す, the release skill shall その前に排他テストの机を申し込み、番が来てから回し、走行が終わったら直ちに返す。
2. The release skill shall マージの机を取らない。
3. The release skill shall 机を使う間だけ参加者になり（見張りを立てる）、手元の確かめを終えて机を返したら参加を終える（main が動いて回し直すときは、そのときにまた参加する）。
4. When 参加している間に停止要請を受けた, the release skill shall 走っている確かめを終えて机を返した切れ目で「止まった」を報告し、再開を待ってから次の項目へ進む。
5. The release skill shall 机の番待ちと再開待ちを「止まり方の決まり」の止まりに数えず、開発者に承認を求めない。
6. If 机が使えない, then the release skill shall 机の段を飛ばして手順を続け、訳を最後の報告に書く。

### Requirement 13: 手順書とテスト
**Objective:** As a 開発者, I want 3 つの机の決まり・呼び方・判定の基準が手順書に書かれ、番の決め方が決定論のテストと実機のテストで確かめられる, so that 自分と将来の自分が迷わず使え、行き詰まりが起きないことを信じられる

#### Acceptance Criteria
1. The 手順書 `doc/impl-watch.md` shall 3 つの机の表・排他の決まりの表・新しい申し込みと返し方の呼び方・終了コードごとにすること・スキルからの呼び方の表（`kiro-impl`・`kiro-complete`・`release`・pasta のマージの手順）・Requirement 9 の判定の基準・開発者が `/kiro-validate-impl` を単独で呼んだときは机を取らないこと（要るなら先に排他テストの机を取る）を書く。
2. The 手順書 shall 版が上がる更新のときに、入れ直した後で 1 度 `clear` を呼んで、各セッションが見張りを立ててから申し込み直すことを書く。
3. The areka-impl-watch shall 常時テスト（時刻とプロセスの生死を注入する決定論のテスト）で、一度に渡すこと・一部だけを渡さないこと・追い越し・止まった参加者に渡さないこと・止まった報告での排他テストの机の空け・持ちながらの申し込みの可否・回収・Requirement 3.6 の行き詰まりの無さを確かめる。
4. The areka-impl-watch shall 明示したときだけ走る実機テストで、本物の実行ファイルの 2 つのプロセスが排他テストの机を取り合い、1 つだけが番を受け、返した後にもう 1 つが番を受けることを確かめる（子プロセスの置き場所はワークツリーの `target\` の下の Windows 形の絶対パス）。
5. The areka-impl-watch shall 全体テストが常時テストを拾い、実機テストは拾わない今の形を保つ。
