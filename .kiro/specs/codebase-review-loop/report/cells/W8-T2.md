- `tick_advancing_time_replaces_previous_result` — tick(1.0) で end 値配信後、tick(2.0) は同値で空差分（最新 tick へ置換＝蓄積でない証跡）

- `debug_format_reports_has_runtime_true` — Debug が型名 + `has_runtime` + `true` を含む固定様式

System 配線（3件・実 System を Schedule で駆動）:
- `tick_system_on_empty_world_is_noop` — DolaAnimator ゼロ + FrameTime のみで System がパニックせず走る（Query 空でループ本体不実行）・World は空のまま

## テスト不能箇所・深掘り所見（R2.8）

1. **dola ランタイム本体（補間・インスタンス管理・トリガー・差分検出）は D1〜D3 領域でテスト済み・本セル境界外** — `DolaAnimator::tick` は `DolaRuntime::tick`（facade.rs:307-309）へ、`last_result` は `DolaRuntime::last_result`（facade.rs:315-317）へ委譲する薄いラッパーである。`update_internal`（facade.rs:334-385）の finish deadline / トリガー / ループ / 自然終了 / 評価 / `diff_and_update` の全ロジックは dola クレート内で完結し、wintf 側は時刻を渡して結果を読むのみ。これらの本質ロジックは `crates/dola/src/runtime/` の各 in-source `mod tests`（facade/subscription_manager/timeline_manager/instance_manager/interpolator）と `tests/runtime/` で固定済みであり、wintf からの再検証は重複となるため見送った（D1a/D1b/D2/D3 担当）。本セルは委譲が正しく行われること（tick→last_result の更新・冪等読取・置換性・空 World no-op・FrameTime 反映）を wintf 統合点で固定した。

2. **`tick_dola_animators` の本番駆動は `Res<FrameTime>`（`dola::runtime::clock::now()` 由来）を要するが、時刻注入で完全決定論化できる** — 本番では `EcsWorld` 外で `FrameTime.0 = dola::runtime::clock::now()`（world/mod.rs:50,465、`QueryPerformanceCounter` 由来の実時間）が毎 tick 更新され、System はこの値で全 animator を tick する。clock::now() 自体は Win32 QPC 依存（clock.rs:14-29、dola 側 D 領域）だが、`FrameTime` は `#[derive(Resource, Default, Debug, Clone, Copy)]`（graphics/core.rs:146-147）で**任意値を注入可能**であり、本セルの System テスト 3 件は `World::insert_resource(FrameTime(固定値))` で実時間を排して決定論的に駆動した。実 clock::now() の単調性・精度は dola の clock テスト（clock.rs in-source、target_os=windows）が回帰検知器であり、wintf からの実時間駆動は不要（提案化しない）。

3. **`unsafe impl Send + Sync for DolaAnimator`（mod.rs:51-52）は単一スレッド前提・`Rc` 内包のための手動実装で、健全性点検は 19.4 W8-V の主担当（本 T セルでは所見化に留める）** — `DolaRuntime` 内部に `Rc`（dola types.rs:4 等で `Rc<DynamicValue>` を保持）を含むため `DolaAnimator` は自動で `Send/Sync` を導出できず手動 `unsafe impl` する。健全性の根拠は doc コメント（mod.rs:47-50）どおり「wintf は単一スレッド（Windows UI スレッド）でのみ動作し、`tick_dola_animators` の `Query<&mut DolaAnimator>` が 1 tick 1 回・単一スレッドの排他アクセスを型レベルで保証する」。親指示の確定知見（WIC・HWND/HINSTANCE は手動 impl 必須、D2D/DWrite は手動 impl 冗長）に照らすと、本 `unsafe impl` は **`Rc`（!Send + !Sync）を跨スレッド共有不可能な型に被せる手動 impl** であり、`bevy_ecs` の Component が `Send + Sync` を要求する制約を満たすために必須（自動導出不可）。ただし「単一スレッドでのみアクセス」という不変条件が実スケジュール構成（`par_iter_mut` で並列化されないこと）に依存するため、**unsafe 点検の主担当 19.4 W8-V** が ECS スケジュールの実駆動経路（`tick_dola_animators` が `Update` で単一スレッド実行されること、他の並列システムが `&DolaAnimator` を跨スレッド参照しないこと）を検証すべき領域である。本 T セルでは深入りせず所見化に留めた（親指示「ecs/dola/ に `unsafe impl Send + Sync` がある場合は所見化に留め深入りしない」に従う）。テスト網羅性の観点では、`DolaAnimator` の機能契約（tick/last_result/system 配線）を全面特性化しており、Send/Sync の健全性そのものはテストで検証する性質のものではない（型システム + スケジュール構成の不変条件）。

## RED フェーズ / 特性化の収束（重要）

12件中 **9件は初回 GREEN**（ラッパー委譲契約の単純な代数）だが、**3件が初回失敗**し深掘りにより dola 差分セマンティクスの真の挙動を発見、テスト前提を実挙動へ修正した（プロダクション挙動は不変＝特性化の正常な収束。W8-T1 の `tick_is_idempotent` 深掘りと同型）。

- **深掘り（ソース + 経験的 probe）**: `subscription_manager::diff_and_update`（subscription_manager/mod.rs:138-142）を精読し、**「前回配信値（`last_sent_values`）が無い初回は常に変化あり」**（コメント「初回は常に変化あり」）を確認。一時 probe テストで実値を観測:
  - start=0: t=0→`[(0,0.0)]`, t=0.5→`[(0,0.5)]`, t=1.0→`[(0,1.0)]`, t=2.0→`[]`
  - start=1: t=0.5→`[(0,0.0)]`, t=1.0→`[]`, t=1.5→`[(0,0.5)]`, t=2.0→`[(0,1.0)]`

## clippy（S3・記録のみ・非ブロッカー）
- `cargo clippy -p wintf --tests` は既存警告群（合計 172 warning 系。大半は `crates/dola/`（D 領域）および wintf 既存ファイル由来）を出力。
  - **本セルで追加したテストコード（`dola/mod.rs` の `mod tests` 追記分）を指す診断はゼロ**（パスフィルタ `wintf[\/].*dola[\/]mod\.rs` / `src[\/]ecs[\/]dola` で grep し該当なしを確認）。
  - 本セルはテスト追加のみでプロダクションコード未変更のため、新規 clippy 警告/error の導入はゼロ。S3 規定によりブロッカーとせず記録に留める（プロダクションコードの簡素化は S 観点 W8-S の担当）。
