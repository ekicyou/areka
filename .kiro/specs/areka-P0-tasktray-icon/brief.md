# Brief: areka-P0-tasktray-icon

> 2026-10-10 `/kiro-discovery`（開発者「タスクトレイの土台仕様を起票したうえで、上流の ukadoc 項目を後続仕様にせよ」「タスクトレイで出てくるべきメニューは今出てるシステムメニューと同じ」）で起票した。roadmap の予約「アプリ層」に名前だけ在った「トレイアイコン」を spec にしたもの。正典は ukadoc MCP で確かめた。コードは「何の定義か」で指す。着手時に引き直す。

## Problem

areka は通知領域（タスクトレイ）にアイコンを出さない。利用者がメニューへ届く入口は、キャラクターの窓の右クリックだけである。キャラクターを見失ったとき・ほかの窓の下に隠れたとき・ゴーストを切り替えている間（窓が 0 枚になる）に、areka へ触る手がかりが画面に無い。動いているかどうかも、キャラクターが見えていなければ分からない。

通知領域の上に乗る ukadoc の項目（ゴーストのアイコン・台本からの差し替え・通知領域からの知らせ・アイコン化）も、土台が無いので 1 つも作れない。

## Current State

- 正典（ukadoc と SSP のヘルプを ukadoc MCP で確かめた。以下は要旨）:
  - descript の `icon,ファイル名`: 「そのゴーストのタスクトレイアイコン」。値が無いときは、ベースウェアの標準アイコンを出す（ukadoc「ゴースト descript.txt」）。
  - `\![set,tasktrayicon,ファイル名.ico,テキスト(,--duration=待機時間(,--runcount=繰り返し回数))]` の説明: アイコンにマウスを重ねたときの文言は、既定で「SSP/[起動中のゴースト名]」。
  - SSP のヘルプ「右クリックメニュー」「よくある質問」: 本体側のキャラクターの右クリックメニューは、アイコンの右クリックでも開く。キャラクターが画面の外へ行ったときの戻し方として案内している。
  - SSP のヘルプ「右クリックメニュー」の「アイコン化」: 最小化から戻すには、アイコンをダブルクリックする。
- areka のコード:
  - `Shell_NotifyIcon` を呼ぶ所は `crates/` に無い。アイコンのハンドル（`HICON`）を作る所も、exe に埋めたアイコンの資源も無い（`crates/areka/build.rs` が埋めるのはマニフェストだけ・リポジトリに `.ico` は 1 つも無い）。
  - 開発者の言う「今出ているシステムメニュー」は、キャラクターの右クリックで出るメニュー（`crates/areka/src/menu/`）。枠は 7 つ（`Frame::ORDER`＝ゴースト・シェル・バルーン・ネットワーク更新・インストール・説明書・終了）。項目は右クリックのたびに `MenuRegistry::snapshot` が供給元を呼んで作る。OS のシステムメニューではない（キャラクターの窓は `WS_SYSMENU` を持たない）。
  - メニューの部品のうち、`MenuRegistry::snapshot`・`captions` の照会と読み取り・`plan::build`・`win32::show`（任意の窓と画面の座標を取る）は、呼び手を選ばない。
  - 一方、依頼の形 `MenuRequest`（`menu/trigger.rs`）は、キャラクターの窓のエンティティ・窓のハンドル・スコープを持ち、窓が消えていれば依頼を捨てる。組み立ての唯一の場所は `handle_release`（右ボタンを放した知らせ）。同時に出せるメニューは 1 つ（`MenuWiring.in_flight`）。
  - `MenuWiring` はゴーストの起動のたびに作り直す（`ghost_session::boot_wired`）。SHIORI が動かない縮退の起動では作られない。
  - アプリの持ち物の窓は無い。ゴーストの切替では、ゴーストの窓を全部消してから作り直すので（`app_exit::close_windows_for_restart`）、窓が 0 枚の間がある。
  - wintf の窓の手続き（`ecs::window_proc::dispatch_window_message`）は決まったメッセージだけを見て、ほかは OS の既定へ流す。独自のメッセージや `RegisterWindowMessageW` の受け口は無い。World を借りている最中に届いたメッセージは、決まった 5 つを除いて配らずに返す（`runtime::wndproc_bridge::make_wndproc`）。
  - ECS の表の外に、自前の手続きを持つ窓を作る口は在る（wintf が `executor` の名前で出し直している外部クレート `wintf-winmsg-executor` の `Window::new_ex`）。OS の部品を ECS の外で持つ前例は、ツールチップの窓（wintf の `ecs/tooltip/os.rs` の `TipWindow`）。
  - 起動中のゴーストの名前は、`mcp::resolve::active`（`crates/areka/src/mcp/resolve.rs`・`ActiveGhost`）で引ける。切替の途中は `None`。起動と切替のたびに `main.rs` の `on_boot_ok` が通る。
  - プロセスの終わりは 1 か所（`app_exit::quit_app` → `AppExit::request_exit`）。`app.run()` が返った直後に片付ける前例は `mcp::close`。
  - キャラクターとバルーンの窓を手前へ出す働き・隠す働き・最小化の状態は、どれも無い。
- 網羅台帳（`doc/ukadoc-coverage/ledger/`）: `icon,ファイル名` は `absent`・持ち主なし。
- 以前の扱い: 完了した `popup-menu-minimal` と `app-lifetime-separation` は、トレイアイコンを範囲の外に置いた（α に含めない）。進行中の `popup-menu-residue` も範囲の外としている。

## Desired Outcome

- areka が動いている間、通知領域に areka のアイコンが 1 つ出ている。ゴーストの切替をまたいでも消えない。
- アイコンにマウスを重ねると「areka/[起動中のゴースト名]」が出る。ゴーストを切り替えると名前が替わる。
- アイコンを右クリックすると、本体側のキャラクターを右クリックしたときと同じメニューが出る。項目・並び・ゴーストが決めた文言は同じで、選んだ項目は同じに働く。
- エクスプローラーが立ち上げ直されても、アイコンが戻る。
- 終了すると、アイコンが通知領域に残らない。
- 後続の spec が、アイコンの絵と文言の差し替え・通知領域からの知らせ・ダブルクリックの受け口を、この土台の上に足せる。

## Approach

プロセスに 1 つの「アプリの持ち物」として、見えない窓 1 枚と通知領域のアイコンを持つ。ゴーストの窓にはぶら下げない。

- OS の部品を包む所は wintf に置く（見えない窓・アイコンの登録と差し替えと取り消し・エクスプローラーの立ち上げ直しの知らせ・クリックの知らせを出来事にして渡す）。ツールチップの前例と同じ置き方。
- areka は結線だけを持つ。起動のときに据え、`app.run()` が返ったら取り消す。文言は起動と切替のたびに書き直す。
- メニューは作り直さない。今の組み立てと表示をそのまま使い、依頼の形を「キャラクターの窓を持たない呼び手」からも出せるように広げる。

選ばなかった案:

- キャラクターの窓にアイコンをぶら下げる: ゴーストの切替で窓が 0 枚になるのでアイコンが消えて出直す。通知領域での並び順も動く。
- 通知領域用のメニューを別に作る: 開発者の指示（同じメニュー）に反する。項目が 2 か所に分かれる。

## 議題（要件の段で決める）

1. **標準アイコンの絵**（解消・2026-10-10）。絵を作って `areka.exe` に埋める仕事は、前提の spec `areka-P0-app-icon` に切り出した（開発者「より上位に、アプリアイコンとタスクトレイアイコンを作成して areka.exe に埋め込むスペックを用意しないとダメ」）。この spec は、埋めてある通知領域用のアイコンを読んで出すだけ。
2. **左クリックとダブルクリックで何をするか**。正典に在るのは「ダブルクリックでアイコン化から戻す」だけで、アイコン化は後続（`areka-P0-tasktray-minimize`）。土台では、何もしないか、キャラクターとバルーンの窓を手前へ出すか（今は無い働きなので足すことになる）。
3. **ゴーストがメニューを止めているとき**（`popupmenu.visible` による抑止と、右ダブルクリックの送り直し）に、アイコンからの呼び出しにも同じ抑止を当てるか。SSP のヘルプは、アイコンのメニューを「キャラクターを見失ったときの戻し方」として案内している。
4. **ゴーストが居ない間の右クリック**（切替の途中・SHIORI が動かない縮退の起動で `MenuWiring` が無いとき）に、何も出さないか、「終了」だけのメニューを出すか。
5. **アイコンを出さない設定**を持つか。土台は常に出す。SSP の「常にトレイアイコンを表示」の項目（`alwaystrayiconvisiblebutton.caption`）は `areka-P0-tasktray-minimize` の議題。

## Scope

- **In**: 通知領域のアイコンを出す・消す・エクスプローラーの立ち上げ直しで出し直す／exe に埋めてある標準アイコンを読んで出す／マウスを重ねたときの既定の文言と、切替での書き直し／右クリックで今のメニューを出す（依頼の形の広げ方を含む）／左クリックとダブルクリックの受け口（議題 2 の結論まで）／決定論テスト（知らせから動きを決める所・OS の呼び出しは偽の境界）／実機の確かめ／網羅台帳の `icon,ファイル名` の行のうち「値なしは標準アイコン」の分。
- **Out**: アイコンの絵と exe への埋め込み（`areka-P0-app-icon`）／ゴーストが決めるアイコン（descript の `icon`）と `\![set,tasktrayicon,…]`（`areka-P0-tasktray-ghost-icon`）／`\![set,trayballoon,…]` と 2 つのイベント（`areka-P0-tasktray-balloon`）／アイコン化（最小化）と `icon.minimize`（`areka-P0-tasktray-minimize`）／アイコンの動く絵／メニューの項目の追加・オーナードロー／複数のゴーストの同時起動のときのアイコンの数（予約「多重ゴースト」）／SHIORI のエラーを通知領域で知らせること。

## Boundary Candidates

- wintf の通知領域の部品（見えない窓・アイコンの登録と差し替えと取り消し・立ち上げ直しの知らせ・クリックの知らせ）。
- areka の結線（新しい `crates/areka/src/tray/`・`main.rs` での据え付けと片付け・文言の書き直し）。
- メニューの依頼の形（`crates/areka/src/menu/trigger.rs`・`menu/mod.rs`）。
- exe に埋めてあるアイコンの読み込み（資源の番号は `areka-P0-app-icon` が決める）。

## Out of Boundary

- メニューの項目と供給元（`menu/` の各 `*_frame.rs`）。中身は変えない。
- キャラクターの窓の右クリックの流れ。今の動きを変えない。
- kanade。この spec は SHIORI へ新しいイベントを送らない（メニューの文言の照会は今の経路を使う）。

## Upstream / Downstream

- **Upstream**: `areka-P0-app-icon`（通知領域用のアイコンを `areka.exe` に埋める）。下敷きは完了した `popup-menu-minimal`（メニュー）と `app-lifetime-separation`（プロセスの終わり方）。
- **Downstream**: `areka-P0-tasktray-ghost-icon`・`areka-P0-tasktray-balloon`・`areka-P0-tasktray-minimize`。roadmap の予約「インストーラー版」（同じ絵を使う）。

## Existing Spec Touchpoints

- **Extends**: なし（下敷きの 2 本は完了済みで消化できない＝新しい spec）。
- **Adjacent**: `menu/` を触る `popup-menu-residue`（残件の相乗り先の候補になる）。`main.rs` と `ghost_session` の起動の流れを触る spec（`baseware-root-list`・`mcp-reload` など）。触るファイルの重なりは次の棚卸で測る。

## Constraints

- 通知領域の知らせを取りこぼさない。wintf の窓の手続きは World を借りている最中のメッセージを配らないので、自前の窓で受けて出来事として積む。
- メニューを出すのは UI スレッド。メニューが出ている間も描画が止まらない今の作り（実行器のタスクの中で出す）を保つ。
- 失敗をメッセージボックスで知らせない（開発者の方針）。アイコンを登録できなかったときは記録を残し、エクスプローラーの立ち上げ直しの知らせで出し直す。黙って失敗する経路を作らない（steering `logging.md`）。
- 依存を足さない方向で設計する（ワークスペースの `windows` の機能には `Win32_UI_Shell` が既に入っている）。exe へのアイコンの埋め込みは `areka-P0-app-icon` の仕事で、この spec は `build.rs` に触らない。
- アイコンの大きさは、画面の拡大率に合わせて選ぶ（areka は拡大率に追従する作り）。
- 実機の確かめは、画面のロックを外した机で行う。Windows 11 は既定でアイコンを「隠れているアイコン」に入れるので、確かめの手順にその開き方を書く。
- 異常終了のとき、アイコンは OS が片付けるまで残る（OS の仕様）。既知の制限として書く。
