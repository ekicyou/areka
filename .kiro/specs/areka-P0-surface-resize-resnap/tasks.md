# Implementation Plan

- [x] 1. 基盤: アンカー表現の一般化
- [x] 1.1 ゴースト設定のアンカー指定（`top`/`bottom`/`left`/`right`/`free`、および解釈不能な既存値）を、5値の純粋なアンカー種別へ解釈する仕組みを追加する
  - 既存の2値（吸着あり/なし）判定を、5値アンカーを保持できる表現へ置き換える
  - 未知のアンカー指定は `bottom` 相当へフォールバックしログへ警告を残す
  - 観測可能な完了条件: アンカー解決済み設定値（`bottom`/`free`/`top`/`left`/`right`/未知値）の全パターンを与えたとき、期待する5値アンカーへ変換されることを純粋関数テストで確認できる
  - _Requirements: 4.2_

- [x] 1.2 スコープ配置情報が持つ既存の2値吸着フラグを、5値アンカー種別のフィールドへ置き換える
  - 既存フラグから5値アンカーへの移行に伴い、格納される真実が単一（アンカー種別のみ）になることを保証する
  - 既存フラグの伝播を検証していたテスト群を、新しいアンカー種別ベースの検証へ意味を保ったまま更新する
  - 観測可能な完了条件: 4層優先度カスケードで解決された各アンカー設定（bottom・free・未指定＝既定bottom・混在スコープ）が、対応する5値アンカーとしてスコープ配置情報に正しく伝播することをテストで確認できる
  - _Requirements: 1.6, 4.2_
  - _Depends: 1.1_

- [ ] 2. 中核: アンカー射影（変換T）と単一ライター反映口
- [x] 2.1 解決済みアンカー・現在位置・新しい表示寸法から、アンカー辺をデスクトップ作業領域の対応辺へ固定した窓位置を導出する純粋な射影関数を実装する
  - `bottom` は既存の下端吸着ポリシーへ委譲し再定義しない。`top`/`left`/`right`/`free` はその一般化として同じ規約（アンカー辺固定・非アンカー軸は現在値保持）で実装する
  - 作業領域が取得できない場合や寸法が非正のときは位置を変更せず現状維持（識別写像）へ縮退させる
  - 観測可能な完了条件: 5種のアンカーそれぞれについて、多様な寸法・作業領域値（96の非倍数を含む）・モニタ跨ぎ・非正寸・作業領域不明の各ケースで期待どおりの位置（または現状維持）が返ることを純粋関数テストの網羅で確認できる。また同一の射影がべき等（既にアンカー辺が一致する位置に対して同値を返す）であることも確認できる
  - _Requirements: 1.1, 1.2, 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.4, 5.4_
  - _Depends: 1.1_

- [x] 2.2 キャラクター窓が現在のアンカー種別を保持するための表現を追加する
  - 窓エンティティに5値アンカーを1つだけ紐づけられるようにする（ドラッグ・リサイズ双方がこの表現を読み取る単一の真実源とする）
  - 観測可能な完了条件: 任意の窓エンティティへアンカー種別を付与・読み出しできることを確認できる
  - _Requirements: 4.2, 1.4_
  - _Depends: 1.1_

- [x] 2.3 窓の位置とサイズを同時に反映できる単一の発行口へ、既存の移動専用発行口を一般化する
  - サイズを指定しない場合は既存の移動専用の挙動（位置のみ反映）を完全に維持し、既存のドラッグ関連の挙動へ影響を与えない
  - サイズを指定した場合は、位置とサイズを一度の発行でまとめて反映する
  - 観測可能な完了条件: 既存のドラッグ関連テスト（移動専用発行）がすべて変更なく成功し続けること、およびサイズ指定時に窓のサイズ状態が正しく更新されることの双方をテストで確認できる
  - _Requirements: 1.5, 3.3_

- [x] 2.4 新しい表示寸法に対してアンカー射影を再適用し、確定した位置とサイズを単一の反映口経由で一度だけ書き込む機能を実装する
  - 対象窓が不在・未生成・アンカー未付与のときは窓を変更せずログを残して安全に終了する
  - 新しい寸法が非正のときはアンカー再適用を行わず現状を維持してログを残す
  - 導出した位置・サイズが現在値と同一のときは書き込みを行わない（冗長な再配置を避ける）
  - 随伴するバルーン窓の追従オフセットを破壊しない
  - 観測可能な完了条件: 疑似窓を用いたヘッドレス環境で、寸法変化時に一度の書き込みで新しい位置・サイズへ更新されること（`bottom`での下端再計算を含む）を確認できる
  - _Requirements: 1.1, 1.3, 1.7, 3.1, 3.4_
  - _Depends: 2.1, 2.2, 2.3_

- [x] 2.5 上記の再適用機能について、5種すべてのアンカーでの寸法変化時の挙動と、随伴バルーンの追従維持、および異常系（不在・非正寸・べき等）を統合テストで固定する
  - `top`/`left`/`right` はそれぞれの固定辺へ正しく再計算され、`free` は寸法のみ反映し位置を保持することを確認する
  - 随伴バルーン窓がある場合、リサイズ後もキャラ窓とバルーン窓の相対オフセットが維持されることを確認する
  - 同一寸法・同一アンカーでの再適用が窓状態を変更しない（冗長な書き込みをしない）ことを確認する
  - 観測可能な完了条件: 5アンカー×正常系・異常系（不在・非正寸・べき等）の統合テストが緑になること
  - _Requirements: 1.1, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 3.1, 3.3, 3.4_
  - _Depends: 2.4_

- [x] 2.6 対象窓のアンカーが実行時に変わったとき、現在の表示寸法でアンカー射影を再適用する仕組みを追加する
  - アンカー変更の検知は、アンカー表現の変化そのものに反応する形で行う（変更元がまだ実装されていなくても、アンカー表現を直接書き換えることで検証できるようにする）
  - 観測可能な完了条件: アンカー表現を直接変更すると、現在の表示寸法のまま新しいアンカー辺へ窓が再配置されることをテストで確認できる
  - _Requirements: 1.4_
  - _Depends: 2.4_

- [ ] 2.7 ドラッグ操作とリサイズ操作が同一のアンカー射影・同一の単一ライターを使うよう、既存のドラッグ処理を新しいアンカー表現ベースへ移行する
  - `free` アンカーの窓は従来どおりOS標準のドラッグ移動に委譲し、それ以外のアンカーはアンカー射影の結果に基づいて単一ライター経由で位置を確定する
  - 既存の `bottom` ドラッグ挙動（Y座標の釘付け）が移行後も変わらないことを確認する
  - 観測可能な完了条件: `bottom` アンカーの窓をドラッグしたときの既存挙動が保たれ、かつ `free` アンカーの窓は引き続きOS標準委譲のまま動くことをテストで確認できる
  - _Requirements: 1.6_
  - _Depends: 2.4_

- [ ] 3. 結合: 生成時のアンカー付与と実行時サイズ変化の検知
- [ ] 3.1 (P) ゴースト窓の生成時に、各キャラクター窓へ解決済みアンカーを付与し、ドラッグ移動の可否・ドラッグ終了時の反映対象を全アンカー種別に対応させる
  - `free` のみOS標準のドラッグ移動を許可し、それ以外のアンカーは単一ライター経由のドラッグ終了反映を結線する
  - 既存の2値吸着マーカーの有無を検証していたテストを、新しいアンカー種別の付与を検証するテストへ意味を保ったまま更新する
  - 観測可能な完了条件: 生成直後の全キャラクター窓が対応する5値アンカーを保持し、`free` 窓のみドラッグ移動可、それ以外はドラッグ終了時に単一ライター経由で反映される設定になっていることをテストで確認できる
  - _Requirements: 4.2, 1.6_
  - _Boundary: placement::spawn_
  - _Depends: 2.7_

- [ ] 3.2 (P) 表示中のキャラクター用サーフェス寸法の変化を検知し、対応するキャラクター窓へアンカー再適用を直接駆動する仕組みを追加する
  - 検知対象は「実際に適用された表示寸法」に限定し、キャラクター（シェル）側の寸法変化のみを駆動入力とする（バルーン側の寸法変化では駆動しない）
  - 同一寸法であれば何もしない（冗長な駆動を避ける）
  - 変換できない・非正な寸法値は安全にスキップする
  - 観測可能な完了条件: 合成した寸法データを用いて、「寸法が変わったときのみ再適用が駆動される」「同一寸法では駆動されない」「不正な寸法値はスキップされる」「バルーン側の寸法変化では駆動されない」ことをヘッドレス環境で確認できる
  - _Requirements: 1.3, 3.1, 3.2, 4.1, 4.3, 4.5_
  - _Boundary: emo2_boot::frame_
  - _Depends: 2.4_

- [ ] 4. 統合・回帰検証
- [ ] 4.1 既存のドラッグ・移動専用経路が新しい単一ライター一般化の影響を受けずに動作し続けることと、寸法検知からアンカー再適用までの一連の流れがべき等に働くことを確認する
  - 既存の移動専用の統合テスト群がすべて変更なく成功することを確認する
  - サイズ変化検知から窓反映までの一連の流れで、同一寸法・同一アンカーが繰り返し来ても窓状態が変化しないことを確認する
  - 観測可能な完了条件: 既存の移動専用テスト群、および検知〜反映の一連のべき等性テストがすべて緑になること
  - _Requirements: 1.5, 3.1_
  - _Depends: 3.1, 3.2_

- [ ] 4.2 非`bottom`アンカーのドラッグ配線が、決め打ちの値でなく実際に付与されたアンカーを正しく転送していることを確認する検証を1件追加する
  - `left` アンカーを付与した窓をドラッグしたとき、左端固定・縦方向自由という期待挙動になることを確認する（`bottom`の挙動と混同していないことの証拠とする）
  - 観測可能な完了条件: `left` アンカー窓のドラッグ統合テストが緑になり、ドラッグ配線が実際のアンカー値を読み取っていることが示されること
  - _Requirements: 1.6_
  - _Depends: 3.1_

- [ ] 5. 検証: 実DPI本番ゴースト受け入れと境界確認
- [ ] 5.1 実際のディスプレイ拡大率が96%（等倍）でない環境（例: 125%）で本番ゴーストを`bottom`アンカー表示させ、既定サーフェスから寸法の異なる本体サーフェスへの切替後もキャラクター窓の下端がデスクトップ下端に維持されることを目視確認する
  - 拡大率96%のみでの確認は受け入れ根拠として不十分とし、実際の拡大率での証跡を必須とする
  - ハードコードした窓寸法や架空の作業領域を用いた単発デモではなく、本番ゴースト表示に対して確認する
  - 観測可能な完了条件: 実際の拡大率環境で、サーフェス切替後もキャラクター窓の下端が画面下端に一致し続けることの目視証跡が得られること
  - _Requirements: 5.1, 5.2, 5.3_
  - _Depends: 4.1, 4.2_

- [ ] 5.2 上記と同じ実環境でのサーフェス切替直後に、キャラクター窓が振動しないこと、およびリサイズ後もバルーン窓の透過クリックが生きていることを、アンカー維持確認とは独立した観測項目として目視確認する
  - 観測可能な完了条件: サーフェス切替直後の窓位置が振動せず一度の反映で確定すること、かつリサイズ後にバルーン窓の透過部分がクリックスルーし続けることの目視証跡が得られること
  - _Requirements: 5.5_
  - _Depends: 5.1_

- [ ] 5.3 実装が設計の境界（初期表示サーフェスの選択、サーフェス合成・文字層の中身、アンカー優先度解決やその実行時変更の経路、二人立ちの窓割当、バルーンの配置規則・位置永続化、ドラッグ機構そのもの）を侵していないこと、および新規の外部依存を追加していないことを確認する
  - 観測可能な完了条件: 変更差分が対象4ファイル（アンカー解決・単一ライター反映・生成時結線・実行時検知の各モジュール）の範囲内に収まっており、上記の境界へ変更が及んでいないこと、依存関係定義に新規追加がないことをレビューで確認できる
