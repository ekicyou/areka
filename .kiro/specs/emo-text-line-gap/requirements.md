# Requirements Document

## Project Description (Input)

- **困っている人**:
  - ゴーストの利用者。書体の行間（hhea の lineGap）を持つ書体（游ゴシックなど）を `font.name` に書いた横書きのバルーンで、選択肢やアンカーにマウスを乗せると、反転の帯が字からずれて塗られる見込みがある（まだ測っていない）。
  - バルーンの作者。書体を選んだだけで、選択肢の反転が字に合わなくなる。
- **今の状況**:
  - emo-text が見込む行の箱の高さは `(ascent ＋ descent) ÷ upem` の比から出し、書体の行間を数えない。DirectWrite は書体の既定の行の高さ（書体の行間を含む）で組むので、書体の行間を持つ書体では見込みが実際の行の箱より狭い。
  - 測った数（完了 `vertical-choice-hover-band` のタスク 5.1・縦書きの列の箱）: 游ゴシック（lineGap 1024・upem 2048）の大きさ 20 で、比から出す行の箱は 25.74、DirectWrite が組む列の箱は 32.04（28 では 36.04 と 44.86）。書体の行間 0 の Yu Gothic UI とＭＳ ゴシックでは両者が一致する。
  - 縦書きの帯は同 spec で DirectWrite が測った基線から置く形に改めたので、この食い違いの影響を受けない。横書きの帯の厚みと寄せは今も比から出す行の箱を読む。横書きでどれだけずれるかは測っていない。
  - 今の手元の検体（ぱすたの `pasta_tategaki`＝縦書き・emo2 の `emo2-kakukaku`＝Yu Gothic UI・既定＝ＭＳ ゴシック）には、横書きでこのずれに当たるものは無い。
- **変えたいこと**:
  - 書体の行間を持つ書体の横書きで、選択肢とアンカーの反転の帯が字に対して正しい所（縦書きと同じく字に対して中央）に塗られ、当たりの範囲も同じ所になる。
  - 行の箱の比を読む所が、DirectWrite が実際に組む行の箱と食い違わない。または比を読まない形に改めてある。
  - 書体の行間 0 の書体の帯の画素は変わらない。
- 詳細は同じフォルダの `brief.md`。

## Introduction

本 spec は、**書体の行間を持つ書体の横書き**で、選択肢とアンカーの反転の帯の **厚みと置く所** を字に合わせて直す。区分は B（バグ）。版に縛らない（ぱすたの横書きのバルーンは無いので、v0.1.0 のゴール「ぱすたが SSP と同じに動く」には当たらない）。ウェーブ C15 の割り込みの 1 本。

**用語**:

- **書体の行間**: DirectWrite が組む行の高さと、字の箱の丈（ascent ＋ descent）との差。游ゴシックでは、表の hhea の lineGap は 1024（upem 2048）だが、DirectWrite の ascent・descent は OS/2 の win の値（2017／619）、行の高さは hhea の和（1802＋455＋1024）なので、差は 645 設計単位（大きさ 20 で 6.30・28 で 8.82）。Yu Gothic UI とＭＳ ゴシックは 0。「書体の行間を持つ書体」はこの差が 0 より大きい書体を言う（hhea の lineGap の欄の値だけでは決めない）。**行送りの行間**（設定の `line_pitch = font.height ＋ 行間` の「行間」＝既定の定数 2 image px・`doc/COMPAT_ARCHITECTURE.md` §8）とは別物で、本 spec は行送りの行間に触らない。
- **字の箱**: その行の字について、書体の ascent ＋ descent の丈を持ち、DirectWrite が実際に字を置いた所に在る箱。書体の行間 0 の書体では行の箱と同じ。
- **帯**: マウスを乗せた選択肢（とアンカー）を塗る四角（`cursor.style,square` の塗り）。
- **当たり**: マウスを乗せた・クリックしたと判じる範囲。
- **今の帯と字の関係**: 書体の行間 0 の書体の横書きで、今の帯は厚みを「行の箱の丈を em の丈と行送りのあいだに収めた値」とし、行の箱（＝字の箱）の中央へ寄せている（完了 `areka-P0-emo2-conformance-e2e` の開発者裁定 2026-09-06 第 2 回）。

**今の形の確かめ（2026-10-31 棚卸㉜の再測定・main `d374f901`）**:

- 選択肢の範囲・帯・当たりは 1 つの関数で出し、当たりは帯から作る（完了 `choice-ranges-one-function`）。横書きの帯の式を直せば、塗りと当たりが一緒に動く。
- 行の箱の比を読む所は、横書きの帯の厚みと寄せのほか、縦書きの em の箱の置き場の既定の決め方（書体から測った置き場が無いときの逃げ道）にも在る。

**直し方（2026-10-31 要件の討議で開発者が案 2 に裁定）**:

- 案 1（取らない）: 行の箱の比に書体の行間を数え、DirectWrite の行の高さに合わせる。
- **案 2（取る）**: 横書きの帯も、縦書きと同じく DirectWrite が測った基線（字の置き場）から置き、比を帯から外す。

裁定の根拠（`research.md` §1.4 の見込みの表）: DirectWrite が書体の行間を字の上・上下に半分ずつ・下のどこに置いても、案 2 は帯を字の箱の中央に置ける（差 0.2 画素以内の見込み）。案 1 は半分ずつのときだけ中央になり、上なら 3〜5 画素ずれたまま残る。案 2 は縦書きと同じ単一の源で、書体の行間 0 の書体では足す量が 0 になり、今の画素の檻が動かない。帯の厚みは今の決まり（字の箱の丈を em の丈と行送りのあいだに収めた値＝書体の行間を厚みに数えない）のまま。測りは直し方を決めるためでなく、裁定の確かめとして実装の最初のタスクで行う（要件 1）。

## Boundary Context

- **In scope**:
  - 書体の行間を持つ書体の横書きでの、帯と字のずれの測り（実物の書体の読み戻し）。
  - 直し方の裁定（案 2・2026-10-31）の記録と、測りによる確かめ。
  - 横書きの選択肢とアンカーの帯の厚みと置く所の直し。塗りと当たりの両方。
  - 行の箱の比の扱い（比を読む所が、DirectWrite が組む行の箱と食い違わないこと）。
  - 決定論のテストと、実物の書体（游ゴシック）の読み戻し。
  - 扱いを変えたときの `doc/COMPAT_ARCHITECTURE.md` §8 の行（表の末尾への追記）。
- **Out of scope**:
  - 縦書きの帯の形（完了 `vertical-choice-hover-band` で済み・変更 0）。
  - 行送り（設定の `line_pitch` と行送りの行間）。
  - 字の描画そのもの（DirectWrite の組み方・字の位置）。書式に行の間隔を設定して組み方を変えることも含む（brief の Out・要件の討議で要ると決まらない限り取らない）。
  - 選択肢の飾り（`choice-marker-styling`）・`cursor.*` の色と混ぜ方。
  - 書体の引き当て（`balloon-font-file`）。
  - 大きさの違う行が隣り合うときの帯の重なり（源は行送りの決まりで字のインク同士が重なること・帯は行ごとのまま・起票しない＝2026-11-01 設計の討議の裁定）。
- **Adjacent expectations**:
  - 完了 `vertical-choice-hover-band` の、縦書きの帯を DirectWrite が測った基線から置く形とその測り方を前例として使う。縦書きの帯の数値と画素は本 spec で動かさない（要件 5.2）。
  - 完了 `choice-ranges-one-function` の「帯と当たりを 1 つの関数から出す」形に乗る。本 spec はその形を崩さない。
  - `audit-emo-text-layout-draw`（v0.1.0 の後）・`text-typesetting`・`balloon-font-file`・`clippy-199-lints` の段 2 が同じファイルを後で触る。本 spec はそれらの持ち分（見直し・組版・書体の引き当て・既存の lint の指摘）を先取りしない。
- **同じウェーブ（2026-10-31 C15）との約束**:
  - 触るのは emo-text の `draw_metrics.rs`・`choice.rs`・`layout.rs`（字の寸法を渡す口）・新しいテストのファイル `src/viewbox_draw_line_gap_band_tests.rs` とその子の宣言（`viewbox_draw.rs`）と `lib.rs` の一覧の 1 行・要るときだけ `viewbox_draw_vertical_band_readback_tests.rs` の助けの関数の可視性の 1 語・§8（設計の段で `tests/line_pitch_readback_test.rs` は触らないと決めた）。C15 のほかの 5 本は emo-text に触らない。
  - emo-text に新しいソースファイルを足してよいのは C15 では本 spec だけ（1 ウェーブに 1 本だけの席）。足すなら `lib.rs` の一覧の行も足す。
  - 依存を足さない。1 ファイル 1,000 行を超えない（上限に近い `choice_tests.rs`・`draw_format_metrics_tests.rs` へは検査を足さない）。
  - 実物の書体の読み戻しは GPU を使う検査で、排他テストの机を取って短く 1 回。静かな机・前後の全体テストの比べは要らない。

## Requirements

### Requirement 1: 直す前に測って裁定を確かめる

**Objective:** As a 開発者, I want 横書きの帯がどれだけずれているかを実物の書体で測った数で確かめてから直す, so that 裁定した案 2 が実際のずれに合っていることを確かめられる

#### Acceptance Criteria

1. When 実装の最初のタスク（帯の式を直す前）, the 本 spec shall 游ゴシック（書体の行間を持つ書体）の横書きの大きさ 20 と 28 について、DirectWrite が組む行の箱・基線・仮名と漢字のインクの上下の位置・今の帯の厚みと置く所を実物の描画から読み戻し、帯とインクの上下の余白（物理画素）とともに spec のフォルダの記録へ残す。
2. When 要件 1.1 を測る, the 本 spec shall 同じ形で書体の行間 0 の書体（Yu Gothic UI・ＭＳ ゴシック）も測り、今の帯と字の関係の基準として同じ記録へ残す。
3. When 要件 1.1・1.2 の数が揃った, the 本 spec shall 案 2 で帯がどこにどの厚みで塗られるかを測った数から出して記録へ残し、案 2 で要件 2.1〜2.3 を満たせると確かめてから直しに入る（満たせないと分かったら要件 2.7 に従う）。
4. If 要件 1.1 の測りで、横書きの帯が今のままで要件 2 を満たしている（ずれていない）と分かった, the 本 spec shall 帯の式に触らず、`GlyphMetrics::line_box_height` の説明の事実と違う所（DirectWrite が行を ascent ＋ descent で組むという記述）を直し、記録だけの検査（要件 1.5）と `doc/COMPAT_ARCHITECTURE.md` §8 の行（要件 4.3）を残して閉じる。測った数は開発者へ報告するが、決めを仰いで止まらない。
5. The 本 spec shall 要件 1.1・1.2 の測りを、普段のテストの走行では回らない記録だけの検査として残し、後から同じ測りを回し直せるようにする。

### Requirement 2: 書体の行間を持つ書体の横書きの帯を字に対して中央に塗る

**Objective:** As a ゴーストの利用者, I want 游ゴシックなどの書体の横書きのバルーンで、選択肢に乗せた帯が字に合って塗られる, so that どの選択肢を選ぼうとしているかが読め、帯の外へ字がはみ出さない

#### Acceptance Criteria

1. While バルーンが横書きで、行の書体が書体の行間を持つ, when 利用者が選択肢の範囲にマウスを乗せた, the areka shall 帯の中心を、その行の字の箱の中心に合わせて塗る（ずれは画素への丸めの 1 画素以内）。書体の行間 0 の書体で今の帯が字の箱に対して置かれている関係と同じ関係にする。
2. While バルーンが横書きで、行の書体が書体の行間を持つ, the areka shall 帯の厚みを em の丈以上・行送り以下にし、その行の仮名と漢字のインクを上下とも帯で覆う。
3. While バルーンが横書きで、隣り合う 2 行の大きさが同じ, the areka shall 帯を隣の行の帯と重ねない（接してもよいが重ならない）。大きさの違う行が隣り合うときの帯の重なりは今の形のまま（字のインク同士が行送りで既に重なるため・本 spec の外・2026-11-01 設計の討議の裁定）。
4. Where 行の中に既定より大きい字（`\f[height,…]` など）が在る, the areka shall その行の大きさから帯の厚みと置く所を決め、大きい字のインクも帯で覆う。
5. Where アンカー（`\_a`）の範囲が選択肢と同じ帯で塗られる, the areka shall 横書きのアンカーの帯にも要件 2.1〜2.4 と同じ形を使う（選択肢とアンカーで帯の形を分けない）。
6. The areka shall 帯の厚みを、今の決まり（字の箱の丈を em の丈と行送りのあいだに収めた値＝書体の行間を厚みに数えない）で決め、書体の行間を持つ書体と持たない書体で同じ決まりを使う（書体の名前で分けない）。
7. If 裁定した直し方で要件 2.1〜2.3 のどれかを満たせない（中央に置くと字のインクが帯の外へ出る・隣の行の帯と重なるなど）, the 本 spec shall どれを先にするかを自分で選ばず、測った値を添えて開発者の決めを仰ぐ。

### Requirement 3: 当たりを塗りと同じ所にする

**Objective:** As a ゴーストの利用者, I want 見えている帯の所をクリックすればその選択肢が選ばれる, so that 見た目と操作が食い違わない

#### Acceptance Criteria

1. While バルーンが横書き, the areka shall どの書体でも、選択肢とアンカーの当たりの範囲を、その帯を塗る範囲と数値まで同じにする。
2. While バルーンが横書きで、行の書体が書体の行間を持つ, when 利用者が帯の中の点（字のインクの上を含む）をクリックした, the areka shall その選択肢を選ぶ。
3. If 1 つの点が隣り合う 2 つの行の帯の境に在る, the areka shall その点をたかだか 1 つの選択肢にだけ当てる。

### Requirement 4: 行の箱の寸法を読む所の食い違いをなくす

**Objective:** As a 開発者, I want 書体から測った行の箱の寸法を読む所が、DirectWrite が実際に組む行の箱と食い違わない, so that 同じ種類のずれが別の所で再び起きない

#### Acceptance Criteria

1. The areka shall 横書きの帯の置く所を、書体から測った行の箱の寸法でなく DirectWrite が測った基線（字の置き場）から決め、帯の厚みは字の箱の丈として読む（DirectWrite が組む行の箱とは読まない）。
2. If 書体の寸法が測れない（書体が見つからない・書体の表の値が使えないなど）, the areka shall 今と同じ縮退の値と記録の扱いを保つ（縮退の扱いを本 spec で変えない）。
3. Where 本 spec が行の箱の寸法の意味や扱いを変えた, the 本 spec shall `doc/COMPAT_ARCHITECTURE.md` §8 の表の末尾へ、変えた扱いと根拠（測った数・裁定）の行を足す。
4. Where 縦書きの em の箱の置き場の既定の決め方（横書きに束縛した寸法へ縦書きを問うときの逃げ道）, the 本 spec shall 本番でその道を通らないことを設計の段で確かめ、確かめられたら値を変えずに説明で示すだけにする。通る道が見つかったときだけ、行の箱の寸法を読まない形に改める（そのとき書き換える檻は要件 5.4 の記録の決まりに従う）。

### Requirement 5: 変えないもの

**Objective:** As a 書体の行間 0 の書体や縦書きのバルーンの利用者, I want 直っている帯と字が今のまま, so that 本 spec の直しで別の所が崩れない

#### Acceptance Criteria

1. While バルーンが横書きで、行の書体の書体の行間が 0（Yu Gothic UI・ＭＳ ゴシック・既定の書体）, the areka shall 選択肢とアンカーの帯と当たりを、今と数値も画素も同じにする（今ある画素の一致の検査を 1 バイトも動かさない）。
2. While バルーンが縦書き, the areka shall どの書体でも、選択肢とアンカーの帯と当たりを今と数値も画素も同じにする。
3. The areka shall 字の描画（字の置き場・行送り・字の画素）を、どの書体と向きでも今と同じにする。
4. The 本 spec shall 帯と当たりの今ある検査を、1 本も消さず、ゆるめず、すべて通す。期待値を書き換えてよいのは書体の行間を持つ書体の横書きの帯と当たりを固定している検査だけとし、書き換えた検査ごとに元の期待値と新しい期待値を記録へ残す。

### Requirement 6: 検査と実物の書体の読み戻し

**Objective:** As a 開発者, I want 書体の行間を持つ書体の横書きの帯が、決定論のテストと実物の書体の読み戻しの両方で確かめられている, so that 再び崩れたら気づける

#### Acceptance Criteria

1. The 本 spec shall 書体の行間を持つ寸法（DirectWrite が組む行の箱が字の箱より大きい）を与えた決定論のテストで、横書きの帯が要件 2.1・2.2 を満たし、当たりが帯と数値まで同じ（要件 3.1）であることを確かめ、書体の行間 0 の寸法だけでは確かめたことにしない。
2. The 本 spec shall 実物の游ゴシックの横書き（大きさ 20 と 28）の描画を読み戻し、帯が仮名と漢字のインクを上下とも覆い、字の箱に対して中央（要件 2.1）であることを確かめる検査を残す。検査は引けた書体の名前を中で固定し、游ゴシックが無い機械では赤になる（代わりの書体のまま緑にしない）。
3. If 直しを外した（横書きの帯を今の決め方に戻した）, the 要件 6.1 のテスト shall 赤になる（本 spec は直しを外すと赤になることを 1 度確かめて記録に残す）。
4. When 実物の書体の読み戻しを回す, the 本 spec shall 排他テストの机を取って短く 1 回だけ回し、終わったらすぐ机を返す（赤が出たら回し直しは赤のテストだけに絞る）。
