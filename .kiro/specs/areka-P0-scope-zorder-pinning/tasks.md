- [x] 1.3 鎖の型・帳簿・差分の純判断・後押しの選定
  - 望む鎖（手前から奥へ並んだ窓の列・張るべき繋ぎの列・窓が無かった宣言要素）を運ぶ型と、その受け口を置く
  - 自分が張った繋ぎの帳簿を、被所有側に付く形で置く。張った時点の相手の窓ハンドルを控え、撤去前の照合に使えるようにする
  - 望む繋ぎと現況の帳簿から出すべき操作列を導く純関数を置く。返り値は**必ず全ての撤去が先・全ての付与が後**
  - 後押しの指令を組む純関数を置く。**鎖の先頭を 2 番目の直後へ差し直す 1 形のみ**とし、参照するのは自分の窓 2 枚だけ。位置・寸法・活性化を伴わない
  - 窓が 2 枚未満なら後押しを出さない
  - 記録を出す口はこのモジュールに集約する（別モジュールから出すと照合の対象が分裂する）
  - 新しいモジュールはこの task で登記し再輸出する（areka から受け口の型を取り込めるようにするため）
  - **本番ファイルを 1 本増やしたら、その task の中で両層の名簿へ自分のファイルを足す**（名簿の檻は「実在する重なり順系の本番ファイルが 1 本残らず載っている」ことを両向きで見張るので、足した瞬間に赤くなる）
  - 完了状態: 差分の 4 形（追加のみ・撤去のみ・張り替え・変化なし）と後押しの選定が決定論テストで緑になり、**自分の窓以外の窓ハンドルが後押しの指令に現れないこと**が檻で固定される

- [x] 2.2 (P) 鎖の適用系（差分の書込・後押し 1 回・直後の実測・記録）
  - 望む鎖に変化が無ければ**即座に何もしない**（1 命令も出さない）
  - 去る窓の繋ぎを**破棄に先立って**外す経路を持つ
  - 撤去は「帳簿にあり、かつ外す前に読んだ現況が帳簿と一致する」繋ぎだけに限る。食い違えば実行環境の呼び出しを行わず帳簿だけ落とし、理由つきで記録する
  - 付与に失敗した繋ぎは**その 1 本だけ**飛ばし、残りは張る。同じ巡で再試行しない
  - 実際に操作が走った巡だけ、鎖全体へ後押しを 1 回出す
  - 後押しの**直後に**重なりを実測し、宣言と実測を対応づけて 1 行に載せる。実測では実行環境上で非表示の窓を読み飛ばし、最も近い可視の隣で判定する（既存の実測の口を流用する）
  - 見送り・拒否・失敗のいずれの経路でも記録を残さないまま諦めない
  - **処理の実行を促す呼び出しを行わない**——ソースにその呼び出しが無いことを字面で固定し、併せて「呼ぶ側の実装へ差し替えると赤になる」対照を置く
  - 記録を捕捉する檻は単一スレッドの実行器を明示する（既定の実行器では 1 行も拾えず、検査が空虚に緑になる）
  - 適用系のモジュールはこの task で登記する（結線は 3.2）
  - **本番ファイルを 1 本増やしたら、その task の中で両層の名簿へ自分のファイルを足す**（名簿の檻は「実在する重なり順系の本番ファイルが 1 本残らず載っている」ことを両向きで見張るので、足した瞬間に赤くなる）
  - 完了状態: 偽ハンドルの 1 巡テストで「変化なしなら無操作」「撤去が先・付与が後」「食い違いでは実行環境を呼ばない」「失敗した 1 本を飛ばして残りを張る」が緑になり、促しの呼び出しの不在が対照つきで固定される

- [x] 2.3 後押しの空振りを塞ぐ（**2026-08-30 に実窓検証で掘り当てた本番欠陥・後から起票**）
  - 欠陥: 後押しは「鎖の先頭を 2 番目の直後へ差し直す」1 形だが、**先頭が既に 2 番目の生の直後に居ると Windows は Z 変更を省略し、所有関係の再強制も走らない**＝完全な空振りになる。適用系は後押しの前に印を降ろし再試行経路を持たないので、1 度空振りすると計画の内容が変わるまで鎖は収まらない
  - **本番の起動直後の配置がまさにその引き金**: 本番は各スコープでバルーンを先に・キャラ窓を後に生成し、ブロックの並びは「バルーン・キャラ窓」なので、先頭＝最前スコープのバルーン・2 番目＝その相棒キャラ窓になる。解くはずのペア機構の是正は巡の後の掃き出しで書かれ、同じ巡の鎖の適用はその前に走る
  - **4 枚（2 スコープ＝本番の最小構成）で再現する**。既存の実窓の檻が緑なのは、不可視の既定 IME 窓がたまたま間に居るからであって、本番にその保証は無い
  - **同じ「1 発限り」の性質が持つ隣接ハザードがもう 1 件ある**: 適用系は印を `execute_ops` より**前**に降ろすので、ハンドル未取得の巡は何も書かないまま印だけが消える。しかも計画の解決は在庫と entity の実在だけを見て **HWND を要求しない**ため、計画は HWND 生成より前に公開されうる。その場合、後からハンドルが現れても計画の内容は変わらないので再公開されず、**印は二度と立たない**。本番でこの順序になるかは未確定だが、採る是正はこの経路の影響を受けるので必ず確かめること
  - **⚠ 前提の限界**: 「Windows が Z 変更を省略する」は実測で得た**相関と結果**（隣接 ⇒ 1 枚も動かず所有関係の再強制も走らない）であって、公式に保証された挙動ではない。**隣接判定に依存しない形を選べばこの前提自体が不要になる**。採る形の有効性は必ず実測で確かめること
  - 是正の方針は実測で決めること。**指令を出す前に現況を読んで「既に望む位置なら別の形を採る」か、後押しの形そのものを見直すか**——ただし要件 14.2（毎巡の観測と是正の禁止）と要件 11.1（窓を動かさない）を破らないこと。1 巡 1 回の原則も守る
  - 決定論テストで是正の判断分岐を全網羅し、**実窓では窓の生成順を降順にした構成**（＝引き金配置）で鎖が収まることを示す
  - 既存の実窓の檻 3 ファイルへ、引き金配置の変種を足すか、生成順を降順へ改めること。**「不可視 IME 窓の居場所に乗って緑」の状態を残さない**
  - 完了状態: 引き金配置で鎖が収まることが実窓で緑になり、是正を経路から外す変異で赤が出る。既存の実窓の檻が生成順の反転でも緑を保つ
  - _Requirements: 1.1, 1.2, 8.2, 11.1, 14.1, 14.2_

## 実装上の共通制約

- 新設するファイルはすべて 1,000 行未満で作り、行数の例外表には触れない（並走 spec の共有ファイル）
- 決定論テストは実装と同じ場所へ兄弟として置く
- 重なり順系の**本番ファイルを増やしたら、その作業単位で両層の名簿へ足す**。名簿の檻は「実在する本番ファイルが 1 本残らず載っている」ことと「載っているファイルが実在する」ことを**両向きで**見張るので、片側だけ直すと必ず赤くなる
- 窓の位置と寸法を扱う既存の指令経路には触れない（並走 spec の領域）。本 spec は窓を動かさない
- **cargo は必ず PowerShell から実行する**。Git Bash の GNU coreutils `link.exe` が MSVC のリンカを遮蔽する
- **`cargo test -p areka --lib` は使わない**——areka は bin crate なので `error: no library targets found` で exit 101 を返し、テスト失敗と区別が付かない
- 検証コマンド一式に `cargo fmt --all -- --check` を必ず含める（初版で 2 度、書式が赤のまま着地した）
- `| tail` は終了コードを tail のものにする。緑の判定は終了コードで取る
- 記録の語の照合は必ず冠（角括弧）込みで行う
- そのほかの道具の罠と初版の教訓は後半の「実装上の申し送り」を読むこと（60 項目超）
