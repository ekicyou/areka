# Implementation Plan

> 設計 `design.md`（2026-10-23）の部品ごとに分けた。sylphya の口（1）→ areka の読み手と表（2）→ 実行系への結線と道を通すテスト（3）→ 台帳・手順書・実機（4）の順。push・PR・merge は `/kiro-complete` の役目で、このタスクでは行わない。

- [x] 1. sylphya に「名前の形に登録された読み手を、読まれた時に呼ぶ口」を足す
- [x] 1.1 名前の形・読み手・登録の表を作る
  - 名前を今の点付きの名前の読み方で読み、選択子の付いた区切りの選択子を `(*)` に寄せた正準の形を作る（英字は今の読み方が小文字に畳んだもの・選択子の無い区切りはそのまま別の形）
  - 読み手は「読まれた名前に答える・値なしもある」だけの約束で、待たず遅れない読み取りに限ることを型の説明に書く
  - 登録の表は読み口の複製どうしで共有し、同じ形への 2 度目の登録は前の読み手を置き換える。引く時は鍵を取って読み手を写しすぐ外す（鍵の壊れ〔poison〕でも中身で続ける）
  - sylphya の依存（Cargo.toml）を増やさず、OS の型を持ち込まない。crate の外へは形と読み手の型だけを公開する
  - 完了の状態: `cargo build -p areka-sylphya` が通り、形の文字が `currentghost.scope(0).rect`・`currentghost.scope(*).rect`・`CURRENTGHOST.SCOPE(00).RECT` で同じになることを形の単体の確かめで示せる
  - _Requirements: 5.1, 5.2, 7.1, 7.2, 7.3, 7.4_

- [x] 1.2 読み口が写しの区画に無い名前だけを登録の表へ聞くようにし、言い過ぎのコメントを直す
  - 読み口に登録の口を足し、今の作り方（写しだけを受ける作り方）は変えない
  - 点付きの名前の読み（名前の文字・読んだ名前の両方の入口）は、問い手の区画 → 大域の区画 → どちらにも無い時だけ登録の表、の順で引き、読み手の答えを値か値なしで返す。フラットの名前と台本向けの写しの読みは読み手を引かない
  - 読み手の答えは写しにも保存にも書かない。「どこにも無い」の debug の記録は読み手も無い・値なしの時にだけ出す
  - 読み口の冒頭のコメントと、写しの読み（`load`）の説明を、完了 spec の要件 2.7・8.3 の言い方（他のスレッドを待たない・遅れうる値源を載せない・外の環境は外から登録した読み手を通す）へ直す。写しの読みのコードは変えない
  - 完了の状態: `cargo test -p areka-sylphya` の今のテストが全部緑のまま、読み口に登録の口が在る
  - _Requirements: 6.4, 6.6, 7.1, 7.5, 7.8_

- [x] 1.3 口の決定論テストを兄弟のテストファイルに置く
  - 形: `scope(0)`・`scope(00)`・大文字の名前が同じ読み手に届き、`currentghost.scope.rect`・`currentghost.scope(0).rect.x` は届かない
  - 引く順: 大域の区画に同じ名前の値が在れば読み手を登録しても答えが変わらず、登録の前後で別の名前の答えと台本向けの写しが変わらない
  - 共有と置き換え: 登録の前に作った読み口の複製でも登録した読み手で答え、同じ形への 2 度目の登録で答えが替わる
  - 再入: 読み手の中から同じ読み口で別の名前を読んでも止まらない。保存しない: 読んだ後も写しの世代の数が変わらない
  - 完了の状態: `cargo test -p areka-sylphya` で新しいテストが全部緑
  - _Requirements: 1.9, 3.6, 5.2, 6.3, 6.4, 6.6, 7.4, 7.5_

- [x] 2. areka に窓の矩形の読み手と、スコープ → 窓の印の表を作る
- [x] 2.1 窓の矩形の読み手と数の形を作る
  - 新しいファイルを作り、`ghost_session` の中にモジュールとして `pub(crate)` で宣言する（3.3 の MCP のテストから差し替え口を使うため。宣言だけで、系の登録と結線は 3.1）
  - 窓の印は HWND の生の値で持ち、画面の矩形は物理の画素・右と下は外の最初の画素とする。4 つの数は `左,上,右,下` を `,` でつなぎ、空白・`+`・前ゼロを付けない
  - 名前の選択子の読み: 番号はそのスコープ、`-` と 1 つ以上の半角数字は負の番号（窓を持たないスコープ）、それ以外（`x`・空・`+1`）は書式の誤りで値なし
  - 答えは設計の「場面 × キャラクター／バルーン」の表どおり（無い番号・負の番号・印がまだ無い・OS の失敗はキャラクター `0,0,0,0`・バルーン値なし）。画面に出ているかは見ない
  - 表の鍵は窓の印を写す間だけ持ち、OS の読み取りは鍵の外で 1 回だけ呼ぶ。OS の失敗は debug（`scope_rect_window_gone`）で、警告以上を出さない
  - 完了の状態: `cargo build -p areka` が通る（呼び手が 3.1 まで無いので dead_code の警告は 3.1 まで許す）。答えの表の全場面は 2.4 のテストで確かめる
  - _Requirements: 1.1, 1.2, 1.4, 1.7, 1.8, 1.9, 2.1, 2.4, 3.1, 3.2, 3.5, 3.6, 4.7, 5.5_

- [x] 2.2 本物の OS の窓の矩形の読み取りを作る
  - 呼ぶ間だけ呼んだスレッドの DPI の扱いをモニタごとの v2 にし、`GetWindowRect` を 1 回呼び、扱いを元へ戻す。扱いを変えられなかった時は読みは行い、戻しはせず debug（`scope_rect_dpi_context_unchanged`）を残す
  - 失敗（壊れた窓の印）は値なし。`unsafe` はこの関数の中に閉じ、新しい依存も `windows` クレートの機能の指定も足さない
  - ukadoc の 2 つの名前の `// ukadoc:` の行（カタログの URL の形）をこの関数に添える
  - 完了の状態: `cargo build -p areka` が通り、読み手の既定の読み取りがこの関数になっている
  - _Requirements: 1.3, 1.5, 1.6, 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 5.1_

- [x] 2.3 スコープ → 窓の印の表と、その出し方（結線と系）を作る
  - 表は窓の一式（`GhostWindows`）の各スコープについて、キャラクターとバルーンの窓の entity に付いた窓の印を引いて組む（印が無ければ空）。可視の欄は持たない
  - 結線: 渡された sylphya の読み口に対し、今の World から表を組んで新しい置き場へ入れ、テスト用の差し替え口が在ればそれ、無ければ本物の読み取りを使って、キャラクター用とバルーン用の読み手を 2 つの形へ登録し、置き場を World の資源として置き換える（実行系ごとに新しい置き場）
  - 系: 窓の一式が変わった・窓の印が付いた・外れた、のどれかの時だけ表を組み、中身が違う時だけ差し替えて debug（`scope_rect_table_updated`）を出す。置き場が無ければ何もしない。系をプロセスに 1 回載せる登録の関数も作る（段は `FrameFinalize`）
  - 値ごとの型は設計の「値ごとの型」の表どおり（矩形はプル・表と登録はプッシュ）に保ち、毎フレーム比べる仕組みを作らない
  - 完了の状態: 結線の関数・系・登録の関数が在り、`cargo build -p areka` が通る（dead_code の警告は 3.1 まで許す）
  - _Requirements: 2.2, 3.3, 3.5, 5.3, 5.4, 6.1, 6.2, 6.5, 7.6, 7.7_

- [x] 2.4 読み手と表の決定論テストを兄弟のテストファイルに置く
  - 偽の窓の印は、このテストファイルの中に自前の `fake_handle(raw) -> WindowHandle` を置いて作る（共有の部品は無く、`placement/follow_test_support.rs` などの写しに倣う）
  - 数の形: 主の画面より左上の画面の矩形（`-2560,195` の画面の `-782,201` から幅 831・高さ 1026）が `-782,201,49,1227` になる
  - 無いとき: 表に無い番号・`scope(-1)`・印の無い窓・OS の失敗でキャラクター `0,0,0,0`・バルーン値なし。`scope(x)`・`scope()`・`scope(+1)` は両方値なし
  - 1 回の問い合わせ: 呼ぶたびに違う矩形を返し回数を数える偽で、1 回の読みの呼び出しは 1 回・答えはその矩形そのもの
  - 動いた後: 偽の OS の矩形を替えた後（ドラッグ・`\![move]`・拡大率の違う画面・面の替わり・一緒に動いた窓とバルーン）の読みは新しい矩形。重なった 2 つの窓は同じ数。窓の在る `scope(2)`（3 人目）も同じ形で答える
  - 表の出し方（窓なしの World・窓の一式を作る今の関数と偽の窓の印）: 印が付く前は窓が無い答え、付いた後のフレームで矩形、entity を消したフレームで窓が無い答え。可視の変化では表が替わらない
  - 移動で仕事をしない: 窓の位置を毎フレーム書き換える数十フレームの間、`scope_rect_table_updated` が 0 件。読みを繰り返す間に WARN 以上が 0 件（記録の捕捉）
  - 完了の状態: `cargo test -p areka ghost_session_scope_rect` で全部緑・テストファイルが 1,000 行を超えるなら設計の決まりどおりテーマで分ける
