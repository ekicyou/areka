- [ ] 2. 純粋な芯: 範囲の表と出す番の状態機械

- [x] 2.1 範囲の表と当たり
  - 窓のエンティティに付ける範囲の表を作る。登録の順に並べ、持ち手の通し番号は窓ごとに増えるだけで使い回さない
  - 登録・差し替え（並びの位置は保つ）・取り消し・取り出し・当たり（後ろから探して後から登録した方が勝つ）を持つ。範囲は論理の単位で持ち、窓の全体も範囲にできる。空の文字は預けていないものとして持つ
  - 兄弟のテストで固定する: 重なりの勝ち負け・差し替え後の順・窓の全体・空の文字・取り消した持ち手が当たらない・通し番号を使い回さない

- [x] 2.2 出す番の状態機械（待ち・来た・取り消し・安全地帯・終わり・入り直し）
  - 状態を「何もない・待ち・出す番・押したので休み」の 4 つで持ち、時刻・マウスの位置・押下・足元・追っている範囲の様子を引数で受けて 1 回進め、「すること」（期限を預ける・来た・消す・終わった）を返す
  - 待ちに入るときだけ OS の設定を（引数の関数で）読み、期限を設定の 2 倍（直前のツールチップが消えてから 0.2 秒以内なら 1 倍）に決める。範囲の中で動いても期限を動かさない。設定を読めないときの代わりの 400 ミリ秒を定数で持つ
  - 出す番の間は足元を ツールチップ → 範囲（窓が受けていれば続く。受けていなければ位置が変わったかで「安全地帯から出た」か「窓が隠れた」）→ 通り道 → それ以外 の順に見る。終わったその回のうちに別の範囲の待ちまで進める
  - 来たの「すること」に、その範囲に文字が預けてあるかを載せる
  - 印は発行のたびに 1 ずつ増やし、来た・終わったは同じ印について 1 回ずつ。待ちから外れるだけなら知らせを出さない。待ちと出す番の間は毎回期限を預け直す（出す番の間は 100 ミリ秒の見回り）
  - 判定の分岐（入った・数え始め・使った待ち時間・来た・来なかった理由・終わりの理由）を `trace` に残す
  - 兄弟のテストで固定する: 799 ミリ秒では来ず 800 ミリ秒で 1 回・範囲の中の移動で期限が動かない・0.2 秒以内の出し直しは 400 ミリ秒（201 ミリ秒後なら 800）・待ちの途中の出た／押した／隠れた／壊れた／取り消しで何も出ない・安全地帯の中の移動で終わらない・各理由での終わり・押した後は入り直すまで来ない・別の印・動かないまま受けなくなったら「窓が隠れた」・動いて受けなくなったら「安全地帯から出た」・ツールチップの中なら受けていなくても続く・出てそのまま別の範囲へ・代わりの 400 ミリ秒で 800 ミリ秒に来る・期限の預け直し
  - 完了の状態: 状態機械のテストが、実際の時間を待たず窓も作らずに緑
  - _Requirements: 1.1, 1.2, 1.4, 1.6, 1.7, 1.8, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 2.8, 2.9, 2.10, 3.13, 6.4, 7.1_

- [x] 2.3 印の照合（文字を渡す・消す・表示の結果・取り消しの同期の終わり）
  - 印を照らして渡された文字をどうするか（出す・空なので消す・終わった印なので出さない）を決める。出す番が続いている限り時間の上限なく受ける
  - 利用側の「消して」で消す（出す番は続く）。表示の結果（出た矩形・出ていない）と消えた時刻を覚える。表示が失敗しても状態を変えない
  - 登録の取り消しを同期で反映し、追っている範囲なら消す・終わったを返す
  - 預けた文字が無い出す番では、渡されるまで出さない
  - 兄弟のテストで固定する: 続いている印で出す・空で消す・終わった印・前の印を後の出す番に渡す・長い時間の後・預けた文字が出ている間の置き換え・消した後も続いて渡せばまた出る・表示の失敗の後も終わりの判定が続く・取り消しで終わる
  - 完了の状態: 印の照合のテストが窓を作らずに緑

## Implementation Notes

- 1.1: 新しいワークツリーでは areka のテストの前に i686 の `shiori-host32-helper` と `shiori-host32-testdll-loadu` を `--target i686-pc-windows-msvc` でビルドしておく（無いと `mcp_get_log_real_run`・`smoke_boot_loop_exit` が赤）
- 1.1（範囲外・完了の棚卸で起票）: 明示したときだけ走る `AREKA_EMO2_REAL_RUN=1` の `emo2_real_run` が `crates/areka/tests/emo2_real_run.rs` の `wrap=BudouxWordWrap` の待ちで赤。マニフェストを外しても同じく赤＝この spec の前からの問題。192 DPI の debug ビルドで文字の取り付けが起動から約 2.5 秒かかり、3 秒の自動終了に間に合わない見込み
- 1.2: `cargo clippy -p wintf --all-targets -- -D warnings` は前からある警告（dola 約 10 件・wintf 約 143 件）で赤。この spec の判定は「`ecs[\/]tooltip` を指す警告が 0 件」（`cargo clippy -p wintf --all-targets -j 2 2>&1 | grep -E "ecs[\/]tooltip"`）
- 1.2: `tooltip/mod.rs` の `mod geometry;` に `#[cfg_attr(not(test), expect(dead_code))]` がある。os.rs（3.1）が使い始めたら外す。`force_break` の `fit` は Rust の `char` の数で返す約束＝os 側で `GetTextExtentExPointW` の UTF-16 の数を `char` の数に直す（サロゲート対に注意）
- 2.2（4.2 で使う）: `TurnMachine` は出す番の始まりの論理の矩形 `Turn.area` を持つが、読み出しの口が無い（`tracked_range()` は持ち手だけ）。殻が `Tracked::Present.range_px` を始まりの矩形から作るなら、4.2 で読み出しを足す。位置が読めないまま待ちの期限を過ぎると `ArmDeadline(過ぎた期限)` が毎回返る＝殻はすぐ起き直さないよう扱う
- 2.3（4.3 で使う）: `supply` は `HideEmpty` を返すだけでツールチップの矩形を外さない（`now` を受けない設計の形）。殻は `HideEmpty` で表示を消した後に必ず `set_tip(None, now)` を呼ぶ（忘れると矩形が安全地帯に残り、消えた時刻＝出し直しの起点も記録されない）。表示の失敗も `set_tip(None, now)` で渡す（出ていなければ起点にならない）。`HideReason` の `#[cfg_attr(test, expect(dead_code))]` は 4.3 で `Dismissed`/`EmptyText` を作り始めたら外す
- 3.1（3.2 で必ず確かめる）: `os.rs` の `tool_info` は道具の `hwnd` にツールチップの窓自身を入れている。`TTF_TRANSPARENT` がマウスのメッセージを道具の hwnd へ回す作りなら自分へ再帰しうる＝S4（メモ帳の上で押す）とツールチップの上での移動（2.5 の安全地帯）を必ず通し、落ちたら `tool_info` の hwnd を null にする（道具を指すのは全部 `tool_info` を通るので 1 か所）。直さない場合も理由を註釈に書く
- 3.1（3.2 か 6.1 で確かめる）: `make_lparam` は負の座標を 16 ビットの 2 の補数で詰める。`TTM_TRACKPOSITION` が符号付きで読むかは実機でしか決まらない＝主画面の左の画面（負の座標）で出す確認を入れる。`TTTOOLINFOW.cbSize` は古い版でも通る V2 の大きさ
- 3.2（4.2 で使う）: S7 の逃げ道で `TipWindow::keep_on_top()` を足した。出す番の間の見回り（100 ミリ秒）から毎回呼ぶ（後から最前面へ当て直した別のいつも手前の窓に覆われるため）
- 3.2: 古い版（テストの exe）は追跡を始める前に `TTM_GETBUBBLESIZE` を送るとプロセスごと落ちる＝`set_text_and_measure` は出ていなければ画面の外で追跡を始めてから測る。追跡中かは `IsWindowVisible` で代用＝版 6 で `TTM_TRACKACTIVATE(FALSE)` の後もフェードで見えたまま残らないか、6.1 で「消してすぐ出す」を確かめる。画面の外の位置に本当に置かれたかの判定は S3・S4 の走らせ直しと一緒に足す
- 4.1: `register`・`update` の期限の預け（`tick_wake::arm_deadline`）はテストで固定していない。共有の錠 `crate::ecs::world::TICK_WAKE_TEST_LOCK` はあるが、無条件の配線で判断の分岐ではないため（固定するなら `register`/`update` を呼ぶ tooltip のテストすべてに錠を取らせる必要がある）
- 4.2（4.3・5.1 で使う）: `note_button_press` は `system.rs` にある（5.1 は `tooltip::system::note_button_press` の道か、mod.rs に `pub(crate) use` を足して呼ぶ）。本物の差し込み（`os::sample`・`os::read_hover_time`・`WindowHandle` の hwnd → `os::is_visible`）は 4.3/5.1 の `tooltip_frame` が組み立てる。早戻りは「`TooltipRanges` を持つ窓が 0 件かつ Idle」＝全部取り消して空の表が残ると早戻りしないので、4.3 の取り消しで表が空になったら部品を外すかを決める
- 4.3: 表示の窓は資源でなく UI スレッドの thread_local に置いた（4.2 の「表示の窓…を資源 1 つに持つ」から変更・design.md の system に反映済み）。空になった範囲の表は部品を残し（通し番号を使い回さない）、早戻りは「中身のある表が 0 件かつ何もない」で見る
- 5.2（開発者に諮る）: 出す番が来た後は、足元が別の範囲でも、始まりの範囲の矩形・ツールチップ・通り道の中にある限り同じ出す番が続く（turn.rs の `check_active`）。そのため窓の全体の中にボタンを入れ子で登録すると、窓の全体の説明が出ている間はボタンへ切り替わらない。用語集「重なった所は後から登録した範囲だけに入っている」を出す番の後にも当てるなら変わるが、要件 2.5（範囲からツールチップへ渡る通り道では終わらない）とぶつかる。今は文書に今の振る舞いを書き、切り替えたい範囲は重ねずに登録するよう案内した
