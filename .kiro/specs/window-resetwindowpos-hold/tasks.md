## Implementation Notes

- `cargo clippy -D warnings` は areka-parsers・dola・wintf などの既存の警告で止まる（この spec の差分の外）。clippy は `-D warnings` なしで回し、触ったファイルに警告が無いことを見る。
- `ShownRatioSource` の trait に一時の `#[cfg_attr(not(test), expect(dead_code, ...))]` がある。判定が `never_shown`・`physical_size` を使い始めたタスクで外す（外し忘れは「満たされない expect」の警告で見える）。
- 表示層の「面の指令を受けた」印は `Hide` でも立つ（未表示の `\s[-1]` を `Hidden` と読むため）。
- 赤の檻（直す前・`cargo test -p areka-runtime --lib reset_hold`）: (c) 隙間 0 は緑。(a) 先頭の窓の右端 left 2522 / right 2574（52px＝(434−330)/2）、(b) 起動の確定が `chain_finalize: 実表示寸で連鎖を再解決 scope=1 from_x=1886 to_x=1962` を出した、(d) 巡 1 に `reset_window_pos_held` が無く仮の大きさで `reset_window_pos` が即座に当たった、の 3 本が赤。1 passed; 3 failed。
- 預かった並べ直しの `reset_window_pos_held` は届いた巡だけに出る。今は並べ直しを塞げるのは前に預かった並べ直しだけ（その行は出ている）なので記録は欠けないが、指令ごとに判定が変わる形（トークの終わりの通し番号）を入れたら、塞がれて届いた並べ直しが記録無しで待たないかを見直す。
- `physical_size` の一時の `expect(dead_code)` は 3.4 で外した（大きさの着地の判定が使う）。
- 申し送り（test-crash-report-merge から・2026-11-21）: `frame_test_support.rs:886` の `window_move_lines` は placement の `test_support::window_move_lines` と同じ働きの写し。この spec は `frame_test_support.rs` を触らない約束なので付け替えていない。完了の棚卸で扱う（brief.md の末尾にも同じ申し送りが main 経由で入る）。
- 預かりの指令には「前に線を取り出したときのトークの終わりの通し番号」（`move_talk_ends_seen`）を添える。今の番号を添えると、台本の最後の cue と自分の `TalkEnded` が同じフレームに届いたとき（同じ talk スレッドで move → lifecycle の順に送る）、次のトークが終わるまで詰まるため。`reset_window_pos_held` は届いた巡でなく「並べ直し 1 件につき 1 度」（`held_logged`）。塞がれて届いた並べ直しは自分が待ち始めた巡に出る。
- 残る競り（完了の棚卸で扱う）: 割り込みでトーク A の `TalkEnded` と次のトーク B の時刻 0 の位置の指令が同じフレームに届くと、B の指令も「運んだトークが終わった」と読む（`PositionCue` と `TalkEnded { at }` がトークの識別を持たないため）。害は、B の時点で面の指令をまだ受けていない窓がある時だけ並べ直しが早く当たること（起動の確定が直す）。消すには指令と `TalkEnded` に `talk_id` を載せる要があり、この spec の境界（`frame_test_support.rs` の送り口を含む）の外。
