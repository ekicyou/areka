## Project Description (Input)
検体のゴーストとバルーン（テストと実機の確かめに使う第三者の作品）は、書庫（`.nar`）をそのままリポジトリに入れている（今は 8 本で約 13.6 MB）。v0.1.0 のゴールの検体「窓際のぱすたさん」（ghost_dev の `pasta-in-windows`）は、シェルの絵が寄贈で、別のリポジトリへの置き直しが許されるか分からないため、書庫をこのリポジトリに入れられない。そこで検体の登記表に「取り寄せる URL・ハッシュ・大きさ」を持てるようにし、手元に無い書庫を取り寄せの段で取り寄せてハッシュを確かめ、合ったものだけを窓口が使う形を作る。最初の 1 本として「窓際のぱすたさん」をコミットを固定した ghost_dev の URL で登記する。テストと実機の手順の呼び方（`SampleRoot::acquire`・`nar-sample-path`）は変えない。今の 8 本の書庫を `vendors/` から外す移し替えは後へ回す（今の 8 本は置いたまま動く）。詳細は brief.md。

## Introduction

### 誰が困っているか

- v0.1.0 の 2 つ目のゴール（「窓際のぱすたさん」が SSP と同じに動く）を確かめる開発者と、後続 `areka-P0-pasta-in-windows-verification`。検体の窓口が「リポジトリに置いた書庫」しか読めないので、書庫を置けない検体をテストと実機の手順で引けない。

### いま何が起きているか

- 検体は `vendors/sample_ghost/*.nar` に 8 本在る（`emo2`・`R_POST_and_KOMAINU`・`emo2-kakukaku-offsetdpi`・`emo2-kakukaku-wplimit`・`konnoyayame`・`StayseeBalloon`・`claudia`・`emily4`）。
- テストは検体の窓口 `sample-ghost-kit` の登記表 `SAMPLES`（`crates/sample-ghost-kit/src/lib.rs`。行は「名前・種別・同梱のバルーン」だけ）越しに `SampleRoot::acquire("<名>")` で引く。書庫の在処は `devroot::nar_dir()` が `vendors/sample_ghost` を直に指して決める。窓口は書庫を `<target>/nar-samples/` の下へ展開し、原本に刻印（長さと CRC）を付けて陳腐化を見る。登記の数は `lib_tests.rs` が 8 と書いている。登記表の全部の行を引く判定（`every_registered_sample_lands_where_its_registry_row_says` ほか）が在る。

- 窓口は通信の依存を持たない。`tools/` に取り寄せの段は無い。
- 「窓際のぱすたさん」の書庫は ghost_dev の git に入っている。コミットを固定した URL `https://raw.githubusercontent.com/ekicyou/ghost_dev/e1e05590dbed0a4a4b1afadf55ca896f36d82c14/release/pasta-in-windows/pasta-in-windows.nar`（3,025,198 バイト・sha256 `04a8e1c19b534b38e39d24f93ac7735c74e186249965b3a0876a893cb41fe35b`）で取れる。ghost_dev の履歴を書き換えない限り、この URL は消えない。

### 何を変えるか

**登記表の行に「取り寄せる URL・ハッシュ・大きさ」を持てるようにし（以下「URL の行」）、URL の行の書庫は、取り寄せの段が取り寄せ先から取ってハッシュと大きさを確かめ、ワークツリーの `target\` の下の置き場に置く。** 窓口と `nar-sample-path` は通信せず、置き場の書庫を確かめてから今と同じ呼び方で配る。書庫が無い・合わないときは、検体の名前・探した場所・直し方を示して失敗する。通信できない場所のために、書庫を手で置く口を残す。最初の URL の行として「窓際のぱすたさん」を登記する（登記の数は 8 → 9）。今の 8 本は今の行（書庫をリポジトリに置く行）のまま、今と同じに動く。

## Requirements

### Requirement 1: 登記表の URL の行

**Objective:** As a 検体を足す開発者, I want 書庫をリポジトリに入れずに、名前・URL・ハッシュ・大きさで検体を登記できること, so that 置き直しが許されない検体も引け、リポジトリが太らない

#### Acceptance Criteria

1. The 検体の登記表 shall 行ごとに、書庫をリポジトリに置く行（今の行）か、取り寄せる行（URL の行）かを区別して持つ。
2. The 検体の登記表 shall URL の行に、今の行と同じ欄（名前・種別・同梱のバルーン）に加えて、取り寄せる URL・書庫のハッシュ（SHA-256）・書庫の大きさ（バイト）を持つ。
3. Where 行が URL の行である, the リポジトリ shall その書庫を追跡しない（`vendors/sample_ghost/` にその名前の `.nar` が無い）。
4. The 検体の登記表 shall 今の 8 本の行を今の行のまま残す（今の 8 本の書庫の置き場・引き方・展開の結果は変わらない）。
5. If URL の行の URL・ハッシュ・大きさのどれかが欠けている、または形が正しくない, then the 窓口の決定論テスト shall 失敗する。
6. The 取り寄せた書庫の置き場 shall リポジトリに追跡されない（取り寄せの段を回した後の `git status` に、新しい追跡の候補が出ない）。

### Requirement 2: 取り寄せの段

**Objective:** As a 開発者（人と AI）, I want URL の行の書庫を 1 つのコマンドで取り寄せて確かめられること, so that テストは通信せずに、決まったバイト列の検体で回る

#### Acceptance Criteria

1. The 取り寄せの段 shall 開発者がどのディレクトリからでも 1 つのコマンド（絶対パスで示せる形）で回せる。
2. When 取り寄せの段を回す, the 取り寄せの段 shall URL の行のうち、置き場に無いもの、またはハッシュか大きさが登記と合わないものだけを、登記の URL から取り寄せる。
3. When 取り寄せた書庫のハッシュと大きさが登記と合う, the 取り寄せの段 shall その書庫を置き場に置く。
4. If 取り寄せた書庫のハッシュまたは大きさが登記と合わない, then the 取り寄せの段 shall その書庫を置き場に置かずに捨て、検体の名前・URL・登記のハッシュと得たハッシュを示して失敗する。
5. If 取り寄せが途中で切れる、または取り寄せ先に届かない（名前の解決・接続の失敗・取り寄せ先が書庫を返さないことを含む）, then the 取り寄せの段 shall 途中までのファイルを置き場に残さず、検体の名前・URL・失敗の理由・直し方（回し直す・手で置く口〔要件 4〕）を示して失敗する。
6. When URL の行の書庫がすべて置き場に在り、ハッシュと大きさが登記と合う, the 取り寄せの段 shall 通信せずに成功で終わる（2 回目からは取り寄せる数が 0）。
7. When 取り寄せの段が終わる, the 取り寄せの段 shall 取り寄せた数・すでに在った数・失敗した数を示し、失敗が 1 つでも在れば 0 でない終了コードで、無ければ 0 で終わる。
8. The 取り寄せの段 shall 端末へ出す文を ASCII だけにする。
9. The 取り寄せの段 shall 登記の URL・ハッシュ・大きさを登記表と同じ 1 か所から読む（同じ検体の URL やハッシュを 2 か所に書かない）。
10. The 取り寄せの段 shall 新しい依存を足さずに動く（Windows に標準で在る取り寄せの仕組みだけを使う）。

### Requirement 3: 窓口と実機の手順

**Objective:** As a 検体を使うテストと実機の手順の書き手, I want URL の行の検体も今と同じ呼び方で引けて、確かめた書庫だけが使われること, so that テストを書き替えずに、同じバイト列の検体で走る

#### Acceptance Criteria

1. The 窓口 shall URL の行の書庫を、ワークツリーの `target\` の下の置き場から読む。
2. The 窓口 shall `SampleRoot::acquire("<名>")` と `nar-sample-path <名>` の呼び方・返す値・出力の形（`root=`・`folder=`・`balloon.<名>=` の行）を、URL の行の検体でも今の行の検体と同じにする。
3. The 窓口 and `nar-sample-path` shall 検体を引く間に通信しない。
4. When URL の行の検体を引く, the 窓口 shall 置き場の書庫の大きさとハッシュが登記と合うことを確かめてから展開する。
5. If URL の行の書庫が置き場に無い, then the 窓口 shall その検体を引く呼び出しを失敗させ、検体の名前・探した場所・直し方（取り寄せの段のコマンド、または手で置く口）を示す（黙って飛ばさない・テストを無視扱いにしない）。
6. If 置き場の書庫の大きさまたはハッシュが登記と合わない, then the 窓口 shall その書庫を展開に使わずに失敗させ、検体の名前・置き場のパス・登記のハッシュと得たハッシュ・直し方を示す。
7. If `nar-sample-path` が URL の行の書庫を得られない（3.5・3.6）, then `nar-sample-path` shall 標準出力へ 1 行も出さず、標準エラーへその文を ASCII で出し、未登録の名前の終了コード（2）とは別の 0 でない終了コードで終わる。
8. While 今の行の検体を引く, the 窓口 shall 今と同じくリポジトリの書庫を読み、取り寄せの段を回していなくても引ける。
9. The 窓口 shall 同じ登記なら、いつ回しても同じバイト列の書庫から展開する。

### Requirement 4: 手で置く口

**Objective:** As a 通信できない場所の開発者, I want 書庫を手で置いて検体を使えること, so that 取り寄せ先に届かなくてもテストと実機の手順を回せる

#### Acceptance Criteria

1. When 開発者が URL の行の書庫を手で置き場に置く, the 窓口 and 取り寄せの段 shall ハッシュと大きさが登記と合えば、取り寄せたものと同じに扱う（取り寄せの段は通信しない）。
2. If 手で置いた書庫のハッシュまたは大きさが登記と合わない, then the 窓口 and 取り寄せの段 shall それを使わず、要件 2.4・3.6 と同じ文で知らせる。
3. The 検体の README shall 手で置く口の置き場のパス・置く書庫のファイル名・確かめ方を書く。

### Requirement 5: 「窓際のぱすたさん」の登記

**Objective:** As a 後続 `pasta-in-windows-verification` と v0.1.0 のゴールを確かめる開発者, I want 「窓際のぱすたさん」を名前で引けること, so that 書庫をこのリポジトリに入れずに、テストと実機の手順で使える

#### Acceptance Criteria

1. The 検体の登記表 shall 「窓際のぱすたさん」を URL の行として登記し、URL を `https://raw.githubusercontent.com/ekicyou/ghost_dev/e1e05590dbed0a4a4b1afadf55ca896f36d82c14/release/pasta-in-windows/pasta-in-windows.nar`、大きさを 3,025,198 バイト、SHA-256 を `04a8e1c19b534b38e39d24f93ac7735c74e186249965b3a0876a893cb41fe35b` とする。
2. The 検体の登記表 shall 「窓際のぱすたさん」の行の名前・種別・同梱のバルーンを、その書庫が実際に入れる物（`install.txt` の `directory` と、同時に入るバルーン）に合わせる（登記表の全部の行を引く判定が、この行でも合う）。
3. The リポジトリ shall 「窓際のぱすたさん」の書庫を、`vendors/` にも配布物にも、ほかのどの追跡ファイルとしても持たない。
4. When この spec が着地する, the 窓口の決定論テスト shall 登記の数を 9 とする（8 → 9）。
5. The 検体の README shall 「窓際のぱすたさん」の出どころ（ghost_dev・固定したコミット）・ハッシュと大きさ・書庫をこのリポジトリに入れない理由（寄贈のシェルの絵の置き直しが許されるか分からない）を登記する。
6. When 取り寄せの段を回した後に「窓際のぱすたさん」を `SampleRoot::acquire` と `nar-sample-path` で引く, the 窓口 shall 今の行の検体と同じ形の木を配る。
7. If 展開器 `areka-nar` が「窓際のぱすたさん」の書庫を受け入れない, then the この spec の実装 shall 行の登記で回避せずに止めて開発者へ報告する（展開器の直しはこの spec の範囲の外・最初のタスクで実物を取り寄せて確かめる）。

### Requirement 6: 全体テストと取り寄せの段

**Objective:** As a 全体テストを回す開発者（人と AI）と同じウェーブの兄弟の spec, I want 全体テストが取り寄せの段を先に回し、回していないときに何が起きるかも分かること, so that URL の行の検体を使うテストが、取り寄せ忘れで赤になったり、走っていないことに気付かずに緑になったりしない

#### Acceptance Criteria
