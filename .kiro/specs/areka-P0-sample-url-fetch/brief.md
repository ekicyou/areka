# Brief: areka-P0-sample-url-fetch

> 2026-10-10 `/kiro-discovery`（開発者「将来的には検体を URL ダウンロード方式に変えてほしいのですが、この要望もブリーフィングしておいて欲しい」）で起票した。検体「どっとさくら」を足す話（`areka-P0-dot-sakura-specimen`）の続きで出た要望。**急がない**（開発者「将来的には」）。roadmap「自前の既定バルーンと検体『どっとさくら』」節。コードは「何の定義か」で指す。着手時に引き直す。

## Problem

検体のゴーストとバルーンは、書庫（`.nar`）をそのままリポジトリに入れている。今は 8 本で約 13.5 MB、`dot_sakura` を足すと 9 本で約 15 MB になる。検体を足すたびにリポジトリが太り、差し替えのたびに古い書庫が履歴に残り続ける。

第三者の作品を公開のリポジトリから配り直している形でもある。改変禁止や非営利の条件が付いた検体（`konnoyayame` のシェル・`emily4`）は、リポジトリの MIT ライセンスが及ばないことを README で断って置いている。

検体を「出どころの URL から取り寄せる」形にすれば、リポジトリは検体の名前・URL・ハッシュだけを持てばよくなる。

## Current State

- 検体の保管形は `vendors/sample_ghost/*.nar`（配布形のまま）。テストは `sample-ghost-kit` の登記表 `SAMPLES`（名前・種別・同梱バルーンの名前）越しに `SampleRoot::acquire("<名>")` で引く。窓口は書庫を `target/` の下へ展開し、原本に刻印（長さと CRC）を付けて陳腐化を見ている。
- 窓口を名指すソースは、窓口自身のほかに 12 のクレートに在る（`areka`・`areka-nar`・`areka-update`・`areka-emo-text` ほか。ほとんどがテスト）。実機の手順は `nar-sample-path`（検体の絶対パスを印字する道具）で引く。
- 配布の道具 `tools/package.ps1` は、既定バルーン（今は `StayseeBalloon`）を検体の窓口から引いて配布物へ入れる。リリースの CI（`.github/workflows/release.yml`）がこの道具を回す。
- `.github/workflows/` に在るのは `release.yml` と `crates-io.yml` の 2 つ。全体テストは開発者の手元で回す（`tools/test-all.ps1`）。
- **URL から取り寄せる形は、前に一度見送っている。** `vendors/sample_ghost/README.md` の `claudia.nar` の節に理由が書いてある: 上流（`konnoyayame`・`claudia`）は最新の 1 本しかリリースを残さず、固定したタグが数日で 404 になった。上流の URL だけを頼ると、検体が取れなくなる。
- 検体ごとの出どころ（README の登記）:
  - 上流の URL が消える実例が在る: `konnoyayame`・`claudia`。
  - 単独の配布ページが無い: `emily4`（開発者が SSP のインストール先から作った書庫）。
  - 開発者のサイトに在る: `dot_sakura`（`https://ekicyou.github.io/old/dot-sakura/download/nar/dot_sakura.nar`）。
  - 上流は在るが、リポジトリの書庫は畳み直したもの: `StayseeBalloon`（上流は GitHub のリポジトリ）。
  - `emo2`・`emo2-kakukaku-*`・`R_POST_and_KOMAINU` の出どころと畳み直しの有無は、着手時に README で引き直す。
- 条件の付いた検体: `konnoyayame` のシェルは CC BY-NC-ND 2.1 JP、`emily4` は CC BY-NC 4.0、`dot_sakura` は「インターネット上の転載不可」（管理者は開発者本人）。

## Desired Outcome

- リポジトリは、検体ごとに「名前・取り寄せる URL・ハッシュ（と大きさ）」を持つ。書庫そのものは持たない。
- 検体を使うテストと実機の手順は、今と同じ呼び方（`SampleRoot::acquire`・`nar-sample-path`）で動く。取り寄せた書庫は、ハッシュが合ったものだけが使われる。
- 上流が書庫を消しても検体が取れる（取り寄せ先が長く生きる場所である）。
- 取り寄せられないときは、何が取れなかったか・どうすれば直るかが、はっきりした文で分かる（黙って飛ばさない）。
- 検体を足す作業は「置き場に書庫を置く → 登記表に 1 行（URL とハッシュつき）」で済む。
- リリースの配布物を組む道が、検体の取り寄せに左右されない。

## Approach

登記表の 1 行に URL とハッシュを足し、窓口が「手元に在ればそれを使い、無ければ取り寄せてハッシュを確かめてから使う」形にする。展開と刻印より先の仕組み（配る・捨てる）は今のまま使う。

取り寄せ先は、上流の URL をそのまま頼らず、**長く生きる置き場を 1 つ決めてそこへ写す**（議題 1）。前に見送った理由（上流が消す）を、これでふさぐ。

通信はテストの中でなく、**先に回す取り寄せの段**（`tools/` のスクリプト）に寄せる案を推す（議題 3）。テストは手元に置かれた書庫だけを読むので、決定論のまま保てる。

## 議題（要件の段で決める）

1. **取り寄せ先をどこにするか**（開発者の決めごと）。
   - 案 あ: 検体だけを置くリポジトリを別に作り、そのリリースの添付から取る。置いた書庫は消さない決まりにする。
   - 案 い: 開発者のサイト（`ekicyou.github.io`）に検体の置き場を作る。`dot_sakura` はすでにそこに在る。
   - 案 う: 上流の URL を第一にし、消えたときの控えとして案 あ か い を持つ。
   - どの案でも、条件の付いた検体（改変禁止・非営利）を置いてよいかを 1 本ずつ確かめる（議題 6）。
2. **取り寄せられないときの振る舞い**。案: テストは止める（はっきりした文で）。黙って飛ばすと、検体を使うテストが走っていないことに気付けない。通信できない場所のために、書庫を手で置く口を残す。
3. **いつ・誰が通信するか**。
   - 案 A（推し）: 先に回す段のスクリプト（PowerShell の標準の取り寄せ＝新しい依存なし）。`tools/test-all.ps1` と配布の道具が最初に呼ぶ。テストは通信しない。
   - 案 B: 窓口（Rust）が初回に取り寄せる。素の `cargo test` でそのまま動くが、テスト専用のクレートに通信の依存が要り、テストが通信の調子に左右される。
4. **取り寄せた書庫の置き場**。ワークツリーの `target\` の下（今の決まりどおり・`cargo clean` のたびに取り寄せ直す）か、ワークツリーをまたいで使い回す置き場（ワークツリーを何本も並べる開発の形で、毎回 15 MB を落とさずに済む）か。後者は「検体・一時のフォルダはワークツリーの `target\` の下だけ」の決まりの例外になるので、開発者が決める。
5. **どの検体を対象にするか**。第三者の検体と `dot_sakura` は対象。areka が自分で作った変種（`emo2-kakukaku-*`）と、製品の資産（既定バルーン）をどうするか。**製品の資産は対象にしない**案を推す（配布物に必ず入る物は、リポジトリが持つ。`areka-P0-default-balloon-selfmade` が作る自前の既定バルーンがこれに当たる）。
6. **条件の付いた検体を取り寄せ先へ置く権利**。`konnoyayame`（改変禁止・非営利）と `emily4`（非営利）は、そのままのバイト列を非営利で置く分には条件に合う見込みだが、1 本ずつ条件の文を読んで確かめる。合わないものは、リポジトリにも取り寄せ先にも置かず、手で置く口（議題 2）だけにする。
7. **畳み直した検体の扱い**。リポジトリの書庫が上流のバイト列と違うもの（`StayseeBalloon` など）は、畳み直した後の書庫を取り寄せ先に置くのか、上流のバイト列を取り寄せて手元で畳むのか。
8. **履歴に残る書庫**。リポジトリから書庫を外しても、過去の履歴には残る。履歴は書き換えない案を推す（リポジトリの太りは、これ以上増えない所で止める）。
9. **移す順番**。一度に全部か、`dot_sakura` を最初の 1 本にして 1 本ずつか。

## Scope

- **In**: 登記表の URL とハッシュの欄／取り寄せとハッシュの確かめ／取り寄せられないときの知らせ／手で置く口／取り寄せ先の用意と書庫の写し（議題 1）／`vendors/sample_ghost/` から書庫を外すことと README の書き直し（「URL 方式にしない」と書いた節を含む）／`tools/test-all.ps1`・`tools/package.ps1`・リリースの CI の手当て／steering（`tech.md` の「検体は配布形のまま保管」・`structure.md` の Sample Ghost Kit の節・`product.md`）の書き直し／検体を足す手順の書き直し。
- **Out**: 検体の中身や顔ぶれを変えること／展開器 `areka-nar`／窓口の配り方（刻印・複製・後始末）の作り直し／利用者向けのゴーストの取り寄せ（ネットワーク更新・インストール＝製品の機能）／製品の資産（既定バルーン）の置き場／履歴の書き換え。

## Boundary Candidates

- 登記表と窓口（`crates/sample-ghost-kit/src/lib.rs`・`devroot.rs`・`bin/nar-sample-path.rs`）。
- 取り寄せの段（`tools/` のスクリプトか窓口の中か＝議題 3）と、取り寄せ先の置き場。
- 配布の道（`tools/package.ps1`・`.github/workflows/release.yml`）。
- 文書（`vendors/sample_ghost/README.md`・steering・根の `README.md`）。

## Out of Boundary

- 検体を使う各クレートのテスト。呼び方を変えない（`SampleRoot::acquire("<名>")` のまま）。
- `areka-update`（利用者向けのネットワーク更新）。検体の取り寄せに流用しない（テストの道具が製品の通信の作りに縛られないため）。
- 検体の見張り（`sample_path_guard_test`）。見張る語の作り方は変えない。

## Upstream / Downstream

- **Upstream**: `areka-P0-dot-sakura-specimen`（取り寄せ先がすでに在る最初の検体・同じ登記表を触る）。同じ登記表を触る `areka-P0-emily-ghost-verification`・`areka-P0-default-balloon-selfmade` が走っていないときに着手する。
- **Downstream**: これから足す検体はどれも、書庫をリポジトリに入れずに足せる。

## Existing Spec Touchpoints

- **Extends**: 完了 `areka-P0-nar-install`（登記表と窓口を作り、「検体は配布形のまま保管する」と決めた）の決めごとを改める。
- **Adjacent**: `areka-P0-default-balloon-selfmade`（既定バルーンは製品の資産＝この spec の対象にしない。同 spec が既定を差し替えた後は、配布の道が検体の取り寄せに触れない形にできる）。`areka-P0-test-roots-under-target`（検体・一時のフォルダの置き場の決まり＝議題 4）。配布と公開の列（`tools/package.ps1`・`release.yml`）。`areka-P0-release-cycle`（リリースの手順が検体の取り寄せで変わらないこと）。

## Constraints

- 取り寄せた書庫は、ハッシュが合わない限り 1 バイトも使わない。途中で切れた取り寄せを原本として残さない。
- テストの決定論を崩さない（同じ登記なら、いつ回しても同じバイト列の検体で走る）。
- 失敗を黙って通さない（取れなかった・ハッシュが合わなかったは、記録と失敗で知らせる）。
- 条件の付いた検体を、条件に合わない形で置かない。
- リリースの配布物を組む道を、通信の失敗で止めない（製品の資産はリポジトリが持つ）。
- 道具が端末へ出す文は ASCII だけ。
- 規模の見立ては M（8〜12 タスク）。
