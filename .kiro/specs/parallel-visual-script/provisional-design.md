## 4. 設計

### 4.1 結論（大枠）

- **区間の形と、brief の「1 本まるごと」の形は、1 つの仕掛けで持てる。** 並走の単位は「区間」1 種類にする。「1 本まるごと」は、「区間の外に何も無い 1 本」という、区間の形の端の場合になる（要件 7）。
- **区間は、主の流れとは別の表（`CueSheet`）にする。** 同じ表の別の列にはしない（3 章「区切りに着くと…」のとおり、主の流れが止まると一緒に止まる。主の 1 本が閉じると `CuePlayer` ごと落ちる）。
- **並走の流れは、トークの糸ではなく、dispatcher が持つ「並走の組」に置く。** dispatcher はゴーストに 1 つで、1 本が替わっても生きているので、流れは 1 本をまたいで生き残る。糸は増えない。
- **「後から始まった方が勝つ」は、配る側の 1 か所で決める。** 受け手（seriko・音）には、流れの区別を持ち込まない。seriko へ足すのは、「並走の合図では、トークの起点の見積もりを動かさない」の 1 つだけである。

### 4.3 読む時（コンパイル）

`scan` に、区間の中かどうかの状態を 1 つ足す。

- 開く印（`GenericCommand` の名前が `parallel`・1 つ目の引数が `1`）を、区間の外で読んだら:
  - 今の `scope` を控える。区間用の時刻 `section_ms` を 0 から始める。
  - 以後の命令は、区間の表へ積む。主の `offset_ms` は進めない（要件 2）。
- 区間の中で読んだ命令は、「書ける物」（要件 4）なら区間の表へ積み、そうでなければ `warn!` を 1 行出して捨てる。strict では検出点にする（要件 18）。
  - 書ける物: `Wait`・`SpeakerScope`・`Surface`、キャリアのうち名前が `bind`・`bind-noevent`・`anim`・`sound` の物、`\i`・`\_v`・`\8`（読み手に腕ができた後）。
  - 捨てる物: `Text`・`SystemVar`・`Choice`・`NewLine`・`Clear`・`Cursor`・`BalloonSurface`・`Font`・`Anchor`・`AnchorEnd`・`Quit`・ほかの名前のキャリア（`raise`・`move`・`play` など）・`\x`（腕ができた後）。
  - `End`（`\e`）は、今どおり走査を打ち切る。区間はそこで終わる（要件 5）。
- 閉じる印（`parallel`・`0`）を区間の中で読んだら、区間を閉じ、`scope` を控えた値へ戻す（要件 6）。走査の終わりでも、開いたままなら閉じる。
- 区間の中の開く印・区間の外の閉じる印・引数が `1` でも `0` でもない `parallel` は、効かせずに記録する（要件 5）。
- 区間を閉じた時、区間の表に合図が 1 つでも在れば:
  - `parallels` に `ParallelSheet { sheet }` を足す。区間の表の頭に `ClearAll` は置かない。
  - 主の表の、開く印の時刻（主の `offset`）に、長さ 0 のキャリア（名前 `parallel`・引数 `["1"]`）を 1 つ置く。これが「ここで区間を始める」の合図になる。`Custom{command, params}` のままで、命令の型は増やさない。
- 区間の表が空なら、何も足さない（`debug!` の記録だけ）。pasta の「待たないだけ」の印（`\s[10]` の後ろに印を書く形）は、areka では何も起こさない。

「主の流れが空」とは、主の表に、上の「区間を始める」合図のほかに合図が 1 つも無いことである。`is_parallel_only(script)` は、台本に `\![parallel,1` の綴りが在るときだけ、読み・走査をして、これを答える（綴りが無い台本は読まずに偽を返す＝ふつうの台本に手間を足さない）。

### 4.4 主の流れが印に着いた時

- `spawn_talk` に、渡し口 `ParallelLauncher`（`fn launch(&mut self, n: u32, sheet: ParallelSheet, at: f64)`）を足す（今の `spawn_talk` は、渡し口なしの形として残す＝試験の呼び手を直さない）。
- `drive.rs` は、`parallels` が空でない 1 本のときだけ、小さい受け手を 1 つ主の `CuePlayer` へ登録する。この受け手は、「区間を始める」合図を受けるたびに、次の区間を 1 つ取り出して `launch` を呼ぶ。合図は書いた順に 1 回ずつ配られるので（`runtime.rs:204-213`）、n 番目の合図が n 番目の区間に当たる。
- 主の 1 本が、印に着く前に閉じられたら、合図は配られないので、その区間は始まらない。
- `launch` の実装は `areka-ghost` に置く。並走の組の鍵を取り、流れを 1 つ作り、**その場で**（トークの糸の上で）区間の時刻 0 の合図を配る。したがって、印と同じ時刻の区間の合図は、主の流れの次の合図より前に、同じ配りの中で受け手へ出る（要件 3）。

### 4.5 並走の組と、流れ

```rust
struct FlowKey { talk: u64, section: u32 }      // 主の流れは section = 0。順序は (talk, section)
struct ParallelFlow { key: FlowKey, schedule: TimedSchedule<TalkCue>, sinks: Vec<Box<dyn BootCueSink>> }
struct ParallelSet {
    flows: Vec<ParallelFlow>,
    last_placed: HashMap<ActorKey, FlowKey>,    // アクターごとの「最後に表情を置いた流れ」
    stopped_before: FlowKey,                    // これより前の並走は、もう配らない
    sinks: Vec<Box<dyn BootCueSink>>,           // 並走の受け手の原本（複製して流れへ渡す）
}
type SharedParallel = Arc<Mutex<ParallelSet>>;  // dispatcher と、再生中のトークの糸が分け持つ
```

- **流れの中身は `TimedSchedule<TalkCue>` をじかに使う。** 区間には区切り（`\x`・選択肢）が無いので、`CuePlayer` の状態機械は要らない。`CuePlayer` は受け手に `Send` の縛りが無く（`runtime.rs:100`）、2 本の糸で分け持てない。dola を直さずに済む形を取った。
- **流れの番号 `FlowKey`** は、「その 1 本の番号（kanade の `TalkId`）」と「1 本の中で何番目の区間か」の組である。新しい数え手は作らない。
- **進め方**: dispatcher は、`Tick` のたびに、再生中の 1 本が在っても無くても、組の全部の流れを今の時刻で進める。末尾まで走った流れは組から外す（`debug!`）。kanade へは知らせない。
- **受け手**: 流れを作るたびに、並走の受け手の原本を `clone_box` し、`begin_talk(その 1 本の番号, 出どころ)` を呼んでから渡す（主の流れと同じ作法）。並走の受け手の並びには、文字の層・`BalloonLifecycleSink`・窓や切り替えの受け手を**入れない**。今は seriko の受け口だけで、音の受け手は `sound-canon-tags` が、`\i`・`\![anim]` は seriko の中の腕が受ける。
- **主の流れの受け手の覆い**: dispatcher は、主の 1 本の受け手（複製の列）を、覆い 1 つに入れて `spawn_talk` へ渡す（`StrictTap` と同じ作り。`emit_with`・`preview`・`choice_wait_began` はそのまま中へ流す）。覆いは、合図を中へ流す前に鍵を取り、次の 2 つをする。
  - `\s`（`Emote`）と `bind`・`bind-noevent` のキャリアなら、`last_placed[アクター]` を、今の値と自分の番号の大きい方にする。
  - 「全部止める」合図（`\![play,again]`・舞台を閉じる命令。名前は取り決めの要件定義で確定）なら、`stopped_before` を自分の番号にして、組の流れを全部落とす（要件 13）。
  - 組に流れが 1 つも無い間は、どちらもせずに中へ流すだけにする（ふつうのゴーストでは、合図 1 つにつき、争いの無い鍵を 1 回取るだけ）。
- **並走の流れが合図を配る時の決まり**（鍵を取ったまま判定し、受け手へ出す）:
  1. 自分の番号が `stopped_before` より小さければ、配らない。
  2. アクターに当てる見た目の合図（`\s`・着せ替え・`\i`・`\![anim]`）で、`last_placed[アクター]` が自分の番号より大きければ、配らずに `debug!` で記録する（要件 11）。
  3. `\s`・着せ替えを配ったら、`last_placed[アクター]` を自分の番号にする。
  4. 音と待ちは、アクターに付かないので、2 の対象にしない。
- 主の流れの合図は、止めない（取り決めの文は「前から走っている**並走**は」）。
- **鍵を取ったまま受け手へ出す**理由: 判定と配りの間に別の糸の配りが割り込むと、「負けた」はずの合図が後から受け箱に着く。受け手へ出す操作は線への送り出しだけで、待たない。dispatcher は、トークの糸を join する間（`close_active_if_any`）は鍵を持たない。

主の 1 本が替わる時の流れ:

```
1 本目（番号 6）: … 教室の \![parallel,1]\s[12]\_w[200]\s[10]\_w[200]\s[12]\![parallel,0] … きゃっ！\x
   印に着く → 流れ (6,1) を組へ。\s[12] をその場で配る。last_placed[教室] = (6,1)
   主は「きゃっ！」を出して \x で待つ。流れ (6,1) は dispatcher の刻みで進む
遊ぶ人が押す → 2 本目（番号 7）が 1 本目を置き換える（今どおり close → spawn）。組はそのまま
   2 本目が教室に \s[消灯] を置く → last_placed[教室] = (7,0)
   流れ (6,1) の残りの \s[12] は、(7,0) > (6,1) なので配らない（記録）。流れは末尾まで走って外れる
```

### 4.6 主の流れが空の 1 本（brief の形）

- kanade は読み手に依存しないので、判定は関数 1 つを差し込む（`KanadeConfig` に `parallel_only: fn(&str) -> bool`。既定は常に偽。`areka-ghost` が `areka_sakura::parallel::is_parallel_only` をつなぐ）。
- `start_talk` の呼び手の手前で、台本が「主の流れが空」なら、枠（`Phase`）・`prev_talk`・選択肢の帳簿に触らず、番号だけ取って `Action::StartParallel` を返す。殻は `TalkCommand::Parallel` を、今の 1 本の線で送る（順が保たれる）。
- dispatcher は `Parallel` を受けたら、読み・コンパイルし、区間を全部、今の時刻（差し込んだ時計を読む）を起点に、組へ入れて、その場で時刻 0 の合図を配る。再生中の 1 本には触らない。
- 入口は選ばない。`start_talk` を通る台本（SHIORI の返事・SSTP・MCP・選択肢の台本）は、どれも同じ判定を通る【仮 7】。区間の形は、1 本の中身なので、どの入口でも効く。
- `OnSecondChange` の返事は、今どおり、話している最中は捨てる（今の腕を変えない）。

### 4.7 時刻の扱いと、SERIKO の時計との関係

- **区間の起点** ＝ 主の表の起点 ＋ 印の合図の相対時刻（`sum_on_ms_grid` の足し算。引き算で相対へ戻さない）。配られた刻みの時刻ではない。区間の中の時刻は、起点からの相対で、区間の表が持つ。
- 今の作りでは、トークの糸が知るのは「その 1 本の最初の刻みからの秒」だけで（`dispatcher.rs:392-409`）、絶対の時刻を知らない。この設計は、`talk-anchor-interrupt-ticks` の着地の後（台本の起点が、配る時に押す本物の絶対時刻になった後）に乗る【仮 3】。その前に作るなら、dispatcher が最初の刻みで決めた `base_now` を並走の組へ書いておき、`launch` がそれを足す。
- **配る細かさ**は、主の流れと同じ（dispatcher の 50 ms の刻み）。合図の時刻そのものは正確に持つ。受け手が合図の時刻で当てるようになるのは、時刻の土台の後である。
- **SERIKO のループの時計**（16 ms・シェルの時計）は、流れと無関係に進む。区間が `\s` を置けば、その面のアニメーションはシェルの時計で始まる。区間は「点の合図を、時刻を付けて届ける」だけで、SERIKO の時計には触らない。
- **トークの起点の見積もり**: 並走の合図の時刻は、区間の頭からの相対である。そのまま `observe_cue` へ渡すと、`今 − 合図の時刻` が主の 1 本の起点より後ろになり、`max` が起点を後ろへ飛ばす（`talk.rs:31-37`）。口パク（`talk` の interval）がずれる。そこで:
  - 並走の受け手の並びに入れる seriko の受け口は、「並走から」の印を付けて送る（`SerikoMsg` に腕か欄を 1 つ）。
  - seriko は、その合図を `observe_cue` へ渡さない（`actor.rs:601` の手前で分ける）。`looper.rs` は触らない。
  - 区間の表には `ClearAll` も字も無いので、`talk` の流れを戻す所（`looper.rs:392-401`）には、もともと当たらない。
- 文字の層の時計（`ClockedTextSink`）と `BalloonLifecycleSink` は、並走の受け手の並びに入れないので、並走の合図を見ない。

### 4.8 失敗の扱い

- 効かせなかった物（区間に書けないタグ・入れ子・迷子の閉じる印・読めない引数）: `warn!` を 1 件ずつ。strict では検出点。
- 「負けた」合図（要件 11）と、止められた流れ: `debug!`（決まりどおりの動きで、失敗ではない）。
- 並走の受け手が 1 つも無い構築で区間が届いた: `warn!` を 1 行出して、流れを作らない。
- 鍵が毒されていた（別の糸が鍵を持ったまま panic した）: 中身をそのまま使い、`error!` を 1 行出す（panic を広げない）。
- メッセージボックスは出さない。SHIORI へは何も送らない。

### 4.9 ほかの単位との境

- `talk-fast-forward`: 主の流れの時刻を早回ししても、並走の組には触らない。早回しで印を何個も越えたら、区間はその時に始まる。その時の起点は、「主の流れが、その合図に付け替えた後の時刻」でなければならない（6 章）。
- `shell-multi-compose`: 舞台を閉じる命令が「全部止める」合図の表に載る。アクターの見分け方は 9 章。
- `sound-canon-tags`: 音の受け手を、並走の受け手の並びに足す。音の待ち（`\_V`・`\![sound,wait]`）は、区間では当面「効かせず記録」【仮 5】。
- `element-animation-easing`・`seriko-script-triggers`: `\![anim]`・`\i` の受け手は seriko の中にできる。並走の受け口から届けば、そのまま効く。時間をかける指令（`\![move,…,--time]`・`\![set,alpha]` など）は、区間に書ける物に入れていない【仮 4】。

## 6. ほかの単位に期待する事

- **`talk-anchor-interrupt-ticks`（先に要る）**:
  - 台本の起点が絶対の時刻になり、トークの糸がそれを知っていること（区間の起点を足し算で出すため）。
  - 同 brief の「文字の層と seriko は、押された起点を読む」は、起点が同時に 1 つという前提に読める。並走が入ると、起点が同時にいくつも在る。**「並走の合図は、トークの起点を動かさない」を、その設計で持ってほしい**（この spec が後から足すと、`talk.rs`・`talk_clock.rs` を 2 度直す）。
  - dispatcher が時計を読める形（主の流れが空の 1 本の起点に使う）。
- **`talk-fast-forward`**:
  - `\x` の腕ができたら、「区間に書けない物」の表に `\x` を足す（同じ `compile.rs` の `scan` を触る。同じウェーブに置かない）。
  - 途中の `\x` の後ろの時刻の付け替え・早回しの後、**合図が配られた時に、その合図の（付け替えた後の）絶対の時刻が分かること**。区間の起点はそれを使う。分からないと、早回しで越えた印の区間が、元の予定の時刻まで始まらない。
  - 早送りは並走に効かせない（取り決め）。早送りの入口が dispatcher を通るので、並走の組へ配らないことを、そちらの設計に 1 行。
- **`shell-multi-compose`**: 舞台を閉じる命令を、「全部止める」合図の表に登記する。並び（cast）の扱いは 9 章。
- **`sound-canon-tags`**: 音の受け手を、並走の受け手の並びに入れられる形（`BootCueSink`）で作る。待ち（`\_V`）を区切りで作るなら、並走の流れの側に解く口が要る（`TimedSchedule` の区切りは使える）。相対パスの基準（台本を実行したゴースト）は、`begin_talk` の出どころで渡る。
- **`seriko-script-triggers`・`element-animation-easing`**: `\i`・`\![anim]` の腕を、seriko の受け箱の「合図」の腕の中に作る（並走の印の付いた合図でも同じ腕を通る）。`actor.rs`（827 行）を同時に触るので、同じウェーブに置かない。
- **`talk-thread-count-growth`**: brief は Upstream に挙げているが、この設計は糸を増やさないので、順番の縛りは無くなる。
- **`tick-gate-adoption`**（刻みを止める門）: 並走の流れが残っている間は、dispatcher への刻みを止めないこと。
- **同じファイルを触る相手**: `compile.rs`（`range-choice-tag`・`talk-fast-forward`）・`dispatcher.rs` と `drive.rs`（`talk-fast-forward`・`talk-anchor-interrupt-ticks`）・`steady.rs`（940 行。`sakura-time-critical` ほか）・seriko の `actor.rs`。

## 7. 置いた仮定

1. brief の「冒頭に印」を、「主の流れに合図が 1 つも無い 1 本」と読み替えた。「最初のタグが印か」で決めると、スコープ 0 の印の単語で始まる演劇の 1 本（pasta が `\0` を省いたとき）が、まるごと並走と読まれ、字と `\x` と `\![raise]` が捨てられる。
2. 「後から始まった」の順は、「1 本の番号（届いた順）→ 1 本の中の区間の順」で決める。実際に始まった時刻の順とは、次の場合だけ違う: 主の流れが空の 1 本が届いた後で、その前から在る主の 1 本が、後ろの印に着いて区間を始めたとき（届いた順では、主の 1 本の区間が古い）。
3. `talk-anchor-interrupt-ticks` が先に着地している。
4. 区間に書ける `\![…]` は `bind`・`bind-noevent`・`anim`・`sound` だけ。`\![move]`・`\![set,…]`・`play` の命令（位置・透明度・揺れ・転換など）・`\![raise]`・`\![embed]` は書けない。
5. 音の待ち（`\_V`・`\![sound,wait]`）と `\__w` は、区間では当面、効かせず記録する。
6. 利用者の中断（ダブルクリック）は、並走を止めない。ゴーストの終了・切り替え・再読み込み（dispatcher の `Close`）は、全部止める。
7. 並走は、`start_talk` を通る全部の入口で許す（SHIORI の返事・SSTP・MCP の `sakurascript`・選択肢の台本）。出どころ（`ScriptOrigin`）は流れへ運ぶ。
8. 並走の流れは、SHIORI へ何も知らせない。
9. 主の流れの合図は、「後から始まった方が勝つ」で止めない（止めるのは並走だけ）。主の 1 本と、その 1 本の区間が同じアクターへ書いたときは、時刻の後の方が残る。
10. 主の流れが空の 1 本は、kanade の糸で 1 回、dispatcher の糸で 1 回、読まれる（合わせて 2 回）。見た目だけの短い台本を当てにした近道である。
11. 「全部止める」合図の名前（`play,again`・舞台を閉じる命令）は、取り決めの要件定義で確定した物を、表に書く。
12. 最初の起動の挨拶に付く epilogue の在る 1 本は、主の流れが空でも、ふつうの 1 本として扱う。

## 8. 決まっていない所

1. **並びが替わった時の並走**（9 章）。答えで、4.5 の「アクター」の鍵（スコープの番号か、並びで解いた先か）と、「全部止める」合図の表が変わる。
2. **「冒頭の印」を「主の流れが空」と読み替えてよいか**（仮定 1）。「最初のタグで決める」なら、kanade の判定は軽くなるが、pasta に「印の単語で始まる 1 本は、必ず前にスコープのタグを出す」を頼むことになる。
3. **「後から始まった」の順を、届いた順で決めてよいか**（仮定 2）。実際に始まった順にするなら、`FlowKey` を dispatcher が数える通し番号に替え、始まりを 1 か所で見る作りが要る。
4. **区間に書ける物の線**（仮定 4・5）。位置・透明度・揺れなどを区間に許すなら、並走の受け手の並びに窓の受け手が入り、「後から始まった方が勝つ」を表情のほかの値にも広げる文が、取り決めに要る。
5. **中断・切り替え・再読み込みでの止め方**（仮定 6）。中断でも止めるなら、中断の道（`user_break`）から並走の組へ 1 本、線が要る。

## 9. 差し戻しが要りそうな所
