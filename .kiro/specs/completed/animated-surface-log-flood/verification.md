- 適用 1 回の段ごとの所要（release 版・面 0 の perf の行 `perf(apply_show): 段階別計時` のうち `surface_id=1002` の行・どれも `cache_hit=false`・µs の中央値）:

| | 行数 | 面 1002 の時間（Z） | 合成 `t_compose_us` | マスク `t_mask_us` | 表示の記録 `t_upload_us` | 全体 `t_total_us` |

- 直す前は「作る前の測り」の表と同じ値で、記録は `target\animated-surface-log-flood\pre\logs\pre-release.stdout.log`。このタスクで数え直して一致を確かめた（全体の中央値は 2,944.5）。
- 直した後は、件 26 の実機の確かめ（3.7）の release 版の記録 `target\animated-surface-log-flood\blink\release\logs\blink-release.stdout.log` から、このタスクで数えた。直した後の release 版の走りで `areka_emo_present=debug` が入っているのはこの走りだけ。
  - 面 1002 が出ていたのは、起動から面 1000 に替えるまでの約 7 秒だけ（103 行・毎秒約 14.5 回）。
  - `RUST_LOG` に `areka_seriko=debug` も入っている。直す前とは窓の長さと記録の水準が違うので、目安の値である。
- debug 版の面 1002 の適用 1 回の全体の中央値は、直す前 8,702 µs（`pre-debug.stdout.log`・499 行・合成 3,222・マスク 3,623）、直した後 9,047 µs（5.1 の `target\animated-surface-log-flood\flood\run-debug\logs\run-debug.stdout.log`・1,027 行・合成 3,207・マスク 3,510）で、悪くなってはいない（どちらも `areka_emo_present=debug` を足し、seriko の DEBUG の行は 0 行の走り）。件 26 の確かめの debug 版の記録では全体が 15,590 µs になるが、これはその走りだけの外れの値である（同じ走りで面 1001 のマスクも 3,272 → 4,430 µs に上がっており、`areka_seriko=debug` も入っていた）。
- 見積り: コマ送りは毎秒約 14 回。全体 1,987 µs × 14.3 回 ≈ 28 ms／秒＝1 コアの約 3%（直す前は 2,944 µs で約 4.2%）。areka の 15.4% のうち約 12 ポイントは、perf の行が測る段の外で使われている。
- 段の外の内訳は測っていない。見込みは wintf の描画面の全面の描き直し（WUC の `BeginDraw`）と出す処理（present）。動く絵のコマを進める処理や記録を書く処理の分もありうる。
- wintf の全面の描き直しは残っている。本 spec の境界（emo-present と、emo-compose の口 1 つ）では縮められない（要件討議の決め 3・設計の判断 D4）。

### 開発者への問いと答え

- 問い（2026-10-31）: release 版の中央値が SSP の基準を上回る。差を記録して本 spec を合格とし、残りを起票するか。それとも本 spec の境界を wintf まで広げて描き直しを縮めるか。推奨は前者（wintf へ広げると、v0.2.0 の `wintf-d2d-composite-rules` と重なるため）。
- 答え: 開発者「承認」＝推奨の案。差を記録して合格とし、残りは `wintf-visual-damage-redraw` の件 1 として起票した（下の一覧）。
