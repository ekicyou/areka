## 重い議題（3 つ）

### 議題 1: `doc/COMPAT_ARCHITECTURE.md` §8 で `session-crate-split` の直す行と隣り合う

- **懸念**: この spec が直す 354 行の上下の 353・355 行と、412 行の上の 411 行は、`crates/areka/src/session/` の道を書く行で、`session-crate-split` が直す。git は隣り合う行の変更を衝突として扱うので、後に着地する側の取り込みで §8 が衝突する。設計は「別々の行＝許す重なり」とだけ書き、衝突の解き方を書いていない。行の番号（196・226・354・412）も、相手が先に着地すれば動く。
- **影響**: 後に着地する側が手で衝突を解くと、名の直しか道の直しのどちらかを落とすおそれがある。
- **提案**: Revalidation Triggers か DocFollow に「後に着地する側は main を取り込み、§8 の衝突は相手の行を採ってから `apply` を当て直す（名で当てるので行の番号に依らない・2 度当てても変わらない）」と書く。行の番号は目安で、正本は改名表の名だと明記する。
- **要件**: 4.1・4.4・6.3
- **設計の箇所**: Boundary Commitments の Revalidation Triggers・DocFollow

### 議題 2: 最後の確かめの式と数えが実物と食い違う所がある

- **懸念**: ⑴ 式 4・5（`git grep -nP …`）は今の木で画像のファイル（`crates/areka/shell/org/320/a.png`・`8.png`）にも「Binary file … matches」で当たる。例外の表（research.md 8.4）にこの当たりは無い。⑵ Testing Strategy の「表の 68 の名」は、測ると表の行が 69・違う名が 62 で、どちらとも合わない。

- **要件**: 4.3・5.4・5.5
