- 2.1: `compose_alone` の中の合成の層（`areka-emo-compose/src/plan.rs`）は、正常な経路でも条件つきで `trace!`／`debug!` を出す。「記録を出さない」の検査は ERROR／WARN の水準で判定する（`snapshot.rs` 自身は記録を出さない）。
- 2.1: `cargo clippy -p areka-emo-present -- -D warnings` は既存の lint（`hub.rs:172` など・依存の `dola`）で止まる。起票済みの `clippy-199-lints` の範囲。新しいファイルは `--no-deps` で 0 件を確かめる。
- 3.1: `areka` は bin だけのクレートなので、テストは `cargo test -p areka --bin areka <filter>`（`--lib` は「no library targets」）。
- 3.1〜3.3: 呼び手が 4.1・4.2 で来るまで、`dump_surface.rs`／`dump_balloon.rs` の子モジュールの宣言に一時の `#[allow(dead_code)]` を付けている。4.1・4.2 で配線したら外す。
- 3.2: `png_base64` は幅 0 で panic し、バイト数が幅×高さ×4 と合わないと端を黙って捨てる。4.1・4.2 は呼ぶ前に幅・高さ・バイト数を確かめ、合わなければ `NG:picture size mismatch`＋`error!` 1 件で答える（design の Error Handling）。
- 3.2: テストの一時ファイルは `temp-path-kit`（%TEMP% の下）を使わず、`CARGO_MANIFEST_DIR/../../target/test-tmp/` の下に作る。
- 3.3: `overlay_text` も canvas・text の長さが幅×高さ×4 に合わないと添字で panic する。4.2 は呼ぶ前に確かめる（3.2 の項と同じ扱い）。
- 4.1: `judge` の宣言の一時の `#[allow(dead_code)]` は `judge_balloon`・`balloon_text` の呼び手が 4.2 で生えるまで残した。4.2 で外す。
- 4.1: 「装着の前は後から答える」を固定するのは 5.2 の GPU を通るテスト（4.1 の空の World のテストでは捕まらない）。
- 4.1（範囲外・完了時の棚卸へ）: `crates/areka/src/mcp/mod.rs` の `later` に付いた一時の `#[allow(dead_code)]` は呼び手ができて不要になったが、mod.rs は本 spec で触らない約束なので残している。
- 4.2: 文字の面は在るのに差し込み口に `Arrangement` が無い場合は、design の表に無い文言 `NG:the text slot has no arrangement`（`fail`＝`error!` 1 件）にした。`TextSurface::attach` が両方を同じ insert で入れるので本番では届かない防御の枝（4.1 の `compose_alone` が None の枝と同じ扱い）。

- 5.1（範囲外・完了時の棚卸へ）: 他のセッションの cargo が 25〜35 本動く重さの下で、全体テストに無関係な不安定が出た（`default_ghost_fault_after_fallback_exits_through_shiori_fault_path`・`script_change_tag_switches_a_to_b_and_reaches_steady`・`switch_to_b_without_boot_record_sends_first_boot_not_ghost_changed`・`stop_with_handoff_under_reservation_switches_without_exit`）。1 本ずつ流すと緑・新しいテストを外した対照でも出る。
- 5.2: 偽の SHIORI の呼び出しの列を比べる前に、土台の `flush_to_shiori()`（kanade へ返事つきの NOTIFY `OnSecondChange` を送り返事まで巡を回す）を通す。巡を回すだけの比較は「呼び出しのたびに kanade へ送る」壊し方を見逃した。5.3 の「邪魔をしない」も同じ関所を使う。
- 5.3: GPU を通るテストで台詞が現れ切ったかは、注入する Tick の時刻でなく実時間の台詞の時刻で決まる（話の起点は遅れて届く指令が後ろへ押す）。字の現れる時刻の列が字数だけ揃い、その末尾だけ実時間が過ぎた状態が 2 巡続くのを待つ。隠す指令は Tick を 1 ms ずつ刻まないと字が現れ切る前に届き、後から現れた字で表示が戻る。
- 6.1: design-validation.md の b（ゴーストの切り替えの途中に別のゴーストの絵を返しうる）は design の 8 行に無く未確認なので、差の一覧に載せていない。6.2 の実機確認か完了時の棚卸で確かめる。
- 4.3: 装着の前に `later` へ預けた組だけは、今も UI スレッドで符号化まで仕上げる（`later` の口が同期で `ToolOutcome` を返す形で、`mod.rs` は本 spec で触らない）。起きるのは起動の直後に 1 度だけ。このときの `ui_us`・`encode_us` はどちらも UI スレッドの時間。
- 4.3: `log_capture_kit` は呼んだスレッドの記録しか捕まえないので、別のスレッドで出る成功の `debug!`（`ui_us`・`encode_us` の欄）はテストで数えられない。欄は実機確認の記録で確かめる。符号化のスレッドの panic は `catch_unwind` で受けて `error!` 1 件と `NG:the encoding thread panicked` にした（受けないと入口が「終了中」と誤って答える）。
- 6.2: 実機の emo2 は休まず話し続けるので、バルーンが消える場面はバルーンのダブルクリック（台詞の中断）で作った。`sakurascript` は未実装（`areka-P0-mcp-kanade-tools` の受け持ち）なので、⑵ はキャラクターのダブルクリックで表情を変える代わりの手順にした（開発者の了承済み）。`dump_balloon` の UI スレッドの側は最大 14.2 ms で線に近い（文字の面の GPU からの読み戻しが UI スレッドに残る）。
- 検証（範囲外・完了時の棚卸へ）: `dump_surface.rs` の `compose_alone` が None の枝は、判断の文言 `NG:No such scope in this ghost` を `error!` つきで返す（届かない枝・要件 4.6 の精神と食い違う）。`later` を通る経路（`Step::here`）は `catch_unwind` なしに UI スレッドで符号化する。符号化のスレッドの記録は `log_capture_kit` に捕まらないので、GPU のテストの ERROR 0 件は UI スレッドの記録だけを見ている。`dump_balloon` の UI スレッドの側は最大 14.2 ms で線に近い（読み戻しを別のスレッドへ逃がすのは起票候補）。`sakurascript` が入ったら 7.7 ⑵ を本来の手順で撮り直す（`mcp-kanade-tools` の側）。
