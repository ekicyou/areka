# 設計の確かめ: real-run-log-noise

- 日付: 2026-10-29
- 対象: `design.md`（要件 6 を足した版・コミット `f7eff978`）
- 読んだもの: `spec.json`・`requirements.md`・`design.md`・`research.md`・`brief.md`・ステアリング（`product.md`・`tech.md`・`structure.md`・`logging.md`・`roadmap.md` の C12 の表の ④ の行）
- やり方: 対話なし（呼び手の指示）。設計が名前で挙げるコードを実物で引き直した。

## まとめ

設計は「毎フレームの行の出どころは再追従の判定の 1 か所」という見立てをコードで裏付けたうえで、そこだけを直す形になっており、要件 1〜6 のすべてに部品・口・テストが対応している。解き直しを省いても判定の答えが変わらないことと、`validrect` の右辺・下辺の 0 の読みの変更がほかの呼び手を壊さないことは、どちらもコードで確かめられた。実装に進めてよい。下の 2 点は設計の直しでなく、タスクを作るときに書き足せば足りる。

## コードで確かめたこと

1. **解き直しの入力は 3 つだけか**: `ResolvedBalloonText::resolve_with_background`（`actor_decoration.rs` 146 行目）は `WritingMode::resolve`・`ResolvedFont::resolve_with_background`・`ResolvedChoiceStyle::resolve`・`TextRegion::resolve`・`WrapMode::resolve` を呼ぶだけで、使う値はバルーンの定義・画像の原寸・背景色の 3 つ。`draw.rs`・`region.rs`・`wrap.rs`・`writing.rs`・`choice.rs`・`balloon_overrides.rs` に、外の状態（スレッドごとの値・static・環境変数・時刻・DPI・フォントの一覧）を読む所は無い。画像の原寸は `u32` から作るので非数も出ない。→ 入力が前と同じなら結果も同じで、判定の答えは変わらない。
2. **記憶の不変条件が破れる道は無いか**: 普通のバルーンの場所の `layout_input` を書くのは `register_actor`（`actor_attach.rs` 150 行目）だけ。`actor_box.rs` の書き込みと消去（63・438・445 行目）は箱の場所だけ。普通のバルーンの `routing` を消す口も無い。背景色の変化（`set_balloon_background`）は入力に入っているので、今と同じく解き直して作り直す。名前（`set_balloon_label`）は解き直しに使われない。
3. **同じウェーブの ③ `emo-text-dwrite-fidelity`**: その設計は `ResolvedFont` に `face` を足すが、`resolve_with_background` の中では名前から作る値（`FontFace::regular(&name)`）を入れるだけで、フォントの一覧を引くのは描く側（`FontCatalog::pick`）。→ 解き直しは純粋なまま。
4. **`validrect` の右辺・下辺の 0**: 座標へ解くのは `region.rs` の `TextRegion::resolve` だけ（emo-present の `balloon.rs` 530 行目は素の値を記録に出すだけ）。テストで右辺か下辺に 0 を渡しているのは `region_tests.rs` 118 行目・`region_vertical_canon_tests.rs` 656 行目（どちらも設計の T12 が直す）と `model_tests.rs` 230 行目（素の値の写しだけ）。`ValidRect::new` の引数の順は (top, bottom, left, right) で、設計の「2 つめ・4 つめ」はこれと合う。同梱の書庫を全部読むと、右辺か下辺が 0 なのは emo2 系の `descript.txt`（面ごとの上書きが 4 辺を書くので結果は変わらない）と `dot_sakura` の `bottle`（直したい当の相手）だけ。`bottle` を固定しているテストは無い。
5. **焼き込みの見分け**: emo2 の `purple/a/null.png` を持つ面は `surface1414` だけで、それを参照するのは `surface1000` の `animation1403`（`interval,bind`）のパターンだけ。設計の条件で集合に入る。`Interval::Bind`・`BindRandom` は在る。
6. **数え直しの文言**: 「テキスト供給面を予約スロットへ装着した」（`actor_present.rs` 245 行目・info）・「箱の束を受け取った」・「actor の装着先（予約スロット）を登録した」は今のコードに在る。`attach_wiring_test.rs` の「ちょうど 1 件」は作り直しの道なので、`trace` へ下げる行は数に入らない。

## 大事な指摘（2 件）

### 指摘 1: 飾りの警告で比べる「前の値」を、`register_actor` より先に取ること

- **問題**: 設計では `register_actor` がその場所の記憶を消し、そのあと装着と再追従が記憶を入れ直して飾りの警告を照らし合わせる（流れの図の「Register → update memory and check cursor warn」）。図の順のまま実装すると、照らし合わせの時点で前の記憶が消えていて「前は無い」になり、作り直しのたび（拡大率が変わるたび・付け替えのたび）に警告がもう 1 件出る。
- **影響**: 要件 2.3（値が同じなら追加で出さない）を破る。T4 の「拡大率の変わる再追従で 0 件」が赤で気付けるが、実装係が手戻りする。
- **直し方**: タスクに「装着と再追従は、`register_actor` を呼ぶ前に前の記憶の `CursorFallback` を取り出しておき、呼んだ後に新しい入力と比べる」と書く。設計の直しは要らない。
- **関わる要件**: 2.3・2.4
- **設計の場所**: 「再追従の判定」の流れの図・「解き直しの入力の記憶と解き直しの省き」の不変条件・「飾りの警告」の責務と決まり

### 指摘 2: 実機の数え直しの `r6-surface` の下限が弱い

- **問題**: 走行 B の `r6-surface`（供給面の装着の info）は「1 以上」で合格になる。`bottle` は本体側も相方側も右辺 0 で潰れていたので、片方しか直っていなくても合格する。この行は箱の場所でも出る。50 秒の間にゴーストが話さないと 0 になる心配もある。
- **影響**: 要件 6.4（`bottle` で文字を描く）の確かめが粗くなる。決定論のテスト T11 が読みそのものを固定するので、動きの誤りを見逃す危うさは小さい。
- **直し方**: 数える命令で `place` の欄が普通のバルーンの行だけを数え、話したスコープ（少なくとも本体 `actor=0`）ごとに 1 以上を求める。起動の挨拶で話すことを走行の記録で確かめる。
- **関わる要件**: 4.2・4.4・6.4
- **設計の場所**: 「実機の数え直し」の数える文言と上限の表（`r6-surface` の行）

## 小さい注意（指摘ほどではない）

- 要件 1.7 の 4 つの警告のほかに、同じ解き直しの中の「`font.name` が実質空」の `warn`（`draw.rs` 253 行目）も同じく止まる。数え直しの表に入れるかはタスクで決めてよい。
- 箱の束の受け取り（`actor_box.rs` 96 行目）でも `ResolvedFont` を解くので、`r17-font-height` の上限には箱の分（`N` × `G`）も足すのが正確。同梱物は `font.height,0` を書かないので、実際の数には効かない。
- `resolves` の上限 50 は、走行の長さに比例しない数として要件 4.3 に合う。実際の数が 50 に近ければ、上限を走行の記録から決め直してよい。
- 下辺の 0 は SSP で測っていない（設計の Revalidation Triggers の要件 6 の ⑴ に書いてある）。読みは右辺の測りと脚注の対称によるもので、受け入れてよい危うさ。

## よいところ

1. **根の 1 か所で止める**: 毎フレームの行を 1 本ずつ黙らせるのでなく、再追従の判定が毎フレーム解き直していることそのものを止める。解き直しの中の作者向けの警告（要件 1.7）まで、コードに触らずに「装着と変わり目だけ」になる。失敗と作者の誤りの記録は 1 つも消さない。不変条件・その破れ方（直の道 `register_actor`）・Revalidation Triggers まで書いてあり、後から触る spec が読める。
2. **要件 6 の調べが行き届いている**: `validrect` を座標へ解くのが 1 か所だけであることを `crates/` 全体で確かめ、期待値の変わるテスト 2 本と変わらないテストの名前を挙げ、読みの表・正典の出所・SSP の測り・測っていない所を分けて書いている。下流（配置・当たり・供給面・箱）に手を入れずに同じ読みへそろう形になっている。
