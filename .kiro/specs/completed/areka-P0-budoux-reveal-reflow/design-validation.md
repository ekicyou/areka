## 討議で決めたい点

### 1. 先渡しがバルーンの装着より先に届く窓（起動直後の最初のトーク）の扱い

**何が起きるか**

空回しは「先渡しを受け取った時点の状態の写し」から始まる。ところが、バルーンの既定の見た目が状態へ入るのは装着のとき（`TextLayerState::set_look_layers`・`crates/areka-emo-text/src/state_decoration.rs`）で、その説明自体が「合図の取り出しは非同期で、装着が次のフレームへ送られる間に `\f` が先に届くことがある」と書いている。`\s` の解決の閉包も、箱の束を受け取る（`TextLayerRuntime::set_box_layout`）までは無い（`TextLayerRuntime` の欄 `surface_resolver` の初期値）。

この窓で先渡しが届くと、空回しは「既定の見た目が ukadoc の既定・解決の閉包なし」の状態で走る。その後に装着が入ると:

- `\f` を使う台本: 空回しが装飾の表に入れた見た目（ukadoc の既定の上の指定）と、本番が入れる見た目（バルーンの定義の上の指定）が違う。装飾付きの字が届いた時点で食い違い、その区間は修正前の動き＋warn になる。
- 箱のあるシェルで、箱の束の受け取りが先渡しより後になった場合: 空回しは `\s` を読まないので行き先がすべて普通のバルーンになり、箱の字は「先渡しが無い」になる。
- 装飾を使わない台本・箱の無いシェル: 番号がどれも既定なので一致し、問題ない（設計の読みどおり）。

**なぜ討議に上げるか**

- 設計の表はこれを「トークの途中でバルーンが装着され」る場面として挙げているが、実際は「スコープの最初のトーク」で起きる順の話で、起動のたびに同じように起きうる。本 spec の実機の確かめ（初回起動トーク）がまさにこの窓の中にある。
- この順を踏む検査が設計に無い。「装飾なしなら装着が挟まっても一致する」という設計の読みを固定するものが無い。
- 実機の確かめの合格条件は「warn が 0 件」だが、それが通るのは emo2 の初回起動トークが `\f` を使わず箱も無い場合だけである（台本の中身は未確認）。

**決めること**

- (a) 受け入れる: 修正前の動きへ落ちる場面として表に「最初のトークで装着が後になった場合」を書き足し、純粋な部品の検査に「先渡し → `set_look_layers` → 合図」の順を 2 本足す（装飾なし＝全文のまま一致、`\f` あり＝落ちて warn 1 件）。実機の確かめでは、記録の上で先渡しの受け取りと装着のどちらが先かを読む。
- (b) 直す: 既定の見た目の差し込み（`register_actor`）と箱の束の受け取りのときに、残りの合図で空回しをやり直す。本番の合図はすべて `note_cue` を通るので「どこまで届いたか」は数えるだけで分かり、足すのは先渡しの列の保持 1 つ。設計が退けた「食い違いを見つけてからのやり直し」とは別で、やり直す時点が 2 か所に決まっている。

どちらでも設計の形は変わらない。(a) なら起動直後の `\f` 入りのトークでは字が飛ぶことが残る。

### 2. 文節の枝で「今の見た目」を届いた内容から取ると、狭い場面で表示済みの字が動く

**何が起きるか**

設計は、全文で配置するときも「今の見た目」（字の無い行の丈に使う値・`GlyphStyles` の欄 `current`）だけは届いた内容から取る、としている。この値は、字の置かれていない行を `\_l` や改行で閉じるときの行送りに使われる（`LineHeights::close` と `LineHeights::peek`・`crates/areka-emo-text/src/layout_styled.rs`、呼び手は `layout_scan.rs` の改行の腕と `\_l` の腕）。

たとえば区間の頭が「改行 → 相対の `\_l` → 字」で、その字が出た後に `\f[height,…]` が届く台本では、`\f` が届いた瞬間に「今の見た目」が変わり、すでに出ている字の行の位置が動く。今のコードでも起きる動きだが、本 spec の要件 1.1・1.2（各字は最初から最終の位置に出る・表示済みの字を動かさない）に当たる。

**決めること**

全文で配置する枝では「今の見た目」も全文の側から取る。全部出終わったときは届いた内容と全文が同じなので最終形は変わらず（要件 3.2）、途中だけが安定する。修正前の動きの枝は今のまま。変えるのは `arrange_lines` の 1 か所で、検査は「改行 → `\_l` → 字 → `\f[height]` → 字」の台本を 1 本足せば足りる。受け入れない（範囲外とする）なら、その旨を設計の「変わること・変わらないこと」に書く。

## 軽い指摘（討議は要らない・タスクで拾えばよい）

- **空回しの debug 行**: 空回しは状態の適用をそのまま呼ぶので、「Text cue 適用」などの debug 行が先渡しの時点でもう 1 組出る。実機の確かめは「最初の字の適用の記録より前に先渡しの受け取りの行がある」を読むので、空回しの行と本番の行を取り違えない読み方（区切りの印の名前で除く、など）を手順に書いておく。
- **「写しは比べられない」の言い回し**: `TextLayerState` は等しさを自動で導いているので、印の欄を足すと「印の立った写し」と本番の状態は中身が同じでも等しくならない。検査で比べるのは場所ごとの内容（`ActorTextState`）なので実害は無いが、設計の文は「比べない」に直すと正確。
- **本番の鎖を通しで歩く検査**: 経路を歩く検査は `EmoTextSink` を直接登録する。本番の鎖（トークごとの写し → `ClockedTextSink` → `EmoTextSink`）の通しは、飾りの転送の検査 1 本と実機の記録で確かめる形になっている。配線を二重に検査しない方針どおりで足りるが、起動の通しの検査（`crates/areka/src/emo2_boot/spine.rs` の土台）に「先渡しが無い」の warn が 0 件であることを 1 行足すと、将来の飾りの転送漏れも拾える。
- **既存の検査で増える warn**: 文節の折り返しのバルーンへ合図を直接流す既存の検査では warn が 1 件増える。設計は「件数を見る検査は無い」と調べているが、裏取りは全体テストに任されている。タスクの早い段（`TalkLookahead` を入れた直後）に 1 度全体を回す。

## 設計のよい点

- **配置を触らずに、配置の入力だけを元の前提へ戻している**。完了済みの文節の折り返しが持つ「同じ字の列なら、見える数を変えても前の字は動かない」性質をそのまま使うので、新しい判定が増えず、既存の検査も書き換えずに済む。コードで確かめた範囲では、見えている字より後ろを読むのは文節の幅の合計だけだった。
- **正本と先読みを分け、食い違いは必ず正本へ落ちる**。届いた字の正本は今までどおり状態の側にあり、全文は捨ててよい写しである。区間の番号に状態の消去の回数を使わず、空回しと本番で同じ数え方を同じ合図の列に当てる形にしたことで、装着が挟まって回数がずれる罠（research.md が見つけたもの）を作りの段階で避けている。対照の検査が同じ落とし先を使うので、古い実装の写しを検査のために持たなくてよい。
