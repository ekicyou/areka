# 追補: 要件 4.7/4.8 実 DPI 受け入れ（Task 8.4・2026-07-11）

目視受け入れでの開発者指摘（ukadoc 正典: bottom 吸着中は上下ドラッグ不可／SSP de-facto: バルーン相対位置の記憶）を要件 4.7/4.8 として追加し、DD15 v2（`DragPositionPolicy` トレイト分離・`move_window=false` 単一ライター）で実装後、同環境（dpi=120 主／192 副）で再検証した。

## 実機検証の過程で発見・修正した欠陥（実機必達原則の実証）

1. **DD15 v1（事後再釘付け）の構造的不成立**: wndproc（move_window=true）がドラッグ開始スナップショット＋カーソル差分で毎移動位置を再主張するため、事後補正は毎サイクル振動し最終位置は必ず非釘付けで確定（debug 調査 3/3 決定論再現・trace ログ立証）→ v2 単一ライターへ設計改訂（開発者指示: 反映段階で正しい座標を確定）。
2. **移動後バルーンのクリック死**: `enqueue_window_move` の bypass 書込は `Changed<WindowPos>` を発火させず `Arrangement.offset`（αマスクヒット矩形）が spawn 位置で凍結——初回キャラドラッグ後にバルーンが全面クリック透過化（状態依存・起動直後は正常）。wintf DragEnd donor と同型の直接 sync を内蔵して修正。
