# Requirements Document

> **改訂（2026-07-24・W4 着手前の要件再整備）**: 旧版（2026-07-16 生成）冒頭の申し送り（`areka-P0-sylphya` discovery 帰結のデルタ適用指示）を本改訂で**適用済み**。統一プロパティシステム（`completed/areka-P0-sylphya`・W3 完了・実装着地済み）の永続バッキングが、旧版で本 spec が所有を予定していた永続ストア実体（バージョン付き形式・原子的書込・寛容読取・ゴースト単位スコープ分離・往復耐久）を実装済みであることを前提に、本 spec を「永続ストアを**消費**して復元意味論と結線を担う spec」へ再切削した。ウェーブ配置は W4（roadmap 追記㊵/㊹）。

## Introduction

areka（ukadoc 準拠の互換ベースウェア）は現在、再起動のたびにゴースト窓が既定位置（右下吸着）へ戻り、ユーザーが決めた配置を忘れる。さらに起動記録を持たないため「初回かどうか」を判定できず、OnFirstBoot が毎回発火して初回挨拶を繰り返す（SSP 互換の「2 回目以降は OnBoot」にならない）。

永続化層の実体（ゴースト単位の永続ストア）は、統一プロパティシステム（`completed/areka-P0-sylphya`）の永続バッキングとして**既に実装・着地済み**である——窓位置・バルーン相対オフセット・起動記録・vanish 回数の 4 key 族、原子的書込、寛容読取、ゴースト単位のスコープ分離が檻（決定論テスト）込みで存在する。しかし現時点でこの器に**読み書きする消費者が存在しない**——窓位置は保存されず、起動記録は書かれず、boot 運行は毎回無条件に OnFirstBoot を発火し、vanish 回数は固定値 "0" のままである。

本ユニット（⓪ ghost 帰属）はこの永続ストアを消費して**復元意味論と結線**を実装で埋める: (1) 窓位置とバルーン相対オフセットの保存（ドラッグ確定の観測点からの書込）と復元（起動時の読出→初期配置への注入）、(2) 初回起動と通常起動の区別（OnFirstBoot ゲート）、(3) vanish 回数の永続読取経路（OnFirstBoot の Reference0）、(4) モニタ構成変化への画面内縮退（アンカー再射影）と、永続ストアが値を提供できないときの既定への寛容縮退。「伺かアプリとしての体裁」（位置を覚える・初回と通常起動を区別する）を、後続の消費者（`\![vanish]`・ゴースト切替）が同じ永続 key 族をそのまま使える形で成立させる。

本ユニットは窓生成・既定位置解決そのもの（window-placement ✅ 完了）や再吸着機構（surface-resize-resnap ✅ 完了）、永続ストア実装そのもの（sylphya ✅ 完了）を所有せず、それらの初期位置注入口・ドラッグ観測点・アンカー再射影・永続 key 族契約を消費して「値を差し、値を書く」結線層に徹する。永続化に起因するいかなる失敗でもゴーストの起動を停止させない（失敗はログ＋既定縮退）。

## Boundary Context

- **In scope**: 窓位置（キャラクタースコープ別）の保存結線（ドラッグ確定→永続ストアへの書込）と復元結線（起動時の読出→初期配置への注入）／バルーン相対オフセットの永続化（現状のセッション内記憶の持ち上げ・スコープ別）／初回起動と通常起動の区別（OnFirstBoot 発火 or スキップ→OnBoot）／vanish 回数の永続読取経路（OnFirstBoot の Reference0・M1 では実値 0）／保存位置が現在の作業領域外のときのアンカー再射影による画面内縮退／永続ストアが値を提供できないとき（不在・破損・未知形式は永続ストア側の寛容読取が吸収し「値なし」として現れる）の既定位置解決・既定運行への縮退と起動継続／本 spec が消費する永続 key 族（窓位置・バルーン相対オフセット・起動記録・vanish 回数）を当該ゴーストの永続スコープ下で読み書きすること。
- **Out of scope**: 永続ストア実装そのもの（バージョン付き形式・原子的書込・寛容読取・ゴースト単位スコープ分離・往復耐久性＝統一プロパティシステム `completed/areka-P0-sylphya` の領分・実装済み）／`\![vanish]` の実装（vanish カウント増分の発生源＝M2）／ゴースト切替・多重ゴースト（M2）／ウィンドウ以外の設定永続化（音量等・現状存在しない）／`\![move]` との相互作用（M-dialogue・`sakura-dialogue-tags`）／SSP の `ghost.dat` バイナリ互換（不要・保存形式は永続ストア側で確定済み）／窓生成・既定位置解決そのもの（window-placement の領分）／再吸着機構そのもの（surface-resize-resnap のアンカー再射影を消費するのみ）／バルーン位置のサーフェス単位（per-surface）再配置モデル（ukadoc 正典の `balloon.offsetx/offsety` は「そのサーフェスでのみの」定義＝サーフェスごとに再配置する設計だが、areka M1 はキャラクタースコープ単位の単一オフセットに畳んだ簡略化を維持する。per-surface 忠実化は M2 領分。本ユニットが保証するのは「永続オフセットがキャラサーフェス寸に依存せず再起動をまたいで正しく復元される」ことまで）。
- **Adjacent expectations**: 本ユニットは window-placement が提供する初期位置の注入口（spawn への placements 供給）とドラッグ終了の観測点を消費し、surface-resize-resnap のアンカー再射影を再利用する。ghost-setup の起動経路（ゴースト起動時に統一プロパティシステムの永続状態が当該ゴーストの profile 配下から寛容ロード済み）と kanade の起動運行（boot cascade）へ「初回か否か」「vanish 回数」を構築時に注入する。永続状態の保存先（ゴースト単位の profile 配下）・内部形式・耐久性保証（原子的確定・書込中断時の旧状態非破壊・寛容読取・スコープ分離）は統一プロパティシステム側で確定・実装済みであり、本 spec は同システムが公開する永続 key 族（キャラクタースコープ別の窓位置・バルーン相対オフセット・起動記録・vanish 回数）の契約を消費する。起動運行には OnInitialize と OnFirstBoot の間に起動時リソース照会（username 照会）段が既に存在し、本 spec の初回ゲートはそれを変更しない。

## Requirements

### Requirement 1: 窓位置の保存と復元

**Objective:** As an areka ユーザー, I want 移動したゴースト窓の位置が終了・再起動をまたいで保たれること, so that 毎回位置を決め直さずに済む

#### Acceptance Criteria
1. When ユーザーがキャラ窓（surface 全面ドラッグ）を移動し終えたとき, the ゴースト永続化機構 shall その窓の最終位置を、アンカー種別（吸着・Free）を問わず当該ゴーストの永続状態へ反映し、その時点で永続ストアへ即時に確定（書き込み）する（吸着はドラッグ中の移動制約であり、最終位置を保存するか否かの条件ではない）。
2. When areka が正常終了するとき, the ゴースト永続化機構 shall セッション中にユーザーのドラッグにより変更された窓位置が永続状態へ確定していることを、終了経路での最終確認（フラッシュ）により保証する（ドラッグ確定時の即時書き込みに対する安全網）。
3. If areka がドラッグ確定後・正常終了前に異常終了（クラッシュ／強制終了）したとき, the ゴースト永続化機構 shall 直近のドラッグ確定時点で永続化済みの窓位置を、次回起動で復元可能な状態に保つ（書込の原子的確定・中断時の旧状態非破壊は永続ストアの契約として保証済み——本 spec はドラッグ確定時点の即時書込によりこの契約へ載せる）。
4. When ゴーストが起動し、当該ゴーストの永続状態に保存済みの窓位置が存在するとき, the ゴースト永続化機構 shall 既定位置解決に優先して、保存済み位置へ窓を配置する。
5. When ゴーストが起動し、当該ゴーストの永続状態に保存済みの窓位置が存在しないとき, the ゴースト永続化機構 shall 従来の既定位置解決（既定の吸着位置）に従って窓を配置する。
6. The ゴースト永続化機構 shall キャラ窓の位置をキャラクタースコープ（本体・相方等のスコープ番号）ごとに区別して保存・復元する。バルーン窓の位置は Requirement 2 の相対オフセットから導出するものとし、絶対位置として独立には保存しない（位置の単一真実源はキャラ窓側に置く）。
7. The ゴースト永続化機構 shall 窓位置を、どのモニタ上のどの位置かを含めて復元する（仮想デスクトップ上の一貫した位置として保存・復元し、初期表示のプライマリモニタ基準へ丸めない）。
8. When 保存済み位置からキャラ窓を復元するとき, the ゴースト永続化機構 shall 起動時に設定から再解決したアンカー（吸着規則）を適用した位置へ配置する（吸着キャラは保存済みの水平位置を保ちつつ、アンカー辺＝下端の位置を現在の作業領域から導出する）。アンカー自体は永続状態に保存せず、毎起動の設定解決から得る。
9. The ゴースト永続化機構 shall 永続状態の窓位置・バルーン相対オフセットを、ユーザーの明示的なドラッグ確定によってのみ更新する。モニタ構成変化・作業領域変化・サーフェス寸法変化に伴う自動的な再射影／再吸着は、表示位置を変えても永続状態を書き換えない（保存値＝ユーザーの意図、表示位置＝意図と現在の物理制約との写像、という役割分離を保つ）。

### Requirement 2: バルーン相対オフセットの永続化

**Objective:** As an areka ユーザー, I want バルーンを単独で動かして決めた相対位置が再起動後も保たれること, so that 好みのバルーン配置が維持される

#### Acceptance Criteria
1. When ユーザーがバルーン窓を単独ドラッグしてキャラに対する相対位置を変更したとき, the ゴースト永続化機構 shall そのバルーンの相対オフセットを当該ゴーストの永続状態へ反映し、その時点で永続ストアへ即時に確定する（Requirement 1 と同じ「ドラッグ確定時の即時書き込み＋終了時フラッシュ」の耐久性モデルに従う）。
2. The ゴースト永続化機構 shall バルーン相対オフセットを、キャラサーフェスの寸法変動に対して不変な基準点——すなわちキャラのアンカー辺（下端吸着キャラでは下端）——を基準として保存・復元する。キャラ窓の左上を基準としてはならない（下端吸着ではサーフェス高さの変動に伴い左上が移動し、オフセットがずれるため）。
3. When ゴーストが起動し、永続状態にバルーン相対オフセットが存在するとき, the ゴースト永続化機構 shall そのオフセットを適用してバルーン窓をキャラへ追従配置する。
4. When 永続状態にバルーン相対オフセットが存在しないとき, the ゴースト永続化機構 shall 既定の暫定 offset（シェル定義由来）に従ってバルーン窓を配置する。
5. The ゴースト永続化機構 shall バルーン相対オフセットをキャラクタースコープごとに区別して保存・復元する。

### Requirement 3: 初回起動と通常起動の区別（OnFirstBoot ゲート）

**Objective:** As an areka ユーザー, I want 初回だけ初回挨拶が行われ、2 回目以降は通常起動として振る舞うこと, so that 毎回初回挨拶が繰り返されない（SSP 互換の体裁）

#### Acceptance Criteria
1. When ゴーストが起動し、当該ゴーストの起動記録が永続状態に存在しないとき, the ゴースト永続化機構 shall その起動を初回起動として扱い、OnFirstBoot イベントを発火させる。
2. When 初回起動として OnFirstBoot にスクリプトが返されなかった（204）とき, the ゴースト永続化機構 shall 続けて OnBoot イベントを発火させる（ukadoc 正典の 204 フォールスルーを維持）。
3. When ゴーストが起動し、当該ゴーストの起動記録が永続状態に存在するとき, the ゴースト永続化機構 shall OnFirstBoot をスキップし、OnBoot イベントから起動運行を開始させる。
4. When 初回起動として発火した初回挨拶トークの再生が完走したとき, the ゴースト永続化機構 shall 以降の起動が通常起動として扱われるよう、起動記録を永続状態へ記録する（「完了」＝初回挨拶トークの再生完走と定義する。記録前に異常終了した場合、次回起動は再び初回起動として扱われる——初回挨拶が一度は完走することの保証。boot 運行全体の完了監視は導入しない）。
5. The ゴースト永続化機構 shall OnFirstBoot 以外の起動運行——OnInitialize の発火、および OnInitialize と OnFirstBoot／OnBoot の間に既存する起動時リソース照会（username 照会）段——の挙動を変更しない（ゲートの対象は OnFirstBoot のみ）。

### Requirement 4: vanish 回数の永続読取経路（Reference0）

**Objective:** As a ゴースト（SHIORI 脳）, I want OnFirstBoot の Reference0 が永続状態由来の vanish 回数を反映すること, so that 将来の vanish カウント増分がそのまま体裁へ反映される

#### Acceptance Criteria
1. When OnFirstBoot イベントを発火させるとき, the ゴースト永続化機構 shall 当該ゴーストの永続状態から読み取った vanish 回数を Reference0 として渡す。
2. When 永続状態に vanish 回数が記録されていないとき, the ゴースト永続化機構 shall Reference0 を 0 として渡す（M1 では vanish の発生源が未実装のため実値は常に 0）。

### Requirement 5: 保存位置の画面内縮退（モニタ構成変化への追従）

**Objective:** As an areka ユーザー, I want モニタ構成や解像度が変わって保存位置が画面外になっても、ゴーストが画面内に現れること, so that ゴーストを見失わない

#### Acceptance Criteria
1. When ゴーストが起動し、復元しようとした保存位置が現在の作業領域（work area）内に収まらないとき, the ゴースト永続化機構 shall 保存位置をアンカー再射影で作業領域内へ寄せて窓を配置する。
2. While 保存位置を作業領域内へ再射影するとき, the ゴースト永続化機構 shall 既存の吸着規則（例: 下端吸着）を維持する。
3. When 復元した保存位置が現在の作業領域内に収まるとき, the ゴースト永続化機構 shall 保存位置をそのまま用い、不要な再射影を行わない。
4. When 保存位置を作業領域内へ再射影して窓を配置したとき, the ゴースト永続化機構 shall 再射影後の位置を永続状態へ書き戻さず、保存済みの位置（ユーザーが最後に決めた位置）を保持する（モニタ構成が元に戻った次回起動で、元の位置へ復元できるようにするため）。

### Requirement 6: 永続化の頑健性（消費側の寛容縮退）

**Objective:** As an areka ユーザー, I want 永続状態が読めなかったり保存に失敗しても、起動が失敗せず既定位置で立ち上がること, so that 永続化の不具合でゴーストが使えなくならない

#### Acceptance Criteria
1. If 起動時に永続ストアが当該 key の値を提供できないとき（不在・読取障害・破損・未知形式——これらは永続ストアの寛容読取契約により「値なし」として現れる）, the ゴースト永続化機構 shall 既定位置解決・既定運行（初回起動扱い・vanish 回数 0 を含む）へ寛容に縮退し、起動を継続する。
2. If 永続状態の保存（書き込み・確定）が失敗した（永続ストアが縮退を報告した）とき, the ゴースト永続化機構 shall 警告またはエラーログが記録されたうえで、起動・実行を中断せず継続する（保存失敗・書込中断の際に以前の保存済み有効状態が破壊されず次回起動で読めることは、永続ストアの原子的確定の契約として保証済み——本 spec で再実装しない）。
3. The ゴースト永続化機構 shall 永続化に起因するいかなる失敗でもゴーストの起動を停止（クラッシュ）させない。

### Requirement 7: ゴースト単位の永続化スコープ（消費）

**Objective:** As a 将来の消費者（`\![vanish]`・ゴースト切替）, I want 本 spec の読み書きする永続状態が当該ゴーストの永続スコープ下に置かれること, so that 複数ゴーストや将来機能が状態を取り違えない

#### Acceptance Criteria
1. The ゴースト永続化機構 shall 本 spec が消費する永続 key 族（窓位置・バルーン相対オフセット・起動記録・vanish 回数）の読み書きを、すべて当該ゴーストに対応する永続スコープに対して行い、他ゴーストの状態と混同しない（ゴースト単位の物理分離そのものは永続ストアの契約として保証済み）。
2. When 本 spec の消費する key 以外の値が同じ永続スコープに同居しているとき, the ゴースト永続化機構 shall 自らの保存操作によってそれらを破壊しない（無関係 key の温存は永続ストアの保存契約として保証済み——本 spec は key 族契約に沿った書込のみを行う）。

### Requirement 8: 受け入れ検証（決定論 unit ＋ 実機サインオフ）

**Objective:** As a 受け入れ検証者, I want 復元意味論と結線の中核挙動が決定論的に検証でき、実機で位置維持を確認できること, so that 非決定な I/O に依存せず回帰を檻に入れられる

#### Acceptance Criteria
1. The ゴースト永続化機構 shall 保存結線→復元結線の往復（ドラッグ確定で書き込まれた窓位置・バルーン相対オフセット・起動記録・vanish 回数が、次回起動の読出で配置・運行・Reference0 へ値等価に反映されること）を決定論的な単体テストで検証可能とする（永続ストア自体の書込往復・寛容読取・原子的確定の檻は `completed/areka-P0-sylphya` 側で保証済み＝本 spec は結線の檻のみを追加する）。
2. The ゴースト永続化機構 shall 永続ストアが値を提供しないときの既定への縮退、および保存位置が作業領域外のときのアンカー再射影を、決定論的な単体テストで検証可能とする。
3. The ゴースト永続化機構 shall 初回起動（起動記録なし）で OnFirstBoot が発火し、2 回目以降（起動記録あり）で OnFirstBoot がスキップされて OnBoot から始まることを、決定論的な単体テストで検証可能とする。
4. The ゴースト永続化機構 shall 自動的な再射影・再吸着が永続状態を書き換えないこと（保存位置が作業領域外 → 再射影して表示 → 永続値は保存時のまま不変）を決定論的な単体テストで検証可能とする。
5. The ゴースト永続化機構 shall バルーン相対オフセットがキャラサーフェスの寸法変動に対して不変であること（あるサーフェス高さで保存したオフセットを、異なるサーフェス高さで復元してもバルーンとキャラの配置関係が保たれること）を決定論的な単体テストで検証可能とする。
