要件 3.8（2026-10-19 の開発者の裁定）。8.2 の「気付いたこと 1」（`ghost` の読み直しの後、キャラクターの姿が出ない）を直した後の実機の確かめ。

## 手順

- ビルド: `cargo build -p areka --bin areka -j 8`・`cargo build -p shiori-host32-helper --target i686-pc-windows-msvc -j 8`（作業ツリー＝HEAD `d2e9343e`＋本タスクの未コミットの変更）。
- 検体: `target\nar-samples\manual\emo2` の `ghost\emo2`・`balloon\emo2-kakukaku` を `target\mcp-reload-carry\root` へ写した。時報（`dic\hour.pasta`）は外した。`areka.exe` と i686 の `shiori-host32-helper.exe` も同じ根へ写した。
- 起こし方: PowerShell から `Start-Process`（標準出力を `target\mcp-reload-carry\logs\run1.log` へ）。`AREKA_*`・`WINTF_*` を消してから `RUST_LOG=info,kanade=debug,areka::emo2_boot=debug,areka::ghost_session=debug`・`AREKA_APP_SMOKE_EXIT_MS=300000`（有界の自動終了）・`AREKA_NO_ALERT=1`・`AREKA_MCP_PORT=9841`・`AREKA_ROOT=<根>`・`LOCALAPPDATA`／`TMP` を `target\mcp-reload-carry\` の下へ。ゴーストは argv で絶対パス `…\root\ghost\emo2` を渡した。
- MCP: `POST http://127.0.0.1:9841/api/mcp/v1`（`Accept: application/json, text/event-stream`）へ JSON-RPC の `tools/call`（`get_status`・`sakurascript`・`dump_surface`・`reload`）。
- 面の確かめ: `dump_surface`（`scope` 0・1）の答えの文（`OK:scope N, surface M as currently shown …`）と、`apply(ShowSurface)` の記録（`TargetId(0)`＝scope 0 のシェル・`TargetId(2)`＝scope 1 のシェル）。

起こした areka（`target\mcp-reload-carry\runs.txt`）: run1・番号 11260・有界の自動終了（`app_exit origin=Smoke`・10:02:48 UTC）。run2（着せ替えの持ち越しを足した後の版・番号 18020・ポート 9842・`AREKA_APP_SMOKE_EXIT_MS=150000`）と run3（2 度目の差し戻しの後の版＝既定の基準を読み直しの前の既定に・着せ替えを面より先に送る・番号 11252・ポート 9843・`AREKA_APP_SMOKE_EXIT_MS=120000`）も有界の自動終了（`origin=Smoke`）。強制終了は 0 件。終わった後に areka・補助プロセスは残っていない（`tasklist`）。

## ⑴ 面を保つ

```
sakurascript {"script":"\0\s[1205]\1\s[2102]\e"} → OK
dump_surface {"scope":0} → OK:scope 0, surface 1205 as currently shown …
dump_surface {"scope":1} → OK:scope 1, surface 2102 as currently shown …
reload {"target":"ghost"} → OK:reload requested. …(log_type=error, since_id=14)
```

記録（UTC）:

```
09:58:08.851621 reload_started target=Ghost origin=Mcp ghost=えも？？
09:58:08.910542 reload_shell_captured surfaces={0: 1205, 1: 2102}
09:58:08.919261 windows_closed_for_restart closed=4
09:58:09.423525 emo2 attach: 装着計画を実行 planned=2 attached=2
09:58:09.423801 reload_shell_restored scope=0 surface=1205
09:58:09.424005 reload_shell_restored scope=1 surface=2102
09:58:09.428512 apply(ShowSurface) target_id=TargetId(0) surface_id=1205
09:58:09.434969 apply(ShowSurface) target_id=TargetId(2) surface_id=2102
09:58:09.701419 reload_done target=Ghost origin=Mcp
```

読み直しの後: `dump_surface` は scope 0＝1205・scope 1＝2102。8.2 では `NG:No surface has been shown in this scope yet` だった。装着から面が出るまで約 5ms（装着の相が seriko へ `\s[面]` と同じ合図を送り、seriko の `Show` が次の取り出しで表示層へ届く）。

同じ手順を最後にもう一度（面 1205／2101）: `reload_shell_captured surfaces={0: 1205, 1: 2101}` → `reload_shell_restored` 2 件 → `reload_done`（10:00:35）。読み直しの後の `dump_surface` の絵を `target\mcp-reload-carry\shots\5-after-s0.png`・`5-after-s1.png`（並べたもの `5-after-both.png`）に残した。

## ⑵ 読み直しを待つ間に台詞で面が変わった

2 回目の読み直しでは、`sakurascript` の直後にランダムトーク（`OnTalk`）が始まり、読み直しは台詞の終わりまで待った（要件 2.4）。控えは降ろす直前の面で、その面が出し直された:

```

09:58:43.293152 reload_shell_captured surfaces={0: 1000, 1: 2106}
09:58:43.715684 reload_shell_restored scope=0 surface=1000
09:58:43.715892 reload_shell_restored scope=1 surface=2106
09:58:43.968294 reload_done target=Ghost
```

## ⑶ 面がシェルから消えたときは既定の面へ

1. シェルの `surfaces.txt` を元に戻して `reload`（`ghost`）で 2102 の在るシェルを読み、`\0\s[1205]\1\s[2102]` を出した（`dump_surface` で 1205／2102）。
2. `surfaces.txt` の `surface2102` のブレスの名前を `surface2902` に替えた（2102 が無いシェル）。
3. `reload {"target":"ghost"}`。

```
09:59:20.517914 reload_started target=Ghost
09:59:20.576830 reload_shell_captured surfaces={0: 1205, 1: 2102}
09:59:21.038093 reload_shell_restored scope=0 surface=1205
09:59:21.038273 WARN reload_shell_fell_back scope=1 missing=2102 to=10
09:59:21.043811 apply(ShowSurface) target_id=TargetId(0) surface_id=1205
09:59:21.049689 apply(ShowSurface) target_id=TargetId(2) surface_id=10
09:59:21.285220 reload_done target=Ghost
```

読み直しの後の `dump_surface`: scope 0＝1205・scope 1＝10。その後も `TargetId(2)` の面 10 の `ShowSurface` が続く（seriko のループのアニメが新しい seriko で動いている）。

この走行の `ERROR` の 7 件は、どれも手順 2 で 2102 を消したシェルに対して台本が 2102（`\s[2102]`・別名 `笑顔`）を出そうとしたもので、本タスクの変更によるものではない。

## ⑸ 着せ替えを保つ（差し戻しの後・run2）

差し戻し（2026-10-19「着せ替えもシェルの状態」）で着せ替えの持ち越しを足した版を、⑴〜⑶ と同じ根から起こし直して確かめた（シェルの定義は元に戻した）。起動の挨拶が `\![bind]` で 口＝にこっ・目＝笑顔・まばたき などを着る。

```
sakurascript {"script":"\0\s[0]\![bind,腕,組み,1]\e"} → OK
reload {"target":"ghost"} → OK:reload requested. …
```

記録（UTC）:

```
10:18:03.071073 reload_started target=Ghost origin=Mcp
10:18:03.180974 reload_shell_captured surfaces={0: 0, 1: 2106} binds={0: BindSet([1101, 1207, 1303, 1403, 1500, 1800]), 1: BindSet([1100, 1207, 1302, 1500, 1800])}
10:18:03.218941 windows_closed_for_restart closed=4
10:18:05.409115 reload_shell_restored scope=0 surface=0
10:18:05.412176 reload_shell_restored scope=1 surface=2106
10:18:05.414544 reload_shell_bind_restored scope=0 category=腕 part=組み on=true
10:18:05.415807 reload_shell_bind_restored scope=0 category=目 part=笑顔 on=true
10:18:05.417262 reload_shell_bind_restored scope=0 category=まばたき part=---- on=true
10:18:05.422946 seriko: bind 適用 scope=0 category=腕 part=組み id=1101 on=true
10:18:05.424376 seriko: bind 適用 scope=0 category=目 part=笑顔 id=1303 on=true
10:18:05.425755 seriko: bind 適用 scope=0 category=まばたき part=---- id=1403 on=true
10:18:05.526164 apply(ShowSurface) target_id=TargetId(0) surface_id=0
10:18:06.658225 reload_done target=Ghost origin=Mcp
```

- 読み直したシェルの既定（腕＝伸び 1100・口＝にこっ 1207・目＝通常 1302 ほか）との差だけを、台本の `\![bind,…]` と同じ合図で送った。腕・目は排他の置き換えで既定の 伸び・通常 が外れる（脱ぐ合図は送らない）。口＝にこっ（1207）は既定と同じなので送らない。
- scope 1 の控えは読み直したシェルの既定と同じ（着せ替えを変えていない）なので、合図は 0 件。
- `reload_shell_bind_dropped`（名前の無くなった着せ替え）は 0 件（シェルの名前の表を変えていないため。落とす枝は決定論テスト `decide_binds_keeps_a_worn_bind_and_drops_an_undefined_one`・`attach_replays_the_carried_binds_and_drops_an_undefined_one` が固定する）。
- `dump_surface {"scope":0}` → `OK:scope 0, surface 0 as currently shown (with running animations and dressups, …)`。

### 2 度目の差し戻しの後（run3）: 最初の表示から着せ替えた姿

着せ替えの基準を「読み直しの前のシェルの既定」に改め、合図を着せ替え → 面の順にした版で、同じ手順（`\0\s[0]\![bind,腕,組み,1]\e` → `reload ghost`）を回した。

```
10:30:26.367009 reload_shell_captured surfaces={0: 0, 1: 2106} binds={0: BindSet([1101, 1207, 1303, 1403, 1500, 1800]), 1: BindSet([1100, 1207, 1302, 1500, 1800])} old_static=BindSet([1100, 1207, 1302, 1500, 1800])
10:30:26.769820 reload_shell_bind_restored scope=0 category=腕 part=組み on=true
10:30:26.769922 reload_shell_bind_restored scope=0 category=目 part=笑顔 on=true
10:30:26.770020 reload_shell_bind_restored scope=0 category=まばたき part=---- on=true
10:30:26.781869 apply(ShowSurface) target_id=TargetId(0) surface_id=0
10:30:26.983045 reload_done target=Ghost origin=Mcp
```

- 読み直しの後の `TargetId(0)` の `ShowSurface` は **1 件だけ**（run2 では面 → 着せ替えの順だったので 4 件＝最初の 1 件が既定の姿・続く 3 件が着せ替えごとの出し直し）。着せ替えの合図は面の出ていないスコープで seriko の状態だけを変え（`StateOnly`・seriko の `bind 適用` の info は出ない）、続く面の合図の最初の `Show` がもう着せ替えた集合を載せたことを示す。既定の姿のフレームは出ていない。最初の `Show` の着せ替えの集合そのものは決定論テスト（`replay_shows_the_decided_surfaces_and_binds_through_seriko`・`attach_replays_the_carried_binds_and_drops_an_undefined_one`）が固定する。
- 控えの `old_static` は読み直しの前のシェルの既定。台本で着た分は 腕＝組み（1101）・目＝笑顔（1303）・まばたき（1403）で、送ったのもこの 3 件だけ（口＝にこっ 1207 などの既定は送らない）。
- この走行の版は、記録だけ「面を出し直す」を「着せ替えを出し直す」より先に書いていた（送る順は着せ替えが先）。記録の順も送る順に合わせて直した（実機の走行の後の変更・テストで確かめた）。

## 画面の撮り方について

PowerShell の `CopyFromScreen`（DPI を意識した全画面）で前後を撮ったが、この時の画面ではキャラクターの窓が手前の別アプリの窓に隠れていて、キャラクターは写らなかった（窓は `EnumWindows`＋`GetWindowRect` で 4 枚とも在り、位置は読み直しの前後で同じ `[1392,904,2064,1704]`・`[2064,610,2828,1704]` ほか）。画面の操作で窓を手前へ出すことはしていない。絵の証跡は `dump_surface` の絵（表示層が今出している面の合成）に替えた。撮った全画面の画像はキャラクターが写っておらず別アプリの中身が写ったので消した。
