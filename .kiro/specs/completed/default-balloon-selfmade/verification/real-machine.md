## 組み方と回し方

- 根: ワークツリーの `target\balloon-real\root\`（要件 13.8）
  - `ghost\emo2`・`ghost\dot_sakura`: `nar-sample-path` が開いた検体の写し
  - `balloon\areka-balloon`: 窓口から開いた検体の写し
- 記憶: `target\balloon-real\profile\<回>\`。回ごとに空にした。
- 記録と撮った画像: `target\balloon-real\logs\`・`target\balloon-real\shots\`
- バルーンの被せ方: 位置の引数の 2 つ目で被せた（`areka.exe "<根>\ghost\<名>" "<根>\balloon\areka-balloon"`）。記録はどの回も `balloon_resolved route=Argv dir=...\balloon\areka-balloon` だった。
- 環境変数: `AREKA_ROOT`・`AREKA_PROFILE_DIR` は target の下へ向け、`AREKA_USER_ROOT`・`PASTA_DEBUG` は消した。`RUST_LOG=info,areka::boot_resolve=debug,wintf::ecs::layout::systems::monitor_systems=debug`。
- 台本: areka の MCP の `sakurascript` で送り、送る前に `check_script` で確かめた（0 diagnostics）。
  - A（小の面）: `\0\b[0]` で半角だけ・全角だけ・混ぜた本文を流し、続けて `\1\b[0]` で相方側に 3 行の本文を流す。末尾は `\_w[30000]`。
  - B（大の面）: `\0\b[2]` で本体側の大の面へ切り替え、10 行の本文を流す。末尾は `\_w[30000]`。
  - 末尾の `\_w[30000]` は、ゴーストが自分から話し出して台本を上書きしないよう、喋っている状態を保つため。emo2 は最初の 2 回の送りをすぐ自分の話で上書きした。
- 閉じ方: MCP で `\0\-` を送った。4 回とも終了コードは 0。

## 崩れの振り分け（要件 12.9）

1. **`cursor.blendmethod` の WARN が 1 回あたり 3 万〜6 万行あふれる → areka の欠陥・`real-run-log-noise` 件 2 で起票済み。**
   - `areka-balloon` の `cursor.blendmethod,mergepennot` は手本のバルーンの値（research.md 10.2）で、正典の値なので、バルーンは変えない。
   - areka が、この値を none 扱いへ縮退したことを毎フレーム記録するのが欠陥である（1 回だけ出すはず）。同じ件が、生きている spec `.kiro/specs/real-run-log-noise/`（`completed/` でない）に起票済み。場所は brief の「どっとさくらで見えた事実」の節で、`bottle` で `cursor.blendmethod` の WARN が毎フレーム出る件である（根拠は完了 `areka-P0-dot-sakura-specimen` の verification.md 8 節の件 2）。重ねて起票しない。
   - 測った数: emo2 100% 34,264 件・emo2 200% 40,504 件・どっとさくら 100% 62,044 件・どっとさくら 200% 44,676 件。
2. **面の縮退の WARN は 1 回あたり 6 件 → 今の作りどおり（崩れではない）。**
   - 相方側は面 0・1 しか持たない（要件 2.2）ので、面 2・3 が本体側の系列へ縮退する 2 件が、装着のたびに出る。
   - 1 回の起動で 3 回装着するので 6 件になる。tasks.md の Implementation Notes（3.2）が見込んだ「2 件」は装着 1 回分の数である。
3. **半角の行を折り返したとき、次の行の先頭に空白が残る**（`…The quick` の次の行が ` brown fox …` で始まる。4 回とも同じ）。
   - areka の文字の層の振る舞いで、バルーンの誤りではない。
   - 生きている spec の brief と roadmap.md に、これを持つ件は見当たらない。
   - tasks.md の Implementation Notes に「`/kiro-complete` の棚卸で `/kiro-discovery` に起票する候補」として書いた。
4. **大の面の本文で、行の頭に `:` が来る・`0` と `123456789` が行をまたいで割れる**（4 回とも同じ）。
   - areka の文字の層の振る舞いで、バルーンの誤りではない。
   - 行の頭の `:` は行頭禁則の件で、生きている spec `text-typesetting`（禁則・バルーンのキー `line_break`）が持つ。ただしその spec の既定は `anywhere`（禁則なし＝SSP と同じ折り返し）である。
   - 数字の並びを行で割らないことは、`text-typesetting` の brief に明記が無い。tasks.md の Implementation Notes に起票の候補として書いた。
   - SSP でも同じ割れ方になるかは測っていない（SSP との見比べはしていない）。

本仕様で直すバルーンの絵や設定の誤りは見つからなかった。
