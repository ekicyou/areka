# Brief: areka-P0-sakura-tag-word-boundary

> 起票: 2026-09-03（`areka-P0-sakura-bare-tag-lexer` の `/kiro-validate-impl` 中に発見・同 spec の射程外）。
> 本書の file:line は起票時の実測。**着手時に必ず再検証すること**（`areka-P0-sakura-bare-tag-lexer` が `scan_tag` を触った直後ゆえ行番号が動く）。

## Problem

台詞の本文に**半角 `[`** が現れると、その直前のタグと、タグから `]` までの本文が**黙って消える**。利用者にはエラーも欠けた記号も見えず、ただ文が短くなる。

消えるのは表示だけではない。タグ自身の意味も失われる。

```
\1青い[1]ノートさんから交代したよ〜。\e
  → [Raw("\1青い[1]"), Text("ノートさんから交代したよ〜。"), End]
```

「青い」が消えるうえに **`\1` の話者切替が消滅し、別のキャラクターが喋る**。同様に `\n`（改行）・`\e`（トーク終了）・`\-`（終了指令）も失われる。

角括弧が閉じない場合はさらに悪く、**入力の残り全部**が飲まれる。

```
\eテキスト[注です。まだ続く台詞  →  [Raw("\eテキスト[注です。まだ続く台詞")]
```

本プロジェクトが最悪と定める「間違った結果を正常な顔で見せる」類型にあたる。

## Current State

`crates/areka-parsers/src/sakura/lexer.rs` の `scan_tag` は、`\` の次からタグ語を読むとき **`[`／`\`／`%` に当たるまで**進む。タグ語の語彙を持たないため、本文の文字列もタグ語に含めてしまう。

その結果、本文に `[` があると角括弧経路が選ばれ、`Tag { word: "1青い", args: ["1"] }` のような実在しないタグができる。`decode_tag` はこの語を知らないので `Instruction::Raw` へ落ち、`crates/areka-sakura/src/compile.rs:201-203` が `Raw` を捨てる。よって飲み込まれた本文もタグの意味も表示に届かない。

**発火条件**: 素のタグ（角括弧付きでも短縮形でもない）の後ろ、次の `\` か `%` が来る前に半角 `[` が本文に現れること。

**影響しない形**（起票時に実測で確認）:

| 形 | 例 | 理由 |
|---|---|---|
| 角括弧付きタグ | `\s[0]テキスト[注]です` | 引数走査が正しく閉じ、次の走査が本文から始まる |
| 真の短縮形 | `\w9テキスト[注]です` | 短縮形判定が語走査より手前で確定する |
| 全角の括弧 | `\eテキスト［注］です` | 半角 `[` ではない |
| 直前にタグが無い本文 | `ふつうの台詞[1]です` | タグ走査に入らない |

**既存契約への違反**: 完了済み spec `areka-P0-sakura-parse` の受入基準 **13.1** は「バックスラッシュで始まる単一文字タグ（例 `\0` `\1` `\e` `\-`…）… そのタグ規則に従って当該タグを終端し、**後続文字をタグの一部に巻き込まない**」と定める。`\eテキスト[注]です` はこれに正面から違反する。つまり本件は所有先未定の新発見ではなく、**完了済み契約に開いた、テストされていなかった穴**である。当時のテストは `[` が後続しない形しか見ていない。

**なぜ今まで露見しなかったか**: 適合対象フィクスチャ emo2 の辞書にある半角 `[` は 21 件すべてが正当な角括弧付きタグ（`\s[...]`・`\q[...]`・`\![move,...]`・`\w[3000]`・`\_l[...]`・`\_w[600]`）とコメント 1 行で、台詞中の素の `[` は 0 件。M1 の適合判定はこの欠陥に触れない。

**正典側の裏付け**: さくらスクリプトのエスケープはバックスラッシュの二重化のみで行う（YAYA Tips「SAKURAスクリプトタグをエスケープする」＝`\s[0]` を表示したいときは `\\s[0]` と変換）。`[` はエスケープ対象ではない＝**台詞中の素の `[` は正当な入力**である。さらに YAYA の `EscapeAllTags` は外部由来テキスト（他ゴースト名・D&D ファイル名・RSS 見出し・ユーザー入力）の `[` を素通しさせるため、それらを台詞へ差し込むゴーストは容易にこの形を作る。

## Desired Outcome

- 台詞本文に半角 `[` があっても、直前のタグが自分の規則どおりに終端し、本文が 1 文字も消えない。
- タグの意味（話者切替・改行・トーク終了・終了指令）が失われない。
- 角括弧付きタグの引数分割・短縮形・エスケープ・未閉じの寛容吸収は 1 バイトも変わらない。
- 完了済み spec `areka-P0-sakura-parse` の受入基準 13.1 が、`[` が後続する形でも成立することを決定論テストで固定する。

## Approach

**既知タグを自分の規則で終端する（案 C）**。

areka が意味を与えているタグ——1 文字 bare（`\e` `\c` `\-` `\n` `\0` `\1` `\h` `\u`）・短縮形の対象語（`\w` `\b` `\p`）・角括弧なし `\_X`／`\__X`（`areka-P0-sakura-bare-tag-lexer` が確定した固定長規律）——については、語走査を greedy に回さず、そのタグ自身の規則で語を閉じる。閉じた位置で**既存の `[` 判定をそのまま行う**（`\n[half]` のような正当な角括弧形は現行どおり角括弧経路へ）。未知の語は現行の走査を維持する。

検討した他案:

- **案 A（語彙表とアリティ表の導入）**——正典の模型そのもので理想形だが、タグ語彙の正本が必要になる。その正本は `areka-P0-ukadoc-survey-sakura-script` の網羅調査が生む。調査の後に来るべきで、本 spec で先取りしない。
- **案 B（タグ語らしさの推定）**——走査結果が ASCII のみのときだけ `[` を引数開始と見なす等の発見的規則。小さく効くが、正典に無い規則を新設するため COMPAT §8 の裁量行が増え、ASCII 混じりの台詞（`\0file[1].txt`）は救えない。

案 C を採る理由は 3 つ。⑴ 違反している契約 13.1 が名指ししているのがまさに単一文字タグであること。⑵ **意味の消失（話者取り違え・改行消失・トークが終わらない）は全件が既知タグ**で起きるため、案 C で全滅すること。⑶ 未知タグの扱いについて新しい正典解釈を持ち込まず、一般語彙の問題を調査トラックへ残せること。

## Scope

- **In**:
  - `scan_tag` のタグ語終端規則を、既知タグについて「そのタグ自身の規則で閉じる」形へ変える。
  - 閉じた位置での既存 `[` 判定の維持（`\n[half]`・`\w[2]`・`\_a[ID]` 等は現行どおり角括弧経路）。
  - 未閉じ角括弧による「残り全部の吸収」が既知タグでは起きなくなることの確認。
  - 決定論テストの新設（既知タグ全件 × 本文に `[` を含む形・未閉じ形・角括弧形の不変・免疫のある 4 形）。
  - COMPAT 記録と、`areka-P0-sakura-parse` の受入基準 13.1 に穴があった事実の登記。
- **Out**:
  - 未知タグ語（areka が意味を与えていない語）の走査規則。現行維持し、一般解は調査トラックへ送る。
  - タグ語彙表・アリティ表の新設（案 A）。
  - 角括弧なし `\_` タグの消費長規律そのもの（`areka-P0-sakura-bare-tag-lexer` が確定済み・不変）。
  - `Instruction::Raw` が下流で捨てられる契約（`compile.rs`）の変更。
  - `\_a`・`\_q` 等の意味付け（各所有 spec の領分）。
  - 全角括弧・その他の記号を引数開始と見なす拡張。

## Boundary Candidates

- **タグ語の終端規則**（`lexer.rs` `scan_tag` の語走査）——本 spec の中核。既知タグの終端位置を決める判断を 1 か所に閉じる。
- **既知タグ集合の所在**——現状は `SHORTHAND_WORDS`（`lexer.rs`）と `decode_bare` の腕（`decode.rs`）に分かれている。字句層が「既知の 1 文字タグ」を知る必要が生じるため、集合の置き場と依存方向（`lexer` は `decode` を知らない）が設計上の主要な判断点。
- **決定論テストの接続**——`lexer_*_tests.rs`／`parse_*_tests.rs` の兄弟ファイル規約（steering `structure.md`）に従う。

## Out of Boundary

- 未知タグの走査規則の一般解（案 A の語彙表）。
- `decode_tag` の腕の追加・削除、`Instruction` への variant 追加。
- 角括弧なし `\_` タグの固定長規律（先行 spec の確定事項）。
- ソースへの正典出典注記（`areka-P0-ukadoc-survey-sakura-script` の領分）。

## Upstream / Downstream

- **Upstream**:
  - `areka-P0-sakura-bare-tag-lexer`（**先行必須**）——同じ `scan_tag` の角括弧なし経路を確定済み。本 spec はその上に積む。
  - 完了済み `areka-P0-sakura-parse`——違反している契約（R13.1）の出所。アーカイブ済みゆえ非改変とし、穴があった事実を本 spec 側に登記する。
- **Downstream**:
  - `areka-P0-ukadoc-survey-sakura-script`——タグ語彙の正本を生む。案 A（語彙表）へ進むならその後。
  - `areka-P0-property-query-channels`・`areka-P0-text-decoration-canon`——同じ字句・意味写像へ後から触れる。

## Existing Spec Touchpoints

- **Extends**: なし（`areka-P0-sakura-parse` は完了アーカイブ済みで拡張不能。契約の穴は本 spec が引き取る）。
- **Adjacent**:
  - `areka-P0-sakura-bare-tag-lexer`（同一関数・先行着地）
  - `areka-P0-ukadoc-survey-sakura-script`（タグ語彙の網羅・案 A の上流）
  - `areka-P0-anchor-tag-canon`・`areka-P0-sakura-time-directives`（`\_a`／`\_q` の意味付け所有・本 spec は触れない）

## Constraints

- **M1 の適合判定には影響しない**——emo2 は本欠陥に触れないため、M1 完成のブロッカーではない。互換品質の項目として位置づける。ただし発現時の壊れ方は重い（話者取り違え・本文消失）。
- 公開契約 `parse(&str) -> Vec<Instruction>` の形と意味を変えない。
- 依存方向 `model ← lexer ← decode ← parse` を維持する（`lexer` から `decode` への上向き import を作らない）。既知タグ集合を字句層が参照する形をどう作るかが設計の主要論点。
- 決定論テストのみ（`#[test]`・時計／GPU／実機非依存）。実機検証へ回さない。
- 触れるファイルは 1,000 行未満に保つ。
