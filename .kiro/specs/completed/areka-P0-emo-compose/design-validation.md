## Critical Issues

### 🔴 Critical Issue 1: parser 構造体へのフィールド追加はソース破壊的 —「既存テスト不変」の主張と矛盾

- **Concern**: design は `Shell`（`definitions`/`animation_sort`/`collision_sort`）・`Surface`（`targets`）・`SurfaceAppend`（`elements`）へ公開フィールドを追加しつつ「既存テストは不変」「emo-atlas の SurfaceSet 消費は不変」と主張する。しかしこれらは `#[non_exhaustive]` でない全公開フィールド struct であり、構造体リテラル構築箇所は**全てコンパイル不能になる**。実測: parsers 自身のテスト（validation_tests.rs L85-86/186・decode_tests.rs L25/40/57/100・parse_tests.rs L22/91-92/120・model_tests.rs L98/123-124/152）＋ **emo-atlas 側**（emo2_e2e.rs L66/290・manifest.rs L150・lib.rs L203）の約20箇所。
- **Impact**: 要件 12.5 の shall「既存の転記契約・parser テストを壊さない（emo-atlas の SurfaceSet 消費との互換は design で担保）」を文字通りには満たせず、実装者が無設計の判断（Default 導入か・リテラル機械更新か・完了済み emo-atlas への侵襲可否）を迫られる。
- **Suggestion**: 互換機構を design/tasks で明示せよ——(a)「非破壊」の定義を「公開読取契約・アサーション意味・実行時挙動の不変」と明文化し、リテラル構築箇所の機械的追随（`targets: vec![AppendTarget::Single(id)]` 等）を許容範囲として列挙する、または (b) 3 struct へ `Default` 実装＋`..Default::default()` 追随／コンストラクタ関数の提供を仕様化する。完了済み `areka-emo-atlas` テストヘルパ4箇所への追随修正が 12.5 の許容範囲であることをディスカッションで確認すること。
- **Traceability**: 要件 12.5（既存契約・テスト非破壊）・2.5・1.6・1.7
- **Evidence**: design.md「Modified Files」「areka-parsers::shell — 転記層拡張 ▸ State」「Implementation Notes ▸ Risks」（`Surface.id` の意味拡張のみ記載・リテラル互換性は無記載）

### 🔴 Critical Issue 2: キャンバス外形の de-facto 規則が R6.5 の文言と乖離＋全透明 surface の Err 分類

- **Concern**: R6.5 は「合成結果のサイズを base surface 原寸とし」と shall で定めるが、design は「原点(0,0)固定・全描画層の `offset+original` の和集合」へ再解釈する（element が element0 の外形を超えると原寸を超え得る）。加えて「命令 0 件 → `Err(EmptyComposition)`」の規則は、**全 element が placement None（＝正当な全透明 surface・6.3 の正常系）**の場合や空 BindSet の bind-only surface も error 扱いにし、6.3「正常系スキップ・ログ不要」と分類が衝突する。
- **Impact**: emo2 では差が出ないが、requirements の shall と実装規則の乖離が黙示のまま実装に入ると、将来の実ゴーストで golden/挙動不一致の火種になる。全透明正常系を `error!`＋Err にするとログ規律（10.5 は「失敗」への error）とも整合しない。
- **Suggestion**: design ディスカッションで (a) 6.5 の文言に対する「和集合外形」再解釈を明示承認（または base=element0 外形へのクリップに規則変更）し、(b) 「surface は存在するが描画可能層ゼロ」を失敗（Err）でなく「原寸（または外形）どおりの全透明 `ComposedSurface` 正常返却」とするかを裁定してテストで固定する。
- **Traceability**: 要件 6.5・6.3・10.5・5.4
- **Evidence**: design.md「PlanBuilder ▸ キャンバス外形（6.5 の解釈・de-facto 決定）」「Error Handling ▸ 描画可能層ゼロ＝Err(EmptyComposition)」「8.3 Design Decisions ▸ キャンバス外形」

## Design Strengths

1. **上流契約の実シンボル忠実性**: `AtlasTable::{resolve, entry, page}`・`Placement{page, uv_rect, trim_offset}`・`AtlasEntry.placement: Option<Placement>`（None=転写スキップ）・`AtlasPage{width, height, stride, bytes: Arc<[u8]>}` を table.rs の実定義どおり消費し再定義ゼロ。parser 4ギャップも decode.rs の実破損行（L127/L87）まで特定した上での最小拡張で、`DefRef` index 参照ストリーム（データ複製なし）は非破壊性への配慮が周到。MemoryDecoder＋bake の COM 非依存テスト経路も実在資産に立脚。
