### `\![move,-353,,,0,base,base]` の意味論解読（両 DPI で厳密一致）
エモの観測中心 X（=L+W/2）が次式で両 DPI とも**誤差 0** で説明できる:
```
エモ中心X = (work_right − 217k) − 353     ※k=DPI/96、217 = surface0幅434の半分
  DPI 96 : (2880−217) −353 = 2310 = 2142+168 ✓
  DPI 192: (2880−434) −353 = 2093 = 1757+336 ✓
```
読み: 基準 = scope0 の**ロード時既定基準点**（代表面 surface0 (434k) を右端密着に置いたときの足元中央）。オフセット **−353 は DPI スケールされず物理 px のまま適用**される。
- ⇒ 開発者所見「SSP の座標補正は 100% でしか正しく動かない」の精密化: **窓寸は k 倍される（シェルサイズは 200% ✓）が、スクリプト座標（move オフセット）は無スケール**。96 前提で書かれたゴーストの move は高 DPI で幾何が崩れる（今回の 313px 重なりの正体）。
- 96 では既定配置と move 着地が**厳密に同値**（中心間距離 353）——ゴースト作者が 96 の既定値を move に焼き込んだと解される（emo-gs 忠実）。

## R1 実測オラクル 最終結論（要件 R1.1〜R1.6 充足）
1. **確定規則（H1）**: 複数スコープの既定 X 連鎖は「前スコープ左端から**自分の幅**を引く」＝完全隣接・gap 0。Y は各スコープ work area 下端密着。scope0 は work area 右端密着（defaultx=0）。
2. **R1.5 判定**: 現行実装式（前スコープの幅を引く・resolver.rs:155-158）は SSP 実挙動と**不一致**（幅差ぶんの隙間を生む・全観測で棄却）。
3. **不変量の範囲**: 規則は物理 px で DPI 不変（k=1, k=2 で厳密確認・丸め余地なし）。SSP のコールドブート定常値は規則出力に「起動レース（代表面寸で配置→合成面へ右端固定縮小）」と「ゴースト演出 move（物理px無スケール適用）」の 2 汚染が乗った合成値であり、**受理オラクルは規則そのもの**とする（レース・move 汚染は互換対象外＝別層の SSP 自己不整合として記録）。
4. **要件への波及（ディスカッション対象）**: R2.3/R6.4 の「実 DPI で SSP 実測オラクルと一致」は「規則（隣接 gap 0）を areka の実表示寸で適用した期待値と一致」と読むべき。SSP コールドブート定常値との直接比較はレース汚染ごと模倣する誤り。
