# 実機の確かめ（stay-on-top-directives・タスク 7.1・7.2・要件 8.1〜8.4）

常に手前のオン・オフ、手前へ出す `\v`、常に手前の状態の寿命（シェルの切り替えでは残り、ゴーストの切り替えでは捨てる）を、本物の窓で確かめる。あわせて、設計が寄りかからないようにした OS の性質 R1〜R3 と、裏のプロセスから `HWND_TOP` で手前へ出せるかを測って残す。1〜3 節（タスク 7.1）の判定は、窓の重なりの順と `WS_EX_TOPMOST` を読んで機械的に出し、開発者の目視は使わない。4 節（タスク 7.2）の重なりの順だけは、ぱすたの手順書のとおり開発者が目視で決める。

## 1. 手順

### 1.1 道具

- ハーネス: `crates/areka/tests/stay_on_top_real_run.rs`（`real-run-kit` で起こす・既定 OFF）。環境変数 `AREKA_STAY_ON_TOP_REAL_RUN` が空でないときだけ走り、無ければ即 return する
- 検体: emo2（`SampleRoot::acquire("emo2")`）。根は作業ツリーの `target\sot-signoff\root\` に作る
  - シェルの写し `shell\copy`（名 `copy`・`add_shell_copy`）を足す（シェルの切り替えの先）
  - ゴーストの写し `ghost\emo2b`（`descript.txt` の名を `emo2b` に替える）を足す（ゴーストの切り替えの先）
  - 記憶の置き場は `target\sot-signoff\profile\`（開発者の記憶は読まず・書かない）。根は絶対パスで、`\\?\` を付けない
- 「他のアプリの窓」: 試験のプロセスが専用のスレッドで作る普通の窓（題名 `stay-on-top other app`・`WS_OVERLAPPEDWINDOW`）。ゴーストの見えている窓を全部覆う大きさで出し、メッセージを回し続ける。前に出すのは、利用者と同じくクリックで行う。`SetWindowPos(HWND_TOP, SWP_NOACTIVATE)` に続けて、他のアプリの窓の左の縁の中ほど（ゴーストの見えている窓の外・`WindowFromPoint` がその窓になる点）を `SendInput` で左クリックする。点がその窓にならなければクリックせず、`steps.txt` に `clicked=false` を残す（4 回目は `HWND_TOP` だけでは並びが変わらなかった・2d 節）
- 重なりの読み: `GetTopWindow(NULL)` から `GW_HWNDNEXT` で全部の最上位の窓を辿った順位（0 が最も手前）・`GWL_EXSTYLE` の `WS_EX_TOPMOST`・`GW_OWNER`・`IsWindowVisible`
- 窓の分け方: 記録の `[zorder-pair] owner-established` の行（`owned_hwnd`→`owner_hwnd`）だけで、持たれる窓をバルーン、持ち主をキャラクターとする。`GW_OWNER` は使わない。組の鎖ではキャラクターが相手のバルーンに持たれ、IME の窓（`Default IME`）もキャラクターに持たれるので、`GW_OWNER` で分けると取り違える（1 回目の走りの 3 節）。帯の働きの的は、キャラクターとバルーンの全部（隠れた窓も含む）
- ドラッグ: `SendInput`（computer-use の覆いの窓がマウスの動きを吸うので使わない）。押す点は、キャラクターの窓の矩形の 9×9 の格子から中心に近い順に選ぶ。点ごとにカーソルを乗せて 300 ms 待ち、`WindowFromPoint` がその窓になった最初の点を使う（areka はカーソルの無い所で窓を透ける形にするため）
- 台本: MCP の `sakurascript`。話している最中で断られたら 1 秒ごとに送り直す（最大 15 回）
- `RUST_LOG=info,kanade=debug,areka::emo2_boot::window_state_cue=debug,areka::emo2_boot::zorder_cue=debug,areka::emo2_boot::frame::window_state=debug,areka::emo2_boot::frame::zorder_drain=debug,areka::emo2_boot::frame::zorder_descript=debug,areka::emo2_boot::frame::switch=debug,wintf::ecs::window=debug`（受け口の読み飛ばし・状態の変化・帯の働き `[window_band]`・組の確立と是正・シェルの切り替えで組を保った行 `log_group_applied` が出る水準）
- 保険の自動終了は 300 秒。終わりはハーネスが利用者と同じ閉じ方で閉じる
- 記録: `target\sot-signoff\judgments.txt`（判定）・`steps.txt`（手順・送った台本と返事・各時点の重なりの表）・`run.log`（areka の標準出力と標準エラー）

### 1.2 前に確かめること

1. 排他テストの机を持っている。入力の机に画面のロックもスクリーンセーバーも無い（ハーネスも、areka を起こす前に `SPI_GETSCREENSAVERRUNNING` と `GetForegroundWindow` を読み、スクリーンセーバーが動いているか入力先の窓が無ければ、無効な走りとして止める）
2. 127.0.0.1:9276 を他が握っていない（`netstat -ano | findstr :9276` が空）。握っていれば走らせず、持ち主のセッションに降ろしてもらう
3. 32bit の仲介を建ててある: `cargo build -p shiori-host32-helper --target i686-pc-windows-msvc`
4. 確かめの間は拡大率とモニタの構成を変えない
