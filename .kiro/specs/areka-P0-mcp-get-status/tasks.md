# Implementation Plan

> 設計は `design.md`、決定は `research.md` 8 節。並走の約束（kanade の `schedule/`・`lib.rs`、MCP の `mod.rs`・`handler.rs` に触らない）はどのタスクでも守る。

- [x] 1. kanade に「今の状態」を問う口を作る
- [x] 1.1 kanade が問い合わせの知らせを受けて、今の実行の状態をその場で返す
  - kanade への知らせに「今の状態を教えて」を 1 種足し、返信の口を持たせる。知らせの種類を網羅して確かめている既存のテストにも、その種類を 1 つ足す
  - 殻はこの知らせを、資源の問い合わせと同じ位置（通信中の写しを更新した後・運行を進める前）で受け、SHIORI へ送る要求の `Status` と同じ作り方で値を作って返し、運行を 1 歩も進めずに次の知らせへ戻る
  - 返信の型は語の列を持つ実行の状態そのもの（`ExecutionStatus`。文字列に直さない）とし、振り分けの腕と答える関数は殻のファイルに直に置く（`actor_status.rs` は作らない＝設計の決定 1・4。brief の古いファイル案に従わない）
  - 返信の相手が既に居なければ、黙って捨てる（記録は debug まで）
  - kanade の crate のビルドと既存のテストが緑のまま通り、触ったファイルが知らせの定義と殻の振り分けの 2 つだけである
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 4.1, 4.2_

- [x] 1.2 kanade が問い合わせに正しく答え、運行を変えないことを統合テストで固定する
  - 共通の土台（再生の完了を保留できる偽の sakura・`Status` つきで呼出を記録する偽の shiori）で、起動の前・起動直後・中断の無効化の知らせ（再生の前後）・バルーンの知らせ・再生中・選択待ちの各場面に進め、それぞれで問い合わせた値を確かめる
  - 再生中と選択待ちで、問い合わせの答えと、次の周期の要求に付く `Status` が一字違わず同じことを確かめる
  - 同じ所で続けて 2 回問うと同じ値が返り、筋書きの終わりまで走らせても偽の shiori・偽の sakura が受けた列が問い合わせを挟まない場合と同じで、選択待ちの後の選択のイベントも届くことを確かめる
  - 終了の知らせの直後に送った問い合わせは、受信箱ごと落ちて「返信端が落ちた」で終わることを確かめる
  - 統合テストの束ねに宣言を 1 行足し、新しい統合テストのファイルの 4 本（K1〜K4）が緑になる
  - 触るのは新しい統合テストのファイルと束ねの宣言 1 行だけで、共通の土台（`common/`）は 0 行
  - _Requirements: 1.2, 1.4, 1.5, 2.1, 2.2, 2.3, 2.5, 3.2, 4.1, 4.2, 5.1, 5.3_
  - _Depends: 1.1_

- [x] 2. MCP の `get_status` を本物にする
- [x] 2.1 (P) `get_status` が宛先のゴーストの kanade へ問い合わせ、後から答える口で返事を待つ
  - 宛先の解決は既存のまま使い、その失敗の文言を「降りた」の答えとして取っておく
  - ゴーストの置き場から kanade の送り口を引き、無ければ `NG:Status is not available`・`isError: true` で答えて warn を 1 件残す
  - 送れなかったとき、返事の前に返信端が落ちたときは、宛先の解決の失敗と同じ文言・`isError: true` で答え、記録は debug まで
  - 届いた値は語の列をそのまま本文にし（値なしは空の本文）、`isError: false`・content は本文 1 つで返す。UI スレッドは返事を待たず、毎フレーム覗くだけにする
  - ダミーを固定していたテスト（`not implemented yet` を見るもの）はこの書き換えで赤になるので、同じタスクで消す
  - `not implemented yet` を返す経路が `get_status` から消え、areka の crate がビルドでき、`mcp_tests.rs` と `get_status` の兄弟テストの既存のテストが緑のまま
  - _Requirements: 1.1, 1.3, 1.6, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 4.3, 4.4, 5.4_
  - _Depends: 1.1_
  - _Boundary: MCP の get_status（kanade の統合テスト 1.2 とファイルを共有しない）_

- [x] 2.2 MCP の側の答えを決定論テストに固定する（ダミーのテストを書き換える）

  - 呼んだ直後は答えがまだ無く、預けた組が 1 つ、偽の受信端に届いた知らせが問い合わせ 1 通だけで、成功の枝で warn 以上が 0 件であることを見る
  - 置き場に問い合わせ先が無い場面で、`NG:Status is not available`・`isError: true`・warn がちょうど 1 件・error が 0 件であることを見る
  - MCP の側のテスト M1〜M5 が緑になり、`mcp_tests.rs` の既存のテストも緑のまま
