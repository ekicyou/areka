# Implementation Plan

> 設計は [design.md](design.md)。コードの名前は design.md の Components の節に従う。触るファイルは design.md「File Structure Plan」の一覧の内だけで、`crates/areka/src/mcp/mod.rs`・`crates/log-capture-kit/`・`crates/areka-emo-text/src/lib.rs` には触らない（触る要が出たら止めて報告する）。

- [x] 1. 文字の層に待たない読み戻しを足す
- [x] 1.1 (P) 文字の面の写しを積む口と、待たずに読む口を足す
  - 呼び出しごとに CPU で読める写し先を作り、今の front 面の写しを積んで GPU へ送る口を足す。GPU の終わりは待たない
  - 写し先を待たずに開く口を足す。GPU がまだ使っていれば「まだ」を返し、開けたら密な BGRA の配列へ行ごとに写して閉じる。開いたまま戻らない
  - 2 つの口は記録を出さず、失敗を返すだけにする（例外であることを文書注釈に書く）。写し先の作り方と行ごとの写しは今の読み戻しと共用し、今の読み戻しの結果と記録の出し方は変えない
  - 「まだ」と失敗の分かれ目の判定、および「積んだ後に front 面を描き替えても、積んだ時点の模様が全バイト一致で読める」ことを、文字の層のテスト（WARP 可）で固定する
  - 文字の層のテストが緑で、`surface.rs` が 1,000 行を超えない
  - _Requirements: 1.2, 1.3, 1.5_
  - _Boundary: areka-emo-text surface.rs_

- [ ] 2. 答え方の部品を作り直す（`dump_surface` の側）
- [x] 2.1 (P) 指定の surface の合成の結果から答えの種を作る関数を置き、届かない枝に専用の文言を与える
  - 合成の結果が「無い」ときは `NG:the shell of this scope is not ready` と `error!` 1 件で答える。成功と合成の失敗の振る舞いは今のまま
  - 「無い」を渡すと本文・`isError: true`・画像なし・ERROR 1 件になることを、記録を捕まえる決定論テストで固定する
  - _Requirements: 2.1, 7.1_
  - _Boundary: dump_surface.rs, dump_surface_tests.rs_
- [ ] 2.2 判断の文言を型で分ける
  - 判断の文言 4 つを、判断のモジュールの外から作れない型の定数にする。文言そのものは変えない
  - 判断の関数の失敗の型と、判断の失敗で答える関数の引数をその型にし、2 本のツールの呼び手を合わせる。想定外の失敗の関数は文字列のまま
  - 2.1 で届かない枝を専用の文言へ移した後に行う（今の届かない枝は判断の文言を想定外の失敗の関数へ渡しているので、先に型を変えると組み立てが落ちる）
  - 判断のテストの補助関数の型を合わせ、期待する値は変えない
  - 判断の文言を想定外の失敗の関数へそのまま渡す書き方が組み立てで落ち、今のテストがすべて緑
  - _Requirements: 2.2, 6.1, 6.2_
- [ ] 2.3 符号化のスレッドの起こし方と、その体・送り返しを分ける
  - 符号化のスレッドを起こし、起こし終えた後に UI スレッドの側の時間を測って、仕事・届け先・時間を手渡す関数を置く。起こせない・手渡しの前に消えたときは届け先へ想定外の失敗を 1 度だけ届ける
  - 符号化のスレッドの体は、仕事を panic を受けて走らせ、panic なら `NG:the encoding thread panicked` で答える。覗く関数の受け取り口へ送る関数は、受け取り口が無ければ黙って捨てる
  - 装着の後の `dump_surface` の今の答え方は、形を変えずに中身をこの関数へ寄せる（`ui_us` がスレッドを起こす時間を含むようになる）
  - 覗く関数の受け取り口へ送る関数は 2.4 まで本番の呼び手が無い（未使用の警告は 2.4 で消える）
  - 体の較正（panic する仕事・想定外の失敗を呼ぶ仕事は ERROR 1 件、成功する仕事は 0 件）、受け取り口の無い送りが panic も ERROR も出さないこと、`dump_surface` の成功の仕事を UI 時間 1,234 µs で通すと成功の記録が 1 件で `ui_us` が 1234・`encode_us` が数として読めることを決定論テストで固定する
  - _Requirements: 3.3, 3.4, 3.5, 5.1, 5.2, 5.3, 7.1_
- [ ] 2.4 1 フレームで済まない仕事を覗く関数の状態にまとめ、2 本の入口を共通にする
  - UI スレッドで符号化まで仕上げる今の口を消す（読み出し待ちの腕と段は 3.3 で足す）
  - 覗く関数の状態を「装着待ち・符号化待ち」の 2 段で持ち、どの段も待たずに 1 フレームで進められるだけ進める。装着待ちの覗きの入口でだけ、呼び出しを解決したゴースト（名前とルートフォルダ）と今のゴーストを比べ、違えば `NG:Specified ghost is not active` と `debug!` で答える
  - 1 フレームごとの UI スレッドの時間の最大を持ち、最初の覗きには入口で使った時間を足して、符号化のスレッドへ手渡す
  - 2 本のツールの入口を共通の入口の 1 行にする（`dump_balloon` はこの時点では今どおり写しまで済んだ種を返す）
  - 今の決定論テストと GPU を通るテストがすべて緑（装着の前に預けた呼び出しが絵を返すテストを含む）。ゴーストの確かめと符号化待ちの段は 2.5 で、読み出し待ちの段は 4.1 で固定する
  - _Requirements: 1.1, 1.4, 1.6, 3.1, 3.2, 4.1, 4.2, 4.4, 4.5, 5.3, 6.1, 6.2_
- [ ] 2.5 窓の無い切り替えの道具で、預けた呼び出しの振る舞いを固定する
  - 装着の前に預けた呼び出しの符号化が `mcp-encode` のスレッドで行われ、預けた巡の中では答えないことを固定する
  - 同じ形で仕事が panic すると `NG:the encoding thread panicked` になることを固定し、その答えを「画像つきの成功か」の判定の関数に通すと偽、1×1 の絵の仕事では真になることで判定の関数を較正する（判定の関数は GPU のテストからも使える置き場に置く）
  - 符号化待ちのまま待つ側を落とすと置き場の組が 0 件になり、その後に仕事を放しても UI スレッドの ERROR が 0 件で panic しないことを固定する
  - 台本の `\![change,ghost,B]` で本物の切り替えを通し、預けた呼び出しが `NG:Specified ghost is not active`・`isError: true` で答え、`[mcp]` の ERROR が無いことを固定する。`\![change,ghost,A]` の起こし直しでは答えが届かない（まだ装着待ち）ことも固定する
  - 5 本のテストがすべて緑
  - _Requirements: 3.1, 3.2, 3.3, 3.5, 4.1, 4.2, 4.4, 5.1, 5.2, 7.1_

- [ ] 3. `dump_balloon` を待たない読み戻しへ移す
- [ ] 3.1 既存の `dump_balloon` の成功のテストの待ち方を替える
  - GPU のテストの道具に「台詞の時計を止めたままフレームを回して答えを待つ」口を足し、既存の `dump_balloon` の成功を待つテストをその口に替える。期待する値は変えない
  - 今の同期の答えでも使える口なので、待ち方を替えた既存の GPU を通るテストがすべて緑（3.3 で答えが後のフレームになっても待ち方を替えずに済む）
  - _Requirements: 6.2_
- [ ] 3.2 背景と文字を重ねて符号化する仕事を 1 つの関数にまとめる
  - 文字の面がある・ないの両方の腕で同じ関数を使う。仕事の中身（重ね合わせ・PNG・base64・成功の記録の欄）は今のまま
  - 文字の層なし・1×1 の仕事を UI 時間 1,234 µs で符号化のスレッドの体に通すと、成功の記録が 1 件で `ui_us` が 1234・`encode_us` が数として読めることを決定論テストで固定する
  - _Requirements: 5.3, 6.1, 7.1_
- [ ] 3.3 文字の面の写しを積んで、読み出しを待つ種を返す
  - 答えの種に「文字の面の読み出しを待つ」腕を、覗く関数の状態に読み出し待ちの段を足す（読み出しの口を 1 度呼び、まだなら待ち、失敗なら答え、読めたら符号化待ちへ）
  - 文字の面があるとき、今の読み戻しの代わりに写しを積む口を使い、積めなければ想定外の失敗で答える
  - 読み出しを待つ口は、覗かれるたびに待たずに読み、「まだ」なら待ち、失敗なら想定外の失敗（`error!` 1 件）、読めた大きさが合わなければ `NG:picture size mismatch`、合えば 3.2 の仕事を返す
  - 装着の後の `dump_surface` の答え方へ読み出し待ちの種が渡されたときは、黙らせず `fail(tool, scope, "the text read was handed to the wrong path")` で答える
  - 判断・背景の写し・文字の領域の取り出し・面の大きさの検査は今のまま
  - `dump_balloon` の成功が、呼び出しを受けたフレームより後のフレームで届くようになり、`dump_balloon` の UI スレッドから GPU の終わりを待つ呼び出しが無くなる
  - 今の決定論テストと GPU を通るテスト（3.1 で待ち方を替えた `dump_balloon` の成功のテストを含む）がすべて緑で、`dump_balloon.rs` に今の読み戻しの呼び出しが残っていない
  - _Depends: 1.1, 3.2_
  - _Requirements: 1.1, 1.2, 1.3, 1.5_

- [ ] 4. GPU を通るテストと全体で固定する
- [ ] 4.1 呼び出しを受けた時点の絵と、符号化のスレッドの記録を GPU で固定する
  - 台詞 1 行を出した時点の背景と文字から期待の絵を作り、読み出しを待つ種を受け取った後、文字の面が期待と違うようになるまで台詞を進めてから読み、仕事を走らせた絵が期待と一致することを固定する
  - `dump_balloon` の本物の仕事と、`dump_surface` の写しまで済んだ本物の仕事を、記録を数える中で符号化のスレッドの体に通し、ERROR 0 件と画像つきの成功を固定する
  - 3 本のテストが緑で、台詞を進める前後で文字の面が実際に変わったことをテストの中で確かめている
  - _Requirements: 1.3, 5.1, 7.1_
- [ ] 4.2 全体の確かめ
  - `areka`・`areka-emo-text` のテストと clippy を回し、すべて緑・警告 0
  - 判断の文言が想定外の失敗の本文に使われていないこと、`mod.rs`・`log-capture-kit`・`areka-emo-text` の `lib.rs` に差分が無いことを、差分で確かめる
  - _Requirements: 2.2, 6.1, 6.2_
