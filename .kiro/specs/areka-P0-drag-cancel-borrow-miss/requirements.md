# Requirements Document

## Project Description (Input)
まれな条件で、キャラクターやバルーンのドラッグを取り消しても位置が保存されず、その直後に動かさずにクリックすると 1 回だけ位置が保存される。条件は、wintf が画面更新の処理の最中（窓や部品の状態をまとめて更新している間）に、OS から同期で届いたメッセージ（再入）を受けたときで、実機ではまだ見ておらず、ソースを読んで確かめたもの。wintf のキー・取り消し系の 4 つのハンドラ（ESC キー・メニューやダイアログの割り込み・マウスの捕捉の喪失・窓の非活性化）と、左ボタンを離したときのハンドラは、再入の最中だと wintf の ECS の世界（World）を使えず、ドラッグの終了の知らせの種を積まないまま、ドラッグの状態だけを休む状態へ移す。そのため、wndproc から ECS へ知らせを渡す箱（ドラッグの累積器）に「ドラッグ中の対象」が置き去りになり、(1) 閾値を越えたドラッグの取り消し・離しの終了の知らせが落ちる、(2) 次の動かさないクリックの終了の知らせが、`drag-click-without-move` で入れた「開始の知らせの無い終了は捨てる」判断を 1 回だけ通って位置が保存される、の 2 つが起こりうる。あわせて、左ボタンを離したときのハンドラは再入の最中だと「離した窓とドラッグの準備をしている窓の一致」を調べられず、ドラッグの準備の状態とマウスの捕捉が離した後も残り、その後ボタンを押さずに動かすとドラッグが始まりうる。再入の条件でも、取り消し・離しで「ドラッグ中の対象」が置き去りにならず、閾値を越えたドラッグの終わりは今どおり 1 件保存され、動かさないクリックはどの条件でも位置を保存しないようにする。1 フレーム遅らせる解は取らず、状態の持ち方を変えて 0 フレームで解き、直す前に赤になる決定論のテストを立てる。種別はバグ。

## Introduction

ドラッグの知らせには、完了 spec が決めた 2 つの約束がある。

- ドラッグの終了の知らせは、開始の知らせを配ったドラッグにだけ配る（完了 spec `areka-P0-drag-click-without-move` 要件 3）。
- 閾値を越えたドラッグは、離しても取り消しても終了の知らせを 1 回配り、利用者から見ると取り消しでもその時点の位置が保存される（同 spec 要件 2.5・3.3、完了 spec `event-drag-system` 要件 4・5）。

ところが、この 2 つは「ハンドラが wintf の ECS の世界（World）を使えること」を暗に前提にしている。wintf のハンドラは、ドラッグの累積器を World から取り出して終了の知らせの種を積む。画面更新の処理の最中に OS が同期でメッセージを送ってくる（本書ではこれを「再入」と呼ぶ）と World を使えず、ハンドラは種を積まずに先へ進む。ドラッグの状態は休む状態へ移るのに、累積器の側は「ドラッグ中の対象」を持ったまま残る。

利用者から見える症状は次のとおり（実機では未観測・ソースを読んで確かめたもの）。

- 閾値を越えて動かした後の取り消し・離しが再入で届くと、終了の知らせが落ち、位置が保存されない。ドラッグ中の印も窓に残る。
- その直後に動かさずにクリックすると、その終了の知らせが「開始の知らせの無い終了は捨てる」判断を 1 回だけ通り、位置が保存される。
- 閾値に届く前に左ボタンを離し、その離しが再入で届くと、ドラッグの準備の状態とマウスの捕捉が離した後も残る。その後ボタンを押さずにマウスを動かして閾値を越えると、ドラッグが始まり、窓がカーソルに付いて動きうる。

本 spec は、再入の条件でも上の 2 つの約束を守らせる。新しい約束は足さず、完了 spec の要件も上書きしない。brief は「閾値を越えたドラッグの取り消しは、この条件でも今どおり 1 件保存される（または、落とすならそれを決めて記録に残す）」としており、本書は主の案である「今どおり 1 件保存される」を採る。落とす案は、保存されない位置が利用者に見えて残るうえ、「状態の持ち方を変えて 0 フレームで解く」という制約で解けるため取らない。

## Boundary Context

- **In scope**:
  - wintf のキー・取り消し系の 4 つのハンドラ（ESC キー・メニューやダイアログの割り込み・マウスの捕捉の喪失・窓の非活性化）と、左ボタンを離したときのハンドラが、再入で World を使えないときの、終了の知らせの種と「ドラッグ中の対象」の扱い。
  - 左ボタンを離したときのハンドラが再入で World を使えないときに、ドラッグの準備の状態とマウスの捕捉が残る穴（再測定で見つけたもの・同じ「World を使えないときの扱い」の話として本 spec に入れる）。
  - 決定論の自動テストと、ふつうの条件での振る舞いが変わっていないことの実機での確かめ。
- **Out of scope**:
  - ESC キー・メニューやダイアログの割り込みを受け取った窓と、ドラッグ中の窓の一致を確かめない件（完了 spec `areka-P0-drag-click-without-move` の調査で範囲の外と記したもの）。
  - 左ボタンを押したとき・マウスを動かしたときのメッセージが再入で届いた場合の今の扱い（ドラッグの準備に入らない・閾値と比べない）。これは状態を置き去りにしないので変えない。
  - ドラッグの状態機械の移り変わり（押して準備 → 閾値で開始 → 離すか取り消しで休む）、ドラッグの閾値の値、ドラッグ中の窓とバルーンの追従。
  - areka のキャラクターとバルーンのドラッグの終了の受け手、位置の記憶の形式と保存先、受け手の縮退（開始時の記録が先に落ちたときの扱い）。
  - 同じウェーブの他の spec との約束により、触るのは wintf の `crates/wintf/src/ecs/` の下のハンドラ（キー・取り消し系、マウスのボタン）・ドラッグの部分・World を組み立てる所の 1 行と、それぞれのテストだけとする。
- **Adjacent expectations**:
  - areka のキャラクターとバルーンのドラッグの終了の受け手は、wintf の終了の知らせを受けて位置を保存する。本 spec は受け手を変えず、受け手へ届く知らせを、再入の有無に関わらず同じにすることで、利用者から見た保存の振る舞いを揃える。
  - ドラッグの状態が離した後に休む決まり（完了 spec `areka-P0-wintf-drag-state-rest-contract`）と、右クリックメニューがドラッグの状態を読む作りは変えない。
  - `areka-P0-mouse-drag-events`（同じウェーブ）は wintf の開始・終了の知らせを使う側で、本 spec の修正の後も知らせの約束は同じなので、互いに待たない。

## Requirements

### Requirement 1: 再入の条件でも、閾値を越えたドラッグの終わりを落とさない

**Objective:** As a wintf を使う開発者, I want 閾値を越えたドラッグの取り消しや離しが再入で届いても、ふつうと同じ終了の知らせが届くこと, so that 終了の受け手がドラッグの終わりを取りこぼさず、窓をドラッグ中のまま扱い続けない

#### Acceptance Criteria

1. When 閾値を越えたドラッグ（開始の知らせを配ったもの）が ESC キー・メニューやダイアログの割り込み・マウスの捕捉の喪失・窓の非活性化のいずれかで取り消され、そのメッセージが再入で届いたとき, the wintf ドラッグ機能 shall 取り消しの印つきの終了の知らせを 1 回配る。
2. When 閾値を越えたドラッグで、ドラッグしている窓の上で左ボタンが離され、そのメッセージが再入で届いたとき, the wintf ドラッグ機能 shall 取り消しの印の無い終了の知らせを 1 回配る。
3. The wintf ドラッグ機能 shall 前 2 項の終了の知らせの中身（対象・位置・取り消しの印）を、同じ操作が再入でなく届いた場合と同じにする。位置は画面の座標とし、窓の中の座標と取り違えない。
4. The wintf ドラッグ機能 shall 前 2 項の終了の知らせを、同じ操作が再入でなく届いた場合と比べて遅らせずに配る（画面更新を 1 回余計に待たない）。
5. When 前 2 項の終了の知らせを配ったとき, the wintf ドラッグ機能 shall 再入でない場合と同じく、ドラッグ中の印（ドラッグの対象と、それを含む窓に付くもの）を外し、以後その窓をドラッグ中として扱わない。

### Requirement 2: 再入の後も、開始の知らせの無いドラッグには終了の知らせを配らない

**Objective:** As a wintf を使う開発者, I want 再入の後の動かさないクリックや取り消しが、終了の知らせを生まないこと, so that 終了の受け手が「本当にドラッグしたか」を自分で見分けなくてよい

#### Acceptance Criteria

1. When 再入で届いた取り消しまたは離しでドラッグが終わった後、利用者が左ボタンを押して閾値に届かないまま離したとき, the wintf ドラッグ機能 shall ドラッグの終了の知らせを配らない。
2. If 閾値に届く前のドラッグの準備が、ESC キー・メニューやダイアログの割り込み・マウスの捕捉の喪失・窓の非活性化のいずれかで取り消され、そのメッセージが再入で届いたとき, then the wintf ドラッグ機能 shall ドラッグの終了の知らせ（取り消しの印つきのものを含む）を配らない。
3. When 再入で届いた取り消しまたは離しでドラッグが終わった後、利用者が次に閾値を越えてドラッグして離したとき, the wintf ドラッグ機能 shall 開始の知らせを先に、終了の知らせを後に、どちらも 1 回ずつ、その新しいドラッグの対象について配る。

### Requirement 3: 離した後に、ドラッグの準備とマウスの捕捉を残さない

**Objective:** As a areka の利用者, I want ボタンを離した後は、どの条件でもドラッグが終わっていること, so that ボタンを押していないのに窓がカーソルに付いて動かない

#### Acceptance Criteria

1. When 閾値に届く前のドラッグの準備中、または閾値に届いた直後でまだ一度も動かしていないときに、ドラッグの準備をしている窓の上で左ボタンが離され、そのメッセージが再入で届いたとき, the wintf ドラッグ機能 shall 再入でない場合と同じく、ドラッグの状態を休む状態へ移し、マウスの捕捉を解放する。
2. If 左ボタンを離した窓が、ドラッグの準備またはドラッグをしている窓と違うとき, then the wintf ドラッグ機能 shall 再入の有無に関わらず、今の窓の一致の判断どおりそのドラッグを終えない。
3. While 左ボタンが押されていないとき, the wintf ドラッグ機能 shall マウスを動かしてもドラッグを始めず、開始の知らせを配らず、窓を動かさない（再入で届いた離しの後も同じ）。

### Requirement 4: 利用者から見た位置の保存を、再入の有無で変えない

**Objective:** As a areka の利用者, I want まれな条件でも、動かした位置は今どおり保存され、動かさないクリックでは保存されないこと, so that 次の起動で、意図して動かした窓が戻らず、意図せず動いた窓も残らない

#### Acceptance Criteria

1. When 利用者がキャラクターまたはバルーンを閾値を越えて動かした後に ESC キーなどで取り消し、その取り消しが再入で届いたとき, the areka shall 再入でない場合と同じく、その時点の位置を記憶へ 1 件書く。
2. When 利用者がキャラクターまたはバルーンを閾値を越えて動かして離し、その離しが再入で届いたとき, the areka shall 再入でない場合と同じ最終位置へ窓を置き、その位置を記憶へ 1 件書く。
3. When 前 2 項のいずれかの後に、利用者がキャラクターまたはバルーンを動かさずにクリックしたとき, the areka shall 窓の位置とバルーンの相対位置を記憶へ書かない（位置の保存の記録は 0 件）。

### Requirement 5: ふつうの条件での振る舞いを変えない

**Objective:** As a wintf を使う開発者, I want 再入でない、ふつうの条件での知らせとドラッグの振る舞いが修正の前と同じであること, so that 修正がまれな条件の穴埋めにとどまり、ふだんの操作に影響しない

#### Acceptance Criteria

1. The wintf ドラッグ機能 shall 再入でない条件での開始・終了の知らせの配り方（配るかどうか・中身・順・時機）を、本 spec の修正によって変えない。
2. The wintf ドラッグ機能 shall 再入でない条件での、ドラッグの状態の移り変わり、ドラッグの閾値の値、ドラッグ中の窓とバルーンの追従、離したときと取り消したときのマウスの捕捉の解放を、本 spec の修正によって変えない。
3. The wintf ドラッグ機能 shall 左ボタンを押したとき・マウスを動かしたときのメッセージが再入で届いた場合の今の扱い（ドラッグの準備に入らない・閾値と比べない）を、本 spec の修正によって変えない。

### Requirement 6: 再入で情報を読めなかったことを黙って捨てない

**Objective:** As a 開発チーム, I want 再入のためにハンドラがドラッグの扱いに要る情報を読めなかったことが記録に残ること, so that 実機で再入が起きたとき、記録から気付ける

#### Acceptance Criteria

1. If ハンドラが再入のために、ドラッグの扱いに要る情報（窓の位置・窓の一致など）を読めなかったとき, then the wintf ドラッグ機能 shall 何を読めなかったか（メッセージの種類・ドラッグの対象）を記録に 1 行残し、黙って先へ進まない。

### Requirement 7: 検証

**Objective:** As a 開発チーム, I want 穴が塞がったことと、ふつうの条件の振る舞いが崩れていないことを決定論のテストで示すこと, so that 同じ穴が再び入り込めば赤で気付ける

#### Acceptance Criteria

1. The 開発チーム shall 再入の状態（画面更新の処理の最中を再現し、ハンドラが World を使えない状態）を作って本物のハンドラへメッセージを渡し、本物の知らせを配る段を回す形の決定論の自動テストで、要件 1.1（4 種の取り消しのそれぞれ）・1.2・1.3・1.5・2.1・3.1・3.3 を確かめ、それらが修正の前に失敗し、修正の後に通ることを確かめる。
2. The 開発チーム shall 同じ形の決定論の自動テストで、要件 2.2・2.3・3.2 を確かめ、それらが修正の前後とも通ることを確かめる。
3. The 開発チーム shall 要件 1.4 を、再入で届いたメッセージの終了の知らせが、再入でない場合と同じ回の知らせを配る段で配られることとして、決定論の自動テストで確かめる。
4. The 開発チーム shall 要件 5.1・5.2 が崩れていないことを、既存または新しい決定論の自動テスト（完了 spec `areka-P0-drag-click-without-move`・`event-drag-system` のテストを含む）で確かめる。要件 4 は、要件 1・2 の終了の知らせのテストと、areka のキャラクターとバルーンのドラッグの終了の受け手の既存のテスト（終了の知らせ 1 件で保存 1 件・知らせ 0 件で保存 0 件）を合わせて確かめる。
5. The 開発チーム shall 前各項のテストを、注入した入力と画面更新の並びで駆動し、実時間の待機に依存させない。新しいテストは本番ファイルの兄弟ファイルへ置き、本番ファイル・テストファイルのどれも 1,000 行以下に保つ。
6. The 開発チーム shall 再入の条件そのものは実機で狙って起こせないため、その証拠を前各項の決定論のテストとし、実機ではふつうの条件で、閾値を越えたドラッグで保存 1 件、動かさないクリックで保存 0 件、閾値を越えた後の ESC キーの取り消しで今どおりの保存になることを確かめる。このとき記録の level を、位置の保存・ドラッグの終了の知らせ・要件 6.1 の記録まで開け、実機の根と一時フォルダはワークツリーの `target\` の下だけに置く。
7. Where 本 spec の修正が完了 spec の要件と食い違うことが判ったとき, the 開発チーム shall その上書きを `doc/COMPAT_ARCHITECTURE.md` §8 へ記録し、完了 spec のアーカイブ本体は書き換えない。
8. When 本 spec の完了を判定するとき, the 開発チーム shall ワークスペース全体のテストが緑であることを確かめる。
