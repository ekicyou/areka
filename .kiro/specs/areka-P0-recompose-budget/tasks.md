# Implementation Plan

> 段階ループ（design.md Flow 1）と 1:1 対応する。第 0 段（観測）と第 1 段（計測資産）は表示コードの挙動を変えない。是正（第 2 段）の着手順は第 1 段の実測が決める（3.2 のゲート）。

- [x] 1. 第0段: 観測基盤の導入（計時と確保計数・表示結果は不変）
- [x] 1.1 段階別計時の記録器とサマリ行の出力を新設
  - 1 回の表示適用について、キャッシュ照会・合成・リサンプル・当たり判定マスク生成・供給面転写・合計の所要を記録する器を表示層に置く
  - 行には段階別の所要に加え、適用対象の識別子・引き当ての可否・run 内で安定な合成キーのハッシュを持たせる（命中率とキャッシュ容量の裁定材料を後段が機械抽出できるようにする）
  - 計測は無条件に実行し、出力の有無のみログ水準のフィルタに委ねる（表示経路がログ設定で分岐しない）
  - 固定文言・全段フィールド常時出現（実行されなかった段は 0）・1 適用 1 行のスキーマで出力する
  - 観測可能な完了状態: 単体テストで、記録器が固定文言と全段フィールドを備えた行を 1 本生成し、実行されなかった段が 0 で出ることを確認できる
  - _Requirements: 1.1, 1.2, 1.5, 7.2_
  - _Boundary: FrameTiming_

- [x] 1.2 バッファ確保の計数シームを新設（席の再利用は第2段）
  - 毎フレーム経路の確保発生点（合成先・リサンプル先・リサンプル作業領域・当たり判定マスク）ごとのカウンタを持つ器を置く
  - 現時点では各発生点が確保のたびに計数する（是正後は同じシームが再利用の可否を計数する）
  - 適用単位の増分と累積の両方を露出し、増分は計時行のフィールドへ同居させる
  - 観測可能な完了状態: 単体テストで、確保が起きたときだけカウンタが増え、増分の取り出しでリセットされることを確認できる
  - _Requirements: 1.3_
  - _Boundary: FrameBudget_

- [x] 1.3 表示適用の毎フレーム経路へ計時点と計数を配線
  - 表示対象の状態に計数器の席を 1 つ持たせ、適用をまたいで存続させる（累積カウンタの所有者を確定する）
  - 各段の境界で所要を記録し、既存の表示成立点ログの直後に計時行を出力する
  - 早期復帰の経路では出力しない（成立点の対のみ）
  - 既存の表示成立点ログ（文言・水準・フィールド）と、面の入れ替えから供給面転写までの帯の分岐・呼出順序・エラー経路は変更しない
  - 観測可能な完了状態: 既存テストが全て通り、実走ログで表示成立行と計時行が同一適用の対として隣接して出る
  - _Requirements: 1.1, 1.3_
  - _Depends: 1.1, 1.2_

- [x] 1.4 計時ログの較正テストを追加
  - 計時行の固定文言・ログ水準・全段フィールドの出現を検証する
  - 既存の表示成立点ログの文言・水準・全フィールドが不変であることを同時に固定する
  - 「出ないこと」の主張は同一の捕捉スコープ内で陽性と陰性を対で観測する
  - 実時間を合否に使わず、純 x64 の常時テストに含める
  - 観測可能な完了状態: 計時行の文言やフィールドを 1 つ壊すと赤になり、既存の表示成立点ログを変えても赤になる
  - _Requirements: 1.4, 1.5, 6.2, 6.3_
  - _Depends: 1.3_

- [x] 2. 第1段: 計測資産の新設（リポジトリ共通の恒久置き場・製品コード非接触）
- [x] 2.1 (P) 有界実走と CPU 時系列採取のランナーを新設
  - 短時間（7 分程度）・長時間（20 分超）の 2 水準と、開発ビルド・リリースビルドの指定で実走を起動する
  - 静寂状態の明示確認がない場合は起動を拒否する（測定条件の保証を機械化する）
  - 実行ログ・CPU 時系列・実行条件（ビルド種別・水準・開始終了時刻・マシン識別）を 1 つの出力先へ収める
  - 起動失敗・カウンタ取得失敗は即エラー終了し、部分成果を残さない
  - 観測可能な完了状態: 1 コマンドで実走が有界終了し、出力先に実行ログと CPU 時系列と実行条件が揃う
  - _Requirements: 2.1, 2.3, 2.6, 2.7_
  - _Boundary: invoke-perf-run_

- [x] 2.2 (P) 集計モードを新設
  - 計時行から段階別 p50/p95・キャッシュ命中率・コマ適用間隔・確保計数を集計し、CPU 時系列から統計を出す
  - 進行境界スキップの件数は既存ログの実文言で数える
  - 必要なログ種の欠落・段フィールドの欠落は部分集計を出さずエラーとして報告する
  - 較正値（間隔の期待値・許容率・測定窓の定義・アイドル CPU 目標・文言一覧）をスクリプト冒頭に明記し、出力先頭にマシン条件を併記する
  - キャッシュ容量の裁定材料として合成キーの異なり数を集計する
  - 観測可能な完了状態: 実走ログと CPU 時系列を渡すと集計レポートが出て、段フィールドを 1 つ削ったログでは部分集計を出さずエラー終了する
  - _Requirements: 2.2, 2.5, 2.6, 4.5, 7.2_
  - _Boundary: judge-perf 集計_
  - _Depends: 1.1, 1.2_

- [x] 2.3 判定モードを追加
  - 合格判定式のうち間隔・進行境界スキップ・確保計数を両ビルドへ、アイドル CPU をリリースビルドのみへ適用する
  - CPU 時系列が頭打ちへ収束するか単調上昇を続けるかを機械判定し、収束判定の方法と閾値を較正値として明記する
  - 観測可能な完了状態: 合格・不合格・判定不能・引数不正が終了コードで区別され、判定根拠が較正値つきで出力される
  - _Requirements: 4.2, 4.3, 5.1, 5.3_
  - _Depends: 2.2_

- [x] 2.4 判定スクリプトの自己較正セットと手順書を用意
  - 合格・不合格・観測ゼロの 3 態を再現する既知ログ断片を用意し、期待どおりの終了コードを逐語再現する自己検査を持たせる
  - 手順書に 2 水準の使い分け（長時間はベースラインと最終判定のみ・中間の是正ループは短時間）・静寂確認の運用・同一手順再測の条件・較正値の所在・未知の機序を記録して独立課題として起票する手順を書く
  - 観測可能な完了状態: 自己検査が 3 態とも期待終了コードを逐語再現し、赤も必ず出る
  - _Requirements: 2.4, 2.6, 5.2_
