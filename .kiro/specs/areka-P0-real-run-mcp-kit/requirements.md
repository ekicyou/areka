# Requirements Document

## Project Description (Input)
開発者と AI のエージェントは、areka を本物の窓・GPU・SHIORI で立て、MCP で台本を流し、記録と絵を読んで確かめる「実機の試験」を書くたびに、同じ足場を一から組んでいる。今ある実機の試験 3 本（`crates/areka/tests/emo2_real_run.rs`・`mcp_get_log_real_run.rs`・`smoke_boot_loop_exit.rs`）は、それぞれが自分で検体の写しを取り、`areka.exe` の隣に 32bit の仲介（i686 の `shiori-host32-helper.exe`）を置き（同じ関数 `is_i686_pe`・`ensure_helper_beside_areka` が 2 本に写してある）、環境変数の組を書き（3 本で組がばらばら）、子の出力を読み（パイプとファイルが混ざる）、終わらせ方を自動終了（`AREKA_APP_SMOKE_EXIT_MS`）の残り時間に頼り、MCP を手書きの HTTP と JSON で呼んでいる。v0.1.0 で MCP のツールが揃っても、それを使う実機の試験を書くたびに同じ穴を踏む。SSP なら `--option readonly --sstp-listen 9900` で「干渉しない試験用の SSP」を 1 行で立て、MCP で回せる。

この spec は、実機の試験の共通の窓口を 1 つ作る。窓口は ⑴ `target\` の下の一時の根・一時の記憶の置き場・空いた MCP の番号で `areka.exe` を立て（32bit の仲介は自動で隣へ置き、開発者の環境変数は受け継がない）、⑵ 子の出力をファイルへ流して走りながら探し、⑶ MCP のツールを名前と引数で呼んで答えの文を受け取り、⑷ 利用者と同じ道（`OnClose`）で閉じて終了コードを返す。落ちた回は根と出力を消さずに残す。今の実機の試験 3 本をこの窓口へ移し、写した関数を 0 にする（試験の確かめの中身は変えない）。`startup-options-core` が着地した後は、環境変数の代わりに起動オプションでも立てられる作りにしておく。

## Introduction

実機の試験は、本物の `areka.exe` を子のプロセスとして起こし、その記録・MCP の答え・終了コードで振る舞いを確かめる。今は試験ごとに足場を書いているので、同じ不具合（パイプが詰まる・締切の残り時間に頼る・開発者の環境変数を持ち込む・後片付けが漏れる）が試験ごとに別々に起きる。

本 spec は、その足場を 1 つの窓口に集め、v0.1.0 で足される実機の試験（`mcp-kanade-tools`・`mcp-reload`・`mcp-strict-errors`・`pasta-in-windows-verification` ほか）がそれを使って短く書けるようにする。窓口は試験の側の道具であり、`areka.exe` の本番の振る舞いは変えない。

C9 のウェーブ編成（`roadmap.md`「ウェーブ編成」・棚卸㉗）で、窓口は `crates/` の下の新しいクレートに置くこと（`sample-ghost-kit` は使うだけ）、このウェーブの `Cargo.lock` の席を本 spec が使うこと（外の依存は足さない）、実機の試験 3 本は本 spec の持ち物であることが決まっている。

### 用語

- **窓口**: 本 spec が作る、実機の試験の共通の道具。
- **走り**: 窓口が `areka.exe` を 1 回立ててから終わるまで。
- **子**: 窓口が走りのために起こした `areka.exe` のプロセス。
- **回の置き場**: 走りごとに作る、その回だけの根・記憶の置き場・出力のファイルの置き場。どれもワークツリーの `target\` の下。
- **32bit の仲介**: `areka.exe` の隣に要る i686 の `shiori-host32-helper.exe`（32bit の SHIORI を読む）。
- **利用者と同じ閉じ方**: 利用者がゴーストの窓を閉じたとき（Alt+F4・メニューの「終了」）と同じ道。ゴーストへ `OnClose` が届き、別れの台詞の後で areka が自分で終わる。
- **保険の自動終了**: `AREKA_APP_SMOKE_EXIT_MS` による子の自動終了。窓口では、閉じ方が働かなかったときに子を残さないための締切としてだけ使う。

## Boundary Context

- **In scope**:
  - 窓口の 4 つの働き（立てる・出力を探す・MCP を呼ぶ・閉じる）
  - 32bit の仲介と、試験用の 32bit の成果物の揃え方の 1 本化
  - 空いた MCP の番号の取り方と、待受の始まりの観測
  - 落ちた回の証拠の残し方
  - 今の実機の試験 3 本の窓口への移し替え（確かめの中身は変えない）
  - 窓口そのものの決定論のテスト（偽の子と偽の MCP の受け口）
  - 使い方の説明（窓口の説明と `doc/` の試験の手引きの 1 節）
- **Out of scope**:
  - 新しい実機の試験を足すこと（各 spec が窓口を使って足す）
  - ぱすたの検体の取り寄せ（`sample-url-fetch`）
  - MCP のツールの中身（`mcp-kanade-tools`・`mcp-reload` ほか）
  - 起動オプション（`startup-options-core`・`readonly-mode`）
  - 排他テストの机の取り合い（`impl-watch-test-desk`）
  - 画面の入力（`SendInput`・computer-use）の足場
  - `emo2_real_run` の待ち方の直し（印を観測してから閉じる形への直しと、200% と 100% 相当での確かめ）＝`emo2-real-run-stability` の件 1。本 spec は同じ試験を窓口へ移し、閉じ方を用意するところまで
  - `areka.exe` の本番の振る舞い（終了の握手・MCP の受け口・記録の行）の変更
- **Adjacent expectations**:
  - areka 本体の起動の約束（`AREKA_ROOT`・`AREKA_PROFILE_DIR`・`AREKA_MCP_PORT`・`AREKA_NO_ALERT`・`AREKA_APP_SMOKE_EXIT_MS`・位置の引数）、MCP の待受を始めた／始められなかったことの記録の行、利用者と同じ閉じ方で `OnClose` を経て終了コード 0 で終わることは、今のまま使う。本 spec はこれらを変えない。
  - 検体の窓口（`sample-ghost-kit`）は使うだけで、このウェーブでは `crates/sample-ghost-kit/src/lib.rs` に触らない（同じウェーブの `sample-url-fetch` の持ち物）。
  - `startup-options-core`（同じウェーブ）は、後で `--sstp-listen`・`--option readonly` などの起動オプションを足す。窓口は今は環境変数で立て、着地の後に起動オプションへ移れるようにしておく（要件 8）。
  - `startup-options-core` と `mcp-kanade-tools` は、実機の試験 3 本に触らないと約束している。
  - `emo2-real-run-stability` の件 1 は、本 spec の閉じ方を使って `emo2_real_run` の待ち方を直す。
  - 実機の窓が出るので、負荷の走り（`areka-test-binary-stability`）と同じ時間に回さない。実機の試験を 1 本ずつ回す机は `impl-watch-test-desk` が持つ。

## Requirements

### Requirement 1: 走りを立てる

**Objective:** As a 実機の試験を書く人, I want 起動するゴーストを渡すだけで、開発者の環境に干渉しない areka を立てたい, so that 試験ごとに環境変数の組や置き場を書かずに済み、手元の設定に左右されない

#### Acceptance Criteria

1. The 窓口 shall 呼び手が次のどれかで起動するものを指定できるようにする: ⑴ 検体の名前（同梱バルーンのフォルダ名を添えてもよい・写しのゴーストのフォルダを起動するゴーストとして渡す）⑵ 任意のゴーストのフォルダ（バルーンのフォルダを添えてもよい）⑶ 根だけ（検体の写しの根でもよい・どのゴーストを起こすかは areka が根から決める）⑷ 何も渡さない（その回だけの空の根）。
2. When 呼び手が検体の名前で走りを立てようとしたとき, the 窓口 shall その検体の新しい写しを `target\` の下に取り、その写しを起動に使う。
3. The 窓口 shall 呼び手が子を起こす前に検体の写しの中身を書き換えられるようにする（例: 失敗方向の試験が SHIORI を試験用の DLL へ差し替える）。
4. The 窓口 shall 走りごとに回の置き場（呼び手が根を渡さないとき＝要件 1.1 の ⑴⑵⑷ はその回だけの空の根・その回だけの記憶の置き場・出力のファイル）を `target\` の下に新しく作る。
5. The 窓口 shall 開発者の環境の `AREKA_ROOT`・`AREKA_USER_ROOT`・`AREKA_PROFILE_DIR`・`AREKA_MCP_PORT` を子へ受け継がない。
6. Where 呼び手が根・記憶の置き場・任意の環境変数・任意の引数を明示したとき, the 窓口 shall 窓口の既定よりその値を優先して子へ渡す（記憶の置き場に普通のファイルを渡すような、わざと壊した値も含む）。
7. The 窓口 shall 既定で、告知のメッセージボックスを抑え、記録の着色を切り、保険の自動終了を付けて子を起こす。
8. The 窓口 shall 保険の自動終了の既定の時間を、窓口自身の待ちの締切の既定より短くする（窓口が締切で子を止めるより先に、子が自分で終わる）。
9. The 窓口 shall 子へ渡すパスを Windows の形の絶対パスにし、回の置き場のパスを短く保って、emo2 の実走（32bit の SHIORI の読み込み）が通る長さに収める。
10. If 子を起こせなかった場合（実行ファイルが無いなど）, then the 窓口 shall 実行ファイルの場所と理由を文に書いて試験を失敗させる。

### Requirement 2: 32bit の仲介と試験用の 32bit の成果物を揃える

**Objective:** As a 実機の試験を書く人, I want 32bit の仲介が `areka.exe` の隣に自動で揃ってほしい, so that 試験ごとに置き方を写さずに済み、x64 の仲介のせいで SHIORI の接続に落ちることが無い

#### Acceptance Criteria

1. When 走りを立てるとき, the 窓口 shall `areka.exe` の隣に 32bit（i686）の仲介が在ることを確かめ、無いか 32bit でないときは 32bit の仲介を置いてから子を起こす。
2. The 窓口 shall 仲介の元を、環境変数 `HOST32_HELPER_EXE` が指すファイル → `target\` の i686 の debug の成果物 → release の成果物の順に探す。
3. If 環境変数 `HOST32_HELPER_EXE` が指すファイルが無いか 32bit でない場合, then the 窓口 shall ほかの場所へ黙って移らず、指した値を添えて試験を失敗させる。
4. If どこにも 32bit の仲介が見つからない場合, then the 窓口 shall 建て方のコマンドを添えて試験を失敗させる。
5. The 窓口 shall 仲介以外の試験用の 32bit の成果物（例: 失敗方向の試験の SHIORI の DLL）を、呼び手が指定した場所へ、要件 2.1〜2.4 と同じ規則（隣が 32bit ならそのまま・環境変数 → debug → release の順・見つからなければ建て方を添えて失敗）で揃えられるようにする。
6. While 同じ試験のプロセスの中や別の試験のプロセスで、同時に仲介を揃えているとき, the 窓口 shall 書きかけのファイルを子に起動させない。

### Requirement 3: 子の出力をファイルへ流して探す

**Objective:** As a 実機の試験を書く人, I want 子が走っている間に記録の行を探して待ちたい, so that 決まった時間の眠りや締切の残り時間に頼らず、印が出た時点で次へ進める

#### Acceptance Criteria

1. The 窓口 shall 子の標準出力と標準エラーを、回の置き場の別々のファイルへ流す（出力の多さで子が止まらない）。
2. When 呼び手が文字列が出るのを待つよう求めたとき, the 窓口 shall 子が走っている間に出力を読み、その文字列が現れた時点で待ちを終える。
3. The 窓口 shall どの待ちにも締切を持たせ、呼び手が締切を指定しないときは窓口の既定の締切を使う。
4. If 締切までに待っていた文字列が現れない場合, then the 窓口 shall 待っていた文字列・待った時間・出力のファイルの場所・子の出力を文に書いて試験を失敗させる。
5. If 待っていた文字列が現れる前に子が終わった場合, then the 窓口 shall 締切を待たずに待ちを終え、子が終わったことと終了コードを、締切切れと見分けられる形で呼び手へ返す（例: モニタ 0 台で起動窓を開けずに終わった回を、呼び手が受理できる）。
6. The 窓口 shall 呼び手が標準出力だけ・標準エラーだけ・両方を合わせたものを、走りの途中でも終わった後でも読めるようにする。
7. The 窓口 shall 待ちの終わりを、出力・子の終了・MCP の答えの観測で決め、決まった時間だけ眠ってから進む形の待ちを持たない。

### Requirement 4: MCP のツールを呼ぶ

**Objective:** As a 実機の試験を書く人, I want MCP のツールを名前と引数だけで呼んで答えの文を受け取りたい, so that HTTP や JSON を試験ごとに手で書かずに済む

#### Acceptance Criteria

1. The 窓口 shall 走りごとに空いている MCP の番号を選んで子へ渡す。
2. When 呼び手がツールの名前と引数を渡して呼んだとき, the 窓口 shall その走りの子の MCP の受け口へそのツールを呼び、答えの文を返す。
3. When 呼び手が MCP を呼ぶとき、まだ子の待受の始まりを観測していないなら, the 窓口 shall 子の記録に待受を始めた行が現れるまで締切の内で待ってから呼ぶ。
4. While 呼び手が子の記録の段を絞っているとき（例: 警告より上だけを出す）, the 窓口 shall 待受の始まりを観測できる。
5. If 子の記録が待受を始められなかったことを示した場合, then the 窓口 shall 締切を待たずに、その記録の行と選んだ番号を添えて失敗を返す。
6. If 子がツールの失敗を答えた場合, then the 窓口 shall 呼び手が成功の答えと見分けられる形で、答えの文と一緒に返す。
7. If 受け口へつながらない・答えが読めない・呼び出しの締切を過ぎた場合, then the 窓口 shall つなぐ先と理由を添えて失敗を返す。
8. If 呼び出しの前か途中で子が終わった場合, then the 窓口 shall 締切を待たずに失敗を返し、子の終了コードを添える。
9. When 呼び手が答えに文字列が現れるまで呼び直すよう求めたとき, the 窓口 shall 締切の内で同じツールを呼び直し、その文字列を含む最初の答えを返す（締切までに現れなければ要件 3.4 と同じ形で失敗させ、途中で子が終われば要件 3.5 と同じ形で返す）。

### Requirement 5: 走りを閉じる

**Objective:** As a 実機の試験を書く人, I want 利用者と同じ閉じ方で子を終わらせて終了コードを受け取りたい, so that 自動終了の残り時間に頼らず、後片付けも areka 自身の終了の道を通る

#### Acceptance Criteria

1. When 呼び手が走りを閉じるよう求めたとき, the 窓口 shall 子へ利用者と同じ閉じ方の知らせを送り、子が `OnClose` を経て自分で終わるのを締切の内で待ち、終了コードを返す。
2. When 呼び手が子が自分で終わるのを待つよう求めたとき（自動終了や起動の失敗で終わることを確かめる試験）, the 窓口 shall 閉じる知らせを送らず、締切の内で子の終わりを待って終了コードを返す。
3. When 閉じるよう求めた走りが終わったとき, the 窓口 shall 子が利用者と同じ閉じ方で終わったのか、保険の自動終了で終わったのかを、呼び手が見分けられるように返す。
4. If 閉じる・終わりを待つ締切までに子が終わらない場合, then the 窓口 shall 窓口が起こした子だけを止め、締切切れであることと出力のファイルの場所・子の出力を文に書いて試験を失敗させる。
5. If 試験が走りを閉じないまま終わった・途中で失敗した場合, then the 窓口 shall 子を残さない（まず利用者と同じ閉じ方で閉じ、締切の内に終わらなければ窓口が起こした子だけを止める）。
6. The 窓口 shall 窓口が自分で起こしたと確かめられないプロセスを止めない（プロセスの名前や番号の決めつけで止めない）。

### Requirement 6: 落ちた回の証拠を残す

**Objective:** As a 実機の試験を書く人, I want 失敗した回の根と出力が消えずに残ってほしい, so that 後から同じ回を読んで原因を調べられる

#### Acceptance Criteria

1. If 試験が失敗した場合（窓口が失敗させたときも、呼び手の確かめが失敗したときも）, then the 窓口 shall その回の根・記憶の置き場・出力のファイル・検体の写しを消さずに残す。
2. When 回の置き場を残したとき, the 窓口 shall 残した場所を試験の出力に書く。
3. When 試験が成功で終わったとき, the 窓口 shall その回の置き場と検体の写しを消す。
4. The 窓口 shall 残す回の置き場を `target\` の下に限る。

### Requirement 7: 今の実機の試験 3 本の移し替え

**Objective:** As a 開発者, I want 今の実機の試験 3 本が窓口を使う形に揃ってほしい, so that 写した足場が無くなり、窓口が実物の試験で使えることを確かめられる

#### Acceptance Criteria

1. When 移し替えが終わったとき, the 実機の試験 3 本（`emo2_real_run.rs`・`mcp_get_log_real_run.rs`・`smoke_boot_loop_exit.rs`） shall 窓口を通して areka を立て、出力を読み、走りを終わらせる。
2. When 移し替えが終わったとき, the 実機の試験 3 本 shall 移し替えの前と同じ確かめを持つ: 終了コード（0 か非 0 か）・記録の行の有無と数・経路の目印（`route=` の欄）・`get_log` の答えの行の頭の形と番号の昇順と本文の照合・標準出力に出ないはずの行が出ていないこと・モニタ 0 台のときの受理。
3. When 移し替えが終わったとき, the 実機の試験 3 本 shall 32bit の判定・仲介と試験用の DLL の揃え方・空いた番号の取り方・子の起こし方と締切の見張り・MCP の要求の手書き・JSON の手書きの復号を、自分の中に持たない（写しが 0）。
4. The `smoke_boot_loop_exit.rs` shall 自動終了の道そのものを確かめる試験なので、子が自分で終わるのを待つ（要件 5.2）。
5. The `mcp_get_log_real_run.rs` shall 答えを得た後、自動終了を待たずに利用者と同じ閉じ方で閉じる（要件 5.1）。
6. The `emo2_real_run.rs` shall 今の終わり方（短い自動終了で子が自分で終わるのを待つ）を保つ（印を観測してから閉じる形への直しは `emo2-real-run-stability` の件 1）。
7. The 実機の試験 3 本 shall 走る条件を移し替えの前と変えない（`emo2_real_run.rs` は `AREKA_EMO2_REAL_RUN` を明示したときだけ走り、ほかの 2 本は今のまま常時のテストで走る）。

### Requirement 8: 起動の約束を後から起動オプションへ移せること

**Objective:** As a 実機の試験を書く人, I want 窓口を使う試験が起動の約束の綴りを知らずに済んでほしい, so that `startup-options-core` が着地して起動オプションで立てるようになっても、試験を書き換えずに済む

#### Acceptance Criteria

1. The 窓口 shall 呼び手が、環境変数の名前や起動オプションの綴りを書かずに、起動するもの・根・記憶の置き場・MCP の番号を指定できるようにする。
2. The 窓口 shall それらを areka へ伝える形（今は環境変数と位置の引数）を窓口の中で決め、呼び手の試験の中に `AREKA_ROOT`・`AREKA_PROFILE_DIR`・`AREKA_MCP_PORT`・`AREKA_NO_ALERT` の名前を綴らせない（呼び手がわざと任意の環境変数を足す要件 1.6 の場合を除く）。
3. When `startup-options-core` の着地の後に伝える形を起動オプションへ移すとき, the 窓口 shall 窓口の中を替えるだけで移れ、窓口を使う試験の書き換えを要さない。

### Requirement 9: 並べて立てる走り

**Objective:** As a 実機の試験を書く人, I want 同じ時間に立てた走りどうしが取り合わないでほしい, so that 同じ試験のバイナリの中で並走するテストが互いを壊さない

#### Acceptance Criteria

1. While 同じ試験のプロセスの中、または別の試験のプロセスで、窓口の走りが同時に立っているとき, the 窓口 shall 走りごとに根・記憶の置き場・出力のファイル・検体の写し・MCP の番号を分け、走りどうしが互いのものを使わない。
2. If 選んだ MCP の番号が子の起動までに他に取られていた場合, then the 窓口 shall 要件 4.5 と同じ形で、取られていたと分かる失敗を返す。

### Requirement 10: 窓口の確かめ・説明・守ること

**Objective:** As a 開発者, I want 窓口そのものが本物の窓なしで確かめられ、使い方が書いてあってほしい, so that 窓口の不具合を実機の試験の赤と取り違えず、次の spec がすぐ使える

#### Acceptance Criteria

1. The 窓口 shall 立てる・出力を探す・MCP を呼ぶ・閉じる・証拠を残す・仲介を揃える各働きの分岐（成功・締切切れ・子が先に終わる・待受を始められない・ツールの失敗・つながらない・止める）を、本物の窓・GPU・SHIORI を使わない決定論のテスト（偽の子と偽の MCP の受け口）で確かめ、常時のテストに入れる。
2. The 窓口 shall 使い方を、窓口そのものの説明と、`doc/` の試験の手引きの 1 節に書く（立て方・ツールの呼び方・閉じ方と自分で終わるのを待つ形の使い分け・残した証拠の場所と読み方・32bit の仲介の建て方・負荷の走りと同じ時間に回さないこと・実機の試験を 1 本ずつ回す机のこと）。
3. The 窓口 shall 試験からだけ使われ、areka の配布物の依存に入らない。検体の窓口を配布物の依存から締め出す今の見張りは、窓口を足した後も同じ強さで働く。
4. The 窓口 shall 新しい外の依存を足さない（ワークスペースに既にあるものだけを使う）。
5. The 窓口 shall MCP の要求と答えを試験の側で手で組まず、areka の受け口と中継が使っているのと同じ MCP の公式の SDK で話し、その中の非同期の仕組みを呼び手に見せない。
6. The 窓口 shall 作るファイルと置き場をすべてワークツリーの `target\` の下に置く。
