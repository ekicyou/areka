# Requirements Document

## Project Description (Input)

- **困っている人**:
  - ゴーストの作者。そのゴースト専用のバルーンを、ゴーストと一体で配れない。
    - 同梱のバルーンは根の置き場（`<根>\balloon\`）へ入り、全ゴーストの共有物になる。同じフォルダ名のバルーンを別のゴーストが入れると、上書きされるか、別の版に替わる。
    - シェルは `<ゴースト>\shell\` に抱えられるのに、バルーンには同じ置き場が無い。
  - 利用者。ゴーストを消しても、そのゴースト専用のバルーンが根の置き場に残る。
- **今の状況**:
  - バルーンの一覧は、置き場の並びの各根の `<根>\balloon\` だけから作る。メニュー・`\![change,balloon,バルーン名]`・起動とゴースト切替のときの決め方・前回の記憶は、この一覧とだけ突き合わせる。
  - ゴーストのフォルダの中は見ない。`doc/COMPAT_ARCHITECTURE.md` §8 に「ゴーストのフォルダの中（`<ゴースト>\balloon\`）は探さない」と書いてある。
  - ゴーストの書庫の同梱のバルーン（`install.txt` の `balloon.directory`／`balloon.source.directory` で名指ししたもの）は、根の置き場へ入る。
- **変えたいこと**:
  - ゴーストのフォルダの中の `balloon\<名>\` に置いたバルーンを、そのゴーストが、根の置き場のバルーンと同じように使える（選べる・覚えられる・戻れる）。
  - 同梱のバルーンを、ゴーストの中の `balloon\` へ入れる。
  - 他のゴーストからは、そのバルーンが見えない。
  - ゴーストの中と根の置き場に同じ名前が在るときの優先を決め、`doc/COMPAT_ARCHITECTURE.md` §8 に記す。
- 詳細は同じフォルダの `brief.md`。

## Introduction

ukadoc はバルーンをゴーストの持ち物として書いていない。「全体の構成」（ https://ssp.shillest.net/ukadoc/manual/manual_directory.html ）は、バルーンはゴーストごとでなく、一つのベースウェアの元でまとめて管理され、全ゴーストで共有されると書く。同梱の鍵 `balloon.directory` は「インストール後のディレクトリ名」を決める鍵で、入れる親の置き場は書いていない。

したがって、ゴーストのフォルダの中のバルーンは **areka 独自の決まり** である。本 spec は ukadoc の鍵の意味を変えない。areka が決めるのは、同梱のバルーンを入れる親の置き場だけである。

**SSP での実測（2026-10-22・開発者の SSP 2.9・測った後に元へ戻した）**:

- ゴースト「窓際のぱすたさん」は、縦書きのバルーンをゴーストのフォルダの直下（`<ゴースト>\pasta_tategaki\`、descript.txt に `type,balloon`）に置いている。
- 根の置き場の写し（`<根>\balloon\pasta_tategaki\`）を外して SSP を起動し直すと、バルーンの数は 11 から 10 に減り、ゴーストの直下の写しは一覧に出なかった。ぱすたに切り替えると、使うバルーンは SSP の既定のバルーンになった。記録に失敗は残らなかった。
- つまり SSP は、ゴーストのフォルダの中をバルーンとして探さない。そのゴースト自身のためにも探さない。ぱすたが SSP で縦書きに見えていたのは、根の置き場に別の写しが在ったからである。
- `\![reload,balloon]` ではバルーンの一覧は数え直されず、起動し直したときだけ数え直された。
- SSP のバルーンの扱いは一貫していないので、areka はここを SSP に合わせない（開発者の判断）。

本 spec が決めること（開発者の決め 2026-10-22）:

- ゴーストの中のバルーンは `<ゴースト>\balloon\<フォルダ名>\` に置く。ゴーストのフォルダの中で探すのはここだけで、ゴーストのフォルダの直下のフォルダ（例: `<ゴースト>\pasta_tategaki\`）は探さない（要件 1）。
- ゴーストの中のバルーンは、そのゴーストにだけ見える（要件 2）。**SSP では同梱のバルーンが全ゴーストで共有されるのと違う。**
- ゴーストの中と根の置き場に同じフォルダ名が在るときは、そのゴーストではゴーストの中のものが勝ち、根の置き場のものはそのゴーストでだけ隠れ、隠したことを記録に残す（要件 3）。
- 記憶の持ち方（ゴーストごと・フォルダ名 1 つ）は変えない（要件 5）。
- 一覧とメニューは、ゴーストの中のバルーンを先に、根の置き場のバルーンを後に並べる。同じ `name` はこの並びでゴーストの中が当たる（要件 2・3）。
- 記憶はフォルダ名なので、根の置き場で選んだバルーンも、同じフォルダ名がゴーストの中に入ればそちらが出る。これは上書きと数えず、§8 と README に書き、バルーンだけの書庫を入れたときに隠れることを記録に残す（要件 3.5・9.1）。
- 同梱のバルーンは、根の置き場でなく、入れるゴーストの中の `balloon\<balloon.directory の名>\` へ入れる。シェルの書庫の同梱も、シェルを入れる先のゴーストの中へ入れる。今のインストールの動きを変える（要件 7）。バルーンだけの書庫は今どおり根の置き場へ入れる。
- 以前の areka が根の置き場へ入れた同梱のバルーンは、動かさない。そのゴーストの次の上書きインストールまたはネットワーク更新から、同梱のバルーンはゴーストの中へ入る（要件 8）。
- ゴーストのネットワーク更新・上書きインストール・削除で、ゴーストの中のバルーンはゴーストと一緒に替わる・消える（要件 8）。

## Boundary Context

- **In scope**:
  - ゴーストの中の `balloon\` のバルーンの見つけ方と、どの置き場のものかの区別。
  - 起動・ゴーストの切替・メニュー・`\![change,balloon,バルーン名]`・無作為の切替・前回の記憶・バルーンの読み直しでの扱い。
  - バルーンを名前で引く他の入口（その他の更新のバルーンの名前引き・`\![open,explorer,…]` の名前引き・インストールの後の表示名）での見え方。
  - 同梱のバルーンの入れ先を、根の置き場からゴーストの中の `balloon\` へ変えること。
  - 決定論の自動テスト。
  - `doc/COMPAT_ARCHITECTURE.md` §8 と `dist/README.txt` の作者向けの説明。
- **Out of scope**:
  - 根の置き場のバルーンの扱い（一覧・順・根どうしの同名の隠れ方・記憶の読み書き）。変更 0。
  - バルーンだけの書庫の入れ先。変更 0（今どおり根の置き場）。
  - ukadoc の `install.txt` の鍵の意味。新しい鍵も足さない。
  - 以前の areka が根の置き場へ入れた同梱のバルーンを、ゴーストの中へ移すこと・消すこと。
  - ゴーストのフォルダの直下（`balloon\` の外）に置いたバルーンを探すこと。SSP も探さない（上の実測）。
  - ゴースト「窓際のぱすたさん」の縦書きのバルーンを使えるようにすること。これはぱすたのゴーストの側で直す。上の実測のとおり、SSP でも根の置き場に写しが無ければ使われていない。ぱすたの `install.txt` に `balloon.source.directory,pasta_tategaki` と `balloon.directory,pasta_tategaki` を書けば、1 つの書庫で SSP（根の置き場へ入る）と areka（`<ゴースト>\balloon\pasta_tategaki\` へ入る）の両方で使える。
  - ゴーストを削除する操作を areka に作ること（今の areka に無い）。
  - `recommended.balloon`／`recommended.balloon.path`。
  - シェルのフォルダの中にバルーンを抱えること（`<ゴースト>\shell\<名>\balloon\`）。
  - シェルの絵の中に台詞を書くこと（完了 `areka-P0-shell-balloon`）。名前が似ているが別物。
  - バルーンの見た目の鍵（`char*.balloon.*` など）。
  - 起動時の段の並び（引数 → 記憶 → descript → 同梱 → 唯一 → 既定 → 無作為）と、descript の 2 鍵の値の書き方。
  - 引数で渡したバルーンの扱い。
- **Adjacent expectations**:
  - 完了 `areka-P0-ghost-standard-balloon` の「`default.balloon.path` の突き合わせ先は根の置き場だけ・ゴーストの中は探さない」を、本 spec が「根の置き場と今のゴーストの中の `balloon\`」に広げる。値の書き方（フォルダ名 1 段）は受け継ぐ。
  - `areka-P0-shell-companion-balloon`（後に着地する）は、シェルに紐づくバルーンがゴーストの中のバルーンを指せるかを決める。本 spec はその段を作らない。
  - `areka-P0-install-live-target-hazards` は、使用中のファイルへの上書きの扱いを決める。本 spec は、使用中のゴーストの中のバルーンを、ゴーストの他の使用中のファイルと別に扱わない。

## Requirements

### Requirement 1: ゴーストのフォルダの中のバルーンを見つける

**Objective:** As a ゴーストの作者, I want ゴーストのフォルダの `balloon\` に置いたバルーンを areka が見つけること, so that 専用のバルーンをゴーストと一体で配れる

#### Acceptance Criteria

1. When ゴーストのバルーンの一覧を作る, the areka shall そのゴーストのフォルダの `balloon\` の直下のフォルダのうち、根の置き場でバルーンとして数える決まり（descript.txt が読め、`type` の行が無いか `type,balloon`）を満たすものを、そのゴーストの中のバルーンとして数える。
2. The areka shall ゴーストのフォルダの中で、`balloon\` の直下のフォルダ以外（ゴーストのフォルダの直下のフォルダ・`balloon\` そのもの・`balloon\<名>\` のさらに下）を、descript.txt に `type,balloon` と書いてあってもバルーンとして数えない。
3. If ゴーストの `balloon\` の直下のフォルダが要件 1.1 の決まりを満たさない, the areka shall そのフォルダを一覧に入れず、根の置き場で同じ決まりを満たさないフォルダと同じ記録を残す。
4. When ゴーストのフォルダを起動の引数で直接渡して起動した, the areka shall そのゴーストの中のバルーンも、置き場の並びから選んだゴーストと同じく数える。
5. Where ゴーストのフォルダに `balloon\` が無い、または中のバルーンが 1 つも無い, the areka shall 今どおり根の置き場のバルーンだけで一覧を作る。

### Requirement 2: 今のゴーストだけに見える

**Objective:** As a 利用者, I want ゴーストの中のバルーンが、そのゴーストのときだけ選べること, so that 他のゴーストのメニューが、関係のないゴーストの専用のバルーンで散らからない

#### Acceptance Criteria

1. While あるゴーストが動いている, the areka shall そのゴーストの中のバルーンを、バルーンのメニュー・`\![change,balloon,バルーン名]`・`\![change,balloon,random]`・その他の更新のバルーンの名前引き・`\![open,explorer,…]` のバルーンの名前引きの、すべての候補に入れる。
2. The areka shall あるゴーストの中のバルーンを、別のゴーストが動いているときの、どの候補にも入れない。
3. When ゴーストを切り替えた, the areka shall 候補に入れるゴーストの中のバルーンを、切替先のゴーストのものに入れ替える。
4. The areka shall バルーンのメニューで、ゴーストの中のバルーンと根の置き場のバルーンを同じ一覧に並べ、今使っているバルーンに今と同じ印を付ける。
5. The areka shall 候補の一覧を、ゴーストの中のバルーンを先に、根の置き場のバルーンを後に並べ、それぞれの中は今と同じ順にする。メニューの並びもこの順にする。

### Requirement 3: 同じ名前が両方に在るとき

**Objective:** As a ゴーストの作者, I want 自分のゴーストに入れたバルーンが、根の置き場の同じ名前のバルーンより先に使われること, so that 他のゴーストが入れた同じ名前の別の版に替わらない

#### Acceptance Criteria

1. If 今のゴーストの中と根の置き場に同じフォルダ名のバルーンが在る, the areka shall そのゴーストではゴーストの中のものを使い、根の置き場の同じフォルダ名のものを候補から外す。フォルダ名の突き合わせは、根どうしの同名と同じ決まり（大文字小文字を区別しない）で行う。
2. When 要件 3.1 で根の置き場のバルーンを候補から外した, the areka shall 外したバルーンの場所と、それを隠したゴーストの中のバルーンの場所を記録に残す。
3. When バルーンを `name` で引く（ゴーストの descript.txt の `balloon`・`\![change,balloon,バルーン名]`・その他の更新の名前引き・`\![open,explorer,…]` の名前引き）とき、同じ `name` を持つバルーンがゴーストの中と根の置き場の両方に在る, the areka shall 要件 2.5 の並びで最初のもの、つまりゴーストの中のものを当てる。
4. While 別のゴーストが動いている, the areka shall 要件 3.1 で隠した根の置き場のバルーンを、今どおり候補に入れる。
5. When バルーンだけの書庫を根の置き場へ入れ、今のゴーストの中に同じフォルダ名のバルーンが在る, the areka shall 入れたバルーンがそのゴーストでは隠れることを、入れたバルーンの場所と隠すゴーストの中のバルーンの場所と共に記録に残す。

### Requirement 4: 起動とゴースト切替のときの決め方

**Objective:** As a ゴーストの作者, I want 起動とゴースト切替のバルーンの決め方が、ゴーストの中のバルーンにも当たること, so that descript.txt や同梱で指したゴーストの中のバルーンで出てくる

#### Acceptance Criteria

1. The areka shall 段の並び（引数 → 記憶 → descript の `default.balloon.path`・`balloon` → 同梱 → 唯一 → 既定 → 無作為）を変えずに、引数を除く各段の突き合わせ先に、そのゴーストの中のバルーンを要件 3 の優先で含める。
2. When ゴーストの descript.txt の `default.balloon.path` の値がフォルダ名 1 段で、ゴーストの中のバルーンのフォルダ名と一致する, the areka shall そのゴーストの中のバルーンを当てる。
3. If `default.balloon.path` の値が区切り（`\`・`/`）・`..`・絶対パスを含む, the areka shall 今どおり当たらなかったものとして記録し、ゴーストのフォルダからの相対パスとして読み替えない。
4. When ゴーストの `install.txt` が同梱のバルーンを名指ししている, the areka shall 同梱の段で、そのフォルダ名をゴーストの中と根の置き場の両方から要件 3 の優先で探す。
5. When 起動するゴーストの中にバルーンが在り、根の置き場にバルーンが 1 つも無い, the areka shall ゴーストの中のバルーンから決め、バルーンが 0 個のときの失敗にしない。
6. When ゴーストを切り替えた, the areka shall 切替先のゴーストの中のバルーンを含めて、起動と同じ並びで切替先のバルーンを決める。
7. The areka shall 各段が当たらなかったときの記録を、ゴーストの中のバルーンが加わった後も今と同じ形で残す。

### Requirement 5: 記憶と読み直し

**Objective:** As a 利用者, I want ゴーストの中のバルーンを選んだら覚えられ、次に起動したときもそのバルーンで出てくること, so that 一度選んだら戻れないバルーンが無い

#### Acceptance Criteria

1. When 利用者がメニューまたは `\![change,balloon,バルーン名]` でゴーストの中のバルーンに切り替えた, the areka shall それをそのゴーストの前回のバルーンとして記憶する。
2. When 起動またはゴースト切替がゴーストの中のバルーンで成功した（引数で渡したときを除く）, the areka shall 根の置き場のバルーンと同じく、それを前回のバルーンとして記憶する。
3. The areka shall 前回のバルーンの記憶を、今と同じ形（ゴーストごとに、バルーンのフォルダ名 1 つ）で持ち、置き場を区別する欄を足さない。
4. When 前回の記憶がゴーストの中のバルーンのフォルダ名を指している, the areka shall 次の起動とそのゴーストへの切替で、要件 3 の優先で同じバルーンを出す。
5. If 前回の記憶のバルーンが、そのゴーストの中にも根の置き場にも無い, the areka shall 今どおり当たらなかったものとして記録し、次の段へ進む。
6. The areka shall 本 spec の前に書かれた記憶を、書き直さずにそのまま読む。
7. When バルーンの読み直し（`\![reload,balloon]`・MCP の読み直し）を行った, the areka shall ゴーストの中のバルーンを使っていたら、同じゴーストの中のバルーンのまま読み直す。

### Requirement 6: 根の置き場のバルーンを変えない

**Objective:** As a 利用者, I want 根の置き場のバルーンの動きが本 spec の前と同じであること, so that SSP 向けに書かれたゴーストと今の設定がそのまま動く

#### Acceptance Criteria

1. Where 今のゴーストの中にバルーンが 1 つも無い, the areka shall バルーンの一覧・メニュー・起動とゴースト切替の決め方・記憶を、本 spec の前と同じにする。
2. The areka shall 根の置き場どうしの同じフォルダ名の隠れ方（上の根が先）と、根の置き場の並びの順を変えない。
3. The areka shall 引数で渡したバルーンの扱いを変えない。
4. The areka shall 以前の areka が根の置き場へ入れた同梱のバルーンを、移さず消さず、今どおり根の置き場のバルーンとして扱う。

### Requirement 7: 同梱のバルーンをゴーストの中へ入れる

**Objective:** As a ゴーストの作者, I want ゴーストの書庫に同梱したバルーンが、そのゴーストの中へ入ること, so that 専用のバルーンを 1 つの書庫で配り、他のゴーストの同じ名前のバルーンとぶつからない

#### Acceptance Criteria

1. When ゴーストの書庫の `install.txt` が `balloon.directory`・`balloon.source.directory`（番号付きの形を含む）で同梱のバルーンを名指ししている, the areka shall そのバルーンを、根の置き場でなく、入れるゴーストのフォルダの `balloon\<balloon.directory の値>\` へ入れる。
2. The areka shall `balloon.directory` を「インストール後のフォルダ名」として読む ukadoc の意味を変えず、`install.txt` に鍵を足さない。
3. When 同梱のバルーンをゴーストの中へ入れた, the areka shall 根の置き場に在る同じフォルダ名のバルーンを上書きも削除もしない。
4. The areka shall バルーンだけの書庫（`type,balloon`）を、今どおり根の置き場の `<根>\balloon\` へ入れる。
5. The areka shall ゴーストの書庫のうち同梱として名指しされていないフォルダを、今どおりゴーストのフォルダの中へそのまま入れる。そのフォルダが `balloon\<名>\` に在れば、入れた後はそのゴーストの中のバルーンとして使えるようにする。
6. When ゴーストの書庫を入れ終えた, the areka shall 入れた同梱のバルーンの表示名を、入れたゴーストの中のバルーンから引く。
7. If 同梱のバルーンをゴーストの中へ入れられない, the areka shall 今の同梱のバルーンを入れられなかったときと同じ扱いと記録にし、根の置き場へ入れ直さない。
8. When シェルの書庫の `install.txt` が同梱のバルーンを名指ししている, the areka shall そのバルーンを、シェルを入れる先のゴーストのフォルダの `balloon\<balloon.directory の値>\` へ、要件 7.1〜7.3・7.6・7.7 と同じ決まりで入れる。

### Requirement 8: ゴーストと一緒に替わる・消える

**Objective:** As a ゴーストの作者, I want ゴーストの中のバルーンが、ゴーストの更新・上書きインストール・削除で一緒に替わる・消えること, so that ゴーストとバルーンの版がずれず、ゴーストを消してもバルーンが残らない

#### Acceptance Criteria

1. When ゴーストのネットワーク更新または上書きインストールを行った, the areka shall ゴーストの中のバルーンを、ゴーストのフォルダの他のファイルと同じ決まりで替える。ただし `install.txt` で名指しされた同梱のバルーンは、本体の `refresh` に関わらず、自分の `balloon.refresh`・`balloon.refreshundeletemask` で替える（ukadoc の鍵の意味のまま・要件 7.2）。
2. When 以前の areka が根の置き場へ同梱のバルーンを入れたゴーストを、上書きインストールまたはネットワーク更新した, the areka shall 上書きインストールでは同梱のバルーンをゴーストの中へ入れ、ネットワーク更新では更新の一覧に載ったゴーストの中の `balloon\<名>\` のファイルだけを替え、どちらでも根の置き場のものは移さず消さない。
3. When 今使っているバルーンがゴーストの中のバルーンで、そのバルーンのネットワーク更新を行った, the areka shall そのゴーストの中のバルーンのフォルダを更新する。
4. When ゴーストのフォルダが消された, the areka shall そのゴーストの中のバルーンを、どのゴーストの候補にも入れず、根の置き場にも何も残さない。
5. If ゴーストの更新でゴーストの中のバルーンが無くなった, the areka shall 次に決めるときに要件 5.5 のとおり記録して次の段へ進む。

### Requirement 9: 作者と利用者への説明

**Objective:** As a ゴーストの作者, I want ゴーストの中にバルーンを置く決まりが文書に書いてあること, so that areka 独自の決まりだと分かって使える

#### Acceptance Criteria

1. The areka の文書 shall `doc/COMPAT_ARCHITECTURE.md` §8 の「ゴーストのフォルダの中は探さない」の記述を、areka の決まりとして次の記述に置き換える: ゴーストの中のバルーンの置き場（`<ゴースト>\balloon\<フォルダ名>\` だけ）・同梱のバルーンの入れ先（ゴーストの書庫もシェルの書庫もゴーストの中・`balloon.directory` の意味は変えない）・バルーンだけの書庫の入れ先（根の置き場のまま）・同じ名前のときの優先（記憶はフォルダ名なので、根の置き場で選んだバルーンも、同じフォルダ名がゴーストの中に入ればそちらが出ること）・一覧とメニューの並び（ゴーストの中が先）・他のゴーストから見えないこと・`default.balloon.path` の値の書き方が変わらないこと・以前に根の置き場へ入れたものは移さないこと。
2. The areka の文書 shall `doc/COMPAT_ARCHITECTURE.md` §8 の `default.balloon.path`・`balloon` の行に残る「フォルダ名は大文字と小文字を区別する」という古い記述（と、今は無いテストの名前）を、今の動き（フォルダ名は区別しない・`name` は区別する）に直す。シェルとバルーンの切替の部品の頭の説明に残る同じ古い記述も直す。
3. The areka の文書 shall `doc/COMPAT_ARCHITECTURE.md` §8 の同じ行に、根拠として 2026-10-22 の SSP での実測（SSP はゴーストのフォルダの中を探さない・同梱のバルーンは全ゴーストで共有される）と、SSP に合わせない理由を短く書く。
4. The areka の文書 shall `dist/README.txt` に、ゴーストのフォルダの `balloon\` にバルーンを置けること・同梱のバルーンがゴーストの中へ入ること・それが ukadoc に無い areka 独自の決まりであることを、作者向けに書く。
5. The areka の文書 shall `dist/README.txt` のバルーンのメニューの説明（置き場の balloon フォルダに在るバルーンの一覧）を、今のゴーストの中のバルーンも並ぶことに合わせる。

### Requirement 10: 決定論の自動テストと記録

**Objective:** As a 開発者, I want 本 spec の決まりが決定論の自動テストで確かめられること, so that 後の変更で崩れたら分かる

#### Acceptance Criteria

1. The areka shall 要件 1〜8 の判断の分かれ目（ゴーストの中だけに在る・根の置き場だけに在る・両方に同じフォルダ名・両方に同じ `name`・ゴーストの直下のフォルダを数えない・別のゴーストからの見え方・`default.balloon.path` の区切り入りの値・記憶からの復帰・読み直し・一覧の並び（ゴーストの中が先）・バルーンだけの書庫が隠れる記録・同梱のバルーンの入れ先（ゴーストの書庫・シェルの書庫）・バルーンだけの書庫の入れ先・根の置き場の同名に触らない・以前に根の置き場へ入れたものを動かさない）を、決定論の自動テストで確かめる。
2. The areka shall テストの検体と一時フォルダを、ワークツリーの `target\` の下だけに作る。
3. If ゴーストの中のバルーンの読み取りまたは入れ込みに失敗した, the areka shall 失敗した場所と理由を記録に残し、記録の無い失敗の経路を作らない。

## 要件の討議の決め（2026-10-22・全議題を推奨案で確定）

1. 利用者が根の置き場で選んだバルーンが、ゴーストの中の同じフォルダ名に替わる件: 要件はそのまま（上書きと数えない）。§8 と README に書き、バルーンだけの書庫を入れたときに隠れることを記録に残す（要件 3.5・9.1）。記憶に置き場の欄は足さない。
