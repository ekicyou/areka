# Brief: areka-P0-app-icon

> 2026-10-10 `/kiro-discovery`（開発者「より上位に、アプリアイコンとタスクトレイアイコンを作成して areka.exe に埋め込むスペックを用意しないとダメなんじゃないか」「fal も使えるし」）で起票した。同じ日に起票した `areka-P0-tasktray-icon` の議題 1（標準アイコンの絵が無い）を、その前提の spec として切り出したもの。コードは「何の定義か」で指す。着手時に引き直す。

## Problem

areka には自分のアイコンが無い。`areka.exe` はエクスプローラーでも、タスクマネージャーでも、スタートメニューでも、OS の既定の「名無しのアプリ」の絵で出る。配布物を受け取った人には、それが何のアプリか絵で分からない。

通知領域（タスクトレイ）のアイコンも、出す絵が無いので作れない（`areka-P0-tasktray-icon` が止まる）。インストーラー版のスタートメニューのアイコン（roadmap の予約）も同じ絵を待っている。

## Current State

- リポジトリに `.ico` は 1 つも無い。アイコンの原画も無い。
- `areka.exe` に埋めているのはマニフェストだけ。`crates/areka/build.rs` が、bin にだけ届く指示（`cargo:rustc-link-arg-bins`）でリンカへ `/MANIFEST:EMBED` と `areka.manifest` を渡している。資源のスクリプト（`.rc`）も、資源を埋めるための依存（`embed-resource`・`winresource` など）も無い。
- bin は `crates/areka` の `areka` 1 つ（ほかに開発の道具の `ukadoc-survey`）。32bit の SHIORI を載せる補助の exe は別のクレートに在る。
- areka は 3 つの形で配っている: GitHub のリリースの書庫（`tools/package.ps1`・`.github/workflows/release.yml`）、winget（`winget-manifest-submission` が進行中）、crates.io（`tools/crates-io.ps1`＝利用者の手元でソースから組む）。x64・arm64 と、32bit の補助の exe を組む。
- アイコンのハンドルを作るコード・埋めた資源を読むコードは無い。
- steering（`product.md`・`tech.md`・`structure.md`）に、areka の絵柄・色・ロゴの決まりは無い。
- 画像を作る道具として、開発者の fal（画像生成のサービス）が MCP から使える。

## Desired Outcome

- `areka.exe` がアプリのアイコンを持ち、エクスプローラー・タスクマネージャー・ショートカットにその絵が出る。
- 通知領域用のアイコンが同じ exe に入っていて、後続の `areka-P0-tasktray-icon` がファイルを別に配らずに読める。
- 小さい表示（16〜48 ピクセル）でも潰れず、画面の拡大率を上げてもぼけない。明るいタスクバーでも暗いタスクバーでも見える。
- 原画・作り方（使ったモデルと指示の文）・権利の扱いがリポジトリに残っていて、絵を直すときに同じ手順で `.ico` を作り直せる。
- 3 つの配り方のどれで組んでも、同じアイコンが入る。

## Approach

絵を作る仕事と、exe に埋める仕事の 2 つを、1 本の spec で続けて行う。**絵は要件の段で作って選ぶ**（2026-10-10 開発者「絵を作るのは要件フェーズで行った方が良い」）。絵が決まらないと、寸法の整え方も確かめの中身も書けないからである。設計・タスク・実装は、決まった絵を前提に進める。

1. **絵を作る（要件の段）**: 要件の討議の中で、fal で案をいくつか出し、開発者が選ぶ。アプリ用（大きく出る・描き込める）と通知領域用（16 ピクセルから出る・形を絞る）の 2 種の原画まで決める。選んだ原画は spec のフォルダに置いてコミットし、要件はその絵を名指して書く（置き場は要件の段で決め直してよい）。
2. **小さい寸法を整える（実装）**: 通知領域用は、大きい絵を縮めただけでは潰れるので、小さい寸法は別に整える。原画は、製品の置き場（`crates/areka/` の下）へ写す。組むときに spec のフォルダを読ませない（完了で `completed/` へ移るため）。
3. **`.ico` にまとめる（実装）**: 1 つの `.ico` に複数の寸法を入れる（拡大率 100〜300% の小さいアイコン＝16・20・24・32・40・48 と、大きい表示用の 64・256）。
4. **exe に埋める（実装）**: 今のマニフェストと同じ道（`build.rs` から bin にだけ届く指示）で、アイコンの資源をリンカへ渡す。資源の番号を決めて、読む側（`areka-P0-tasktray-icon`）が名前で引けるようにする。
5. **確かめる（実装）**: 組んだ exe からアイコンを引けることを、テストで見る（bin への指示は bin のユニットテストの exe にも届くので、テストの中から自分の exe の資源を引ける）。実機でエクスプローラーの表示を見る。

## 議題（要件の段で決める）

議題 1・2・4 は、絵を作る前か作りながら決める（絵そのものが要件の段の成果になる）。

1. **絵柄**。areka の顔になる題材・色・雰囲気は、開発者が決める。steering に決まりが無いので、案出しの前に方向を聞き、案を見ながら詰める。何回か出し直す往復になる。
2. **通知領域用の絵を別に持つか**。アプリ用と同じ絵の小さい寸法で足りるか、形を絞った別の絵にするか。
3. **埋め方**。
   - 案 A: 資源を先に組んだもの（`.res`）をリポジトリに置き、`build.rs` からリンカへ渡す。依存を足さない。組むときに道具が要らないので、crates.io から組む利用者の手元でも同じに通る。絵を直したときだけ、`tools/` のスクリプトで作り直す。
   - 案 B: 資源のスクリプト（`.rc`）を組むたびに処理する依存を足す。置くファイルは少ないが、組むたびに OS の開発キットの道具が要り、ウェーブの「依存を足す spec は 1 本だけ」の席を使う。
4. **作った絵の権利の書き方**。使うモデルの利用条件（商用・再配布）を、案を出す前に確かめ（条件に合わないモデルで作った絵を選んでしまわないため）、リポジトリのどこに何と書くかを決める（`THIRD-PARTY-NOTICES.md` は依存のライセンスの生成物なので、置き場は別になる見込み）。
5. **32bit の補助の exe にも同じアイコンを入れるか**。窓を持たないが、タスクマネージャーには出る。
6. **原画の置き場と形式**（PNG だけか、輪郭のデータも持つか）と、crates.io の包みに何を入れるか（組むのに要るものだけにして、原画は入れない）。

## Scope

- **In**: アプリ用と通知領域用のアイコンの絵／複数の寸法を持つ `.ico`／`areka.exe` への埋め込み（`build.rs`）と資源の番号の定義／作り直しの手順（`tools/` のスクリプトと説明）／原画・作り方・権利の記録／組んだ exe から引けることのテストと実機の確かめ／crates.io の包みと x64・arm64 のどちらでも入ることの確かめ。
- **Out**: 通知領域にアイコンを出すこと（`areka-P0-tasktray-icon`）／ゴーストが決めるアイコン（`areka-P0-tasktray-ghost-icon`）／窓のタイトルバーやタスクバーのボタンのアイコン（キャラクターの窓はどちらも持たない）／インストーラー版とスタートメニューのショートカット（roadmap の予約。exe にアイコンが入れば、ショートカットはその絵を使える）／winget のマニフェストのアイコンの欄／README やサイトに載せるロゴ／ファイルの関連付けの絵（`.nar` のアイコン）。

## Boundary Candidates

- 絵（原画・2 種の仕上げ・`.ico`）。置き場は `crates/areka/` の下の新しいフォルダ。
- 埋め込み（`crates/areka/build.rs`・`crates/areka/Cargo.toml` の包みの指定・資源の番号の定義）。
- 作り直しの道具と記録（`tools/` のスクリプト・作り方と権利の文書）。

## Out of Boundary

- wintf。アイコンを読む・出すコードは足さない（読むのは `areka-P0-tasktray-icon`）。
- 今のマニフェストの埋め込み。動きを変えない（版 6 の標準の部品の申告を壊さない）。
- リリースの段取り（`release-cycle`）。exe の中身が増えるだけで、手順は変えない。

## Upstream / Downstream

- **Upstream**: なし（今すぐ着手できる）。要件の段に、開発者と絵を選ぶ往復が入る。
- **Downstream**: `areka-P0-tasktray-icon`（埋めたアイコンを読んで通知領域に出す）。roadmap の予約「インストーラー版」（スタートメニューのアイコン）。

## Existing Spec Touchpoints

- **Extends**: なし。
- **Adjacent**: `crates/areka/build.rs` を作った `wintf-tooltip`（完了）。exe に署名する `release-code-signing`（埋め込みの後に署名する順になるだけで、重ならない見込み）。`winget-manifest-submission`・`winget-release-automation`（マニフェストのアイコンの欄は範囲の外）。`release-cycle`（次の版の配布物から絵が入る）。

## Constraints

- 画像の生成は外のサービスで、開発者の持ち分を使う。案出しの枚数と使うモデルは、要件の討議の中で開発者と決めてから回す。要件を作るサブエージェントには生成させない（開発者と話せないので、絵は討議の段で主のセッションが出す）。
- 絵は開発者が選ぶ。エージェントだけで絵を確定しない。
- 埋め込みで今のマニフェストを壊さない（資源の側にマニフェストを入れない）。
- crates.io から組む利用者の手元でも通る。組むのに要るファイルは包みに入れ、包みの大きさの上限に収める。
- リンカが MSVC でないときは、今の `build.rs` と同じく何もしない。
- エクスプローラーはアイコンを覚えているので、実機の確かめは覚えを消した状態か、別の名前に写した exe で見る。手順に書く。
- 一時のファイル（生成した案・途中の画像）は、ワークツリーの `target\` の下に置く。リポジトリに入れるのは、選んだ原画（要件の段）と仕上げ（実装）だけ。
