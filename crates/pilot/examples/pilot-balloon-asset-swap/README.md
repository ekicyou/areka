## 動機（なぜ掘るか）

- 対応する本坑 spec: `areka-P0-shell-balloon-switch`（roadmap 台帳 #50）。本坑はこの先進坑の go 判定を前提依存（`_Depends(confirmed): pilot-balloon-asset-swap`）として持つ。
- 何を決める材料か: 本坑には「走っているゴーストのバルーン（とシェル）を差し替える」2 つの案があり、**どちらが安いかはコードを書いてみないと分からない**。この先進坑の数は、その選択の材料である。
  - **案 A**: ゴースト切替（#13）が作る「降ろして起こし直す」一般形を、SHIORI だけ残して回す。
  - **案 B**: seriko・present・text に「資産を差し替えろ」の語を 1 つずつ足す。鍵は `EmoPresenter::attach_target`（`crates/areka-emo-present/src/presenter/hub.rs`）——同じ id を再登録すると表示コンテキストごと置き換える。これが差し替えの最小の部品になり得る。
- 確かめたい 1 点: **走っているバルーン窓を閉じずに、present のバルーン資産だけを別のバルーンへ差し替えたとき、差し替えの前後のどのフレームにも「古い絵と新しい当たり判定の混在」「空の窓」「古い絵の残り」「大きさの食い違い」が出ないか**。コードを読むだけでは、差し替えの途中の 1 フレームに何が画面に出るかは分からない。1 フレーム遅らせて辻褄を合わせる解は取らない。
- 合否基準（2026-09-24 の要件ディスカッションで改訂）:
  - **go**: 今の部品のまま（`attach_target` の再登録をそのまま使う基準の版）で崩れが 0。
  - **直す**: 基準の版では崩れるが、**差し替える前に古いバルーンを消す版**（本命の版）で崩れが 0。案 B で進め、本坑で present に古い装着を片付ける口を足す。
  - **違う**: 本命の版でも崩れが 0 にならない。案 A（降ろして起こし直す）へ倒すかを判定する。
  - ここでの「崩れが 0」は**反映待ちを除いて**数える（開発者裁定・2026-09-24）。反映待ちとは、アプリが当たり判定を新しくしてから OS がその絵を画面に出すまでの画面更新 1 回ぶんのフレーム（絵は古く、当たり判定だけが新しい）で、差し替え方に依らず、本番のバルーン番号の切り替え（`\b[ID]`）でも同じように出る。本番のバルーン番号の切り替えで出た反映待ちの数を**床**とし、「崩れが 0」は「反映待ち以外の崩れが 0、かつ反映待ちの数が床と同数以下」を指す。

## 概要（何を作ったか）

### 作った物

コードは `crates/pilot/examples/pilot-balloon-asset-swap/` の下だけにある（依存の追加は `crates/pilot/Cargo.toml` だけ・他の crate は 1 行も変えていない）。検体は `sample-ghost-kit` の窓口から引く `StayseeBalloon`（以下 A）と、`emo2` 同梱の `emo2-kakukaku`（以下 B）。

| ファイル | 役割 |
|---|---|
| `main.rs` | 起動と終了。検体 2 つを引き、資産を作り置き、判別に使う面 3 つ（A の面 0＝335x205・A の面 2＝335x395・B の面 0＝400x224）を合成し、バルーン窓を 1 つ（固定位置 (160,160)・最前面・可視）出し、system と取り込みスレッドを起こして `run()`。戻りで終了コードを決める。 |
| `swap.rs` | World を書く唯一の書き手。台本（観測の並び）・差し替えの 3 版・面の切り替え・較正 5 項・各観測の前の下ごしらえ。 |
| `observe.rs` | World を読む側。標本点の導出・tick ごとの当たり判定と窓の矩形の記録・フレームとの突き合わせ・崩れの数え方・観測の窓・集計・較正の合否・床。数え方の規則の検査（`#[cfg(test)]`）もここ。 |
| `capture.rs` | 別スレッドで OS の画面の複製（Desktop Duplication）を作り、画面更新ごとに窓の矩形を切り出して絵を判別する。 |

差し替えの版（ログと README で同じ名前）:

| 名前 | 中身 |
|---|---|
| `reattach@update` | 基準の版。`attach_target(TargetId(1), …)` の再登録 → 面 0 の表示 → 窓寸合わせ。配置が決まる前の段（`Update`）で行う。 |
| `reattach@finalize` | 基準の版を画面への反映の後の段（`FrameFinalize`）で行う（比較）。 |
| `remove-then-attach@update` | **本命の版**。窓のバルーンの子（名前 `emo-surface`・`emo-text-layer-slot`）を外から探して消し、同じ呼び出しの中で再登録 → 表示 → 窓寸合わせ。**判定の主な根拠**。 |
| `remove-then-attach@finalize` | 本命の版を `FrameFinalize` で行う（比較。絵の変化が次の tick にずれる＝1 フレーム遅らせる形なので直し方には数えない）。 |
| `attach-new-hide-old@update` | 隠すだけの版。別の id で新しいバルーンを装着・表示し、古い id を隠す（比較）。 |
| `attach-new-hide-old@finalize` | 隠すだけの版を `FrameFinalize` で行う（比較）。 |
| `face-switch@update` | 同じ A の中で面 0 ↔ 面 2（`\b[ID]` に当たる・本番と同じ `Update` の段）。資産の差し替えとは分けて示す。ここの反映待ちが床。 |

各差し替えは往復（`A→B` と `B→A`、面の切り替えは `A0→A2` と `A2→A0`）で 1 本ずつ観測する。

台本の順（39 段・資産は起動時に作り置き A 19・B 14）: 起動 → 較正 5 項 → 版 6 種 × 往復（12 本）→ 面の切り替え 2 本 → 終了。各観測の前に、観測しない下ごしらえ（窓のバルーンの子を全部消す → 出発の面を `TargetId(1)` で装着・表示・窓寸合わせ → 最新のフレーム・当たり判定・寸法が揃うのを 5〜60 tick 待つ）を置き、どの版の後でも同じ状態から始める。

較正 5 項（わざと崩したフレームを実際の窓に出し、本番と同じ取り込み・同じ規則で数える）:

| 較正 | 作り方 | 期待 |
|---|---|---|
| `calib-static` | 窓を 1px 動かして次の tick で戻す（絵は変えない） | 4 種とも 0・フレーム 1 以上 |
| `calib-empty` | 表示中のバルーンを隠す | 空 1 以上 |
| `calib-mixed` | 絵は A のまま、当たり判定だけ B の子へ付け替える（当たり判定の付け替えだけでは画面が更新されないので 1px の移動を足し、10 tick 後に戻す） | 混在 1 以上 |
| `calib-stale` | A を隠して B を出し、揃った 10 tick 後に A の子を見える状態へ戻す（A の当たり判定は止めたまま） | 古い絵の残り 1 以上 |
| `calib-size` | A の面 2 を出し、窓寸の合わせ直しを 1 回捨てる（窓 335x205 に 335x395 の絵） | 大きさの食い違い 1 以上 |

### 実行法

```sh
cargo run -p pilot --example pilot-balloon-asset-swap
```

- 上限時間: 環境変数 `AREKA_APP_SMOKE_EXIT_MS`（ミリ秒）で与える。空・数でない値・未設定は既定の **90 秒**。上限に達すると「打ち切り」とそれまでの数を出して終わる。台本を終えたら上限を待たずに終わる（静かな走行で窓の生成から終了まで約 12 秒）。
- 終了コード: **0**＝全観測を終え較正も合格／**1**＝上限時間で打ち切り／**2**＝初期化の失敗（検体・復号・構築・標本点の導出・画面の取り込みの初期化）／**3**＝較正不合格（先頭に「本番の数は無効」を出す）。終了の理由は必ずログに出る。
- ログ: 既定は `info`（観測ごとの 1 行と最終の並べ出し）。フレームごとの組（絵, 当たり判定）と提示と tick の時刻差を見るときは `RUST_LOG=info,pilot_balloon_asset_swap=debug`。
- 数え方の規則の検査: `cargo test -p pilot --example pilot-balloon-asset-swap`。

走らせる前に要る条件（実装中に分かったもの）:

- **画面の拡大率を 100% にする**。拡大率が 1 でないと標本点の座標が合わず、全フレームが「測れない」になる（起動ログの `k_ok=true`／`dpi 96` で確かめる）。
- **スクリーンセーバーと画面のロックを止める**。スクリーンセーバー中は画面の複製の作成が拒否され（`E_ACCESSDENIED`）、初期化の失敗で終了コード 2 になる。
- **(160,160) 付近に他の窓を置かない**。他の窓がバルーンに重なるとその間は「測れない」になり、観測が揃わず未完になる。
- **x64 専用**。wintf は i686 で組めないので、追加した dev-dependencies は x86 を除外している。
- 窓は 1 枚目のモニタ（`EnumOutputs(0)`）の中にある前提（窓の矩形がその出力の外なら「測れない」）。

### 観測のしかた（数え方の規則の平易な写し）

- **1 フレーム**は OS が画面を 1 回更新したこと。取り込みスレッドが画面の更新ごとに 1 枚受け取り、窓の矩形の中の標本点の色を読む。
- **組にする相手**: 各フレームを、その提示時刻より前に終わった最新の tick の記録（その tick の終わりの当たり判定と、その tick の後に効く窓の矩形）と組にする。
- **標本点**: 比べる 2 つの面（判別対）を合成し、共通の範囲を 16×16 の升に切って、升ごとに「一方だけ不透明」「他方だけ不透明」「両方不透明で色の差が 48 以上」の点を 1 つずつ拾う。「他方だけ」と「両方」が 16 点以上あれば見分けられる（「一方だけ」は無くてもよい）。
- **絵の判別**: 標本点の色が合成の色と各チャネル ±12 で一致する割合で、一方（P）・他方（Q）・両方・どちらでもない・判別できない、に分ける（おおむね、片方の色に 9 割以上一致し他方には 1 割以下なら P／Q、「一方だけ」と「他方だけ」の点がそれぞれ半分以上一致すれば「両方」、どちらにも 1 割以下なら「どちらでもない」）。
- **当たり判定の判別**: クリック透過を決めるのと同じ wintf の判定（`wintf::ecs::hit_test_in_window`）に標本点を問い合わせ、当たった割合で同じ 4 通り＋判別できない、に分ける。「両方」は 2 つのバルーンのマスクが同時に効いている状態。
- **揃った**: 要求より後のフレームで、絵も当たり判定も到達先になった最初のフレーム（大きさは条件に入れない）。
- 4 種の崩れ（1 つのフレームが複数に当たればそれぞれに数える）:
  - **混在**: 絵と当たり判定が別のバルーン、片方だけが「どちらでもない」、絵が「両方」、または当たり判定が「両方」。**重なって見える「両方」の絵はすべて混在に入り、大きさの食い違いには数えない**。
  - **反映待ち**（混在の内訳）: 揃う前のフレームで、絵＝出発・当たり判定＝到達先のもの。逆向き（絵＝到達先・当たり判定＝出発）は突き合わせの前提が外れた証拠として `error!` を出す。
  - **空**: 絵が「どちらでもない」（窓に何も描かれていない）。
  - **古い絵の残り**: 揃った後のフレームで、絵が出発または「両方」（出発と到達先が同じ観測では数えない）。
  - **大きさの食い違い**: 絵が P か Q で、その面の原寸と組にした窓の矩形の幅・高さが違う。
- **測れない**: 絵か当たり判定が判別できない・窓が他の窓に覆われている・拡大率が 1 でない・文字層の子に当たった・取りこぼし（1 回の受け取りに画面更新が 2 回以上たまっていた）のどれか。測れないフレームは 4 種に数えず、0 とも書かない。取りこぼした更新の回数は別に「取りこぼし」として数える。
- **観測の窓**: 要求の直前に取り込んだ最後のフレームから、揃った tick の **30 tick** 後まで。要求から **180 tick** で揃わなければ「未完」として閉じ、最後の（絵, 当たり判定）と矩形を出す。窓の外のフレームが届くか、窓の終わりから 12 tick の猶予で閉じる。
- **床**: 面の切り替え 2 本の反映待ちの大きい方。

### 分かること／分からないこと

分かること:

- 取り込んだのは OS が合成して画面に出した絵そのもの（Desktop Duplication）であり、アプリの中の値ではない。当たり判定もクリック透過を決める wintf の判定に実際に問い合わせた結果である。
- 1 回の画面更新ごとに、標本点の上で「どちらのバルーンが見えているか」「どちらのバルーンの当たり判定が効いているか」が分かる。

分からないこと:

- **標本点の外は見ていない**。絵は 16×16 の升から拾った点（(A0, B0) で 47＋28＋76＝151 点、(A0, A2) で 35＋21＝56 点。(A0, A2) の「A0 だけ」2 点は使わない）だけで判別しており、全画素ではない。取り込めるのは OS が画面の複製に出した更新であって、モニタが実際に光らせた時刻ではない。
- **「一方だけ」が無い対 (A0, A2) の限界**: この対では、絵の「両方」は A0 が A2 の上に描かれたときしか見分けられず（A2 が上なら A2 と区別できない）、当たり判定の「両方」（2 つのマスクの和）は A2 と区別できない。面の切り替えと `calib-size` はこの対で数えている。面の切り替えは同じ装着の面を入れ替えるだけで子が 2 組にならないので、「両方」は起きない見込みだが、この対の数からは確かめられない。
- **反映待ちの数は較正で 0 と確かめられない**。`calib-static` は差し替えを含まないので、反映待ちが本当は 0 枚なのに 1 枚と数えている（またはその逆の）見落としを較正では捕まえられない。床（本番の面の切り替え）との比べでしか読めない。
- **拡大率が 1 でない画面（k≠1.0）は未観測**。開発機の既定は 200% だが、この走行は全部 100% で行った。
- **反映待ちの 1 枚で窓が本当に食い違って見えたかは、画素から証明できない**。その 1 枚は数の上で大きさの食い違いにも入るが、(1) 層つきの窓の縁は透明なので、古い絵が新しい窓寸の中にあっても縁の外は何も見えず、画素からは区別できない、(2) tick の終わりの時刻は窓の移動（`SetWindowPos`）を流す前に打っていて、そこに 2〜6 ms の隙間がある——ので、画面で窓寸が本当に先に変わっていたかは分からない。
- **重なって見える「両方」の絵は混在として数え、大きさの食い違いには数えない**。開発者が基準の版の B→A で見た「Staysee の窓寸に kakukaku が切れて見えた」姿は、表の大きさの食い違いの列には現れない。

### 学び

この走行とコードで事実として確かめたものだけを書く。

- **`attach_target` の同じ id の再登録は古い子を残す**。`EmoPresenter::attach_target` は `targets` の表の中身を置き換えるだけで World に触れず（引数の World は使われていない）、新しい表示コンテキストは装着を持たない状態（`mount: None`）から始まるので、次の表示で新しい 2 つの子が窓に足され、古い 2 つの子は見える・当たるまま残る（実測: 基準の版は 9 走行すべてで絵も当たり判定も「両方」のまま未完・次の下ごしらえで消した子の数は 4）。同じ置き換えで、可視性の持ち主（`VisibilityOwnership`）は既定の `CommandDriven` に、窓寸の要求（`applied`・`native_size`・`pending_resize`）は空に戻る。**本坑で present に「古い装着を片付ける正規の口」を足す必要がある**（要件 5.7・5.8）。本命の版はそれを、窓の子を名前（`emo-surface`・`emo-text-layer-slot`）で外から探して消すことで代えた（`swap.rs` の `despawn_mounts`）。これは present の内部の物を外から消す行為で、本坑へは持ち込まない。
- **presenter には登録を消す口も無い**。`EmoPresenter` の公開の関数は登録（`attach_target`）・指令（`apply`）・可視性（`set_visibility_ownership`・`show_target`）・窓寸の要求の受け取り（`take_pending_resize`）・拡大率の追従（`refresh_scale`）・読み出し（当たり領域・寸法・今の面など）だけで、登録を消す関数は無い。較正や隠すだけの版で使った `TargetId`（この走行では 2〜6）の登録は、装着の子を消した後も表に残る。害は見ていないが、本坑の「片付ける口」の範囲に入る。
- **wintf の兄弟の重なり順は、描画と当たり判定で逆**。描画は `visual_hierarchy_sync_system` が `Children` を前から `InsertAtBottom` で積むので先頭の子が一番上、当たり判定（`hit_test_in_window`）は `DepthFirstReversePostOrder` で最後の子から調べる。古い子と新しい子が並ぶと「絵は古い方が上・当たり判定は新しい方が先」になる。描画の側は目視で確かめた（基準の版で古い子が上に見えた）。当たり判定の側はコードで確かめただけで、この走行では当たり判定は「両方」としか見えないので順は数に出ていない（範囲外の既存の食い違い）。
- **`VisualGraphics` の `on_remove` フックは、component が外れた時点で WUC の親から自分の visual を外す**（`on_visual_graphics_remove`）。だから古い子の despawn と新しい装着を `Update` の同じ呼び出しに入れると、1 回の反映に一緒に載る——本命の版 `@update` で空 0・古い絵の残り 0 だったのはこの形の結果。同じことを `FrameFinalize` で行うと、古い visual はその場で外れるのに新しい visual は次の tick まで作られないので、絵が空のフレームが 1〜2 枚出る（本命の版 `@finalize` の空 1〜2）。
- **wintf は窓の位置と大きさの変更を tick の中では積むだけで、`SetWindowPos` は tick の後に流す**（`flush_window_pos_commands` を tick の後に呼ぶ）。tick の終わりに `GetWindowRect` で読む矩形はまだ流す前の古い矩形なので、観測では積まれた変更から「その tick の後に効く矩形」を予測して使った（次の tick の実物と照合し、外れは 9 走行で 0）。`Update` で書いた窓寸は同じ tick の後に、`FrameFinalize` で書いた窓寸は次の tick の後に効く。
- **隠すだけの版を `FrameFinalize` で行うと、当たり判定が 1〜2 フレームどこにも当たらない**（絵は古いバルーンが見えているのに、クリックが素通りする隙間。debug 3 走行で 9 枚）。古いほうは隠れたが、新しいマスクはまだ効いていない。
- **面の切り替え（`\b[ID]` の経路）の反映待ち以外の崩れは 0**（9 走行すべて）。要件 2.7 の「本番の経路の既存の欠陥」に当たる崩れは出なかった。ただし反映待ちの 1 枚（絵は古いまま、当たり判定と窓の矩形だけ新しい）は本番の経路にも同じ形で在る。
- **`EmoWorld` は `Clone` でない**。`attach_target` は資産を値で受け取って消費するので、差し替えのたびに資産が要る。この先進坑では台本で要る数を起動時にまとめて作り置いた（A 19・B 14）。本坑で差し替えを繰り返すなら、資産をどこで作り直すか（または使い回せる形にするか）を決める必要がある。
- **画面の取り込み（Desktop Duplication）の前提**: スクリーンセーバー中（入力デスクトップが `Screen-saver`）は画面の複製の作成が `E_ACCESSDENIED` で拒否される。拡大率が 1 でないと標本点の座標が合わない。他の窓が重なるとその間は測れない。フレームは tick より多く来ることがあり（他の画面更新でも来る）、1 つの tick に複数のフレームが付くことがある。
