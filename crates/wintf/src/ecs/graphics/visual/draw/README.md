# visual描画戦略

## 差分の描き直し
描画の木を持つ描画面は、前の合成から変わった所だけを入れ物の中で描き直す。答えは毎回全部描いた答えとバイトで一致する（WARP のテストで固めている）。

### 項
描く列の Pop 以外の命令を、COM を持たない比べの項（`DamageEntry`・`diff.rs`）の列にする。項は件 1 つか層を積む命令 1 つで、同一性の鍵（親の層の鎖を含む）・平行移動を除いた鍵・画素を変えうる範囲（物理ピクセルの整数・外向き。にじみの余白を足す。`SOURCE_OVER` でない重ね方の件と、縮める `HIGH_QUALITY_CUBIC` の件は囲む矩形の切り抜きか全面）を持つ。層の鍵は節の実体と版。まとめ（`PushGroup`）の項の範囲は、閉じる重ね方が `SOURCE_OVER` なら部分木の範囲（1 枚を節の変換で描いた外接矩形とにじみの余白）、それ以外は囲む矩形の切り抜きか全面。まとめの中の項の範囲はまとめの範囲で切る。

### 比べ
前の合成の項の列と今の列を同一性の鍵で対にし、対の最長増加部分列に入らない項を動いた項とする（自前の LIS・`diff.rs`）。答えは消えた・足された・動いた・動かなかった項。

### 計画
描画面 1 枚ごとに、この回の描き方（`ComposePlan`・`../../damage.rs`）を決める: 何もしない・写すだけ（入れ物は描かず描画面へ写す）・全部（理由つき）・範囲だけ。範囲だけの回は、変わった項の範囲を 1 つの外接矩形にまとめ、その矩形を透明に塗って描き直す。決められない回は必ず全部へ倒す。
- 範囲だけの描き直しは、描く矩形と交わる件とまとめを丸ごと描く単位で行う。描く矩形を、交わる件とまとめの範囲で動かなくなるまで広げる（D2D は絵を恒等でない変換で描くと、答えが描く範囲に依って変わるため）。まとめの中の 1 つの子が変わった回は、まとめ 1 つの範囲を描き直す。広げた矩形が描画面の全面になれば全部へ倒す。
- 根の命令の列と描画の木を両方持つ描画面は、変化の在る回は全部で描く（根の命令の列の中の絵の答えも描く範囲で変わりうるため）。

### 写し
矩形の切り抜きの中身が物理ピクセルの整数だけ平行移動しただけの回は、入れ物の中で前の画素を写し（作業用の絵を通す）、露出した帯だけを描く。写しが効く木の形は次のとおり。
- スクロールの区画が自分の描画面を持つ（描画面の全面を写しの候補にする）か、動かない矩形の切り抜きの中に中身が在る。
- 根の命令の列が無い。区画の外の絵が区画に下からも上からも重ならない。親の鎖に図形の切り抜きとまとめが無く、中に `SOURCE_OVER` でない重ね方の件とまとめが無い（まとめの中は局所の解像度で描いてから重ねるので、物理ピクセルの写しと答えが揃わない）。
- スクロールの量を物理ピクセルの整数に置く。拡大を掛けて整数にならない量（例えば拡大 1.25 で 1 行が 15 論理ピクセル）では写さず、範囲だけの描き直しになる。
- 余白込みで行の範囲が重ならない。隣り合う行がにじみの余白で重なると、上の「件を丸ごと描く」規則で露出した帯が行から行へ広がり、写しの先まで描き直すことになって写しは捨てられる（答えは一致する）。

中身が描画面 1 枚に収まるなら、中身の Visual に `OwnSurface` を付けて自分の描画面にし、位置だけを動かす方がよい。位置だけの変化は親の描画面に触らず（自分の描画面の持ち主は親の描画面の木には入らず、WUC の位置だけが変わる）、自分の描画面も計画が何もしない（`skip`）になるので、描き直しも写しも 0 で済む。
- 命令の列だけを持つ持ち主: 拡大の変わらない位置だけの変化では描き直しの印が立たない。
- 描画の木を持つ持ち主: 根の配置の変化で木を組み直して印が立ち、項の列を比べるが、版は上がらず項は根からの相対なので計画は `skip` になる（組み直しと比べの手間は掛かる）。

前提は、区画の切り抜きが持ち主の WUC の切り抜き（`../../systems/clip_sync.rs`）で効くこと。動かすのは `Arrangement` の位置でも `VisualTransform` でもよい（持ち主の `VisualTransform` は WUC の変形に写る。下の「持ち主の `VisualTransform`」）。中身の持ち主は描画面の持ち主の直下でも節の下でもよい（下の「節の下の持ち主」）。

### 記録
合成の回ごとに target `wintf::damage` の debug の 1 行（`../../systems/render.rs`）を残す。欄は描画面の実体名（`entity`）・描き方（`mode`）・全部の理由（`reason`）・描き直した件の数（`items_redrawn`）・描く列の件数（`items`）・描き直した面積（`area`）・描画面の面積（`surface_area`）・写した面積（`shift_area`）・露出した帯の面積（`exposed_area`）・描画面へ写した面積（`present_area`）・合成の所要（`compose_us`）・描画面へ写す所要（`present_us`）。既存の性能の行とは別の行。

## 描く列

### 型の定義
型の定義はこの文書に写さない。正本はソース（`command.rs`・`builder.rs`・`clip_geometry.rs`・`../draw_tree.rs`）と `.kiro/specs/completed/wintf-visual-tree/design.md`。

### 節にする Visual
中身の無いまとめ役の Visual は、`WorldVisual` が無いと描画面の持ち主になり、子孫を訪れない。節にするには `VisualTransform`（恒等でも）を付ける。

### 層の旗と混ぜ方
描く中身の混ぜ方（`MixMode`）は、重ね方（`DrawImage` の 13 種）かブレンド（`ID2D1DeviceContext6::BlendImage` の 26 種・Windows 10 1903 以降。描き方が無ければ 1 度だけ `error!` を残して `SOURCE_OVER`）のどちらか 1 つ。不透明度の層は透明から始まり（`D2D1_LAYER_OPTIONS1_NONE`）、中の混ぜ方は同じ層の中で先に描いた画素に効き、降ろすとき不透明度を掛けて重なる。図形の切り抜きの層は背景の写しから始まり（`D2D1_LAYER_OPTIONS1_INITIALIZE_FROM_BACKGROUND`）、積む時点だけ基本の混ぜ方を `COPY` にするので、中の混ぜ方は切り抜きの形に依らず下の画素に効き、外側は変わらない。描画の木の答えは描画面ごとの入れ物（`../../composite.rs`）に合成してから WUC の描画面へ写し、入れ物の画素は `SurfaceReadback`（`../../readback.rs`）で読み戻せる。

### まとめの節
`VisualGroup { mix }`（`../group.rs`）を付けた節は、節と子孫を透明から始まる 1 枚に描き、閉じるとき節の変換を当てて `mix` で親の画素へ重ねる（描く列の `PushGroup`〜`PopGroup`）。
- 中の重ね方とブレンドは、同じまとめの中で先に描いた画素にだけ効く（中の `DESTINATION_IN` は親の画素に届かない）。
- 中は節の局所の座標（節の変換の前・1 DIP＝1 画素）の解像度で描く。拡大のある節では「原寸で描いてから拡大」になる。
- 同じ節では外から、不透明度の層 → まとめ → 切り抜き。`mix` が `SOURCE_OVER` でなければ、1 枚は今の軸に沿う切り抜きまで透明で広がって重なる（描く中身の件と同じ）。
- 描き方: `SOURCE_OVER` で、節の局所→物理の変換が整数の平行移動なら透明から始まる不透明度 1 の層。ほかは同じ装置の別の DC で作業用の絵（1 枚の範囲・`B8G8R8A8` 乗算済み・96 DPI）へ描き、`LINEAR` で親へ描く（`emit.rs`）。作業用の絵を作れなければ `error!` を残してまとめごと描かない。
- `VisualGroup` だけを外した回も描画の木を組み直す（`RemovedComponents` で拾う）。

## 画面の外の口
`render_tree_offscreen(device, world, root, size, root_transform)`（`../../offscreen.rs`）は、根の下の木を描く係と同じ順（世界の節を満たす → 組む → 描く）で、透明に塗った `size` の的へ描き、乗算済み BGRA（`OffscreenImage`）で読み戻す。視野は根の `Arrangement.size`、`root_transform` は DIP → 物理。窓も WUC も要らない（使い捨ての `World` でよい）。失敗は `error!` を残して `Err`。装置は描画面の入れ物と同じ合成（`../../composite.rs`）を通るので、同じ装置なら画面の入れ物と答えがバイトで一致する。`warp_d2d_device()` はプロセスで 1 つの WARP の D2D の装置を返す（テストと窓を出さない書き出し向け）。

## 描画面の自動の上げ下げ
更新が頻繁な節を wintf が自動で描画面の持ち主（自動の持ち主）へ上げ、落ち着いたら節へ戻す。判断は時刻を注入できる純粋な規則（`../promotion.rs`）、上げてよい形の見分けと自分の描画面の矩形の決めは `../promotion_shape.rs`、1 回の判断の配線は `../promotion_round.rs`。使い手は何も付けない（止める口も閾値の設定の口も無い）。上げ下げで画面の画素の答えは変わらない（全部を節にした形と、境界から離れた画素で 1 チャネルあたり ±1。WARP と実 GPU のテストで固めている）。

### 対象
窓の下の節（新しい描き方の部品を持ち、`GraphicsCommandList` と `OwnSurface` を持たない Visual）だけ。`GraphicsCommandList` を持つ Visual・何も持たない Visual・`OwnSurface` を持つ Visual の描画面の有無は自動では変えない。使い手が自動の持ち主へ `OwnSurface` を付けると、付いている間は手動の持ち主になる。外すと規則 `wants_own_surface` の答えへ戻り、節なら改めて判断の対象になる。

### 材料と定数
材料は節の「描き直しの印」（部分木の件が変わった回）の時刻つきの履歴。定数は `../promotion.rs` の 1 か所で、1 秒の窓の中に 8 回で上げる（`PROMOTE_COUNT`・`PROMOTE_WINDOW`）。3 秒更新が無ければ戻す（`DEMOTE_QUIET`）。上げた後と戻した後は、それぞれ 3 秒は逆向きの判断をしない（`HOLD_AFTER_PROMOTE`・`HOLD_AFTER_DEMOTE`）。数コマで止まるまばたきは上げず、口の動きのように動き続ける部品を上げる。静かな間の戻しは心拍で拾う（遅れは最大約 0.5 秒で画素に出ない）。

### 相
節 → 用意中 → 上げた形の 3 つ（`AutoPromotion`）。用意中の 1 回は、部分木を節として親の描画面にも自分の描画面にも描き、描画面が出来た次の回に切り替える（切り替える答えを出したフレームのうちに画面の画素を切り替える・遅らせない）。戻すときも同じ。部分木を 2 か所で描く費用が用意中の 1 回に掛かる。

### 見送りと戻し
上げると画素が変わる形の節は上げず、節のまま描く。上げた後にその形になったら履歴を待たずにそのフレームのうちに戻す（戻した後は上げる側の履歴を掛ける）。形は次のとおり（`../promotion_shape.rs` の `Ineligible`・括弧の中は記録の `shape=` の語）。
- 同じ描画面の中で後に描く中身と重なる（`later_content_overlap`）。
- 部分木の中に手動の持ち主が在る（`contains_owner`）。
- 祖先の節の不透明度の層（1 未満）か図形の切り抜き（角丸・任意の図形）か軸に沿わない矩形の切り抜き（D2D では図形の層で描く）かまとめの節の中に在る（`ancestor_layer`）。上げると 1 枚の外へ出て答えが変わる。
- 部分木に `SOURCE_OVER` でない混ぜ方の件か、`SOURCE_OVER` でない重ね方で閉じるまとめの節が在る（`non_source_over`）。後に描く中身の `SOURCE_OVER` でない件も、位置によらず重なりとみなす。
- 部分木の描く範囲が、親の描画面と祖先の節の矩形の切り抜きの交わりに収まらない（`out_of_bounds`）。
重なりと収まりの判定は、物理ピクセルの整数へ外向きに丸めた外接矩形に、にじみの余白（`diff.rs` と同じ規則）を足して行う。手動の持ち主との重なり・回転や拡大を含む変形・角丸や図形の自分の切り抜き・端数の位置は、画素を変えないので見送りの理由にしない。そのほか、見えない節（`hidden`）と、描画面を作れない（装置が無い `no_device`・作るのに失敗した）節は上げない・節へ戻す。記録は target 既定の `debug!` の 1 行で、`[surface_promotion] promoted`（用意中へ入った回・`reason=frequent`）・`[surface_promotion] activated`（用意中から上げた形へ切り替えた回）・`[surface_promotion] demoted`（`reason=` が `quiet`・`shape`・`hidden`・`absorbed`・`surface_failed`。`shape` のときは `shape=` も付く）・`[surface_promotion] skipped`（`shape=` に上の語。同じ語が続く間は繰り返さない）を残す（`../promotion_round.rs`）。

### 自動の持ち主の描画面
描画面の矩形は、用意中の回に部分木の描く範囲（物理ピクセルへ外向きに丸め・にじみの余白込み・親の描画面と祖先の矩形の切り抜きで切ったもの）から決め、原点をその左上の整数の物理ピクセルに置く。世界の位置の端数は自分の描画面の中でずらして描き、WUC の位置は整数に置く。範囲がはみ出したら自分の描画面だけを作り直して全部描き直す（親には触らない・縮むほうは追わない）。部分の列（`TreeFrame::Segment`）は自分の描画面の物理ピクセルで出し、再生の根の変換は恒等・`diff::entries` の拡大は (1,1) にする（`DrawTree.device_px`・`render.rs`。さもないと DPI の拡大が二重に掛かる）。自分の不透明度・切り抜き・変形は部分の列が D2D の命令で描く。WUC の側は位置・大きさだけを写し、不透明度は 1・変形は恒等・切り抜きは外す。

## 節の下の持ち主
描画面の持ち主（今の描き方の Visual・`OwnSurface` を持つ Visual・自動の持ち主）は節の子孫に在ってよい。部分木を切らず、`error!` も残さない。節の下の持ち主の子孫の節は、その持ち主の描画面に描き、祖先の持ち主の描画面には描かない。`fill_world_visuals` は節の下の持ち主に置き場（`SurfacePlacement`・`../placement.rs`）を記す。
- WUC の木: いちばん近い祖先の持ち主の Visual を親にし、節を通り抜けた前順で子を並べる。節の下から外れた・消えた・節へ戻った持ち主は、古い親の子から外す。`Children` の並びだけが変わった回も同じフレームのうちに並べ直す。
- 重なりの順: 同じ祖先の持ち主の下の手動の持ち主（直下の持ち主と節の下の持ち主）は今までの規則どおり木の前順（`Children` の並び）で、前順で先の持ち主が上（前順に `InsertAtBottom` で入れるので WUC の最初の子が最上。`../placement.rs` の `wuc_children_order`）。自動の持ち主は、その祖先の持ち主の WUC の子の一番下（手動の持ち主すべての下）に並べ、自動どうしは描く順（前順で後が上）にする。自動の持ち主の順は全部を節にした形と同じになる。
- 位置: 祖先の節の局所の変形と配置（`Arrangement`）を、いちばん近い祖先の持ち主まで重ねた行列と DPI の拡大で決める（WUC の `Offset` は物理ピクセル）。祖先の節の変形・配置・親子のつながりが変わった回に同じフレームのうちに合わせ直す。
- 祖先の節の性質: 見えない（`is_visible` が偽か不透明度 0）なら出さない。不透明度は積を掛ける。矩形の切り抜きは持ち主の WUC の切り抜きに合わせる（持ち主の変形（局所から祖先の持ち主まで）が軸に沿えば局所へ移した 1 つの矩形の `Rect`、沿わなければ `CompositionClip.TransformMatrix` に逆行列を入れる `Transformed`。`../placement.rs` の `merged_clip` を `../../systems/clip_sync.rs` が呼ぶ・鍵 `ClipKey` は当てた置き場の切り抜き `PlacedClip` を持つ）。
- 効かせられない形（手動の持ち主のみ）: 祖先の角丸か図形の切り抜き（`geometry_clip`）・軸に沿わない祖先の矩形の切り抜き（`rotated_clip`）・祖先の `SOURCE_OVER` でない混ぜ方（`blend`）・同じ描画面の中で後に描く中身との重なり（`later_overlap`）・祖先の矩形の切り抜きの下で、自分の角丸の切り抜きか軸に沿わない自分の矩形の切り抜きがその矩形からはみ出す、または自分の図形の切り抜きを持つ（`clip_combo`・`../promotion_round.rs`）。実体名つきの `warn!`（`[surface_promotion] 節の下の持ち主に効かせられない形`・欄 `kind` に括弧の中の語）を種類ごとに続く間 1 度だけ残す。`geometry_clip`・`rotated_clip`・`clip_combo` のときは祖先の切り抜きを捨てて自分の切り抜きだけを写し、`blend`・`later_overlap` のときは祖先の矩形の切り抜きも効かせる。見た目は全部を節にした形と違いうる。

## 持ち主の `VisualTransform`
描画面の持ち主の `VisualTransform` は、節のときと同じ意味（局所の変形 × `Arrangement` の位置）で WUC の `TransformMatrix` に写り、その持ち主とその下の木の見た目に効く（以前の `warn!` で無視する作りは無い）。変形が平行移動だけなら今までどおり `Offset` だけを写す。節の下の持ち主は祖先の節の行列を掛けて写す。持ち主の `VisualTransform` の変化は版を上げない（`../version.rs`）。自動の持ち主の変形は部分の列が描くので WUC へは写さない。

## 当たり判定との差
当たり判定は今の作り（`GlobalArrangement`）のままで、`VisualTransform` を見ない。回転・拡大を含む `VisualTransform` を持つ持ち主は、見た目と当たりの領域がずれうる（平行移動だけならずれない）。この spec では直さない。

## 読み戻し
`SurfaceReadback` は描画面ごとの入れ物を読む。自動で上げた部分木は自分の描画面の入れ物へ描かれ、親の描画面の読み戻しには載らない（上げ下げで親の読み戻しの画素が変わる）。今の使い手は wintf 自身のテスト（`readback_test`・`composite_systems_test`・`surface_embedding_test` ほか）だけで、上げ下げを確かめるテストは親と自分の描画面の両方を読んで答えを決める。

### 入れ物の α の当たり
`surface_alpha_at(world, owner, x, y)`（`../../readback.rs`）は、描画面の持ち主の物理ピクセルの α を入れ物から 1 画素その場で読む（前のフレームの値も CPU の α の表も使わない）。答えは `AlphaRead`（`Alpha(a)`・`Outside`・`Unreadable`）。判定の順は `read_pixel` と同じで、同じ座標・同じ世代は控えが答える。持ち主の子孫に上げた形の自動の持ち主が在れば、その入れ物も原点 `origin_px` からの座標で読み、`1-(1-a)(1-b)` で重ねる（上げられる部分木は `SOURCE_OVER` だけ）。用意中の自動の持ち主（まだ親の描画面にも描かれている）と、手動の持ち主の下は重ねない。子孫の入れ物が読めなければ全体が `Unreadable`。
当たりの形 `HitTestMode::SurfaceAlpha`（`HitTest::surface_alpha()`・`../../../layout/hit_test/mod.rs`）は、点から `GlobalArrangement.bounds` の左上を引いて切り捨てた座標で読み、α が 128 未満・`Outside`・`Unreadable` なら当たらない。読めない間は持ち主ごとに最初の 1 回だけ `error!`（`[hit_test] surface alpha unreadable, no hit`）を残し、読めたら印を戻す。この 128 の閾値と印は公開の `surface_alpha_hits(world, owner, x, y)` が持ち、areka-emo-present の当たりの名前の解決も同じ口を呼ぶ（同じ原因で 2 件にならない）。

## 既定を「描画面なし」へ寄せる道筋
今の描き方の Visual（`GraphicsCommandList` を持つ）と何も持たない Visual の既定（描画面の持ち主）は、この spec では変えない。新しい描き方の Visual の既定（節）は保ち、自動の上げ下げはその上に足してある。何も持たない Visual（`WorldVisual` が無い Visual・中身の無いまとめ役など）は、今でも `VisualTransform`（恒等でも）を付ければ節になる（上の「節にする Visual」）。既定で節にするには、次の条件がそろう必要がある。
- 何も持たない Visual にも `WorldVisual` を付け、規則 `wants_own_surface` の答えを節にする（命令の列も `OwnSurface` も無いとき）。
- その子孫の持ち主が節の下に置ける（この spec で出来た。上の「節の下の持ち主」）。
- 何も持たない Visual の描画面を読む使い手（`SurfaceReadback`）が無いか、読む先を移してある。
- 節にした後の画素が今の描画面の持ち主の形と一致する（WARP の比べで確かめる）。

今の描き方の Visual を節にするには、次の条件がそろう必要がある。
- 命令の列を祖先の描画面へ描き込む作りがある（今は無く、命令の列は持ち主の描画面にしか描けない）。
- emo の部品（シェル・バルーンの文字など）が命令の列から描画の木（`VisualDrawContent`・`VisualTransform`）の描き方へ移っている。
- 移した後の画素が今の描画面の持ち主の形と一致する（WARP の比べで確かめる）。
これを受け持つのは後の spec（emo の部品を描画の木へ移す `draw-methods-canon`。関連して `shell-multi-compose`・`balloon-text-visual-tree`）。何も持たない Visual の既定を変える spec は、まだ決まっていない。条件がそろった部品から節へ寄せ、頻繁に変わる部品だけを自動の上げ下げが描画面へ上げる。

## ID の描き先
画面に出ない ID の描き先（`IdTarget`・`../../id_target.rs`・`wintf::ecs` から公開）。形の列を ID の色で塗り、点の 1 画素から ID を読む。当たり判定の形の答えを GPU の絵で持つための部品で、描画面（`SurfaceReadback`・WUC）には結び付かない。

### 公開の名前
`MAX_ID`（ID の上限・24 ビット）・`IdForm`（`Rect`・`Ellipse`・`Polygon`・`Mask { mask, left, top }`）・`IdShape`（`id` と `form`）・`IdRead`（`Id`・`Empty`・`Outside`・`Unreadable`）・`IdMask`・`IdMaskPictures`（`len`・`created`）・`IdTarget`（`new`・`paint`・`read`・`generation`）。

### 求め方
`IdTarget::new(core, (w, h))` に大きさ（一辺 1〜16,384 の物理ピクセル）だけを渡す。どの描画面の大きさにも結ばない。装置（`GraphicsCore`）が無いか大きさが範囲外なら `Err`。形式は `B8G8R8A8_UNORM`・α 掛け済み・96 DPI。

### 塗り方
`paint(core, shapes, pictures)` は UI スレッドから呼ぶ。透明に消してから、列の順に上書きして塗る（後の形が先の形の上に載る）。
- 縁のぼかしは掛けない（画素ごとに ID か ID なしのどちらか）。
- ID は不透明の色（B＝下位 8 ビット・G＝中位・R＝上位・A＝255）で塗る。`MAX_ID` を越える ID を含む列は塗らずに失敗にする。
- `Polygon` は書いた順の頂点を最後から最初へ閉じ、巻き数が 0 でない所を塗る。
- `Mask` はマスクの左上を (`left`, `top`) に 1 対 1 で置き、立っている画素にだけ ID を置く（拡大も補間もしない）。座標は描き先の画素の単位で、左上が (0, 0)。
- マスク（`IdMask::new(width, height, is_set)`・一辺 1〜16,384）の GPU の絵は `IdMaskPictures` が持つ。同じ `Arc<IdMask>` の実体は 1 度だけ GPU へ載せ、以後の `paint` では引くだけ（載せた回数は `created`、覚えている絵の数は `len`）。
- 塗り終えるごとに `generation` が 1 上がる。塗りが失敗したら 0 に戻る。

### 読み戻しの答え
`read(x, y)` は最後に塗り終えた絵の 1 画素の答えを返す。
- `Id(id)`: その画素に ID が塗られている。
- `Empty`: 塗られていない画素（ID なし）。
- `Outside`: 座標が描き先の外。GPU は読まない。
- `Unreadable`: まだ塗っていない・装置が無いか失われた・塗りか読みが失敗した。
同じ座標は塗り直すまで読み直さない（控えを返す）。読みが失敗したら 1 度だけ記録し、塗り直すまで GPU に触らずに `Unreadable` を返し続ける。読みは GPU が塗りを終えるまで待つ。

### 装置の作り直し
`IdTarget` と `IdMaskPictures` は装置に結び付く。装置が作り直されたら、使い手が新しい `IdTarget` と新しい `IdMaskPictures` を作って塗り直す。古い `IdMaskPictures` を別の装置へ渡した `paint` は失敗になる。
