# visual描画戦略

## 差分の描き直し
描画の木を持つ描画面は、前の合成から変わった所だけを入れ物の中で描き直す。答えは毎回全部描いた答えとバイトで一致する（WARP のテストで固めている）。

### 項
描く列の Pop 以外の命令を、COM を持たない比べの項（`DamageEntry`・`diff.rs`）の列にする。項は件 1 つか層を積む命令 1 つで、同一性の鍵（親の層の鎖を含む）・平行移動を除いた鍵・画素を変えうる範囲（物理ピクセルの整数・外向き。にじみの余白を足す。`SOURCE_OVER` でない重ね方の件と、縮める `HIGH_QUALITY_CUBIC` の件は囲む矩形の切り抜きか全面）を持つ。層の鍵は節の実体と版。

### 比べ
前の合成の項の列と今の列を同一性の鍵で対にし、対の最長増加部分列に入らない項を動いた項とする（自前の LIS・`diff.rs`）。答えは消えた・足された・動いた・動かなかった項。

### 計画
描画面 1 枚ごとに、この回の描き方（`ComposePlan`・`../../damage.rs`）を決める: 何もしない・写すだけ（入れ物は描かず描画面へ写す）・全部（理由つき）・範囲だけ。範囲だけの回は、変わった項の範囲を 1 つの外接矩形にまとめ、その矩形を透明に塗って描き直す。決められない回は必ず全部へ倒す。
- 範囲だけの描き直しは、描く矩形と交わる件を丸ごと描く単位で行う。描く矩形を、交わる件の範囲で動かなくなるまで広げる（D2D は絵を恒等でない変換で描くと、答えが描く範囲に依って変わるため）。広げた矩形が描画面の全面になれば全部へ倒す。
- 根の命令の列と描画の木を両方持つ描画面は、変化の在る回は全部で描く（根の命令の列の中の絵の答えも描く範囲で変わりうるため）。

### 写し
矩形の切り抜きの中身が物理ピクセルの整数だけ平行移動しただけの回は、入れ物の中で前の画素を写し（作業用の絵を通す）、露出した帯だけを描く。写しが効く木の形は次のとおり。
- スクロールの区画が自分の描画面を持つ（描画面の全面を写しの候補にする）か、動かない矩形の切り抜きの中に中身が在る。
- 根の命令の列が無い。区画の外の絵が区画に下からも上からも重ならない。親の鎖に図形の切り抜きが無く、中に `SOURCE_OVER` でない重ね方の件が無い。
- スクロールの量を物理ピクセルの整数に置く。拡大を掛けて整数にならない量（例えば拡大 1.25 で 1 行が 15 論理ピクセル）では写さず、範囲だけの描き直しになる。
- 余白込みで行の範囲が重ならない。隣り合う行がにじみの余白で重なると、上の「件を丸ごと描く」規則で露出した帯が行から行へ広がり、写しの先まで描き直すことになって写しは捨てられる（答えは一致する）。

中身が描画面 1 枚に収まるなら、中身の Visual に `OwnSurface` を付けて自分の描画面にし、位置だけを動かす方がよい。位置だけの変化は親の描画面に触らず（自分の描画面の持ち主は親の木から切られる）、自分の描画面も計画が何もしない（`skip`）になるので、描き直しも写しも 0 で済む。
- 命令の列だけを持つ持ち主: 拡大の変わらない位置だけの変化では描き直しの印が立たない。
- 描画の木を持つ持ち主: 根の配置の変化で木を組み直して印が立ち、項の列を比べるが、版は上がらず項は根からの相対なので計画は `skip` になる（組み直しと比べの手間は掛かる）。

前提が 2 つある。中身の持ち主は描画面の持ち主の直下に置く（節の下に置いた描画面の持ち主は、その部分木ごと切られて `error!` が残る）。区画の切り抜きは持ち主の WUC の切り抜き（`../../systems/clip_sync.rs`）で効く。動かすのは `Arrangement` の位置で行う（描画面の持ち主の `VisualTransform` は WUC では効かず、`warn!` を残して無視される）。

### 記録
合成の回ごとに target `wintf::damage` の debug の 1 行（`../../systems/render.rs`）を残す。欄は描画面の実体名（`entity`）・描き方（`mode`）・全部の理由（`reason`）・描き直した件の数（`items_redrawn`）・描く列の件数（`items`）・描き直した面積（`area`）・描画面の面積（`surface_area`）・写した面積（`shift_area`）・露出した帯の面積（`exposed_area`）・描画面へ写した面積（`present_area`）・合成の所要（`compose_us`）・描画面へ写す所要（`present_us`）。既存の性能の行とは別の行。

## 描く列

### 型の定義
型の定義はこの文書に写さない。正本はソース（`command.rs`・`builder.rs`・`clip_geometry.rs`・`../draw_tree.rs`）と `.kiro/specs/completed/wintf-visual-tree/design.md`。

### 節にする Visual
中身の無いまとめ役の Visual は、`WorldVisual` が無いと描画面の持ち主になり、子孫を訪れない。節にするには `VisualTransform`（恒等でも）を付ける。

### 層の旗と混ぜ方
描く中身の混ぜ方（`MixMode`）は、重ね方（`DrawImage` の 13 種）かブレンド（`ID2D1DeviceContext6::BlendImage` の 26 種・Windows 10 1903 以降。描き方が無ければ 1 度だけ `error!` を残して `SOURCE_OVER`）のどちらか 1 つ。不透明度の層は透明から始まり（`D2D1_LAYER_OPTIONS1_NONE`）、中の混ぜ方は同じ層の中で先に描いた画素に効き、降ろすとき不透明度を掛けて重なる。図形の切り抜きの層は背景の写しから始まり（`D2D1_LAYER_OPTIONS1_INITIALIZE_FROM_BACKGROUND`）、積む時点だけ基本の混ぜ方を `COPY` にするので、中の混ぜ方は切り抜きの形に依らず下の画素に効き、外側は変わらない。描画の木の答えは描画面ごとの入れ物（`../../composite.rs`）に合成してから WUC の描画面へ写し、入れ物の画素は `SurfaceReadback`（`../../readback.rs`）で読み戻せる。
