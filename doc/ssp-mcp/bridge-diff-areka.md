# SSP の中継と areka の中継の差（rmcp 3.5.0・2026-10-10 測定）

Claude Desktop の設定は `command` で起こす標準入出力のサーバーしか書けないので、SSP も areka も、標準入出力と HTTP の MCP の口をつなぐ小さな実行ファイルを配る。この文書ではそれを「中継」と呼ぶ（SSP は `data\mcp.exe`、areka は `areka-mcp-bridge.exe`）。同じ入力に 2 つの中継が何を返すかを行ごとに並べ、違う行には理由を書く。比べるのは字の並びではなく意味（欄と値）。SSP の本体と areka の本体の HTTP の口どうしの差は [transport-diff-areka.md](transport-diff-areka.md) にある。areka の中継の版を上げたとき・rmcp の版を上げたときは、表のテストを回してこの表を測り直す。

- **測った版と日**: areka の中継は rmcp 3.5.0・2026-10-10（spec `areka-P0-mcp-stdio-bridge` の実装の時点・main `414d43eb` の上）。areka も控えも無いときの組み込みの答え（2 節・3 節の当たる行と、4 節の「組み込みの答え」の行）は 2026-10-11 に足した。SSP の中継は開発者の机の `C:\wintools\ssp\data\mcp.exe`（94,208 バイト・2026-09-24 の日付）を 2026-10-10 に測った
- **SSP の欄**: 9801 に記録を取る偽のサーバーを立てた場合（1 節）と、何も居ない場合（2 節・答えの控えがある・無いの 2 通り）で、標準入力へ要求を流して出力を記録したもの。記録の正本は spec `areka-P0-mcp-stdio-bridge` の `requirements.md` の節「SSP の中継 `mcp.exe` の実測」で、1 節と 2 節の SSP の欄はその表の行を全部、同じ文で写した。「未実測」は SSP で測っていないもの、「対応物なし」は SSP にその仕組みが無いもの。2026-09-29 の実測（[survey.md](survey.md) §6）から引いた欄はその旨を書いた
- **areka の欄**: `crates/areka-mcp-bridge/` のテストの assert から写した。最後の列がそのテストの名前（ファイル名＋テスト関数の名前）。テストで固定していない事実は「テストなし」と書き、根拠の定義（関数名＋ファイル）か、rmcp の決まりであることを添えた
- **SSP の中継を測り直すときの注意**: SSP の中継は、通った `initialize` の答えを SSP のフォルダの控えに書く。2026-10-10 の測定では、偽のサーバーの答えで開発者の SSP の控えを上書きした（開発者の了承を得て取り除いた）。測り直すのは開発者の了承の下で行う。areka の中継のテストは、SSP とその控えにも、机の 9801〜9830 にも触れない
- **判定の数**: 実測の表の 16 行のうち 同じ 3 行・違う 13 行。SSP で未実測の 3 点（3 節）。areka の中継だけにある決まり 22 行（4 節）

## 言葉

| 言葉 | 意味 |
|---|---|
| 中継 | 標準入力の要求を HTTP の MCP の口へ届け、応答を標準出力へ返す実行ファイル |
| 受け口 | 本体（areka・SSP）が `127.0.0.1` で待ち受ける HTTP の MCP の口（`POST /api/mcp/v1`） |
| Desktop | 中継を起こして、標準入力へ要求を書き、標準出力の応答を読む側（Claude Desktop など） |
| 控え | 中継が前に受け口から受け取った答えを、ファイルに取っておいたもの。受け口が居ないときの答えに使う |
| 組み込みの答え | areka の中継が実行ファイルの中に持っている、サーバーの情報とツールの一覧。areka の受け口が居らず、当たる控えも無いときの答えに使う（4 節） |
| 名乗り | `initialize` の答えの `serverInfo.name`。areka は `areka-mcp-server`、SSP は `ssp-mcp-server` |
| 確かめ | 相手の名乗りを読むために、areka の中継が自分で送る `initialize` |
| つなぐ先 | areka の中継が、areka の受け口だと確かめて覚えた番号と、そこへ立てた rmcp のクライアント。失敗によっては捨てて、探し直して作り直す |
| 札 | HTTP のヘッダ（`MCP-Protocol-Version`・`Mcp-Method`・`Mcp-Name` など） |
| rmcp の受け手 | areka の中継の中で、Desktop の側の要求を受ける rmcp の部品（要求ごとに仕事を起こし、応答の行を書く） |
| 送り手 | areka の中継が、areka の受け口へ HTTP で送るために自前で持つ部品（`crates/areka-mcp-bridge/src/http.rs` の `OwnHttp`） |
| 旧式の話し方 | `initialize` で始める 4 つの版（`2025-11-25`・`2025-06-18`・`2025-03-26`・`2024-11-05`）の送り方 |
| `2026-07-28` の話し方 | `initialize` を使わず `server/discover` で始め、要求ごとに `params._meta` へ版・クライアントの名乗り・できることを載せる送り方 |

## 2. 受け口が居ないとき

SSP の欄は、9801 に何も居ないときの値。areka の欄は、候補のどの番号にも areka の受け口が居ないとき（何も居ない・areka でない相手だけが居る、の両方）の値。

| 入力・場面 | SSP の中継（`mcp.exe`） | areka の中継（`areka-mcp-bridge.exe`） | 判定と理由 | areka の値を固定するテスト |
|---|---|---|---|---|
| `ping` | 自分で `{"jsonrpc":"2.0","id":<id>,"result":{}}` と答える（控えの有無に関わらず） | 同じ行を自分で答える（控えの有無にも、要求の話し方にも関わらず `{}`） | 同じ | `service_tests.rs` の `without_areka_the_cache_answers_the_first_inquiries_and_the_tool_list`・`without_areka_an_inquiry_with_no_cache_of_its_kind_gets_the_built_in_answer`（話し方を見ないことは `service.rs` の `Bridge::absent`） |

## 残る縛り

- **areka の受け口が SSE を返すようになったら**（ツールが途中で通知や要求を出す）、中継はそれを 1 節の `Invalid JSON response from server: HTTP 200 content-type text/event-stream` のエラーにする。SSE を返す変更は、先に中継の HTTP の送り手（`crates/areka-mcp-bridge/src/http.rs` の `OwnHttp`）を SSE に対応させる。
- **10 秒より長く待つツールを足すとき**は、中継の応答の上限（`crates/areka-mcp-bridge/src/config.rs` の `REPLY_WAIT`＝30 秒）も見直す。areka のツールの上限（`areka_mcp::tools::REPLY_WAIT`）のほうが長くなると、`config_tests.rs` の `reply_wait_is_longer_than_the_areka_tool_limit` が赤になる。
- **rmcp の版を上げるとき**は、中継のテストも全部通す（`cargo test -p areka-mcp-bridge`。本物の受け口を相手にするのは `tests/real_receiver_test.rs` と、`http_tests.rs`・`scan_tests.rs` の一部）。4 節で「rmcp の決まり」と書いた行（最初の `2026-07-28` の要求を 1 つだけで送る・`x-mcp-header` のツール外し・上限を越えたときの `notifications/cancelled`・標準入力が閉じた後の 5 秒・`id` の形が違う要求の読み方・同時に出せる要求は 16 件まで）は、テストで固定していないので、版を上げたら読み直す。控えの形は rmcp の型そのものなので、形が変わって読めなくなった控えは、無いものとして作り直される。
- **areka の受け口が取り消しを聞くようになったら**（SSE・セッションを持つ形）、Desktop の `notifications/cancelled` を、rmcp のクライアントが振り直した番号に直して届ける。今は届けない。
- **SSP の中継の未実測の 3 点**（3 節）は、測ったらこの表に書き足す。

## 補足

- テスト名は `crates/areka-mcp-bridge/` の `src/` の兄弟のテストファイル（`stdio_tests.rs`・`http_tests.rs`・`scan_tests.rs`・`cache_tests.rs`・`config_tests.rs`・`errors_tests.rs`・`service_tests.rs`・`service_failure_tests.rs`・`service_retry_tests.rs`）と、`tests/` の通しのテスト（`real_receiver_test.rs`・`exe_test.rs`）のもの。相手にするのは、台本で答える偽の受け口（`tests/common/fake_server.rs`）と、空きポートに起こした本物の受け口（`areka_mcp::start`）。
- areka の中継が Claude Desktop とどの版で話すかは、実機確認の記録（spec `areka-P0-mcp-stdio-bridge` の `verification/signoff.md`）に残す。
- 2026-09-29 の実測（[survey.md](survey.md) §6）の「JSON でない行の直後の `no/such` に応答が出なかった」は、1 節の「入力の切り方」で説明が付く: JSON でない行と次の要求が 1 つの本文として送られ、1 つのエラーで答えられた。終了も握りつぶしもしていない。
