# 机の貸し出し（areka-impl-watch）の手順

同じマシンで実装の Claude セッションを何本も並べて進めるときに、「実装の机」「排他テストの机」「マージの机」の 3 種類の机を貸し出すコンソールアプリ `areka-impl-watch` の、入れ方・更新・呼び方・困ったときの手順である。

各セッションは Bash から実行ファイルを直接呼ぶ。「待つ」は、バックグラウンドで走らせたコマンドが番が来るまで終わらないことで表し、「止まる合図」は、走らせておいた見張りのコマンドが終わることで表す。セッション同士のメッセージは 1 通も使わない。

## 1. 何をするものか

### 机は 3 種類

| 机 | 数 | 乗り方 | 守るもの |
|---|---|---|---|
| 実装の机 | マシンに 1 つ | 実装が走る机。何人でも乗れる。負荷テストがひとり占めできる | 計測のための静かな CPU（ひとり占めの間だけ） |
| 排他テストの机 | マシンに 1 つ | 同時に 1 人だけ。全体テスト・UI テストを回す者が取る | 窓・入力・前面と、メモリやビルド。2 つ同時に回すと取り合って偽の赤が出る |
| マージの机 | リポジトリごとに 1 つ | マージの作業が取る | 1 リポジトリに 1 つしかないファイル（`roadmap.md`・台帳の数・生成した報告）。同時にマージすると競合する |

する事ごとに取る机:

| する事 | 取る机 |
|---|---|
| 実装 | 実装の机に乗れたら実装する（見張りを立てて「作業中」でいること） |
| 全体テスト・UI テスト | 排他テストの机（`request --desk test`） |
| 負荷テスト | 排他テストの机と、実装の机のひとり占め（`request --desk test,sole`。ほかの全員を止める） |
| areka のマージ | マージの机と、全体テストをするので排他テストの机（マージの机を持ったまま `request --desk test`） |
| pasta のマージ | マージの机だけ |

どの段が「全体テスト・UI テスト」で、どの段が「負荷テスト」かは、下の「判定の基準」で決める。

この文書で使う言葉:

- **参加者**: 貸し出しを受けると申し出たセッション。呼ぶときに渡す**識別**（`--id`）で区別する。識別はセッションごとに 1 つ決め、最初から最後まで同じものを渡す。
- **実装の机に乗る**: 参加者が「作業中」でいること。見張りを立てて参加した参加者は、実装の机に乗っている。
- **申し込み**・**返す**: 欲しい机を 1 つ以上並べて番を待つことと、持っている机を空けること。排他テストの机とひとり占めは `request` で申し込んで `return` で返し、マージの机は `merge` で申し込んで `merged` で空ける。
- **持ち主**・**待ち行列**: 机を持っている参加者と、番を待つ申し込みの並び。
- **ひとり占め**: 実装の机の上の持ち方。ほかの参加者全員に停止要請を出し、全員が「止まった」ところで受け取る。`--desk` には `sole` と書く。
- **停止要請**: ひとり占めのために、参加者へ「今のタスクをコミットした切れ目で止まってほしい」と求めること。
- **見張り**: 参加者が走らせ続けるコマンド `watch`。自分宛ての停止要請が出たら終わる。走っていることが、その参加者が「居る」ことの印でもある。
- **再開**: 止まっていた参加者が作業を続けてよくなること。
- **置き場所**: 環境変数 `AREKA_IMPL_WATCH_HOME` が指すフォルダ。実行ファイルと状態のファイルを全部ここに置く。

参加者の状態は 3 つで、`status` には英字で出る: 作業中（`working`）・停止要請中（`stop-requested`）・止まった（`stopped`）。

### 決まり

1. 実装の机には何人でも乗れる。乗る人数に上限は無い。
2. 排他テストの机は 1 度に 1 人。渡すときも、待つときも、持つときも停止要請を出さない（全体テストや UI テストの番を待つ間も持つ間も、ほかの参加者は作業中のまま）。
3. ひとり占めは、ほかの参加者全員が「今のタスクをコミットした」ところで止まってから渡る。実行の途中では止めない。
4. 1 つの申し込みに並べた机は、全部渡せるときにだけ、同じ呼び出しの中で一度に渡る。一部だけを先に渡さない。
5. 番は申し込みの早い順に見て、並べた机が全部渡せる申し込みへ順に渡る。渡せない申し込みは後ろを止めない（先の申し込みのために机を取っておかない）。
6. ひとり占めを含む申し込みが待たれている間は、排他テストの机を、停止要請中の参加者とマージの机を持つ参加者のほかには渡さない。
7. 「止まった」の参加者には、ひとり占めを含まない申し込みの机を渡さない（再開すると、同じ呼び出しの中で渡る）。排他テストの机を持つ参加者が「止まった」と報告すると、その机は空く。
8. ひとり占めが持たれている・待たれている間は、どのリポジトリでも新しいマージを始めない（pasta のマージも同じ）。リポジトリの中のマージの順は、バグの修正（`--bug`）が先、次に申し込みの早い順。
9. マージの机を持っている・待っている者は止めない。マージの机を持つ者は「済んだ」と言うまで止めない。
10. すでに走っている負荷テストは、停止要請を出さずに、排他テストの机とひとり占めの両方の持ち主として記録できる。出した停止要請は取り消せる。
11. 排他テストの机とひとり占めの持ち主は、ほかの番を待たずに、走行が終わったら（成否によらず）返す。

持ちながら申し込めるのは、マージの机を持つ者が排他テストの机を足すときだけである。次の呼び方は、状態を変えずに終了コード 3 で断られる（`--wait` があっても待たない）: 排他テストの机かひとり占めを持つ者の `merge`・机の申し込みを待つ者の `merge`・マージの机を待つ（まだ持たない）者の `request` と `loadrunning`・机を持つ者の別の組の `request`・待っている申し込みと違う組の `request`。こうして待ちの向きは「マージの机の持ち主 → 排他テストの机」だけになり、互いに待って止まる輪は生まれない。

停止要請が出ないのは、ひとり占めの持ち主（持ち主が居なければ、ひとり占めを含む申し込みのうち最も早いもの）自身と、どこかのリポジトリでマージの机を持っている・待っている参加者である。リポジトリが違っても停止要請は出る（実装の机はマシンに 1 つ）。後から参加した者にも出る。

止まる時機（コミットの切れ目がどこか）を決めるのはセッションである。アプリは合図を出すだけで、ほかのプロセスには触らない。

### 判定の基準

どの段で排他テストの机を取り、どの段で負荷テストを申し込むかは、この表で決める（スキルの机の段もこの表に従う）。

| 段 | 取る机 |
|---|---|
| 全体テストのスクリプトを回す（どの引数でも）・ワークスペース全体の `cargo test`・`/kiro-validate-impl` が回す全体テスト・`#[ignore]` の実機テストを `--ignored` で回す（例外なし。窓も入力も使わないものも数える）・spec ごとの実機の走行の道具・areka／ゴースト／窓を実際のデスクトップに立てる確かめ（配布物の起動の確かめを含む）・`SendInput` や computer-use でデスクトップを操作する確かめ | 排他テストの机（`--desk test`） |
| 静かな CPU での計測・わざと負荷をかける再現・時間の比べ | 排他テストの机とひとり占め（`--desk test,sole`） |
| `--ignored` を付けない `cargo test -p <クレート>`・clippy・整形（`cargo fmt --all -- --check` を含む）・ビルド | 取らない（実装の机の上で回す） |

- `kiro-impl` は、タスクの文・`_Boundary:_`・設計の確かめの記述から、そのタスクが上の段を含むかを決める。
- 開発者が `/kiro-validate-impl` を単独で呼ぶときは、机を取らない（`/kiro-validate-impl` 自身は机のコマンドを呼ばない）。ほかのセッションの全体テストや UI テストと重ねたくないときは、先に手で `request --desk test --wait` を取り、番が来てから呼び、終わったら `return` する。机を取るのは、`kiro-impl` が最後の検証で呼ぶときだけである。

### 調停役のセッションとの違い

これまでは、調停役の Claude セッション（スキル `kiro-watch`）がメッセージのやり取りで机を貸し出していた。その頃の決まりを引き継いでやり方だけを替え、のちに机を上の 3 種類へ組み直した。下の表は、やり方を替えたときの違いの記録である。

| | 調停役のセッション | `areka-impl-watch` |
|---|---|---|
| やり取り | セッション同士のメッセージ（LLM が読んで送る） | 各セッションが Bash から実行ファイルを呼ぶ。メッセージは使わない |
| 待つ | 「どうぞ」のメッセージを待つ | 番が来るまで終わらないコマンドをバックグラウンドで走らせる |
| 止まる合図 | 停止のメッセージ | 走らせておいた見張りのコマンドが終わる |
| 状態の置き場 | 調停役のワークツリーの `target/` の下（掃除で消える） | マシン共通の置き場所（掃除やビルドの影響を受けない） |
| 落ちたとき | 調停役が落ちると合図が届かない | 落ちたセッションの机と申し込みは、ほかの参加者の次の呼び出しが外す（自動で外れるのは「作業中」の参加者だけ。6 節） |
| 送れる数 | 開発者の入力 1 回につき約 10 通で止まる | 上限は無い |
| 次の「どうぞ」への添え書き | 在る | 無い。伝えたいことは開発者がそのセッションへ直接書く |

今は、実装・完了・棚卸・リリースのスキル（`kiro-impl`・`kiro-complete`・`kiro-next`・`release`）と pasta のマージの手順がこのアプリを呼ぶ。調停役のセッションはもう使わない。スキルがいつ何を呼ぶかは、4 節の「スキルからの呼び方」にある。

## 2. 入れ方

要るもの: Rust 1.89 以上（ファイルのロックを標準ライブラリで使うため）と PowerShell 7（置き方の道具を走らせるため）。

1. **ユーザー環境変数 `AREKA_IMPL_WATCH_HOME` を 1 度だけ設定する。** 例は `%USERPROFILE%\.areka-impl-watch`。

   ```powershell
   [Environment]::SetEnvironmentVariable('AREKA_IMPL_WATCH_HOME', "$env:USERPROFILE\.areka-impl-watch", 'User')
   ```

   設定は、その後に開いた端末とアプリから見える。Claude のアプリも立ち上げ直す。

2. **置き方の道具を走らせる。**（新しい端末で）

   ```powershell
   pwsh -NoProfile -File <メインの作業コピー>\tools\impl-watch-install.ps1
   ```

   `<メインの作業コピー>` は、リポジトリの本体の作業コピー（共通の git フォルダ `.git` の親。`git rev-parse --path-format=absolute --git-common-dir` の親）の `C:\…` の形の絶対パスである。既定の枝の最新を取り込んだ作業コピーで走らせる。どのフォルダから呼んでも同じに動き、今のフォルダを変えない。

   道具は、スクリプトの在る作業コピーのソースから実行ファイルを release でビルドし、置き場所のフォルダが無ければ作って `areka-impl-watch.exe` を置き、置いたものの `--help` を呼んで確かめる。うまくいけば次の行が出て、終了コード 0 で終わる。

   ```
   OK placed areka-impl-watch.exe
   OK check: --help exit 0
   ```

   最後の `OK check: --help exit 0` が確かめである。別に `status` を呼ばなくてよい。

   うまくいかなければ、`FAIL` で始まる行を出して終了コード 1 で終わる。

   | 出る行 | 訳とすること |
   |---|---|
   | `FAIL home: AREKA_IMPL_WATCH_HOME is not set` | 環境変数が無い・空。手順 1 をして、新しい端末で走らせ直す |
   | `FAIL home: AREKA_IMPL_WATCH_HOME is not an absolute path` | 値が `C:\…` の形でない。下の「環境変数について」のとおり直す |
   | `FAIL build: cargo exit <n>`・`FAIL build: no executable in cargo output` | ビルドに失敗した（cargo のエラーの行がその前に出る）。置き場所には触っていない |
   | `FAIL place: copy`・`FAIL place: rename` | 置き場所に書けなかった。前の実行ファイルは元のまま残っている |
   | `FAIL check: --help exit <n>` | 置いたものが動かなかった |

   道具は環境変数の値を画面へ出さず、設定も変更もしない。

環境変数について:

- **値は必ず `C:\…` の形の絶対パスにする。** 絶対パスでない値（`foo`・`.` のような相対の値、ドライブの無い `\foo`、`C:foo`、Git Bash の `/c/…` の形）は断られる。標準エラーへ次の形の 1 行が出て終了コード 1 で終わり、フォルダは作られない。

  ```
  AREKA_IMPL_WATCH_HOME must be an absolute path such as C:\Users\me\.areka-impl-watch, but it is '<設定されていた値>'. See doc/impl-watch.md
  ```

  断るのは、相対の値を受けると、呼んだときのカレントフォルダごとに別々の置き場所ができて、机が黙って割れるからである。Bash の中で `AREKA_IMPL_WATCH_HOME=/c/…` と上書きして呼ばない（この形も絶対パスではない）。
- 変数が無い・空（空白だけも含む）・フォルダを作れないときも、標準エラーへ 1 行出して終了コード 1 で終わり、何も読み書きしない。既定の場所へは倒れない。
- フォルダがまだ無ければ、アプリが作ってから続ける。

`cargo run` は開発中の試しだけに使う。ふだんの呼び出しに使わない理由は 3 つある: 待っている間 `target\` の下の実行ファイルが開かれたままになり、次のビルドが書き替えられない／cargo の起動が計測を乱す／掃除で実行ファイルが消える。試すときは、その端末の中だけ環境変数を `target\` の下の絶対パスへ向ける（向けないと本物の置き場所へ書く）。

## 3. 更新

2 節の手順 2 と同じコマンドをもう一度走らせる。誰かが待ち・見張りで走らせている間でもよい（Windows は、動いている実行ファイルの上書きはできないが、改名はできる）。手順はいつもこの 1 通りである。

道具は、今の `areka-impl-watch.exe` を `areka-impl-watch.old-<UTC>.exe` へ改名してから新しいものを置き、続けて古い実行ファイル（前の形の `areka-impl-watch.old.exe` も）を 1 つずつ消してみる。走っていた待ち・見張りは古いもののまま続き、その後の呼び出しから新しいものが使われる。出る行は次の形である。

```
OK renamed previous to areka-impl-watch.old-20261016T020500Z.exe
OK placed areka-impl-watch.exe
OK removed areka-impl-watch.old-20261016T020500Z.exe
OK check: --help exit 0
```

誰かが古いものを走らせていると、`OK removed …` の代わりに `KEEP areka-impl-watch.old-<UTC>.exe (in use; run again later)` と出る。そのままでよい。残った古いものは、次に道具を走らせたときに消える。

道具が触るのは、置き場所の `areka-impl-watch.exe`・`areka-impl-watch.new.exe`・`areka-impl-watch.old*.exe` だけである。状態ファイル・ロック・居る印・ログ・`status.md`・退避のファイルには触らず、`clear` も呼ばない。

**状態ファイルの版が上がる更新のとき。** 状態ファイルには版の番号が入っている（今は 2）。知らない版のファイルを見た実行ファイルは、読まず・書き替えずに、標準エラーへ次の形の 1 行を出して終了コード 1 で終わる（新しい実行ファイルが古い版のファイルを見ても、古い実行ファイルが新しい版のファイルを見ても同じ）。

```
state file version mismatch: file has 1, this exe knows 2. Do not mix old and new exes; see doc/impl-watch.md
```

古い状態を新しい版へ移す仕組みは無い。版が上がる更新では、次の順に進める。

1. 各マシンで、2 節の手順 2 の道具で入れ直す。
2. 入れ直した後で、1 度 `clear` を呼ぶ（`clear` は古いファイルを読まずに退避するので、版が合わなくても通る）。Claude のセッションからは `/kiro-watch-clear` でよい。
3. 走っていた待ち・見張りは終了コード 3 で終わる（古い実行ファイルの待ちも、記録が消えて終わる）。各セッションは `watch` を立ててから申し込み直す。

古い実行ファイルと新しい実行ファイルを混ぜて使わない。

## 4. 呼び方の約束

下の例では、実行ファイルを次のように呼ぶ（Bash）。

```bash
EXE="$AREKA_IMPL_WATCH_HOME/areka-impl-watch.exe"
```

「バックグラウンドで」は、終わるまで待たずに走らせておくこと（Claude のセッションでは Bash のバックグラウンド実行。コマンドが終わったときにセッションが 1 回起きる）。待っている間、コマンドは何も出さず、時間切れも無い。

### 流れ

1. **最初に見張りを立てる。**（バックグラウンド）

   ```bash
   "$EXE" watch --id <識別> --repo <リポジトリ> [--name <名前>]
   ```

   見張りは参加の申し出を兼ねる。**`merge`・`request`・`loadrunning` より先に立てる。** 見張りの無い「作業中」の参加者は、ほかの参加者の次の呼び出し（状態を変えるもの。待ちが 30 秒ごとに行う見回りも含む）で、落ちたものとして机・申し込みごと外されるからである。順を逆にして申し込みが消えたら、待ちが終了コード 3 で終わるので、`watch` を立ててから申し込み直す。

2. **マージしたいとき。**

   ```bash
   "$EXE" merge --id <識別> --repo <リポジトリ> --spec <spec の名前> [--bug] --wait   # バックグラウンド
   "$EXE" merged --id <識別> --pr <PR の番号> --sha <マージ後のコミット>
   ```

   `merge --wait` が終了コード 0 で終わったら番が来ている。出力の `last:` に、そのリポジトリの直前のマージが載る。マージの作業を終えたら `merged` を呼ぶ。`merged` は参加の終わりを兼ねる（走らせていた見張りが終了コード 3 で終わる。行動は要らない）。排他テストの机かひとり占めを持つ間と、机の申し込みを待つ間は、`merge` は断られる（先に返す・番を受けて返してから申し込む）。

3. **全体テスト・UI テストを回したいとき。**（判定の基準の表の 1 行目）

   ```bash
   "$EXE" request --id <識別> --repo <リポジトリ> --desk test --purpose "<何のテストか>" --wait   # バックグラウンド
   "$EXE" return --id <識別>
   ```

   `request --wait` が `granted test` と出して終了コード 0 で終わったら番が来ている。テストを 1 回回し、終わったら（成否によらず）直ちに `return` を呼ぶ。直しの間は机を持たず、回し直す前に申し込み直す。ほかの参加者は止まらない。

4. **負荷テストをしたいとき。**（判定の基準の表の 2 行目）

   ```bash
   "$EXE" request --id <識別> --repo <リポジトリ> --desk test,sole --purpose "<内容とおよその分>" --wait   # バックグラウンド
   "$EXE" return --id <識別>
   ```

   `request --wait` が `granted test,sole; stopped: …` と出して終了コード 0 で終わったら番が来ている。出力の `stopped:` に、止まってくれた参加者が載る。自分が止まっている間に番を受けたときは、見張りが停止要請で終わっているので、**負荷テストを始める前に `watch` を立て直す。** このとき、走らせてある `stopped --wait` も `resumed` で終わるが、`watch` の立て直しは 1 回でよい（2 度目は `a watch wait for <識別> is already running` と出て終了コード 1 で終わるだけで、害は無い）。テストが済んだら `return` を呼ぶ（名指しなしで、2 つの机を両方返す）。

5. **マージの机を持ったまま全体テストを回すとき。**（areka の完了の手順）

   ```bash
   "$EXE" request --id <識別> --repo <リポジトリ> --desk test --purpose "<何のテストか>" --wait   # バックグラウンド
   "$EXE" return --id <識別> --desk test
   ```

   マージの机を持つ者だけが、持ったまま排他テストの机を足せる（足せるのは `test` だけ）。走行が終わったら `return --desk test` で排他テストの机だけを返し、マージの机は `merged` まで持ち続ける。名指しなしの `return` でも、マージの机は返らない。マージの机を待っている（まだ持たない）間は `request` は断られるので、番を受けてから申し込む。

6. **見張りが終了コード 0 で終わったとき（停止要請）。** 出力は `stop requested by <識別>` で、2 行目の `details:` に、理由を日本語で読める `status.md` の道筋が載る。

   1. 今のタスクを、コミットの切れ目まで進める。実行の途中では止まらない。その途中の全体テスト・UI テストは、3 のとおり排他テストの机を取って回してよい（停止要請中の参加者には、ひとり占めが待たれていても排他テストの机が渡る）。
   2. 排他テストの机を持っていれば `return` してから、`"$EXE" stopped --id <識別> --wait` をバックグラウンドで走らせる。「止まった」を記録して、自分が「止まった」でなくなるまで終わらない（返し忘れても、「止まった」の記録で排他テストの机は空く）。
   3. `resumed` と出て終了コード 0 で終わったら、再開である。`watch` を立て直してから続きの作業に戻る。次の `merge`・`request` は、見張りを立て直した後に呼ぶ。
   4. `stop requested again by <識別>` と出て終了コード 0 で終わったら、止まっている間に停止要請が取り消されて、出し直されている。作業には戻らず、**もう一度 `stopped --id <識別> --wait` を走らせる**（訳は 6 節の「止まっている間に停止要請が出し直された」）。

   **停止要請を受けたら、次にしたいことが負荷テストの申し込みでも、「止まった」は報告する。** `request` は申し込んだ参加者の状態を変えないので、申し込んだだけでは「停止要請中」のままで、先に待っている負荷テストの番を止め続ける。`stopped --wait` を走らせた後なら、止まったまま `request --desk test,sole --wait` を申し込んでよい。「止まった」のまま並び、自分の番が来たときに作業へ戻る（そのとき `stopped --wait` は `resumed` で、`request --wait` は `granted test,sole; …` で終わる）。止まったまま `--desk test` を申し込んだときは、再開するまで番が来ない。

7. **すでに走っている負荷テストを記録するとき。** `watch` を立ててから `loadrunning --id --repo --purpose` を呼び、済んだら `return`（名指しなし、または `--desk test,sole`）を呼ぶ。排他テストの机とひとり占めの両方の持ち主として記録され、停止要請は出ない。記録の間、どのリポジトリでもマージは始まらない。走っている記録の持ち主は 2 つの机を 1 組で返す（`return --desk test` は断られる）。

8. **終わるとき。** `"$EXE" leave --id <識別>`（`merged` で終えたなら要らない）。走らせていた見張りと待ちは終了コード 3 で終わる。

申し込みだけを取り下げるときは `cancel --id <識別>`（申し込みと机を外す。参加は続く。走らせていた `merge --wait`・`request --wait` は終了コード 3 で終わる）。

### 往復のコマンド数

セッションが起きるのは「コマンドが終わる」ときだけである。`watch` はセッションの最初に 1 回立て、停止要請で終わるまで走り続ける。

| 往復 | 呼ぶコマンド | 数 | セッションが起きる回数 |
|---|---|---|---|
| マージの机 | ① `merge --id --repo --spec [--bug] --wait`（バックグラウンド・番が来て終わる）② `merged --id --pr --sha` | 2 | 1（①の終わり） |
| 排他テストの机 | ① `request --id --repo --desk test --purpose --wait`（バックグラウンド）② `return --id` | 2 | 1（①の終わり） |
| 負荷テスト | ① `request --id --repo --desk test,sole --purpose --wait`（バックグラウンド）② `return --id` | 2 | 1（①の終わり） |
| マージの机＋排他テストの机（areka の完了） | ① `merge --wait`（バックグラウンド）② `request --desk test --wait`（バックグラウンド）③ `return --desk test` ④ `merged` | 4 | 2（①と②の終わり） |
| 停止 | （走らせてある `watch` が終わる）① `stopped --id --wait`（バックグラウンド・再開で終わる）② `watch --id --repo`（立て直し・バックグラウンド） | 2 | 2（`watch` の終わり・①の終わり） |
| 走っている負荷テストの記録 | ① `loadrunning` ② `return` | 2 | 0 |
| 参加の始まり／終わり | `watch`（バックグラウンド）／`leave`（`merged` は参加の終わりを兼ねる） | 1／1 | 0 |

同じことを 2 度呼ばなくてよい: 直前のマージは `merge --wait` の終わりの出力に、止まった参加者は `request --wait`（ひとり占めを含むとき）の終わりの出力に、停止要請を出した相手は `watch` の終わりの出力に載る。待ちを始め直しても、申し込みは二重にならない（同じ組の申し込み直しは元の申し込みのまま。すでに持っていれば直ちに番が来たとして終わる）。

参加の終わり（`merged`・`leave`）では、走っていた `watch` が終了コード 3 で終わるので、セッションがもう 1 回起きる（行動は要らない）。表には数えていない。

停止の往復の ① が `stop requested again by <識別>` で終わったときだけ、① をもう 1 度呼ぶ（コマンドが 1 つ、セッションが起きる回数が 1 回増える）。出し直しを知らせるものがほかに無いので、この 1 回は要る。

### 前の負荷テストの呼び方の読み替え

机を 3 種類へ組み直したときに、負荷テストの机の申し込みと返しのコマンドは無くなった。下の左の列のコマンドを新しい実行ファイルへ渡すと、使い方の誤り（終了コード 2）で終わる。`loadrunning` は名前・引数・出力のまま残る。

| 前の呼び方・出力 | 今の呼び方・出力 |
|---|---|
| `loadtest --id --repo --purpose [--name] [--wait]` | `request --id --repo --desk test,sole --purpose [--name] [--wait]` |
| `loaddone --id` | `return --id`（名指しなし。排他テストの机とひとり占めを両方返す） |
| `granted load; stopped: …`・`queued load pos=<n>` | `granted test,sole; stopped: …`・`queued test,sole pos=<n>` |
| `load done`・`not applied: not the load-test holder` | `returned test,sole`・`not applied: not the holder of that desk`（何も持たなければ `holds no desk to return`） |
| `loadrunning` の `not applied: the load-test desk already has a holder` | `not applied: the test desk or the sole desk already has a holder` |
| 待ちの種類・居る印の `load`（`a load wait for <識別> is already running`） | `request`（`a request wait for <識別> is already running`） |
| `status` の `load-holder=`・`load-queued=`・`load:` の行 | `sole=`・`test=`・`requests=`・`impl:` の行・`test:` の行（6 節） |

### スキルからの呼び方

実装・完了・棚卸・リリースのスキル（`kiro-impl`・`kiro-complete`・`kiro-next`・`release`）と pasta のマージの手順は、上の流れを次の形で呼ぶ。

- **机のコマンドを呼ぶのは主の会話だけ。** 実装係・レビュー係・検証係などのサブエージェントは `areka-impl-watch.exe` を呼ばない（1 つのセッションが 1 つの参加者）。サブエージェントが判定の基準の段を回すのは、主の会話が「排他テストの机（または負荷テストの組）を持っている」と知らせたときだけで、知らせていなければその手前で止まって机が要ることを返す。
- **1 つの作業木で机を使うセッションは 1 つ。** 同じ作業木の 2 つのセッションは識別が同じになり、互いの見張りを外し合う。
- 机は助けである。使えないとき（下の `skip`、環境変数の断り、直らない失敗）は、その回だけ机の段を飛ばして作業を続け、訳を最後の報告に残す。
- 見回り・時間を決めた繰り返し・定期の `status` はしない。セッションが起きるのは待ちのコマンドが終わったときだけで、机について開発者へ伝えるのは 1 つの出来事につき 1 行である。机の番待ち（`排他テストの机の番待ち`・`負荷テストの机の番待ち`）と再開待ちは、承認の止まりにしない。

**識別・リポジトリ・名前の求め方。** 実行の初めに、次の 1 回の Bash（前景）で求める。

```bash
ID=$(basename "$(git rev-parse --show-toplevel)"); R=$(basename "$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")")
if [ -z "$AREKA_IMPL_WATCH_HOME" ]; then echo "desk: skip no-home"
elif [ ! -f "$AREKA_IMPL_WATCH_HOME/areka-impl-watch.exe" ]; then echo "desk: skip no-exe"
elif ! [[ "$ID" =~ ^[A-Za-z0-9._-]{1,100}$ && "$R" =~ ^[A-Za-z0-9._-]{1,100}$ ]]; then echo "desk: skip bad-name $ID $R"
else echo "desk: id=$ID repo=$R"; fi
```

- 識別（`--id`）は作業木の最上位のフォルダの名前。Claude のセッションが替わっても、同じ作業木なら同じ値になる。
- リポジトリ（`--repo`）は共通の git フォルダ（`.git`）の親の名前で、どの作業木から呼んでも同じ。`origin` の URL は資格情報を含むことがあるので使わない。
- 名前（`--name`）と `merge` の `--spec` には spec の名前を渡す。
- `desk: skip …` なら別の値をこしらえず、その回は机のコマンドを 1 つも呼ばない（`no-exe` のときは 2 節の置き方の道具のコマンドを案内する）。
- `desk: id=… repo=…` の値を覚え、以後のコマンドへ字のまま書く。

**呼ぶ形。** どのコマンドも同じ形で呼び、最後の `exit=<n>` とその前の 1〜2 行だけを読む（`2>&1` で、標準エラーの 1 行も同じ出力に入る）。

```bash
"$AREKA_IMPL_WATCH_HOME/areka-impl-watch.exe" <コマンド> <引数> 2>&1; echo "exit=$?"
```

`watch`・`merge --wait`・`request --wait`・`stopped --wait`・`resume` はバックグラウンドで、`leave`・`merged`・`return`・`cancel`・`loadrunning`・`clear --repo` は前景で呼ぶ。`status` は訳を調べるときだけ前景で呼ぶ。

**いつ何を呼ぶか。**

| スキル | 時点 | 呼ぶもの |
|---|---|---|
| `kiro-impl` | 実行の初め（準備の最後） | 上の求め方 → 最初のタスクの前に `watch --id --repo --name`（バックグラウンド） |
| `kiro-impl` | 全体テスト・UI テスト（判定の基準の表の 1 行目）を回す段の前（実装係・直し係が `MISSING: exclusive-test desk` を返したとき。手で回す形では主の会話がその段に入る前） | `request --id --repo --desk test --purpose --wait`（バックグラウンド）。番が来てから、その段を 1 回だけ回させる。待つ間は机の要らないタスクを進める |
| `kiro-impl` | 全体テスト・UI テストの走行が終わった（成否によらず） | 直ちに `return`。直しの間は持たず、回し直す前に申し込み直す |
| `kiro-impl` | 負荷テスト（判定の基準の表の 2 行目）を含むタスクの前 | `request --id --repo --desk test,sole --purpose "<内容とおよその分>" --wait`（バックグラウンド）。番が来るまでそのタスクに入らない |
| `kiro-impl` | 負荷テストの番が来た（`granted test,sole; …`） | 止まっている間に受けたなら `watch` を 1 回立て直す → そのタスク → 済んだら直ちに `return` |
| `kiro-impl` | 見張りが `stop requested by <識別>` で終わった | 今のタスクをコミットの切れ目まで進め（途中の全体テスト・UI テストは排他テストの机を取ってよい）、排他テストの机を持っていれば `return` → `stopped --id --wait`（バックグラウンド） |
| `kiro-impl` | 再開の待ちが `resumed` で終わった | `watch` を立て直して次のタスクへ |
| `kiro-impl` | 最後の検証（`/kiro-validate-impl`）の前 | `request --id --repo --desk test --purpose "kiro-validate-impl <feature>" --wait`（バックグラウンド）→ 番が来てから `/kiro-validate-impl` を呼ぶ → 終わったら（成否によらず）直ちに `return` |
| `kiro-impl` | 実行の終わり（どの終わり方でも） | `leave`。完了の承認を待つ間は参加者でない |
| `kiro-impl` | 開発者が「走っている負荷テストを記録せよ」と言ったときだけ | `loadrunning --id --repo --purpose` → 済んだら `return` |
| `kiro-complete` | 完了の手順の前（前置きステップ） | 上の求め方 → 自分の見張りが走っていなければ `watch` → 停止要請を受けていたら `stopped --wait` → `merge --id --repo --spec [--bug] --wait`（バックグラウンド）。番が来るまで手順に入らない |
| `kiro-complete` | マージの番が来た（`granted merge …`） | 既定の枝を取り込んでから完了の手順へ |
| `kiro-complete` | アーカイブの後の全体テストの前（回し直しのたびにも） | マージの机を持ったまま `request --id --repo --desk test --purpose "kiro-complete full test" --wait`（バックグラウンド）。番待ちは 1 行 `排他テストの机の番待ち` で伝え、待つ間も並行の仕事は進める |
| `kiro-complete` | 全体テストの走行が終わった（成否によらず・判定より先） | `return --id --desk test`。マージの机は持ち続ける |
| `kiro-complete` | PR の squash マージが成功した後 | `merged --id --pr --sha`（参加の終わりを兼ねる） |
| `kiro-complete` | 中断条件・開発者の取りやめで手順をやめるとき | `cancel`（参加は続ける。排他テストの机を持っていればそれも空く） |
| `kiro-complete` | PR を作れずにマージの無いまま終わるとき | `leave` |
| `release` | 段 3（手元の確かめ）に入る前 | 上の求め方 → 3.1 の前に `watch`（バックグラウンド）。マージの机は取らない |
| `release` | 3.1 の全体テストと 3.3 の起動の確かめのそれぞれの前 | `request --id --repo --desk test --purpose "release <版> <3.1 か 3.3>" --wait`（バックグラウンド）→ 番が来てから回す → 走行が終わったら（成否によらず）直ちに `return`。3.2 の読みは机を持たずに行う |
| `release` | 段 3 を終えて机を返した後 | `leave`。4.2 で回し直すときは、そのときにまた `watch` → `request` → 走行 → `return` → `leave` |
| `release` | 見張りが `stop requested by <識別>` で終わった | 走っている確かめを終えて机を返した切れ目で `stopped --wait` → `resumed` を待って `watch` を立て直し、次の項目へ |
| pasta のマージの手順 | マージするとき | `watch` → `merge --wait`（バックグラウンド）→ マージ → `merged`。排他テストの机は取らない（呼び方は前のまま） |
| `kiro-next` | 棚卸の始め（1 回だけ） | `clear --repo <リポジトリ>`（前景）。そのリポジトリの記録だけを消す。`watch` は立てず、`status` も読まない |

`kiro-next` は求め方のうちリポジトリだけを求め、`clear --repo` が 1 で終わっても 2（`--repo` を受けない古い実行ファイル）で終わっても、1 行伝えて棚卸を続ける。消された記録の持ち主が実は動いていたときは、そのセッションの見張りが終了コード 3 で終わり、下の扱いで立て直す。

**終わったときの扱い**は、5 節の「終了コードごとにセッションがすること」と終了コード 1 の表のとおりである。スキルは次を足す。

- **立て直しと申し込み直しは 1 回まで。** 同じ出来事で 2 つの待ちが続けて終わっても、立て直しと申し込み直しはそれぞれ 1 回だけ行う。2 度目が `already running` で終わっても害は無い。
- 排他テストの机かひとり占めを持つ間に、見張りか番の待ちが終了コード 3 で終わったら、次の走行を始めず、見張りを立て直して申し込み直す。
- 見張りが終了コード 1（下の 2 つのほか）で終わったら、直ちに 1 回だけ立て直す。立て直しも同じ文の 1 で終わったら終了コード 1 の表に従い、直らなければその回の机の段を止める。
- `AREKA_IMPL_WATCH_HOME …` の断りで終わったら、その回の机の段を止め、標準エラーの 1 行をそのまま伝える。
- 見張りが `a watch wait for <識別> is already running` で終わり、自分で立てた見張りの覚えが無ければ、前のセッションの残りの見張りである。外す・待つ・立てるを 1 本にまとめてバックグラウンドで走らせる（残りの見張りは、記録が消えたことを 1 秒ごとの見回りで見つけて終わるまで、同じ識別の錠を持ち続けるため）。持っていた申し込みがあれば、この 1 本が終わる前に申し込み直す。この 1 本がまた `already running` で終わったら繰り返さず、その回の机の段を止める。

  ```bash
  "$AREKA_IMPL_WATCH_HOME/areka-impl-watch.exe" leave --id <識別> 2>&1; sleep 3; "$AREKA_IMPL_WATCH_HOME/areka-impl-watch.exe" watch --id <識別> --repo <リポジトリ> --name <spec の名前> 2>&1; echo "exit=$?"
  ```

  この `leave` は参加の終わりに数えない（参加を終えるのは実行の終わりの `leave` と `merged` だけ）。
- 終了コード 2 は、スキルの文の誤りである。その回の机の段を止める。

## 5. コマンド・引数・終了コード

`areka-impl-watch.exe --help` が同じ対応を英語で出す（置き場所の環境変数が無くても出る）。

### コマンドの表

終了コード 1（失敗）と 2（使い方の誤り）は全部のコマンドに共通なので、表には 0 と 3 だけを書く。

| コマンド | 要る引数 | 任意の引数 | すること | 0 | 3 |
|---|---|---|---|---|---|
| `watch` | `--id` `--repo` | `--name` | 参加して「居る」印になり、停止要請が出るまで終わらない | 停止要請が出た（すでに止まっているときも） | 記録が消えた |
| `merge` | `--id` `--repo` `--spec` | `--bug` `--name` `--wait` | そのリポジトリのマージの机に並ぶ（参加を兼ねる）。`--wait` なら番が来るまで終わらない | 並んだ。`--wait` つきは番が来た | `--wait` つきは申し込みが消えた。排他テストの机かひとり占めを持つ・机の申し込みを待つ者の申し込みは当てはまらない（状態を変えず、`--wait` つきでも待たない） |
| `merged` | `--id` `--pr` `--sha` | — | マージの机を空け、直前のマージを記録し、参加を終える | 済んだ | 持ち主でない |
| `request` | `--id` `--repo` `--desk` `--purpose` | `--name` `--wait` | 並べた机の申し込み 1 つ（参加を兼ねる。申し込んだ参加者の状態は変えない）。並べた机は全部が一度に渡る。`--wait` なら番が来るまで終わらない | 並んだ・番が来た。`--wait` つきは番が来た | 当てはまらない（状態を変えず、`--wait` つきでも待たない）。`--wait` つきは、加えて申し込みが消えた |
| `return` | `--id` | `--desk` | 名指しした机を返す。名指しが無ければ、マージの机のほかの全部を返す | 返した | 持ち主でない（持っていない机） |
| `loadrunning` | `--id` `--repo` `--purpose` | `--name` | すでに走っている負荷テストを、停止要請を出さずに、排他テストの机とひとり占めの両方の持ち主として記録する | 記録した | どちらかの机に持ち主が居る、またはマージの机を待っている |
| `stopped` | `--id` | `--wait` | 「止まった」を記録する（持っていた排他テストの机は空く）。`--wait` なら、続けて自分が「止まった」でなくなるまで終わらない | 記録した。`--wait` つきは再開した、または停止要請が出し直された | 停止要請中でない。`--wait` つきは記録が消えた |
| `resume` | `--id` | — | 再開を待つだけ（`stopped --wait` が途中で止められたときの始め直し） | 再開した、または停止要請が出し直された | 記録が消えた |
| `unstop` | — | `--id` | 停止要請を取り消す（全員、または識別 1 つ） | 済んだ | 取り消す相手が居ない |
| `cancel` | `--id` | — | その識別の申し込みと机を外す。参加者の記録は残る | 済んだ | — |
| `leave` | `--id` | — | その識別の申し込み・机・参加者の記録を消す | 済んだ | — |
| `tick` | — | — | 落ちた参加者を外し、番を決め直すだけ | 済んだ | — |
| `status` | — | — | 状態を変えずに読み、`status.md` を書き、要約を出す | 済んだ | — |
| `clear` | — | `--repo` | 状態ファイルを退避して空から始める。問い合わせはしない。`--repo` つきは、そのリポジトリの参加者を全員外し、マージの机と待ち行列を空にする（直前のマージは残す。退避はせず、ほかのリポジトリには触らない） | 済んだ（`--repo` つきは外す者が居なくても 0） | — |
| `--help` | — | — | 使い方を出す | 済んだ | — |

`cancel`・`leave`・`unstop`・`stopped`・`merged`・`return` の `--id` は「誰について」であって、呼ぶ者と違ってよい（開発者が代わりに呼べる）。

### 引数の形

| 引数 | 形 |
|---|---|
| `--id`・`--repo`・`--spec` | 英数字と `.` `_` `-` だけの 1〜100 字 |
| `--name`・`--purpose` | `--` で始まらない任意の文字（日本語でよい。端末へは出ず、`status.md` で読める） |
| `--desk` | `test`・`sole`・`test,sole` のどれか（`sole,test` も `test,sole` と同じ）。マージの机は `merge` で申し込み、ここには並べない |
| `--pr` | 数字だけ |
| `--sha` | 16 進の 7〜40 字 |
| `--bug`・`--wait` | 値なし |

- 識別（`--id`）は、読んだ時点で小文字に寄せて使う。`A` と `a` は同じ参加者で、出力・`status`・ログには小文字で出る。`--repo` と `--spec` は寄せない（大文字と小文字を区別する）。
- 値を取る引数は、どれも `--` で始まる値を断る（終了コード 2。例: `--purpose "--release build x5"`）。空の変数を引用符なしで渡したとき（`--spec $SPEC --bug`）に、次の引数を値として読み違えないためである。
- `--desk` の値が空・同じ名前を 2 度（`test,test`）・知らない名前・`merge` のときは使い方の誤り（終了コード 2・何も読み書きしない）で、標準エラーに `usage error: --desk must be test, sole or test,sole (the merge desk is requested with merge); see areka-impl-watch --help` の 1 行が出る。大文字（`Test`）も知らない名前である。
- `--name` を省くと、初めての参加では識別がそのまま名前になり、2 度目からは元の名前のまま変わらない。
- 同じ引数を 2 度書く・そのコマンドが受けない引数を書く・足りない、はどれも使い方の誤り。`-h` と、引数なしの呼び出しも使い方の誤りである（使い方を出すのは `--help` だけ）。

### 終了コードと出力の行き先

| 終了コード | 意味 | 出力 |
|---|---|---|
| 0 | できた（番が来た・停止要請が出た・再開した・停止要請が出し直された・状態を変えた・並んだ） | 標準出力に 1〜数行 |
| 1 | 失敗（環境変数が無い・絶対パスでない・フォルダを作れない／状態ファイル・ロック・読み書き・同じ待ちがすでに走っている） | 標準エラーに 1 行 |
| 2 | 使い方の誤り。何も読み書きしていない | 標準エラーに 1 行（`usage error: …; see areka-impl-watch --help`） |
| 3 | 当てはまらなかった（申し込みや記録が消えた・条件に合わず状態を変えなかった） | 標準エラーに 1 行（`gone: …` か `not applied: …`） |

**終了コード 3 の文は標準出力でなく標準エラーに出る。** 標準出力に文が出るのは 0 のときだけである。出力は全部 ASCII で、名前（`--name`）と内容（`--purpose`）は端末へ出ない。

| コマンド | 0 のときの標準出力 | 3 のときの標準エラー |
|---|---|---|
| `watch` | `stop requested by <識別>`（すでに止まっているときは `already stopped; run stopped --wait or resume`）と、2 行目に `details: <置き場所>\status.md` | `gone: removed` |
| `merge` | `granted merge repo=<リポジトリ>; last: PR#<番号> <sha> <spec> <UTC>`（直前のマージが無ければ `last: none`）／並んだだけなら `queued merge repo=<リポジトリ> pos=<順番>` | `gone: request gone`／`not applied: return the test and sole desks before merge`（排他テストの机かひとり占めを持つ）／`not applied: a desk request is waiting; merge after it is granted and returned`（机の申し込みを待つ） |
| `merged` | `merged repo=<リポジトリ>` | `not applied: not the merge holder` |
| `request` | `granted <机>`（ひとり占めを含むなら `granted <机>; stopped: <識別>, <識別>`、居なければ `stopped: none`）／並んだだけなら `queued <机> pos=<順番>` | `not applied: a different desk request is already waiting`／`not applied: desks are held; only a merge holder may add the test desk`／`not applied: a merge request is waiting; request desks after the merge desk is granted`。`--wait` つきは、加えて `gone: request gone` |
| `return` | `returned <机>` | `not applied: not the holder of that desk`／`not applied: holds no desk to return`／`not applied: a running load test returns test and sole together` |
| `loadrunning` | `recorded running load` | `not applied: the test desk or the sole desk already has a holder`／`not applied: a merge request is waiting; record the running load after the merge desk is granted` |
| `stopped` | `stopped`。`--wait` つきは `resumed` か `stop requested again by <識別>` | `not applied: not asked to stop`。`--wait` つきは `gone: removed` |
| `resume` | `resumed` か `stop requested again by <識別>` | `gone: removed` |
| `unstop` | `unstopped n=<戻した人数>` | `not applied: nobody to unstop` |
| `cancel` | `cancelled` | — |
| `leave` | `left` | — |
| `tick` | `tick` | — |
| `status` | 要約（6 節）。状態ファイルが無ければ `no state file` | — |
| `clear` | `cleared; backup: <退避したファイル>`（退避するものが無ければ `cleared; backup: none`）。`--repo` つきは `cleared repo=<リポジトリ>; left: <識別>, <識別>`（外した者が居なければ `left: none`。`--repo` を受けない古い実行ファイルは使い方の誤りの 2） | — |

`<机>` は `test`・`sole`・`test,sole` のどれかで、並べた順によらずこの綴りに揃う。`pos=` は、申し込みの早い順で数えた自分より前の申し込みの数＋1 である（追い越しがあるので目安）。

待つコマンド（`watch`・`merge --wait`・`request --wait`・`stopped --wait`・`resume`）は、「居る印を握る → 申し込む（または『止まった』を記録する）→ 待つ」の順に進む。同じ識別・同じ種類の待ちがすでに走っていれば、申し込みもせずに `a <種類> wait for <識別> is already running` で終了コード 1 になる（種類は `watch`・`merge`・`request`・`resume`。`stopped --wait` と `resume` は同じ種類）。呼んだ時点でもう条件が満ちていれば、待たずに直ちに終わる。申し込みが当てはまらなかった `merge --wait`・`request --wait` は、待ちに入らず、待ちの記録も残さずに終了コード 3 で終わる。「停止要請中」の参加者に `resume` を呼んだときも、直ちに `stop requested again by <識別>` で終わる（「止まった」をまだ報告していないので、`stopped --wait` を呼ぶ）。

### 終了コードごとにセッションがすること

| コマンド | 0 | 3 |
|---|---|---|
| `watch` | 停止要請。今のタスクをコミットの切れ目まで進めて（排他テストの机を持っていれば返して）`stopped --wait`。`already stopped; …` のときは、すでに「止まった」を記録済みなので、記録し直さずに `resume` で再開を待つ | 参加者の記録が消えた。最後に立てた見張りでなければ（立て直す前の古い見張りの終わり）行動は要らない。参加を終えた（`merged`・`leave`）後なら行動は要らない。それ以外は 1 行伝えて `watch` を立て直し、持っていた申し込みを申し込み直す（机を持っていたなら、番がまた来てから続ける） |
| `merge --wait`・`request --wait` | 番が来た。作業をして `merged`／`return` | `gone: …` なら申し込みが消えた（取り下げ・参加の終わり・落ちたと見なされて外された・`clear`）。自分で `cancel` した後なら行動は要らない。それ以外は 1 行伝えて、**`watch` を立ててから**申し込み直す。訳を調べたいときだけ `status` と `status.md` の最近の出来事を見る。`not applied: …` なら、申し込みの組の誤りか、持ちながら・待ちながらの申し込みである。状態は変わっていない。`status` は読まずに、持っている机を返してから（`merge` なら机の申し込みの番を受けて返してから、`request` ならマージの机の番を受けてから）申し込み直す。1 行で伝える |
| `stopped --wait`・`resume` | `resumed` なら再開した。`watch` を立て直して続ける。`stop requested again by <識別>` なら、停止要請が出し直されている。作業には戻らず、もう一度 `stopped --wait` を呼ぶ | 参加者の記録が無い。`watch` を立て直して続ける |
| `stopped`（`--wait` 無し） | 記録した。再開は `resume` で待つ | 停止要請中でない（取り消された・すでに「止まった」を記録済み・参加者の記録が無い）。`watch` を立て直す。直ちに `already stopped; …` で終わったら `resume` で再開を待ち、終わらなければそのまま続ける |
| `merge`・`request`（`--wait` 無し） | `granted …` なら番が来ている。`queued …` なら並んだだけなので、`--wait` つきで呼び直して待つ（二重には並ばない） | 上の `not applied: …` と同じ |
| `merged` | 済んだ | 持ち主でない。`status` の `last=` に自分のマージが載っていれば、すでに記録済み |
| `return` | 済んだ | もう持っていない（机は空いているか、他の参加者のもの）。返し直さない。`a running load test returns test and sole together` のときだけ、名指しなし（または `--desk test,sole`）で返し直す |
| `loadrunning` | 記録した | どちらかの机に持ち主が居る（自分がすでに持ち主のときの呼び直しも 3）か、マージの机を待っている。持ち主にならず、その計測は記録されない。1 行伝えて開発者の指示を待つ（持ち主は `status` で見られる） |
| `unstop` | 取り消した。ひとり占めを含む申し込みがまだ待たれていれば、同じ呼び出しの中で出し直される。出し直しは `unstopped n=<戻した人数>` に載らないので、続けて `status` を見る（再開の待ちを走らせていない参加者が `stop-requested` と出ていたら、6 節の「止まっている間に停止要請が出し直された」） | 取り消す相手が居ない。行動は要らない |

終了コード 1 のときは、標準エラーの 1 行を読む。

| 標準エラーの文（先頭） | すること |
|---|---|
| `AREKA_IMPL_WATCH_HOME is not set or empty. …` | 2 節のとおり環境変数を設定する |
| `AREKA_IMPL_WATCH_HOME must be an absolute path …` | 変数の値を `C:\…` の形の絶対パスに直す（2 節） |
| `AREKA_IMPL_WATCH_HOME cannot be created: …` | 変数の値（書ける場所か）を直す |
| `a watch wait for <識別> is already running` | 同じ識別の見張りがまだ走っている。自分で立てた見張りなら行動は要らない。覚えが無ければ前のセッションの残りなので、4 節の「スキルからの呼び方」の外し方の 1 本を走らせる（手で外すときは 6 節） |
| `a resume wait for <識別> is already running` | 前の再開の待ち（`stopped --wait`・`resume`）がまだ走っている。行動は要らない |
| `a merge wait for <識別> is already running`・`a request wait for <識別> is already running` | 同じ識別の番の待ちがまだ走っている。自分で走らせた待ちなら行動は要らない。覚えが無ければ `cancel --id <識別>` を呼んでから申し込み直す |
| `state file version mismatch: …` | 3 節の「版が上がる更新のとき」 |
| `state file is broken; see impl-watch.log` | `status`、または走っていた待ち・見張りが、状態ファイルを読めなかった。6 節の「状態ファイルが壊れた」 |
| `state.lock is busy for 10 s; …` | 間を置かずに 1 回だけ呼び直す（実行ファイルが 10 秒待ってから断っているので、待ち足さなくてよい）。続くなら、止まったままの `areka-impl-watch.exe` が無いか見る |
| `io write state.json: PermissionDenied …`・`io set aside state.json: …` | 6 節の「ファイルを開いたままのアプリが居る」 |

**`watch` が終了コード 1 で終わったら、直ちに 1 回だけ立て直す。** 立て直すまでの間にほかの参加者の呼び出しが来ると、落ちたものとして外される。立て直しも同じ文の 1 で終わったら、上の表に従う。ただし、出た文が `AREKA_IMPL_WATCH_HOME …` の断りのときは立て直さずに変数を直し、`a watch wait for <識別> is already running` のときは上の表の行に従う。

終了コード 2 は呼び方の誤りなので、引数を直して呼び直す。スキルから出たときはスキルの文の誤りなので、その回の机の段を止める。

## 6. 困ったとき

### 状態を見る

```
participants=3 sole=none test=b requests=1 merging=1 merge-queued=0 not-working=0 waits=4
a areka working
b areka working
c pasta working
merge areka: holder=a queue=0 last=none
impl: riding=3 sole=none queue=none
test: holder=b queue=a
status: C:\Users\me\.areka-impl-watch\status.md
```

上は `status` の出力の例（末尾の道筋は置き場所による）。マージの机を持つ `a` が、`b` の持つ排他テストの机を待っている。`status` は状態を変えない（落ちた参加者を外すこともしない）。

- 1 行目の数: `participants`＝参加者／`sole`＝ひとり占めの持ち主（居なければ `none`）／`test`＝排他テストの机の持ち主（居なければ `none`）／`requests`＝机の申し込みの待ち行列の数／`merging`＝持ち主の居るマージの机の数／`merge-queued`＝全リポジトリのマージの待ち行列の合計／`not-working`＝停止要請中と止まったの合計／`waits`＝走っている待ち・見張りの記録の数。
- 続けて参加者 1 人に 1 行（識別・リポジトリ・状態・印）、マージの机 1 つに 1 行（`merge <リポジトリ>: holder=<識別> queue=<数> last=<直前のマージ>`）。
- `impl:` の行は実装の机: `riding`＝「作業中」の参加者の数／`sole`＝ひとり占めの持ち主／`queue`＝ひとり占めを含む申し込みの識別（来る順）。
- `test:` の行は排他テストの机: `holder`＝持ち主／`queue`＝排他テストの机を含む申し込みの識別（来る順）。
- 末尾の `status:` は、人が読む `status.md` の道筋。`status.md` の節は、参加者（Participants の表。名前・停止要請の理由つき）・実装の机（Implementation desk。乗っている人数・ひとり占めの持ち主の申し込みと番の時刻・走っている印・止まった一覧・内容）・排他テストの机（Exclusive-test desk。持ち主の申し込みと番の時刻・内容）・机の申し込み（Desk requests。来る順の番号つきで、識別・並べた机・申し込みの時刻・内容）・マージの机（Merge desks）・待ちと見張りの一覧（Waits and watches の表・プロセス番号つき）・最近の出来事（Recent events の表。新しい 50 件）である。
- 最近の出来事の種類: `reclaimed`（外した）・`recovered`（作り直した）・`cleared`（全部消した）・`test-freed`（排他テストの机が空いた。訳は `returned` 返した・`stopped` 止まった・`reclaimed` 回収・`cancelled` 取り下げ・`left` 離脱・`merged` マージが済んだ）。

参加者の行の印:

- **`absent`**: その参加者の見張りが走っていない。
  - `working absent`: 落ちたか、見張りを立てる前に申し込んだ。ほかの参加者の次の呼び出しか `tick` で外される。
  - `stop-requested absent`・`stopped absent`: **正常である。** 見張りは停止要請で終わっている。負荷テストの間は、止まった全員に `absent` が並ぶ。この 2 つの状態の参加者は、自動では外されない。落ちたかどうかは、`status.md` の Participants の `since`（その状態になった時刻）が古すぎないかと、`stopped` なら Waits and watches に同じ識別の `resume` の記録が在るか（在れば再開を待っていて、生きている）で見分ける。
- **`awaiting-watch`**: 再開して「作業中」に戻ったが、見張りがまだ立て直されていない。セッションが起きて `watch` を立て直すまでの間の印で、この間は自動では外されない。長く残っているなら、再開の直後に落ちている。

### 排他テストの机の番が来ない

`status` の `test:` の行と、`status.md` の Exclusive-test desk・Desk requests の節を読む。

- `test: holder=<識別>`: その参加者がテストを回している。持ち主は走行が終わったら返すので、ふつうは待てばよい。Exclusive-test desk の番の時刻が古すぎるなら、そのセッションが返し忘れているか落ちている。落ちていれば次の「落ちたセッションを手で外す」。
- `test: holder=none` なのに `queue=` に自分が居る:
  - `impl:` の行の `queue=` にひとり占めを含む申し込みが在る（負荷テストが待たれている）。その間、排他テストの机は停止要請中の参加者とマージの机の持ち主にしか渡らない。自分が「作業中」なら、負荷テストの番が済むまで待つ。
  - 自分が「止まった」である。止まった参加者の、ひとり占めを含まない申し込みには、再開するまで机が渡らない。
- 自分の申し込みが Desk requests に無い: 申し込みが消えている（最近の出来事で訳を見る）。`watch` を立ててから申し込み直す。
- 前の持ち主がいつ・なぜ返したかは、最近の出来事の `test-freed` に載る。

### 落ちたセッションを手で外す

`leave --id <識別>` を呼ぶ。申し込み・机・参加者の記録が消え、同じ呼び出しの中で次の番が決まる。

**`cancel` は使わない。** `cancel` は参加者の記録を残す。ひとり占めを含む申し込みが待たれていると、残った記録に停止要請が出て（すでに停止要請中ならそのまま）、落ちたセッションは「止まった」と言わないので、`leave --id` を呼ぶまで負荷テストの番が来ない。停止要請中・止まったの参加者は自動では外されない。

止まっていてひとり占めの番を受けた持ち主が、見張りを立て直す前に落ちたときも、自動では外されない（`awaiting-watch` の印のまま残る）。同じく `leave --id` で外す。

### 全部消す

`clear` を呼ぶ。問い合わせをせずに、今の状態ファイルを `state.json.cleared-<UTC>` へ退避し、空の状態から始める。出力に退避したファイルの道筋が載る。走っていた待ち・見張りは全部、終了コード 3 で終わる。Claude のセッションからは、スキル `/kiro-watch-clear` が同じこと（`clear` と、続けて `status`）を行う。

退避から戻すには、ほかの呼び出しが走っていないときに、退避したファイルを `state.json` へコピーして `tick` を呼ぶ。戻るのは記録だけで、`clear` で終わった見張り・待ちは戻らない。見張りの無い「作業中」の参加者は `tick` が外すので、各セッションは `watch` を立ててから申し込み直す。

### Claude のアプリを閉じた後に見張りが残っている

アプリを閉じても、バックグラウンドの見張り・待ちのプロセスが残ることがある。残った見張りは「居る」印を握り続けるので、そのセッションは落ちていても `absent` が付かず、自動では外されない。`status.md` の Waits and watches で、もう無いセッションの識別を見つけたら `leave --id <識別>` を呼ぶ。記録が消えると、残っていた見張り・待ちは自分で終了コード 3 で終わる。

### 同じ識別の `watch` が残っていて、新しい `watch` が 1 で終わる

`a watch wait for <識別> is already running` と出る。前の見張りのプロセスがまだ走っている。

- 申し込みや机を残したいとき: `status.md` の Waits and watches で、種類が `watch`・同じ識別の行のプロセス番号を見る。その番号のプロセスが `areka-impl-watch.exe` であることを確かめてから止め、直ちに `watch` を立て直す。
- 残さなくてよいとき: `leave --id <識別>` を呼ぶ（前の見張りは自分で終わる）。その後 `watch` を立てて申し込み直す。

### `loadrunning` の後も停止要請が残っている

`loadrunning` は、すでに出ている停止要請を取り消さない（新しく出さないだけ）。戻したければ、続けて `unstop` を呼ぶ。

### 止まっている間に停止要請が出し直された

止まっている間に `unstop` が呼ばれると、停止要請はいったん取り消される。しかし、ひとり占めを含む申し込みがまだ待たれている、または走っている記録（`loadrunning`）でないひとり占めが持たれていれば、同じ呼び出しの中で停止要請が出し直され、その参加者は「停止要請中」になる。`unstop` の出力（`unstopped n=<人数>`）には、出し直しは載らない。

出し直された参加者の見張りは、最初の停止要請ですでに終わっている。そこで、出し直しは再開の待ちが知らせる: 走らせてある `stopped --wait`（または `resume`）が、`stop requested again by <識別>` と出して終了コード 0 で終わる（`<識別>` はひとり占めを待っている・持っている参加者）。セッションは、もう一度 `stopped --id <識別> --wait` を走らせる。そうするまで、その参加者は「停止要請中」のままで、負荷テストの番は来ない。

- 再開の待ちを走らせていなかった参加者には、出し直しが知らされない。`status` で、止まっているはずの参加者が `stop-requested` と出ていたら、そのセッションに `stopped --id <識別> --wait` を呼ばせる。
- 止まっている参加者が `request` を申し込んでも、その参加者の状態は変わらない。「止まった」のまま並び、ひとり占めを含む申し込みなら自分の番が来たときに作業へ戻る（含まない申し込みは再開まで番が来ない）。

### 生きているのに外された

待ちが終了コード 3（`gone: …`）で終わり、`status.md` の最近の出来事に、その識別の `reclaimed`（`watch absent`）が載っている。見張りを立てる前に申し込んだ、見張りが終了コード 1 で終わってから立て直すまでに間があった、のどちらかがほとんどである。どの場合も、`watch` を立ててから申し込み直せば元に戻る。

### ファイルを開いたままのアプリが居る

- `state.json` を、ほかからの置き換えを許さない形で開き続けているアプリが居ると、状態を変えるコマンドが `io write state.json: PermissionDenied (os error 5)` で終了コード 1 になる（`clear` は `io set aside state.json: …`）。状態は変わっていない。そのアプリを閉じて呼び直す。すでに走っている待ち・見張りは、読むだけなので続く。
- `status.md` を同じように開いているアプリが居ても、コマンドは失敗しない。変更は記録され、結果の行も終了コードもふだんと同じである（`status` も要約を出して終了コード 0）。書けなかったのは読み物だけで、`impl-watch.log` に `[store] status.md not written; the result stands` の警告の行が残る。`status.md` は、次に書けたとき（次の変更か `status`）まで古い中身のままになる。

### 状態ファイルが壊れた・無くなった

- 状態を変えるコマンドが、読めない状態ファイルを見つけると、`state.json.broken-<UTC>` へ退避して空から始める（上書きはしない）。`status.md` の最近の出来事に `recovered`（`backed up: <道筋>`）が載り、ログにも残る。参加者は全員消えているので、走っていた待ち・見張りは終わる。終了コードは、退避の後に読み直したものが 3、退避より先に読めないファイルを読んでしまったものが 1（`state file is broken; see impl-watch.log`）。どちらの場合も、各セッションは `watch` を立ててから申し込み直す。
- 状態ファイルが無いときは、空から作る（最近の出来事に `recovered`・`created`）。
- `status` は作りも退避もしない。無ければ `no state file`、読めなければ `state file is broken; see impl-watch.log` で終了コード 1。

### 識別と名前の注意

- **識別は小文字に寄せて使われる。** `A` と `a` は同じ参加者で、出力にも `status` にも小文字で出る。大文字と小文字だけが違う識別を、別々のセッションに付けない（同じ参加者として扱われ、後から立てた `watch` は `already running` で終了コード 1 になる）。
- `con`・`nul` など、Windows の予約名も識別に使わない。
- Bash で空の変数を引用符つきで渡すと（`--name "$NAME"`）、名前が空になる。引用符なしなら、値が抜けて終了コード 2 になる。
- 1 つの識別で 2 つのリポジトリのマージの机を同時に持たない。`merged` は持っている机を全部空け、どちらの「直前のマージ」にも同じ PR とコミットを書く。

### `status.md` の中身が古い

`status` は排他を取らずに `status.md` を書くので、同時に走った変更の内容を古い内容で上書きすることがある。`status.md` を開いたままのアプリが居て書けなかったときも、古い中身のまま残る。どちらも、次の変更か、もう一度の `status` で直る。正本は `state.json` である。

## 7. 置き場所の下のファイル

| ファイル | 中身 | 手で消してよいか |
|---|---|---|
| `areka-impl-watch.exe` | 実行ファイル | 置き方の道具で置き換える（3 節） |
| `areka-impl-watch.old-<UTC>.exe`（前の形の `areka-impl-watch.old.exe` も） | 更新のときに改名した古い実行ファイル。走っていて消せなかったものが残る | 置き方の道具が次に消す |
| `areka-impl-watch.new.exe` | 写したばかりの新しい実行ファイル。置き方の途中で止まったときだけ残る | 置き方の道具が次に上書きして使う |
| `state.json` | 状態の正本（UTF-8 の JSON・版つき。今は版 2） | 消さない・手で書き替えない。消したいときは `clear` |
| `state.lock` | 状態を変える間だけ握る排他の印（空） | 消さない |
| `alive\<識別>.<種類>.lock` | 「居る」印（空）。走っている見張り・待ちが握る。種類は `watch`・`merge`・`request`・`resume`。終わっても残る | 誰も走らせていないとき（`waits=0`）だけ消してよい。走っている間は消さない |
| `status.md` | 人が読む状態（UTF-8）。状態が変わるたびと `status` のたびに書き直される | 消してよい（次に書き直される） |
| `impl-watch.log` | ログ（追記）。状態の変化 1 件に 1 行と、失敗。切り詰めはしない | 大きくなったら、誰も走らせていないときに消してよい |
| `state.json.broken-<UTC>` | 読めなかった状態ファイルの退避 | 調べ終えたら消してよい |
| `state.json.cleared-<UTC>` | `clear` の前の状態ファイルの退避 | 戻す必要が無くなったら消してよい |
| `state.json.<プロセス番号>.tmp`・`status.md.<プロセス番号>.tmp` | 書きかけ。書き終えると置き換えで消える | 残っていたら（書いている途中で止められた）、誰も走らせていないときに消してよい |

`<UTC>` は `20261010T105033Z` の形。退避のファイルは、同じ秒に 2 度退避したときに、末尾に `-1` のように番号が付く。
