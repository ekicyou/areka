## 2. この単位は何か

- **誰の**: ノベルの作者（pasta で書く）と、遊ぶ人。
- **何のため**: 1 枚の窓の中に、背景・人物・台詞の箱を、何枚でも重ねて出す。今の areka は、スコープ 1 つに透明の窓を 1 枚ずつ、2 人までである。
- **どうする**: 台本が「舞台を開く」「並びを決める」「位置・重ね順・大きさ・透明度を置く」「転換する」を命令で書く。areka は、届いた順に当てるだけである。舞台を開いたのも、並びを決めたのも、台本である。
- 例（命令の名前は仮）:

```
\![play,stage,window]\![play,cast,教室,さくら,台詞枠]\p[0]\s[0]\p[1]\![play,pos,600,200]\s[5]\p[2]\s[0]\p[1]むかしむかし。\![play,next,OnPlayNext]
```

  舞台の窓が開き、`\p[0]` は「教室」、`\p[1]` は「さくら」、`\p[2]` は「台詞枠」を指すようになる。さくらの字は、台詞枠の箱に出る。全部が同じフレームに出る。
- 舞台を開かない台本では、この単位は何もしない。デスクトップのゴーストの動きは、1 つも変わらない。

## 3. 暫定の要件

出どころの略: 【決】＝決め。【骨 n】＝骨組みの章。【取】＝取り決めの brief の「決定（最終形）」。【b】＝`shell-multi-compose` の brief。【指】＝今回の割り当て。

1. `play` の命令（舞台・並び・位置・重ね順・大きさ・透明度・転換）を受けるのは、舞台が開いている間だけである。閉じている間に届いた物は、何もせず `warn!` を 1 行残す。【決・骨 8・b の追記⑴】
2. 舞台を開く命令で、areka は舞台の窓を 1 枚開く。形はウィンドウ・全画面・ボーダーレス。同じ形をもう一度受けたら何もしない。別の形なら、開いたまま替える。【取「舞台の窓と箱」】
3. 基準は 1920×1080（96DPI の論理の大きさ）。窓の中に、比を保って拡大縮小し、中央に置き、余りは黒にする。窓の形も大きさも保存しない。最大化のボタンは押せない。【取】
4. 舞台が開いている間、デスクトップの窓とバルーンを隠す。閉じたら戻す。【取】
5. 並びの命令で、舞台のアクターを、その並びに置き換える。並びに無いアクターは消える。同じ並びなら何もしない。【取】
6. スコープの番号は、並びの順のアクターを指す。流れ（主・並走）は、始まった時の舞台の並びから読み始め、自分の中の並びの命令より後ろは、新しい並びで読む。【取・骨 2・指 4】
7. 読み替えるのは、スコープを宛先にする合図だけである。それ以外の合図は、今のまま流す。【前の検証の 1】
8. アクターごとに、どのシェルか・そのシェルの中のどの側か（`sakura`・`kero`・`charN`）を持つ。【前の検証の 2】
9. 1 回に配った命令は、全部当ててから絵を出す（作りかけの舞台を見せない）。【取「命令の表」】
10. 主の流れの命令も、並走の流れの命令も、届いた順にそのまま当てる。areka は裁かない。【決 D・骨 2】
11. 出し直しの印は、舞台の受け口が自分で拾い、アクターに付く値を既定へ戻す。舞台そのもの（窓・並び）は戻さない。【骨 3・指 5】
12. 転換は、dola の口（今の値から終わりの値へ、長さと形で始める／終わりの値にする）で動かす。舞台は、時計も補間も持たない。【決・骨 7】
13. 舞台の上のクリックは、今までどおりイベントを投げるだけである。舞台が決めるのは「どのアクターに当たったか」と Reference の中身である。透明な所でも、当たり判定の領域が在れば当たる。黒い余白は送らない。【決 A・骨 6】
14. 台詞の箱（字の出ている箱）のクリックは、今までどおり areka が使う。【骨 6】
15. 字は、話者のスコープに打たれた物を、並びで最初の、出ている「字を受ける」アクターの箱へ出す。そのアクター自身の字は、自分の箱に出す。居なければ、話者自身のシェルの箱へ出す。舞台の中に、ふつうのバルーンは出さない。行き先の無い字は、出さずに記録する。【取】
16. 話者の名前は、字を受けたアクターのシェルの、決まった名前の箱に出す。箱が無ければ出さない。話者が替わるたびに置き換える。【取・前の検証 3 章の 5】
17. 舞台の窓の × と Alt+F4 は、`OnClose` へ流す。SHIORI が答えなくても、遊ぶ人は必ず出られる。【取・指 4】
18. 舞台が閉じている間の動きは、1 つも変えない。失敗は記録し、メッセージボックスは出さない。`play` に関わる物は v0.3.0 より後、dola の直し（v0.2.0）の後に作る。【決・骨 1 の 4・b】

## 5. 設計

### 5.1 どの層に何を足すか

| 層 | 足す物（仮の名前） | 中身 |
| -- | ------------------ | ---- |
| `areka-runtime`・`areka-seriko`・`areka-emo-text` | アクターごとの表 | 鍵 → 「どのシェルの表か」と「どの側か」。今 1 つしか無い表（4 章）を、鍵で引く形にする（5.2） |
| `areka-runtime` | 読み替え（純粋な関数）と、名前と鍵の表 | 流れを始める前に、合図の列のスコープの番号を、アクターの鍵へ書き換える（5.3） |
| `areka-sakura`（`drive.rs`）・`areka-ghost` | 読み替えを呼ぶ所 1 つ | 台本を合図に直した直後（`drive.rs:250` の次）に、外から渡された口を 1 回呼ぶ。`areka-ghost` は、起動の時に受け取った口を、トークごとに渡すだけ（どちらも中身を知らない。今の `system_vars` の渡し方と同じ形） |
| `dola`（`CueSink`） | 「配り終えた」の口 1 つ | 再生機が、1 回の `tick` で配る分を配り終えた直後に呼ぶ。既定は何もしない（5.4） |
| `areka-runtime` | 舞台の受け口 `StageCueSink` | 舞台の命令を名前で拾い、UI スレッドへ送る。受け口の並びの先頭に置く |
| 純粋な層（`areka-placement` の中） | `StageState`・`stage_fit`・`stage_hit` | 舞台の値・窓の大きさから拡大率と余白を出す計算・当たりの決まり。時計も窓も見ない |
| `areka-placement` | 舞台の窓・デスクトップの窓を隠す／戻す | 今の `spawn.rs` とは別のファイル。別の印（`StageWindowMarker`）を持つ |
| `areka`（本体） | 舞台の上のマウスの入口・閉じる要求 | デスクトップの入口（`crates/areka-input/src/lib.rs`）とは別の入口。今の入口は触らない |
| `areka-emo-present`・`areka-seriko`・`areka-emo-text` | 動いている途中にアクターを足す・外す口／組の始まりと終わりの知らせ | 5.2・5.4 |
| `wintf` | 枠つきの窓の確かめと直し・窓を隠す口・全画面 | 持ち主の spec が無い（11 章） |

### 5.2 アクターごとの表（「全スコープが同じシェル」を外す土台）

- **誰が・何のために**: seriko・文字の層・着せ替えの側を引く所が、「この鍵のアクターは、どのシェルの、どの側か」を引くための表である。
- 1 行は「鍵 → シェルの表（SERIKO・サーフェスの名前・着せ替えの名前・箱・カーソル）と、側（`sakura`・`kero`・`charN`）」。
- **デスクトップのゴーストでは、起動の時に、今と同じ中身を入れる。** 鍵 0 →（ゴーストのシェル・`sakura`）、鍵 1 →（同じシェル・`kero`）。側は、今の決まり（`bind.rs:299-308`）で出した値を入れる。引いた答えは今と同じなので、動きは変わらない。
- 舞台のアクターは、並びの命令で、行が足される・外される。側は、並びの命令が渡す（書かなければ `sakura`）。
- これで、前の検証の 2（鍵の数 1 つが 2 つの意味）が消える。下流は、側を数から決めず、表から引く。
- この土台は、舞台より先に、単独で作れる（13 章）。`extra-character-windows`（3 人目からの窓）も、同じ表に乗る。

### 5.3 並びと、スコープの番号の読み替え

**状態と、それを入れる命令:**

| 状態 | 持つ所 | 入れる命令 |
| ---- | ------ | ---------- |
| 舞台の並び（今、舞台に出ているアクターの鍵の列） | `StageCueSink` が書く、分け持つ 1 つの値 | `\![play,cast,…]`（舞台を閉じる命令で「無い」） |
| 名前と鍵の表（名前 → 鍵。足すだけ） | `areka-runtime` | `\![play,cast,…]`。ゴーストの切り替え・終了・SHIORI の読み直しで空にする |

**読み替え（純粋な関数）:**

- 入るもの: 流れを始める時の舞台の並び・合図の列。出るもの: 合図の `actor` を書き換えた列。合図の数と順は変えない。
- 列を頭からたどる。スコープを宛先にする合図（下の表）は、番号 n を、その時の並びの n 番目の鍵に書き換える。並びの命令に出会ったら、そこから後ろは新しい並びで読む。
- 並びが「無い」間は、何も書き換えない（**舞台を使わない台本は、1 文字も変わらない**）。
- 並びが在るのに、番号に当たるアクターが居ない合図（スコープを宛先にする物だけ）は、鍵を「無い」にして流し、受け口が捨てて `warn!` を残す。
- 鍵は、名前ごとに 1 つで、変わらない（`STAGE_ACTOR_BASE + 連番`）。台本が帯の中の番号をじかに書いたら、捨てて記録する。

| 合図 | 読み替え |
| ---- | -------- |
| `\s`・`\b`・字・改行・`\c`・選択肢・`\_l`・アンカー・`\i`・`\![bind,…]`・`\![anim,…]`・`play` の位置／重ね順／大きさ／透明度／話者の名前 | **読み替える**（スコープを宛先にする） |
| 待ち・全消去・音・`\![raise]`・`play` の舞台／並び／転換／出し直し／続き／目印／早送り／高速再生・並走の印・表に無い名前の `\![…]` | 読み替えない（今のまま流す） |
| 正典の窓の命令（`\![move]`・`\![set,zorder]`・`\![set,sticky-window]`・`\![set,alpha]`・`\![set,scaling]`・`\![change,shell]`・`\![reload,shell]` ほか） | 読み替えない。**意味は今のまま**（デスクトップの窓に効く。舞台が開いている間は、隠れた窓に効く） |

**いつ呼ぶか**: 流れを始める直前（台本を合図の列に直した直後・並走の区間に分ける前）に 1 回。主の流れも、並走の 1 本も、同じ口を呼ぶ。区間は、主の列を読み替えた後に分けるので、開く印の位置の並びで読まれる。先渡し（`preview`）も `emit` も、読み替えた後の値を受け取るので、受け口ごとの食い違いは起きない。

**シェルの読み込み**: 同じ口の中で、並びの命令に初めて出た名前のシェルを、流れを始める前に読み、seriko・文字の層・表示対象へ行を足す（UI スレッドの外）。台本の時計は、読み終わってから動き出す。字が絵より先に進むことは無い。読めなかった名前は、表に「読めない」と書き、その鍵宛ての合図は受け口が捨てて記録する（番号は詰めない）。

### 5.4 1 回に配った命令を、全部当ててから出す

- **組**＝再生機が 1 回の `tick` で配った合図の全部（同じ時刻の命令は、必ず同じ組に入る）。区切り（`\x`・選択待ち・続きを示すキューコマンド）に着くと、再生機は手前まで配って止まるので、組はそこで閉じる。
- dola の `CueSink` に、口を 1 つ足す（仮 `delivered()`。既定は何もしない）。再生機は、合図を 1 つ以上配った `tick` の終わりに、全部の受け口へ 1 回ずつ呼ぶ。並走の流れを進める所も、同じ時に呼ぶ。
- 舞台の受け口・seriko の受け口・文字の受け口は、組の最初の `emit` で「組の始まり」、`delivered()` で「組の終わり」を、自分の線へ流す（流れの番号と通し番号つき）。seriko は、受け箱の順のまま、提示の段へ中継する（今の `StageAck` と同じ、合成に触らない合図。`crates/areka-emo-present/src/command.rs:95-105`）。
- UI スレッドは、フレームごとに 3 本の線を全部受け取ってから、**舞台のアクター宛ての物だけ**を次の決まりで当てる。
  - 開いている組（どれかの線で始まり、3 本ともでは終わっていない組）が 1 つでも在る間は、貯める。
  - 開いている組が 0 になったら、貯めた物を、線の中の順のまま、舞台 → 絵 → 字 の順に、同じフレームで全部当てる。
  - 組が 1 秒（仮）閉じなければ、`error!` を残して当てる。
- デスクトップの表示対象宛ての物は、貯めずに今のまま通す（動きは変わらない）。
- フレームを数えて待つ所は無い。当てる条件は「組の全部が届いた」である。台本の時計は止めない。

### 5.5 舞台の値と、残る命令

`StageState`（純粋な値）: 開いているか・形・並び・アクターごとの〔位置・重ね順・大きさ・透明度・字を受ける印〕。

| 命令（仮） | 宛先 | 入れる値 |
| ---------- | ---- | -------- |
| `\![play,stage,window]`・`fullscreen`・`borderless`・`close` | 舞台 | 開いているか・形 |
| `\![play,cast,名前…]` | 舞台 | 並び |
| `\![play,pos,x,y]`・`\![play,z,数]`・`\![play,scale,百分率]`・`\![play,alpha,百分率]` | 今のスコープのアクター | 位置・重ね順・大きさ・透明度（引数なしは既定） |
| `\![play,again]` | 舞台 | 全アクターの位置・重ね順・大きさ・透明度・字を受ける印を既定へ。窓と並びは戻さない |
| `\![play,trans,ミリ秒]` | 舞台 | 残らない（5.7） |

- 命令は値を書き換えるだけで、絵には触らない。組を当てる時に、**組の前の値と後の値の差**だけを絵へ当てる。「同じ値は何もしない」「出し直しで戻して当て直した結果が前と同じなら、ちらつかない」は、この形から出る。
- 表情（サーフェス）と着せ替えは、seriko が持つ。出し直しの印は、seriko の受け口も自分で拾い、舞台のアクターの表情と着せ替えを既定（サーフェスは「無い」）へ戻して、組の終わりに差だけを出す（同じサーフェスの置き直しでは、アニメーションを頭から始めない）。骨組みの 3 章の表の書き方との違いは、12 章の 1。
- 舞台を閉じる時: 並びを「無い」にし、アクターの値を捨て、走っている転換を dola の口で捨て、窓を閉じ、デスクトップの窓を戻す。並走・バックログ・seriko・文字の層は、**同じ命令を自分で拾って**、自分の物を片付ける（知らせる口は作らない）。
- ゴーストの切り替え・終了・SHIORI の読み直しの時も、舞台を閉じる（骨組みの 4.2 の高速再生と同じ線）。

**役と立ち位置（決まっていない。2 通り）:**

| | 案 A: 役は 3 値の宣言で、自動に置く | 案 B: スポットごとの値を、pasta が命令で渡す |
| - | ---- | ---- |
| 位置・重ね順の既定 | シェルの役の宣言と並びから、`auto_layout`（純粋な関数）が出す | 位置は原点、重ね順は並びの順 |
| 字を受ける印 | 役が「トークの場所」なら立つ | 命令で立てる（仮 `\![play,textbox,1]`。並びの命令に添える形でもよい） |
| 側 | 舞台の定義に書く | 並びの命令で、名前に添える |
| areka が読むファイル | シェルの descript の役・舞台の定義の席（素材の単位が読む） | 0 |

**どちらでも変わらない所**: `StageState` の欄・読み替え・組・差を当てる所・当たり・字の行き先の決まり（「字を受ける印の在るアクター」で書いて在る）・転換。変わるのは、「既定の値を出す関数」1 つと、印の出どころだけである。

### 5.6 舞台の窓と、描く木

| 形 | 窓 | 大きさ |
| -- | -- | ------ |
| ウィンドウ | OS の枠つき・タスクバーに出る・最大化なし | 開く時はモニターに収まる大きさ。遊ぶ人が変えられる |
| 全画面 | 枠なしで、今いるモニターいっぱい | モニターの大きさ |
| ボーダーレス | 枠なし | （仮定）基準 × モニターの倍率を、収まるまで縮めた大きさ |

- 拡大率 s と余白は、`stage_fit(窓の中の大きさ)` で出す。窓の大きさが変わった知らせ（プッシュ）のたびに引き直す。
- 描く木は、前の設計の案 A のまま（アクターごとに描画面）: 舞台の窓（黒）→ 舞台の中身（offset＝余白）→ アクターの席（重ね順の順・offset＝位置 × s・不透明度＝透明度）→ 文字の層の置き場・絵（offset＝0・拡大率＝s × アクターの大きさ）・消えていく前の絵。絵の拡大率は、今の「アプリの倍率」の席に入れる（値を時間で変える単位と、同じ席を使う。10 章）。
- デスクトップの窓を隠す・戻すは、舞台を開く・閉じる命令を当てる時に行う。隠れている窓にも、正典の命令は今までどおり効く。

### 5.7 転換（dola の口を使う）

- 転換の命令から「次の字・次の待ち・次の転換・列の終わり」までが、転換の組である。舞台の受け口と seriko の受け口が、**どちらも転換の命令を拾い**、その間の自分の変更に「何ミリ秒かける」を付ける。
- 値（位置・大きさ・透明度・並びの出入りの透明度）: 差を当てる時に、dola の口「今の値から、終わりの値へ、長さと形で始める」を呼ぶ。始まりの時刻は、転換の合図の時刻（dola の直しの後の、絶対の時刻）を渡す。当てるのが遅れたら、過ぎたぶんだけ進んだ値から出る。転換なしの変更は、走っている変化を終わりの値にしてから、値を置く。重ね順は、その瞬間に替える。
- サーフェス: 転換つきで替わった絵は、前の絵を「消えていく前の絵」として残し、その不透明度を dola の口で 1 → 0 に動かす。終わりの知らせ（プッシュ）で外す。SERIKO のコマ送りは溶かさない。
- 始めた変化には、流れの番号を札として付ける。早送りが主の流れに掛かった時は、主の流れの札の変化を、dola の口で全部終わりの値にする（骨組みの 7 章）。並びを出るアクターは、透明度が 0 に着いた知らせで外す。
- 形は等速で始める。形の選び方は、値を時間で変える単位の語彙を使う。揺れとフラッシュも、同じ口で作る（残らない。引数は未定）。

### 5.8 当たり（どのアクターに当たったか）

**今の作りとのつながり。** デスクトップでは、決まりが 2 段である。⑴ 窓がクリックを拾うか＝絵の濃い画素（α ≥ 128/255）だけ（`mount.rs:107-112`）。⑵ 領域の名前＝α を見ずに引く（`hit.rs:50-97`）。透明な画素のクリックは、⑴ で後ろのアプリへ抜けるので、⑵ に届かない。舞台の窓は、中が黒で埋まった 1 枚の窓なので、後ろへ抜ける先が無い。そこで舞台では、⑴ の「窓」を「アクター」に読み替え、⑵ の関数をそのまま使う。

**決まり（`stage_hit`・純粋な関数）**: 押した点が黒い余白なら、何も送らない。そうでなければ、アクターを**手前から順に**見て、最初に次のどれかに当たった所で決める。隠れているアクター（サーフェスが無い）は飛ばす。

| 順 | 条件 | 結果 |
| -- | ---- | ---- |
| 1 | 点が、そのアクターの「字の出ている箱」の中 | 台詞の箱のクリック。今の箱の前段（`shell_box_handler`）と同じ扱いで、areka が使う（選択肢を選ぶ・再生の制御の単位の「吹き出しのクリック」）。イベントは、今の箱と同じ |
| 2 | 点が、そのアクターの当たり判定の領域の中（**透明な画素でもよい**） | そのアクターに当たり。Reference4＝領域の名前 |
| 3 | 点の画素が濃い（α ≥ 128/255） | そのアクターに当たり。Reference4 は空（デスクトップと同じ） |
| — | どれでもない | 次のアクターへ。最後まで無ければ、何も送らない |

- 領域の名前は、今の `hit_region_client` へ、席の原点を引いた点を渡して引く。α は、絵の Entity が持つ α マスクを読む。どちらも今の口を使うだけで、直さない。舞台のアクターの絵は wintf の当たりから外し（`HitTest::none()`）、舞台の中身の Entity 1 つが受ける。
- イベントは今のまま（`OnMouseUp` → 返事が無ければ `OnMouseClick`）。Reference0・1＝そのアクターのサーフェスの中の座標（今と同じ ÷k の値。ukadoc: 「Reference0: マウスカーソルの x 座標（ローカル座標）」 `https://ukatech.shillest.net/ukadoc-spec/list_shiori_event.html#OnMouseClick`）。Reference3＝送る時点の舞台の並びでの番号。Reference4＝領域の名前。
- **デスクトップのゴーストの当たりは、1 行も変えない。** 舞台の入口は別の関数で、デスクトップの入口（`on_char_pointer_pressed`・`char_scope`）を通らない。
- 例（開発者の例）: 全部が透明な 1920×1080 のサーフェスに `collision0,0,0,1919,1079,screen` を書いたシェルを、いちばん上のアクターにする。どこを押しても、順 2 で `screen` に当たり、`OnMouseClick`（Reference4＝`screen`）が届く。SHIORI が `\![parallel]\![play,fastforward]` を返すと、今の行が早送りされる。areka は、クリックを早送りに使っていない。

### 5.9 字の行き先と、話者の名前

- 字の合図の `actor` は、話者のままにする。回すのは、文字の層である。字の場所の鍵を「（持ち主のアクター, 場所）」として使い、話者と持ち主が違ってよい形にする。
- 行き先の決まり: 話者が字を受ける印を持てば、自分の箱。そうでなければ、舞台の並びで最初の、出ている、字を受ける印の在るアクターの既定の箱。居なければ、話者自身のシェルの箱。それも無ければ、出さずに `warn!`。
- 文字の受け口は、並びの命令と字を受ける印の命令を**自分でも拾い**、自分の線の順で、行き先の表を進める（別のスレッドの状態を、後から読まない）。
- クリック待ちの印・選択肢・`\c` は、字と同じ行き先の箱に出る。だから「どのアクターの箱の上か」は、5.8 の順 1（手前から見て、最初に点を含んだ、字の出ている箱）で決まる。
- 話者の名前: 字を回した時、行き先のシェルの決まった名前の箱へ、話者の並びの名前を置く。`\![play,speaker,名前]` が在れば、その 1 本では、そのスコープの名前をそれにする。話者が前の字と違えば置き換える。字を受けるアクター自身の字の時は、空にする（仮定）。

### 5.10 舞台から出る道

- 舞台の窓の閉じる要求（×・Alt+F4・タスクバーの「閉じる」）は、今のゴーストの窓と同じ受け手へつなぎ、同じ終了要求（`OnClose`）にする。窓は、終了の流れが終わった時に閉じる。SHIORI が別れの台詞を返さなくても、今の終了の流れの上限（30 秒）で終わる。舞台が止まっていても、この道は台本に依らない。
- 全画面とボーダーレスには × が無い。Alt+F4 は、舞台の窓が入力を持っていれば効く。
- 舞台だけを閉じてデスクトップへ戻る道（areka のキーやメニュー）は、作らない。台本の命令に依らずに舞台の状態が変わり、pasta の覚えとずれるためである。
- 右クリックは、5.8 の決まりでアクターを決めた後、今と同じに扱う（メニューを出すか、`OnMouseClick` の Reference5＝1 で送るかは、正典のリソース `*.popupmenu.visible` の答えで決まる）。メニューの中身を替える道（見立ての A・B・C）は、決まっていない（11 章）。

### 5.11 失敗の扱い

| 失敗 | 扱い |
| ---- | ---- |
| 舞台が閉じているのに届いた舞台の命令 | 何もせず `warn!` |
| 並びの名前が解けない・シェルが読めない・「借りないで」 | そのアクターを飛ばす。`warn!`（名前・理由）。番号は詰めない |
| 番号に当たるアクターが居ない・帯の中の番号をじかに書いた | その合図を捨てて `warn!` |
| 読めない引数 | その命令だけ捨てて `warn!`。値は変えない |
| 行き先の箱が無い字 | 出さずに `warn!` |
| 組が閉じない | 上限の時間で当てて `error!` |
| 舞台の窓が作れない | `error!`。デスクトップの窓は隠さない。舞台は閉じたまま |

### 5.12 台本から受け口まで（2 章の例）

1. トークのスレッドが、台本を合図の列に直す。読み替えの口を呼ぶ。並びは「無い」から始まり、並びの命令で 教室→鍵 A・さくら→鍵 B・台詞枠→鍵 C を名前と鍵の表に足す。3 つのシェルを読み、seriko・文字の層・表示対象へ行を足す。`\p[0]\s[0]` は鍵 A、`\p[1]` の位置と `\s[5]` と字は鍵 B、`\p[2]\s[0]` は鍵 C 宛てに書き換わる。全消去・舞台・並び・続きの命令は、そのまま。
2. 再生機の最初の `tick` が、時刻 0 の合図（字まで）を、全部の受け口へ順に配り、`delivered()` を呼ぶ。
3. 舞台の受け口は、舞台・並び・位置を拾い、組の始まり・命令の列・組の終わりを 1 通で UI へ送る。seriko は、並びと `\s` を拾って絵を決め、提示の段へ流す。文字の受け口は、並びを拾い、鍵 B の字を鍵 C の箱へ回す。
4. UI スレッドは、3 本の線の組の終わりがそろったフレームで、舞台の窓を開き、デスクトップの窓を隠し、席を 3 つ作り、位置・絵・字を当てる。
5. 再生機は、字を出し終えて、続きを示すキューコマンドで止まる（再生の制御の単位）。

## 7. 立場の確かめ

**areka が持つ状態**（全部。どれも台本の命令が入れる）:

| 状態 | 入れる命令 | 消える時 |
| ---- | ---------- | -------- |
| 舞台が開いているか・形 | `play,stage` | `play,stage,close`・ゴーストの切り替え・終了・SHIORI の読み直し |
| 舞台の並び | `play,cast` | 同上 |
| アクターごとの位置・重ね順・大きさ・透明度・字を受ける印 | `play,pos` ほか | 出し直しの印（既定へ）・並びから出た時・舞台を閉じた時 |
| 名前と鍵の表・読んだシェル | `play,cast` | ゴーストの切り替え・終了・SHIORI の読み直し |
| 走っている転換（持つのは dola） | `play,trans` | 終わった時・早送り・舞台を閉じた時 |
| その 1 本の話者の名前 | `play,speaker` | その 1 本の終わり |
| デスクトップの窓を隠している | `play,stage`（舞台が開いている、に従う） | 舞台を閉じた時 |

台本に依らない物が 1 つ在る: ウィンドウの形の窓の大きさ（遊ぶ人が OS の操作で変える。保存しない）。

**areka が判断する所**: ⑴ 当たりの決まり（5.8。台本の中身も状況も見ない、いつも同じ決まり）。⑵ 組がそろうまで貯める（5.4。出す時だけを決め、命令の中身は変えない）。⑶ 失敗の時に捨てて記録する（5.11）。台本の中身や状況を見分けて動きを変える所は **0**。

**既定の動作の変更**: **0**。正典のタグに足した意味も 0（スコープの番号が指す先を替えるのは、並びの命令である）。

## 11. 置いた仮定と、決まっていない所

**仮定**: ⑴ 舞台を開く・閉じる・形を替えるは、1 つの命令で受ける。⑵ 舞台の窓は、ゴーストに 1 枚まで。⑶ 鍵は数の帯で、名前ごとに 1 つ。⑷ 並びを出たアクターの値は消える。⑸ 読んだシェルは、ゴーストのセッションの間は持ち続ける。⑹ 読めないアクターは、既定のシェルへ戻さず、飛ばす。⑺ 重ね順は、数が大きいほど手前。⑻ SSTP・MCP の台本も、同じ決まりで読み替える（出どころで分けない）。⑼ 描く木は案 A。⑽ 舞台のアクターは、掴んで動かせない（ドラッグのイベントは送らない）。⑾ 組の上限は 1 秒。⑿ 字を受けるアクター自身の字では、名前を出さない。

**決まっていない所**（開発者に諮る問い）:

1. **役と立ち位置は、案 A（役で自動）か、案 B（pasta が命令で渡す）か。** → 5.5 の「既定の値を出す関数」と、素材の単位が読むキーが変わる。ほかは変わらない。
2. **濃い画素で、領域の無い所は、後ろのアクターの領域を遮るか。台詞の箱は、重ね順のとおりに見るか、全アクターより先に見るか。** → 5.8 の順 1〜3 の並べ方と、10 章の 5 が変わる。
3. **右クリックのメニュー。** 見立ての 3 つの道（A 止めてイベントで受ける・B 正典の「おすすめ」に項目を出す・C ゴーストが項目の並びを答える）のどれにするか。舞台のアクターの `*.popupmenu.visible` を、どの側の名前で尋ねるか。→ 舞台の上でメニューを出す入口の作りが変わる。
4. **マウスの座標。** サーフェスの中の座標（正典の「ローカル座標」。この設計）か、舞台の基準の座標（取り決めの文）か。→ Reference0・1 の値と、取り決めの 1 文が変わる。
5. **ボーダーレスの中身（透明か黒か・大きさ）と、性能の目標（メモリ・開くまでの時間）。** → 5.6 の表・描く木を案 A のままでよいか・読んだシェルをいつ捨てるか。
6. 舞台を開かない演劇の出し直しの印で、デスクトップのスコープの表情と着せ替えを戻すか（12 章の 1 の答えに従う）。
7. 舞台の窓が作れなかった事を、pasta へどう伝えるか（既定のゴーストの台詞で伝える決まりとの関係）。

## 12. 骨組みを直したほうがよい所

1. **3 章の表の「舞台」の行。** 表情と着せ替えを持つのは seriko で（`crates/areka-seriko/src/actor.rs:349-356`）、舞台の受け口は、合図を通さずには触れない。舞台が閉じている演劇では、舞台の受け口は何もしないので、戻す者が居なくなる。行を 2 つに分けたい: 「seriko: 表情・着せ替えを既定へ戻す」「舞台: 位置・重ね順・大きさ・透明度を既定へ戻す」。
2. **6 章の最後の文。** 濃い画素で、領域の無い所が書いていない。デスクトップでは、そこも窓がクリックを拾い、Reference4 が空で届く（`crates/areka-emo-present/src/mount.rs:107-112`・`presenter/hit.rs:119-127`）。「領域が無くても、濃い画素なら、そのアクターに当たる（Reference4 は空）」を足したい。
3. **2 章か 8 章に、読み替えの決まりを 1 文。** 「流れは、始まった時の舞台の並びから読み始め、自分の中の並びの命令より後ろは、新しい並びで読む」。主の流れにも並走の流れにも同じに効く決まりで、今は割り当ての指示にしか無い。
4. **4.3 の順番に、再生機の「配り終えた」の口を足す。** 区切りの手前で組を閉じるには、再生機（`crates/dola/src/cue/runtime.rs:179-232`）が知らせるほか無い。再生の制御の単位が触る所と同じなので、順番の表に載せたい。
