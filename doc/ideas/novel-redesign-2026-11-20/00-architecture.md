# ノベル（演劇）の作り直し — 単位をまたぐ骨組み（2026-11-20・暫定）

- 2026-11-19 の暫定の設計（8 本）は、単位ごとに別々に書いたので、継ぎ目が割れた。2026-11-20 に開発者と議論して決めが出た（`doc/ideas/novel-decisions-2026-11-20.md`。以下「決め」）。この文書は、その決めから、**単位をまたぐ形を先に 1 つに決める**ための骨組みである。各単位の作り直しは、この文書に合わせる。
- 正式な設計ではない。命令の名前は、どれも仮である（pasta の取り決めで決まる）。コードは 1 行も書いていない。
- 上位の決定の正: 決め ＞ pasta の骨子（`final-model-2026-11-19.md` の 8 章 ＞ 上の章）と取り決めの brief。決めが骨子と食い違う所（決めの A〜D）は、決めが勝つ。

## 1. 立場

1. **areka は、さくらスクリプトの再生機である。** SSP（さくらスクリプトプレイヤー）と同じ立場。「イベントを投げて、さくらスクリプトが返ってきたら、再生する」という仕組みを壊さない。
2. **SSP との違いは、さくらスクリプトの並走を許す事である。** 表現力は、そこから得る。
3. **新しい働きは、「台本に書ける命令」と「台本の並走」で作る。** areka が自分で見分ける・振り分ける・モードを決める形にしない。areka が持ってよい状態は、台本の命令が入れた物だけである。
4. **既定の動作を変えない。** 新しい命令を使わない台本は、今までどおりに動く。正典のタグの意味に、areka だけの意味を足さない。

設計の中で「areka が○○を見分けて」「○○の時は areka が」と書きたくなったら、立場の 3 に反していないかを確かめる。台本の命令で言い直せないかを、先に考える。

## 2. 流れは 2 種類

| | 主の流れ | 並走の流れ |
|---|---|---|
| 何か | バルーン（字・選択肢・クリック待ち）に触る台本 | バルーンに触らない台本 |
| 同時にいくつ | 1 つ | いくつでも |
| 新しい台本が届くと | 前の主の流れを置き換える（正典のまま） | 何も置き換えない。横で走る |
| 見分け方 | 並走の印が無い | 台本の冒頭に並走の印が在る（1 本まるごと）。または、主の台本の中の、開く印から閉じる印までの区間 |

- 並走の流れに書ける物は、バルーンに触らない物の全部である。見た目（表情・着せ替え・アニメーション）・音・待ち・`play` の残る命令・**再生の制御の命令**（4 章）。字・選択肢・`\x`・続きを示すキューコマンドは、並走の流れでは読み捨てて記録する。
- **並走は並走。** areka は裁かない。主の流れの命令も、並走の流れの命令も、届いた順にそのまま当てる。同じアクターの表情を 2 つの流れが置けば、後に配られた方の絵が出る。避けるのは、台本を書く側である。
- 並走の流れは、主の流れが別の台本に替わっても、自分の末尾まで走る。止まるのは、出し直しの印・舞台を閉じる命令・ゴーストの切り替えと終了の時である。

## 3. 命令の配り方

- `\![名前,引数…]` は、中身を見ない入れ物（`Custom{command, params}`）で運び、**全部の受け口へ、同じ時刻に配る**。受け口は、名前を見て、自分の物を拾う。
- **1 つの命令を、複数の受け口が拾ってよい。** 関わる係が同時に受けるための作りである。「1 つの命令を拾う係は 1 つまで」というテストの縛り（`crates/areka-runtime/src/consumer_ledger.rs`）は外す。
- 「どの命令を、どの受け口が拾うか」の表は残す。台本の検査（`check_script`）と strict の記録が、「拾う受け口が居るか」を引くためである。表の 1 行は、受け口を並べて書ける形にする。同じ受け口を同じ命令に 2 度つなぐ誤りは、今までどおり見つける。
- 例: 出し直しの印 `\![play,again]` は、次の受け口が、それぞれ自分の物だけを行う。束ね役は作らない。

| 受け口 | する事 |
|---|---|
| 再生の制御 | その 1 本の字を一度に出し、待ちを飛ばす |
| 音 | 鳴っている途中の単発の音と声を止める |
| 並走 | 走っている並走の流れを全部止める |
| 舞台 | アクターに付く値（表情・着せ替え・位置・重ね順・大きさ・透明度）を既定へ戻す |
| バックログ | その 1 本を貯めない |

- 出し直しの印は、1 本の先頭（最初の字と待ちより前）に書く。先頭でない所に在れば、効かせずに記録する。

## 4. 再生の制御（高速再生基盤と道具）

### 4.1 基盤

**主の流れの再生を、速く進める仕組み。** 1 つだけ作る。できる事は 3 つ。

| 操作 | 中身 |
|---|---|
| 字を一度に出す | 字の 1 字ごとの間を 0 にする |
| 待ちを飛ばす | `\w`・`\_w` などの待ちを 0 にする |
| 止まる所を通る | クリック待ち（`\x`・続きを示すキューコマンド）で止まらずに、解いて先へ進む |

- 速く進めても、命令は 1 つも飛ばさない。書いた順に、全部当てる（**早送りは中身を見ない**。音だけ鳴らさない、という特別扱いは作らない）。
- 選択肢の待ちは、通らない（選ぶのは遊ぶ人である）。
- 効く相手は、主の流れである。並走の流れは、速く進めない。
- 基盤は、再生している最中に、掛ける・外すができる必要が在る（台本を読んだ時に長さを決め切る形だけでは、足りない）。

### 4.2 道具（基盤を使う物）

| 道具 | 使う操作 | 効く範囲 | 種類 |
|---|---|---|---|
| `\_q`・`\![quicksection,…]` | 字を一度に出す（待ちは飛ばさない。正典） | 台本の中の、挟んだ所 | 正典 |
| 吹き出しのクリックの早送り | 字を一度に・待ちを飛ばす。止まっていれば、解く | 今の主の流れの、次に止まる所まで | 正典の動き |
| 早送りの命令（仮 `\![play,fastforward]`） | 同上 | 同上 | areka の命令 |
| 高速再生の入切（仮 `\![play,fastmode,1]`・`0`） | 3 つとも | 「入」の間に主の流れで再生する台本の全部 | areka の命令（状態） |
| 出し直しの印（仮 `\![play,again]`） | 字を一度に・待ちを飛ばす（止まる所は、ふつうに止まる） | その 1 本 | areka の命令 |

- **早送りの命令**は、主の流れにも、並走の流れにも書ける。並走の流れに書いた時も、効く相手は主の流れである。絵のクリックで読み進める形は、これで作る: areka は今までどおり `OnMouseClick` を投げ、SHIORI が、並走の印と早送りの命令だけの台本を返す。主の流れが何も再生していなければ、何も起きない。
- **高速再生の状態**は、areka が持つ。入れる・切るのは、台本の命令だけである。切れるのは、「切る」の命令・ゴーストの切り替え・終了・SHIORI の読み直しの時。入切の命令も、並走の流れに書ける（今の行を替えずに切り替えられる）。
- 正典の `\_q` は、高速再生のための物ではない。作者が、台本の中で「ここは一度に出す」と書く道具である。

### 4.3 順番

dola の直し（v0.2.0・最優先）→ 基盤 → 正典の道具（`\_q`・`\x` の待ち・吹き出しのクリックの早送り）→ areka の命令の道具（`play` に関わる物・v0.3.0 より後）。同じファイル（台本を時刻の表に直す所・再生機）を触るので、順に作る。

## 5. 続きを示すキューコマンド

**「このスクリプトには続きがあります。クリックで進めてください。」**を表す命令（仮 `\![play,next,イベント名,引数…]`）。正典の `\x` とは別の物である。

```
\0むかしむかし。\![play,next,OnPlayNext]
```

| 段 | 起きること |
|---|---|
| 1. 着く | 主の流れが、そこで止まる。押されるのを待つ。待ちの印を出す |
| 2. 解ける | 書いて在るイベントを、SHIORI へ GET で投げる。引数は Reference0 から載る |
| 3. 返事を待つ | 話は続いていると扱う。バルーンを消さない。字もそのまま残す。Status は talking のまま |
| 4a. 台本が返る | その台本が、続きである。字を替えて再生する |
| 4b. 何も返らない | そこで話が終わる（ふつうの終わり方） |

- 解けるきっかけ: 吹き出しのクリック・早送り（命令でも、クリックでも）・高速再生が「入」・引数で書いた時間が過ぎた時。
- 1 本の末尾に置く。後ろに何か在れば、読み捨てて記録する。
- 待っている間に、別のイベントの返事で主の台本が届いたら、待っていた 1 本は置き換わる（正典の置き換えのまま）。投げるはずだったイベントは、投げない。
- 並走の流れに書かれた時は、読み捨てて記録する。
- 正典の `\x`（押すまで待って、同じ台本を続ける）と `\![raise]`（イベントを起こす）の意味は、変えない。SSP 向けの台本（末尾が `\x\![raise,…]`）を areka で再生した時は、正典どおりに動く（話は、台本の終わりで終わる）。
- 引数に載せる物（行の ID・自動で進むまでの時間）の形は、pasta の取り決めで決まる。前の `\![play,xtimeout,…]` は、この命令の引数に入る見込み。

## 6. クリック

- areka は、今までどおり、クリックのイベントを SHIORI へ投げる（`OnMouseUp` → 返事が無ければ `OnMouseClick`。Reference4 は当たり判定の名前）。**絵のクリックを、areka が自分で早送りや「進める」に使う事は、しない。**
- 吹き出し（台詞の箱）のクリックは、今までどおり areka が使う（クリック待ちを解く・早送り）。
- 「画面のどこを押しても読み進める」は、シェルと台本の作りで行う。例: 画面の全体を当たり判定の領域にした透明なアクターを、いちばん上に置く。押すと、その領域の名前で `OnMouseClick` が届き、SHIORI が早送りの台本を返す。
- 舞台の窓の中で、どのアクターに当たったかを決める決まり（上から順に、押した点を領域に含む最初のアクター。透明な所でも、領域が在れば当たる）は、舞台の単位が持つ。

## 7. 時刻と、値を時間で変える仕組み

- 時刻の土台は、dola の直し（v0.2.0）である。ノベルの物は、どれもその後に作る。
- **値を時間で変える仕組み（変化の形も含めて）は、dola が持つ。** 窓の指令（正典の `--time`）・舞台の転換・変化の形は、dola の口（今の値から、終わりの値へ、長さと形で始める／走っている変化を終わりの値にする）を使う。同じ仕組みを、areka の中に別に作らない。
- 早送りは、主の流れが始めた転換を、終わりの絵へ飛ばす（取り決めの「クリックで字を早送りしたら、走っている転換も、新しい絵へ飛ぶ」）。

## 8. 舞台と素材

- `play` の命令で位置・大きさ・透明度・重ね順・転換を受けるのは、舞台（ウィンドウモード）の中だけである。舞台を開かない演劇は、正典のタグ（`\![move,…]`・`\![set,alpha,…]`・`\![set,scaling,…]`）で届く。
- **役と立ち位置は、決めが出ていない。** pasta の側で開発者に諮っている途中である（開発者: 「スポットごとに座標情報が必要になると思う」）。areka の見立ては、「座標は pasta が命令で渡す。スポットごとに、座標・重ね順・字を受ける印を持てば、シェルの側の役の宣言は要らない」。舞台と素材の単位は、決まっていない所として扱い、どちらに決まっても変わらない形を先に書く。
- 素材の決まり（遊ぶ人による役者の差し替え・差し替える素材への要求・「この席は替えさせない」の指定）は、brief のまま残す。

## 9. 目印とバックログ

- 取り決めのまま。バックログは、どのゴーストでも貯まるベースウェアの機能。目印（仮 `\![play,mark,イベント名,ID]`）は、その 1 本の項目に付く。目印の在る項目を選ぶと、そのイベントを GET で投げる（Reference0＝ID）。選ばれた時に、その項目を含めて後ろを捨てる。`\__v[disable]` の区間は貯めない。
- 続きを示すキューコマンドで分かれた 1 本ずつが、1 項目になる。

## 11. 確かめていないこと
