## 2. この単位は何か

- **誰の物か**: 台本を書く人（ゴーストの作者・pasta）の物である。「窓をすべらせて移す」「ふっと消して現す」「大きくして戻す」を、台本に 1 行書くだけで動かしたい。
- **何をする物か**: 数の値（窓の位置・透明度・倍率。後で、舞台のアクターの値）を、今の値から終わりの値へ、決まった長さと形で変える。
- **誰が持つか**: 仕組みは dola が持つ（開発者「イージングはdolaの仕事」）。areka は、台本の命令を読んで、dola の口を呼び、出てきた値を窓へ書くだけである。
- 例（舞台を開かない演劇。デスクトップに浮いたまま）:

```
\0\![set,alpha,0,--time=500]\_w[500]\![move,--X=400,--Y=0,--base=screen]\![set,alpha,100,--time=500]席を替えたよ。\![play,next,OnPlayNext]
```

- この 1 本で、窓が 0.5 秒かけて消え、位置が替わり、0.5 秒かけて現れる。字は、現れている途中から出る。最後の `\![play,next,…]` で止まっている間も、現れる変化は進む。吹き出しを押して早送りすると、変化は、その場で終わりの値（不透明）になる。
- 使い手は 3 つ: 正典の時間つきの窓の指令（`window-timed-directives`）・舞台の転換（舞台の単位）・変化の形（`--easing`。`element-animation-easing`）。3 つは、同じ dola の口を使う。areka の中に、同じ仕組みを別に作らない。

## 5. 設計

### 5.1 結論（先に）

1. **dola に、口を 4 つ足す**（始める・印で選んで終わりの値にする・止める・値を読む）。本体の計算は、もう在る。
2. **wintf は、その口を `DolaAnimator` から呼べるようにし、刻む所を「毎フレームの相の中から呼べる関数」にする。**
3. **areka は、呼ぶだけである。** 台本の命令を読む → 線で送る → 相の中で「口を呼ぶ → 刻む → 値を書く」を 1 フレームの中で行う。
4. **時刻**: 区間の始まりは「口を呼んだフレームの時刻」、終わりは「合図の絶対の発火時刻＋長さ」。値は飛ばず、終わりの時刻は正確である。
5. **早送り**: 変化は、始めた流れの印を持つ。早送りは、主の流れの印の変化だけを、終わりの値にする。

### 5.2 持ち物の線

| 層 | 持つ物 | 置き場 | 作る単位 |
| -- | ------ | ------ | -------- |
| **dola** | 始める口・終わりの値にする口・止める口・値を読む口。始めた流れの印を、インスタンスに持つ | `crates/dola/src/runtime/facade.rs`・`instance_manager/mod.rs` | この単位（dola の側） |
| **dola** | 変化の形（CSS の型 3 つ・式・文字列の読み手・`apply_easing` の公開） | `crates/dola/src/easing.rs`・`runtime/interpolator/` | この単位（形） |
| **wintf** | `DolaAnimator` の書き換えの口（dola の 4 つへ渡すだけ）・全部を刻む関数・起床の旗 | `crates/wintf/src/ecs/dola/mod.rs` | この単位（dola の側と一緒） |
| areka（呼ぶだけ） | 正典のタグの引数の読み・台本の時刻の表に長さを書く・線・相・値を窓へ書く係・ゴーストの終わりまで残す値 | `crates/areka-runtime/`・`crates/areka-sakura/src/compile.rs`・`crates/areka-placement/`・`crates/areka-emo-present/` | `window-timed-directives` |
| areka（呼ぶだけ） | `--easing` を読んで、形の欄へ渡す | `crates/areka-runtime/` の引数の読み | `element-animation-easing` の段 2 |
| areka（呼ぶだけ） | アクターの値を `Visual`・`Arrangement` へ書く係・転換の組・前の絵を残して溶かす | 舞台の窓の側 | 舞台の単位 |

- dola は、窓も、スコープも、流れも、タグの名前も知らない。受けるのは、変数の名前・数・時刻・形・意味を見ない印の数だけである。
- areka の側に、補間の式・経過時間の計算・「今どこまで進んだか」の状態を書かない（R1）。

### 5.3 dola に足す口

時刻と長さは、`dola-interrupt-ticks` が入れる型で書く（今は `f64` の秒）。

**口 A: 始める（仮 `start_change`）。**

```
start_change {
  targets:   [(変数の名前, 出発点: Option<数>, 終わりの値: 数)],   // 1 つ以上。同じ組で一緒に動く
  begin:     時刻,                 // 区間の始まり＝口を呼んだフレームの時刻
  end:       時刻,                 // 区間の終わり＝合図の絶対の発火時刻＋長さ
  easing:    Option<EasingFunction>,   // None は等速
  range:     Option<(下限, 上限)>,     // 透明度なら 0〜100
  started_by: u64,                 // 始めた流れの印。dola は意味を見ない
} -> Result<StartResult, RuntimeError>
```

- 誰が・何のために: areka の相が、台本の時間つきの指令 1 つにつき 1 回呼ぶ。文書を組み直さずに、実行時の値から始めるためである。
- 中身: 1 変数 1 区間の `CompiledStoryboard` を手で組み、`start_internal` の後ろ半分（`facade.rs:113-186`）へ渡す。`start_internal` を、「文書から引いてコンパイルする」前半と、後ろ半分に割る。
- 方針は `Cancel` に固定する（既定の `Conclude` のままだと、次の変化に割り込まれた時に、終わりの値へ飛んでしまう）。
- **出発点の決まり**: ⑴ 呼び手が値を渡したら、それを使う。⑵ 渡さなければ、割り込みの始末（`conflict_resolver.rs:73-74`）が済んだ後の `last_values` を使う。これは、走っていた変化が在れば「それを `begin` で評価した値」、無ければ「最後に出した値」である。⑶ どちらも無ければ、誤りを返す（R18 で、呼び手が終わりの値を置く）。
- `end` が `begin` 以下なら、長さ 0 の区間になり、同じ `tick` で終わりの値が出る。**時間なしの指令（すぐ替える）も、この口を長さ 0 で通す。** 値をじかに窓へ書くと、dola の覚えている値が古くなるからである（検証の N1）。
- 1 回の呼び出しに変数をいくつか入れられる（位置の x と y・倍率の横と縦）。同じ組になり、一緒に始まり、一緒に終わる。
- 同じ終わりの値でも、言われたとおりに始める（R12）。

**口 B: 印で選んで、終わりの値にする（仮 `conclude_started_by(印)`）。** 生きているインスタンスのうち、印が合う物の全部に、今の `conclude_internal`（`facade.rs:519`）を回す。終わらせた数を返す。使うのは、早送りである（5.7）。

**口 C: 止める（仮 `stop_changes(変数の名前)`）。** その変数に走っている変化を、その時の値で止める。中身は今の `cancel`（`facade.rs:240`）で、呼び手が `group_id` を覚えなくて済むように、変数の名前で引く。使うのは `\![moveasync,cancel]` と、位置をじかに書く命令（5.5）である。

**口 D: 値を読む（仮 `value_of(変数の ID) -> Option<数>`）。** `last_values` を返す。使うのは、「途中の値を見たい」呼び手である（`currentghost.scope(ID).scaling` を途中で読んだ時など。値が要る時に読む＝プル）。

**インスタンスに足す欄**: `started_by: Option<u64>`（文書から始めた物は `None`。口 B は `None` を選ばない）。

### 5.4 wintf に足す結線

1. **書き換えの口**: `DolaAnimator` に、dola の 4 つの口と `subscribe` へ渡すだけの関数を足す。どれも `&mut self` で受ける（今の `unsafe impl Send/Sync` の根拠＝中身に触る口は全部 `&mut self`、を崩さない。`mod.rs:86-96`）。
2. **起床の旗**: 口 A・B・C を呼んだ時に、`ANIM` を立てる。何も走っていない所へ始めた時に、最初のフレームが確かに来るようにする（検証の X1 の 5）。
3. **刻む関数**: 今の `tick_dola_animators` の中身（刻む・トリガの失敗の記録・旗）を、`&mut World` を受ける関数へ出す。係は、その関数を呼ぶだけにする。areka の相は、口を呼んだ後に、この関数を呼ぶ。
4. **注釈を直す**: 「Update スケジュール先頭に配置」（`mod.rs:166-167`）を、「口を呼ぶ所より後・値を書く所より前に呼ぶ」に替える。先頭に置くと、同じフレームで始めた変化が、次のフレームまで出ない。
- 同じ時刻で 2 度刻んでも、値は変わらない（2 度目は、時刻までの出来事が残っておらず、差分が空になる。`facade.rs:326-358` の形からの見立て。書いて確かめてはいない）。相の中で、値ごとに置き場が分かれても困らない。

### 5.5 areka の側（呼ぶだけ。中身は `window-timed-directives` の設計で決める）

1. **受け口**: `\![move]` の時間・`\![moveasync]`・`\![moveasync,cancel]`・`\![set,alpha]`・`\![set,scaling]` を、名前で拾う。`Custom{command, params}` のまま受け、命令ごとの型は増やさない。引数を読み、「どのスコープの・どの値を・どこへ・長さ・合図の絶対の発火時刻・始めた流れの印」を、線で UI スレッドへ送る。
2. **線**: `\![move]` は、今の線（`move_tx`）に乗せる（窓の組を作る命令と同じ線で、台本の順が保たれる。`move_cue.rs:260`）。透明度と倍率を同じ線に乗せるか、別の線にするかは、値を書く置き場で決まる（下の 5）。どちらでも、5.7 の順は崩れない。
3. **相**: `frame_system` の中で、「線を読む → 口 A・B・C → 刻む関数 → 値を書く」を、この順に、同じフレームで行う。
4. **`DolaAnimator` の置き場**: スコープの窓のエンティティに 1 つ。変数は `x`・`y`・`alpha`・`scale_x`・`scale_y`。舞台のアクターは、アクターのエンティティに 1 つ（舞台の単位）。
5. **値を書く係**（置き場の見立て。コードは読み切っていない）:
   - 透明度: `Visual.opacity` へ。
   - 位置: placement の今の書き方へ（組にした窓が一緒に動く道）。再スナップの後に置く（`frame.rs:322-326`）。
   - 倍率: アプリの倍率の席へ。倍率は窓の大きさを変えるので、窓寸の照合（`reconcile_reported_sizes`。`frame.rs:296`）より前に書く必要が在る見込み。
6. **位置の出発点は、呼び手が渡す**（5.3 の出発点の ⑴）。窓の位置は placement の持ち物で、ドラッグ・吸い付き・組の移動で、dola の外で変わる。始める時に、placement から今の位置を読んで渡す（値が要る時に読む＝プル）。透明度と倍率は、dola の外で変わらないので、渡さない（⑵）。
7. **位置をじかに書く台本の命令**（時間なしの `\![move]`・`\![execute,resetwindowpos]`）は、その窓の位置に走っている変化を、口 C で止めてから書く。止めないと、次のフレームに、走っている変化が上から書き戻す。
8. **待つ形**（`\![move]` の時間・`--wait`）は、台本を読んだ時に長さが分かるので、台本の時刻の表を、そのぶん進める（`crates/areka-sakura/src/compile.rs` の走査。今は、字と待ちだけが進める）。待たない形は、進めない。

### 5.6 時刻

- **時計は 2 つの役で、物差しは 1 本。**
  - 終わりの時刻を決めるのは、台本の時計である（合図の絶対の発火時刻＋長さ）。
  - 値を読むのは、フレームの時計である（`FrameTime`）。フレームごとに、「その時刻の値」を dola から読む。変わっている間は毎フレーム動く値なので、読む側が取りに行く（プル）。始まり・終わり・止めるは、時点が分かるので、命令で渡す（プッシュ）。
  - 2 つが同じ物差しになるのは、v0.2.0 の時刻の土台の後である（5.12）。
- **区間の決まり**: 始まり＝口を呼んだフレームの時刻。終わり＝発火時刻＋長さ。出発点＝始まりの時刻の値（5.3）。
  - 合図は 50 ms の格子で配られるので、発火時刻から口を呼ぶまでに、0〜50 ms（フレームの待ちを足すと、もう少し）の遅れが在る。
  - 発火時刻を始まりにすると、最初のフレームで、遅れたぶんの値が一度に動く。走っている変化へ逆向きに割り込む時は、画面の値が、一度戻ってから進む（検証の X3）。
  - この設計では、遅れたぶん、区間が短くなる（500 ms の変化が、450〜500 ms で走る）。値は飛ばない。終わりの時刻は、台本の時刻の表と合う。
  - 遅れが長さ以上なら、すぐ終わりの値になる。
- **クリック待ちの間も進む**: 変化は、窓のエンティティの `DolaRuntime` の中に在り、フレームの時計で刻む。台本の再生機が止まっていても、台本が終わっても、関わらない。走っている間は、刻む関数が `ANIM` を立て続けて、フレームを起こす。走り終わると、旗は止まる（R14）。
- **1 フレーム遅らせない**: 口を呼ぶ・刻む・値を書くは、同じ相の中で順に行う。`frame_system` は `Update` に載っているので、書いた値は、同じ巡の描画が拾う。口 B の終わりの値も、すぐ後ろの刻みで出る。
- **決定論**: 口に渡す `begin`・`end` と、刻む時刻は、どれも呼び手が渡す。テストは、時刻を外から渡して値を検査する（R15）。

### 5.7 始めた流れの印と、早送り

- **印を入れるのは、受け口である。** 受け口は、作られる時に、「主の流れの物か、並走の流れの物か」を 1 つ受け取り、送る物に付ける。受け口が、台本の中身から見分ける事はしない（流れを分けるのは、台本の並走の印で、並走の単位の仕事）。
- 印は、2 つの値で足りる（主の流れ＝0・並走の流れ＝1）。dola は、意味を見ない数として受ける。
- **早送りの流れ**:

| 段 | 起きること |
| -- | ---------- |
| 1 | 再生の制御の単位が、主の流れを早送りする（吹き出しのクリック・早送りの命令・高速再生が「入」・出し直しの印） |
| 2 | 再生の制御の単位が、主の流れの受け口の全部へ、「早送りした」を配る。配るのは、早送りで先に出した合図を全部 `emit` した**後**である |
| 3 | この単位の受け口が、自分の線へ、「主の流れの印の変化を、終わりの値に」を流す |
| 4 | UI スレッドの相が、線を順に読む。始める（口 A）が先、終わりの値にする（口 B）が後になる |
| 5 | 同じ相の刻みで、終わりの値が出る。同じフレームで窓に書く |

- 始める合図と、終わりへ飛ばす合図は、同じスレッドから、同じ線に、順に入る。だから、早送りで配られた変化が、飛ばずに走り出す事は無い（検証の X4 の 1）。線が 2 本在る時は、線ごとに 1 つずつ流す（線の中の順が保たれれば足りる）。
- 高速再生が「入」の間は、主の流れの 1 本ごとに段 2 が起きるので、主の流れが始めた変化は、どれも、始めたフレームで終わりの値になる。
- 並走の流れの受け口には、「早送りした」は配られない。並走の流れが始めた変化は、口 B に選ばれず、そのまま進む（R10）。
- 早送りは、中身を見ない。口 B は、印だけで選ぶ。値の種類（位置・透明度）で分けない。

### 5.8 同じ値へ、2 つの流れが変化を始めた時

- 例: 主の流れが `\0\![set,alpha,0,--time=1000]` を始め、0.3 秒後に、並走の流れが `\0\![set,alpha,100,--time=500]` を始めた。
- 起きること: 後から始めた変化が、その時の途中の値（70 のあたり）から、100 へ向かう。前の変化は、そこで終わる。areka は、どちらの流れの物かを見ない（dola の割り込みは、変数だけを見る。`conflict_resolver.rs:134-154`）。
- その後に早送りが来ても、主の流れが始めた変化は、もう無い。並走の流れが始めた変化は、そのまま 100 へ進む。逆の順（並走が先・主が後）なら、主の流れの変化が残っていて、早送りで終わりの値（0）になる。
- どちらも、「届いた順に、そのまま当てる」の帰結である。避けるのは、台本を書く側である（骨組みの 2 章）。

### 5.9 台本の例から、窓が動くまで（舞台を開かない演劇）

2 章の例の、最初の `\0\![set,alpha,0,--time=500]` を追う。

| 段 | 所 | 起きること |
| -- | -- | ---------- |
| 1 | pasta | 舞台を開いていないので、透明度を正典のタグで出す（骨子 8 章の議題 5）。並走の印は無い＝主の流れ |
| 2 | `areka-sakura` の `compile.rs` | `Custom{command:"set", params:["alpha","0","--time=500"]}` を、時刻 0・長さ 0 で時刻の表に置く（`--wait` が無いので、表を進めない） |
| 3 | 再生機 | 起点を本物の絶対時刻 T0 で押す（v0.2.0 の後）。台詞の刻みで、合図を全部の受け口へ配る。合図は、絶対の発火時刻 T0 を運ぶ |
| 4 | この単位の受け口（主の流れの物） | 名前 `set`・第 1 引数 `alpha` を拾う。引数を読み、`{スコープ 0, 透明度, 終わり 0, 長さ 500 ms, 発火 T0, 印＝主}` を線へ送る。起床の旗を立てる |
| 5 | UI スレッドの相（フレームの時刻 Tn） | 線を読む。スコープ 0 の窓の `DolaAnimator` に、口 A: `targets=[("alpha", None, 0)]`・`begin=Tn`・`end=T0+500ms`・等速・`range=(0,100)`・印 0 |
| 6 | dola | 走っている変化は無いので、出発点は、最後に出した値（100）。1 区間のインスタンスを作る |
| 7 | 同じ相 | 刻む（Tn）。値は 100 のまま。走っている物が在るので、`ANIM` が立つ |
| 8 | 次のフレームから | 刻むたびに、その時刻の値が出る。書く係が `Visual.opacity` へ書く。T0+500 ms を過ぎたフレームで 0 になり、インスタンスが消える。次のフレームで、旗が止まる |

- 続く `\_w[500]` が表を 500 ms 進め、T0+500 ms に `\![move,…]`（時間なし）と `\![set,alpha,100,--time=500]` が配られる。`\![move]` は、今の道（すぐ置く）で動く。位置に走っている変化は無いので、口 C は何も止めない。透明度は、出発点が 0（最後に出した値）で、T0+1000 ms に 100 になる。
- `\![move,--X=400,--time=300]`（待つ形）の時は、段 2 で表が 300 ms 進み、段 5 で、placement から読んだ今の位置を出発点に渡し、移動先の計算（今の `compute_move_target`）の結果を終わりの値にして、`x` と `y` を 1 回の口 A で始める。
- `\![set,scaling,150,--time=400]` は、`scale_x`・`scale_y` を 1 回の口 A で始める。書く先は、アプリの倍率の席である。
- 最後の `\![play,next,OnPlayNext]` で主の流れが止まっても、段 8 は続く。吹き出しを押すと、5.7 の段 1〜5 で、透明度が同じフレームで 100 になる。

### 5.10 状態の持ち方（その状態を入れる台本の命令）

| 状態 | 持ち場 | 入れる台本の命令 | 消える時 |
| ---- | ------ | ---------------- | -------- |
| 走っている変化（出発点・終わりの値・始まりと終わりの時刻・形・始めた流れの印） | 窓のエンティティの `DolaAnimator` の中 | `\![move]` の時間・`\![moveasync]`・`\![set,alpha]`・`\![set,scaling]`（舞台の中は、舞台の単位の命令） | 終わりの時刻・口 B・口 C・同じ値への次の命令・窓が消える時 |
| スコープの今の透明度・倍率 | dola の覚えている値（`last_values`）と、窓の単位の表（正典の「ゴースト終了まで有効」を持つ） | `\![set,alpha]`・`\![set,scaling]` | ゴーストの切り替え・終了 |
| 受け口の「どの流れの物か」 | 受け口の欄 | 台本の並走の印（並走の単位が、受け口を作る時に渡す） | その流れが終わる時 |

- この単位は、モードを持たない。「今は早送り中」「今は演劇中」を、この単位の中に覚えない。

### 5.11 失敗の扱い

- 口 A が誤りを返した（出発点が決まらない・dola の `RuntimeError`）: 出発点に終わりの値を渡して、長さ 0 で呼び直す（終わりの値がすぐ出る）。`error!` を 1 行（スコープ・命令・誤り）。
- 引数が読めない・長さが負: 正典の決まりで置き換える（`--time` は、省略と負を 0 に読む。brief の 25 行）。置き換えたら `warn!` を 1 行。トークは止めない。メッセージボックスは出さない。
- 窓のエンティティが無い（まだ生えていない・もう消えた）: `\![move]` の今の決まり（最初の面が出るまで預かる。`frame.rs:315-319`）に合わせる。預かった間に過ぎた時間は、区間が短くなるだけで、終わりの時刻は動かない。
- 終わりの時刻が、始まりより前（遅れが長さを超えた）: 誤りにしない。すぐ終わりの値になる。

### 5.12 dola の直し（v0.2.0）との境と順番（案）

| 単位 | 持ち分 | この単位との境 |
| ---- | ------ | -------------- |
| `dola-interrupt-ticks` | 時刻の型と時計を替える。振る舞いは変えない。cue の層と storyboard の層の両方 | 口は足さない。**storyboard の層を、後ろへ切らないでほしい**（同 brief の 80 行「20 を超えるなら…切る」。切ると、`FrameTime`〔新しい型〕と `DolaRuntime`〔`f64` の秒〕の物差しが割れたまま、この単位の着手になる） |
| `talk-anchor-interrupt-ticks` | 台本の起点を、本物の絶対時刻で押す。受け口は、押された起点を読む | 受け口が「合図の絶対の発火時刻」を得る事を、ここから受ける。刻みの周期（50 ms）は変えないので、5.6 の遅れは残る |
| **この単位（dola の側）** | 口 A〜D・印の欄・wintf の結線 | 上の 2 本の後。新しい時刻の型で、最初から書く |

- **案: この単位の dola の側（口 A〜D と wintf の結線）を、別の単位として、v0.2.0 の時刻の土台 2 本の直後に置く。版は、v0.2.0 の末尾に入れる。**
  - `dola-interrupt-ticks` の中には入れない。同 spec は「型を替えるだけで、振る舞いは変えない」spec で、規模も L（14〜20）である。口を足すと、性格が混ざり、あふれる。
  - v0.2.0 に入れる理由: dola は crates.io に公開している。時刻の型が替わるのと同じ版上げで口も出せば、`f64` の秒の口を、1 度も公開しないで済む。使い手（窓の指令・舞台）は v0.4.0 より後なので、前に在ればよい。`play` には関わらないので、「play 関係は 0.3.0 以降」には当たらない。
  - v0.2.0 に入れられない時は、v0.2.0 の直後（v0.3.0 のフェードと同じ時期）に置く。使い手より前である限り、困らない。
- **作る順**: `dola-interrupt-ticks` → `talk-anchor-interrupt-ticks` → この単位の dola の側 → `window-timed-directives`（areka の側。再生の制御の単位と同じファイル〔`compile.rs`・再生機〕を触るので、順に）→ `--easing`（段 2）→ 舞台の転換。
- 変化の形（dola の `easing` の CSS の型と読み手）は、時刻の型に関わらない（進み具合 0〜1 の純粋な関数）。`dola-interrupt-ticks` と同じ時に走らせなければ、いつ作ってもよい。`--easing` より前に要る。

## 7. 立場の確かめ

areka が、判断・状態・既定の動作の変更を持つ所。

| 所 | 種類 | 起こす台本の命令 |
| -- | ---- | ---------------- |
| 走っている変化 | 状態 | 正典の時間つきの指令（5.10） |
| スコープの今の透明度・倍率 | 状態 | `\![set,alpha]`・`\![set,scaling]`（正典「ゴースト終了まで有効」） |
| 受け口の流れの印 | 状態 | 台本の並走の印 |
| 主の流れの変化を、早送りで終わりの値にする | 動作 | 吹き出しのクリック（正典の早送り）・早送りの命令・高速再生の入・出し直しの印。**正典の `\![move]` の時間などにも当てるかは、SSP を測ってから決める**（11 章の問 2） |
| `--easing` の引数 | 正典のタグへの、areka だけの引数 | 作者が書いた時だけ。書かなければ等速。11 章の問 4 |

## 11. 置いた仮定と、決まっていない所

### 置いた仮定

- A1: 口を呼ぶのは、`frame_system` の相の中だけである。
- A2: 流れの印は、主の流れと並走の流れの 2 つの値で足りる。
- A3: 出し直しの印や、舞台を閉じる命令で並走の流れが止まった時、その流れが始めた変化は止めない（始めた変化は、流れと別に、終わりまで走る）。舞台の中は、舞台の単位が値を既定へ戻すので、そこで終わる。
- A4: 既定の形は等速（正典は形を書いていない。SSP の形は測っていない）。
- A5: `DolaAnimator` は、窓のエンティティごとに 1 つ。窓のエンティティは、シェルの差し替えをまたいで残る（読んでいない。残らないなら、窓の単位の表から値を入れ直す）。
- A6: 1 回の口 A に入れた変数（x と y）は、後から片方だけへ割り込まれると、組ごと止まる（割り込みは組の単位。`conflict_resolver.rs:54-98`）。正典の `\![move]` は、いつも両方を書くので、困らない。
- A7: v0.2.0 の後、`FrameTime` と台本の起点は同じ物差しで、受け口は合図の絶対の発火時刻を得る。

### 決まっていない所（開発者に諮る問い）

1. **区間の始まりは、「口を呼んだフレームの時刻」でよいか。**「時刻は正確に（遅れたら、過ぎたぶんだけ進める）」を字面どおりに取ると、始まりは発火時刻になり、最初のフレームで、遅れたぶん（最大 50 ms ぶん）の値が一度に動く。→ 答えで、口 A の引数の意味（`begin`）と、出発点の決まりが変わる。終わりの時刻は、どちらでも正確である。
2. **正典の時間つきの指令（`\![move]` の時間など）は、吹き出しのクリックの早送りで、終わりの値へ飛ぶか。** ukadoc は書いていない。SSP を測ってから決める。→ 飛ばないなら、印の値を 1 つ足す（主の流れの正典の物）。口の形は変わらない。
3. **正典の `--time` の変化の形は、等速でよいか。** SSP が等速でないなら、「SSP と同じ見た目」（`window-timed-directives` の Desired Outcome）と割れる。→ 既定の形が変わる。形の単位が、窓の指令の前提になる。
4. **`--easing` を、正典のタグの引数として足してよいか。** 骨組みの 1 章の 4（正典のタグに、areka だけの意味を足さない）に当たるかどうか。書かなければ動きは変わらないが、正典のタグに areka だけの引数が付く。→ 当たるなら、形を選ぶ書き方を、areka の命令にする（窓の指令の前に置く命令など）。
5. **dola の側の単位を、v0.2.0 の末尾に入れてよいか**（5.12 の案）。→ 入れないなら、v0.2.0 の直後に置く。`dola-interrupt-ticks` が storyboard の層を後ろへ切る時は、切った残りを、この単位の前に置く。
6. **時間をかけた移動の途中に、遊ぶ人が窓をドラッグした時。** 変化を止めるか、書き戻すか。SSP を測ってから、窓の指令の要件の段で決める。→ ドラッグの始まりで口 C を呼ぶかどうかが変わる。

## 12. 骨組みを直したほうがよい所

1. **7 章に、区間の決まりを 1 行足す。**「今の値から」だけでは、合図の遅れ（50 ms の格子。`crates/areka-ghost/src/ticker.rs:56-69`）の扱いが決まらない。「始まりは、口を呼んだフレームの時刻とその時の値。終わりは、合図の絶対の発火時刻＋長さ」を足す（11 章の問 1 の答えで）。
2. **4.1 に、「基盤は、主の流れを早送りした事を、主の流れの受け口の全部へ配る」を足す。** 吹き出しのクリックの早送りと高速再生は、台本の命令ではないので、3 章の `Custom` の配りに乗らない。今の受け口の口（`crates/dola/src/cue/sink.rs:27-54` の 4 つ）に、それを知る物が無い。この単位と舞台の単位が、同じ口を要る。
3. **2 章か 3 章に、「受け口は、どの流れの物かを、作られる時に受け取る」を足す。** 合図（`crates/dola/src/cue/command.rs:290-304`）に、流れの欄が無い。印が無いと、7 章の「主の流れが始めた転換」を選べない。
4. **7 章の「主の流れが始めた転換を、終わりの絵へ飛ばす」が、正典の時間つきの指令にも当たるかを書く**（11 章の問 2）。
5. **10 章の「値を時間で変える」の行を、3 つに分ける。** dola の口と wintf の結線（dola・wintf。v0.2.0 の末尾の案）・正典の窓の指令（areka。`window-timed-directives`）・変化の形（dola と、台本の `--easing`）。crate も、版の段も、違う。
