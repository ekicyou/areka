## 2. この単位は何か

ゴーストの作者が、さくらスクリプトで音を鳴らす・止める・待つための、正典のタグの受け口である。今の areka は、音のタグを 1 つも鳴らさない。

- 例 1（ふつうのゴースト）: `\0\_v[se/door.wav]\_Vただいま。` 扉の音を鳴らし、鳴り終わってから「ただいま。」を出す。
- 例 2（演劇。pasta が出す 1 本）: `\![sound,stop,bgm/day.mp3]\![sound,loop,bgm/rain.mp3]\![sound,play,se/thunder.wav]\0雨だ。` 昼の曲を名前で止め、雨の曲を繰り返しで鳴らし、雷を 1 回鳴らす。
- 例 3（並走）: `\![parallel,1]\_v[se/thunder.wav]\_V\s[12]\![parallel,0]\0…` 雷が鳴り終わったら表情を替える。その間、主の流れは待たずに字を出す。

この単位が持つ物は、正典の音のタグ（`\_v`・`\_V`・`\8`・`\![sound,play／loop／stop／pause／resume／wait／load／option]`）・音のプロパティ・`OnSound*` のイベントである。正典でない物は 1 つだけで、出し直しの印（仮 `\![play,again]`）を自分で拾って、鳴っている途中の単発の音を止める（骨組みの 3 章の表）。曲のフェード・区分ごとの音量・声と台詞の結び付けは、この単位の外である。

areka は、音について「曲」「効果音」「声」を見分けない。見分けるのは、タグの形だけである（`loop` で始めた物が「ループ」、ほかで始めた物が「単発」）。

## 3. 暫定の要件

出どころの略: 【brief】＝`sound-canon-tags` の brief、【決め】＝2026-11-20 の決め、【骨 N】＝骨組みの N 章、【取り決め】＝pasta の `novel-areka-contract/brief.md` の最終形の節、【正典】＝ukadoc。

1. `\_v[ファイル名]`・`\![sound,play,ファイル名,オプション…]` を受けたら、その wave・mp3・wma を 1 回鳴らす。`\8[ファイル名]` も、wave を 1 回鳴らす。【brief・正典】
2. `\![sound,loop,ファイル名]` を受けたら、止められるまで繰り返して鳴らす。ループの音は、音の待ちの相手にしない。【正典「\_Vの対象にならない」】
3. `\![sound,stop,ファイル名]` を受けたら、その名前の音を止めて手放す。名前が無ければ、そのゴーストの音を全部止める。`pause`・`resume` も、名前（無ければ全部）に効く。【正典・取り決め「止めるときは名前を付ける」】
4. `\![sound,load,…]` で先読みし、`\![sound,option,…]` で鳴っている音のオプションを変える。オプションは `--volume`・`--balance`・`--rate`・`--seektime` を持つ。【brief・正典】
5. ループの音を 2 本以上、単発の音を何本でも、同時に重ねて鳴らせる。【取り決め「曲・環境の音・効果音・声」】
6. `\_V`・`\![sound,wait]` に着いた流れは、その時に鳴っている単発の音が全部終わるまで、そこで待つ。鳴っていなければ、待たない（後ろの合図の時刻は、1ms もずれない）。待った時は、後ろの合図が、待った長さだけ後ろへずれる。【正典「既に終了しているか存在しない場合は無視」・brief「時刻は正確に」】
7. 音の待ちは、主の流れにも、並走の流れにも書ける。待つのは、着いた流れだけである。【骨 2「並走の流れに書ける物は、バルーンに触らない物の全部」】
8. 早送り（吹き出しのクリック・早送りの命令）・高速再生が「入」・出し直しの 1 本では、主の流れは音の待ちで待たずに先へ進む。音は鳴り続ける。`\_q` だけでは、待つ。【決め「早送りは早送り。再生内容に依存せず即時に次に移るべき」・骨 4.1・4.2】
9. 早送りの間も、高速再生が「入」の間も、音の命令は、書いた順に全部当てる。飛び越えた単発を鳴らさない、という扱いは作らない。【決め「そのほか」・骨 4.1】
10. 音の状態は、トーク（1 本の再生）にも、流れにも結び付けない。1 本が終わっても、置き換わっても、並走の流れが止まっても、鳴っている音は続く。【骨 2・骨子 2.4「前の音が続く」】
11. 音の受け口は、出し直しの印（仮 `\![play,again]`）を自分で拾い、そのゴーストの、鳴っている途中の単発の音を止める。ループは止めない。【骨 3 の表・決め「同じ命令を複数の受け口が拾う」】
12. 舞台を閉じる命令では、音は何もしない。止めるのは、台本の `\![sound,stop,名前]` である。【取り決め「舞台の窓と箱」の閉じる時の文に音が無い・骨 1 の 3】
13. ゴーストを降ろす時（切り替え・ゴーストの読み直し・areka の終了）、そのゴーストが開いた音を全部閉じる。【正典「現在のゴーストが管理しているメディア」からの読み。SSP を測る事（12 章）】
14. `currentghost.sound.count`・`currentghost.sound(要素名).…`・`currentghost.sound.index(ID).…` が、本物の値を返す。`playing`・`pause`・`position` は SET で効く。【brief・正典】
15. 音が終わった・ループの頭へ戻った・鳴らせなかった時、`OnSoundStop`・`OnSoundLoop`・`OnSoundError` を送る。【正典。brief の Scope には無い（13 章の切り方）】
16. ファイルが無い・形式が読めない・音の装置が無い時、areka は落ちず、`warn!` を 1 行残して先へ進む。メッセージボックスは出さない。音の待ちは、待たない。【brief】
17. 読み込み・デコード・再生は、UI スレッドの外で行う。台本のスレッドも、プロパティに答えるスレッドも、止めない。【brief・前の検証 ⑷】
18. 相対パスは、台本を実行したゴーストの `ghost/master` から解く（`talk-script-metadata` の関数）。要素名は、台本に書いた字のまま覚える。【brief・正典「指定したファイル名/パス/URLそのもの」】
19. 音楽 CD（`cdplay`）・動画（`--window`・`--sound-only`）・`--spectrum*`・`--eq*` は作らない。受けたら `warn!` を 1 行残して、その部分だけ読み捨てる。【brief Scope Out】
20. 待ち・止め・一時停止・ファイルが無い時・ゴーストを降ろす時・早送りで待ちを通る時を、偽の再生の土台と注入した時刻で、決定論のテストで固定する。【brief】

前の設計の要件 13（飛び越えた単発を鳴らさない）と 18（音量を時間で変える仕組みを音の中に持つ）は、外した（8 章）。

## 5. 設計

### 5.1 構成

```
台本のスレッド（主の流れ・並走の流れごと）            音のスレッド（1 本・areka が生きている間）
  音の受け口 SoundCueSink ──SoundMsg──────────▶ 音の表 SoundTable（状態の正・1 つ）
   名前 "sound" と、"play" の "again" を拾う            │  開く・読むは、読みのスレッドへ頼む（輪を止めない）
  ◀── 待ちの解け（dispatcher が、流れの番号で回す）──    └ 再生の土台 SoundBackend（trait）
ghost のスレッド: プロパティの GET／SET ─────────▶         本番: Media Foundation で読む＋XAudio2 で混ぜる
ゴーストを起こす所・降ろす所: 付ける／閉じる ─────▶         テスト: 偽の土台（時刻を注入）
```

| 置き場 | 足す物 |
| ------ | ------ |
| 新しい crate `areka-sound` | 命令の読み（入れ物の字の列 → `SoundCommand`）・音の表・再生の土台の trait・音のスレッド（`areka-actor` の `spawn_actor`）・本番の土台（OS の API を呼ぶ所は、この中の 1 つのモジュールに閉じる） |
| `areka-parsers` の `sakura/decode.rs` | `\_v[f]` → `GenericCommand{"sound", ["play", f]}`・`\_V` → `GenericCommand{"sound", ["wait"]}`・`\8[f]` → `GenericCommand{"sound", ["play", f]}`（正典の「同じ機能」どおりに畳む） |
| `areka-sakura` の `compile.rs` | `sound,wait` を読んだら、入れ物の合図の直後に「外の出来事で解ける区切り」を置く（`set,choicetimeout` を名前で読む前例と同じ所） |
| `areka-runtime` | `sound_cue.rs` の音の受け口・受け口の表の行 |
| `areka` の `session` | 音のスレッドを、areka の起動で 1 度だけ起こして World に置く・`wire_runtime` が送り手の複製を `CueSinkSources` に 1 欄足す・`take_down` の直後に「閉じる」を送る |
| プロパティ（`areka-sylphya`・`areka-ghost`） | 問い合わせの時に、音のスレッドへ聞く口。SET の 3 葉を `SoundMsg` に直す |
| `areka-kanade` の `schedule/events.rs` | 許可の表に `OnSoundStop`・`OnSoundLoop`・`OnSoundError` |

区切りの種類・解く口・待ちに入った知らせ・解けの伝言を回す道（dola・`drive.rs`・`dispatcher.rs`）は、**再生の制御の単位の基盤が持つ**（9 章）。音は、それを使うだけにする。

### 5.2 主な型

- `SoundCommand`（受け口の中だけの型。入れ物は `Custom{command:"sound", params}` のまま）: `Play{name, opts}`・`Loop{name}`・`Stop{name?}`・`Pause{name?}`・`Resume{name?}`・`Load{name, opts}`・`Option{name, opts}`。`wait` は、受け口は読まない（5.4）。読めない形は `Err` で、受け口が `warn!` を 1 行残す。
- `SoundMsg`（音のスレッドへの伝言）: `Command{owner, base_dir, cmd}`・`WaitRequested{owner, flow, token}`・`FlowEnded{flow}`・`StopOneShots{owner}`・`Attach{owner, events}`（ゴーストを起こした時。イベントの送り先を渡す）・`Close{owner}`（降ろした時）・`Query{…, reply}`・`Set{…}`・土台と読みのスレッドからの `Opened{id, duration}`／`Ended{id, at}`／`Looped{id}`／`Failed{id, why}`。
- 音の表の要素: `id`（開いた順の通し番号）・`owner`（開いたゴースト）・`name`（台本に書いた字のまま）・`path`（解いた後）・`looping`・`preload`・`state`（開いている途中／読み込み済み／再生中／一時停止）・`volume`・`balance`・`rate`・`duration`・`error`。並びは新しい順（`index(ID)` の順）。
- 要素が表から消える時: `stop`・単発の終わり・`StopOneShots`・`Close{owner}`。`load` だけした物は残る（`count` の「まだ閉じられていないものすべて」）。

### 5.3 鳴らす（例 2 を、段を追って）

台本: `\![sound,stop,bgm/day.mp3]\![sound,loop,bgm/rain.mp3]\![sound,play,se/thunder.wav]\0雨だ。`

1. 読み手が 3 つの `GenericCommand` にし、compile が、時刻 0 の入れ物の合図 3 つにする（今の道のまま）。
2. 再生機が、時刻 0 で、3 つの合図を全部の受け口へ配る。音の受け口は、名前 `sound` の物を `SoundCommand` に読み、`begin_talk` で受けた「実行したゴースト」と `ghost/master` を添えて、音のスレッドへ送る。返事は待たない。
3. 音のスレッドは、届いた順に当てる。`Stop{bgm/day.mp3}`: 名前の合う要素を全部止めて消す。`Loop{bgm/rain.mp3}`: 要素を作り、読みのスレッドへ「開く」を頼む。`Play{se/thunder.wav}`: 同じ。
4. 読みのスレッドが開き終えると `Opened` が届き、土台が鳴らし始める。開く途中に届いた `option`・`pause`・`stop` は、要素の値として覚え、開き終えた時に当てる（`stop` なら鳴らさずに消す）。
5. 雷が終わると、土台の知らせで `Ended{id, at}` が届く。要素を消し、`OnSoundStop`（Reference0＝`se/thunder.wav`・Reference1＝`end`）を頼む。

- **同じ名前をもう一度**: 単発は、新しい要素を足して重ねる。ループは、鳴っている同じ名前のループを止めて、頭から鳴らし直す（仮定 A2）。
- **名前を指す命令が当たる相手**: `stop`・`pause`・`resume` は、その名前の要素の全部。`option` と SET は、名前の合う最も新しい 1 つ（正典「書き込みは要素名が一致する最も新しいメディアに対して行われる」・`list_propertysystem.html#sound.pause.note`）。`stop` の方は仮定 A3。
- **早送り・高速再生**: 音の受け口は、何も見ない。届いた合図を、届いた順に全部送る（要件 9）。早送りで 3 つの効果音の合図が同じ時刻に配られたら、3 つが同時に鳴り始める。

### 5.4 待つ（例 1 を、段を追って）

台本: `\0\_v[se/door.wav]\_Vただいま。`

1. 読み手が `\_V` を `GenericCommand{"sound", ["wait"]}` にする。compile は、入れ物の合図を積んだ直後に、同じ時刻へ「外の出来事で解ける区切り（鍵 `sound`）」を置く。
2. 時刻 0: `sound,play` の合図が配られ、扉の音が鳴り始める。続けて再生機が区切りに着いて止まり、受け口へ「待ちに入った（鍵 `sound`・この待ちの番号）」を知らせる（選択肢の `choice_wait_began` と同じ足し方。基盤の口）。
3. 音の受け口は、知らせの鍵が `sound` なら、`WaitRequested{owner, flow, token}` を送る。`flow` は `begin_talk` で受けた流れの番号、`token` は知らせで受けた待ちの番号である。
4. 音のスレッドは、その時に鳴っている、そのゴーストの単発の要素（一時停止の物・ループ・`load` だけの物を除く）の組を控える。伝言は届いた順に当てるので、同じ 1 本の、手前の `play` は、必ず組に入る。
5. 組が空なら、すぐ「解け（終わった時刻＝無い）」を返す。空でなければ、組の全部が終わった時（`stop` で消えた時も終わりに数える）に、「解け（終わった時刻＝最後の 1 つが終わった時刻）」を返す。
6. dispatcher が、流れの番号で、その流れへ回す。流れは、待ちの番号が今の待ちと合う時だけ、区切りを解く。合わない解け（早送りで通り過ぎた後に届いた物）は、`debug!` を 1 行残して捨てる。
7. 解く時の時刻の扱い: 終わった時刻が「無い」か、区切りの予定の時刻より前なら、起点を動かさない。後なら、起点を「終わった時刻 − 区切りの相対の時刻」へ付け替える（`\x` を解く時と同じ引き算。基盤の口）。解けたら、次の刻みを待たずに、その場で 1 回進める。

- **待ちの番号が要る理由**: `\_v[a]\_V…\_v[b]\_V` の 1 つ目の待ちを早送りで通った後、a が終わった解けが遅れて届く。番号が無いと、2 つ目の待ち（a と b を待っている）を、a の終わりで解いてしまう。
- **受け口が `sound,wait` の合図を読まない理由**: 決めで、同じ命令を compile と受け口の 2 つが拾う形も許された。それでも、待ちの番号を再生機から受け取る形のほうが、数え手が 1 つで済むので、知らせで受ける。受け口の表の `sound,wait` の行の担当は、compile だけである。
- **流れが先に終わった時**: 受け口の複製が捨てられる時に `FlowEnded{flow}` を送り、音のスレッドは、その流れの待ちの控えを消す。
- **一時停止**: 待ちの間に、相手の音が一時停止されたら、再開して終わるか、`stop` されるまで待つ。抜ける道は、吹き出しのクリックの早送り（正典の動き）と、新しい 1 本による置き換えである。

### 5.5 早送り・高速再生・出し直しと、音の待ち

音の待ちは、**作りは「止まる所」（区切り）、扱いは「待ち」**（`\w`・`\_w` と同じ組）である。長さを台本が決めず、音が決めるだけで、遊ぶ人が押して解く物ではないからである。

| 道具（骨組みの 4.2） | 音の待ちで起きる事 | 音 |
| -------------------- | ------------------ | -- |
| `\_q`・`\![quicksection,…]` | 待つ（`\_q` は待ちを飛ばさない。正典） | 鳴る |
| 吹き出しのクリックの早送り・早送りの命令 | 待っていれば、すぐ解く。途中に在れば、待たずに通る | 鳴り続ける |
| 高速再生が「入」 | 待たずに通る | 鳴り続ける |
| 出し直しの 1 本 | 待たずに通る（頭で単発は止まっているので、ふつうは相手が居ない） | 5.6 |

- 解くのは、基盤である。音は呼ばれない。基盤が解いた後に届く、音からの解けは、待ちの番号が合わないので捨てられる。
- 並走の流れは、速く進めない（骨組みの 4.1）。並走の流れの中の音の待ちは、早送りでも、音が終わるまで待つ。

### 5.6 出し直しの印（`play` の命令が着地した後に足す）

台本: `\![play,again]\![sound,stop,bgm/day.mp3]\![sound,loop,bgm/rain.mp3]\s[3]\0雨だ。`

1. 入れ物 `Custom{"play", ["again"]}` が、全部の受け口へ同じ時刻に配られる。音の受け口は、名前 `play`・第 1 引数 `again` を自分で拾い、`StopOneShots{owner}` を送る。束ね役は居ない。
2. 音のスレッドは、そのゴーストの単発の要素（再生中・一時停止・開いている途中）を止めて消す。ループと、`load` だけの物は残す。`OnSoundStop` は、`stop` で止めた時と同じ扱いにする（仮定 A6）。
3. 続く `stop`・`loop` は、ふつうに当たる。同じ時刻の伝言は、届いた順に当たるので、`again` で止めた後に、同じ 1 本が鳴らした音は止まらない。
4. 受け口の表の `("play", Some("again"))` の行に、音の受け口を並べる。「先頭に在るか」は、音の受け口は見ない（9 章で、再生の制御の単位に求める）。

### 5.7 状態の持ち方（状態を入れる台本の命令）

| 状態 | 置き場 | 入れる命令 | 消す命令・時 |
| ---- | ------ | ---------- | ------------ |
| 音の要素（開いている音） | 音のスレッドの音の表 | `\_v`・`\8`・`\![sound,play]`・`\![sound,loop]`・`\![sound,load]`・`playing` の SET | `\![sound,stop]`・単発の終わり・`\![play,again]`（単発）・`playing` の SET・ゴーストを降ろす時 |
| 要素の値（音量・バランス・速さ・位置・一時停止） | 同上 | `play`／`load` のオプション・`\![sound,option]`・`\![sound,pause]`・`\![sound,resume]`・`pause`／`position` の SET | 要素と一緒に消える |
| 待ちの控え（どの流れが、どの音の組を待っているか） | 同上 | `\_V`・`\![sound,wait]` | 組の音が終わった時・流れが終わった時 |

- 状態の正は、音の表 1 つである。受け口・UI・ghost のスレッドは、写しを持たない。モードは無い。
- 音の終わりは「変わった時点が分かる」ので、土台の知らせ（プッシュ）で受ける。推し量った長さでは待たない。`position` は絶えず変わるので、問い合わせの時に土台へ聞く（プル）。

### 5.8 時刻

- 鳴らし始めは、合図が配られて、伝言が着いた時である。刻みが遅れても、`--seektime` で頭を詰めて追い付く事は、しない（効果音の頭が欠ける）。鳴り始めの正確さは、台本のスレッドの刻みの細かさ（dola の直し）に従う。読み込みの遅れは、正典の `\![sound,load,…]` で消せる。
- 終わった時刻は、土台の知らせを受けた時に、台本の刻みと同じ時刻源（注入できる）で押す。丸めない。
- 音の待ちを解いた時の起点の付け替えは、5.4 の 7 のとおり。鳴っていない時は、起点が動かない。
- 1 フレーム遅らせる所は、無い。

### 5.9 失敗の扱い

| 事 | 動き |
| -- | ---- |
| ファイルが無い（正典「存在しない場合は無視」） | `warn!` 1 行・要素を作らない・音の待ちの相手にならない |
| 形式が読めない・読みの途中で失敗 | `warn!` 1 行・要素を消す・`OnSoundError`・待っている流れの組から外す |
| 音の装置が無い・土台が起きない | 起動の時に `warn!` 1 行。以後の命令は、命令ごとに `debug!`。台本は進む |
| 名前の合う要素が無い `stop`／`pause`／`resume`／`option` | `debug!` 1 行（正典に文が無い。仮定） |
| 範囲の外のオプションの値 | 正典の範囲（`--rate` は土台の上限）へ収める。`warn!` 1 行 |
| 作らないオプション・`cdplay`・URL の名前 | `warn!` 1 行で、その部分だけ読み捨てる |
| 解けの送り先の流れが、もう居ない | `debug!` 1 行で捨てる |

### 5.10 再生の土台（前の設計の向きを、もう一度確かめた）

**結論: 向きは変えない（Media Foundation の Source Reader で読み、XAudio2 で混ぜる）。ただし、正式な設計の前に、先進坑で測る。**

| 形 | 書く量 | 分かっている事 | 机の上では決まらない事 |
| -- | ------ | -------------- | ---------------------- |
| A. Source Reader＋XAudio2（前の設計） | 多い | ループの継ぎ目・重ね・要素ごとの音量とバランスと速さ・終わりとループの折り返しの知らせを、土台が持つ | 知らせの口 `IXAudio2VoiceCallback` は `IUnknown` を継がない。`windows-bindgen` の束縛で実装できるか |
| B. Media Foundation の Media Engine を、要素ごとに 1 つ | 少ない（読みも混ぜも OS 任せ。知らせの口は `IUnknown` を継ぐので、先進坑で通った形） | 音量・バランス・速さ・位置・長さ・終わりの知らせは在る | ループの継ぎ目に間が空くか・鳴り始めの遅れ・何十本も重ねた時の重さ・ループの折り返しの知らせが取れるか |

- A を保つ理由: ノベルでいちばん耳に付くのは、曲のループの継ぎ目と、効果音の出だしである。A は作りとして保証され、B は測らないと分からない。
- 土台は trait（`SoundBackend`）の向こうに在り、決定論のテストは偽の土台で回す。A と B のどちらでも、音の表・受け口・待ちは変わらない。
- 前の設計から直す所: 短いファイルは全部読む・長いファイルは少しずつ読む、の 2 つの道を作らない。**どの音も、少しずつ読んで足す 1 つの道で鳴らす**（ループは、末尾で読み位置を頭へ戻して続ける。その時に `Looped` を出せる）。読む仕事は、読みのスレッドで行い、音のスレッドの輪を止めない（プロパティの問い合わせが待たされない）。
- `windows-bindgen` への移行との重なり: この単位は、`talk-script-metadata` と dola の直し（どちらも v0.2.0）の後に着地する。移行の本体も v0.2.0 の列なので、**束縛は `windows-bindgen` で書く前提にする**。移行が遅れた時は、`windows` クレートの features で書き、移行の本体と一緒に書き換える。どちらでも、OS の API を呼ぶ所は 1 つのモジュール（名前で 20 個ほど）に閉じておく。
- 先進坑で測る事（1 本・`crates/pilot`）: A の知らせの口の束縛・A と B のループの継ぎ目と鳴り始めの遅れ・16 本の重ね・arm64・既定の装置が替わった時・`--rate` の上限。B で足りると出たら、B に替える（書く量が減る）。

### 5.11 プロパティとイベント

- GET: ghost のスレッドが `Query` を送り、返事を待つ。音のスレッドは、読む仕事を持たないので、すぐ返る。`count`・`name`・`loop`・`playing`・`pause`・`preload`・`id`・`path`・`duration`・`error` は表から、`position` はその場で土台に聞いて返す。
- SET: `playing`（1＝`play`・0＝`stop`）・`pause`（1＝`pause`・0＝`resume`）・`position`（`--seektime` と同じ書式）を、`SoundMsg` に直す。`\![set,property,…]` の道は `property-query-channels` が開く。
- `meta.*` の 8 葉: **この単位では読まない。**「取得できなかった」として、正典の中の動き（「そのプロパティ自体が存在しないものとして扱われる」・`list_propertysystem.html#sound.meta.artwork.note`）で返す。タグを読む仕事（ID3 ほか・絵の取り出し）は、正典の `internal_file.MediaInfo` と同じ読み手になるので、そちらを作る時に一緒に行う（追う先の brief は、まだ無い。roadmap を `MediaInfo` で grep して 0 件）。
- イベント: 音のスレッドが、`Attach` で受けた送り先へ `KanadeMsg::RaiseEvent` を頼む。`OnSoundStop`（終わり＝`end`）・`OnSoundLoop`・`OnSoundError`。定常でない間の物は、今の口の決まりどおり `warn!` で捨てられる。`OnSoundSpectrum` は作らない。

## 7. 立場の確かめ

areka が、判断・状態・既定の動作の変更を持つ所を、全部挙げる。

| 所 | 中身 | 起こす台本の命令 |
| -- | ---- | ---------------- |
| 状態 1〜3 | 5.7 の表の 3 つ | 表のとおり |
| 「単発」と「ループ」の分け | タグの形で決まる（`loop` で開いたか）。台本の中身や状況は見ない | `\![sound,loop]` か、ほかか |
| ゴーストを降ろす時に、そのゴーストの音を閉じる | 台本の命令に依らない、ただ 1 つの「止める」である。根拠は、正典の「現在のゴーストが管理しているメディア」（表はゴーストの持ち物で、持ち主が居なくなれば、どの台本からも止められなくなる）。正典に、切り替えの時の文は無い。SSP を測る（12 章の 1） | `\![change,ghost]`・`\![reload,ghost]`・メニューの切り替え・終了 |
| オプションの値を範囲へ収める | 正典の範囲 | `--volume` ほか |

- areka が、台本の中身や状況を見分けて動きを変える所: **0**（早送り・高速再生・出し直し・舞台・並走のどれでも、音の受け口は、届いた合図を同じに扱う）。
- 新しい命令を使わない台本の動きが、今と変わる所: 音のタグが鳴るようになる事と、`\_V` が待つようになる事。どちらも正典の動きである。それ以外は 0。
- 舞台を閉じる・1 本が替わる・トークが中断される・SHIORI だけを読み直す時に、areka が音を止める所: **0**。

- 前の設計の「一時停止の単発は、終わるまで待つ」（着いた時に一時停止の物も組に入れる）は、やめた。着いた時に一時停止の物は、組に入れない（解けない待ちを、過去の一時停止が作らない）。
- 前の設計の「短いファイルは全部読んでから渡す」は、やめた（5.10）。読む仕事を音のスレッドの輪の外へ出した（前の検証 ⑷ の「返事が止まる」）。
- フェードを、正典のタグの独自のオプション（`--fade`）で出す案は、取らない（立場の 4）。出すなら `play` の命令で、値を時間で変えるのは dola である。音は、要素の音量を置く口（`option` と同じ道）を出すだけにする。
- `\![sound,stop,名前]` が、同じ名前の全部を止めるか、最も新しい 1 つかを、仮定 A3 として書いた（前の検証 ⑴ の足し）。

## 9. ほかの単位との継ぎ目

### 再生の制御（相手から受ける口。音の待ちは、これが無いと作れない）

1. dola に、**外の出来事で解ける区切り**（鍵は中身を見ない字。dola は語彙を持たない）。着いたら、受け口へ「待ちに入った（鍵・待ちの番号・区切りの時刻）」を 1 回知らせる。`\x` の待ちの知らせと、1 つの形にまとめる。
2. 解く口は、「鍵・待ちの番号・終わった時刻（無くてもよい）」を受ける。番号が今の待ちと合わなければ、何もしない。起点を付け替えるのは、終わった時刻が区切りの予定の時刻より後の時だけ。解けたら、その場で 1 回進める。
3. 基盤の「待ちを飛ばす」は、この区切りも、待たずに通る・待っていれば解く。「止まる所を通る」（高速再生）も同じ。`\_q` だけでは、通らない。
4. この区切りで待つ間の、台詞の時計と口パクの止め・合わせは、`\x` の待ちと同じに、基盤が行う。
5. 解けの伝言を、流れの番号で、主の流れへ回す道（`drive.rs`・`dispatcher.rs`）。
6. 出し直しの印が「1 本の先頭に在るか」は、台本を時刻の表に直す所で 1 度だけ確かめ、先頭でない物は、合図にせずに記録する。受け口へは、効く印だけが届く（12 章の骨組みの所の 2）。
- 同じファイル: `compile.rs`（`sound,wait` の読み）・dola の `cue/{command,schedule,runtime,sink}.rs`・`drive.rs`・`dispatcher.rs`。順番は、基盤が先、音の待ちが後。音の鳴らす部分（13 章）は、これらを触らないので、先に作れる。

### 並走

- 相手に出す口: 音の受け口を、並走の受け口の並びに入れられる形（`BootCueSink`）で作る。
- 相手から受ける口: 並走の流れにも、`begin_talk` で流れの番号と「実行したゴースト」が届く事。並走の流れにも、上の 1〜2 と同じ区切りと、解けを流れの番号で回す道が在る事（`TimedSchedule` は区切りを持っている・`schedule.rs:201-231`）。
- 順番: ゴーストを降ろす時は、並走の流れを全部止めてから、音へ「閉じる」を送る（逆だと、止まる前の流れが鳴らした音が、居ないゴーストの音として残る）。
- 並走の流れを止めても、もう鳴っている音は止めない。

### 舞台

- 舞台を閉じる命令で、音を止める仕事を、舞台の単位は持たない（取り決めの閉じる時の文に、音は無い）。
- 出し直しの印を、舞台の受け口と音の受け口が、同じ時刻に別々に拾う。順は問わない（持ち物が重ならない）。

### 値を時間で変える

- 音は、「要素の名前と音量を受けて、すぐ置く口」（`option` の `--volume` と同じ道）を持つ。曲のフェードを作る時は、dola の連続値の行き先を、この口につなぐ。この単位では、つながない。

### 目印とバックログ

- 継ぎ目は無い（声を項目に結び付ける欄は、どちらにも無い。brief の Out「バックログからの聞き直し」のまま）。

### 骨組みの 10 章に無い相手

- `talk-script-metadata`（先に着地）: `begin_talk` で、実行したゴーストと `ghost/master` が受け口に届く事。相対パスを解く関数が、`areka-runtime` から呼べる所に在る事。
- `property-catalog-lists`・`property-query-channels`: 音の葉の値を、この単位が出す事。SET の道。
- `sakura-time-directives`: 網羅台帳の `\![sound,wait]` の行の持ち主を、この単位へ付け替える。
- dola の直し（`dola-interrupt-ticks` ほか）: 台本のスレッドの刻みが細かくなる事。
- windows-rs の移行の本体: 束縛の置き方（5.10）。

## 11. 置いた仮定

- A1. 音の待ちの相手は、着いた時に鳴っている、そのゴーストの単発の全部（一時停止の物を除く。後から鳴り始めた物は待たない。ほかの流れが鳴らした物も入る）。
- A2. 同じ名前の `play` は重ねる。同じ名前の `loop` は鳴らし直す。
- A3. `stop`・`pause`・`resume` は、その名前の要素の全部に当たる。`option` と SET は、最も新しい 1 つ。
- A4. 1 本の終わり・置き換え・トークの中断・SHIORI だけの読み直し・舞台を閉じる時、音は止めない。
- A5. ゴーストを降ろす時（切り替え・ゴーストの読み直し・終了）、そのゴーストの音を全部閉じる。この時の `OnSoundStop` は、送り先が無いので送らない。
- A6. `\![play,again]` と `stop` で止めた時の `OnSoundStop` は、送らない（正典の終了理由は `end` と `close` の 2 つで、「止めた」が無い）。
- A7. `\8[ファイル名]` の基準のフォルダは `\_v` と同じ（`ghost/master`）。
- A8. `--spectrum*`・`--eq*`・`OnSoundSpectrum` は、この単位の外。
- A9. 要素名は、書いた字のまま比べる。URL の名前は鳴らさない。
- A10. 並走の流れが、区切りと「実行したゴースト」を持てる（並走の単位の設計による）。
- A11. この単位は、`windows-bindgen` への移行の本体の後に着地する（5.10）。
- A12. 今は、同時に居るゴーストは 1 体である。要素は持ち主の欄を持つが、「閉じる」は、今は全部を閉じるのと同じである。

## 12. 決まっていない所・骨組みを直したほうがよい所

### 決まっていない所（問いの形）

1. **SSP を測る事（正典に文が無い所）**: ゴーストを切り替えた時・`\![reload,ghost]`・`\![reload,shiori]` で、鳴っている音は止まるか。`\_V` は、全部の単発を待つか、最後の 1 本か。一時停止の音を待つか。吹き出しのクリックで `\_V` は切り上がるか。同じ名前をもう一度鳴らすと、重なるか。名前つきの `stop` は、同じ名前の全部を止めるか。トークの中断で音は止まるか。`stop` で止めた時に `OnSoundStop` は出るか。`\8` の基準のフォルダ。→ 答えで変わる所: 仮定 A1〜A7 の値（音の表の数行）。骨の形は変わらない。
2. **高速再生と早送りで、行ごとの声と効果音が重なって鳴る。これでよいか。** → 「よい」なら何も変わらない。「避ける」なら、pasta が各 1 本の頭に名前つきの `stop` を書く（areka は 0）。
3. **出し直しで止まる「単発」に、`play` で鳴らした曲（終わりの曲・ジングル）と、その行の声が入る。鳴り直さない。これでよいか。** → 変えるなら、取り決めの文（pasta が出し直しの 1 本に何を書くか）が変わる。areka は、タグの形のほかでは見分けない。
4. **再生の土台を、先進坑で測ってから決めてよいか**（5.10 の A と B）。→ B で足りれば、土台の仕事が 5 から 3 ほどに減る。
5. **切り方**（13 章）: 鳴らす部分を先に出し、音の待ちは再生の制御の基盤の後、値とイベントはその後、の 3 つに切ってよいか。→ 鳴らす部分を、ノベルゲーム基盤の段より前に出せるかが変わる。
6. **`meta.*` の 8 葉を後へ送り、`OnSound*` の 3 つを入れる、でよいか。** → 2〜3 タスクが出入りする。
7. **「実行したゴースト」を何で表すか**（`talk-script-metadata` が決める鍵）。→ 要素の持ち主の欄の型。

### 骨組みを直したほうがよい所

1. **4.1 の表に、音の待ちが無い。**「待ちを飛ばす」の行に、「`\_V`・`\![sound,wait]`（音が終わるまでの待ち）も、待ちに数える」と足す。根拠: 音の待ちは、長さを台本が持たないので、作りは区切りになる（区切りは、外から解くまで止まる・`crates/dola/src/cue/schedule.rs:201-204`・`223-231`）。書いておかないと、基盤が「止まる所」として扱い、早送りが音の待ちで止まる（決めの「再生内容に依存せず即時に次に移る」に反する）。
2. **3 章の「先頭でない所に在れば、効かせずに記録する」を、誰が確かめるかが無い。** 受け口は、合図を 1 つずつ受ける（`crates/dola/src/cue/sink.rs:27-32`）。5 つの受け口が、それぞれ「先頭か」を確かめると、判定が割れる。「台本を時刻の表に直す所で 1 度だけ確かめ、先頭でない印は配らない」と足す。
3. **2 章の「並走の流れに書ける物」の「待ち」に、音の待ちが入ると明記する。**「止まるのは、その流れだけ」も足す。根拠: 前の検証の問題 6（2 つの設計が逆になった所）。
4. **10 章の音の行**: 種類を「正典」から「正典＋命令（出し直しの印を拾う 1 つ）」に。中身に「プロパティ・`OnSound*`」を足す。
5. **3 章の表の持ち主に、compile が居る事**を 1 行足す。今の表は、受け口でない担当（`ScriptCompile`・`crates/areka-runtime/src/consumer_ledger.rs:365`）も行に持つ。「受け口を並べて書ける形」は、「担当（受け口と、台本を時刻の表に直す所）を並べて書ける形」が正しい。
