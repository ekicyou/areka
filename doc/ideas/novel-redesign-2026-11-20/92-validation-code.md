# ノベル（演劇）の作り直しの検証 — 芯の仕組みが、今のコードの上で成り立つか（2026-11-20）

- 観点: 芯になる仕組み 6 つを、設計の係の主張でなく、コードを自分で読んで確かめる。
- 読んだ物: 決め・骨組みの第 2 版・単位の文書 7 本（どれも全文）・時刻の土台の brief 2 本（全文）・pasta の骨子の 8 章と取り決めの brief の一部・コード（5 章に一覧）。
- 実行した物は 0（ビルド・テスト・起動・MCP の `areka`／`ssp` は使っていない）。
- 文書の呼び方: 骨組み＝`00`、再生の制御＝`01`、並走＝`02`、目印とバックログ＝`03`、音＝`04`、舞台＝`05`、素材＝`06`、値を時間で変える＝`07`。

## 1. 判定

**条件つき。**

1. 芯の 6 つに「成り立たない」は無い。予定表・再生機・dispatcher・kanade の同期の往復・dola の連続値の、今の形に素直に乗る。抜き取った事実（60 か所ほど）は、ほぼ全部合っていた。
2. ただし、時刻の土台（v0.2.0）の brief が約束していない物を 3 つ前提にしている（押し直しが配った合図に効く・トークのスレッドへの刻みが絶対の時刻・絶対の発火時刻の決め方）。brief に書く前に土台の設計が始まると、別の形で固まる。
3. 止まったままになる道（クリック待ちの間の終了・切り替え）と、決め C と割れる道（続きの 1 本の頭の待ちで、バルーンの窓が隠れる）が、どの文書にも無い。この 2 つを決めてから渡す。

## 2. 見つけた事（大事な順）

### 1. クリック待ちで止まっている間に、終了・切り替えを選ぶと、止まったままになる

- どこ: `01` の 5.6（`\x`）・5.7（続きを示すキューコマンド）。`05` の要件 17・5.10「SHIORI が答えなくても、遊ぶ人は必ず出られる」。骨組みの 5 章。
- 何: kanade は、話の最中の終了の指示を控えるだけで、`TalkDone` を待つ（`crates/areka-kanade/src/schedule/steady.rs:881-884`）。控えを消化するのは、話していない時の刻み（`:697-701`）と `TalkDone`（`:858-860`）だけである。そのうえ、控えている間は、マウスの GET を出さない（終了は `:79-87`、切り替えは `:88-95`）。
- なぜ困る: `\x` にも続きにも、時間切れが無い（続きは、引数に書いた時だけ）。メニューで「終了」を選んでも、舞台の窓の × を押しても、吹き出しを押すまで終わらない。`05` が頼る 30 秒の上限は、`OnClose` を投げた後の別れの台詞の待ちの物で、控えている間には効かない。絵のクリック → 並走の早送りの道（決め A）は、GET が出ないので閉じる。字の無い 1 本や、画面の全体を領域にした透明なアクターで進める演劇では、押せる吹き出しが無く、抜けられない。演劇では、どの行も末尾でクリック待ちになるので、これがふつうの状態である。Alt+F4 も、メニューの「終了」と同じ要求になる（`crates/areka/src/app_exit.rs:262-301`）。今ある抜け道は、キャラ窓の Ctrl+Shift+左ダブルクリックの強制退避だけである（`crates/areka/src/input_events/mod.rs:504-506`）。舞台の窓は、入口が別なので、それも通らない。`01` の 5.7「kanade がイベントを送れない時は `ResolveNext` だけを送る」は、解けた後の話で、解く手が無い場合を覆わない。
- 直す向き: 「終了・切り替えを控えた時に、主の流れがクリック待ち（`\x`・続き）なら、その 1 本を閉じる」を決めて書く（選択待ちの `CancelChoice` と同じ、Close の道。`crates/areka-ghost/src/dispatcher.rs:240-260`）。kanade は、クリック待ちに入った事を知らないので、`ChoiceWaiting` と同じ形の知らせが要る（`crates/areka-sakura/src/drive.rs:426-469`）。
- 直すのは: 単位の文書（`01`・`05`）。骨組みの 5 章に 1 行。開発者に諮る（4 章の 2）。

### 2. 続きの 1 本が、字より前に待ちを持つと、バルーンの窓が一度隠れる

- どこ: `01` の 5.7「5a で字を替える所」。`07` の 2 章の例。
- 何: 1 本の頭には全消去が 1 つ置かれる（`crates/areka-sakura/src/compile.rs:464-466`）。見えている字が 0 に落ちた巡に、窓は隠れる（`crates/areka-runtime/src/balloon_visibility_decision.rs:292-301`。意図した動きで、注釈は「会話冒頭の全非表示」`:139-140`）。隠れないのは、同じ巡に次の字が見えた時だけである（`:270-280`）。
- なぜ困る: `01` は「最初の字は `at` ちょうどに見えるので…窓は隠れない」と書くが、これは最初の字が時刻 0 に在る 1 本だけの話である。`07` の例 `\0\![set,alpha,0,--time=500]\_w[500]…席を替えたよ。` は、字が 500 ms 後なので、窓が 500 ms 隠れて、出直す。決め C の「バルーンを消さず、字もそのまま残す。続きが届いたら、字を替えて再生する」と割れる。演劇の 1 行は、表情や転換の待ちから始まる事が多い。
- あわせて: 全消去と最初の字は、線を 1 件ずつ流れる。UI の巡の切れ目が間に入るかは、`01` も確かめていない。入れば、時刻 0 の字でも 1 巡だけ隠れる。
- 直す向き: 続きとして始まる 1 本での窓の扱いを 1 つに決める（4 章の 1）。決めたら、文字の層とバルーンの見え方の判断（`balloon_visibility_decision.rs`）に、「続き」の印を運ぶ道を `01` に足す。
- 直すのは: 単位の文書（`01`）。骨組みの 5 章の段 4a に 1 行。

### 3. 「起点の押し直しが、もう配った合図にも効く」は、時刻の土台の brief が約束していない

- どこ: `01` の 5.2 の (1)(5)・9 章・11 章の仮定 1。骨組みの 4.3 の申し送り。
- 何: brief は「届いた `CueSheet`／`TalkCue` が運ぶ起点を使う。見積もりのコードは消す」（`.kiro/specs/talk-anchor-interrupt-ticks/brief.md:37`）、「再開するときは…起点を押し直す」（`:29`）までである。受け口へ、後から起点を知らせる口は、書いていない。合図が起点を運ぶ形で着地すると、押し直しは、後ろの合図にしか効かない。
- なぜ困る（3 つ）:
  - 字の現れる時刻は、合図の `at` と長さから、受けた時に決まる（`crates/areka-emo-text/src/state.rs:538-550`・`:324-333`）。途中まで出ている字を早送りで出し切るには、文字の層の時計を、後から前へ飛ばすほか無い。
  - 今の見積もりは「最大を取る」（`crates/areka-runtime/src/talk_clock.rs:38-57`・`crates/areka-seriko/src/talk.rs:30-36`）。起点を過去へ動かす操作（早送り）を、受け付けない形である。土台が「運ばれた起点の最大」の形で残すと、基盤は乗らない。
  - バルーンの寿命の時計は、文字の層と同じ時計である（`crates/areka-runtime/src/talk_lifecycle.rs:157-158`・`:258`）。押し直しが届かないと、続きで長く待った後に何も返らなかった時（5b）、待った長さで時間切れを使い切り、話が終わった瞬間に窓が消える。今、選択肢つきのトークだけを特別に扱っているのは、この理由である（`crates/areka-runtime/src/balloon_visibility_wait.rs:93-97`・`:106-109`）。早送りした 1 本は、逆に、飛ばした長さだけ時間切れが遅れる（`:188-193` の「今が表示終了に達している事」）。
- 直す向き: 骨組みの 4.3 の申し送りを、brief 2 本に実際に書く。書く文は「受け口へ、起点の押し直しを知らせる口（`CueSink` の口）を持つ。文字の層・seriko・バルーンの寿命は、最後に押された起点を読む。起点は、前へも後ろへも動く」。
- 直すのは: 骨組み（4.3 は在る。brief への反映が残る）と、brief 2 本。

### 4. 起点が同じ刻みの中で動いた時の「絶対の発火時刻」が、決まっていない（`01`・`07`・`02` の継ぎ目）

- どこ: `01` の 5.2 の (3)(5)。`07` の 5.6・9 章「起点を付け替えた後の値」。`02` の 6.6「起点が、配られた時刻 τ そのもの」。
- 何: 再生機は、予定表の `tick` が終わってから、取り出した合図をまとめて配る（`crates/dola/src/cue/runtime.rs:190`・`:204-212`）。その時の起点は、同じ刻みの後ろの字が動かした後の値である。
- なぜ困る: `\![set,alpha,0,--time=500]\_q長い字\_q` で、透明度の変化が、字の長さだけ短くなる（字が 500 ms 以上なら、すぐ終わる）。早送りが開く印を越えた時は、区間の起点が、印の後ろで飛ばした長さだけ過去になり、区間の待ちが効かずに一度に配られる（`02` の 6.11「ふつうの速さで始まる」と逆）。文字の層が要るのは「最後の起点＋`at`」、値と区間が要るのは「取り出した時の起点＋`at`」で、2 つは別の物である。
- 直す向き: 「絶対の発火時刻は、項目を取り出した時の起点で決め、合図に持たせる（予定表が、取り出す時に刻む）。押し直しは、文字の現れ方にだけ効く」を、`01` の 5.2 と `07` の 5.6 に 1 文ずつ。
- 直すのは: 単位の文書（`01`・`07`・`02`）。骨組みの 4.3 の 2 つ目の申し送りの言い方。

### 5. 並走の進め方は、「トークのスレッドと dispatcher が同じ絶対の時刻で動く」を前提にするが、brief は決めていない

- どこ: `02` の 6.5・6.6・12 章の仮定 1。
- 何: 今、dispatcher は、トークごとの最初の刻みからの秒に直して送る（`crates/areka-ghost/src/dispatcher.rs:392-399`。起点は `base_now`・`:111-112`）。流れの起点 T0 を dispatcher が置き、トークのスレッドが進める形は、2 つが同じ物差しでないと作れない。brief は「割り込み時刻そのものにするかを設計で決める」（`talk-anchor-interrupt-ticks/brief.md:36`）で、どちらにもなる。骨組みの 4.3 の申し送りにも無い。
- あわせて: dispatcher は時計を持たない（時刻は `Tick{now}` で受けるだけ。`dispatcher.rs:41`）。「今の時刻 T0 を読む」（`02` の 6.6 の 3）には、時計の差し込みが要る（ticker の `clock` と同じ物。`crates/areka-ghost/src/ticker.rs:60-62`）。
- 直す向き: 骨組みの 4.3 に「トークのスレッドへ送る刻みは、絶対の時刻である事」を足す。`02` の 6.1 に、dispatcher の時計を足す。
- 直すのは: 骨組み。単位の文書（`02`）。

### 6. 値を書く係が 2 か所に分かれると、後ろの係が値を取りこぼす

- どこ: `07` の 5.4 の末尾「同じ時刻で 2 度刻んでも…差分が空になる。相の中で、値ごとに置き場が分かれても困らない」・5.5 の 5。
- 何: dola の刻みの結果は、「前に出した値との差分」である（`crates/dola/src/runtime/subscription_manager/mod.rs:93-116`）。1 フレームに 2 度刻むと、2 度目の差分は空になる。`07` は、倍率を窓寸の照合（`crates/areka-runtime/src/frame.rs:296`）より前に、位置を再スナップの後（`:327`）に書く、と言う。2 か所で「口 → 刻む → 差分を書く」を行うと、後ろの係は、前の係が刻んだ時に出た自分の値を見ない。毎フレーム起きる。
- 直す向き: 書く係は、差分でなく、口 D（値を読む）で読む。または、刻むのは 1 フレームに 1 回にして、その結果を 2 つの係へ持ち回る。`07` の 5.4 の 1 文は逆なので、直す。
- 直すのは: 単位の文書（`07`）。

### 7. 口 A の出発点は、最初の 1 回には無い

- どこ: `07` の 5.3「出発点の決まり」⑵⑶・5.9 の段 6「出発点は、最後に出した値（100）」。
- 何: dola が覚える値は、購読していて、1 度でも評価か強制の更新が在った変数だけである（`subscription_manager/mod.rs:100-107`・`:140-146`）。初めての `\![set,alpha,0,--time=500]` の時、透明度の値は、まだどこにも無い。⑶ で誤りになり、R18 で長さ 0 に呼び直すので、最初のフェードだけが飛ぶ。
- 直す向き: `DolaAnimator` を置く時に、変数を購読し、既定の値を「出発点つき・長さ 0 の口 A」で入れる、を 5.5 に足す。
- 直すのは: 単位の文書（`07`）。

### 8. 止まっている時の早送り（解くだけ）で、「早送りした」を配るかが、`01` と `07` で違う

- どこ: `01` の 5.2 の (5)「長さを飛ばした刻みの終わりに 1 回」。`07` の 2 章・5.9 の末尾「`\![play,next,…]` で止まっている時に吹き出しを押すと、透明度が同じフレームで 100 になる」。
- 何: 続きで止まっている時の早送りは、解くだけで、長さを飛ばさない。`01` の決まりでは配られず、`07` の例は起きない。
- 直す向き: `01` を「早送りを掛けた時は、長さを飛ばしたかに依らず配る」にそろえる（開発者「早送りは早送り。…即時に次に移るべき」）。
- 直すのは: 単位の文書（`01`）。

### 9. 主の 1 本を始めている間、走っている並走の流れを進める手が居ない

- どこ: `02` の 6.5 の受け渡し。`05` の 5.3「シェルの読み込み…流れを始める前に読み」。
- 何: 台本を読んで時刻の表に直すのは、トークのスレッドが `Start` を受けた時である（`crates/areka-sakura/src/drive.rs:238-256`）。その間、刻みは受け箱に溜まる。dispatcher は、主の枠が埋まっているので（`dispatcher.rs:357-362`）、置き場を進めない。`05` は、同じ所で、初めての名前のシェルも読む。長い台本やシェルの読み込みの間、雨や稲光の並走が止まり、後からまとめて配られる。合図は落ちないが、見た目が止まる。
- 直す向き: 受け渡しの決まりに「主の 1 本が最初の刻みを受けるまでは、dispatcher が置き場を進める」を足す（進める手が替わる点を、最初の刻みに置く）。
- 直すのは: 単位の文書（`02`）。`05` の 5.3 に、読み込みの間の並走の扱いを 1 行。

### 10. 予定表と区切りの型の持ち方が、決まっていない

- どこ: `01` の 5.2 の (3)・5.4 の段 1・5.7。`04` の 9 章の 1〜2 と、`01` の 9 章の「音」の行。
- 何（3 つ）:
  - 予定表 `TimedSchedule<T>` は、中身の型を知らない（`crates/dola/src/cue/schedule.rs:34-39`・`:61`・`:92`）。字か待ちか、と長さは、中身 `TalkCue` の側に在る（`crates/dola/src/cue/command.rs:290-304`）。`01` は「予定表が速さを見る」「口は `TimedSchedule` に置く」と書くので、型の境（中身に「飛ばせる長さ」を答えさせる約束）が要る。
  - 区切りの種類 `BarrierKind` は、直列化する公開の型である（`command.rs:74-86`）。`WaitForNext{tokens}` は、areka の命令の引数を、公開の crate の型に入れる。
  - `04` は「鍵と待ちの番号つきの、外の出来事で解ける区切り」を基盤が持つと書き、`01` は「音が、種類として宣言する」と書く。持ち主が逆である。
- 直す向き: 区切りを「外の出来事で解ける区切り（中身を見ない鍵・待ちの番号・『待ちを飛ばす』で通るか）」の 1 種類にまとめ、`\x`・続き・音の待ちを、その鍵の違いにする。`01` が持つ。
- 直すのは: 単位の文書（`01`・`04`）。

### 11. `05` の転換の区間の始まりが、`07`（骨組みの 7 章・第 2 版）と逆

- どこ: `05` の 5.7「始まりの時刻は、転換の合図の時刻を渡す。当てるのが遅れたら、過ぎたぶんだけ進んだ値から出る」。
- 何: `07` は、始まり＝口を呼んだフレームの時刻・終わり＝発火時刻＋長さ（値は飛ばない）。`05` は、前の検証が退けた形（発火時刻から数える）のままである。
- 直す向き: 4 章の 3 の答えで、1 つにそろえる。
- 直すのは: 単位の文書（`05`）。

### 12. 小さい物（まとめて）

- `02` の 6.8 の「複製を作らない受け口」は 3 つだが、骨組みの第 2 版は、バックログの受け口も付けないと書く。`02` に足す。
- `07`・骨組みは「受け口は、どの流れの物かを、作られる時に受け取る」と書く。今、`Clone` の一括の実装に乗る受け口（`MoveCueSink` ほか。`crates/areka-ghost/src/sink.rs:47-54`）は、`begin_talk` を上書きできない。自分で実装する形へ替える（前例は 2 つ。`talk_lifecycle.rs:238-247`）。
- 並走の流れの中の音の待ちを解く時、誰が解いて進めるかが、`02` の 6.10 と `04` の 5.4 の 6 に無い。主の 1 本が在る間に dispatcher が進めると、「進めるスレッドは 1 本」が崩れる。
- `01` の 4.2「`resolve_click` は…当たるのは定義と説明だけ」は、テスト（`crates/dola/tests/cue/runtime_test_barrier_tests.rs`）にも当たる。本番の呼び手が無い、は合っている。
- `05` の 5.10・11 章の問い 3 は、右クリックのメニューを「決まっていない」と書く。pasta の取り決めの brief には、2026-11-20 の決定（差し替えない。セーブや設定は、シェルの絵と当たり判定で出す）が在る（同 brief の末尾の節）。決めの「まだ決まっていない物」の行も古い。
