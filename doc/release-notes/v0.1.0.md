ごきげんよう、[Claudia](https://github.com/ponapalt/claudia) ですわ。この版では、Claude Desktop から台本を流してゴーストを話させられるようになり、SSP と同じ書き方の起動オプションも読むようになりましたの。既定のバルーンも、areka のために描いた「areka バルーン」に替わりましたわ。MCP の受け口を使う道具を作っている方と、ゴーストを作る方は、最初の 2 つと 5 つ目の見どころを必ずお読みくださいまし。

### Claude Desktop から台本を流し、イベントを頼めますわ(#336)

MCP の `sakurascript` は、`NG:not implemented yet` を返すのをやめ、台本を再生して `OK` を返しますわ。トークの再生中や選択肢の最中に送ると、今のトークを中断して新しい台本を再生しますの。`raise_event` は、任意の名前のイベントでゴーストを呼び、返った台本を再生して、答えに `Script: <台本>` を載せますわ。台本が返らなければ `OK:the ghost returned no script.` と答えますの。`get_log` の `script` には、MCP から流した台本と、ゴーストが自分から話した台本が出ますわ。

これまで `NG:not implemented yet` を見て別の道へ回していた道具は、その回り道を外してくださいまし。

### MCP の受け口が、形の合わない引数に `-32602` で答えますわ(#335, #389)

MCP の受け口は、`params` の形が合わない `tools/call`・`initialize`・`completion/complete` に、`-32601` ではなく `-32602` で答えますわ。文は `invalid params for <メソッド名>` ですの。中継 `areka-mcp-bridge.exe` を通しても同じですわ。ほかの知らないメソッドには、今までどおり `-32601` で答えますの。

答えの番号で誤りを見分けている道具は、この 3 つのメソッドの形の誤りを `-32602` で見分けるよう直してくださいまし。

### SSP と同じ書き方の起動オプションを読みますわ(#338, #377, #391, #407, #365)

`areka.exe` が、SSP と同じ書き方の起動オプションを読むようになりましたわ。`--ghost`（名前か絶対パス）・`--random`・`--install`・`--option nobootcheck`・`--option dontloadmodule`・`--option readonly`・`--option callghost`・`--option deletesource`・`--sstp-listen`（MCP の待受）・`--offline-dump`（窓を出さずに面を PNG に書き出す）・`--help` の 11 個が効きますの。`areka.exe` の隣に置いた `initial_install.nar` も、起動の途中で入りますわ。

これまでは `--` で始まる引数もゴーストのフォルダとして読まれ、「ゴーストが見つからない」で止まっていましたの。今は、知らない起動オプションは記録に残して、起動を続けますわ。`areka.exe <ゴースト> <バルーン>` と並べる今までの起動は、そのまま使えますわよ。書き方の全部は、同梱の説明書の「■ 起動オプション」にありますわ。

### 既定のバルーンが「areka バルーン」に替わりますわ(#386, #398)

バルーンを持たず、使うバルーンの指定も無いゴーストは、新しく入った「areka バルーン」（フォルダ `areka-balloon`）で話しますわ。白い地に灰色の縁のシンプルな吹き出しで、絵と設定は CC0 ですの。これまでの既定の Balloon for Staysee Syncfield はメニューの「バルーン」から選べますし、前の版でそれを使っていたゴーストは、そのまま Balloon for Staysee Syncfield で話しますわ。

長い台詞で文字が押し出されたときは、バルーンにスクロールの矢印（`arrow0`・`arrow1`）を出し、矢印のクリックとホイールで読み返せるようになりましたの。横書きと縦書き、シェルの中の箱でも同じですわ。

### 同梱のバルーンは、ゴーストのフォルダの中に入りますわ(#364)

ゴーストとシェルの `.nar` に一緒に入っているバルーンは、置き場の `balloon` フォルダではなく、そのゴーストのフォルダの中の `ghost\<ゴースト>\balloon\` に入りますわ。そこにあるバルーンは、そのゴーストを使っているときだけメニューの「バルーン」に出て、ほかのゴーストでは使えませんの。同じフォルダ名のバルーンが置き場にもあるときは、ゴーストのフォルダの中のものが使われますわ。以前の版で置き場に入れたものは動かしませんし、バルーンだけの `.nar` は今までどおり置き場に入りますの。

これは ukadoc に無い、areka だけの決まりですわ。SSP は同梱のバルーンを全部のゴーストで使えるように置き場へ入れますので、同梱のバルーンをほかのゴーストにも使わせたい作者の方は、バルーンだけの `.nar` を別に配ってくださいまし。

### マウスがゴーストへ届き、窓は画面からはみ出しませんわ(#380, #393, #360, #415)

クリック・ホイール・窓への出入りが、`OnMouseClick`・`OnMouseWheel`・`OnMouseEnter` などのイベントでゴーストへ届くようになりましたわ。右クリックは、ボタンを離した知らせをゴーストへ送ってから、メニューを出しますの。

キャラクターの窓は、画面の使える範囲の中に置くようになりましたわ。起動の並べ直しや大きな面への切り替えで、画面の外や隣の画面へはみ出しませんの。窓どうしをくっつける `sticky-window` の組も受け、ドラッグや `\![move]` で組の相手を連れて動きますわ。エラーや利用条件のお知らせの画面も、拡大率の違うモニタでにじまずに出ますわよ。
